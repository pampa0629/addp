## 一、背景与目标

### 背景

Service 模块已支持关系型数据库（PostgreSQL/MySQL/Doris/ClickHouse）的数据服务发布，提供 REST API 和 OGC Features 两种协议。

Neo4j 在 ADDP 平台已有完整的底层支持（plugin 插件、dbbridge 统一查询、meta 元数据扫描、develop 模块 Cypher 执行），但 service 模块尚未支持 Neo4j 数据的服务发布。

### 目标

新增**图查询服务**（Graph Query Service）类型，使用户能够将 Neo4j 中的图数据发布为标准化 REST API，供外部系统消费。

### 核心设计理念：命名参数化查询即服务

参考 Neo4j Data API（2024）和 TigerGraph REST++ 的设计模式：
- 用户定义一段参数化 Cypher 查询（`$param` 占位符）
- 给它一个服务名称
- 发布为 HTTP REST 端点：`POST /api/graph/{serviceName}`
- 消费方传入参数，获得图或表格结果

### 架构决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 与现有 QueryService 的关系 | **完全独立的新类型** | 图/关系模型差距过大，共享代码会导致持续分叉 |
| 结果格式 | **同时支持 table 和 graph** | graph 格式是 Neo4j 的核心差异化价值，底层 `dbbridge.ExecuteGraphQuery()` 已支持 |
| 配置入口 | **两种：label 向导 + 手写 Cypher** | 向导降低使用门槛，两者底层共用同一 Cypher 执行引擎 |
| OGC Features 协议 | **不支持** | 专为地理空间表格数据设计，不适用于图数据 |

### 2.1 数据库表

**迁移文件**：`service/backend/migrations/20260404_create_graph_query_services.sql`

```sql
CREATE TABLE IF NOT EXISTS service.graph_query_services (
    id              BIGSERIAL PRIMARY KEY,
    tenant_id       BIGINT NOT NULL,
    service_name    VARCHAR(255) NOT NULL,      -- URL 安全标识符
    title           VARCHAR(255) NOT NULL,
    description     TEXT,
    keywords        TEXT[],

    -- 引擎配置
    engine_id       BIGINT NOT NULL,            -- 引用 system 模块的引擎 ID
    database_name   VARCHAR(255) DEFAULT 'neo4j', -- Neo4j 数据库名（CE 版固定为 neo4j）

    -- 配置类型: 'label' | 'cypher'
    config_type     VARCHAR(50) NOT NULL,

    -- label 模式：选择节点标签
    node_label      VARCHAR(255),

    -- cypher 模式：手写参数化 Cypher
    cypher_query    TEXT,

    -- 参数定义（从 Cypher 中自动提取或手动配置）
    -- 格式: [{"name": "city", "type": "string", "required": true, "description": "城市名称", "default": "北京"}]
    parameters      JSONB NOT NULL DEFAULT '[]',

    -- 数据配置
    -- label 模式: {"properties": ["id","name","age"], "filterable_properties": ["name","age"]}
    -- cypher 模式: {"result_type": "table|graph|both"}
    data_config     JSONB NOT NULL DEFAULT '{}',

    -- 访问控制
    public_access   BOOLEAN DEFAULT FALSE,
    max_records     INTEGER DEFAULT 500,       -- 单次返回最大节点/行数

    -- 状态
    status          VARCHAR(50) DEFAULT 'active',
    error_message   TEXT,

    -- 审计
    created_by      BIGINT NOT NULL,
    created_at      TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    updated_at      TIMESTAMP WITH TIME ZONE DEFAULT NOW(),

    CONSTRAINT unique_graph_service_name UNIQUE (tenant_id, service_name),
    CONSTRAINT chk_graph_config_type CHECK (config_type IN ('label', 'cypher'))
);

CREATE INDEX idx_graph_query_services_tenant    ON service.graph_query_services(tenant_id);
CREATE INDEX idx_graph_query_services_status    ON service.graph_query_services(status);
CREATE INDEX idx_graph_query_services_engine    ON service.graph_query_services(engine_id);
CREATE INDEX idx_graph_query_services_config_gin ON service.graph_query_services USING GIN (data_config);
```

### 2.2 JSONB 字段结构详解

**parameters（参数定义）**：

```json
[
  {"name": "city",     "type": "string",  "required": true,  "description": "城市名称", "default": "北京"},
  {"name": "min_age",  "type": "integer", "required": false, "description": "最小年龄", "default": 0},
  {"name": "depth",    "type": "integer", "required": false, "description": "遍历深度", "default": 2}
]
```

**data_config（label 模式）**：

```json
{
  "properties": ["id", "name", "age", "city"],
  "filterable_properties": ["name", "age", "city"]
}
```

**data_config（cypher 模式）**：

```json
{
  "result_type": "graph"
}
```

`result_type` 可选值：`"table"` / `"graph"` / `"both"`

func (GraphQueryService) TableName() string {
    return "service.graph_query_services"
}

// GetResultType 获取结果类型（cypher 模式）
func (g *GraphQueryService) GetResultType() string {
    if rt, ok := g.DataConfig["result_type"].(string); ok {
        return rt
    }
    return "table" // 默认表格
}

// IsGraphResult 是否返回图结构
func (g *GraphQueryService) IsGraphResult() bool {
    rt := g.GetResultType()
    return rt == "graph" || rt == "both"
}

// ---- 请求/响应 DTO ----

type CreateGraphQueryServiceRequest struct {
    ServiceName  string   `json:"service_name" binding:"required"`

    DatabaseName string   `json:"database_name"`
    ConfigType   string   `json:"config_type" binding:"required,oneof=label cypher"`
    NodeLabel    string   `json:"node_label"`
    CypherQuery  string   `json:"cypher_query"`
    Parameters   []ParameterDef `json:"parameters"`
    DataConfig   map[string]interface{} `json:"data_config"`

    Name        string      `json:"name"`

    Required    bool        `json:"required"`

type GraphQueryServiceDTO struct {
    GraphQueryService
    EngineName string `json:"engine_name,omitempty"` // 展示用
}

// ---- 查询执行请求/响应 ----

type GraphQueryRequest struct {
    // 用户自定义参数（对应 parameters 中定义的字段）

type GraphQueryResponse struct {

    Columns    []string                   `json:"columns,omitempty"`

    PageSize   *int                       `json:"page_size,omitempty"`
    HasMore    *bool                      `json:"has_more,omitempty"`
    // 图格式（graph / both 模式）

    // 通用

#### 3.3.2 查询执行服务

**文件**：`service/backend/internal/service/data/graph_query_service.go`

```go
type GraphQueryDataService struct {
    repo         *repository.GraphQueryServiceRepository
    systemClient *commonClient.SystemClient
}

// Execute 执行图查询服务
// 流程：
//   1. 通过 serviceName 获取服务配置
//   2. 权限检查（PublicAccess 或 tenantID 匹配）
//   3. 验证并绑定用户传入参数（按 parameters 定义校验类型/必填）
//   4. 根据 config_type 路由执行：
//      - label 模式 → buildLabelCypher() 生成 Cypher → executeCypher()
//      - cypher 模式 → bindParams() 处理参数 → executeCypher()
//   5. 根据 result_type 组装响应
func (s *) Execute(ctx context.Context, serviceName string, tenantID uint, params map[string]interface{}) (*models.GraphQueryResponse, error)

// buildLabelCypher 将 label 模式配置构建为参数化 Cypher
// 示例输出：MATCH (n:`Person`) WHERE n.city = $city RETURN properties(n) as props SKIP $offset LIMIT $limit
func buildLabelCypher(service *models.GraphQueryService, params map[string]interface{}) (cypher string, neo4jParams map[string]interface{})

// executeCypher 调用 dbbridge.ExecuteGraphQuery()，统一执行入口
func executeCypher(ctx context.Context, engine *commonModels.Engine, cypher string, neo4jParams map[string]interface{}) (*plugin.GraphQueryResult, error)

// 注意：Neo4j 参数化查询通过 Cypher 中嵌入参数映射实现
// dbbridge.ExecuteGraphQuery() 目前接收 query string，参数需内联到 Cypher 字符串
// 如 dbbridge 后续支持参数化传递，此处同步更新
```

> **关键约束**：当前 `dbbridge.ExecuteGraphQuery(ctx, engine, query string)` 接收完整 Cypher 字符串。
> 参数绑定在 service 层处理：将用户参数安全地内联到 Cypher 中（字符串值引号转义，数值直接替换 `$param`）。
> 后续如 dbbridge 支持原生参数化传递，可升级此层。

## 五、安全设计

### 5.1 Cypher 写操作拦截

在 `validateCypher()` 中检查关键字（大小写不敏感）：

```go
writeKeywords := []string{"CREATE", "MERGE", "DELETE", "DETACH", "SET", "REMOVE", "DROP"}
// 检查方式：解析 Cypher token，或使用正则词边界匹配
// 注意：避免误判字符串内容，如 RETURN "DELETE" AS msg 不应触发
```

### 5.2 参数安全绑定

label 模式生成 Cypher 时：
- 节点标签：反引号转义（将 `` ` `` 替换为 ` `` `）
- 属性值：根据类型处理
  - string：单引号包裹，转义单引号（`'` → `\'`）
  - integer/float：直接数值，无引号
  - boolean：`true`/`false`

Cypher 模式：用户参数直接替换 `$param`，同上规则。

> **理想方案**：若 `dbbridge.ExecuteGraphQuery()` 未来支持原生参数化传递（类似 GORM 的 `?`），则直接传参，消除手动转义。目前手动转义是临时方案，需完整的类型安全保障。

### 5.3 资源限制

- `MaxRecords` 强制生效（label 模式 LIMIT 子句、cypher 模式检查 LIMIT 值）
- 查询超时继承 `dbbridge` 的 Context 超时（建议 30s）
- 租户隔离：服务管理 API 所有操作均过滤 `tenant_id`

## 九、设计决策记录

1. **参数化执行方式**：`dbbridge.ExecuteGraphQuery(ctx, engine, queryString)` 只接受完整 Cypher 字符串，不支持原生参数化传递（即参数和查询分离）。**决策：在 service 层手动绑定参数**（字符串值加引号+转义，数值直接替换），不扩展 dbbridge 接口。理由：手动绑定实现简单可控，安全性通过严格的类型校验保障；dbbridge 的参数化扩展作为后续优化项，不阻塞当前实现。

2. **节点标签列表获取**：service 模块不依赖 manager，只通过 system client 和 meta client 获取数据。**决策：直接复用现有的 `DataSourceHandler` + `MetaClient.GetMetadataTree()` 链路**。meta 模块扫描 Neo4j 后，节点标签以"集合"形式存储在元数据树中（engine → database → labels），层次结构与关系型数据库的 engine → schema → table 完全对应。前端 label 模式的标签选择，复用现有 `DataSourceCascader` 组件 + `/api/service/engines/:id/tree` 端点即可，无需新增任何 API。

3. **分页对 cypher 模式的支持**：cypher 模式用户自写 Cypher，分页由用户通过 `$offset`/`$limit` 参数自行控制，`total_count` 无法自动计算（不执行额外 COUNT 查询）。详情页测试面板展示时说明此限制。
