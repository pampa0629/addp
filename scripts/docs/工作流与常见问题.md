## 使用场景对比

源码开发、本地容器与生产部署的运行方式、Runtime 例外和镜像来源统一见[部署模式对照](../local/README.md#与其他部署模式对比)。编译、镜像推送与打包阶段见[构建打包与推送](构建打包与推送.md)，平台限制和参数见 [Build 指南](../build/README.md)。

以下命令在仓库根目录执行；远端部署须进入实际部署根目录。

## 典型工作流

### 场景 1: 日常开发

```bash
# 1. 启动开发环境
bash scripts/dev/start.sh

# 2. 修改所需模块源码

# 3. 重启服务
bash scripts/dev/restart.sh

# 4. 在 System → 模块管理 → 服务实例 → 查看日志中排查对应实例

# 5. 停止环境
bash scripts/dev/stop.sh
```

### 场景 2: 本地容器化测试

先按 [Local 镜像准备](../local/README.md#2-构建镜像)核对本机所需的 Linux 镜像、平台和版本；构建参数统一见 [Build 指南](../build/README.md#build-imagessh)。准备后执行：

```bash
# 1. 启动本地容器环境
bash scripts/local/start.sh

# 2. 通过启动输出中的 Nginx 统一地址验证所需功能

# 3. 查看状态
bash scripts/local/status.sh

# 4. 停止平台与 Runtime，保留 Infra 和数据卷
bash scripts/local/stop.sh
```

### 场景 3: 生产发布

生产发布的编译、镜像构建、跨 Registry 推送与打包顺序统一见[构建流程](构建打包与推送.md#完整构建流程)。按 [Build 指南](../build/README.md#build-imagessh)选择目标平台与服务，不使用全量多架构命令代替各 Runtime 的支持边界；构建、推送、打包与部署核对同一版本，根 `.env` 指向最终发布 Registry 中的目标镜像。

部署包模式、凭据和传输范围见[打包说明](../build/README.md#packagesh)。使用 `--server` 时默认远端目标为 `~/addp-deploy/`；须根据本次传输输出和实际目录层级，进入包含根 Compose 定义及 `scripts/prod/` 的部署根目录，不固定假定为 `/opt/addp`。

配置初始化、启动和健康检查按 [Prod 首次部署](../prod/README.md#首次部署)执行，版本更新与持久化状态要求见[更新部署](../prod/README.md#更新部署)和[回滚边界](../prod/README.md#回滚部署)。容器状态与 Nginx 入口健康不代替业务功能及发布验收。

## 常见问题

### Q1: 端口冲突怎么办？

先用 `bash scripts/infra/status.sh` 核对 Infra 实际映射，再核验进程、Compose project、service 和工作区归属。本地 Infra 首次宿主机映射及源码开发端口按[端口规范](../../docs/spec/addp端口分配.md)避让冲突，既有本工作区服务复用实际映射；本地容器与生产部署的 Nginx 入口、Online 专用 Runner 冲突时失败，不自动漂移。由占用者所属的标准生命周期入口处理，不能按端口盲目终止其他服务。

### Q3: 服务健康检查超时？

- 开发模式：按[开发指南](../dev/README.md#健康检查超时)读取当前实际端口，检查受管进程和 Backend `/health/ready`，不要直接假定首选端口仍可用。
- 本地容器模式：运行 `bash scripts/local/status.sh` 核对容器状态与统一入口；生产模式运行 `bash scripts/prod/health-check.sh`。这两种模式均不通过宿主机 8180 直连 System。
- 已登记实例与有效可信未登记来源均可经 System 的相应页面授权读取，权限、入口与保留边界见[日志规范](../../docs/spec/addp模块服务运行日志规范.md#四可信来源目录)。未登记不等于启动失败，目录存在不代表正文已送达；未纳入目录或页面不可用时，可结合受控节点源与启动终端诊断。`docker compose logs` 用于容器入口和日志设施诊断。

容器状态和入口健康不能代替业务功能验收；不要把超时直接判断为“只需再等待”。

### Q4: Docker 镜像不存在？

核对缺失提示中的服务、Registry、标签和平台。镜像准备与启动预检范围见 [Local 镜像准备](../local/README.md#2-构建镜像)，构建、验证和推送参数见 [Build 指南](../build/README.md#build-imagessh)；本机镜像列表不等于本次部署清单已齐备。

### Q5: 如何停止服务并保留数据？

```bash
# 开发模式
bash scripts/dev/stop.sh

# 本地 Docker：停止平台与 Runtime，保留 Infra
bash scripts/local/stop.sh

# 需要同时停止 Infra 时，仍保留数据卷
bash scripts/local/stop.sh --all

# 生产环境
bash scripts/prod/stop.sh
```

以上命令均保留持久化卷。需要销毁 Infra 数据时，先核验可恢复备份及目标 Compose project，再通过 `scripts/infra/down.sh --volumes` 的独立交互流程操作；不要把删卷作为常规故障排查步骤。
