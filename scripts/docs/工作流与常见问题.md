# ADDP 脚本：工作流与常见问题

[返回脚本导航](../README.md)

## 使用场景对比

| 场景 | 使用脚本 | 运行方式 | 镜像需求 |
|------|---------|---------|---------|
| **日常开发** | `scripts/dev/` | Go + npm 直接运行 | ❌ 不需要 |
| **本地测试** | `scripts/local/` | Docker Compose | ✅ 需要先构建 |
| **生产部署** | `scripts/prod/` | Docker Compose | ✅ 从 Registry 拉取 |
| **构建发布** | `scripts/build/` | 编译 + 构建 + 打包 | ✅ 生成镜像 |


## 典型工作流

### 场景 1: 日常开发

```bash
# 1. 启动开发环境
bash scripts/dev/start.sh

# 2. 修改代码
vim system/backend/internal/service/user_service.go

# 3. 重启服务
bash scripts/dev/restart.sh

# 4. 在 System → 模块管理 → 服务实例 → 查看日志中排查对应实例

# 5. 停止环境
bash scripts/dev/stop.sh
```

### 场景 2: 本地容器化测试

```bash
# 1. 构建镜像
make build
make build-images

# 2. 启动 Docker 环境
bash scripts/local/start.sh

# 3. 通过启动输出中的 Nginx 统一地址验证所需功能

# 4. 查看状态
bash scripts/local/status.sh

# 5. 停止环境
bash scripts/local/stop.sh
```

### 场景 3: 生产发布

```bash
# 1. 编译多架构二进制
make build BUILD_ARGS="--arch both"

# 2. 构建多架构镜像
IMAGE_TAG=v1.0.0 make build-images \
  IMAGE_BUILD_ARGS="--multi-arch --registry localhost:5001"

# 3. 登录并推送镜像到 Registry
docker login  # Docker Hub
# 或: docker login harbor.example.com:5001  # Harbor

bash scripts/build/push-images.sh \
  --registry docker.io/myorg \
  --tag v1.0.0

# 4. 生成部署包
bash scripts/build/package.sh \
  --mode registry \
  --registry docker.io/myorg \
  --server ubuntu@production-server

# 5. 在生产服务器上部署
ssh ubuntu@production-server
cd /opt/addp
bash scripts/prod/start.sh

# 6. 健康检查
bash scripts/prod/health-check.sh
```


## 常见问题

### Q1: 端口冲突怎么办？

本地标准入口会为首次映射避让被占用端口，已经运行的本工作区服务复用实际映射；Online 专用 Runner 冲突时失败。先核对实际端口和进程归属，再由所属服务的标准入口处理，见[Infra 端口排查](../infra/docs/故障排查.md#端口被占用)。

### Q3: 服务健康检查超时？

- 开发模式：按[开发指南](../dev/README.md#健康检查超时)读取当前实际端口，检查受管进程和 Backend `/health/ready`，不要直接假定首选端口仍可用。
- 本地容器模式：运行 `bash scripts/local/status.sh` 核对容器状态与统一入口；生产模式运行 `bash scripts/prod/health-check.sh`。这两种模式均不通过宿主机 8180 直连 System。
- 模块日志正文从 System 的服务实例页读取；尚未登记就启动失败时，按[日志规范](../../docs/spec/addp模块服务运行日志规范.md#21-启动与实例关联)检查受控节点源及启动终端输出。`docker compose logs` 用于容器入口和日志设施诊断。

容器状态和入口健康不能代替业务功能验收；不要把超时直接判断为“只需再等待”。

### Q4: Docker 镜像不存在？

```bash
# 重新构建镜像
make build
make build-images

# 验证镜像
docker images | grep addp
```

### Q5: 如何停止服务并保留数据？

```bash
# 开发模式
bash scripts/dev/stop.sh

# 本地 Docker
bash scripts/local/stop.sh --all

# 生产环境
bash scripts/prod/stop.sh
```

以上命令均保留持久化卷。需要销毁 Infra 数据时，先核验可恢复备份及目标 Compose project，再通过 `scripts/infra/down.sh --volumes` 的独立交互流程操作；不要把删卷作为常规故障排查步骤。
