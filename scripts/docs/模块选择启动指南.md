# ADDP 模块选择启动指南

## 概述

ADDP 开发环境支持**模块选择启动**,可以只启动需要的模块及其依赖,大幅提升开发效率。

单模块启动统一带上公共依赖：System Backend、Meta Backend、Meta Worker、Gateway 和 Console。各模块的专属前端和额外依赖会在此基础上按需启动。

## 使用方法

### 基本命令

```bash
# 启动所有模块(默认)
bash scripts/dev/start.sh

# 启动指定模块
bash scripts/dev/start.sh -<模块名>

# 查看帮助
bash scripts/dev/start.sh -h
```


### 开发工作流（重要）

**如果你修改了某个模块的代码，使用选择性重启快速验证**：

```bash
# 场景 1: 修改了 Manager 模块
bash scripts/dev/restart.sh -manager

# 场景 2: 修改了common、或者多个模块、或不确定影响范围
bash scripts/dev/restart.sh -all

# 场景 3: 只重启服务，不重新编译（最快）
bash scripts/dev/restart.sh

# 场景 4: 只局部重启扩展服务
bash scripts/dev/restart.sh -python-workflow
bash scripts/dev/restart.sh -pointcloud-workflow
```

**支持的模块选项**：

- `-system` - System 模块
- `-manager` - Manager 模块
- `-meta` - Meta 模块
- `-transfer` - Transfer 模块
- `-orchestrator` - Orchestrator 模块
- `-develop` - Develop 模块
- `-service` - Service 模块
- `-monitor` - Monitor 模块
- `-gateway` - Gateway 模块
- `-python-workflow` - 局部重启 GeoPython Workflow Engine
- `-math-workflow` - 局部重启 Math Workflow Engine
- `-model3d-workflow` - 局部重启 Model3D Workflow Engine
- `-pointcloud-workflow` - 局部重启 PointCloud Workflow Engine Docker runtime
- `-supermap-workflow` - 局部重启 SuperMap Workflow Engine C++ Docker runtime，需先构建 iObjects C++ 基础镜像
- `-spark-workflow` - 局部重启 Spark Workflow Engine
- `-jupyter` - 局部重启 Jupyter Engine
- `-copilot` - 局部重启 Copilot Backend
- `-agent` - 局部重启 Agent Backend
- `-all` - 所有模块

**当前处于开发阶段，优先采用 ./scripts/dev/ 下的脚本，有明确要求时再使用容器方式。**


### 支持的模块选项

| 选项 | 说明 | 启动内容 |
|------|------|---------|
| `-system` | System 模块 | 公共依赖 + System Frontend |
| `-manager` | Manager 模块 | 公共依赖 + Manager Backend + Frontend + Transfer Backend/bounded Worker/continuous Worker + Model3D/PointCloud Workflow Engine |
| `-meta` | Meta 模块 | 公共依赖 + Meta Frontend |
| `-transfer` | Transfer 模块 | 公共依赖 + Transfer Backend + Frontend + bounded Worker + continuous Worker |
| `-orchestrator` | Orchestrator 模块 | 公共依赖 + Orchestrator Backend + Frontend |
| `-develop` | Develop 模块 | 公共依赖 + Develop Backend + Frontend + Python/Math/Spark Workflow Engine + Jupyter |
| `-service` | Service 模块 | 公共依赖 + Service Backend + Frontend |
| `-monitor` | Monitor 模块 | 公共依赖 + Monitor Backend + Frontend |
| `-copilot` | Copilot 模块 | 公共依赖 + Develop Backend + GeoPython Workflow Engine + Jupyter + Copilot Backend |
| `-gateway` | Gateway | 公共依赖 + 所有后端模块 + Gateway |
| `-console` | Console | 所有模块 |

SuperMap Workflow Engine 不随 `-develop` 默认拉起，但会随无参数全量启动和 `restart.sh -all` 启动。首次使用需保留完整 iObjects C++ SDK 母版，把许可放入 Git 忽略的 `engines/supermap-workflow/vendor/license`，并构建基础镜像：

```bash
SUPERMAP_CPP_SDK_PATH=/path/to/supermap-iobjectscpp-12.1.0-linux-arm64-all \
  bash scripts/build/build-supermap-workflow-base.sh
```

验证或修改超图算子时直接启动或重启；脚本按构建指纹决定是否重新编译当前 C++ 源码，`INTERNAL_API_KEY` 可用时自动注册到 System：

```bash
bash scripts/dev/start.sh -supermap-workflow
bash scripts/dev/restart.sh -supermap-workflow
```

## 模块依赖关系

```text
单模块公共依赖
├── System Backend
├── Meta Backend
├── Meta Worker
├── Gateway
└── Console

模块额外依赖
├── Manager -> Transfer Backend + Transfer bounded Worker + Transfer continuous Worker + Model3D/PointCloud Workflow Engine
├── Develop -> Python/Math/Spark Workflow Engine + Jupyter
├── Model / Quality -> Standard Backend
├── Portal -> Asset Backend
└── Copilot -> Develop Backend + GeoPython Workflow Engine + Jupyter
```

## 使用场景

### 1. 开发 System 模块

- 基础设施 (PostgreSQL, Redis, MinIO, Meilisearch)
- System Backend (端口 8180)
- Meta Backend + Meta Worker
- Gateway
- Console Frontend
- System Frontend (端口 5173)

**访问地址**:
- Backend: http://localhost:8180
- Frontend: http://localhost:5173

### 2. 开发 Manager 模块

```bash
# 启动 Manager 及公共依赖
bash scripts/dev/start.sh -manager
```

**启动内容**:
- 基础设施
- System Backend
- Meta Backend + Meta Worker
- Transfer Backend + Transfer bounded Worker + Transfer continuous Worker
- Model3D Workflow Engine (端口 8101)
- PointCloud Workflow Engine (端口 8102，Docker runtime)
- Gateway + Console
- Manager Backend (端口 8081) + Frontend (端口 5174)

**访问地址**:
- System Frontend: http://localhost:5173
- Manager Frontend: http://localhost:5174

### 3. 开发 Develop 模块 (需要空间计算)

```bash
# 启动 Develop 及公共依赖
bash scripts/dev/start.sh -develop
```

**启动内容**:
- 基础设施
- System Backend
- Meta Backend + Meta Worker
- Gateway + Console
- Develop Backend (端口 8185) + Frontend (端口 5178)
- GeoPython Workflow Engine (端口 8099)

### 4. 开发 Gateway 或测试完整后端

```bash
# 启动所有后端模块 + Gateway
bash scripts/dev/start.sh -gateway
```

**启动内容**:
- 基础设施
- 所有后端服务 (System, Manager, Meta, Transfer, Orchestrator, Develop, Service)
- 所有 Workers
- GeoPython Workflow Engine
- Copilot Backend
- Gateway (端口 8000)

### 5. 测试完整系统

```bash
# 启动所有模块 (包括 Console)
bash scripts/dev/start.sh -console
# 或
bash scripts/dev/start.sh
```

## 优势

### 1. 节省资源

只启动需要的服务,减少 CPU、内存占用:

```bash
# 完整启动: ~15 个服务进程
bash scripts/dev/start.sh

# System 模块: ~2 个服务进程 (节省 85% 资源)
bash scripts/dev/start.sh -system
```

### 2. 加快启动速度

```bash
# 完整启动: 25-39 秒
bash scripts/dev/start.sh

# System 模块: 5-8 秒 (快 5 倍)
bash scripts/dev/start.sh -system
```

### 3. 简化开发流程

专注于单个模块开发,减少干扰:

```bash
# 修改 System 模块代码
vim system/backend/internal/api/user.go

# 快速重启验证
bash scripts/dev/restart.sh -system
```

## 停止服务

**所有模块选择启动方式都使用统一的停止脚本**:

```bash
bash scripts/dev/stop.sh
```

这会停止所有正在运行的 ADDP 服务。

## 重启服务

### 快速重启(不重新编译)

```bash
# 重启 System 模块
bash scripts/dev/restart.sh -system

# 重启 Manager 模块
bash scripts/dev/restart.sh -manager
```

### 扩展服务局部重启

```bash
# 只重启对应扩展服务，不停止整套 ADDP 开发环境
bash scripts/dev/restart.sh -python-workflow
bash scripts/dev/restart.sh -math-workflow
bash scripts/dev/restart.sh -model3d-workflow
bash scripts/dev/restart.sh -pointcloud-workflow
bash scripts/dev/restart.sh -supermap-workflow
bash scripts/dev/restart.sh -spark-workflow
bash scripts/dev/restart.sh -jupyter
bash scripts/dev/restart.sh -copilot
bash scripts/dev/restart.sh -agent
```

只指定上述扩展服务参数时，`restart.sh` 不会调用全局 `stop.sh`，也不会触发 Go 模块重新编译。扩展服务参数和 Go 模块参数混用时，仍按 Go 模块重启路径执行。

### 重新编译并重启

```bash
# 先停止
bash scripts/dev/stop.sh

# 再启动指定模块
bash scripts/dev/start.sh -system
```

## 注意事项

### 1. 基础设施总是启动

无论选择哪个模块,以下基础设施总是会启动:

- PostgreSQL (端口 5432)
- Redis (端口 6379)
- MinIO (端口 9000-9001)
- Meilisearch (端口 7700)

### 2. 依赖会自动启动

选择模块时,其依赖会自动启动。例如:

```bash
# 启动 Manager
bash scripts/dev/start.sh -manager

# 实际启动:
# - 基础设施
# - System Backend + Frontend
# - Manager Backend + Frontend
# - Transfer Backend + bounded Worker + continuous Worker
```

### 3. 端口冲突检测

如果端口被占用,启动会失败并提示:

```bash
✗ 端口 8180 已被占用 (PID: 12345)
✗ 无法启动 System Backend，请先停止占用端口的进程
提示: 运行 'bash scripts/dev/stop.sh' 停止所有服务
```

### 4. 与 restart.sh 配合使用

`restart.sh` 的 Go 模块 `-模块` 参数是**强制重新编译**指定模块:

```bash
# 重新编译 System 并重启所有服务
bash scripts/dev/restart.sh -system

# 等价于:
# 1. 停止所有服务
# 2. 强制重新编译 System
# 3. 启动所有服务
```

而 `start.sh -system` 是**启动 System 模块及公共依赖**:

```bash
# 启动 System 模块及公共依赖
bash scripts/dev/start.sh -system
```

## FAQ

### Q: 如何查看当前运行的服务?

```bash
# 查看所有 ADDP 进程
ps aux | grep addp

# 或查看 PID 文件
ls -la .dev-pids/
```

### Q: 如何查看服务日志?

```bash
# 查看 System Backend 日志
tail -f logs/system-backend.log

# 查看 Manager Backend 日志
tail -f logs/manager-backend.log
```

### Q: 启动失败怎么办?

1. 查看错误日志:
   ```bash
   tail -f logs/system-backend-stderr.log
   ```

2. 检查端口占用:
   ```bash
   lsof -i :8180
   ```

3. 停止所有服务重试:
   ```bash
   bash scripts/dev/stop.sh
   bash scripts/dev/start.sh -system
   ```

### Q: 如何同时启动多个模块?

目前不支持同时指定多个模块参数。如需启动多个模块,请使用上层模块或启动所有模块:

```bash
# 不支持:
# bash scripts/dev/start.sh -system -manager

# 推荐:
bash scripts/dev/start.sh -manager  # 会自动启动公共依赖
# 或
bash scripts/dev/start.sh           # 启动所有模块
```

## 性能对比

| 启动方式 | 服务数量 | 启动时间 | 内存占用 | 适用场景 |
|---------|---------|---------|---------|---------|
| `-system` | 公共依赖 + System FE | 5-8s | ~500MB | 开发 System 模块 |
| `-manager` | 公共依赖 + Manager + Transfer + 三维/点云工作流 | 10-18s | ~2GB | 开发 Manager 模块 |
| `-develop` | 公共依赖 + Develop + 工作流引擎 | 12-18s | ~1.8GB | 开发 Develop 模块 (含空间计算) |
| `-gateway` | 13 | 20-30s | ~4GB | 后端集成测试 |
| 所有模块 | 15+ | 25-39s | ~5GB | 完整系统测试 |

## 总结

模块选择启动功能让 ADDP 开发更加高效:

- ✅ **节省资源**: 只启动需要的服务
- ✅ **加快启动**: 5-8 秒启动单个模块
- ✅ **简化开发**: 专注于单个模块
- ✅ **自动依赖**: 无需手动管理依赖关系
- ✅ **统一管理**: 与 restart.sh 和 stop.sh 配合使用

开始使用:

```bash
# 查看帮助
bash scripts/dev/start.sh -h

# 启动你需要的模块
bash scripts/dev/start.sh -system
```
