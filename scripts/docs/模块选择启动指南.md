# ADDP 模块选择启动指南

## 概述

ADDP 开发环境支持**模块选择启动**,可以只启动需要的模块及其依赖,大幅提升开发效率。

## 使用方法

### 基本命令

```bash
# 启动所有模块(默认)
bash scripts/dev/start.sh

# 启动指定模块
bash scripts/dev/start.sh -<模块名>

# 查看帮助
bash scripts/dev/start.sh -h
```

### 支持的模块选项

| 选项 | 说明 | 启动内容 |
|------|------|---------|
| `-system` | System 模块 | System Backend + Frontend |
| `-manager` | Manager 模块 | System + Manager Backend + Frontend + Worker |
| `-meta` | Meta 模块 | System + Meta Backend + Frontend + Worker |
| `-transfer` | Transfer 模块 | System + Transfer Backend + Frontend + Worker |
| `-orchestrator` | Orchestrator 模块 | System + Orchestrator Backend + Frontend |
| `-develop` | Develop 模块 | System + Develop Backend + Frontend + Python Workflow Engine |
| `-service` | Service 模块 | System + Service Backend + Frontend |
| `-copilot` | Copilot 模块 | System + Meta + Develop + GeoPandas + Copilot Backend |
| `-gateway` | Gateway | 所有后端模块 + Gateway |
| `-portal` | Portal | 所有模块 |

## 模块依赖关系

```
System (基础模块,几乎所有模块都依赖)
├── Manager (依赖 System)
├── Meta (依赖 System)
├── Transfer (依赖 System)
├── Orchestrator (依赖 System)
├── Develop (依赖 System + Python Workflow Engine)
├── Service (依赖 System)
└── Copilot (依赖 System + Meta + Develop + GeoPandas)

Gateway (依赖所有后端模块)
Portal (依赖所有模块)
```

## 使用场景

### 1. 开发 System 模块

```bash
# 只启动 System 模块
bash scripts/dev/start.sh -system
```

**启动内容**:
- 基础设施 (PostgreSQL, Redis, MinIO, Meilisearch)
- System Backend (端口 8180)
- System Frontend (端口 5173)

**访问地址**:
- Backend: http://localhost:8180
- Frontend: http://localhost:5173

### 2. 开发 Manager 模块

```bash
# 启动 Manager + System
bash scripts/dev/start.sh -manager
```

**启动内容**:
- 基础设施
- System Backend + Frontend
- Manager Backend (端口 8081) + Frontend (端口 5174) + Worker

**访问地址**:
- System Frontend: http://localhost:5173
- Manager Frontend: http://localhost:5174

### 3. 开发 Develop 模块 (需要空间计算)

```bash
# 启动 Develop + System + GeoPandas
bash scripts/dev/start.sh -develop
```

**启动内容**:
- 基础设施
- System Backend + Frontend
- Develop Backend (端口 8085) + Frontend (端口 5178)
- Python Workflow Engine (端口 8099)

### 4. 开发 Gateway 或测试完整后端

```bash
# 启动所有后端模块 + Gateway
bash scripts/dev/start.sh -gateway
```

**启动内容**:
- 基础设施
- 所有后端服务 (System, Manager, Meta, Transfer, Orchestrator, Develop, Service)
- 所有 Workers
- Python Workflow Engine
- Copilot Backend
- Gateway (端口 8000)

### 5. 测试完整系统

```bash
# 启动所有模块 (包括 Portal)
bash scripts/dev/start.sh -portal
# 或
bash scripts/dev/start.sh
```

## 优势

### 1. 节省资源

只启动需要的服务,减少 CPU、内存占用:

```bash
# 完整启动: ~15 个服务进程
bash scripts/dev/start.sh

# System 模块: ~2 个服务进程 (节省 85% 资源)
bash scripts/dev/start.sh -system
```

### 2. 加快启动速度

```bash
# 完整启动: 25-39 秒
bash scripts/dev/start.sh

# System 模块: 5-8 秒 (快 5 倍)
bash scripts/dev/start.sh -system
```

### 3. 简化开发流程

专注于单个模块开发,减少干扰:

```bash
# 修改 System 模块代码
vim system/backend/internal/api/user.go

# 快速重启验证
bash scripts/dev/restart.sh -system
```

## 停止服务

**所有模块选择启动方式都使用统一的停止脚本**:

```bash
bash scripts/dev/stop.sh
```

这会停止所有正在运行的 ADDP 服务。

## 重启服务

### 快速重启(不重新编译)

```bash
# 重启 System 模块
bash scripts/dev/restart.sh -system

# 重启 Manager 模块
bash scripts/dev/restart.sh -manager
```

### 重新编译并重启

```bash
# 先停止
bash scripts/dev/stop.sh

# 再启动指定模块
bash scripts/dev/start.sh -system
```

## 注意事项

### 1. 基础设施总是启动

无论选择哪个模块,以下基础设施总是会启动:

- PostgreSQL (端口 5432)
- Redis (端口 6379)
- MinIO (端口 9000-9001)
- Meilisearch (端口 7700)

### 2. 依赖会自动启动

选择模块时,其依赖会自动启动。例如:

```bash
# 启动 Manager
bash scripts/dev/start.sh -manager

# 实际启动:
# - 基础设施
# - System Backend + Frontend
# - Manager Backend + Frontend + Worker
```

### 3. 端口冲突检测

如果端口被占用,启动会失败并提示:

```bash
✗ 端口 8180 已被占用 (PID: 12345)
✗ 无法启动 System Backend，请先停止占用端口的进程
提示: 运行 'bash scripts/dev/stop.sh' 停止所有服务
```

### 4. 与 restart.sh 配合使用

`restart.sh` 的 `-模块` 参数是**强制重新编译**指定模块:

```bash
# 重新编译 System 并重启所有服务
bash scripts/dev/restart.sh -system

# 等价于:
# 1. 停止所有服务
# 2. 强制重新编译 System
# 3. 启动所有服务
```

而 `start.sh -system` 是**只启动 System 模块**:

```bash
# 只启动 System 模块及其依赖
bash scripts/dev/start.sh -system
```

## FAQ

### Q: 如何查看当前运行的服务?

```bash
# 查看所有 ADDP 进程
ps aux | grep addp

# 或查看 PID 文件
ls -la .dev-pids/
```

### Q: 如何查看服务日志?

```bash
# 查看 System Backend 日志
tail -f logs/system-backend.log

# 查看 Manager Backend 日志
tail -f logs/manager-backend.log
```

### Q: 启动失败怎么办?

1. 查看错误日志:
   ```bash
   tail -f logs/system-backend-stderr.log
   ```

2. 检查端口占用:
   ```bash
   lsof -i :8180
   ```

3. 停止所有服务重试:
   ```bash
   bash scripts/dev/stop.sh
   bash scripts/dev/start.sh -system
   ```

### Q: 如何同时启动多个模块?

目前不支持同时指定多个模块参数。如需启动多个模块,请使用上层模块或启动所有模块:

```bash
# 不支持:
# bash scripts/dev/start.sh -system -manager

# 推荐:
bash scripts/dev/start.sh -manager  # 会自动启动 System
# 或
bash scripts/dev/start.sh           # 启动所有模块
```

## 性能对比

| 启动方式 | 服务数量 | 启动时间 | 内存占用 | 适用场景 |
|---------|---------|---------|---------|---------|
| `-system` | 2 | 5-8s | ~500MB | 开发 System 模块 |
| `-manager` | 5 | 10-15s | ~1.5GB | 开发 Manager 模块 |
| `-develop` | 5 | 12-18s | ~1.8GB | 开发 Develop 模块 (含空间计算) |
| `-gateway` | 13 | 20-30s | ~4GB | 后端集成测试 |
| 所有模块 | 15+ | 25-39s | ~5GB | 完整系统测试 |

## 总结

模块选择启动功能让 ADDP 开发更加高效:

- ✅ **节省资源**: 只启动需要的服务
- ✅ **加快启动**: 5-8 秒启动单个模块
- ✅ **简化开发**: 专注于单个模块
- ✅ **自动依赖**: 无需手动管理依赖关系
- ✅ **统一管理**: 与 restart.sh 和 stop.sh 配合使用

开始使用:

```bash
# 查看帮助
bash scripts/dev/start.sh -h

# 启动你需要的模块
bash scripts/dev/start.sh -system
```
