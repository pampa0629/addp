## 核心原则

所有脚本遵循以下 7 个核心原则：

1. **单一职责**: 同样功能只在一处实现，其他地方调用
2. **适应性**: 适应不同环境（OS、CPU 架构），脚本自动适配
3. **清晰明了**: 一看就懂的结构和命名
4. **可重复执行**: 幂等性，多次执行不会破坏系统
5. **易用性**: 用户无需了解技术细节，按顺序执行即可
6. **分散和集中**: 模块相关配置分散，整体管理脚本集中
7. **敢于删除**: 删除重复或无用的内容，避免违反单一职责原则


## 目录结构

```
scripts/
├── infra/          # 一、基础设施管理
├── dev/            # 二、本地开发使用
├── build/          # Go 编译、产品镜像、跨 Registry 推送与部署包
├── local/          # 四、本地 Docker 部署
├── prod/           # 五、生产服务器部署
├── registry/       # Docker Registry 管理
├── test/           # 测试门禁与发布认证
└── utils/          # 通用工具脚本
```

构建阶段与顺序见[构建打包与推送](构建打包与推送.md#完整构建流程)，各脚本的参数和操作边界统一见 [Build 指南](../build/README.md)。打包模式见[部署包说明](../build/README.md#两种部署模式)，实际镜像上传与结果判定见[推送专题](../build/README.md#推送退出与验收边界)；代理故障按[分层验证](Docker镜像推送代理配置指南.md#验证范围与实际操作)定位。

## 其他辅助目录

### registry/ - Docker Registry 管理

本地构建缓存和镜像部署源的操作使用 [Registry 标准入口](../registry/README.md#标准入口)，删除副作用与持久化范围见[启动与重建边界](../registry/README.md#启动与重建边界)，查询的失败与未覆盖项见[状态验证范围](../registry/README.md#状态查询与验证范围)；Docker daemon 对外部仓库的信任配置、分支写入和重启范围见[外部 Registry 配置](../registry/README.md#外部-registry-信任配置)。该目录不承担 ADDP 服务注册／发现、生产镜像仓库或备份职责；生产仓库的认证、持久化及备份由部署环境负责。

### utils/ - 通用工具

常用辅助入口统一见 [Utils 指南](../utils/README.md)：[Node 校验](../utils/README.md#node-runtimesh)、[端口诊断](../utils/README.md#ports-validatesh)、[本机 Business 注册](../utils/README.md#register-businesssh)与[单次 MVT 请求诊断](../utils/README.md#test-tile-apish)。各工具的环境、身份、写入与覆盖范围按对应说明核对。

Go 依赖整理归入[开发依赖维护](../dev/README.md#modtidysh)，按其清单范围与[依赖变更流程](../dev/README.md#添加新依赖)执行。

## 最佳实践

1. **开发环境**: 始终使用 `scripts/dev/` 进行日常开发，重启速度快
2. **容器测试**: 使用 `scripts/local/` 验证 Docker 配置和部署流程
3. **生产部署**: 使用 `scripts/prod/start.sh` 的 Compose 标准流程；Swarm 脚本的行为和部署缺口见[生产指南](../prod/README.md#swarm)
4. **定期备份**: 生产环境定期备份 PostgreSQL 和 MinIO 数据
5. **版本管理**: 生产镜像使用明确的版本标签（如 `v1.0.0`），避免使用 `latest`
6. **日志监控**: 定期查看日志文件和 `health-check.sh` 输出
7. **资源限制**: 在 docker-compose.yml 中配置 CPU 和内存限制


## 贡献指南

添加新脚本时，请遵循以下规范：

1. **命名规范**: 使用 `kebab-case`（小写 + 连字符）
2. **Shebang**: 始终使用 `#!/usr/bin/env bash`
3. **错误处理**: 使用 `set -e` 或显式错误检查
4. **颜色输出**: 使用统一的颜色变量（GREEN, RED, YELLOW）
5. **幂等性**: 脚本应支持重复执行
6. **文档**: 添加脚本时更新对应的 README.md
