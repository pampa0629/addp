## 二、本地开发使用 (dev/)

Go 服务、Node 前端及支持本机平台的 Python Runtime 使用原生进程，便于开发调试；SuperMap 当前接入的 Linux SDK 开发制品使用容器。开发方式与平台限制见[引擎运行方式](../../engines/README.md#本地开发运行方式)。Infra 与 Business 保留各自容器用途，原生开发不改变产品部署使用正式镜像的路线。

日常启停、就绪与失败处理统一见[启动脚本指南](启动脚本使用指南.md#启动与重启边界)，模块依赖和 Runtime 显式选择见[模块选择指南](模块选择启动指南.md#如何合并依赖)。开发进程及开发容器 Runtime 由 `scripts/dev/` 管理，不通过 `scripts/local/` 或 `scripts/prod/` 接管；工作区锁、PID/监听归属及保活退出范围见[停止与进程归属](启动脚本使用指南.md#停止与进程归属)。

实际地址从启动输出和 `.dev-state/ports.env` 读取；Infra 映射用 `scripts/infra/status.sh` 核对，规则见[端口规范](../../docs/spec/addp端口分配.md)。日志与进程检查见[排查失败](启动脚本使用指南.md#排查失败)；模块正文与引擎、前端启动输出的区别见[开发脚本说明](../dev/README.md#startsh)。

`SKIP_MODTIDY` 仅跳过启动入口的 Go 依赖整理，不承诺固定节省时间；使用要求见 [start.sh](../dev/README.md#startsh)。显式依赖维护的范围、停服顺序和失败边界见[添加新依赖](../dev/README.md#添加新依赖)。

## 四、本地 Docker 部署 (local/)

本模式在本机运行预先准备的正式平台与内置 Runtime 镜像。Docker、目标架构、Registry 和镜像标签要求见[镜像准备](../local/README.md#2-构建镜像)；源码构建入口见[部署指南的构建模式](../../docs/guide/addp部署和开发步骤.md#第三步-构建模式-用于-docker-镜像构建)。镜像存在检查不自动构建应用镜像，也不证明镜像可运行。

启动、状态、重启和停止参数统一见[Local 脚本说明](../local/README.md#脚本说明)。默认停止平台及内置 Runtime、保留 Infra；`stop.sh --all` 额外通过 Infra 标准入口停止基础设施，仍保留数据卷，Business 继续由所属入口管理。数据卷删除须核验目标项目与可恢复备份，并走 Infra 专用交互确认流程，见[数据持久化](../infra/docs/部署与项目隔离.md#数据持久化)。

启停前核对 Compose project、service 和工作区归属，项目划分、容器名占用及开发 Runtime 的管理边界见[本地 Compose 部署说明](../../docs/guide/addp部署和开发步骤.md#第四步-本地-docker-compose-模式)。平台仅发布 Nginx 统一入口；公开 origin、HTTPS/上级反向代理与监听范围统一见[访问地址说明](../../docs/guide/addp部署和开发步骤.md#第五步-生产模式)。

本地状态和资源统计仅反映脚本实际查询的容器；启动及健康检查通过后，仍须单独验证所需业务功能和数据结果，排查入口见[Local 故障排查](../local/README.md#故障排查流程)。

## 五、生产服务器部署 (prod/)

生产部署使用目标平台与版本的正式镜像。配置准备、已有 Secret 和数据卷的匹配要求统一见[首次部署](../prod/README.md#首次部署)，启动与等待顺序见[生产启动流程](../prod/README.md#启动流程)。更新或回退按[更新部署](../prod/README.md#更新部署)及[回滚部署](../prod/README.md#回滚部署)处理，切换代码或镜像不恢复持久化数据。

标准停止只处理平台与内置 Runtime，保留 Infra、Business 和全部数据卷，不接受卷删除参数；完整范围见[生产停止说明](../prod/README.md#stopsh)。容器归属及统一 Nginx 入口沿用上述 Compose 部署边界。

生产检查的范围、失败与覆盖边界统一见[Prod 健康检查正文](../prod/README.md#health-checksh)，排查直达[健康检查失败](../prod/README.md#问题-3-健康检查失败)。容器状态与回环 HTTP 探测不代表公开 HTTPS、业务或恢复验收已通过；未执行、失败或未覆盖项不能计为通过。

### Docker Swarm 脚本状态

Swarm 脚本尚未形成与现行配置及验收闭合的生产流程。现存行为、初始化的集群操作范围和部署缺口统一见[生产指南](../prod/README.md#swarm)；服务器部署按上文 Compose 标准入口执行。
