## 二、本地开发使用 (dev/)

**用途**: 用于日常开发调试，直接运行 Go 和 npm 进程（非容器化）

### 核心脚本

| 脚本 | 功能 | 使用场景 |
|------|------|---------|
| `start.sh` | 启动完整开发环境（后台运行） | 日常开发启动 |
| `stop.sh` | 停止所有开发服务 | 开发结束 |
| `restart.sh` | 重启所有服务 | 代码修改后重启 |
| `modtidy.sh` | 清理 Go 模块依赖 | 依赖调整、同步 main 后 |

### 快速使用

```bash
# 一键启动开发环境（基础设施 + 后端 + 前端）
bash scripts/dev/start.sh

# 跳过 Go 依赖检查（节省 5-10 秒）
SKIP_MODTIDY=1 bash scripts/dev/start.sh

# 修改代码后重启
bash scripts/dev/restart.sh

# 停止所有服务
bash scripts/dev/stop.sh
```

### 启动流程

`start.sh` 先检查依赖和核心 Infra，再按所选模块的依赖清单启动 Backend、Worker、显式选择的 Runtime、Gateway 和前端。模块 Backend 就绪后才启动其 Worker；无参数执行全量启动。具体顺序与参数见[开发脚本指南](../dev/README.md#startsh)。

开发端口是首选值，实际访问地址以启动输出和 `.dev-state/ports.env` 为准；Infra 映射通过 `bash scripts/infra/status.sh` 查询，详见[端口规范](../../docs/spec/addp端口分配.md)。

### 特性

- ✅ **依赖复用**: 核心 Infra 未就绪时调用 `scripts/infra/up.sh`；已就绪时复用。所选观测能力异常单独报告，不触发核心设施重建，业务继续启动但命令返回非零
- ✅ **就绪检查**: ADDP Backend 等待 `/health/ready` 返回 200；Engine Runtime 使用各自协议的 `/health`
- ✅ **日志管理**: 模块正文从 System 服务实例的“查看日志”入口读取；受控节点源为 `logs/runtime/<module>/<instance_id>/*.jsonl`，引擎和前端保留各自启动日志
- ✅ **PID 追踪**: 存储进程 PID，支持优雅停止

详见: [dev/README.md](../dev/README.md)


## 四、本地 Docker 部署 (local/)

**用途**: 在本地使用 Docker Compose 部署完整 ADDP 平台进行测试

### 核心脚本

| 脚本 | 功能 | 使用场景 |
|------|------|---------|
| `start.sh` | 启动完整 Docker 环境 | 本地容器化测试 |
| `stop.sh` | 停止 Docker 服务 | 停止测试 |
| `status.sh` | 查看容器状态 | 健康检查、资源使用 |
| `restart.sh` | 重启服务 | 更新配置后重启 |

### 前置条件

```bash
# 1. 确保 Docker 运行
open -a Docker  # macOS

# 2. 构建镜像
make build
make build-images
```

### 快速使用

```bash
# 启动完整平台
bash scripts/local/start.sh

# 通过启动输出中的统一地址访问 Console、模块页面和 API

# 查看状态和资源使用
bash scripts/local/status.sh

# 停止服务（保留基础设施）
bash scripts/local/stop.sh

# 停止所有服务（包括基础设施）
bash scripts/local/stop.sh --all
```

### 特性

- ✅ **镜像验证**: 自动检查所有必需镜像是否存在
- ✅ **项目启动**: 通过 Infra 标准入口准备基础设施，再分别启动平台与内置 Runtime 两个 Compose project，并等待容器就绪
- ✅ **健康检查**: 等待关键服务健康检查通过
- ✅ **资源监控**: `status.sh` 显示 CPU、内存使用 Top 5

平台容器仅向宿主机发布 Nginx 入口。对外地址由 `ADDP_PUBLIC_ORIGIN` 指定，未设置时使用 `http://localhost:<实际 Nginx 发布端口>`（默认 80）；Backend、Gateway 和前端不另开放宿主机端口。生产容器部署使用同一规则。

详见: [local/README.md](../local/README.md)


## 五、生产服务器部署 (prod/)

**用途**: 在生产服务器上部署和管理 ADDP 平台

### 核心脚本

| 脚本 | 功能 | 使用场景 |
|------|------|---------|
| `start.sh` | 启动生产环境（分步启动） | 生产部署启动 |
| `stop.sh` | 停止生产环境 | 维护、停止服务 |
| `health-check.sh` | 健康检查 | 监控、故障排查 |
| `wait-infra.sh` | 等待基础设施就绪 | 启动流程中的依赖检查 |
| `swarm/` | 现存 Swarm 脚本 | 行为与部署缺口见生产指南 |

### 快速使用

```bash
# 启动完整生产环境
bash scripts/prod/start.sh

# 通过启动输出中的统一地址访问 Console、模块页面和 API

# 健康检查
bash scripts/prod/health-check.sh

# 停止平台与 Runtime 容器（保留 Infra、Business 服务及数据卷）
bash scripts/prod/stop.sh
```

### 启动流程

按“Infra 就绪 → System Backend 就绪 → 全部平台服务就绪 → 内置 Runtime 就绪”启动。平台和 Runtime 使用独立 Compose project，具体检查与等待行为见[生产启动指南](../prod/README.md#启动流程)。

### Docker Swarm 脚本状态

Swarm 脚本尚未形成与现行配置及验收闭合的生产流程。现存行为、初始化的集群操作范围和部署缺口统一见[生产指南](../prod/README.md#swarm)；服务器部署按上文 Compose 标准入口执行。

详见: [prod/README.md](../prod/README.md), [build/README.md](../build/README.md)
