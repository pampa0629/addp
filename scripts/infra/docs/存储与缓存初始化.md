# ADDP Infra：存储与缓存初始化

[返回 Infra 指南](../README.md)

## 模块化资源隔离架构

ADDP 采用**模块化资源隔离**架构,每个模块拥有独立的命名空间:

### MinIO Bucket 隔离

```
MinIO
├── system/             → System 模块（用户头像、系统配置、审计日志归档）
│   └── audit/          → 平台审计归档和实名查询留痕；租户存储身份不得访问
├── manager/            → Manager 模块（预览缓存、瓦片缓存对象）
│   └── tenant_<id>/vector-tile-cache/ → PMTiles 快显缓存对象，由 Manager API 按 storage_ref 访问
├── meta/               → Meta 模块（元数据相关文件）
├── transfer/           → Transfer 模块（传输临时文件）
├── orchestrator/       → Orchestrator 模块（编排文件）
├── develop/            → Develop 模块（查询结果导出）
├── service/            → Service 模块（服务注册文件）
└── graph/              → Graph 模块（知识图谱构建材料）
```

**访问契约**: `manager` bucket 应保持私有。预览缓存和瓦片缓存对象统一通过 Manager API 访问，前端不直接依赖 MinIO bucket 路径。初始化是否成功应用策略，按下文[初始化结果与验收](#init-miniosh)分别核对。

审计复用平台管理的 `system` 桶，固定使用 `audit/sources/<来源UUID>/` 和 `audit/queries/<实名UUID>/`。这不是租户目录，不用 `tenant_0` 表示平台。采集与审计分别使用限定前缀的专用身份，不复用 Infra root；租户普通身份无权访问该区域，最高 Infra 管理员仍在信任边界内。当前 `init-minio.sh` 使用普通建桶，不证明已有桶支持 Object Lock，也不自动给共享桶启用锁、对象锁默认保留或审计身份。部署前用 System 的只读 `check-store` 检查版本与锁状态，不满足时停止并明确处理，不删除、重建或迁移已有桶。详见 [平台审计归档](../../../system/README.md#平台审计归档)。

### Redis Key 命名规范

格式: `{module}:{middleware}:{function}:{id}`

示例:
```
meta:cache:scan_last_time:123                  → Meta 模块上次扫描时间
meta:scan:lock:tenant:1:engine:123:namespace:* → Meta 扫描范围锁
manager:tenant_1:cache:mvt:spatial:*           → Manager 空间瓦片缓存
cleanup:tasks:<task-id>                        → Cleanup 临时协调状态
```

Redis 不承载 ADDP bounded execution 队列。Quality、Meta 和 Transfer bounded
统一从 PostgreSQL `common.task_executions` claim execution；Redis 仅保存可重建的
缓存、事件、分布式锁、限流和临时协调状态。

### Meilisearch Index 命名规范

索引名称、主键、文档语义和设置由对应 Owner 维护，不统一套用 `{module}:{resource_type}` 模板。当前搜索投影按职责隔离：

| Owner | 投影范围 | 当前默认索引名 |
| --- | --- | --- |
| Manager | DataItem 技术元数据与正文内容 | `manager_content_documents` |
| Catalog | 企业元数据、责任、治理与目录可见性 | `catalog_entries` |
| Asset | 已发布资产 | `asset_published` |

Meta 通过 Manager 的正式接口提交技术与正文快照，不直接创建或读写 Manager 索引。Infra 只检查搜索服务，不预建跨模块共享索引；服务健康不表示 Owner 索引、设置或历史投影已就绪。具体边界见[企业资源目录搜索能力](../../../docs/concepts/addp企业资源目录体系图.md#六目录视图与搜索)、[DataItem 技术元数据搜索投影](../../../docs/spec/addp元数据扫描机制规范.md#dataitem-技术元数据搜索投影)和[Asset 模块说明](../../../asset/CLAUDE.md)。

## init-minio.sh

**功能**: 按[模块桶清单](#minio-bucket-隔离)创建缺失的普通 Bucket、复用已存在的 Bucket，并尝试应用 `manager` 桶策略。日志与 Trace 存储桶由各自的标准生命周期准备，不属于此模块桶清单，见[运行日志与 Trace 部署](运行日志.md)。

**初始化结果与验收**:

| 步骤 | 实际结果与边界 |
| --- | --- |
| 管理连接与建桶 | 在 MinIO 容器内通过管理身份配置 `mc` 连接；连接配置或建桶失败返回非零。已存在的桶不重建，前面已完成的桶创建不按整批回滚认定。管理连接成功不代替 Manager 用户授权或业务访问验证。 |
| `manager` 私有访问 | 每次尝试设置私有访问，失败只输出警告并继续。警告中的“可能已设置”不是现有策略的核验结果；须结合实际匿名访问限制与 Manager API 授权验证认定。 |
| `manager/temp/` 过期规则 | 每次尝试添加此前缀的七天过期规则，失败只输出警告并继续。“可能已存在”不证明规则一致；配置与对象过期效果须分别验证，不能推广为全桶清理或审计对象锁保留。 |

最终“初始化完成”提示或退出码为 0 不能证明私有策略、过期规则及完整业务链路均通过；未执行、失败或未覆盖的验证分别保留。

**访问地址**: 宿主 API／Console 的 `19000`／`19001` 只是首选端口，实际映射以 `bash scripts/infra/status.sh` 为准，规则见[环境与运行端口](环境与跨平台配置.md#配置文件说明)。本脚本的建桶连接使用容器内 `localhost:9000`，不以宿主映射作为建桶结果。

**使用示例**:
```bash
./scripts/infra/init-minio.sh
```

## init-meilisearch.sh

**功能**: 校验 Meilisearch API 健康，不创建业务索引。

脚本要求提供 `MEILISEARCH_MASTER_KEY`，通过 `MEILISEARCH_URL_LOCAL` 访问 `/health`，非成功响应返回错误。模块负责各自索引的创建、主键校验和设置安装；异步任务的完成与投影覆盖按 Owner 契约核验，不能以 Infra 脚本成功代替搜索验收。

**访问地址**: http://localhost:17700

**使用示例**:
```bash
./scripts/infra/init-meilisearch.sh
```

## init-redis.sh

**功能**: 查询 Redis 连接与统计，显示脚本内置的通道提示和模块键计数。

默认模式读取连接与统计信息；只有首个参数为 `--clean` 时进入清理分支。目标是根 Infra Compose 的 `redis` 服务，使用根环境中的认证配置；脚本不按 `REDIS_HOST`／`REDIS_PORT` 显示值连接远端，也不按模块 Key 前缀限定清理范围。

### 默认检查与结果判定

| 输出项 | 当前读取方式与验收边界 |
| --- | --- |
| 容器与连接 | 读取 Compose 容器状态并发送 `PING`，打印响应；当前按客户端进程退出状态进入成功分支，未断言响应恰为 `PONG`。输出供连接诊断，不代表业务身份授权或缓存、锁的行为已验证。 |
| Pub/Sub 通道提示 | `engine:changed`、`engine:deleted`、`meta:scan_completed` 来自脚本内置文本；没有执行发布、订阅或 `PUBSUB` 查询。名称和绿色勾号不证明当前存在订阅者、事件已送达，或消费后的业务动作已完成。 |
| 运行统计与持久化标签 | 分次读取 `INFO memory`、`INFO clients` 及 `CONFIG GET maxmemory/appendonly`，不属于同一采样时刻。AOF 关闭时脚本显示“RDB 快照”，但未检查 RDB 保存配置、最近快照或持久化结果；该标签不能作为恢复能力证明。 |
| 模块键计数 | 在默认库分别按 `meta:*`、`manager:*`、`cleanup:*` 执行 `redis-cli --scan --pattern`，逐条计数且不去重，随后另读一次 `DBSIZE`。三个前缀不是全部模块清单，计数之和不能当作全库总量；不同读取间的写入、删除和过期也会影响结果。 |

`SCAN` 可能重复返回元素，对扫描期间发生变化的元素不提供时点快照保证，详见[Redis SCAN 的迭代边界](https://redis.io/docs/latest/commands/scan/)。当前计数函数通过进程替换读取扫描输出，隐藏错误输出且未单独汇总扫描子进程失败；显示 0 不能直接作为该前缀确实无键的验收证据。

“Redis 检查完成”不表示事件链路、锁行为、持久化恢复或完整键空间快照已验证。事件验收须另核实际发布、订阅和对应业务结果；本入口只记录当次实际读取，失败、未执行及未覆盖项分别保留。Infra 整体状态与探针的分工见[生命周期脚本的验证范围](生命周期脚本.md#statussh)。

### 清理确认与结果判定

清理操作须先确认目标实例与授权范围。当前脚本只做提示确认，没有单独核验 Compose 工作区归属，也不会暂停应用写入。

| 阶段 | 当前实现与验收边界 |
| --- | --- |
| 确认或取消 | 通过 `read` 读取确认，只有准确输入 `yes` 才继续；其他已读取的回答取消并返回 0。输入读取失败会退出；没有自动确认参数。因此退出码为 0 也可能只是取消，须保留本次实际分支。 |
| 清理命令 | 执行 `FLUSHALL ASYNC`，作用于该 Redis 实例的全部数据库，不能当作只清理默认库或某个模块。脚本丢弃命令输出、只按客户端进程退出状态进入成功分支，未显式核对服务端 `OK` 回应；客户端调用返回与服务端确认须分别认定。当前调用也未使用 Redis CLI 的命令错误退出选项 `-e`，见[CLI 选项](https://redis.io/docs/latest/develop/tools/cli/)。 |
| 异步语义 | 后台内存释放与键空间结果分别判断；本次命令不影响调用后新创建的键。应用持续写入时，不能承诺检查时实例仍为空，也不能仅凭内存尚有占用判定逻辑清理失败。命令语义见[Redis FLUSHALL](https://redis.io/docs/latest/commands/flushall/)。 |
| 结果读取 | 仅打印一次 `DBSIZE` 和 `INFO memory`；没有断言键数必须为 0、逐库验证或等待后台释放完成。当前连接未指定数据库，`DBSIZE` 只观察默认库，不能证明全部数据库为空；见[Redis DBSIZE](https://redis.io/docs/latest/commands/dbsize/)。 |

脚本中的“Redis 已清空／清理完成”提示不是独立验收证据。应分别记录是否确认并执行、服务端是否确认命令、实际核对的数据库与键数，以及当时是否仍有业务写入；未执行、失败或未覆盖项不能计为通过。脚本没有执行客户端断开或订阅核验，也不能仅据提示文案认定 Pub/Sub 订阅已断开。

该入口保留容器和 Docker 数据卷，但这不表示键数据仍可恢复；本地备份不覆盖 Redis 的边界见[备份与隔离恢复](备份恢复与搜索迁移.md#本地-infra-备份与隔离恢复演练)。

**使用示例**:
```bash
# 验证连接和显示统计
./scripts/infra/init-redis.sh

# 仅在已授权且确认目标范围后请求清理，实际结果按上文分别核验
./scripts/infra/init-redis.sh --clean
```
