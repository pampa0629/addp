# 跨模块审计日志系统

## 概述

ADDP 平台实现了统一的跨模块审计日志系统。所有模块的审计日志都集中存储在 System 模块的 `system.audit_logs` 表中,通过 `module_name` 字段区分日志来源,便于统一查询和管理。

**核心特性**:
- 集中存储和查询
- 自动敏感信息脱敏
- 异步记录,不阻塞主请求
- 支持所有 7 个模块 (System, Manager, Meta, Transfer, Develop, Orchestrator, Service)

## 架构设计

### 核心组件

1. **审计中间件** (`common/middleware/audit/audit.go`)
   - 自动捕获 HTTP 请求信息
   - 异步发送审计日志到 System 模块

2. **System 内部 API** (`POST /internal/audit-logs`)
   - 接收来自其他模块的审计日志
   - 统一存储到 `system.audit_logs` 表

3. **SystemClient** (`common/client/system.go`)
   - 提供 `CreateAuditLog()` 方法
   - 处理日志脱敏和发送

### 数据流程

```
其他模块 HTTP 请求
    ↓
审计中间件捕获请求信息
    ↓
SystemClient.CreateAuditLog() (异步)
    ↓
POST /internal/audit-logs
    ↓
System 模块存储到 system.audit_logs
```

### 数据库 Schema

`system.audit_logs` 表关键字段:

| 字段名 | 类型 | 说明 |
|--------|------|------|
| id | SERIAL | 主键 |
| module_name | VARCHAR(50) | **模块名称** (system/manager/meta 等) |
| user_id | INTEGER | 用户 ID |
| username | VARCHAR | 用户名 |
| tenant_id | INTEGER | 租户 ID |
| action | VARCHAR | 操作 (如 "POST /api/engines/1/scan") |
| details | TEXT | 请求详情 (已脱敏) |
| ip_address | VARCHAR | 客户端 IP |
| created_at | TIMESTAMP | 创建时间 |

## 集成步骤

为新模块添加审计日志功能只需 3 步:

### 1. 导入审计中间件

在模块的 `internal/api/router.go` 中导入:

```go
import (
    "github.com/addp/common/middleware/audit"
    commonClient "github.com/addp/common/client"
)
```

### 2. 注册审计中间件

在认证中间件**之后**添加审计中间件:

```go
api := router.Group("/api")

// 认证中间件
api.Use(auth.SystemAuthMiddleware(cfg.SystemServiceURL))

// 审计日志中间件
if systemClient != nil {
    api.Use(audit.AuditMiddleware("模块名", systemClient))
}
```

### 3. 确保 SystemClient 已初始化

在 `cmd/server/main.go` 中:

```go
var systemClient *commonClient.SystemClient
if cfg.EnableIntegration && cfg.InternalAPIKey != "" {
    systemClient = commonClient.NewSystemClientWithInternalKey(
        cfg.SystemServiceURL,
        cfg.InternalAPIKey,
    )
}
```

完成后执行:

```bash
cd <模块>/backend
go mod tidy
go build -o server cmd/server/main.go
bash scripts/dev/restart.sh -<模块名>
```

## 关键特性

### 安全性

- **自动脱敏**: 自动脱敏 password、token、secret、api_key 等敏感字段
- **内部 API 认证**: 使用 `X-Internal-API-Key` 头部认证
- **租户隔离**: 记录 tenant_id 确保数据隔离

### 性能

- **异步记录**: 使用 goroutine 异步发送,延迟 < 1ms
- **不阻塞主请求**: 审计日志发送失败不影响主请求
- **Redis 缓存**: System 模块使用 Redis 缓存认证信息

### 可追溯性

- 记录用户 (user_id, username)
- 记录操作 (HTTP 方法和路径)
- 记录模块来源 (module_name)
- 记录时间 (精确到毫秒)
- 记录 IP 地址

## 使用指南

### 查询审计日志

**方法 1: 数据库查询**

```bash
PGPASSWORD=addp_password psql -h localhost -p 15432 -U addp -d addp -c "
SELECT id, module_name, action, username, ip_address, created_at
FROM system.audit_logs
WHERE module_name = 'manager'
ORDER BY created_at DESC
LIMIT 10;"
```

**方法 2: API 查询**

```bash
# 1. 登录获取 token
TOKEN=$(curl -s -X POST http://localhost:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"123456"}' | jq -r .access_token)

# 2. 查询审计日志
curl "http://localhost:8080/api/logs?page=1&page_size=20&module_name=manager" \
  -H "Authorization: Bearer $TOKEN" | jq
```

### 按模块统计

```sql
SELECT module_name, COUNT(*) as total, MAX(created_at) as latest
FROM system.audit_logs
GROUP BY module_name
ORDER BY total DESC;
```

### 导出审计日志

```bash
# CSV 格式
curl "http://localhost:8080/api/logs/export?format=csv&module_name=manager" \
  -H "Authorization: Bearer $TOKEN" > audit_logs.csv

# JSON 格式
curl "http://localhost:8080/api/logs/export?format=json&module_name=meta" \
  -H "Authorization: Bearer $TOKEN" > audit_logs.json
```

## 配置说明

### 必需的环境变量

```bash
# System 服务 URL
SYSTEM_SERVICE_URL=http://system-backend:8080

# 内部 API 密钥
INTERNAL_API_KEY=your-internal-api-key

# 启用服务集成
ENABLE_INTEGRATION=true
```

### 审计策略

- **记录范围**: 仅记录 POST、PUT、PATCH、DELETE 请求
- **排除路径**: GET 请求和内部 API (`/internal/*`) 不记录
- **脱敏规则**: 自动脱敏敏感字段,显示为 `***REDACTED***`
- **异步发送**: 审计日志异步发送,不阻塞主请求

## 故障处理

### 审计日志发送失败

如果 System 模块不可用,审计日志会发送失败,但**不会影响主请求**。错误会记录到模块的日志文件中:

```bash
tail -50 /Users/pampa/code/addp/logs/<模块>-backend.log | grep "audit"
```

### 重复记录问题

System 模块的日志中间件已配置为排除 `/internal/audit-logs`,避免重复记录。
