# 快显概念说明

> 状态：Manager 模块快显概念层文档。本文只说明 Manager 空间快显、矢量物化视图、矢量瓦片缓存、栅格 COG 和栅格 mosaic 的价值、概念、分工、边界和协作关系，不描述具体表结构、API 路由或实现算法。实现细节统一见 [快显实现规范](快显实现规范.md)。

## 一、价值定位

Manager 对空间数据有两类预览体验。

基础预览用于“看懂数据”：

1. 表格查看字段、属性、样本和记录。
2. 文本、图片或文件内容预览。
3. 轻量 GeoJSON、表格样本或抽样绘制查看空间形态。
4. 可以分页、抽样或降级，不承诺连续地图浏览体验。

地图快显用于“像浏览地图一样浏览空间数据”：

1. 能按完整空间范围全幅定位。
2. 能随缩放、拖拽连续加载。
3. 能在较大数据量下保持可接受响应。
4. 能复用矢量瓦片缓存、实时 MVT、中小规模 FlatGeobuf、小 TIFF 前端渲染、COG 前端渲染或 mosaic 后端瓦片渲染。

因此，快显不是任务，不是 MVT，不是 COG，不是 mosaic，也不是某张表。快显是 Manager 空间预览中的地图浏览模式；MVT、矢量物化视图、矢量瓦片缓存、栅格 COG 和栅格 mosaic 都只是支撑地图快显的渲染源或业务数据集。

## 二、核心概念

| 概念 | 含义 |
| --- | --- |
| basic preview | 基础预览模式，用于查看样本、属性、原始文件或普通格式预览。 |
| map quick view | 地图快显模式，Manager 空间预览中的连续地图浏览模式。 |
| quick view preference | 快显偏好，记录用户对某个 item 的预览模式偏好；只允许 `basic_preview` / `map_quick_view`。 |
| quick view state | 快显交互状态，记录基础预览和快显各自的地图视口或三维相机状态；只保存用户交互状态，不保存快显能力、产物或任务事实。 |
| quick view capability | 快显能力，查询时根据空间事实、支撑对象事实和引擎能力动态合成。 |
| render source | 快显渲染源，例如已缓存 MVT、实时 MVT、直接 FlatGeobuf、小 TIFF 前端渲染、COG 前端渲染或 mosaic 后端瓦片渲染。 |
| vector materialized view | 矢量物化视图，Manager 创建并拥有生命周期的 3857 可索引渲染目标。 |
| vector materialized view task | 矢量物化视图生成任务，显式创建或刷新 3857 渲染目标的任务定义。 |
| vector tile cache | 矢量瓦片缓存，Manager infra 中已经生成并可被复用的 PMTiles 快显 artifact。 |
| vector tile cache task | 矢量瓦片缓存生成任务，可手动执行或由编排触发；结果固定为 infra PMTiles，当前不支持任务自身定时调度。 |
| vector tile set | 矢量瓦片集，Business 存储中的 PMTiles v3 data item，可被 Meta、Service 和其他平台消费。 |
| vector tile set task | 矢量瓦片集生成任务，把空间 item 生成或把合格缓存固化为 Business PMTiles。 |
| raster COG | 栅格 COG，Manager 创建并拥有生命周期的 infra MinIO COG 快显结果。 |
| raster COG task | 栅格 COG 生成任务，把 TIFF/GeoTIFF 源 item 生成 Manager 受管 COG 的任务定义。 |
| raster mosaic | 栅格镶嵌数据集，由源 node 创建、写入用户选择的业务存储，并由 Meta 识别为 `data_type=media`、`format=raster_mosaic`、`layout=whole` 的业务 item。 |
| raster mosaic task | 栅格 mosaic 生成任务，把一个源 node 下的一批 TIFF/COG 生成 mosaic 业务数据集的任务定义。 |
| managed quick view task | 受管快显任务，为稳定源 item 的某一派生变体维护一个可重复执行的任务定义。 |
| managed quick view result | 受管快显结果，Manager 在 infra 中维护生命周期的当前 artifact；不是业务 data item。 |
| source spatial facts | 源空间事实，例如源 SRID、源 CRS、源 extent、几何列、记录数、栅格尺寸。 |
| render facts | 渲染事实，例如 WGS84 渲染范围、3857 瓦片目标、层级推荐。 |

## 三、对象分工

| 对象 | 职责 | 不承担 |
| --- | --- | --- |
| 空间数据项 | 提供源数据、源空间事实和统一 Resource Locator。 | 不保存快显偏好、支撑对象状态或任务配置。 |
| `preview_state` 偏好与交互状态 | 记录用户偏好的预览模式：`basic_preview` 或 `map_quick_view`；记录基础预览和快显各自的地图视口或三维相机状态。 | 不保存快显能力、渲染源、支撑对象状态、生成配置或执行历史。 |
| 快显能力 | 查询时回答当前能否地图快显、使用哪个渲染源、建议生成哪类支撑对象。 | 不作为长期事实表。 |
| 矢量物化视图 | 记录 Manager 自建 3857 可索引渲染目标是否 ready、在哪里、由哪次任务执行生成。 | 不表达任务定义，不替代执行记录；不登记外部只读 3857 目标。 |
| 矢量物化视图任务 | 记录以后按什么配置创建或刷新 3857 渲染目标。 | 不隐式随普通预览或矢量瓦片缓存生成执行；当前不做自身定时调度。 |
| 矢量瓦片缓存 | 记录 infra PMTiles 是否可用、在哪里、覆盖什么范围和层级。 | 不表达任务定义，不替代执行记录，不是业务 data item。 |
| 矢量瓦片缓存任务 | 记录以后按什么配置生成或刷新 infra PMTiles。 | 不保存每次执行历史，不承担任务自身定时调度。 |
| 矢量瓦片集 item | 作为 `media/pmtiles/single` 业务 item 记录在 Meta 中。 | 不进入 `manager.vector_tile_cache`，不依赖 Manager infra 生命周期。 |
| 矢量瓦片集任务 | 记录源 item、目标 Business 存储、目标名称和生成 profile。 | 不设 Manager 结果表；执行完成后以 Meta item 为结果。 |
| 栅格 COG | 记录 Manager 受管的 infra MinIO COG 是否可用、在哪里、源 item 是什么。 | 不表达任务定义，不替代执行记录，不暴露 NFS 或业务 MinIO 内部路径给前端。 |
| 栅格 COG 任务 | 记录以后按什么配置生成或刷新 COG。 | 不展开完整栅格算子体系，不生成 PNG/JPEG/WebP 图片瓦片。 |
| 栅格 mosaic item | 作为业务 item 记录在 Meta 中，数据集产物位于用户选择的业务存储。 | 不进入 Manager infra MinIO，不写入 `manager.raster_cog`，不把每个 leaf COG 自动升格为同级 Meta item。 |
| 栅格 mosaic 任务 | 记录以后按什么源 node、目标业务存储和策略生成 mosaic 数据集。 | 不保存每次执行历史，不作为 Manager 私有 artifact 结果表。 |
| 执行记录 | 记录某一次生成过程、状态、错误和结果摘要。 | 不作为长期支撑对象事实源。 |

## 四、页面结构

Console 和 Manager 的任务管理导航按生命周期分组：

```text
快显管理
├── 矢量快显 - 物化视图
├── 矢量快显 - 瓦片缓存
├── 栅格快显 - COG
└── 栅格快显 - Mosaic

空间任务
└── 矢量瓦片
```

“空间任务”是导航与能力分类，不新增统一任务表。当前“矢量瓦片”页面管理 `vector_tile_set_generation`，其任务定义仍归 `manager.vector_tile_set_tasks`。

矢量瓦片有两个入口，且必须进入同一个创建页面：

1. Console 数据管理中的“空间任务 → 矢量瓦片”，用于集中管理任务。
2. 选中可生成矢量瓦片的空间数据项后，数据预览操作栏中的“生成矢量瓦片”，用 ResourceLocator 预选来源。

快显管理页面内部统一分为：

```text
任务 / 结果
```

三类页面的含义：

| 页面 | 面向对象 | 说明 |
| --- | --- | --- |
| 矢量快显 - 物化视图 | 矢量物化视图及其任务 | 为 PostGIS 等矢量空间数据生成 Manager 自建 3857 可索引渲染目标。 |
| 矢量快显 - 瓦片缓存 | 矢量瓦片缓存及其任务 | 为矢量空间数据生成 Manager infra PMTiles 快显缓存。 |
| 空间任务 → 矢量瓦片 | 矢量瓦片集任务 | 为矢量空间数据生成 Business PMTiles，或把合格缓存保存为业务数据。 |
| 栅格快显 - COG | 栅格 COG 及其任务 | 为 TIFF/GeoTIFF 数据生成 Manager 受管 COG。 |
| 栅格快显 - Mosaic | 栅格 mosaic 任务 | 从源 node 生成业务级栅格镶嵌数据集 item。 |

不要把 MVT、COG 作为顶层预览模式展示。用户在数据预览页看到的是“基础预览 / 地图快显”，支撑对象的生成和管理放到“快显管理”；业务 PMTiles 的生成归“空间任务”。

## 五、边界原则

### 1. 使用统一资源身份

快显能力和数据出口以 Resource Locator 作为主身份。`schema/table` 只是数据库 provider 内部从 locator 解析出的参数，不是快显公共概念。

### 2. 预览偏好和支撑对象分离

`preview_state` 只表达用户偏好和预览交互状态：

```text
basic_preview
map_quick_view
```

预览交互状态统一保存在 `view_state`，顶层按 `basic_preview` / `quick_view` 区分显示模式，模式内按 `map` / `scene_3d` 区分渲染域。是否能地图快显、使用 MVT 还是 COG、是否已有缓存或 COG，都由 capability 动态合成，不能写回 `preview_state` 状态表。

### 3. 源事实和渲染事实分离

`capabilities.spatial.extent` 是源事实，只表达原生 CRS 下的范围。

地图快显、矢量瓦片缓存和 Web 地图默认视图需要的是渲染事实，例如 WGS84 渲染范围或 WebMercator 瓦片目标。渲染事实可以由引擎或支撑对象生成，但不能写回源 metadata facts。

### 4. 矢量和栅格支撑对象分离

矢量主路径：

```text
direct_flatgeobuf
realtime_tile
cached_tile
vector_materialized_view
vector_tile_cache
```

`direct_flatgeobuf` 是中小规模矢量数据的默认直接快显材料。GeoJSON 从技术层面保留，用于基础预览、小样本、人类可读查看或调试，不作为地图快显的默认推荐渲染源。

栅格主路径：

```text
direct_tiff_client
client_cog_render
raster_cog
raster_mosaic_tile
raster_mosaic_leaf_cog
```

TIFF / COG 栅格快显第一阶段不使用矢量瓦片缓存。小 TIFF 通过 `direct_tiff_client` 由前端读取并渲染；大 TIFF 返回 `requires_cog_generation` 或 `requires_managed_cog`，引导生成 Manager 受管的 infra MinIO COG。图片瓦片缓存属于未来发布阶段，不进入第一阶段 Manager 快显主路径。

Raster mosaic 是另一条栅格快显路线。它不是 Manager infra COG，不是单文件 COG，也不是几千个 TIFF 的临时预览集合。用户从源 node 创建 `raster_mosaic_generation` 任务，并选择目标业务存储；任务生成 leaf COG、全局 overview COG、index、manifest 等业务数据集组成，Meta 识别后形成 mosaic 业务 item。mosaic 主预览以后端瓦片渲染为主，前端只消费 Manager 统一瓦片接口和单 leaf COG 查看能力。

TIFF 的 `.tfw`、`.hdr`、`.aux.xml`、`.ovr` 等 related refs 只参与数据项边界、基础预览和内容查看。地图快显展示的是整个空间 TIFF item 或其 Manager 受管 COG 结果，不展示单个 related ref 切换入口；用户回到基础预览后再查看 sidecar 文本或辅助文件。

### 5. MVT 和 COG 是实现细节，不是预览模式

PMTiles 是批量矢量瓦片的归档格式，MVT 是内部单瓦片编码。快显缓存任务类型为 `vector_tile_cache_generation`，业务瓦片集任务类型为 `vector_tile_set_generation`；二者共享生成 profile，但拥有不同任务身份和生命周期。

COG 是 TIFF/GeoTIFF 的云优化布局和 Manager 受管栅格快显结果。任务概念应是“栅格 COG 生成”，任务类型为 `raster_cog_generation`。

Mosaic 是业务级栅格镶嵌数据集。任务概念应是“栅格 mosaic 生成”，任务类型为 `raster_mosaic_generation`。mosaic 结果进入业务存储和 Meta item，不进入 `manager.raster_cog`。

### 6. 数据源加工必须显式

创建物化视图、空间索引、统计信息、COG 文件等属于派生准备动作。它们不修改原始业务记录，但会创建或刷新支撑对象。

这类动作必须由任务配置或用户操作显式授权，不得在普通预览、普通瓦片请求或普通 COG 读取中隐式执行。

### 7. 外部 3857 目标只读消费

同源 schema 下已有、可轻量校验的外部 3857 物化视图可以作为只读矢量物化视图目标被动态 MVT 和矢量瓦片缓存生成消费。它不写入 `manager.vector_materialized_view`，不进入矢量物化视图结果列表，也不获得 Manager 的刷新、删除或 stale 生命周期。

Manager 自建目标、自动识别外部目标和未来人工登记外部目标是三个不同概念，不能混用同一结果状态表达。

### 8. 受管快显任务必须有统一语义身份

Manager 受管快显任务的语义身份统一为：

```text
tenant_id + item_fingerprint + artifact_variant
```

`item_fingerprint` 是稳定源 item 身份，已包含引擎和完整路径语义。`item_id`、`locator`、`source_engine_id` 用于执行、回查和展示，不重复组成任务主身份。`artifact_variant` 表达同源上的不同当前结果，例如 3D Tiles 与 S3M。

重复创建同一语义任务时复用原任务定义；用户再次执行该任务时创建新 execution，并刷新同一当前结果。源内容是否变化另由 source version 判断，不通过改变 item fingerprint 或新建重复任务表达。

## 六、协作流程

### 1. 空间预览页

用户打开空间 item 后，Manager 展示基础预览，并查询快显能力。

能力查询根据源事实、已有支撑对象、数据量和可用渲染路径，返回：

1. 当前是否可地图快显。
2. 推荐渲染源。
3. 当前用户偏好。
4. 建议生成哪类支撑对象。
5. 不可用原因或推荐说明。

### 2. 直接地图快显

满足以下任一条件时可直接地图快显：

1. 有 ready 的矢量瓦片缓存。
2. 矢量数据量在直接快显预算内，可直接读取 Manager 生成的 FlatGeobuf 快显材料。
3. 有低成本实时 MVT 路径。
4. 空间 TIFF 在浏览器预算内，可由前端 `geotiff.js` 全量读取渲染。
5. 数据项存在 ready 的 Manager 受管 COG，可由前端 `geotiff.js` 通过 HTTP Range 渲染。
6. 数据项是 ready 的 raster mosaic item，可由 Manager 后端按 overview COG、低层级 tiles 或 leaf COG window 返回栅格瓦片。
7. 后续扩展中，数据项暴露可消费的外部瓦片服务。

### 3. 生成矢量物化视图

PG 空间表存在源表转换慢路径、动态 MVT 超时或大数据量风险时，预览页应优先引导用户执行“矢量快显 - 物化视图”。该任务创建 Manager 管理的 3857 可索引目标；动态 MVT 和矢量瓦片缓存生成会优先复用 Manager ready 目标，也会复用同源 schema 下可验证的外部 3857 只读目标。

### 4. 生成矢量瓦片缓存

不能稳定直接地图快显但可生成缓存时，预览页跳转到“矢量快显 - 瓦片缓存”的任务 tab。用户确认范围、层级、格式、目标存储和选项后创建任务，再选择是否执行。

生成完成后，矢量瓦片缓存结果进入结果状态。下一次快显能力查询自然可选择该结果。

### 5. 生成栅格 COG

大 TIFF 或源 COG 尚未成为 Manager 受管 COG 时，预览页引导用户执行“栅格快显 - COG”。任务由 Manager 派生 GDAL source / target 参数，通过 GeoPython Workflow 的 `tiff_to_cog` 生成 infra MinIO COG，并登记为 Manager 受管 COG。

生成完成后，下一次快显能力查询返回 `client_cog_render`，前端通过 Manager COG 内容接口和 HTTP Range 渲染。

栅格快显的默认地图底图顺序应与矢量快显保持一致：优先使用平台配置中的天地图矢量 / 影像底图，高德仅作为最后兜底。

### 6. 生成栅格 mosaic

源 node 下存在一批需要整体浏览的 TIFF/COG 时，预览或资源树入口引导用户执行“栅格快显 - Mosaic”。用户选择目标业务存储后创建 `raster_mosaic_generation` 任务。任务纳入 ADDP 任务体系，由 GeoPython Workflow 承担重型 GDAL 处理，生成或引用通过内容级校验的 leaf COG、全局 overview COG、index 和 manifest。

生成完成后，Meta 扫描目标业务存储，形成 `format=raster_mosaic` 的业务 item。下一次快显能力查询返回 mosaic 后端瓦片渲染源；前端不直接拼接几千个 COG。

## 七、已收敛的问题

以下问题的结论已经并入当前概念和实现规范，不再保留单独跟踪文档：

1. 大表快显定位必须使用 WGS84 渲染范围，不能把源 CRS extent 当作地图初始范围。
2. 矢量瓦片缓存任务默认层级必须来自能力诊断和层级推荐，不能固定套用 `0-18`。
3. 动态 MVT 需要区分 `ok`、`empty`、`timeout`、`degraded`，不能把超时或降级瓦片永久当作真实空瓦片。
4. 矢量瓦片缓存生成必须复用动态 MVT 的可索引 3857 目标解析，不再另起准备路径。
5. 命中矢量瓦片缓存或动态 MVT 时，前后端都必须有瓦片体积、解码大小和并发保护。
6. 重复执行矢量瓦片缓存任务表达刷新当前结果，必须清理旧对象前缀并失效运行时缓存。
7. 自动识别外部 3857 目标只读消费，不进入 Manager 自建矢量物化视图生命周期。

## 八、与其他模块的关系

| 模块 | 协作方式 |
| --- | --- |
| Meta | 提供已扫描源 facts，不承载快显支撑对象。 |
| Manager | 拥有快显能力、矢量物化视图、infra PMTiles 缓存、栅格 COG 及其任务，并提供业务 PMTiles 与 raster mosaic 任务入口。 |
| Orchestrator / Monitor | 发现、执行和监控 `vector_materialized_view_generation`、`vector_tile_cache_generation`、`vector_tile_set_generation`、`raster_cog_generation` 与 `raster_mosaic_generation` 任务。 |
