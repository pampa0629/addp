# 快显问题与改造思路

> 状态：Manager 模块快显改造跟踪文档。稳定概念见 [快显概念总览](快显概念总览.md)，规范和技术路线见 [快显规范与技术路线](快显规范与技术路线.md)。

## 一、当前结论

快显相关文档已从平台级 `docs/next` 收敛到 Manager 模块文档。当前长期入口为：

- [快显概念总览](快显概念总览.md)：说明价值、概念、分工、边界与协作。
- [快显规范与技术路线](快显规范与技术路线.md)：说明表结构、API、MVT 路线、缓存生成和执行 metadata。
- 本文：只记录已解决问题、剩余风险和下一步专题。

当前实现已经形成单一路线：

1. `manager.quick_view` 只保存预览模式偏好。
2. 快显能力由 API 动态合成，不写回 `quick_view`。
3. `manager.tile_cache` 保存瓦片缓存结果状态。
4. `manager.tile_cache_tasks` 保存瓦片缓存生成任务定义。
5. `tile_cache_generation` 是任务类型，`mvt` 是瓦片格式。
6. 动态 MVT 和瓦片缓存生成共享可索引 3857 目标判断。
7. 普通预览、普通瓦片请求不得隐式执行准备动作。
8. 缺少可索引 3857 目标时，动态 MVT 和瓦片缓存生成仍可进行；能力查询和任务执行应给出快显性能优化推荐和诊断，不把优化结果作为所有 MVT 或瓦片缓存生成的强制前置条件。
9. 没有 ready 快显性能优化目标时，动态 MVT 快显仍可开放，但必须标记慢路径并受单瓦片响应时间预算、超时保护和体积保护约束；瓦片缓存生成不做数据量限制，但应给出更强优化提示。
10. Manager 前端已提供独立的快显性能优化任务和结果页面，空间预览和瓦片缓存创建页会根据 capability 与瓦片响应头引导用户先执行快显优化，再生成瓦片缓存。

## 二、已关闭问题

### 1. 大表快显定位错误

状态：已解决。

`public.dltb` 源 extent 为 EPSG:2360，旧实现没有返回 Web 地图可直接消费的 WGS84 渲染范围，导致快显初始视图落到默认位置。当前 capability 已返回渲染用 WGS84 extent，前端不再依赖源 CRS extent 直接定位。

### 2. 瓦片缓存任务默认层级不合理

状态：已解决。

任务创建页不再固定默认 `0-18`。后端输出 `zoom_recommendation`，其中：

- `min_zoom` 面向全幅显示。
- `max_zoom` 面向缓存与动态 MVT 的责任边界。

前端优先使用 capability 推荐层级，缺少可靠范围时不强行套用硬编码层级。

### 3. 动态 MVT 局部缺块后不再重试

状态：已解决。

后端通过 `X-ADDP-Tile-Status` 区分 `ok`、`empty`、`timeout`、`degraded`。前端对 `timeout/degraded` 使用短 TTL 冷却和自然重试，不再把超时或降级瓦片永久当作真实空瓦片。

### 4. 缓存生成未复用 3857 目标

状态：主路径已解决。

瓦片缓存生成执行阶段已复用动态 MVT 的可索引 3857 目标解析。非 3857 源表优先使用 Manager 登记为 ready 的 3857 优化目标；缺少 ready 优化目标时仍可使用源表生成，不做数据量限制，并必须在 execution metadata 中记录更强的快显性能优化推荐。

剩余边界：

缺少 ready 快显性能优化目标时不自动创建派生对象；用户通过独立的快显性能优化任务显式创建和刷新。

### 5. 命中瓦片缓存后浏览器崩溃

状态：已解决。

当前保护链路包括：

- 后端默认 MVT `extent=1024` 起步。
- buffer 随 extent 递减，使用 `extent/32`，限制在 `8-64`。
- 缓存生成单瓦片原始 MVT 默认阈值为 `4MB`。
- 超阈值瓦片按 `1024 -> 512 -> 256` 降级。
- 最小 extent 仍超限时跳过该瓦片，不写入缓存。
- 前端 VectorTile `cacheSize=64`。
- 前端地图 `maxTilesLoading=8`。
- 前端解码前限制解压后 MVT 大小，默认 `8MB`。
- execution metadata 记录 `oversized_skipped_tiles`。

实测样本中，`z8/205/111` 原始 MVT 体积随 extent 降低显著下降：

| extent / buffer | 原始 MVT 体积 |
| --- | ---: |
| `2048 / 64` | `61MB` |
| `1024 / 32` | `24MB` |
| `512 / 16` | `7.9MB` |
| `256 / 8` | `2.0MB` |

### 6. 同一页面多次缩放平移后局部瓦片消失

状态：已解决。

旧实现曾在 `movestart` 中主动 abort 不同层级的瓦片请求，可能让 OpenLayers source 中的 tile 停留在非终态。当前前端不再在正常缩放、平移过程中主动取消 OpenLayers 管理的瓦片请求，只在组件卸载时清理未完成请求。

### 7. 重复生成后命中旧缓存

状态：已解决。

重复执行已有缓存任务时会先清理旧对象前缀；重复执行或删除已有缓存结果时，会按 `tile_cache:{id}` 自动清理 Redis 和内存 LRU 运行时瓦片缓存。

## 三、当前保留的诊断能力

1. MVT 网格调试层只在开启网格时显示，按当前屏幕可见瓦片绘制。
2. 网格标签显示 `z/x/y`，并可按 `ok/empty/timeout/degraded/error/cache/dynamic` 标注状态。
3. 任务详情展示瓦片统计摘要。
4. 核心统计口径为：

```text
已处理瓦片 = 生成瓦片 + 空瓦片 + 跳过瓦片 + 失败瓦片
```

5. execution metadata 记录：

- `tiles_total_estimate`
- `tiles_processed`
- `generated_tiles`
- `empty_tiles`
- `skipped_tiles`
- `failed_tiles`
- `oversized_skipped_tiles`
- `total_size_bytes`
- `max_tile_size_bytes`
- `min_tile_size_bytes`
- `zoom_levels`
- `tile_generation_target`
- `refresh_actions`
- `source_srid`
- `target_srid`
- `extent_srid`

## 四、剩余专题

### 快显性能优化 UI 与结果闭环

状态：已解决。

当前交互闭环：

1. 空间预览处于动态 MVT 慢路径或瓦片返回 `suppress_tile` 时，提示执行快显性能优化。
2. 快显性能优化页面可以创建、编辑、执行任务，并查看优化结果。
3. ready 优化结果可以跳转到瓦片缓存任务创建页。
4. 瓦片缓存任务创建页发现非 3857 慢路径且没有 ready 优化结果时，提示先执行快显性能优化。

### ready 快显性能优化目标缺失时的处理策略

当前已确定的边界：

1. 动态 MVT 和大数据量缓存生成应优先使用可索引 3857 目标；缺少 ready 优化目标时给出优化推荐和诊断。
2. 普通预览和普通瓦片请求不得隐式准备派生产物。
3. 缺少 ready 快显性能优化目标时，动态 MVT 快显按响应时间预算开放；超时后应提示快显性能优化并抑制同 tile key 反复请求。
4. 缺少 ready 快显性能优化目标时，瓦片缓存生成不做数据量限制，但要记录更强推荐与风险提示。

后续专题需要回答：

1. 动态 MVT 响应时间验证：按 `快显规范与技术路线.md` 的验证方案，给出无 ready 快显性能优化目标和有 ready 快显性能优化目标两组响应时间预算、提示等级、超时重试策略和运行时保护配置建议。
2. 外部已有 3857 目标的登记、校验、消费和删除边界。
3. 多尺度快显优化目标的命名、生命周期、刷新和删除策略。
4. 大表快显性能优化期间的锁、并发、失败恢复和进度统计。
5. 快显性能优化目标与源表 schema / geometry column 变化之间的失效规则。
