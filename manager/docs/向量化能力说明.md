# Manager 向量化能力说明

> 本文是 Manager 模块内向量化能力的实现与契约说明。概念边界见 [向量化概念说明](向量化概念说明.md)。向量化当前归属 Manager，不作为平台级横向规范单独放在根 `docs/concepts` 或 `docs/spec` 中。

## 定位

向量化是 Manager 面向数据检索提供的派生能力。Manager 对可支持的数据项生成向量表示，写入 `manager.embeddings` artifact state，使检索可以在关键词和全文检索之外消费语义向量结果。

当前实现遵循以下结论：

1. UI 统一叫“向量化”，英文 API、表名和 TaskProvider `task_type` 统一使用 `embedding`。
2. 向量化对象只允许是 data item；node 只是批量选择范围，不产生 node 向量结果。
3. 资源树 item / node 点击向量化都是一次性 execution，不创建 `manager.embedding_tasks`。
4. 独立向量化页面创建的配置才是向量化任务定义，进入 TaskProvider、调度和 Orchestrator。
5. 向量化结果是 artifact state，不是 execution status；搜索必须消费结果状态。
6. 每个租户在一次执行中只解析一个有效 Model Profile；不支持隐藏 fallback、多向量空间并存或调用方直连 Provider。
7. 向量化结果按 `tenant_id + item_fingerprint` 去重；`item_id` 是当前 Meta item 行引用，不作为去重主键。
8. Meilisearch 不保存向量结果状态；Manager pgvector 保存向量内容和结果状态。

## 数据模型

### `manager.embeddings`

`manager.embeddings` 表达某个 data item 当前留下的向量化结果状态。

核心字段：

| 字段 | 说明 |
| --- | --- |
| `tenant_id` | 租户隔离。 |
| `item_fingerprint` | 标准 data item 指纹，和 `tenant_id` 组成唯一身份。 |
| `item_id` | 当前 Meta item 行引用，用于回查 item 和刷新 locator。 |
| `engine_id` | 支撑按引擎过滤、engine 删除清理和资源树局部刷新。 |
| `locator` | 标准 ResourceLocator，用于结果页、检索命中和资源树回跳。 |
| `source_version` | 源 item 的可向量化内容版本，用于判断是否过期。 |
| `embedding` | pgvector 向量内容，仅 `ready` 时可被检索消费。 |
| `model_profile_id` / `profile_version` / `deployment_id` / `dimension` | Inference 返回的执行快照，用于绑定变化和维度变化后的过滤或过期判断。 |
| `status` / `status_reason` / `error_message` | artifact state 状态、稳定原因码和错误摘要。 |
| `last_execution_id` | 最近一次更新该结果的 execution。 |
| `vectorized_at` | 最近一次成功生成向量的时间。 |

状态只允许：

| 状态 | 含义 | 可检索 |
| --- | --- | --- |
| `ready` | 当前向量可用。 | 是 |
| `outdated` | 曾经生成过向量，但源内容、模型或维度已变化。 | 否 |
| `failed` | 最近一次向量化失败。 | 否 |
| `unsupported` | 当前 item 不满足向量化条件。 | 否 |
| `missing_source` | 源 item 或内容缺失。 | 否 |

约束：

- 同一个 `tenant_id + item_fingerprint` 只允许一条当前结果。
- `bucket/path/name/file_size/content_type/modality` 不作为核心字段长期扩张；需要展示时从 Meta item、locator 或 execution 派生。
- `modality` 不进入结果身份，不进入查询过滤。
- 搜索只消费 `status=ready` 且 `tenant_id/model_profile_id/profile_version/dimension` 匹配的结果。

### `manager.embedding_tasks`

`manager.embedding_tasks` 表达“未来按什么范围和策略反复执行向量化”的任务定义。只有独立向量化页面创建的配置才写入该表。

公共字段遵守任务体系规范：

| 字段 | 说明 |
| --- | --- |
| `enabled` | 是否启用任务。 |
| `schedule` | 调度表达式。空值表示只手动执行。 |
| `next_run_at` | 下次计划运行时间。 |
| `last_run_at` | 最近运行时间。 |
| `last_execution_id` / `last_execution_status` | 最近一次 execution 摘要。 |
| `created_by` / `created_at` / `updated_at` / `deleted_at` | 任务定义生命周期字段。 |

私有配置保存在 `config` JSONB：

```json
{
  "target": {
    "scope": "node",
    "engine_id": 1,
    "node_id": 23,
    "locator": "addp://engine/1/path/addp/reports?type=directory&node_id=23",
    "recursive": true
  },
  "filters": {
    "max_file_size_mb": 10
  },
  "embedding": {
    "model_profile_id": "3f459424-20ad-45b4-8981-cf3f05bf1b16",
    "profile_version": 3,
    "deployment_id": "7bca3220-ab87-4695-9326-cd18b83ec118",
    "dimension": 2560,
    "binding_version": 2
  }
}
```

约束：

- 持久化任务范围以 node 或等价范围为主；单 item 向量化优先走资源树一次性 execution。
- `filters` 不能替代 item 级可向量化判断；执行时仍逐 item 判断格式、大小和内容可读性。
- `embedding.model_profile_id`、`embedding.profile_version`、`embedding.deployment_id`、`embedding.dimension` 和 `embedding.binding_version` 是配置或执行快照；执行时必须与 Manager 当前有效场景绑定一致。

## 执行语义

### 一次性向量化

资源树 item / node 向量化走一次性 execution：

```http
POST /api/v1/manager/embedding_executions
```

要求：

- item 范围必须解析到 `item_id`、`item_fingerprint` 和 locator。
- node 范围只作为范围选择器，执行时枚举其下 data item。
- item / node ad-hoc 都创建 `common.task_executions`。
- 响应直接返回 `execution_id` 和 execution status。
- 长期状态查询使用 `/executions/{execution_id}` 和 `manager.embeddings`，不使用进程内 `TaskTracker`。

### 向量化任务执行

持久化任务执行通过 TaskProvider 标准入口：

```http
GET  /api/v1/manager/tasks?task_type=embedding
GET  /api/v1/manager/tasks/embedding/{id}
POST /api/v1/manager/tasks/embedding/{id}/execute
GET  /api/v1/manager/executions/{execution_id}
```

执行记录写入：

| 字段 | 取值 |
| --- | --- |
| `module` | `manager` |
| `task_type` | `embedding` |
| `source_task_id` | `manager.embedding_tasks.id` 的十进制字符串 |
| `source_task_name` | 任务名称 |
| `trigger_type` | `manual` / `scheduled` |
| `execution_config` | 任务定义当时的完整范围和策略快照 |
| `metadata` | 范围级结果统计 |

ad-hoc execution 不写 `source_task_id`，但必须写完整 `execution_config`。

### 重复执行

每个 item 执行时遵循同一条主路径：

1. 计算 `item_fingerprint` 和 `source_version`。
2. 判断 item 是否支持向量化。
3. 查询现有向量化结果。
4. 如果现有结果 `ready` 且 `source_version/model/dimension` 均匹配，记录 `ready_skipped`。
5. 如果过期、失败、缺失或配置不匹配，重新读取内容并生成向量。
6. 成功后 upsert 为 `ready`。
7. 不支持、源缺失或失败时写入对应非 ready 状态。

执行统计至少包含：

| 字段 | 说明 |
| --- | --- |
| `total` | 枚举到的 item 数。 |
| `ready_skipped` | 已 ready 且未过期而跳过的 item 数。 |
| `generated` | 新生成的 item 数。 |
| `rebuilt` | 覆盖重建的 item 数。 |
| `unsupported` | 不支持向量化的 item 数。 |
| `missing_source` | 源缺失的 item 数。 |
| `failed` | 失败的 item 数。 |

## TaskProvider 能力

Manager 作为单一 TaskProvider 声明 `vector_tile_cache_generation`、`vector_materialized_view_generation` 和 `embedding`，不得拆成 `manager_vector_tile_cache` / `manager_quick_view` / `manager_embedding`。MVT 是瓦片缓存格式，不是任务类型。

`embedding` task type 必须满足：

```json
{
  "type": "embedding",
  "display_name": "向量化",
  "description": "对数据项执行向量化并生成可检索向量结果",
  "definition_schema": { "type": "object" },
  "supports_schedule": true,
  "supports_cancel": false,
  "supports_inline_execution": false,
  "create_url": "/manager/vectorization-tasks?create=1",
  "edit_url": "/manager/vectorization-tasks?task_id=:id",
  "deprecated": false
}
```

约束：

- `supports_schedule=true` 表示独立页面创建的向量化任务支持定时调度。
- 具体任务详情返回空的闭合 `execution_contract.input_schema`；当前不支持执行参数覆盖，`POST /tasks/embedding/{id}/execute` 必须拒绝非空 `parameters`。
- 资源树一次性向量化不是 TaskProvider inline execution，`supports_inline_execution=false`。
- 未实现真实取消前不得声明 `supports_cancel=true`。

## API 契约

英文 API 统一使用 `embedding`。`vectorization` 只作为中文“向量化”的概念翻译，不作为 Manager API 路径、TaskProvider `task_type` 或长期字段命名。

### 一次性执行

```http
POST /api/v1/manager/embedding_executions
```

请求：

```json
{
  "scope": "item",
  "target": {
    "engine_id": 1,
    "item_id": 123,
    "locator": "addp://engine/1/path/addp/reports/a.pdf?type=object&item_id=123"
  }
}
```

响应：

```json
{
  "execution_id": "0f58d8c8-1f7b-4e3a-ae65-d61b41f9b77f",
  "status": "running"
}
```

约束：

1. 该接口只创建一次性 execution，不创建任务定义。
2. `scope=item` 时必须能解析到 `item_id`。
3. `scope=node` 时必须能解析到 `node_id`，执行时枚举范围内 item。
4. 响应必须直接返回统一 `execution_id`。

### 查询向量化结果

```http
GET /api/v1/manager/embeddings
```

查询参数：

| 参数 | 说明 |
| --- | --- |
| `page` / `page_size` | 分页。 |
| `engine_id` | 按 engine 过滤。 |
| `node_id` | 按 node 范围过滤，需由 Manager 解析为 item 集合。 |
| `item_id` | 按 item 过滤。 |
| `status` | 按结果状态过滤。 |
| `q` | 按 locator、item 指纹或错误摘要搜索。 |

响应中的核心字段来自 `manager.embeddings`，可补充从 Meta 派生的展示字段，但不得替代 artifact state 核心字段。

### 查询 item 向量化状态

```http
GET /api/v1/manager/items/{item_id}/embedding
```

已有结果时响应：

```json
{
  "item_id": 123,
  "item_fingerprint": "43788d99024bc40b4b7d19ed651f68014d18fa0199a1fb8d471cffb9897b67e4",
  "has_embedding": true,
  "embedding": {
    "result_id": 1,
    "status": "ready",
    "model": "qwen3-vl-embedding",
    "dimension": 2560,
    "vectorized_at": "2026-06-09T10:05:00Z"
  }
}
```

资源树 item 使用该接口判断是否展示“向量化”按钮。`has_embedding=true` 且 `embedding.status=ready` 且未过期时，只展示“已向量化”提示，不展示向量化按钮。

### 删除向量化结果

```http
DELETE /api/v1/manager/embeddings/{id}
```

删除只删除 Manager 向量化结果，不删除源 item。删除后检索不得再消费该结果。

### 向量化任务 CRUD

Manager 私有 UI 使用：

```http
GET    /api/v1/manager/embedding_tasks
POST   /api/v1/manager/embedding_tasks
GET    /api/v1/manager/embedding_tasks/{id}
PUT    /api/v1/manager/embedding_tasks/{id}
DELETE /api/v1/manager/embedding_tasks/{id}
```

TaskProvider 标准入口保持：

```http
GET  /api/v1/manager/tasks?task_type=embedding
GET  /api/v1/manager/tasks/embedding/{id}
POST /api/v1/manager/tasks/embedding/{id}/execute
GET  /api/v1/manager/executions/{execution_id}
```

私有 UI CRUD 不替代 TaskProvider 标准入口。Orchestrator 只能通过 TaskProvider 标准入口发现和执行向量化任务。

## 检索消费

Manager 混合检索可以在全文 / 关键词检索之外消费向量化结果。

查询要求：

1. 必须按租户隔离。
2. 只消费 `status=ready`。
3. 必须过滤当前启用 `model` 和 `dimension`。
4. 返回结果必须带 locator，供前端回到资源树或预览。
5. 向量服务不可用、pgvector 不可用或没有 ready 结果时，退化为全文 / 关键词检索。

Meilisearch 只作为全文和属性检索事实源，不保存向量结果状态，也不作为判断 item 是否已向量化的依据。

## UI 行为

### 资源树入口

| 对象 | 行为 |
| --- | --- |
| 支持向量化且无结果的 item | 展示“向量化”操作。 |
| `ready` item | 展示“已向量化”提示，不展示向量化按钮。 |
| `outdated` / `failed` item | 展示“重新向量化”操作。 |
| `unsupported` item | 展示“不支持向量化”提示。 |
| node | 可展示“向量化”操作；执行时枚举 item 并逐个跳过 ready。 |

是否展示 item 操作由 `GET /api/v1/manager/items/{item_id}/embedding` 和前端可支持格式判断共同决定。

### 独立向量化页面

独立页面名称使用“向量化”，默认展示“向量化任务”视图，并包含：

| 视图 | 说明 |
| --- | --- |
| 向量化任务 | 管理 `manager.embedding_tasks`，支持创建、编辑、执行、调度、删除、结果查看和跳转监控。 |
| 向量化结果 | 展示 `manager.embeddings`，支持状态筛选、资源定位、重新向量化、删除和跳转监控。 |

任务创建 / 编辑要求：

- 通过资源树选择 node 或 item。
- 调度使用 common frontend 的 `ScheduleConfig`，不要求用户手写 Cron。
- 默认展示全部支持扩展名，不要求用户填写。
- 最大文件大小提供合理默认值，当前默认 `10MB`。
- 界面展示引擎名称，不展示内部 engine id。
- 结果页不展示 locator 和 execution id，改用“定位”和“监控”操作。

## 配置

向量检索距离、文件大小和批处理并发等业务策略使用 `platform_only` 范围；`semantic_search_embedding` Model Profile 绑定使用 `platform_default_with_tenant_override`，Tenant 可以选择 Inference 已授权给本 Tenant 的 Profile，但不能在 Manager 中建立 Provider 连接。

### 配置管理职责

| 组件或角色 | 职责 |
| --- | --- |
| Manager Backend | 定义、校验、保存、读取和应用向量化配置，执行最终 Platform Context 与 Permission 校验。 |
| Manager Frontend | 提供模型配置、连接检查、变更影响和生效状态页面，同时保持 standalone 模式可用。 |
| System | 登记 Manager 发布的配置管理入口，提供 AuthContext、Permission 和统一审计；不保存模型配置值。 |
| Console | 在当前 Platform 或 Tenant Context 的统一配置入口中加载 Manager 配置页面；不生成字段表单或解释模型语义。 |
| Platform System Administrator | 维护平台向量化策略和默认 Profile 绑定。 |
| Tenant Administrator | 可覆盖本 Tenant 的 `semantic_search_embedding` Profile 绑定。 |
| Inference Administrator | 在 Inference owner 页面维护 Provider Credential、Deployment 和 Profile。 |

Manager 通过 `addp.configuration-management/v1` 发布稳定管理入口，声明 `platform_default_with_tenant_override`、前端路由和 Manager 自己的读写 Permission；声明不发布具体配置键、当前值或 Secret。页面在 Platform Context 同时维护平台策略和默认绑定，在 Tenant Context 只维护 Tenant 场景绑定。

### 字段边界

| 字段 | 来源 | 生效和约束 |
| --- | --- | --- |
| Model Profile | Manager 场景绑定 | Platform 默认可被 Tenant 显式覆盖；Profile 解析失败直接报错。 |
| Provider endpoint 与上游模型 | Inference 强类型资源 | Manager 不读取或保存；由 Profile 解析到 Deployment。 |
| 请求 timeout | Inference Runtime | 只影响新请求，运行中的 execution 保持启动时快照。 |
| 向量检索最大距离 | Manager 平台配置 | 当前默认 `0.78`；当前不开放 Tenant 覆盖。 |
| 最大文件大小 | Manager 平台配置 | 当前默认 `10MB`；任务可以在平台上限内保存更小的过滤值。 |
| 批处理并发数 | Manager 平台配置 | 当前默认 `5`；只影响新批次。 |
| 向量维度 | 模型和 pgvector 结构事实 | 当前固定 `2560`，页面只读；不同维度必须走迁移流程。 |
| Provider credential | Inference encrypted credential | Manager 不接收、不保存、不返回；只通过 Inference Runtime 执行。 |

除 API Key 外，上述字段的显式值保存在 Manager 自己的持久化配置中，未保存时使用 Manager 配置定义默认值。不得继续读取对应 `MANAGER_*` 环境变量，也不得在 Manager 配置读取失败时回退到环境变量或 System 内部配置 API。

配置必须带单调递增版本。任务 `config.embedding` 和 execution `execution_config` 保存实际模型、维度及配置版本快照，但不能保存 API Key。平台配置变化不能改写已有任务或历史 execution；已有任务模型与当前启用模型不一致时，执行入口必须拒绝并要求用户显式更新任务。

同维度模型切换在新配置验证成功后原子激活，并使既有不同模型结果退出检索。不同维度切换属于 `migration_required`，普通配置 API 必须拒绝。配置缺失、校验失败或向量服务不可用时，Manager 明确禁用向量化能力并返回稳定原因，不能静默使用另一套配置。

完整配置分类、能力声明和单一来源规则见 [ADDP 配置规范](../../docs/spec/addp配置介绍.md)。

## 审计与监控

- 非 GET 向量化 API 必须进入 `system.audit_logs`。
- execution 历史统一进入 `common.task_executions`。
- 任务和结果页面通过 execution id 跳转 Monitor，但界面不直接展示 execution id。
- `manager.embeddings` 和 `manager.embedding_tasks` 的时间字段只表达表行生命周期，不替代合规审计。
