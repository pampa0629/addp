# 快显概念总览

> 状态：Manager 模块概念层文档。本文只说明 Manager 空间快显与瓦片缓存的价值、概念、分工、边界和协作关系，不描述具体表结构、API 路由或实现算法。

## 一、价值定位

Manager 对空间数据有两类预览体验。

基础预览用于“看懂数据”：

1. 表格查看字段、属性、样本和记录。
2. 轻量 GeoJSON 绘制查看空间形态。
3. 可以分页、抽样或降级，不承诺连续地图浏览体验。

快显用于“像浏览地图一样浏览空间数据”：

1. 能按完整空间范围全幅定位。
2. 能随缩放、拖拽连续加载。
3. 能在较大数据量下保持可接受响应。
4. 能复用瓦片缓存、实时瓦片、小数据量 GeoJSON 或未来外部瓦片服务。

因此，快显不是任务，不是 MVT，也不是某张表。快显是 Manager 空间预览中的高性能显示模式。

## 二、核心概念

| 概念 | 含义 |
| --- | --- |
| quick view | 快显模式，Manager 空间预览中的高性能地图浏览模式。 |
| quick view preference | 快显偏好，记录用户对某个 item 的预览模式偏好。 |
| quick view capability | 快显能力，查询时根据空间事实、产物事实和引擎能力动态合成。 |
| render source | 快显渲染源，例如已缓存瓦片、实时瓦片、直接 GeoJSON。 |
| tile cache result | 瓦片缓存结果，已经生成并可被复用的瓦片产物状态。 |
| tile cache generation task | 瓦片缓存生成任务，面向未来执行和调度的任务定义。 |
| source spatial facts | 源空间事实，例如源 SRID、源 CRS、源 extent、几何列、记录数。 |
| render facts | 渲染事实，例如 WGS84 渲染范围、3857 瓦片目标、层级推荐。 |

## 三、对象分工

| 对象 | 职责 | 不承担 |
| --- | --- | --- |
| 空间数据项 | 提供源数据、源空间事实和统一 Resource Locator。 | 不保存快显状态。 |
| `quick_view` 偏好 | 记录用户偏好的预览模式。 | 不保存快显能力、产物状态、生成配置或执行历史。 |
| 快显能力 | 查询时回答当前能否快显、使用哪个渲染源、是否可生成缓存。 | 不作为长期事实表。 |
| 瓦片缓存结果 | 记录瓦片缓存是否可用、在哪里、覆盖什么范围和层级。 | 不表达任务定义，不替代执行记录。 |
| 瓦片缓存生成任务 | 记录以后按什么配置生成或刷新瓦片缓存。 | 不保存每次执行历史，不直接表达产物是否可用。 |
| 执行记录 | 记录某一次生成过程、状态、错误和结果摘要。 | 不作为长期产物事实源。 |

## 四、边界原则

### 1. 使用统一资源身份

快显能力和数据出口以 Resource Locator 作为主身份。`schema/table` 只是数据库 provider 内部从 locator 解析出的参数，不是快显公共概念。

### 2. 源事实和渲染事实分离

`capabilities.spatial.extent` 是源事实，只表达原生 CRS 下的范围。

快显、瓦片缓存和 Web 地图默认视图需要的是渲染事实，例如 WGS84 渲染范围或 WebMercator 瓦片目标。渲染事实可以由引擎或派生产物生成，但不能写回源 metadata facts。

### 3. 快显能力和瓦片缓存生成分离

`can_use_quick_view` 回答当前是否能直接切换快显。

`can_generate_tile_cache` 回答当前是否能通过生成瓦片缓存获得或改善快显能力。

二者可以同时为 true。例如已有可索引实时瓦片路径时，用户可直接快显，也可选择生成缓存降低后续成本。

### 4. 瓦片缓存是独立产物

瓦片缓存支撑快显，但不只服务快显。它还可能用于空间服务发布、共享浏览、门户展示或后续分析。

瓦片缓存必须作为独立产物记录，不能重新塞回 `quick_view` 偏好表。

### 5. 瓦片格式不等于任务类型

MVT 是当前 PostGIS 第一阶段最方便的瓦片格式。任务概念应是“瓦片缓存生成”，任务类型为 `tile_cache_generation`。瓦片格式进入任务配置和产物状态。

### 6. 数据源加工必须显式

创建物化视图、空间索引、统计信息等属于派生准备动作。它们不修改原始业务记录，但会加工业务数据源环境。

这类动作必须由任务配置或用户操作显式授权，不得在普通预览或普通瓦片请求中隐式执行。

## 五、协作流程

### 1. 空间预览页

用户打开空间 item 后，Manager 展示基础预览，并查询快显能力。

能力查询根据源事实、已有瓦片缓存结果、数据量和可用渲染路径，返回：

1. 当前是否可快显。
2. 推荐渲染源。
3. 当前用户偏好。
4. 是否可生成瓦片缓存。
5. 不可用原因或推荐说明。

### 2. 直接快显

满足以下任一条件时可直接快显：

1. 有 ready 的瓦片缓存结果。
2. 数据量小，可直接读取 GeoJSON。
3. 有低成本实时瓦片路径。
4. 后续扩展中，数据项暴露可消费的外部瓦片服务。

### 3. 生成瓦片缓存

不能直接快显但可生成缓存时，预览页跳转到瓦片缓存页面的“任务”tab。用户确认范围、层级、格式、目标存储和准备动作后创建任务，再选择是否执行。

生成完成后，瓦片缓存结果进入产物状态。下一次快显能力查询自然可选择该结果。

### 4. 大数据量空间数据

大数据量空间数据应遵循：

1. 低层级和全幅浏览优先由瓦片缓存承担。
2. 高层级局部浏览可以由动态 MVT 或按需回填承担。
3. `min_zoom` 面向全幅显示。
4. `max_zoom` 表达缓存与动态 MVT 的责任边界，不表达数据可查看的最高层级。

## 六、与其他模块的关系

| 模块 | 协作方式 |
| --- | --- |
| Meta | 提供已扫描源 facts，不承载快显派生产物。 |
| Manager | 拥有快显能力、瓦片缓存任务和瓦片缓存结果。 |
| Orchestrator / Monitor | 发现、执行和监控 `tile_cache_generation` 任务。 |
| Storage / Object | 保存瓦片对象或 manifest，由 `storage_ref` 描述。 |
| System / Engine | 提供权限、租户和引擎连接信息。 |

快显派生产物的生命周期由 Manager 负责。Meta 或 System 可以发布源 item、engine、tenant 生命周期事件，但不应直接清理 Manager 私有瓦片路径。
