# 三维模型、点云与高斯泼溅预览说明

> 状态：当前实现说明。本文说明 Manager 对 `model_3d`、`point_cloud` 和 `gaussian_splat` 数据项的预览、快显任务、结果状态和 `preview_state` 协作关系。格式识别规则以[平台规范](../../docs/spec/)为准，转换运行时见[Model3D Workflow](../../engines/model3d-workflow/README.md)、[SuperMap Workflow](../../engines/supermap-workflow/README.md)和[PointCloud Workflow](../../engines/pointcloud-workflow/README.md)。

## 一、职责边界

Manager 只负责预览编排、任务定义、结果登记、内容出口和前端渲染材料组织。Manager 内置任务通过 Workflow Runtime direct 算子执行转换；Develop 独立公开同一算子的 workflow 模式。

Manager 不负责：

1. 在 Go 进程内解析 OSGB、FBX、OBJ 或高斯泼溅二进制。
2. 直接调用 `_3dtile`、`assimp`、PDAL 或 KSplat 生成脚本。
3. 把 Manager 受管快显 artifact 自动升格为业务 data item。
4. 把快显能力、转换结果或渲染器状态写回 Meta attributes。

SGM 读取及 OSGB 导出由 `supermap_workflow` operator 承担；其余三维和高斯相关重型转换由 `model3d_workflow` operator 承担；点云 COPC 转换由 `pointcloud_workflow` operator 承担。算子本身是通用持久化转换能力：Manager 通过 direct 模式选择 infra 目标并登记受管快显 artifact，Develop 通过 workflow 模式选择业务目标并触发 Meta scan。两类调用共用 `addp.workflow.access-plan/v1`，但产物生命周期仍由各调用方负责。

## 二、数据类型与预览路线

| 数据项 | 预览路线 | 结果归属 |
| --- | --- | --- |
| `data_type=model_3d + format=glb` | 直接使用三维模型预览 | 源 data item |
| `data_type=model_3d + format=ply + layout=single` | 基础预览直接读取 mesh PLY 源文件 | 源 data item |
| `data_type=model_3d + format=gltf + layout=multi` | `gltf_to_glb` 生成 GLB 快显后预览 | `manager.model_3d_glb` |
| `data_type=model_3d + format=fbx\|obj\|stl + layout=single` | 基础预览直接读取源文件；也可通过对应 mesh operator 生成 GLB 快显 | 源 data item / `manager.model_3d_glb` |
| `data_type=model_3d + format=dae\|3ds + layout=single` | 首期静态模型与 PNG/JPEG 漫反射贴图；生成自包含 GLB 快显，源模型无浏览器直接预览路线 | `manager.model_3d_glb` |
| `data_type=model_3d + format=skp + layout=single` | `skp_to_glb` 转换静态网格、组件变换及内嵌贴图；生成自包含 GLB 后预览 | `manager.model_3d_glb` |
| `data_type=model_3d + format=max + layout=single` | `max_to_glb` 通过 Model3D 内部 Blender 子进程转换静态网格及明确声明的漫反射贴图；未选源单位时默认米 | `manager.model_3d_glb` |
| `data_type=model_3d + format=ifc + layout=single` | `ifc_to_glb` 专用 operator 生成 GLB 快显后预览 | `manager.model_3d_glb` |
| `data_type=model_3d + format=osgb + layout=single` | `osgb_to_glb` 生成 GLB 快显后预览 | `manager.model_3d_glb` |
| `data_type=model_3d + format=sgm + layout=single` | 同一 execution 串行调用 SuperMap `sgm_to_osgb`、Model3D `osgb_to_glb`，生成 GLB 后预览 | `manager.model_3d_glb` |
| `data_type=model_3d + format=osgb_scene + layout=whole` | Manager `model3d_tiles_generation` 通过 `target_format=3d_tiles` 或 `s3m` 生成瓦片快显 | `manager.model3d_tiles` + Manager infra MinIO |
| `data_type=model_3d + format=s3m + layout=whole` | 直接使用 Three.js S3M 模型预览 | 源 data item |
| `data_type=model_3d + format=3dtiles + layout=whole` | 直接使用 3D Tiles 预览 | 源 data item |
| `data_type=gaussian_splat + format=ply\|splat` | 基础预览可直接读取；也可生成 KSplat 受管快显 | `manager.gaussian_splat_ksplat` |
| `data_type=gaussian_splat + format=ksplat` | 直接基础预览 | 源 data item |
| `data_type=point_cloud + format=copc + layout=single` | 通过受控内容 URL 和 HTTP Range 直接 COPC 动态 LOD 预览 | 源 data item |
| `data_type=point_cloud + format=las\|laz\|e57\|pcd\|xyz + layout=single` | 生成 COPC 受管快显后通过 HTTP Range 动态 LOD 预览 | `manager.point_cloud_copc` |

`.ksplat` 本身已经是前端目标渲染格式，不创建 KSplat 快显任务，不登记受管快显结果。它仍然通过 `manager.preview_state` 保存基础预览视角。

DAE、3DS 在源模型尚无直接预览时，Console 仍必须请求 Quick View Capability，并根据 `generate_model_3d_glb` action 显示生成按钮；格式属性及 `.dae` / `.3ds` 文件节点都通过现有三维快显目标识别实现。生成后统一消费 `model_3d_glb` 渲染源。

固定 `model.fbx` 的 GLB 快显通过不能外推其源文件基础预览：已记录样例含 96 个 RGBA 数值，但 `ByVertice`／`IndexToDirect` 颜色层缺少 `ColorIndex`，不能视为空颜色层，也不能宣称只升级依赖即可修复。该源的 Hosted 范围限定 GLB 快显，基础预览不计通过；彩色 `vCube.fbx` 的只读基础预览使用独立固定源，按[Manager 场景规范](../../docs/spec/testing/scenarios/Manager与空间成果.md#彩色-fbx-只读预览)验证。OBJ 基础预览只证明几何加载，外部材质、UV 及实际内嵌 PNG 保真由 GLB 快显分别验证。

### SKP 支持边界

FBX 新接入 FTP／NFS／MinIO 精确组成授权时，仅允许格式层完整证明的 Binary 7400 静态无贴图 profile。Meta basic 保存独立的完整性及 profile；Manager 只冻结唯一主文件，读取和转换复核实际字节，不复制父目录。历史 box 源的颜色层问题仍按上文保留，不以它证明新的严格 profile；新合法固定源、格式证明、GLB 页面预览、原始下载、缓存和撤权分别验收，证据未产出前不声明通过。SKP 当前仅进行严格组成读取技术准入，不开放新的组成批准。

SKP 由权威格式身份 `model_3d/skp/single` 进入同一 GLB 快显任务，不仅凭文件名后缀提供生成能力。源读取使用单文件访问计划，Manager 不解析模型；Model3D 固定使用 OpenSKP 1.3.0 生成并校验 GLB，统一转换为米制、Y 上轴。首期拒绝隐藏组件、隐藏面、关闭图层及解析器不支持的输入，不声明全部 SKP 版本或动态场景语义。Common 不产生未经解析的模型摘要。

### MAX 转换选项

MAX 的数据探查和任务创建入口复用同一源单位、外部贴图声明组件，通过既有快显 action 的可选 `source_unit`、`texture_files` 保存到任务 options，不增加独立 Blender 服务。当前导入器不能可靠识别原始 MAX 系统单位；未选时采用米，并记录 `unit_source=default`，不称为自动识别。外部图片必须显式映射到模型所在目录内的相对路径，不自动搜索。

## 三、快显结果与业务结果

### GLB、KSplat 与 COPC 受管结果

三维模型 GLB 快显、点云 COPC 快显和 3DGS - KSplat 快显是 Manager artifact：

```text
源 item
  -> Manager 快显任务
  -> model3d_workflow / pointcloud_workflow direct operator
  -> Manager infra MinIO
  -> Manager 结果表登记
  -> Preview 返回受控内容 URL
```

对应结果表：

1. `manager.model_3d_glb`：GLB 快显结果。
2. `manager.gaussian_splat_ksplat`：KSplat 快显结果。
3. `manager.point_cloud_copc`：点云 COPC 快显结果。

点云 COPC 前端预览使用 Giro3D 基于受控内容 URL 和 HTTP Range 读取 COPC octree hierarchy 与点数据块，并在前端完成动态 LOD、缓存和视角驱动加载；这些渲染状态只属于前端会话，不写入 Meta attributes 或 Manager artifact 表。

COPC 相机初始化必须同时设置 Giro3D View 的近裁剪面下限和当前近裁剪面，避免其默认 `2` 个坐标单位的下限将小尺度局部点云整体剔除。首次定位和已保存视角恢复使用同一 View 配置；首次定位复用 Manager 的包围盒取景函数，按实际范围和视口比例计算距离，不将局部点云半径强行放大到 `1`。当前数值属性存在有效的非零范围时，色带使用该属性声明的最小值和最大值，避免小尺度 Z 属性落入固定 `0～1000` 色带后近乎全黑；RGB 与分类属性保持其原生映射。

普通 Preview 响应通过 `content.metadata.preview_artifact_status`、`preview_artifact_task_type` 和 `preview_artifact_id` 表达受管 artifact 状态、可创建任务和已就绪结果 ID。不得再使用旧的 `quick_view_status`、`quick_view_task_type` 或 `quick_view_id` 字段。

GLB 快显提交失败必须保留可操作的错误原因：来源身份已核对、但主模型或关联文件组成事实缺失／不完整时，Quick View action 返回 HTTP 409 与 `error_code=source_composition_incomplete`，提示重新扫描模型所在目录；未能取得源读取执行授权时返回 HTTP 403 与 `error_code=source_authorization_required`，提示核对原始模型及关联文件的读取授权。两者都不表示转换器执行失败，也不改变源授权裁决。前端按 HTTP 状态与稳定错误码显示中英文提示，其他 403 同时提示核对功能权限和源数据读取授权，不将未知内部错误正文直接展示给用户。已有成果的覆盖确认仍沿用其独立的 409 契约。

预览页触发 GLB / KSplat / COPC 快显生成时，只允许提交 Resource Locator 和后端 `quick-view/capability` 返回的 `available_actions` 动作值：

```http
POST /api/v1/manager/quick-view/actions
```

通用请求体为：

```json
{
  "locator": "addp://engine/26/path/3d/ifc/building.ifc?type=file&item_id=10441",
  "action": "generate_model_3d_glb"
}
```

任务私有配置必须由 Manager 后端根据 capability 和 Preview source 事实生成。前端不得自行拼接 GLB / KSplat 任务私有配置。

MAX 的 `generate_model_3d_glb` 动作另允许上述可选 `source_unit` 和 `texture_files`；其他源格式不接受这两项 MAX 转换选项。

### FTP／NFS／MinIO 转换输入准备

文件／对象读取与 Workflow Runtime 直接接入是不同能力。FTP、NFS、MinIO 的 IFC／3DS／DAE／OBJ／STL／glTF 通过下述同一受控暂存链生成 GLB；基础 OBJ 几何预览不代替包含 MTL 和贴图的快显。每个来源与格式的实际验收范围以[验收证据索引](../../docs/spec/testing/验收证据索引.md)为准，接线或格式探针不能代替正式用户授权及页面验收。

已确认的接入路线由 Manager 准备转换输入，不给 Model3D 增加源存储协议实现，也不扩展 `addp.workflow.access-plan/v1` 的访问方法：

```text
当前模型的真实执行来源及读取授权
  -> Meta 持久化的精确组成及 System 当次执行授权
  -> Manager 使用原生 File／Object Provider 精确读取
  -> Manager Infra 中本次执行专属的临时对象
  -> object_store access-plan
  -> 同一 Model3D direct 转换算子
  -> 现有 GLB 受管结果与读取出口
```

源身份始终保留原 FTP／NFS／MinIO Engine、DataItem 和指纹。临时对象不是业务 Engine、DataItem 或新的长期来源，不登记到 System 或 Meta；不得复制到 NFS 后将其计作 FTP 转换，也不得伪造 `mounted_path`。Business 连接与密码只用于 Manager 的源内容读取，不交给 Model3D，不写入任务定义、执行记录或审计计划。

glTF 保留 `model_3d/gltf/multi` 身份。基础扫描使用 Common 唯一 `ParseGLTFComposition` 完整证明静态 2.0 profile 的声明，仅从本次已观察文件中匹配 manifest、buffer、PNG/JPEG；内嵌资源不虚造文件项。`format_info.gltf.composition_complete` 是基础识别事实，deep 摘要不得提升或覆盖它。组成角色按物理路径稳定排序编号，保留 `manifest` 主入口和 `buffer`／`image`；原 URI 只解码一次，解码后的首尾空格、大小写、Unicode、加号和字面百分号保留，不在格式私有摘要重复保存资源路径。非法、缺失或不支持的声明使当前组成不完整，不能沿用旧完整状态。

Manager 转换及原始读取先核验正式精确组成许可，再有界读取主 manifest，通过同一解析入口复核冻结成员；不读取新发现依赖。转换暂存同一份已核验主字节及确认成员，保留相对目录和名称，复用 `gltf_to_glb`。原文件 ZIP 恰含完整组成，不枚举业务源目录。Runtime 再验证精确暂存输入的长度、图片及结构；仅当全部通过才发布自包含 GLB。静态核心 profile、预算与拒绝项见[格式规范](../../docs/spec/builtin-formats/三维模型与场景.md#gltf)；格式单测、接线测试、真实转换和三引擎页面验收分别登记。

输入准备只允许精确文件集合，并保留合法依赖的相对目录。IFC 使用其主文件；3DS／DAE 的贴图、OBJ 的 MTL 及其贴图必须来自格式解析和 Meta 已确认的相关引用。不得把模型父目录或整个引擎根递归复制为输入，不按扩展名猜测依赖；缺失必需文件、路径越界、未知读取边界或来源失配时拒绝，不用无贴图转换掩盖缺失。 3DS／DAE 主文件在已获授权的同一次读取中，复用 Common 格式解析核对实际贴图声明与冻结声明；核对通过前不打开依赖、不上传或调用转换。暂存使用这次已核对的主文件字节，不能再次打开源文件引入检查与使用之间的变化。3DS／OBJ 声明保持原始大小写和百分号文字，不做 URI 解码；DAE 按其原生 URI 规则只解码一次。仅调整声明顺序不改变组成。IFC 现有摘要不提供完整外部依赖声明，本轮固定自包含样例通过也不能证明复杂外部引用已支持。

OBJ 组成以 `format_info.obj.composition_complete/material_libraries` 为依据；首期 MTL 必须与主 OBJ 同目录，贴图可位于该目录的子目录，角色沿用 `material_library(_N)` 和 `texture(_N)`。Manager 先从已获授权的流中缓冲并复核主 OBJ 和全部 MTL，之后暂存同一份已核验字节；声明变化时不读取新发现图片、不上传或调用 Runtime。缺失／空图片、嵌套 MTL、链接或组成不完整时拒绝，细节与预算以[元数据 attributes 规范](../../docs/spec/addp元数据attributes规范.md)为准。

临时前缀固定归属本 Tenant、execution 和 attempt，位于 Manager 桶的 `temp/` 范围；同一执行的不同 attempt 不共享输入。开始取数前只读核验现有 Infra `temp/` 7 天过期规则及未启用版本控制的条件。成功、失败和取消时均尝试清理本 attempt 实际写入的精确对象；清理失败不得报告整条生成流程成功。文件模型每次输入准备在任何上传前，将 execution、attempt、准备 UUID 和完整精确 bucket/object 集合写入现有结果的 `metadata.model3d_output_lifecycle.input_preparations`。持久化失败不得上传；存活 attempt 的输入不由后台提前回收。正常退出记录输入写入是否确定结束及删除结果；失败、崩溃或 attempt 更替后的归属仍由既有 CleanupService 精确续清，软删除结果不抹掉归属。上传状态不确定时保留 watch 标记持续重试，不能把一次不存在当作不会迟到写入。已清理清单保留到结果记录生命周期结束，供既有结果详情 API 和物理 Stat 核验，不另建清单表、API 或目录枚举路线。Infra 既有规则继续提供异步过期保障，运行时不修改桶策略或扩大删除范围。Runtime 本地 workspace 继续使用其现有临时目录生命周期。

Manager 已有输入暂存与精确清理内核 `model3d_source_staging.go`，与 SGM 复用同一临时对象过期条件核验。内核在 I/O 前冻结并校验显式文件集合，每次准备使用独立随机子目录，避免同 attempt 的并行准备互相覆盖或清理；上传后核对实际读取尺寸并探测多余字节。它没有 Engine 查询、FTP 客户端、目录枚举或产品调用入口，不把调用者传入的文件集合当成授权证明。内存对象存储及进程内 S3 HTTP 夹具验证文件组合、真实 MinIO 客户端调用、尺寸变更、取消与失败清理；Repository 的 PostgreSQL 门禁验证输入归属持久化与崩溃后精确续清。这两层测试本身不代表真实源暂存、MinIO 物理清理或模型转换已通过；实际 T4 另按下述固定证据认定。

GLB 首期执行入口限定为当前 User 手工发起的 Manager 根执行：资源树 Quick View action 与用户任务执行均从共享认证上下文捕获 Principal、Tenant Membership 和授权版本，按 `common/execution.WithUserOrigin` 与 `ApplyUserOrigin` 的共享规则固化真实发起人。任务创建者不补造来源；`scheduled`、Orchestrator 父子调用或其他来源在创建 pending execution 前明确拒绝。父执行能够证明 Actor 也不产生 GLB 源读取许可，不迁移或补造历史来源。

模型授权按主文件、材质库与 Meta 完整确认的声明贴图组成精确核验，不覆盖所在目录的其他文件，不将贴图伪建为独立 DataItem。旧主文件许可不自动扩张；增加、移除或更换引用目标等组成约束变化后须重新批准，同路径正常内容更新不改变授权边界摘要。缺失、未知或越界组成须拒绝。

FTP、NFS、MinIO 的 IFC／3DS／DAE／OBJ 已统一使用精确组成授权与受控暂存：输入必须冻结精确组成、完整转换配置及任务身份／版本，签发并绑定正式执行授权后才能领取，取数与结果提交边界继续重核。来源分类只能使用 System 当前引擎事实；缺少合法计划或许可时明确拒绝，不因缺失准备标记切换到绕过源授权的路径。各来源和格式的固定样例证据独立记录，不外推到其他格式或任意模型。

Quick View 的 GLB 生成能力同样使用解析器取得的 System 实际引擎类型；FTP 的 IFC／3DS／DAE／OBJ 可返回 `generate_model_3d_glb`，MAX、SKP、OSGB、SGM 等未接入格式不声明这一动作。NFS／MinIO 的上述四种格式沿用同一精确组成契约，其他格式的能力按其各自入口与限制认定。此判断仅表达来源与格式事实，不查询 Grant，也不接受前端或 Meta attributes 自报的引擎类型。

上述三种来源每次执行使用独立的受管 GLB 对象，最终目标在创建 pending execution 前确定，并纳入完整配置及授权摘要。转换器只创建本次对象；不得直接覆盖上一份快显对象。提交前重新核验当前授权与租约，通过后沿现有事务原子切换同一结果记录的对象引用、execution 终态和任务摘要。失败不得切换到本次对象，也不得清理旧快显；本次失败或崩溃遗留对象与成功切换后的旧对象均由 Manager 按精确归属回收，不通过临时对象复制形成第二条发布路线。已实现的发布与清理行为及固定样例验证范围见[验收证据索引](../../docs/spec/testing/验收证据索引.md)。

既有 `GET /model_3d_glb/{id}` 的 `metadata.model3d_output_lifecycle.input_preparations[]` 返回每次准备的 `execution_id`、`attempt`、`preparation_id`、完整 `objects[{bucket,object}]` 及 `released/watch/cleaned`。`released=false` 表示该次输入尚未释放；`cleaned=true` 仅表示上传者已确定结束且全部精确对象删除成功。`watch=true` 表示上传状态不明，必须持续重删且不能标记为 cleaned；崩溃或旧 attempt 恢复按此处理。正常转换失败若上传及删除均已确定完成，可以同时记录执行失败和输入 cleaned。详情只表达归属事实，不授予源内容读取许可；删除前可保存其中的精确对象身份，删除后由 Infra 对这些身份逐个 Stat，不枚举父前缀。

本次输出归属及待清理对象保存在现有结果记录的内部 metadata，转换前先持久化，成功切换与旧对象清理登记同事务完成；失败保留此前可见结果及版本。清理只操作 Manager 桶、本租户模型快显命名空间内登记的精确对象，并覆盖软删除记录。当前 Runtime HTTP 超时只结束客户端等待，不能证明远端转换和上传已终止。因此失败或崩溃输出的清理标记须保留并周期重试，不能在一次删除成功后丢弃，更不能将一次零残留检查解释为不存在迟到写入。

删除已终止的生成任务仍保留 ready 结果。同来源重建任务时，待发布归属记录新的任务 ID；旧结果的任务、对象与版本在成功切换前保持不变，失败不能冒记为新任务产物。再次生成仍须显式确认覆盖，同来源活动执行期间不能删除该模型任务或当前结果。准备阶段沿既有 `updated_at DESC, id DESC` 规则选择当前结果；清理不得修改该排序时间，也不得删除其他存活记录仍引用的对象。

共享工作区有并发改动时，Manager PostgreSQL 验证可使用 `make test-manager-postgres MANAGER_POSTGRES_TEST_ARGS="--source-root <固定源码 checkout>"`。该选项仅切换测试源码；Infra 归属、实际端口与测试库校验仍由原工作区的标准脚本执行，测试集合、临时 Meilisearch 归属及清理要求不变。固定 checkout 的提交必须属于本仓库历史，相关输入须记录并保持不变；不将滚动源码下观察到的 PASS 计为固定版本门禁通过。

**授权边界：** 真实发起人固化、同 Tenant、已取得 Engine 连接、租约存活或 `RelatedRefs` 均不等于源授权。正式文件授权事实投影、执行授权签发／消费和实际调用必须贯通，不设置绕过授权的测试或开发开关。

验收沿现有标准入口扩展，不新增第二条转换路线：Manager T1 覆盖文件集合、路径、attempt 隔离、取消及失败清理；FTP T2 覆盖真实 FTPS 读取；Model3D 门禁验证实际模型及自包含 GLB 发布。现有 `ftp-consumer-flow` Hosted T4 在固定 `a6ad87480b0a11804ddc44061ff16723cea80fbf` 已通过三个来源各 IFC／3DS／DAE／OBJ 的生成、实体渲染、缓存、精确源下载、组成变化／撤权及任务定义与成果分别删除。原始 GLB、源 ZIP、截图、拒绝执行与精确对象清理均经独立复核，完整版本、工件与范围见[验收证据索引](../../docs/spec/testing/验收证据索引.md)。这不替代 T1／T2 的私有故障矩阵，也不认证任意模型、嵌套 MTL 或本机尚未重载的服务。

### SGM 串行转换与临时对象

SGM 解析由 SuperMap Runtime 承担，GLB 转换与发布校验由 Model3D Runtime 承担。Manager 在生成前发现两个 direct 算子，使用执行专属 infra 对象传递 OSGB，并在执行返回时尝试清理；清理失败必须使本次执行失败。中间产物不形成 Meta item，不向用户展示额外转换步骤。生成后的 GLB 复用现有内容出口和 renderer，已有 ready GLB 不因 Runtime 离线失效。SGM 生成沿用任务的 `supports_cancel=false`。

中间 OSGB 固定写入 `temp/model3d-sgm/tenant_<tenant_id>/<execution_uuid>/model.osgb`，复用 `scripts/infra/init-minio.sh` 已有的 `manager:temp/` 7 天过期规则。Manager 在每次转换前只读核实目标桶版本控制状态为空、该规则启用且无标签或对象大小限制；配置不可读、不完整或桶已启用／暂停版本控制时明确失败，不启动转换，不修改生命周期配置。正常终态删除只针对本 execution 的精确对象；超时、断连后的迟到写入及 Manager 退出遗留由 MinIO 扫描异步回收。7 天表示对象年龄阈值，不保证在第 7 天整立即删除；部署须保持规则有效。源 SGM 和最终 GLB 都不使用临时前缀。

### 分块瓦片结果与 S3M 预览

OSGB Scene 的 Manager 快显使用统一分块瓦片任务：

```text
osgb_scene item
  -> manager.task_definitions (task_type=model3d_tiles_generation, target_format=3d_tiles|s3m)
  -> model3d_workflow: osgb_scene_to_3dtiles
     或 supermap_workflow: osgb_scene_to_s3m
  -> Manager infra MinIO
  -> manager.model3d_tiles
  -> 3D Tiles / S3M 预览
```

同一源 item 可以分别关联一条 `target_format=3d_tiles` 和一条 `target_format=s3m` 的当前结果。两种结果独立生成、独立失败、独立失效，不能塞入同一结果记录。源指纹变化后旧结果不再作为当前结果使用。已生成结果的预览只依赖 Manager 与 infra MinIO，不依赖转换引擎在线。

统一“数据任务 → 快显任务”页面使用 `task_definitions` 与 `model3d_tiles` 展示任务、结果和执行监控；创建与生成复用下述来源驱动 Quick View action，不恢复写业务存储并依赖 Meta scan 的旧页面实现。

Model3D Tiles 任务定义由 Quick View action 根据 OSGB Scene 源事实和 `target_format` 派生，创建后只读。该 action 既可从 Data Explorer 当前 item 发起，也可从统一“数据任务 → 快显任务”入口选择一个源 item 后发起；公开 API 不提供直接提交私有配置的任务创建或更新入口。TaskProvider `create_url` 为 `/manager/tasks/quick-view?task_type=model3d_tiles_generation&create=1`，`edit_url` 为 `/manager/tasks/quick-view?task_type=model3d_tiles_generation&task_id=:id`。统一任务工作区的 `task_id` 打开只读定义。

瓦片快显任务和瓦片快显结果是两个独立的生命周期对象：删除任务不级联删除已生成结果；删除结果时，Manager 必须先删除 infra MinIO 中 `storage_ref` 指向的整个瓦片前缀，成功后再软删除 `model3d_tiles` 记录。物理清理失败时保留结果记录，禁止造成“记录已删但瓦片残留”的不可见状态。执行中的任务和生成中的结果不允许删除。

#### S3M 就绪、渲染与资源回收

S3M ready 结果必须包含可独立读取的 JSON `config/scene.scp` 与 manifest 引用的全部瓦片；SuperMap 当前多根场景输出固定为 S3M 3.01、`config/scene/Data/**/*.s3mb`、DXT 纹理压缩、Draco 几何压缩和 EPSG:4326 地球坐标，manifest 使用相对自身的 `./scene/Data/...`。只有 manifest 明确声明 `version=3.01`、`crs=epsg:4326`、`position.unit=Degree`、位置经纬度范围、`s3m:TextureCompressionType=DXT`、`s3m:VertexCompressionType=DRACO`，且所有根瓦片引用均位于结果目录内并真实存在时，才能标记为 ready。

Manager 必须从受管结果元数据向 S3M 预览器传递 `manifest_encoding=json`与 `tile_extension=.s3mb`，不得根据 `target_format=s3m` 硬编码为 legacy XML SCP / `.s3m`。前端按 JSON SCP 中的压缩声明启用 DXT 纹理和 Draco 几何解码；解码库或 WebGL S3TC 能力不可用时必须明确报错，不得回退为白色材质。

Manager 的活动 S3M renderer 固定使用 Three.js，只支持 ADDP 当前生成和声明的 `JSON SCP + S3M 3.01 + S3MB + DXT + Draco` 单一路线。Draco 量化 position 与 texcoord 必须依据 `minVerticesValue / vertCompressConstant` 和 `minTexCoordValue / texCoordCompressConstant` 解码后再交给 Three.js；不得把量化整数直接当作模型坐标。DXT mip chain 必须按 DXT1 / DXT3 / DXT5 的 block size 拆分并通过 `CompressedTexture` 上传。

S3M Draco 解码器只在首次解析 S3M 内容时初始化，同一页面的并发解析共享一次初始化；模块导入、表格预览和血缘浏览不得触发解码器下载。解码器资源路径必须遵循模块的 Vite `BASE_URL`，在独立开发入口与 Console `/module-ui/manager/` 挂载下使用同一实现；下载或初始化失败由解析调用方处理，不得在模块导入阶段产生未处理的异常。

S3M 预览按 SCP root tiles 建立本地模型场景，基于 PageLOD 的 range mode、当前相机距离与屏幕像素范围按需加载子瓦片；子瓦片未 ready 时继续显示父级，ready 后再替换，禁止出现加载空洞。请求必须限制并发并继承 manifest URL 的结果版本参数；缓存超限时只回收当前未选中的非根瓦片。首次定位合并已加载根瓦片的 Three.js `Box3 / Sphere` 后设置 OrbitControls，不使用 SCP 的地球坐标改变 Manager 模型预览坐标系。

S3M 预览组件卸载或切换数据时，必须停止 animation frame、取消未完成请求、从 Three.js scene 移除全部 tile group，并释放 geometry、material、texture、OrbitControls 与 WebGLRenderer。Vue 管理的 viewport DOM 由 Vue 自行卸载，组件不得调用 `replaceChildren()` 或其他原生 DOM 清空方法。

现有 `supermap-s3m/S3MTiles` Cesium renderer 代码保留为未注册参考实现，Manager 页面、PreviewRegistry 和活动组件不得导入，不允许作为 Three.js 加载失败时的回退路径，因此不会进入 Manager 客户端依赖图。它仅为后续独立的、以地球为中心并支持多图层叠加的模块保留研究材料；未来模块必须重新定义图层、地球坐标、相机和生命周期边界，不直接恢复 Manager 的旧双模式预览。

#### 已有结果覆盖与业务派生

Manager 只提供“生成瓦片快显”，不提供“生成全部格式”；同一语义任务的再次生成表现为覆盖当前结果，不另建“更新任务”。已有该格式的未删除结果时，服务端必须要求本次执行显式确认，前端确认后才允许覆盖同一任务和结果记录；不得只靠前端弹窗，也不要求先删除结果。受管对象前缀可按源指纹与目标格式复用，因此受控 asset 接口必须使用 `Cache-Control: no-store`；Quick View manifest URL 必须携带 `last_execution_id` 版本，S3M 加载器派生的全部子瓦片请求也必须继承该版本，避免浏览器复用旧结果响应。预览界面始终显示当前瓦片格式；只有同时存在 3D Tiles 与 S3M ready 结果时才提供分段切换。

Develop 仍可把两种算子用于业务数据派生：

```text
osgb_scene item
  -> Develop workflow
  -> osgb_scene_to_3dtiles / osgb_scene_to_s3m
  -> 用户选择的业务存储
  -> Meta deep scan
  -> 3dtiles / s3m item
```

Develop 结果与 Manager infra 快显结果是两条不同生命周期路线，不互相登记或推断。

## 四、任务类型

| 任务类型 | 任务定义表 | 结果 |
| --- | --- | --- |
| `model_3d_glb_generation` | `manager.task_definitions` | GLB 快显 artifact |
| `model3d_tiles_generation` | `manager.task_definitions` | `manager.model3d_tiles` 中 `target_format=3d_tiles\|s3m` 的 infra artifact |
| `gaussian_splat_ksplat_generation` | `manager.task_definitions` | KSplat 快显 artifact |
| `point_cloud_copc_generation` | `manager.task_definitions` | COPC 快显 artifact |

`model_3d_glb_generation` 和 `gaussian_splat_ksplat_generation` 的启动与终态写入遵守 Manager 受管快显任务的原子 execution lifecycle：启动先持有任务行锁并创建 `pending` execution，后台领取后进入 `running`；同任务只允许一个 `pending` 或 `running` execution。受管结果、execution 终态和任务摘要使用 `last_execution_id` fencing，并在同一 Infra PostgreSQL 事务提交。KSplat 执行前从 Meta 补全的边界事实必须先保存到任务定义，再由 claim 锁定为 `execution_config` 快照。

`point_cloud_copc_generation` 使用相同的原子启动和终态语义。点云 direct operator 的进度事件只接受当前 `running` execution，并使用条件更新；不得接受 `pending` execution 的伪进度，也不得让终态后的迟到事件覆盖 execution 状态。

任务准入只看标准事实：`data_type`、`format`、`layout` 和必要 capabilities。`model_kind` 可用于展示和筛选，但不是第一版任务准入的必填条件。

## 五、预览状态

`manager.preview_state` 保存用户在当前 item 上的预览模式偏好和交互视角状态。它不是快显结果表。

`view_state` 只按显示模式和渲染域分组：

```json
{
  "basic_preview": {
    "map": {},
    "scene_3d": {}
  },
  "quick_view": {
    "map": {},
    "scene_3d": {}
  }
}
```

基础预览和快显各自保存视角，互不覆盖。三维模型、3D Tiles、S3M、点云和高斯泼溅都归入 `scene_3d` 渲染域；地图类预览归入 `map` 渲染域。`scene_3d` 内必须同时记录 `render_source`，受管快显还必须记录 `artifact_version`。Three.js S3M 相机状态额外记录 `renderer_runtime=three_s3m`，只有 runtime 一致时才能恢复；旧 Cesium ECEF 相机和历史 `view_mode` 状态直接忽略并按当前根瓦片范围重新定位。当前渲染源、结果执行版本或 renderer runtime 不匹配时，前端必须忽略旧相机，不能把 GLB 本地坐标、Three.js S3M 本地坐标、Cesium ECEF 坐标或旧瓦片结果的相机状态交叉复用。

首次定位无匹配已保存视角的模型时，GLB 与 Three.js S3M 共用 Manager 的包围盒相机计算：根据观察方向、实际画布宽高比及水平／垂直视角包住全部角点。不得仅用最大边长和垂直视角估算距离；窄画布中的宽模型也必须完整可见。已有匹配视角仍按原规则恢复，不在窗口变化时重置用户视角。
