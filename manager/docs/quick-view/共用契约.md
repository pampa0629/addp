## 目标模型

实现层收敛为统一任务定义、各领域结果状态和业务 item：

| 对象 | 目标落点 | 说明 |
| --- | --- | --- |
| 快显偏好 | `manager.preview_state` | 当前 item 的用户预览模式偏好。 |
| 矢量物化视图 | `manager.vector_materialized_view` | 当前 item 是否存在可复用的 3857 可索引渲染目标，以及该目标位置、状态和最近执行。 |
| 生成任务定义 | `manager.task_definitions` | 统一保存全部 Manager 可重复执行任务；`task_type` 决定强类型配置、执行器和结果策略。 |
| 矢量瓦片缓存结果 | `manager.vector_tile_cache` | infra PMTiles 是否可用、存储引用、源版本、生成 profile、范围、层级和最近执行。 |
| 任务资源绑定 | `manager.task_resource_bindings` | 显式记录任务的 source / target Engine 与 ResourceLocator，供资源回收和引擎生命周期判断使用。 |
| 矢量瓦片集业务 item | Business 存储 + Meta item | `data_type=media`、`format=pmtiles`、`layout=single` 的业务数据。 |
| 栅格 COG 结果 | `manager.raster_cog` | 当前 item 是否存在可复用的 infra MinIO COG，以及该 COG 的状态和最近执行。 |
| 栅格 Mosaic 业务 item | 业务存储 + Meta item | `format=raster_mosaic` 的 whole-scope 业务数据集，不是 Manager 私有 artifact。 |
| PPTX 静态 PDF 结果 | `manager.pptx_pdf` | 当前 PPTX item 的受管静态 PDF 预览材料；不是业务 item，不进入 Meta。 |

执行记录统一写入 `common.task_executions`，任务类型为：

```text
vector_tile_cache_generation
vector_tile_set_generation
vector_materialized_view_generation
raster_cog_generation
raster_mosaic_generation
pptx_pdf_generation
```

Manager 的可重复执行任务由统一“数据任务”工作台承载，Console 承载路由为：

```text
/manager/tasks/quick-view
/manager/tasks/spatial
/manager/tasks/embedding
```

“数据任务”作为父菜单提供“快显任务 / 空间数据任务 / 向量化任务”三个纵向子入口，三个 canonical path 复用同一个任务工作区组件。前两个入口复用生成类任务的列表、分页、详情、执行、监控和删除实现；向量化入口复用既有向量化任务与向量化结果子视图。导航合并不改变存储边界：生成类任务继续使用 `manager.task_definitions`，向量化任务继续使用 `manager.embedding_tasks`。快显任务不提供独立“结果”跳转：其当前结果是 Manager infra 快显材料，用户应通过“源数据”回到 data item 预览；空间业务结果仍在资源树和 Meta item 视角治理。TaskProvider capabilities 中的 `create_url` / `edit_url` 指向对应分类的 canonical path；Orchestrator 和 Monitor 仍通过标准任务 API 和 execution API 交互。浏览器路由不得再使用 `category` query 表达页面身份；`category` 只保留为后端任务列表 API 的筛选参数。

快显任务列表必须从 Manager 快显结果表读取当前状态，不得用 `last_execution_status` 推断快显是否可用。空间数据任务的“目标数据”入口必须按目标 Engine 和 catalog path 向 Meta 查询当前 DataItem，然后构造带 `item_id` 的规范 ResourceLocator；不得把任务配置中尚未被 Meta 发现的目标路径伪装成可导航的 item。

任务定义 CRUD 的唯一公开路线为：`GET /tasks`、`POST /tasks/:task_type`、`GET|PUT|DELETE /tasks/:task_type/:id`；执行继续使用 `POST /tasks/:task_type/:id/execute`。不得保留任何 `/*_tasks` 类型私有路由。

`manager.task_definitions` 至少包含 `id`、`tenant_id`、`task_type`、`version`、名称、启用状态、最近执行摘要、`semantic_key`、强类型 `config` 和审计时间。类型内语义唯一约束统一为 `tenant_id + task_type + semantic_key`。`manager.task_resource_bindings` 以 `role=source|target` 保存 Engine 和 ResourceLocator；资源回收不得再遍历多张任务表或猜测不同 JSON 路径。

### 受管快显任务语义身份

Manager 中“一个稳定源、一种派生变体、一个当前结果”的受管任务，统一按 `tenant_id + item_fingerprint + artifact_variant` 确定语义身份。

| `task_type` | `artifact_variant` |
| --- | --- |
| `model_3d_glb_generation` | `glb` |
| `gaussian_splat_ksplat_generation` | `ksplat` |
| `point_cloud_copc_generation` | `copc` |
| `raster_cog_generation` | `cog` |
| `model3d_tiles_generation` | `target_format=3d_tiles\|s3m` |
| `vector_tile_cache_generation` | 规范化生成 `profile_hash` |
| `vector_materialized_view_generation` | `source_geometry_column + target_srid` |
| `pptx_pdf_generation` | `pdf_static` |

上表任务的创建接口必须先规范化配置，再按语义身份查找。命中时更新名称、描述、`enabled` 和规范化配置，返回原任务 ID；未命中时才插入。数据库必须以部分唯一索引防止并发重复，冲突后回查并复用已存在任务，不向用户返回“重复任务”错误。

每次执行都新建 execution，并刷新同一当前结果。同一任务已有 `pending` / `running` execution 时禁止并发再次执行；其他结束状态不阻止重新生成。已有未删除当前结果时，`vector_tile_cache_generation`、`vector_materialized_view_generation`、`raster_cog_generation`、`model_3d_glb_generation`、`model3d_tiles_generation`、`gaussian_splat_ksplat_generation`、`point_cloud_copc_generation` 和 `pptx_pdf_generation` 必须显式提交本次已有结果动作 `parameters.existing_result_action=overwrite`。任务详情投影只读 `has_current_result` 供交互界面在首次执行请求前确认；未提交动作或确认后出现竞态时返回 HTTP 409 和 `code=existing_result_action_required`，且不得创建 execution、改变结果状态或删除物理产物；动作检查、active execution 检查和 pending execution 创建必须在任务行锁事务内完成。结果失效使用 source version 与产物记录的源版本快照比较，不把 `item_fingerprint` 当作内容版本。

上述受管当前结果任务统一声明 `supports_schedule=false`，Manager 不为它们启动 owner scheduler，但允许 Orchestrator 定时 Pipeline 调用。周期性刷新由用户在 Step 参数中显式配置 `existing_result_action=overwrite`；该动作由 Orchestrator 每次原样提交，Manager 不按 scheduled 来源自动补充。`pptx_pdf_generation` 的普通交互入口仅在用户打开预览且缺少当前结果时由前端显式提交一次；Meta scan、上传和 Manager Preview GET 都不预生成。该提交和统一“数据任务”页都必须使用 Quick View Capability 返回的 `generate_pptx_pdf` 动作，并通过 `POST /quick-view/actions` 执行；不得再保留 PPTX 私有的创建或执行路由。Embedding 的逐 item 调度语义独立保留。

### 业务派生任务语义身份

`raster_mosaic_generation` 和 `vector_tile_set_generation` 是业务派生任务，不按单一源 item 合并。语义身份必须包含规范化源范围、目标 Business 存储、目标名称、placement 和关键生成配置；完整语义不同时可以并存。结果是业务 data item，Manager 不拥有其生命周期，因此不使用上述当前结果覆盖确认。`embedding` 按逐 item 跳过、过期重建规则处理，也不复用本确认契约。

### 失效任务重绑

受管快显任务经 cleanup 标记为 `binding_status=missing` 后，统一通过 `POST /api/v1/manager/tasks/{task_type}/{id}/rebind` 显式重绑源资源。请求只提交当前任务 `version` 与新的 `locator`；Manager 按原 `task_type` 和既有产物变体选择对应 Quick View action，复用 Quick View capability、Preview source 解析和强类型配置构造器完成校验，前端不得提交或修改 `config`。重绑入口依赖的标准任务详情必须返回当前 `category`、`version`、`semantic_key`、`binding_status` 和可选 `binding_issue`，不能只在列表响应中暴露这些控制面字段。重绑只恢复任务定义并重建 `task_resource_bindings`，不自动创建 execution；用户随后仍通过标准任务执行入口生成结果。新语义身份已存在规范任务时，重绑合并到该任务并移除旧失效定义，响应返回最终规范任务 ID；旧 execution 和既有 artifact 保留原来源事实，不改挂到新任务。

### PPTX 静态 PDF 预览

PPTX 在线预览的唯一技术路线是：Manager Backend 通过 Quick View Capability 返回受管 artifact 状态和 `generate_pptx_pdf` 动作；前端缺少结果时显式调用 `POST /quick-view/actions` 创建并执行 `pptx_pdf_generation`；Manager 通过 Common `WorkflowRuntimeProvider` direct 调用 Document Workflow `document_to_pdf`。交互入口只接收带 `item_id` 的 ResourceLocator 和 capability 已声明的 action，Manager 必须联查当前租户 Meta DataItem，并在服务端生成 `item_fingerprint`、`source_version` 与源大小，不信任前端提交的缓存身份。同一源版本转换失败后，Capability 只返回失败状态；用户点击重试时再次显式执行同一 action，不得因重新打开页面而自动重复执行。Manager 负责把已授权源和 infra PDF 目标派生为 `addp.workflow.access-plan/v1`，Document Workflow 在隔离工作目录中调用 LibreOffice 无头转换并按目标计划原子发布；结果 ready 后，Capability 返回 PDF 结果 URL，Manager Preview API 仍使用 `content.kind=pdf + preview_material=url + frontend_renderer=pdf` 渲染。前端不得下载完整 PPTX 后用 JSZip 解析或渲染，也不得动态依赖仓库外的 `open-file-viewer`。

Document Workflow 默认单实例转换并发 1，可通过稳定服务端点后的 Runtime 副本扩容；每个执行使用独立临时目录和 LibreOffice profile；根文件系统只读、以非 root 用户运行，只有工作目录可写；禁用宏、扩展和外部链接，生产环境不允许访问公网。转换超时或请求取消时必须终止 LibreOffice 子进程组。发布前必须验证输出是非空且页数大于零的 PDF；失败不得覆盖上一版 ready 对象。Runtime 只声明经过验证的输入格式，第一阶段固定为 `pptx`。

源内容版本使用当前 Meta DataItem 的 `data_updated_at + size_bytes/object_size_bytes` 规范化快照；`item_fingerprint` 只标识稳定数据项，不作为内容版本。结果对象按 `tenant_id + item_fingerprint` 使用稳定当前对象路径，重建时原子替换；数据库中的当前结果更新与 execution 终态必须在持有当前 lease 的事务中完成。MinIO 与 PostgreSQL 无法组成事务，若对象已上传但终态提交失败，数据库仍不得补写伪造成功；同一路径的下次重建会替换该未引用对象，避免产生无界版本孤儿。

转换成功的 `pptx_pdf_generation` execution 必须写入 `addp.lineage-facts/v1`：输入是经 Meta 校验的业务 ResourceLocator、item ID 与 fingerprint，输出是 Manager infra MinIO 的 PDF object locator。PPTX PDF 结果与任务的正式删除入口分别为 `DELETE /api/v1/manager/pptx_pdf/{id}` 和统一任务入口 `DELETE /api/v1/manager/tasks/pptx_pdf_generation/{id}`；结果删除必须先删除受管对象再软删除记录，调用方按“先结果、后任务”的顺序清理，不得直接操作 Manager 数据库或 infra MinIO。

现有 Hosted suite 在基础设施销毁前独立核对 PDF 对象消失、源 PPTX 哈希不变、Meta item 和 Manager／Monitor execution 保留、PDF capability 不再有结果及内容 404；最终部署零残留不能替代这些领域断言。共享单对象清理的故障与租户隔离回归、五类任务的生产绑定约束纳入 `make test-manager-backend`，由模块门禁与 Go workspace CI 自动发现。

### 有界执行监督与租约

`pptx_pdf_generation` 与其他 Manager bounded execution 的唯一运行入口是 Manager Backend 内嵌有界执行监督器。Manager 执行 API 只创建 `pending` execution；监督器由单一协调循环按可用并发槽位、在全部受管 task type 中按创建时间顺序领取，不得为每个槽位或 task type 启动独立空轮询。空队列按 `MANAGER_EXECUTION_CLAIM_INTERVAL` 起步退避至 `MANAGER_EXECUTION_IDLE_MAX_INTERVAL`；本进程成功创建 `pending` execution 后必须唤醒协调循环，多实例或唤醒丢失时仍由有界退避保证最终领取。监督器使用 PostgreSQL claim + lease 领取后调用领域执行器，并在执行期间续租。进程退出或失联导致 lease 过期时，监督器必须将 execution、任务摘要以及属于该 execution 的 `building` 结果原子收敛为 `failed`，错误码固定为 `manager.execution.lease_expired`；升级前遗留或违反协议的无租约 `running` 记录使用 `manager.execution.lease_missing` 收敛；排队后 owner 任务被删除或不再指向该 execution 时使用 `manager.execution.owner_unavailable` 在领取事务内收敛。不得在缺少跨 Runtime fencing 的情况下自动重放同一 execution。旧 attempt 的迟到进度、结果和终态必须因 attempt/token 不匹配而被拒绝。

### 单对象结果清理

PPTX PDF、COG、COPC、GLB 与 KSplat 的单对象清理共用 Manager `MinIOManagedObjectCleaner`，按受管结果的 object `storage_ref` 删除精确对象，不保留按格式重复的单对象 cleaner。生产初始化必须把这五类任务服务绑定到同一个 cleaner。3D Tiles／S3M 目录结果继续使用前缀清理；空间预览的 PMTiles 解析器仍只接受 `.pmtiles`。

结果删除先按租户与结果 ID 读取记录，再清理该记录的对象，最后删除结果记录。存在非空 `storage_ref` 时，cleaner 未绑定、MinIO client 不可用、引用无效或对象删除失败都必须返回可诊断错误，保留原结果状态和记录供显式重试，不能跳过对象清理后删除记录。尚未产出对象且没有 `storage_ref` 的结果允许直接删除记录。结果清理不删除源文件、源 DataItem 或 execution 历史，任务删除继续使用统一任务 API。

## 表结构

### `manager.preview_state`

`manager.preview_state` 是预览模式偏好和预览交互状态表。

核心字段：

| 字段 | 说明 |
| --- | --- |
| `tenant_id` | 租户 ID。 |
| `item_fingerprint` | 空间 item 指纹，作为稳定身份之一。 |
| `locator` | Resource Locator，用于回跳和定位。 |
| `preferred_mode` | 用户偏好的预览模式，允许 `basic_preview` / `map_quick_view`。 |
| `view_state` | 用户交互产生的轻量渲染状态；顶层按 `basic_preview` / `quick_view` 区分显示模式，模式内按 `map` / `scene_3d` 区分渲染域。`scene_3d` 内用 `render_source` 和可选 `artifact_version` 防止不同坐标语义或不同结果版本交叉复用相机；Three.js S3M 额外使用 `renderer_runtime=three_s3m` 隔离旧 Cesium ECEF 相机。 |
| `created_at` / `updated_at` | 生命周期字段。 |

不进入该表的字段：

1. `can_use_quick_view`
2. `can_generate_vector_tile_cache`
3. `render_source`
4. `default_vector_tile_cache_id`
5. `extent`
6. `storage_ref`
7. 任务状态和执行历史

这些字段由能力 API 动态合成或由其他对象承载。

`view_state` 只保存地图视口和三维相机等交互状态，不保存源 metadata、快显结果、任务配置或执行历史。当前结构只按显示模式和渲染域分组：

```json
{
  "basic_preview": {
    "map": {},
    "scene_3d": {}
  },
  "quick_view": {
    "map": {},
    "scene_3d": {}
  }
}
```

不得在 `view_state` 中按 `model_3d`、`tiles_3d`、`gaussian_splat` 等数据类型继续拆分状态；这些差异属于渲染器内部字段，而不是 `preview_state` 表结构。Three.js S3M 的 `renderer_runtime` 只作为 `quick_view.scene_3d` 内部字段保存；恢复相机时必须同时匹配 `render_source`、可选 `artifact_version` 和 `renderer_runtime=three_s3m`，旧 Cesium ECEF 相机直接忽略。

## API

### 快显能力

```http
GET /api/v1/manager/quick-view/capability?locator={resource_locator}
```

用途：返回当前 item 的快显能力、用户偏好、推荐渲染源、渲染事实和瓦片缓存生成入口。

能力判断是资源事实读取，不是数据预览。源身份、类型、格式、几何字段、坐标系、范围和记录数来自当前租户的 Meta 扫描事实；受管产物状态由 Manager 提供，引擎能力和只读目录结构由各自 owner 提供。不得调用 PreviewProvider、批量读取或以 `LIMIT 1` 采样业务表来填充这些事实。事实缺失时返回已有不可用原因或扫描／刷新提示，不以隐式内容读取补齐，也不把未知记录数写成零。

PostgreSQL 渲染目标的 SRID 验证只读取目录中声明的几何类型约束，不从目标表或物化视图抽取几何值。未声明 SRID 的目标不能以一条样本证明整列坐标系；不得据此选为已验证的 3857 目标。

实施约束：源事实解析复用 Meta 解析器，不执行预览 Provider；渲染目标只读取 `pg_attribute` 中真实 PostGIS geometry 字段的 typmod 声明。未声明或声明非 3857 的旧目标不作为已验证目标；Manager 自建结果标记 stale，由用户显式重新生成，不自动 ALTER、刷新或重建。优化目标的精确访问授权仍须独立落实，类型校验不替代访问裁决。

能力接口、预览状态和生成前的能力核对都复用同一资源事实解析。返回内容 URL 或声明技术能力不授予数据访问权；实际 FlatGeobuf、GeoJSON、瓦片和生成任务仍须在各自执行入口核验真实读取范围及安全保护，不能用源表授权自动替代优化目标授权。

```json
}
```

`quick_view.extent` 是前端地图渲染范围，不是源 extent。当前前端对该字段的直接消费约定为 WGS84 经纬度范围，因此返回 `quick_view.extent` 时应同时返回 `extent_srid=4326`。这不是 MVT 的技术要求；MVT 瓦片矩阵仍使用 WebMercator / EPSG:3857。后续如果前端显式支持按 `extent_srid` 注册 CRS 并转换，也可以扩展为消费 3857 或其他可转换 CRS 的 render extent。

### 快显偏好

```http
PATCH /api/v1/manager/preview-state/preferred-mode
Content-Type: application/json
```

请求：

```json

```

`preferred_mode` 允许：


## 渲染事实与来源选择

### 统一渲染事实

后端应形成单一内部主路径：

```text
Resource Locator
  -> source spatial facts
  -> render facts
  -> quick view capability
  -> preview renderer / tile cache task defaults
```

内部渲染事实至少包含：

| 字段 | 说明 |
| --- | --- |
| `source_srid` | 源几何 SRID。 |
| `source_extent` / `source_extent_srid` | 源 extent，只表达源事实。 |
| `geometry_column` / `geometry_type` | 几何列和几何类型。 |
| `record_count` | 记录数。 |
| `render_extent` / `render_extent_srid` | Web 地图可消费的渲染范围，优先 WGS84。 |
| `render_extent_source` | 来源，例如 ready cache、estimated 3857 target、source 4326。 |
| `tile_target_3857` | 可索引 3857 瓦片目标。 |
| `zoom_recommendation` | 推荐层级及状态。 |

### 渲染范围来源优先级

允许的轻量来源：

1. ready `vector_tile_cache` 的 WGS84 范围。
2. 已知 source extent 且 source SRID 明确时，对 bbox geometry 做常量级 CRS 转换，得到 WGS84 或 3857 render extent。该转换只处理已有范围，不扫描源表。
3. 已存在 populated 的 3857 派生产物，例如 `{table}_mv3857.geom_3857`，通过 PostgreSQL 统计信息或 `ST_EstimatedExtent` 获取估算范围后转为 WGS84。
4. 源 extent 本身是 4326 或 3857，且来源可靠。

不允许为了 capability 或任务表单首屏，在大表上同步执行精确 `ST_Extent(ST_Transform(source_geom, 4326))`。

### 渲染源选择

能力合成顺序：

```text
读取源空间事实
  -> 查询 ready vector_tile_cache
  -> 判断 direct_flatgeobuf
  -> 判断 realtime_tile
  -> 判断 raster_mosaic_tile
  -> 判断 vector_tile_cache_generation
  -> 合成 capability
  -> 叠加 quick_view preferred_mode
```

当前渲染源：

| 渲染源 | 条件 |
| --- | --- |
| `cached_tile` | 存在 ready `vector_tile_cache` 且格式和范围可被前端消费。 |
| `client_cog_render` | 存在 ready `raster_cog` 且 COG 结果 facts 与当前 item facts 匹配。 |
| `direct_flatgeobuf` | 中小规模矢量数据的直接要素快显。`direct_flatgeobuf_max_rows` 是默认推荐阈值，不是 PG 动态 MVT 的准入阈值。 |
| `realtime_tile` | PG 空间表的动态 MVT 快显。是否稳定可用由运行时响应时间预算、超时保护和瓦片体积保护兜底，不再用记录数做硬性准入。 |
| `direct_tiff_client` | 小 TIFF 在浏览器预算内，由前端 `geotiff.js` 全量读取并渲染。 |
| `raster_mosaic_tile` | `format=raster_mosaic` item 的后端瓦片渲染源，低层级读取 overview COG 或 tile cache，中高层级按 index 读取 leaf COG window。 |
