# Manager 数据预览语义协议

## 背景

Manager 负责把不同数据源、数据类型和文件格式转换为前端可展示的预览响应。`data_type` 和 `format` 描述的是数据本体，但它们不足以描述一次预览响应给前端的具体材料。

例如同一个 PDF 文件可以返回：

- 一个 `storage-stream` URL，让前端用 PDF 组件按需加载。
- 小体积 base64 原始字节，让前端直接渲染。
- 抽取出的文本。
- 不支持在线预览的状态。

这些响应的 `data_type=document`、`format=pdf` 可以相同，但前端展示方式完全不同。因此 Manager Preview API 需要额外的预览语义字段。

## 分层定义

| 层次 | 字段 | 责任 |
|---|---|---|
| 数据识别层 | `data_type` | 描述数据本体类型，如 document、table、media、container、graph、unknown |
| 格式识别层 | `format` | 描述文件或内容格式，如 pdf、docx、json、parquet、shapefile |
| 预览内容层 | `content.kind` | 描述本次预览内容大类，如 text、json、table、container、image、pdf |
| 预览材料层 | `preview_material` | 描述后端实际给前端的展示材料或展示状态，如 url、text、json、geojson、table、raw_binary、unsupported |
| 前端渲染层 | `frontend_renderer` | 建议前端使用的渲染器，如 text、json、map、table、container、pdf |

`data_type` 和 `format` 来自平台数据类型与格式体系。`content.kind`、`preview_material`、`frontend_renderer` 是 Manager 面向前端预览响应的语义协议。

空间不是独立 `data_type`。空间表、GeoJSON 或 GeoTIFF 等对象应通过 `data_type` 与 `capabilities.spatial` 组合表达，Manager 可以据此选择 `frontend_renderer=map`。

## 字段职责

### `content.kind`

`content.kind` 表示本次预览内容的大类。它通常接近格式或数据类型，但不等同于 `format`。

示例：

- PDF 原始预览：`content.kind=pdf`
- GeoJSON 预览：`content.kind=json`
- 容器索引：`content.kind=container`
- 表格材料：`content.kind=table`
- 不支持在线预览的说明：`content.kind=unsupported`

`content.kind` 是粗分类字段，不应单独承担前端组件决策。

GeoJSON 预览使用 `content.kind=json`，是因为响应材料本身是 JSON 对象；这不改变平台格式事实。已入库对象仍应保持 `format=geojson`、`data_type=table`，空间事实由 `capabilities.spatial` 表达。

### `preview_material`

`preview_material` 描述后端实际给前端的展示材料，是前端展示协议的核心字段。

合法取值：

| 取值 | 含义 |
|---|---|
| `url` | 后端提供可访问 URL，前端通过 URL 加载 |
| `raw_binary` | 后端返回 base64 原始二进制材料 |
| `text` | 后端返回文本 |
| `markdown` | 后端返回 Markdown 文本 |
| `json` | 后端返回普通 JSON 对象 |
| `geojson` | 后端返回 GeoJSON / 空间 JSON 对象 |
| `table` | 后端返回 columns / rows 表格材料 |
| `container` | 后端返回容器索引 / 子对象导航材料 |
| `unsupported` | Manager 不支持该内容在线预览，前端应展示不支持状态 |

`preview_material` 不等同于 `common/format` 的 `content_readers` 声明。不得把 `raw_content`、`range_content`、`binary_content` 等 format capability 名称写入 `preview_material`。

若后端只是为了判断 unknown 内容读取了一段二进制探测样本，但 Manager 不支持该格式在线预览，则 `preview_material` 必须是 `unsupported`，`frontend_renderer` 必须是 `unsupported`。可以在 `metadata.binary_probe=true`、`metadata.probe_truncated=true/false` 中记录探测事实。不能因为做过二进制探测就把 `preview_material` 标成 `raw_binary`；也不能把“不支持在线预览”的提示文案伪装成 `text` 材料。

容器子项和相关文件的 preview hint 也必须遵循同一规则。只有 PDF、DOCX、PPTX、WPS、图片、视频等 Manager 已有明确前端 renderer 的格式，才能在 hint 中使用 `raw_binary`；未知 document / media 只能标记为 `unsupported`。

### `frontend_renderer`

`frontend_renderer` 是 Manager 对前端渲染组件的建议。前端可以按它选择具体组件，也可以在不支持时降级。

示例：

- `frontend_renderer=map`：使用地图或空间组件。
- `frontend_renderer=container`：使用容器子对象导航组件。
- `frontend_renderer=pdf`：使用 PDF 组件。
- `frontend_renderer=model_3d`：使用三维模型组件。
- `frontend_renderer=3dtiles`：使用 3D Tiles 分块三维场景组件。
- `frontend_renderer=point_cloud`：使用点云组件。
- `frontend_renderer=gaussian_splat`：使用高斯泼溅组件。
- `frontend_renderer=text`：使用文本组件。

### 空间预览 CRS 契约

普通 Manager 空间预览不做后端 CRS transform。表格空间预览、GeoJSON 分页预览、要素几何预览都应返回源坐标下的 geometry 表达，并通过 CRS 元数据说明前端是否可以直接渲染。

空间预览契约字段：

| 字段 | 含义 |
|---|---|
| `geometry_column` | 本次预览使用的几何字段。 |
| `source_srid` | 源 geometry 的 SRID；无法确定时为 `0` 或省略。 |
| `source_crs` | 源 CRS ID，对应 `capabilities.spatial.geometry_columns[].crs_ref` 或由 SRID 派生的 `EPSG:<srid>`；不得混装 WKT / PROJ4 定义文本。 |
| `source_crs_definition` | 当前 `source_crs` 对应的 CRS 定义。仅当前端需要且后端能从标准 attributes 或引擎 CRS 表获得定义时返回。 |
| `source_crs_definition.definition_encoding` | CRS 定义表达方式。第一阶段只允许 `wkt`、`esri_wkt`、`proj4`。 |
| `source_crs_definition.definition` | CRS 定义文本，供前端 CRS registry 注册使用。 |
| `target_srid` | 普通预览不返回。仅 MVT、矢量物化视图等明确引擎转换路径可在各自契约中填写。 |
| `transform_status` | `not_transformed`、`unknown_crs`、`engine_transformed`。普通预览只使用 `not_transformed` 或 `unknown_crs`。 |
| `transform_engine` | 仅 `engine_transformed` 时填写，例如 `postgis`。 |
| `preview_hint` | 前端消费提示，例如 `direct_renderable`、`frontend_transform_required`、`unknown_crs`。 |
| `transform_message` | 普通预览不返回。前端只消费 `transform_status` / `preview_hint` 并按 i18n 展示状态。 |

规则：

- `source_srid=4326` 且 `transform_status=not_transformed` 时，普通 OpenLayers 预览可按源 GeoJSON / WKT 直接解析为 WGS84 数据。
- `source_srid>0` 且不是 `4326` 时，后端仍返回源坐标 geometry，`preview_hint=frontend_transform_required`；前端只在本地 CRS registry 已注册该 CRS，或响应提供可注册的 `source_crs_definition` 时执行小样本预览转换，否则压制地图。
- `source_srid=0` 且 CRS 事实缺失时，必须返回 `transform_status=unknown_crs`，不得当作 `EPSG:4326`。如果 `source_srid=0` 但存在 `source_crs=ADDP:CRS:<sha256>` 和 `source_crs_definition`，前端可按定义尝试转换。
- 前端不得仅凭 `target_srid=4326` 判定 geometry 已可直接渲染；只有 `transform_status=engine_transformed` 且目标 CRS 明确为 `EPSG:4326` 时，才能按已转换 WGS84 geometry 处理。
- `render_geometry_columns` 已废弃并删除；后端不得再返回“原 geometry + 渲染 geometry”双字段路径。
- MVT、矢量物化视图等明确属于 PostGIS / MVT 引擎能力的路径可以使用引擎自身转换，但必须在各自契约中说明目标 SRID。

当前前端 CRS registry 只内置 `EPSG:4326` 与 `EPSG:3857`，并优先尝试注册后端返回的 `source_crs_definition.definition`。前端不访问外部 EPSG 服务，也不得把 `source_crs=EPSG:<code>` 当作 CRS 定义文本。

在线底图的坐标加偏策略属于底图展示 profile，不属于 CRS registry，也不得写入 `source_crs` 或 `capabilities.spatial`。当前高德底图 profile 使用 `coordinate_policy=gcj02`，前端只在高德 renderer 调用 AMap JSAPI 的展示边界执行 WGS84 到 GCJ-02 偏移；组件事件回传的 `coordinate` 仍保持 WGS84 语义，弹窗定位使用 provider 展示坐标 `position`。选择 GCJ-02 底图时前端必须提示该模式仅用于业务浏览，不作为精确空间校验依据。BD-09 尚未实现。

### `preview_kind`

`preview_kind` 是同一预览内容大类下的细分展示语义，只用于指导前端在已选定渲染器内部采用更合适的交互方式。它不改变 `data_type`、`format`、`content.kind`、`preview_material` 或 `frontend_renderer`，也不得作为后端 provider 抽象或元数据类型的事实来源。

当前已使用的取值：

| 取值 | 适用响应 | 前端语义 |
|---|---|---|
| `graph_overview` | `frontend_renderer=table` 的图整体概览 | 表格展示图结构摘要，并可联动图样本预览。 |
| `dynamic_schema_record_set` | `frontend_renderer=table` 的动态 schema 记录集合 | 表格默认展示 `_id` / 标量字段，嵌套 object / array 以摘要呈现，用户可按需展开 JSON 或选择字段。 |

MongoDB collection 等动态 schema 记录集合仍按 `data_type=table`、`content.kind=table`、`preview_material=table`、`frontend_renderer=table` 消费。`preview_kind=dynamic_schema_record_set` 只说明该 table preview 的记录字段可能来自采样画像且不具备强 schema，前端应避免把嵌套 JSON 字段直接铺满表格；不得因此新增 `data_type=document`、`type_info.collection` 或单独的文档型查询入口。

## 前端选择规则

前端选择预览组件时，应按以下顺序兜底：

```text
frontend_renderer -> preview_material -> content.kind
```

即：

1. 若存在合法 `frontend_renderer`，优先按它选择组件。
2. 若没有 renderer，则按 `preview_material` 选择组件。
3. 若没有 material，则按 `content.kind` 兜底。

不能直接用 `format` 决定前端组件。`format` 只能作为识别与路由事实，不能表达本次响应材料。

## 推荐组合矩阵

| 内容语义 | `content.kind` | `preview_material` | `frontend_renderer` |
|---|---|---|---|
| 普通文本 | `text` | `text` | `text` |
| Markdown | `markdown` | `markdown` | `markdown` |
| 普通 JSON | `json` | `json` | `json` |
| GeoJSON / 空间 JSON | `json` | `geojson` | `map` |
| 表格材料 | `table` | `table` | `table` |
| 容器索引 / 子对象导航 | `container` | `container` | `container` |
| 图片 URL 预览 | `image` | `url` | `image` |
| 视频 URL 预览 | `video` | `url` | `video` |
| 音频 URL 预览 | `audio` | `url` | `audio` |
| PDF URL 预览 | `pdf` | `url` | `pdf` |
| DOCX URL 预览 | `docx` | `url` | `docx` |
| PPTX URL 预览 | `pptx` | `url` | `pptx` |
| WPS 原始二进制兜底 | `wps` | `raw_binary` | `wps` |
| GLB 三维模型 URL 预览 | `model_3d` | `url` | `model_3d` |
| 3D Tiles 分块三维场景 URL 预览 | `model_3d` | `url` | `3dtiles` |
| LAS 点云抽样预览 | `point_cloud` | `json` | `point_cloud` |
| LAZ / COPC / E57 / PCD / XYZ 点云摘要 | `point_cloud` | `unsupported` | `unsupported` |
| 高斯泼溅 URL 预览 | `gaussian_splat` | `url` | `gaussian_splat` |
| 不支持在线预览状态 | `unsupported` | `unsupported` | `unsupported` |

JSON 只是常见承载形式，不等于 `preview_material=json`。例如表格材料和容器索引都可能用 JSON 结构承载，但它们的展示语义分别是 `table` 和 `container`。

高斯泼溅 KSplat 快显可以在 `metadata.gaussian_splat.progressive_order` 中声明渐进顺序。`center_first` 表示 artifact 已按场景中心组织 section，前端可以渐进加载；`source_order` 表示 artifact 沿用源文件 section 顺序，前端不应假定中心优先。

### `metadata.preview_artifact_*`

当一次普通预览需要依赖 Manager 受管快显 artifact 时，后端可在 `content.metadata` 中返回以下字段：

| 字段 | 含义 |
|---|---|
| `preview_artifact_status` | 当前预览 artifact 状态，例如 `ready`、`preview_artifact_missing`、`preview_url_missing`。 |
| `preview_artifact_task_type` | 可创建或执行的任务类型，例如 `model_3d_glb_generation`、`gaussian_splat_ksplat_generation`。 |
| `preview_artifact_id` | 已就绪 artifact 在 Manager 结果表中的 ID。 |

这些字段只描述普通预览依赖的受管 artifact，不等同于 `manager.preview_state`。`preview_state` 只保存用户预览偏好和交互视角，不保存 artifact 状态、任务类型或执行历史。

## Truncated 语义

`truncated=true` 只表示“当前返回的可展示材料被截断”。当后端没有任何可展示材料时，不应返回 `truncated=true`。

可展示材料包括：

- `text`
- `json`
- `geojson`
- `data`
- `url`

若格式不可在线预览，应返回 `content.kind=unsupported`、`preview_material=unsupported`、`frontend_renderer=unsupported`，由前端按统一状态展示“暂不支持在线预览”，而不是返回空内容加 `truncated=true`。

## 与 `common/format` 的边界

`common/format` 负责描述和实现格式能力，例如：

- `DocumentTextReader`
- `TableSampleReader`
- `BinaryContentReader`

这些能力描述的是格式层解码、抽取或语义读取能力，不是前端展示材料协议。`raw_content` / `range_content` 属于 engine / contentio / URL 内容通道，不进入 `FormatDescriptor`，也不是 format plugin 的 Go reader。

Manager 可以基于这些能力生成预览材料，但生成后的响应必须使用 Manager 预览语义字段：

- `preview_material`
- `frontend_renderer`
- `content.kind`

Manager 只消费平台已经确认的 `data_type`、`format`、`type_info.*` 和 `capabilities.*` 事实，不重新定义 data type。空间预览、GeoJSON 预览、GeoTIFF 预览等都应由 `data_type + capabilities.spatial` 派生渲染策略，而不是新增 `spatial` data type。

GeoJSON 是特殊的表格格式预览材料：对象内容入口应优先生成 `preview_material=geojson` 和 `frontend_renderer=map`，而不是按通用表格材料返回 `preview_material=table`。普通 JSON records、CSV、Parquet 等仍走表格材料。

## 与存储下载的关系

`storage-stream` 是 Manager 后端代理读取单个存储叶子内容的统一入口。当前预览材料为 URL 时，通常应返回 ADDP 后端的 `storage-stream` URL，而不是真实存储引擎地址。

`preview_material=url` 只表示前端应通过 URL 加载材料，不表示浏览器可以直接访问 MinIO、S3、NFS 等真实存储。

预览状态不决定下载能力。`preview_material=unsupported` 只表示 Manager 不支持该内容在线预览，不表示该对象不可读取或不可下载。只要资源是合法的存储型 item，Manager 后端应能基于 ResourceLocator 解析 DownloadPlan，并通过逻辑下载入口提供原始下载。

原始下载与在线预览使用不同语义：

- `storage-stream`：读取一个存储叶子，支持 Range，主要服务 PDF、图片、视频等按需预览和底层单叶子流。
- `downloads/file`：下载一个存储型 item 逻辑对象，内部基于 ResourceLocator 和 DownloadPlan 自动选择单叶子流式下载或 multi refs zip 打包。

完整的存储流与原始下载语义见 `manager/docs/存储流与原始下载语义.md`。本协议只规定预览响应如何表达材料和状态。

前端通用预览组件不应根据 `format`、`preview_material` 或 `frontend_renderer` 推导原始下载方式，也不应从 `content.metadata.refs` 拼接 multi 文件下载。对于文件/对象类数据，前端应使用 `downloads/file?locator=...`；对于数据库表等非存储叶子，完整数据出本地属于导出语义，走 Manager export，内部调用 Transfer sync。第一阶段不支持数据库表当前页预览下载。

同理，底层 raw binary / `BinaryContentReader` 能力表示“可以读取原始字节”，主要服务下载、传输、未来专业解析器或计算端；它不自动等价为 Manager 在线预览材料。只有前端已有明确 renderer 且响应实际携带对应材料时，Manager 才能使用 `preview_material=raw_binary`。

## 禁止事项

- 不得把 `raw_content`、`range_content`、`binary_content` 写入 `preview_material`。
- 不得在没有 `text/json/geojson/data/url` 等展示材料时返回 `truncated=true`。
- 不得仅凭 `format` 决定前端渲染组件。
- 不得把 `spatial`、`geojson`、`image`、`pdf` 等预览或渲染语义反向写成平台 data type。
- 不得把容器索引材料伪装成普通 JSON 源码展示。
- 不得把表格 rows / columns 材料伪装成普通 JSON 源码展示。
- 不得把 unsupported 状态伪装成 text 材料。
- 不得因为 `preview_material=unsupported` 禁用存储叶子内容的原始下载。
- 不得因为 `content.kind=table` 或 `frontend_renderer=table` 就把文件表预览的原始下载降级为当前页 CSV。
- 不得让前端解释 multi refs 或自行拼接 zip 下载。

## 实现约束

- 后端 `objectcontent.DecoratePreviewContent` 应负责补齐或规范化默认 `preview_material` 和 `frontend_renderer`。
- 前端通用对象预览组件应优先消费 `frontend_renderer` 和 `preview_material`。
- 后端原始下载应通过统一 DownloadPlan resolver 处理 single / multi / export，不在 Handler 或前端按具体格式写下载分支。
- 新增 object content handler 时，应补充语义矩阵测试，确认 `kind`、`preview_material`、`frontend_renderer` 三者一致。
