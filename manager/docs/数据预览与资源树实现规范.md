# Manager 数据预览与资源树实现规范

> 状态：Manager 模块稳定实现规范。本文定义 Manager 数据探查、资源树、数据预览、容器子项选择和预览插件编排的当前契约。预览响应材料语义见 [数据预览语义协议](数据预览语义协议.md)，存储流和原始下载语义见 [存储流与原始下载语义](存储流与原始下载语义.md)。

阅读导航：[资源定位](#二resourcelocator)、[API 契约](#三api-契约)、[后端编排](#四后端实现路线)、[前端状态](#五前端实现路线)、[静态轨迹](#六设备静态轨迹预览)、[能力关系](#七与其他-manager-能力的关系)、[验证](#九验证命令)。

## 一、定位

Manager 负责面向用户的数据探查和只读预览：

1. 从 System 读取用户可访问的引擎信息。
2. 从 Meta 读取已扫描入库的节点、item 和 attributes 事实。目录 `item_count`、`total_size_bytes` 由 Meta 从当前有效子树的 item 记录派生；Manager 不按上传、删除事件加减计数，也不以当前分页条数代替子树统计。上传等待 Meta 同步完成后重新读取目录，扫描状态与当前数量独立展示。
3. 消费 Meta resource-tree API 定位资源树节点或数据项。
4. 通过 PreviewResolver 和 PreviewProvider 生成前端可展示的预览材料。
5. 对存储叶子提供 `storage-stream` 预览流，对存储型 item 提供 `downloads/file` 原始下载入口。

Manager 不管理存储引擎配置，不绕过 Meta 自行定义 data type / format，不提供通用资源树事实代理，不在预览链路中写入派生产物事实。资源树刷新归 Meta resource-tree；Manager 保留已知 item refresh 作为预览建议触发入口。空间快显、瓦片缓存和矢量物化视图属于独立快显体系，见 [快显概念说明](快显概念说明.md) 和 [快显实现规范](快显实现规范.md)。

已知 item 深度刷新（含 CSV/TSV 应用编码）遵循授权上下文规范的同步 BFF 主线：入口只允许当前 Tenant User，同时要求 `manager.data_item.update` 与 `meta.scan_task.execute`；Manager 使用独立 `MetaScanUserClient` 将当前请求的 User Bearer 交给唯一 Meta item refresh API，Meta 重新认证并记录真实发起用户。凭据不进入客户端状态、持久记录、日志或 Worker；不能改用 Service 身份重试或在正文自报用户。编码及精确 item 范围保持原契约；下游 400/403/404/409/504 保留对应失败语义，认证失效、传输故障或其他下游失败返回安全的 503，不转成入口 401 触发刷新 POST 自动重放。验证入口见[验证命令](#九验证命令)；真实刷新、下载与清理复验沿用既有 Manager Hosted suite，不扩张测试身份权限。

数据探查页面入口统一要求 Tenant Context 和 `manager.data_item.read`，与引擎列表、预览描述、资源事实及快显能力接口一致。Console 菜单、直接地址和 Manager 独立入口复用 `common-frontend` 的同一页面规则。进入页面不授予具体内容读取权限：原文件流、原始下载和存储资产继续校验 `manager.content.read`，PDF、COG、GLB 等受管产物内容继续校验 `manager.derived_artifact.read`，各接口仍执行其租户、资源与数据保护检查。不能把原文件读取权限设为整个页面的前置条件，阻断已授权的受管产物消费；也不能为此扩张消费账号权限或绕过后端判断。

普通 TIFF 由共享 `ImagePreview` 读取 Meta 的 `format_info.tiff.page_summary_status/page_count/pages`。仅完整页目录允许分页，按 `ifd_index` 经既有同源 `storage-stream` Range URL 解码当前页，不在 Manager 新建 TIFF 解析器、不整文件加载兜底。页面目录缺失或不完整时提示对该 item 深度刷新；BigTIFF 明确提示当前基础预览不支持。输出与解码预算见平台内置格式规范。GeoTIFF 空间预览、原始下载及接口路由保持原契约。

数据预览同时是 Security 保护投影的服务端执行边界。`/preview` 先从已校验的 Locator 和 Meta item 取得 DataItem fingerprint，再查询 Manager 本地保护投影：未纳管时保持原路径；`enrolling`、失效或结构不匹配时拒绝；`active` 时先校验 Meta `FieldInfo` 结构快照，再执行原有 PreviewProvider，最后在 HTTP 序列化前递归处理 `TablePreview.rows`。前端永远不接收明文后再遮盖，MongoDB、PostgreSQL 等具体 PreviewProvider 不实现私有脱敏分支。

Security 拒绝数据预览时不得连带隐藏 Meta 技术元数据。“属性”视图回答 DataItem 的身份、结构、格式和能力事实，与“预览”数据值出口独立；前端在 `/preview` 未返回 item metadata 时，只允许按 DataItem ID 从 Meta 读取已扫描的技术事实，不得因此读取数据行或原始内容。正常预览已携带 item metadata 时不再发起该请求。按 `tab=attributes` 打开的链接在 Meta 请求尚未结束时必须保留属性视图；只有当前请求完成且确实没有元数据时，才规范化回预览视图，不能把加载中的暂缺事实当作不支持属性。

表格预览的 `preview=suppress` 必须同时删除行值、输出列和对应列元数据；空结果页也不得重新暴露被抑制列。响应边界复用 Common 的查询结果保护执行器，Manager 只适配预览协议；临时原值授权命中时，列契约与有效允许决策保持一致，不能按默认规则额外删除已授权列。

预览失败展示保留服务端稳定错误码。HTTP 403 且 `error_code=security_protection_required` 表示当前数据保护要求阻止预览，界面应引导核对保护规则、同步状态和有效期；不能将其解释为缺少功能权限或源数据 Grant。其他 403 继续展示读取权限提示，503 继续展示依赖不可用；成功重读或切换资源时必须清除旧失败状态。

## 二、ResourceLocator

Manager 预览、资源树刷新、资源定位和跨页面跳转统一使用标准 ResourceLocator URI 作为定位入口。

格式示例：

```text
addp://engine/1/path/?type=database&node_id=10
addp://engine/1/path/public?type=schema&node_id=11
addp://engine/1/path/public/users?type=table&item_id=100
addp://engine/1/path/bucket/folder/file.txt?type=object&item_id=101
```

约束：

1. `locator` 是公共 API 的主身份；`engine_id/schema/table` 等拆散参数只允许作为 provider 内部解析结果。
2. 路径由 ResourceLocator 负责编码和解码，调用方不得手工拼接未转义路径。
3. 预览必须基于已由 Meta 扫描入库的 node 或 item。缺少 Meta 事实时，应提示刷新或扫描，而不是由 Manager 直接猜测结构。
4. 前端保存选中节点、展开节点和跳转上下文时，应使用 locator，而不是旧式拼接 node id。
5. 资源树定位以 locator path 为主事实源。检索索引、任务记录或前端缓存中的 `node_id` / `item_id` 可能因重新扫描发生漂移，只能作为定位身份锚点，不能压过 locator path。
6. locator 是内部定位契约，不作为用户理解对象暴露。界面应展示引擎名、资源路径、资源名和操作按钮，不展示 locator URI。
7. 数据探查的面板选择及预览请求按 locator 的 `node_id` / `item_id` 身份分流，不维护展示类型白名单。`index` 以及展示为 `directory` 的 whole-layout item 均按 item 身份请求预览；node 身份展示范围详情并按需加载子资源。

## 三、API 契约

路由前缀为 `/api/v1/manager`。

### 1. 引擎与资源树

```http
GET  /engines
POST /engines/{engine_id}/items/refresh
```

Manager 不再提供 `/tree/{engine_id}` 通用资源树 API。资源树 root、node children、ancestors、search 和 refresh 统一调用 Meta：

```http
GET  /api/v1/meta/resource-tree/{engine_id}?expand_depth=2
GET  /api/v1/meta/resource-tree/{engine_id}/node?locator={resource_locator}
GET  /api/v1/meta/resource-tree/{engine_id}/ancestors?locator={resource_locator}
GET  /api/v1/meta/resource-tree/{engine_id}/search?q={keyword}&node_types=table,object&limit=50
POST /api/v1/meta/resource-tree/{engine_id}/refresh?locator={resource_locator}
```

资源树 API 返回面向前端的公共资源树节点，节点必须携带 locator。资源树节点展示字段来自 Meta node、Meta item 和 System engine 事实，不得改变 Meta 中的事实定义。

刷新语义必须按资源身份分开：

1. node 行的刷新调用 Meta resource-tree refresh，固定执行 `scan_depth=basic, force=true`，用于重新枚举该范围并发现新 node / item。
2. item 行的刷新调用 Manager known-item refresh，固定执行 `scan_depth=deep, force=true`，只更新已知 item 自身的 attributes、字段、format info、access index 和横切能力。前端 Store 的刷新动作不读取数据；宿主仅在当前预览页刷新所选 item 时重读预览。容器预览先重读容器索引，再读取仍存在的当前子项，保留子项选择和页码；当前子项已移除时，读取新索引的默认子项第一页。刷新期间切换资源或子项后，旧请求不得覆盖新选择。
3. node basic scan 不代替 item deep scan；item refresh 也不得扩大为父 node 范围扫描。
4. 上传、导入的 Meta 同步或 node 刷新完成后，统一强制重载目标节点的直接子资源，并通过 ancestors API 回读目标到根的权威统计。合并祖先事实时保留已加载子树、展开状态和当前选择，同时失效该链上的 children 缓存，避免旧祖先响应重新覆盖新统计。不得清空并按浅层深度重建整棵引擎树，也不得在前端逐级加减计数。
5. 同一个刷新图标必须按 ResourceLocator 身份提供不同提示：node 标明“基础刷新”，item 标明“深度刷新”。
6. 资源树行内只保留刷新快捷操作。向量化从选中资源的操作区或“数据任务”入口发起，不在每个树行上堆叠状态或快捷图标。
7. Meta 返回 `409 + scan_scope_active` 时，表示同范围扫描已经在执行。资源树展示服务端本地化提示，保留正在跟踪的执行进度及树选择，不显示“后台扫描失败”；仅在提交成功后更新后台扫描状态。
8. 节点详情右上角提供独立“深度扫描”操作，通过 Meta 手动扫描接口提交当前 node 的完整 ResourceLocator，固定使用 `scan_depth=deep, force=true, source=manager`，扫描当前节点及其全部下级资源。它与树行的基础刷新共用执行等待和扫描后的资源树回读流程；执行期间禁用当前节点的重复操作，引擎不可用时不允许提交。扫描完成后更新范围状态、深度和时间，切换节点后仍只刷新原扫描范围，不改变当前选择。
9. 已提交的 node 扫描执行进入成功、失败、超时或取消终态后，都回读该节点及祖先的权威事实；失败不能让页面继续保留过期状态，也不能提升已完成深度或成功时间。失败反馈消费 Meta 安全执行响应的 `error_details`，通过共享 `ExecutionFailure` 展示安全类别、稳定码和 execution UUID；不读取旧 `error_message` 或回显运行时自由文本。节点切换后，旧执行失败面板不得覆盖新节点。
10. node 行内基础刷新与详情深度扫描共用资源树顶部的同一条扫描进度条及生命周期回调，不以按钮转圈替代进度。提交成功后显示执行进度，扫描完成后的资源树回读仍保持可见，回读完成后才显示成功；失败显示安全诊断，提交冲突不覆盖正在跟踪的执行。切换所选节点或进入 item 预览时，已提交扫描的进度继续更新。
11. 文件系统扫描消费 Meta 的 `scan_progress`：枚举/识别时显示已发现文件、目录与未确定总量；处理时显示已处理/计划数据项、成功/失败、当前路径及操作，内容指纹读取显示当前文件字节数。总量未知使用不定进度，禁止固定 10% 等估计值；已知比例只表示数据项处理，执行成功前最多 99%。同时显示耗时和距 `last_progress_at` 的时间，不把租约心跳当作进展；失败保留真实比例和计数。节点详情单列本次执行状态，历史范围状态、深度和最近成功时间保持独立。 旧组件索引清理另显示 cleaning_index 操作和累计已确认／总量／未确认数量，不改变数据项处理分母，也不把未确认投递显示为成功删除。

节点详情独立展示最近范围扫描状态（`scan_status`）、已完成扫描深度（`scanned_depth`）和最近成功扫描时间（`scanned_at`）。扫描失败不表示当前元数据不可读取；文件刷新成功也不能证明整个父目录已扫描成功。缺失事实显示未知，不从数量或某个 attributes 字段推测状态、深度和时间。

属性提取的范围读取显示实际返回字节数和已读取范围数；范围总量未知时不制造采样百分比，不改变逻辑数据项的处理分母，也不混用内容指纹读取字节。打开范围或读取 EOF 不能冒充进展。

#### 引擎连通性与历史资源树

Manager 必须分开处理 System 中的引擎运行事实和 Meta 中的历史扫描事实：

1. `GET /engines` 返回当前 Tenant 下 `active + storage capability matched` 的注册引擎及其 `connection_status`。非 `online` 引擎仍在 Data Explorer 中展示，不因断连丢失 Engine Instance 身份。
2. Meta resource-tree 是已扫描的历史事实视图。引擎离线时仍允许展开、定位和阅读已有节点、item 和 attributes，不得清空资源树或删除当前 locator。
3. 数据预览、存储流、下载、资源刷新、上传、导入、导出、向量化和快显生成等会访问实际引擎的操作，只能在引擎 `active + online` 时发起。
4. 前端根据当前 `connection_status` 标记非在线引擎并禁用实时操作；Backend 在每次实时入口中必须重新读取 System 当前事实并校验，不得以前端禁用或历史缓存作为边界。
5. 引擎从非 `online` 恢复为 `online` 后，Data Explorer 应动态刷新状态并恢复实时操作，不需要重启 Manager，不自动改选其他引擎。
6. 引擎不可用是可重试的运行状态，不得返回或展示为权限不足。HTTP 入口统一返回 `503 Service Unavailable` 和稳定 `error_code=engine_unavailable`。
7. Data Explorer 首次进入只加载一次引擎目录，不得并发预取所有引擎的资源树；资源树按展开或 locator 定位按需加载，避免一个下游失败拖垮整个页面初始化。
8. 同一页面生命周期内的并发引擎目录请求必须合并为一个 single-flight；Gateway 启动收敛期间的 `502/503/504` 和网络瞬态错误由共享退避策略自动重试，只展示一次最终失败。
9. 初次发现失败后，周期状态刷新必须自动恢复引擎目录，并继续完成 URL 中尚未完成的 locator 定位；不得要求用户手工刷新整个页面。

#### 资源树祖先链定位

`GET /api/v1/meta/resource-tree/{engine_id}/ancestors?locator={resource_locator}` 用于根据 ResourceLocator 返回从 catalog root 到目标资源自身的祖先链，服务资源树懒加载场景下的深层定位和高亮。

该接口语义是“为资源树展开返回祖先链”，不是读取内容、刷新扫描或创建 Meta 事实。

请求约束：

| 参数 | 说明 |
| --- | --- |
| `engine_id` | 路径参数，用于租户权限和 engine 边界校验。 |
| `locator` | 标准 ResourceLocator URI，必须与 `engine_id` 匹配，并携带 `node_id` 或 `item_id` 作为身份锚点。 |

响应结构：

```json
{
  "engine_id": 1,
  "target_locator": "addp://engine/1/path/bucket/a/b/report.pdf?type=object&item_id=123",
  "target_kind": "item",
  "ancestors": [
    {
      "locator": "addp://engine/1/path/?type=service&node_id=10",
      "type": "service",
      "label": "对象存储",
      "node_id": 10,
      "item_id": null,
      "has_children": true
    },
    {
      "locator": "addp://engine/1/path/bucket?type=bucket&node_id=11",
      "type": "bucket",
      "label": "bucket",
      "node_id": 11,
      "item_id": null,
      "has_children": true
    },
    {
      "locator": "addp://engine/1/path/bucket/a/b/report.pdf?type=object&item_id=123",
      "type": "object",
      "label": "report.pdf",
      "node_id": null,
      "item_id": 123,
      "has_children": false
    }
  ]
}
```

约束：

1. `ancestors` 必须按 root 到目标自身排序。
2. 最后一项必须对应 `target_locator`。
3. node 目标最后一项带 `node_id`，item 目标最后一项带 `item_id`。
4. 每项 locator 必须是标准 ResourceLocator，供前端作为 tree node key。
5. 展示字段可包含 `label/type/has_children`，但不得返回 engine 凭据或 provider 私有连接信息。
6. 部分祖先缺失时返回 404，不引入 `resolved=false` 成功态双轨响应。

Meta resource-tree 处理原则：

1. 先解析 locator，校验 engine、type、`node_id` / `item_id`。
2. 如果 locator 携带 `item_id`，先按 locator path 查询当前 Meta item，再基于当前 item ID 查询祖先链，并用当前 `full_name` 和 item_type 生成目标 locator。
3. 如果 locator 携带 `node_id`，先按 locator path 查询当前 Meta node，再基于当前 node ID 查询祖先链，并用当前 node path 生成目标 locator。
4. 祖先链事实来自 Meta 已落库 node 关系，不触发扫描，不写 Meta attributes，不隐式创建 node / item。
5. engine catalog 模型差异由 Meta resource-tree 统一处理，前端只消费返回链。

### 2. 数据预览

```http
GET /preview?locator={resource_locator}&page=1&page_size=20
```

数据项的用户预览设置统一使用：

```http
GET   /preview-state?locator={resource_locator}
PATCH /preview-state/view-state
```

`preview_state` 以 `tenant_id + item_fingerprint` 为偏好身份，locator 只负责定位和回跳。所有引擎的表格预览统一提供字段选择，并把结果保存到 `view_state.basic_preview.table.visible_columns`；空间表的原始几何字段不进入普通字段选择，空间地图视口与三维相机继续分别保存到 `map` 和 `scene_3d`。前端恢复字段设置时只保留当前结构中仍存在的字段，不按旧字段名做兼容映射。

动态 schema 集合的表格列必须以 Provider 返回的 `column_metadata.path` 为结构事实。顶层 `type=object` 且存在直接子字段时，预览表格将父对象展开为点路径列（例如 `userInfo.gender`），字段选择和 `visible_columns` 同样使用该点路径身份；数组和没有稳定子字段事实的对象仍使用结构化摘要与详情弹窗，不根据当前分页记录临时猜测列结构。

容器和多组件格式的选择参数必须保持语义独立：

| 参数 | 语义 | 示例 |
| --- | --- | --- |
| `child_name` | 当前容器第一层 child。 | `Sheet1`、`cities`、`inner.zip` |
| `ref_path` | multi 格式 child 的 ref 路径。 | `roads.shp`、`roads.dbf` |
| `nested_child_path` | 当前 child 是容器时，其内部 child 相对路径。 | `data/cities.csv`、`middle.zip/data/cities.csv` |

示例：

```http
GET /preview?locator={zip_locator}&child_name=inner.zip&nested_child_path=data/cities.csv
GET /preview?locator={zip_locator}&child_name=roads.shp&ref_path=roads.dbf
```

这些参数不能互相替代：

1. `child_name` 只表示当前容器的第一层 child。
2. `ref_path` 只表示 multi item 的组成 ref。
3. `nested_child_path` 只表示已经进入 child 容器后的内部路径。
4. 前端切换 child、ref 或 nested child 时，应重新请求预览，并重置与上一层选择不兼容的参数。

### 3. 存储流与原始下载

```http
GET /storage-stream?locator={resource_locator}&storage_ref={storage_ref}
GET /downloads/file?locator={resource_locator}
```

`storage-stream` 永远只读取一个存储叶子内容，支持 HTTP Range，主要服务 PDF、图片、视频、音频等在线预览。`locator` 必须携带 `item_id`；Manager 按 ID 回查 Meta 并确认 `storage_ref` 确实属于该 DataItem，不能退回只依赖 `engine_id + storage_ref` 的无主身份路径。

`downloads/file` 表示下载一个存储型 item 逻辑对象，由后端基于 ResourceLocator 和 DownloadPlan 自动选择单文件流或 multi refs zip 打包。前端不得根据 `format`、`preview_material`、`frontend_renderer` 或 `content.metadata.refs` 自行拼接下载。

### 4. 资源动作能力

Manager 面向用户提供四个数据进出动作：

| 动作 | 适用对象 | 用户含义 | Transfer 参与 |
|---|---|---|---|
| `upload` | 存储型 engine 的 node | 把本地文件上传到 bucket / prefix / directory。 | 不参与 |
| `download` | 存储型 engine 的 item | 把已有文件 / 对象原样下载到本地，multi refs 可由后端打包。 | 不参与 |
| `import` | 数据库 engine 的 node | 把本地 table 型文件导入为数据库表。 | Manager 创建并触发 Transfer `sync` |
| `export` | 数据库 engine 的 item | 把数据库表导出为本地文件。 | Manager 创建并触发 Transfer `sync` |

资源树当前选中的 node 或 item 不支持某个动作时，前端不得显示对应按钮。前端不应按 engine type、item type、format 或 data type 自行散落判断，而应调用 Manager 的资源动作能力 API：

```http
GET /resource-actions?locator={resource_locator}
```

`resource-actions` 只回答当前资源可显示哪些 Manager 用户动作，以及对应格式、限制和不支持原因；它不负责执行业务动作，不创建 Transfer 任务，不触发 Meta scan，也不保存资源树事实。

动作矩阵：

| 当前资源 | 显示动作 | 不显示动作 |
|---|---|---|
| MinIO bucket / prefix node、NFS directory node | `upload` | `download` / `import` / `export` |
| MinIO / NFS file item、multi refs item | `download` | `upload` / `import` / `export` |
| PostgreSQL schema node、MySQL/Doris/ClickHouse database node | `import` | `upload` / `download` / `export` |
| 数据库 table item | `export` | `upload` / `download` / `import` |

当前不支持数据库 table item 的当前页预览下载，不支持 database / schema node 级下载，也不支持 bucket / prefix / directory node 级导出。

## 四、后端实现路线

### 1. ExplorerService

ExplorerService 是 Manager 数据探查页的轻量业务服务，负责：

1. 调用 System 获取当前租户可访问引擎。
2. 过滤出可用于 Manager 数据探查的存储引擎。

ExplorerService 不再构造资源树节点，不触发资源树刷新，不直接实现具体格式预览逻辑。资源树事实统一由 Meta resource-tree API 提供。

### 2. PreviewResolver

PreviewResolver 是预览编排层，负责：

1. 解析 ResourceLocator。
2. 根据 locator 查回 System engine 和 Meta node / item。
3. 组装 PreviewResolverRequest，包括分页、容器选择、Graph sample filter、Meta attributes、item fingerprint、scanned depth 等上下文。
4. 将请求转换为 PreviewProvider 所需的 PreviewRequest。
5. 通过 PreviewRegistry 选择 provider 并执行预览。
6. 组装 PreviewResult。

PreviewResolver 必须保证预览来源可追溯到 locator 和 Meta facts；不得为了兼容旧调用重新接受 `schema/table` 作为公共入口。

### 3. PreviewRegistry 与 PreviewProvider

PreviewRegistry 维护已注册的 PreviewProvider。Provider 应按能力处理明确的预览模式：

| 模式 | 典型来源 | 说明 |
| --- | --- | --- |
| `node` | catalog node、目录、bucket、prefix | 返回节点概览或容器索引。 |
| `table` | 数据库表、文件表、图样本表格化概览 | 返回 rows / columns 等表格材料。 |
| `object` | 文件、对象、multi item、容器 child | 返回对象预览材料或不支持状态。 |

Provider 只生成 Manager 预览材料，不反向定义平台 data type / format。新增 provider 时，应同时补充语义矩阵测试，确认 `content.kind`、`preview_material`、`frontend_renderer` 一致。 已扫描容器的父项预览，无论来自文件系统还是对象存储，都先通过同一容器索引构建函数消费 `type_info.container`，返回 `content.kind=container`、`preview_material=container` 和容器渲染器，索引放在既有 `json` 字段；不按扩展名另建选择逻辑，也不为已存在的图层索引重新读取源字节或枚举存储目录。选择 child 后仍沿既有容器子项／scope table 路线读取实际内容，父项的源存储引用和原文件下载事实保持完整。

### CSV／TSV 稀疏索引的源版本校验

单文件 CSV／TSV 的已扫描稀疏索引绑定 `access_index.table.source` 中的 `size_bytes`，以及引擎实际提供的 `etag`、`last_modified_at`；至少有一种版本事实，不能仅凭大小相同判定可复用。Meta 深度扫描和已知项刷新在解析前后读取同一精确资源的 Engine Catalog facts，只把一致源版本绑定到本次新建索引，并更新实际大小和修改时间；basic 扫描不能将新版本事实绑定到旧索引。

Manager 在使用这类已扫描索引前、分页内容读取后分别复核源事实。源版本改变、绑定缺失／不完整或索引格式不匹配时，丢弃本次结果，返回 HTTP 409、`error_code=preview_source_refresh_required` 和国际化刷新提示；不发布旧字段、旧总数或部分行，不改为顺序读取，不自动扫描或重建。读取源事实失败返回 HTTP 503、`error_code=preview_source_unavailable`。用户通过既有 item 深度刷新重建后才能继续预览。没有稀疏索引的 UTF-16／GBK 等输入继续使用原有逻辑行读取，不由本次规则声明其并发一致性。

校验只证明两次观察到的引擎大小、ETag／修改时间一致，不提供不可变读快照，也不能发现存储端刻意保留全部这些事实的原位改写。既有轨迹范围读取的快照边界保持不变。共享源事实比较由 `datatype.AccessIndex` 实现，Meta 负责绑定、Manager 负责消费；页面沿现有持久失败状态展示中英文刷新提示，改选成功的数据项后清除，不新增自动重试。验证使用 Common、Meta、Manager Go 标准门禁、`make test-meta-postgres` 的源版本刷新／失败保留回归、`make test-manager-frontend` 的失败状态页面与构建及 Manager Swagger 检查，已有自动发现和 Meta PostgreSQL CI 覆盖新增测试，不增加权限、任务、服务或 CI 工作流。

## 五、前端实现路线

前端 DataExplorer 以 Pinia store 维护资源树和预览状态：

1. `engines`：当前可访问引擎列表。
2. `engineTrees`：按 engine id 缓存资源树。
3. `selectedLocator`：当前选中资源 locator。
4. `expandedLocators`：已展开节点集合。
5. `selectedChildName` / `selectedRefPath` / `selectedNestedChildPath`：容器和 multi item 当前选择。
6. `previewData` / `activeChildPreviewData`：当前预览结果。
7. `pagination`：预览分页状态。精确总数与未知总数逐页读取遵循[数据预览语义协议](数据预览语义协议.md#表格预览分页)，共享分页组件不得使用估算行数推算末页。

资源树的选中状态与展开状态独立：收起选中资源的祖先后，右侧详情和选中 locator 可以保留，但加载其他引擎、增量回读和恢复高亮不得重新展开已收起的分支。收起只清除对应节点及其子树的展开记录，不影响同名前缀的兄弟节点。共享 `ResourceTree` 按当前展开集合同步所有已挂载节点，不能依赖 Element Plus 恢复选中项时隐式展开祖先；显式 locator 定位仍由 ancestors 流程提供展开路径。

首次进入时引擎根节点保持收起；加载中的未挂载子树也允许再次点击箭头收起。临时根 locator 替换为 Meta 正式 locator 时，只迁移仍有效的展开意图，不能重新展开已收起的根。异步选中遵循最后一次用户选择，较早的引擎加载完成后不得覆盖后来的选中项。顶部刷新只重读引擎目录及连通状态，保留已加载子树、展开记录和当前选择，不预取未打开的引擎；资源事实刷新继续使用 node / item 行内动作。

同一节点的普通子资源读取合并在途请求，缓存命中也必须恢复当前树中的子资源。强制回读使用新的一轮请求，旧轮次的迟到响应不得覆盖新轮次的树和缓存。

资源树搜索、URL 定位和搜索结果定位都必须隔离旧请求：关键词、引擎范围或当前选择改变后，迟到结果不得混入新查询、重新选择旧资源或显示旧操作错误。共享资源选择器在懒加载失败时保留目录可重试状态，不把失败解释为成功空目录；加载期间的收起意图在返回子资源后继续有效。

资源树搜索失败必须在结果区持续显示明确的错误状态，直到改换关键词、清空搜索或成功重试；不能在短暂提示消失后把失败显示为“未找到匹配资源”。

预览请求失败必须保留当前请求的错误状态，持续展示到重新请求或切换资源，不能在短暂消息消失后显示为“暂无可预览数据”。403 表示当前读取请求被拒绝，提示核对功能权限和数据授权，不仅凭状态码断定缺少某一条 Grant；网络失败及 502／503／504 单独展示暂时不可用，其余失败展示预览失败。成功空结果不属于错误。迟到的旧请求不得覆盖当前资源的结果或错误状态；容器 child 预览遵守同一规则。

前端发起预览时必须传 locator。普通预览组件按 `frontend_renderer -> preview_material -> content.kind` 选择 renderer；不得直接用 `format` 选择组件。

DOC、DOCX、RTF、WPS 必须统一使用 `frontend_renderer=office`。Manager 后端只提供源文件 URL 或受限的 raw binary 兜底；前端按需加载统一 Office renderer，不得保留各格式平行预览组件，也不得在后端生成图片作为这四种格式的默认预览路线。

资源树定位流程：

1. 从数据检索结果、向量化结果、任务详情、快显或跨页面跳转中拿到 locator。
2. 调用 `GET /api/v1/meta/resource-tree/{engine_id}/ancestors?locator=...`。
3. 按 `ancestors[].locator` 逐级合并到当前资源树状态。
4. 保留已加载 sibling children，不因为定位链覆盖已有子节点。
5. 展开祖先节点，并把 current node key 设置为目标 locator。

定位时必须按需读取已展开容器（包括 catalog root）的直接子资源。浅层树和 ancestors 只提供路径事实，不代表 sibling item 已完整加载；不得因此把根下只有目标 item 的树标为完整。

前端不得为了定位深层资源自行拆分 `/`、`.`、bucket、schema 或 table，也不得绕过 ancestors API 递归查找尚未加载的树节点。

### 数据探查 URL 状态

数据探查页的公开 URL 必须能够恢复当前资源和当前 item 视图：

```text
/manager/data-explorer?locator={ResourceLocator}&tab={preview|profile|attributes|lineage}
```

约束：

1. `locator` 是当前 engine、node 或 item 的唯一资源身份；不得并行保存 `engine_id/schema/table` 路由参数。
2. `tab` 只表达 item 右侧面板视图，固定为 `preview`、`profile`、`attributes`、`lineage`；默认 `preview` 应从 URL 省略。目标 item 不支持请求的视图时，前端回到 `preview` 并规范化 URL。
3. 用户在资源树中选择资源或切换 item 视图时，应替换当前历史项，避免高频浏览填满浏览器历史；进入瓦片缓存、物化视图等独立页面时，应新增历史项，使浏览器后退能够恢复原 `locator + tab`。
4. 资源树展开状态、滚动位置、分隔栏宽度、分页、加载状态和弹窗状态不进入 URL。资源树展开状态必须由 locator ancestors 恢复。
5. Console iframe 模式下，Console 外层 URL 是公开路由事实源；Manager 通过共享 Console navigation bridge 同步路由，不得维护与地址栏分叉的第二套历史。相同 Manager 页面只更新 query 时不得重载 iframe。
6. Manager 独立运行时复用相同的模块内 query 契约，不依赖 Console 才能定位资源或恢复视图。
7. URL 只能携带资源身份和可恢复视图状态，不得携带 Access Token、资源访问票据、引擎凭据或连接信息。
8. 其他模块进入数据探查时必须使用 `common-frontend` 的 `buildManagerDataExplorerRoute(locator)` 与 `openConsoleRoute()`；不得复制公开路径字符串或为跳转请求 Meta 补齐资源身份。

数据项定位先建立 Meta 资源上下文。只有当前视图为 `preview` 时才请求 `/manager/preview`；直接打开血缘或属性页不隐式读取样本，切换到预览或由浏览器历史恢复预览时执行正式数据授权检查。

## 六、设备静态轨迹预览

设备轨迹仍由 CSV、records JSON 或 Point FeatureCollection GeoJSON 承载，不新增 data type、format、持久任务或派生产物。Manager 对已扫描、可正常表格预览的单文件 item 提供静态轨迹入口；普通 JSON 文档、容器 child、数据库和既有 LineString 不进入点记录连线主线。

用户显式选择设备字段、时间字段，以及两列 X/Y 坐标或一个 GeoJSON Point 几何字段。已知源 CRS 复用现有前端 CRS registry；缺少 CRS 时须显式声明 EPSG:4326 或 EPSG:3857，不根据字段名或数值范围猜测。用户声明只用于本次展示，不写入 Meta。时间格式显式选择带时区 ISO 8601（最多毫秒）、Unix 秒或 Unix 毫秒；无时区文本不使用浏览器本地时区解释。Unix 秒的小数以十进制拆分为毫秒，避免浮点乘法误拒合法时间；非零子毫秒精度明确拒绝，不静默舍入。

通过唯一 `/preview` 接口，以当前 locator、page=1、page_size=2000 重新获取完整有界结果，继续执行现有源读取授权和字段保护。不拼接浏览器已缓存分页，不新增自由查询参数、下载权限或解析原始文件的旁路。只有返回第一页、行数不超过 2000、has_more=false 且精确 total（如有）与实际行数相等时允许连线；未知 total 依赖既有多读一条的 has_more。响应不是表格、缺少完整性事实或超限均明确失败，不把样本称为完整轨迹。

完整结果只读取保护后仍可见的列。设备 ID 限定为非空字符串或安全整数，保留原类型和源值，不猜测或归一化标识。所有记录的设备 ID、时间、二维有限坐标均须有效，任一记录失败则不绘制部分路线；同一设备同一时刻不同坐标明确拒绝，相同时间及坐标的重复记录允许保留。按设备分组后按时间升序连线，原输入不变；只有一个位置的设备仍显示为点，不跨设备连接，不推断缺测点、速度、停留或时间间隔断点。GeoJSON 首期仅接受 Point，既有 LineString 继续由普通空间预览显示，不推断每个顶点的时刻。

字段映射、读取结果和图形仅保留在当前预览会话；关闭或切换资源即清除并取消在途请求，旧请求不得覆盖新资源。每次重新打开都重新走受控预览。公共组件统一维护配置、校验、分组排序与绘图，Manager 只适配 locator、授权后的表格响应和 API 错误；地图复用 MapContainer，无新增 renderer；默认无底图，可选择既有地图 profile，GCJ-02 底图保留业务浏览提示，不回写源坐标。

初始化时先结束当前读取，再填入已识别的源 CRS，最后校验完整性。配置变化须同步取消在途请求并清除旧路线／错误；自动填入默认坐标系不得在后续批处理时清掉本次完整性错误。不完整文件仍保留字段与范围配置入口，必须在所选范围完整读取后才能绘图；关闭并重开仍重新验证。

### 设备与时间范围读取

现有 `GET /preview` 增加单个 `trajectory_selection` JSON query，固定字段为 `device_field`、`time_field`、`time_encoding`、`devices`、`start`、`end`；不得出现未知／重复字段、null 或重复 query。`devices` 为 1–100 个非空字符串或安全整数，保留类型，字段名最多 256 字节、字符串设备标识最多 256 字节、整个选择最多 8192 字节；相同类型和值不得重复。设备字段若为 bigint，沿用 HTTP 预览的精确文本契约，选择文本标识；范围筛选与响应序列化复用同一转换，不经浮点取整。`start/end` 为带时区且最多毫秒的 ISO 8601，采用左闭右开 `[start,end)`，开始必须早于结束。源时间编码仍显式使用 iso/unix_s/unix_ms。选择只能用于 Meta 已扫描的单文件 CSV、records JSON、Point GeoJSON 表格，且 page=1、page_size=2000，不与容器、ref、嵌套 child、图或键值选择组合；不是通用查询语言。

JSON 数组和 GeoJSON FeatureCollection 必须闭合并只有一个根文档，缺少结尾或根后额外内容不得报告正常结束；JSON Lines 继续使用逐对象读取规则。该结束条件由 Common JSON 记录迭代器统一维护，Manager 不增加另一解析器。

Manager 复用 Common 格式 TableReader 单次打开流并逐批读取，不拼接分页、不将整文件下载至浏览器。默认扫描预算固定为 32 MiB 原始输入、250000 行和 15 秒；这些是本版服务端边界，客户端不可调大。只读到共享读取器的完整结束且输入未超过预算时才发布匹配结果，响应 total 为范围内精确条数、has_more=false，并返回 `trajectory_scope={selection,complete:true,scanned_rows}`。匹配超过 2000 点、扫描超预算、源解析错误或取消，均不发布任何部分轨迹；缩小时间／设备范围只能减少匹配点数，不保证减少普通文件扫描量，文件超预算需拆分或导入可查询引擎。设备时间索引与原生读取快照能力不在本版范围内，不承诺并发写文件的一致快照。

设备与时间字段限定 Meta 中的顶层字段（Path 为空或单段同名，不接受嵌套／别名），且本次主体的有效保护决策允许读取原值；复用 Common 的 QueryOutputDerivedFields 判断，不在 Manager 重写保护算法。每批读取前后及最终响应继续校验保护有效性，不能在遮盖／抑制字段原值上筛选后泄露匹配数量。其余返回字段仍由既有响应边界执行保护，既有源读取授权、Tenant 与在途生命周期保持唯一入口。配置只用于本次预览，不持久化、不新增权限、任务或产物。前端必须核对服务器回显的选择和 complete；请求被旧服务忽略或普通分页响应不能当作所选范围完整。

输入／目标错误返回 400 `trajectory_selection_invalid`；范围超限、扫描超预算及源数据无效分别返回 422 `trajectory_point_limit_exceeded`、`trajectory_scan_budget_exceeded`、`trajectory_source_invalid`；字段保护继续使用现有 403 `security_protection_required`。

共享组件与 Manager 的验证职责见[验证命令](#九验证命令)；Hosted 固定断言见[Manager 场景规范](../../docs/spec/testing/scenarios/Manager与空间成果.md#设备静态轨迹范围读取)，本地样例与历史 T4 的证据及适用边界见[验收证据索引](../../docs/spec/testing/验收证据索引.md#manager-静态轨迹历史证据)。

## 七、与其他 Manager 能力的关系

### 1. 与快显

普通空间预览返回源坐标下的小样本 geometry，并通过 CRS 字段告诉前端是否可直接渲染。普通预览不做后端 CRS transform，不返回双 geometry 字段，不隐式创建 3857 物化视图或瓦片缓存。

空间数据需要地图式连续浏览时，走 Quick View capability、动态 MVT 或瓦片缓存体系。

快显、瓦片缓存、矢量物化视图等创建页的路由入口也应只以 locator 作为资源身份。`schema/table/source_engine_id` 可以继续作为空间渲染、建表和任务执行配置字段，但必须由 locator capability 解析或任务记录反填，不能作为创建入口锁定来源的并行定位路线。

### 2. 与向量化

预览可以展示向量化入口和状态，但向量化任务定义、execution 和结果状态归向量化能力管理。预览不得把 embedding 结果写入自身响应事实源。

### 3. 与数据剖析

数据剖析是 Manager 数据探查中与预览、属性并列的独立视图，只对 `data_type=table` 的 data item 或当前表格型容器 child 开放。预览响应可以提供 data item 和当前 child 上下文，但不得用当前分页记录计算剖析指标，也不得把剖析结果塞入 `/preview` 响应。

用户首次打开“剖析”标签且没有有效结果时，由独立剖析入口创建 `task_type=data_profiling` 的 ad-hoc execution。剖析结果和生命周期归 Manager，Meta attributes 只提供身份、结构、源版本和扫描事实。完整规则见 [数据剖析规范](数据剖析规范.md)。

### 4. 与导入和导出

资源树数据库 node 可以提供“导入”入口；数据库 table item 可以提供“导出”入口。完整数据库表导出、跨格式转换和批量数据产出进入 Manager export，内部调用 Transfer sync。文件/对象原始下载走 `downloads/file`。

当前 Shapefile 导入由 Manager 接收 ZIP 或同 basename 的相关文件，校验必需 refs 后写入本模块私有 Infra MinIO；格式解析和空间字段转换继续由 Common Format Provider 执行，不恢复 `s3_shapefile`、`postgres_copy` 或内联凭据配置。Manager 保存私有 `import_sources` 来源事实，绑定 Tenant、上传者、精确 source locator 与一个 Transfer task；它不是可编辑的 import session 或另一份执行记录。

Manager 转发当前已验证的 User Bearer，通过 Transfer 正式 Client 创建并启动 `task_type=sync`，配置为 bounded/snapshot、encoded Shapefile source 与 native table target，目标使用 `parent_locator + name`，当前导入写入策略为 replace，并设置写后 Meta 扫描。响应中的 task ID 与 execution ID 分别表达定义和本次执行；提交成功或 pending 不等于数据及元数据已就绪。Transfer 是实际传输执行和派生血缘的唯一 owner。

导入源核验由 `POST /api/v1/manager/runtime/import-sources/verify` 提供，仅允许固定 Transfer Tenant Service 及 `manager.import_provenance.read`，按上传者、绑定任务和精确 locator 核对本次来源，不返回文件或凭据。不能仅凭一个 `addp-infra://` 地址授予任意平台文件读取权。精确接口以当前 Swagger 为准。

导入弹窗按 Transfer／Meta 的公开执行响应展示进度：终态 `failed`、`timeout`、`cancelled` 均结束轮询并复用共享 `ExecutionFailure`，只消费 `error_details` 与实际执行 UUID，不读取原始运行错误或已删除的 `error_msg`。Transfer 成功后等待其准确的 Meta 子执行，元数据同步失败不能显示整个导入成功；关闭、重试和卸载必须隔离旧请求。数据保护拒绝的共享提示使用适用于数据读取与结果保护的中性文案，不将导入失败解释为 SQL 拼接错误。

Console 导入完成后由 NodePanel 先等待原 schema 的祖先事实与直接子资源刷新完成，再按既有桥接导航进入同一执行 UUID 的 Monitor；ImportDialog 只提交准确的完成执行与目标 locator，不能并行发起会卸载 iframe 的导航。

导出发起用户来源核验复用 `common/exportartifact`：派发前持久化 Transfer UUID 与完整请求摘要，`POST /runtime/export-sessions/{id}/execution-source` 仅允许 `addp-transfer` 持有 `manager.export_provenance.read` 核验有效待执行会话。只返回发起用户事实，不开放文件下载或数据权限。

当前导入、导出、上传、下载的支持边界如下；增强事项见[数据导入后续事项](../../docs/plan/数据导入流程设计.md)：

1. 上传 zip 默认按单个原始对象写入存储型 engine；“解压后上传”需要先补用户交互和 Meta scan 边界设计。
2. 当前下载不引入 download session；如后续需要下载审计、大文件准备、一次性 token 或断点续取，再设计独立 session。
3. 当前导入不引入 import session；如后续需要导入历史、失败重试、上传包保留或可追溯审计，再设计独立 session。
4. 多 item 批量 download / export、外部 URL import 等能力需先确认用户场景和 Transfer 支持边界，再进入实现。
5. export 创建请求应进入审计；导出文件下载是否单独审计，后续按统一审计规范确认，不在当前 Manager resource-actions 中隐式扩展。

## 八、禁止事项

1. 不得恢复旧的 `engine_id/schema/table` 公共预览入口。
2. 不得让 Handler 按单一数据源写特殊预览分支；格式和数据源差异应进入 PreviewProvider。
3. 不得把 `preview_material` 当成 `common/format` reader capability。
4. 不得把 unsupported 预览伪装成 text 或 empty table。
5. 不得在前端解析 multi refs 或拼接 zip 下载。
6. 不得在普通预览链路隐式创建矢量物化视图目标、瓦片缓存、embedding 或其他派生产物。
7. 不得从 `/preview` 当前分页或前端本地记录计算并持久化数据剖析结果。
8. 不得在 `/preview` 用户请求期间同步调用 Security、Catalog 或重新查询 Meta；保护执行只读取 Manager 本地投影和本次 Resolver 已持有的 Meta 快照。
9. 不得把 Locator 型预览开放为用户自由查询。数据库分页预览允许由 Provider 提供不可变 PreparedQuery；普通 View 也可能读取多个底层对象，必须使用该计划证明完整 ReadSet，再核验全部源 Grant/Deny 与本地 Security，并执行同一一次性计划。不能只检查所选叶子后另走未核验的批量读取路径，也不能在 Manager 猜测查询依赖。普通 User 和 Agent `data.preview` 委托预览共用该受控读取链路，分别核验真实凭据；不以 Service 身份替换用户，不把 Tool 凭据降格为普通 User。
10. 不得在前端、MongoDB 专用 PreviewProvider 或通用原始 PreviewResolver 内实现手机号等私有遮盖规则。

PostgreSQL item 表／视图预览使用同一受控读取链路：System 源检查接收当前请求真实 Bearer，完整读取集合只能来自本次 Provider PreparedQuery；源检查失败、依赖不完整或本地保护无法编译均不得执行内容查询。Response 边界消费该计划对应的保护闭包，不重复按所选叶子单独遮盖，不接受新的自由查询参数。后台剖析沿[数据剖析规范的当前授权边界](数据剖析规范.md#当前授权切换边界)执行：首版只开放已扫描 PostgreSQL 单表的有界采样，使用独立 execution 源授权；视图、物化视图和多来源计划不支持，旧 Preview／ReadBatch 路径不恢复，不借 Service 或预览凭据读取。源端并发 DDL 的未覆盖边界以该规范为准。

Tenant HTTP 请求必须在保护规则读取前进入统一在途边界并刷新本地持久 cursor，直到响应序列化或流复制结束才释放。后台剖析及其他有界任务在统一 dispatcher 中执行同一生命周期边界，不把 HTTP 请求结束当作后台执行结束。Security 后置回执屏障等待在途工作和有效 lease 下的运行 execution；该屏障不核验 System 源授权，也不使尚未接入完整 ReadSet 的内容路径获得数据访问权。

## 九、验证命令

测试分层、环境边界和交付要求以[测试与验收总规范](../../docs/spec/addp测试与验收规范.md)为准；下列命令在仓库根目录执行。按变更范围选用标准入口，专项回归不代替完整模块门禁，T1/T3 不替代真实 T4。

```bash
# Manager owner 的 T0-T3 标准门禁
make test-module MODULE=manager

# 开发定位：后端 T1、前端确定性测试与构建
make test-manager-backend
make test-manager-frontend

# 共享轨迹/地图组件变更及 Hosted runner 确定性回归
make test-common-frontend
make test-manager-online-runner
```

共享组件的排序、时间/坐标校验、完整性与唯一所有权归 common-frontend；Manager 负责页面入口、字段映射、有界读取、配置回显、错误与资源切换。范围读取还须覆盖预算/点数超限、保护失效、文件增长、流中途失败/阻塞取消和不完整 JSON；回归场景及标准入口见[Owner 补充门禁](../../docs/spec/testing/Owner补充门禁.md#manager-预览浏览器门禁)。共享 Common 或共享前端变更按[CI 与交付规范](../../docs/spec/testing/CI与交付规范.md)扩散验证。
