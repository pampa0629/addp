# ADDP 数据安全与隐私保护后续事项

Security 的概念、控制面/数据面、显式纳管、检测评估、唯一保护编译器、投影和失效关闭规则已进入[概念体系](../concepts/addp数据安全与隐私保护体系图.md)与[实现规范](../spec/addp数据安全与隐私保护实现规范.md)。本文不再重复维护阶段 0–5 的方案及过程记录，当前能力以正式规范和各 Owner 执行器为准。

## 当前范围与验收边界

- Manager、Develop、Service、Transfer 的已支持动作共用 Security 投影与 Owner 本地执行主路；没有对应动作执行器的出口继续资源级拒绝，不因完成 acknowledgement 就宣称具备字段保护。
- 原专题最终记录包括 MySQL 四出口、PostgreSQL 空间表与 MongoDB Manager/Develop 的算法 Hosted 验收。`4196a84c4` 的 [Hosted T4 38127430328](https://github.com/pampa0629/addp/actions/runs/38127430328) 补齐 MongoDB 原始记录导出的三算法、Canonical Extended JSONL、独立预览策略隔离和退出清理；该结果只覆盖报告场景。
- Service 当前 SQL Runtime 支持不等于 MongoDB 查询服务已实现；复杂查询、联邦、瓦片、watermark、continuous/CDC 等以各 Owner 的正式允许矩阵为准，不能借用已实现保护执行器放开。
- 普通原值访问只在明确出口、主体和期限内申请，由另一人审批；保护例外不授予底层资源读取权。近期 Graph、Develop 等新增切片的实现与验收由实际 owner 另行记录，不以旧四 Owner 清单否定已确认的新规范。

## 剩余能力与准入

| 范围 | 继续推进条件 |
| --- | --- |
| 更多数据出口/引擎 | 同一 PreparedQuery 证明完整 ReadSet 与 OutputLineage，明确动作、读取/输出形态、持续执行屏障与对应真实验收 |
| AI 数据访问与输出 | 先确定 Agent/Copilot/Inference 的访问与输出契约；不预埋保护声明或重复执行上游已保护结果 |
| 文档、图片、人脸、车牌、地理位置与媒体 | 按数据类型分别确认受控样本、Finding、编译与 Owner 动作，不照搬结构化字段假设 |
| 水印、可逆令牌化、假名化、匿名化 | 明确产物、密钥/映射所有权、保护效果与重识别风险，先修订规范 |
| 隐私合规治理 | 同意、用途、保留期、删除/退出和主体权利各有权威事实，不从现有遮盖能力推断已具备 |
| 自动发现调度及 Catalog 摘要 | 有明确场景后先确认任务/调度 owner、事实白名单与同步成本 |
