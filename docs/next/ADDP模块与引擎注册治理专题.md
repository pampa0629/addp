# ADDP 模块与引擎注册治理专题

> 状态：阶段一盘点与 P0 收口完成（2026-08-23）

## 一、专题定位

本专题记录 System 对模块注册、引擎注册和运行状态治理的现状、差异与后续改进任务，不重新定义平台概念。稳定概念与接口边界以以下文档为准：

- [模块架构图](../concepts/addp模块架构图.md)
- [引擎体系图](../concepts/addp引擎体系图.md)
- [术语表](../concepts/addp术语表.md)
- [ADDP 开发原则](../spec/addp开发原则.md)
- [ADDP API 设计规范](../spec/addp-API设计规范.md)
- [统一测试与 Online 验收体系方案](ADDP统一测试与Online验收体系方案.md)

模块与引擎都由 System 管理稳定身份和运行事实，但二者不是同一个聚合，不合并数据模型或注册 API。

## 二、统一治理原则

| 维度 | 模块 | 引擎 |
| --- | --- | --- |
| 稳定身份 | `module_name` 与模块定义 ID | `engine_id` 与租户作用域内的永久身份键 |
| 运行身份 | `module_name + instance_id` | 稳定引擎记录对应的当前连接状态 |
| 管理意图 | 模块定义的 `enabled` | `active / disabled / deleting / deleted` 生命周期 |
| 运行事实 | 实例 `role / status / heartbeat / lease` | `online / offline / unknown / checking` |
| 注册主体 | 模块自身进程 | 用户、管理员或受控的 Runtime Engine 进程 |
| 可用条件 | 已启用且存在租约有效的在线 `backend` 实例 | 生命周期允许且当前在线，并满足消费方要求的能力 |
| 删除语义 | 保留稳定模块定义，实例按租约和注销退出 | 软删除；ID 永不回收，重复注册恢复原记录 |

共同约束：

1. 稳定 ID 一旦分配不得复用或重排。
2. “是否允许使用”和“当前是否在线”必须分离，不能用一个布尔字段表达。
3. 注册必须幂等；重复注册更新同一稳定对象或同一进程实例，不创建幽灵记录。
4. 消费模块必须在实际使用时读取当前状态；引擎或模块恢复后无需重启消费方。
5. 前端可展示离线对象，但新操作不得选择离线对象；后端执行入口必须再次校验。
6. System、Gateway 和各模块只能保留一条注册与发现主路径。

## 三、现状矩阵

| 能力 | 当前状态 | 事实与结论 |
| --- | --- | --- |
| 模块定义与运行实例分离 | 已完成 | `module_definitions` 保存稳定定义，`module_runtime_instances` 保存带租约的进程实例。 |
| 多角色实例 | 已完成 | 支持 `backend / worker / scheduler`；只有在线且租约有效的 `backend` 可进入 Gateway 路由。 |
| Gateway 动态发现 | 已完成 | Gateway 通过路由快照 revision 长轮询更新，不要求模块固定启动顺序。 |
| Go 公共注册客户端 | 基本完成 | 进程级 `instance_id`、角色、心跳、重新注册和注销均已具备；部分调用方仍未把服务生命周期上下文贯穿到客户端。 |
| Python 公共注册客户端 | 已完成 | 进程级 `instance_id`、角色、心跳、按实例注销和 4xx 响应正文日志已纳入契约测试。 |
| 引擎永久身份与软删除 | 已完成 | 引擎 ID 单调增长且不复用；重复注册恢复原记录并沿用 ID。 |
| 引擎生命周期与连接状态分离 | 已完成 | 生命周期表达管理意图，连接状态表达运行事实。 |
| Develop / Manager / Service 动态消费 | 已完成主路径 | 列表保留离线引擎并禁用选择，执行入口动态复核；引擎恢复后可直接使用。 |
| System 管理界面 | 已完成主路径 | 可查看模块定义、实例、角色、状态、心跳和租约，并管理启用状态。 |
| 旧 Runtime Engine 注册服务 | 已删除 | 无生产调用方的 `RegistryService` 与孤立测试已删除，Runtime Engine 统一走 `EngineHandler → EngineService`。 |

## 四、阶段任务

### P0：消除双轨与契约缺口

- [x] Python 客户端生成并贯穿同一进程级 `instance_id`，声明 `role`，心跳和注销携带实例身份。
- [x] Python 客户端 4xx 日志包含响应正文，并补公共契约测试。
- [x] 删除无生产调用方的旧 `RegistryService` 及其孤立测试。
- [x] Runtime Engine 注册只保留 `POST /api/v1/system/runtime/engines` 主路径，由 `EngineService` 承担永久身份、幂等和生命周期规则。

### P1：统一进程生命周期

- [ ] 审计所有 Go 模块与附属 Worker 的注册调用，禁止用不可取消的 `context.Background()` 承载整个注册生命周期。
- [ ] 由进程入口创建信号上下文，并把同一上下文传给 HTTP 服务、注册心跳和关闭流程。
- [ ] 正常关闭时先按 `module_name + instance_id` 注销；异常退出由租约到期兜底。
- [ ] 统一 Go 与 Python 客户端的注册失败诊断字段和日志语义。

### P2：把冷启动与恢复纳入 Online 验收

- [ ] 全量服务重启后，验证模块注册、System 可见、Gateway 可路由之间不再出现需要人工刷新的窗口。
- [ ] 验证模块先启动、System 后启动以及 Gateway 后启动时均能自动恢复。
- [ ] 验证引擎离线时展示但不可选，恢复在线后无需刷新整页即可使用。
- [ ] 验证租约过期、实例重启、同模块多实例和版本切换的路由收敛。

## 五、测试与 CI 门禁

| 层级 | 最小门禁 | 覆盖内容 |
| --- | --- | --- |
| T1 | `make test-common-python` | Python 注册请求、心跳、注销、进程级实例身份和错误日志契约 |
| T1/T2 | `make test-module MODULE=system` | System 模块与引擎注册服务、Repository、Handler 和迁移规则 |
| 平台一致性 | `make test-platform` | 模块发现、共享代码边界和平台级静态一致性 |
| 改动收口 | `make test-changed` | 按工作区差异自动选择受影响门禁 |
| T4 | Online 验收方案中的注册与路由场景 | 冷启动、乱序启动、租约失效、恢复和页面动态可用性 |

新增注册字段、角色、模块、Worker、路由或客户端时，必须在同一次变更中同步公共客户端契约测试、System 测试、Gateway 路由验证和 CI 自动发现规则。

## 六、完成标准

本专题在以下条件全部满足后归档：

1. 所有模块和 Worker 都使用公共注册客户端及可取消的进程生命周期上下文。
2. System 内不存在第二套模块或 Runtime Engine 注册实现。
3. 模块和引擎恢复在线后，各消费模块无需重启或整页刷新即可恢复使用。
4. 冷启动、乱序启动、优雅关闭、异常退出和租约恢复均有自动化 Online 证据。
5. 文档、Swagger、公共客户端、测试入口和 CI 门禁保持同步。
