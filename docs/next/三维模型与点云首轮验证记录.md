# 三维模型与点云阶段记录

## 范围

本记录用于沉淀 `model_3d` / `point_cloud` 阶段性验证结果，并作为三维模型、倾斜摄影和点云格式扩展的入口索引。长期方案不在本文展开：

- OSGB、OSGB Scene、GLB artifact、3D Tiles 和 `model3d_workflow` 主链路见 `docs/next/OSGB倾斜摄影与3DTiles方案.md`。
- OBJ / STL / FBX 已落地能力和 IFC / 3MX / SLPK / LAZ / COPC / E57 等后续格式路线见 `docs/next/三维模型格式扩展路线.md`。
- 已沉淀为稳定规范的概念以 `docs/concepts/` 和 `docs/spec/` 为准。

## 已验证样例

| 样例 | 期望语义 | 验证结果 |
|---|---|---|
| `addp/3d/ABeautifulGame.glb` | `data_type=model_3d`、`layout=single`、`format=glb` | Manager 三维预览可渲染；属性页显示 `type_info.model_3d`、`format_info.glb` |

| `3d/白塔3dtiles/baita` | `data_type=model_3d`、`layout=whole`、`format=3dtiles` | 通过 3D Tiles preview 渲染，源 OSGB Scene 转换结果作为业务 item 管理 |

## 当前基线

- 3D Tiles 应按 `data_type=model_3d`、`layout=whole`、`format=3dtiles` 接入，`tileset.json` 只作为 manifest ref，不作为普通 JSON data item。
- OSGB 倾斜摄影仍归入 `model_3d`；单个 `.osgb` 文件使用 `format=osgb`，一套倾斜摄影场景使用 `format=osgb_scene`，可通过 `model_kind=photogrammetry_scene` 辅助表达子形态，不新增平行 data type。
- glTF、OBJ、STL、FBX 均归入 `model_3d`；glTF 使用 `layout=multi` manifest 规则，OBJ / STL / FBX 使用 `layout=single`。当前 glTF / FBX / OBJ 开放 GLB 快显任务入口，STL 只做 scan 和 attributes 摘要。
- LAZ / COPC、EPT / Potree 等点云格式仍归入 `point_cloud`，通过 format、layout、point_cloud_kind 和 capabilities 区分。

## 后续推进顺序

1. 先补 `gltf` multi 规则，和已落地的 `glb` 对齐。
2. 再补 `obj` / `stl` 到 GLB 快显，验证通用单体模型快显任务。
3. 再调研 `ifc`，作为 BIM 专题。
4. 点云大数据量预览另走 `laz` / `copc` / `e57` 路线，不混入 `model_3d`。
