## 二、已完成范围

| 能力 | 完成内容 |
| --- | --- |
| 实例日志 | Backend / Worker / Scheduler / Gateway 的共享身份与受控输出，登记前输出、保留期内旧实例和 DOWN 实例读取 |
| 正文阅读 | 字面量筛选、未知级别、固定窗口/游标、刷新与跟随、堆栈/复制、失败及迟到响应处理 |
| 未登记来源 | 可信目录、保留及过期、v2 扫描诊断、来源发现不完整提示、复用唯一正文入口 |
| 观测与告警 | 常驻探针、计数基线、新鲜期、未知状态、独立固定级别信号、去重/恢复、确认/抑制 |
| 通知 | Webhook / 企业微信 / 邮件目标、事务 outbox、有界重试、安全诊断、单条 dead 重投 |
| 生命周期 | 私有源目录/接收器所有权、Hosted 仓库外临时凭据、证据归档与退出清理 |

已实现不代表所有生产条件均已认证。日志故障不影响业务 Ready，近期健康也不证明历史完整。

## 四、剩余验收与范围准入

| 优先项 | 尚缺证据 / 条件 |
| --- | --- |
| 真实模块异常退出完整链路 | 专用隔离部署中验证 System 登记、租约到期、DOWN 页面、旧实例正文、新实例隔离与关联通知；已有 SIGKILL T2 不能代替 |
| 自然保留周期 | 观察默认 168 小时与生产删除延迟的完整 Compactor 自然周期；不能复用旧时间戳短调度结果代替 |
| 多节点与恢复 | 各节点认证、可信来源绑定、集中读取及故障恢复；本机/Docker 单节点证据不扩展为多节点通过 |
| 生产容量与背压 | 在明确日志增量、并发、磁盘预算和丢弃口径后验证持续吞吐/容量；夹具用时和丢弃数量不是生产目标 |
| 专项观测与页面 | 节点时钟偏差、迟到拒收分类；Python 新结构化启动消息的实际页面及 INFO 筛选确认 |

零丢失归档、长断连完整重放、存储高可用及 Monitor 整体不可用时的外部自监控属于新的可靠性要求；有明确需求时先讨论设施与确认机制，不由现有 positions、源文件或近期健康推导这些保证。

业务启动结果裁决尚未纳入：需先定义启动超时、未登记退出、正常退出与存活事实；未登记、EOF 或 error 不等于启动失败，不为取得退出码改变既有 exec / PID 语义。引擎/Infra/浏览器日志及 Tenant 执行事件继续按各自 owner 推进。

## 五、维护与验证入口

代码与设施变更遵循[正式规范的分层门禁](../spec/addp模块服务运行日志规范.md#八验证与-ci-边界)，复用 `make test-module MODULE=system`、`make test-module MODULE=monitor`、`make test-system-runtime-log` 及相应共享依赖入口；新增 T4 场景先核对既有 Online 登记、身份和清理边界。不得对个人开发栈注入故障或因文档整理重跑无关 CI。

本专题后续只原位更新最终证据、未完成项和准入条件，不追加接力、重启、失败重试、SQL 取证、计数快照和逐轮 CI 流水。已稳定的约定直接修改概念/规范及对应模块说明，保证一个事实只有一个维护位置。
