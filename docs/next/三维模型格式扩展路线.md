## 一、核心原则

ADDP 的三维格式扩展不应让前端直接解析所有源格式，而应区分：

```text
源格式
  -> Meta scan 形成标准 data item
  -> Manager 判断快显能力
  -> model3d_workflow 或点云处理链路生成快显 / 派生产物
  -> 前端消费 GLB、3D Tiles、COPC / 点云瓦片等少数稳定目标格式
```

第一版稳定目标格式：

| 目标格式 | 用途 | ADDP 语义 |
| --- | --- | --- |
| GLB / glTF | 单体三维模型快显 | `data_type=model_3d`、`format=glb` 或 `format=gltf` |
| 3D Tiles | 大规模三维场景快显 | `data_type=model_3d`、`layout=whole`、`format=3dtiles` |
| COPC / 点云瓦片 | 点云快显和分块读取 | `data_type=point_cloud`，具体 format 后续单独定义 |

约束：

1. 不新增 `data_type=osgb`、`data_type=bim`、`data_type=tiles` 等平行类型。
2. 网格、倾斜摄影、BIM、分块场景统一归入 `model_3d`，通过 `format`、`layout`、`type_info.model_3d.model_kind` 和 `format_info.<format>` 区分。
3. LAS / LAZ / E57 / COPC / PLY 点云不归入 `model_3d`，应归入 `point_cloud`。
4. 快显转换产物不写入 Meta attributes；Manager artifact、业务存储 item 和 preview DTO 各自承担生命周期。
5. 新格式落地前必须先补 format descriptor、detector / claims 规则、attributes 字段归属和 Manager 预览路线。

## 二、格式分层

### 2.1 Web 原生与目标格式

| 格式 | 优先级 | 主路径 |
| --- | --- | --- |
| `glb` | 已落地 | 直接 Three.js / GLTFLoader 预览 |
| `gltf` | 第一批 | multi / related refs 识别，预览前可打包或直接按资源 URL 读取 |
| `3dtiles` | 已落地 | 3D Tiles renderer 预览，内部 b3dm / i3dm / pnts / glTF 不重复入库 |

`glb` 和 `3dtiles` 是 ADDP 三维快显的两个核心目标格式。后续扩展源格式时，应优先考虑能否稳定转换到二者。

### 2.2 单文件或小规模网格模型

| 格式 | 建议 data type | 建议 layout | 快显路线 | 备注 |
| --- | --- | --- | --- | --- |
| `obj` | `model_3d` | `single` | OBJ -> GLB | 使用 `assimp export`；Meta scan 以 `.obj` 为主 item，并将 `mtllib` 命中的 `.mtl` 及 MTL 中命中的本地贴图作为 refs / claims；转换器从源文件相对路径解析并嵌入 GLB |
| `stl` | `model_3d` | `single` | 先 scan，GLB 快显待新增转换器 | 常见于 3D 打印和工业模型，材质弱 |
| `fbx` | `model_3d` | `single` | FBX -> GLB | 使用 `assimp export`；`_3dtile -f fbx` 实测产出 3D Tiles，不作为 GLB 快显路线 |
| `dae` | `model_3d` | `single` 或 `multi` | DAE -> GLB | 老格式，低于 OBJ / STL / FBX |
| mesh 型 `ply` | `model_3d` | `single` | PLY mesh -> GLB | 必须和点云型 PLY 区分 |

第一批实际落地顺序需要服从当前转换器能力。`_3dtile` 保留给 OSGB 单文件快显和 OSGB Scene 到 3D Tiles；glTF / FBX / OBJ 这类 mesh 模型到 GLB 使用 Linux arm64 镜像内置的 `assimp export`，并必须嵌入纹理生成自包含 GLB。STL 第一轮只做格式识别和轻量摘要；GLB 快显入口先开放给 glTF、FBX 和 OBJ。

### 2.3 倾斜摄影与大场景

| 格式 | 建议 data type | 建议 layout | 快显路线 | 备注 |
| --- | --- | --- | --- | --- |
| `osgb` | `model_3d` | `single` | OSGB -> GLB artifact | 已落地 |
| `osgb_scene` | `model_3d` | `whole` | OSGB Scene -> 3D Tiles item | 已落地 |
| `3mx` | `model_3d` | `whole` | 3MX -> 3D Tiles | Bentley / ContextCapture 生态，需调研转换器 |
| `slpk` / I3S | `model_3d` | `single` 或 `whole` | I3S / SLPK -> 3D Tiles 或原生 I3S 预览 | ArcGIS 生态，建议独立专题 |

这类格式通常不适合作为前端直接解析对象，应优先走 `model3d_workflow` 生成 `3dtiles` 业务 item。

### 2.4 BIM / 建筑工程

| 格式 | 建议 data type | 建议 layout | 快显路线 | 备注 |
| --- | --- | --- | --- | --- |
| `ifc` | `model_3d` | `single` | IFC -> GLB，后续 IFC -> 3D Tiles | 第一优先级 BIM 开放格式 |
| `rvt` | `model_3d` | `single` | 暂缓 | Revit 专有格式，工具、授权和部署复杂 |
| `nwd` / `nwc` | `model_3d` | `single` | 暂缓 | Navisworks 生态，先不进入第一批 |

IFC 不能只当普通 mesh。第一阶段可以先生成 GLB 快显，但后续应保留 BIM 构件、楼层、属性集、分类和空间定位进入 `format_info.ifc` 或受控查询服务的空间。

### 2.5 点云

| 格式 | 建议 data type | 建议 layout | 快显路线 | 备注 |
| --- | --- | --- | --- | --- |
| `las` | `point_cloud` | `single` | 抽样点集预览 | 已有第一阶段 |
| `laz` | `point_cloud` | `single` | LAZ 解压 / COPC 派生 | 不借用 `format=las` |
| `copc` | `point_cloud` | `single` | COPC 分块读取 | 点云第一优先级增强 |
| `e57` | `point_cloud` | `single` | E57 -> COPC 或抽样 | 扫描仪点云常见 |
| 点云型 `ply` | `point_cloud` | `single` | 抽样 / COPC 派生 | 需和 mesh 型 PLY 区分 |
| `ept` / Potree | `point_cloud` | `whole` | 原生分块或转换 | whole-scope 点云数据集 |

点云格式不放入 `model3d_workflow` 主线强行处理。后续如果点云转换和瓦片生成复杂度上升，可以新增专门的点云 workflow runtime；第一版仍可在现有 Python 运行时中验证。

### 2.6 高斯泼溅

| 格式 | 建议 data type | 建议 layout | 快显路线 | 备注 |
| --- | --- | --- | --- | --- |
| 3DGS 型 `ply` | `gaussian_splat` | `single` | 前端高斯泼溅 renderer | 已完成 Meta 识别和 Manager 基础预览；支持传统 3DGS PLY 和 SuperSplat 压缩 PLY header 识别；SuperSplat 压缩 PLY 预览关闭渐进加载；不走 GLB 快显 |
| `splat` | `gaussian_splat` | `single` | 前端高斯泼溅 renderer | 已完成 Meta 识别和 Manager 基础预览；不走 GLB 快显 |
| `ksplat` | `gaussian_splat` | `single` | 前端高斯泼溅 renderer / KSplat 受管快显 | 已完成 Meta 识别、Manager 基础预览和 KSplat 受管快显；不走 GLB 快显 |
| `spz` | `gaussian_splat` | `single` | 专用高斯泼溅 renderer 或格式转换 | 当前前端依赖未声明稳定支持，后续单独接入 |

高斯泼溅和点云都可能由 vertex-like 记录承载，但消费语义不同。传统 3DGS PLY 的 vertex 表示带尺度、旋转、不透明度和视角相关颜色的高斯基元；SuperSplat 压缩 PLY 通过 `chunk` element 和 `packed_position` / `packed_rotation` / `packed_scale` / `packed_color` 表达同一类消费语义。因此它们都不能归入 `point_cloud`，也不能复用 `model_3d_quick_view_generation` 的 GLB artifact 路线。当前 Manager 基础预览已接入高斯泼溅前端 renderer，并通过 `format_info.ply.is_compressed_splat` 区分压缩 PLY 的加载策略；受管快显走 `gaussian_splat_quick_view_generation`，结果登记到 `manager.gaussian_splat_quick_view`，由 `model3d_workflow` 的 `gaussian_splat_to_ksplat` direct operator 发布 KSplat artifact。当前只支持源已经是 `.ksplat` 的受管发布；PLY / SPLAT 到 KSplat 的真实转换器后续接入同一路线，接入前前端和 API 不开放 PLY / SPLAT 受管生成入口。

## 三、第一批落地顺序

### 3.1 第一批：单体网格转 GLB

目标：复用三维模型 GLB 快显链路，让常见单体模型能预览。当前 `gltf`、`fbx` 和 `obj` 已进入 GLB 快显主路径：`format=gltf + layout=multi` 或 `format=fbx/obj + layout=single` 的 source item 复用 `model_3d_quick_view_generation`，由对应 direct operator 生成 Manager GLB 快显 artifact。`stl` 已进入 Meta scan 主路径，但不开放快显任务入口。

建议顺序：

1. `gltf`：已落地 GLB 快显主链路
2. `fbx`：已落地 GLB 快显主链路
3. `obj`：已落地 scan 和 GLB 快显主链路
4. `stl`：已落地 scan，快显待新增转换器

最小闭环：

```text
source item
  data_type = model_3d
  format = obj / stl / fbx / gltf
  layout = single / multi
  -> model_3d_quick_view_generation
  -> <format>_to_glb
  -> manager.model_3d_quick_view
  -> Model3DPreview
```

是否复用 `model_3d_quick_view_generation`：

1. 任务类型可以复用，语义是“模型源格式生成 GLB 快显”。
2. `source.format` 不再只允许 `osgb`，但必须按格式显式声明支持列表。
3. operator 名称不能含混，建议使用 `model_to_glb` 统一入口，并在 config 中写 `source.format`；或者保留多个 operator，例如 `fbx_to_glb`、`obj_to_glb`、未来的 `stl_to_glb`。当前更建议多个 operator，便于错误定位和能力声明。

### 3.2 第二批：大场景转 3D Tiles

目标：让非 OSGB 的倾斜摄影或城市模型也能进入 3D Tiles 预览。

建议顺序：

1. `3mx`
2. `slpk` / I3S
3. IFC 大模型 -> 3D Tiles

最小闭环：

```text
source whole item
  data_type = model_3d
  format = 3mx / slpk / ifc
  layout = whole / single
  -> model_3d_tiles_generation
  -> <format>_to_3dtiles
  -> target 业务存储 3D Tiles
  -> Meta scan
  -> ThreeDTilesPreview
```

### 3.3 第三批：点云分块读取

目标：把点云从抽样预览推进到大数据量分块浏览。

建议顺序：

1. `laz`
2. `copc`
3. `e57`
4. `ept` / Potree

点云优先目标不是 GLB，而是 COPC 或点云瓦片。

### 3.4 第四批：高斯泼溅快显

目标：在 `gaussian_splat` 已独立识别和可基础预览的基础上，补齐大模型友好的派生路线。

建议顺序：

1. 基于已接入的浏览器高斯泼溅 renderer，验证不同规模 3DGS PLY、关闭渐进加载的 SuperSplat 压缩 PLY、`.splat` 和 `.ksplat` 的加载与交互成本。
2. 已新增 `model3d_workflow` direct operator `gaussian_splat_to_ksplat`，第一版只支持源已经是 `.ksplat` 的受管发布，用于固定 Manager artifact 生命周期和对象存储发布协议。
3. 已新增 `gaussian_splat_quick_view_generation` 独立任务、`manager.gaussian_splat_quick_view` 结果表和 `gaussian_splat_ksplat` render source；该路线只承载 KSplat 受管 artifact，不复用 GLB 快显。
4. 如浏览器直接读取 PLY / SPLAT 成本过高，再为 `gaussian_splat_to_ksplat` 接入真实 PLY/SPLAT 到 KSplat 的转换器；转换器接入前不开放 PLY / SPLAT 受管生成入口。

## 四、`model3d_workflow` 扩展方式

`model3d_workflow` 继续作为三维模型转换运行时，新增 operator 时遵守：

1. operator 名称表达源格式和目标格式，例如 `fbx_to_glb`、`obj_to_glb`、`gaussian_splat_to_ksplat`、未来的 `stl_to_glb` / `ifc_to_glb`、`3mx_to_3dtiles`。
2. operator metadata 声明支持的 `source_format`、`target_format`、`layout`、是否支持 object store staging / publish。
3. 外部转换工具只作为 runtime 内部实现，不泄漏到 Manager 任务语义中。
4. Manager 任务准入只看 ADDP 标准事实：`data_type + format + layout + capabilities`。
5. 转换产物的生命周期仍分两类：
  - GLB 快显：Manager artifact。
  - KSplat 高斯泼溅快显：Manager artifact。
  - 3D Tiles 数据集：业务存储 data item。

第一批可选转换工具：

| 格式 | 候选工具 | 备注 |
| --- | --- | --- |
| glTF | assimp | 已验证 Linux arm64 `assimp export <input.gltf> <output.glb> -embtex` 可生成自包含 GLB；`_3dtile -f gltf` 对普通 glTF manifest 不作为 GLB 快显路线 |
| FBX | assimp | 已验证 Linux arm64 `assimp export <input.fbx> <output.glb> -embtex` 可生成自包含 GLB |
| OBJ | assimp | 已验证 `assimp export <input.obj> <output.glb> -embtex` 可生成自包含 GLB；`_3dtile` 不作为 OBJ 快显路线 |
| STL / DAE | assimp、Blender CLI、trimesh | 当前不开放 GLB 快显入口，需优先验证 Linux arm64 Docker 可用性和语义边界 |
| IFC | IfcOpenShell、BlenderBIM / IfcConvert | 优先验证 IFC -> GLB |
| 3MX / SLPK | 待调研 | 需要单独样例和转换器验证 |

## 五、文档和代码落地清单

新增任一三维格式时，按以下顺序推进：

1. 更新 `docs/concepts/addp数据类型和格式体系图.md`。
2. 更新 `docs/spec/addp内置数据类型与文件格式规范.md` 或扩展指南。
3. 更新 `docs/spec/addp数据项探测器规范.md`，写明 single / multi / whole、refs 和 claims。
4. 更新 `docs/spec/addp元数据attributes规范.md`，定义 `format_info.<format>` 和 `type_info.model_3d` / `type_info.point_cloud` 边界。
5. 更新 `common/format` descriptor 和 detector。
6. 更新 Meta scan / claims / normalizer 测试。
7. 更新 Manager quick view capability 和任务准入。
8. 更新 `model3d_workflow` 或点云 runtime operator。
9. 更新 Manager 前端快显入口和结果页。
10. 补 Swagger、单元测试、构建验证和真实样例验证。

## 六、当前建议

当前建议：

1. `gltf` multi 规则和 `fbx` single 规则复用 GLB 快显任务主路径。
2. `obj` 复用 GLB 快显任务主路径，通过 `obj_to_glb` 生成自包含 GLB artifact。
3. `stl` 先完成 scan、attributes 和 format_info，不开放 GLB 快显任务入口；如需 STL 快显，先引入并验证 Linux arm64 可部署的转换器，再新增 `stl_to_glb` operator。
4. 3DGS 型 PLY 归入 `gaussian_splat`，当前提供 Meta scan 和 Manager 高斯泼溅基础预览；不开放 GLB 生成入口。
5. 再调研 IFC，作为 BIM 专题。

这样可以先把“非 OSGB 源格式 -> GLB 快显”的通用任务模型打稳，再进入 BIM 和大场景。
