## 一、已定主线

### 1.1 数据类型边界

1. 网格模型、BIM、倾斜摄影、大场景和 3D Tiles 归入 `model_3d`，通过 `format`、`layout`、`type_info.model_3d.model_kind` 和 `format_info.<format>` 区分。
2. LAS、LAZ、COPC、E57、PCD、XYZ、EPT 等归入 `point_cloud`，不借用 `model_3d` 的 GLB 快显路线。
3. 3DGS PLY、SPLAT、KSplat 和后续 SPZ 归入 `gaussian_splat`，不归入普通点云，也不走 GLB。
4. 单体三维优先 GLB，分块三维优先 3D Tiles，点云优先 COPC，高斯泼溅优先原生 renderer / KSplat / 后续 SPZ。

### 1.2 快显产物边界

Manager 私有快显 artifact 只服务预览，不自动升格为业务 data item：

| 主线 | 任务类型 | 结果表 | 结果归属 |
| --- | --- | --- | --- |
| 三维模型转 GLB | `model_3d_glb_generation` | `manager.model_3d_glb` | Manager infra MinIO |
| 点云转 COPC | `point_cloud_copc_generation` | `manager.point_cloud_copc` | Manager infra MinIO |
| 高斯泼溅转 KSplat | `gaussian_splat_ksplat_generation` | `manager.gaussian_splat_ksplat` | Manager infra MinIO |
| OSGB Scene 分块瓦片快显 | `model3d_tiles_generation` | `manager.task_definitions` / `manager.model3d_tiles` | Manager infra MinIO，`target_format=3d_tiles|s3m` |

如后续需要把快显结果归一化为业务数据集，必须单独设计业务数据准备 / 物化任务，不与 Manager 私有快显任务混用。

### 1.3 工作流引擎边界

1. `model3d_workflow` 承担三维模型、BIM、高斯泼溅相关重型转换。
2. `pointcloud_workflow` 承担点云处理，第一阶段依赖容器内 PDAL，不依赖宿主机 PDAL。
3. Manager 只通过标准 workflow runtime direct operator 调用转换能力，不在 Go 进程内直接调用 `_3dtile`、Assimp、IfcConvert、PDAL 或 KSplat 生成脚本。

## 二、已落地基线

本节只记录当前后续路线的基线事实。实现细节以正式文档为准。

### 2.1 三维模型

| 格式 / 场景 | 当前路线 |
| --- | --- |
| `glb` | 源 item 直接三维预览 |
| `gltf + layout=multi` | `gltf_to_glb` 生成 Manager GLB 快显 |
| `fbx|obj|stl + layout=single` | 基础预览读取源文件；可生成 Manager GLB 快显 |
| `ifc + layout=single` | `ifc_to_glb` 专用 operator 生成 Manager GLB 快显，不走普通 mesh operator |
| `osgb + layout=single` | `osgb_to_glb` 生成 Manager GLB 快显 |
| `osgb_scene + layout=whole` | SuperMap Workflow `osgb_scene_to_s3m` 生成业务 S3M 数据集 |
| `osgb_scene + layout=whole` | Model3D Workflow `osgb_scene_to_3dtiles` 生成业务 3D Tiles 数据集 |
| `s3m + layout=whole` | 源 item 直接 S3M 预览 |
| `3dtiles + layout=whole` | 源 item 直接 3D Tiles 预览 |

`preview_state` 已成为预览模式偏好和视角状态表。旧预览状态表只允许出现在清理迁移中。

### 2.2 点云

| 格式 / 场景 | 当前路线 |
| --- | --- |
| `copc + layout=single` | 源 item 通过受控内容 URL、HTTP Range 和 Giro3D 动态 LOD 预览 |
| `las|laz|e57|pcd|xyz + layout=single` | 生成 Manager COPC 快显后预览 |
| `ept + layout=whole` | 已有 whole-scope descriptor 和 manifest 级轻量摘要；端到端预览路线待评估 |

点云主线已经收敛为 COPC。不新增独立点云样本任务，不建立 LAS / LAZ / E57 / PCD / XYZ 原生抽样预览主路径。

### 2.3 高斯泼溅

| 格式 / 场景 | 当前路线 |
| --- | --- |
| `gaussian_splat + format=ply|splat` | 可生成 Manager KSplat 快显 |
| `gaussian_splat + format=ksplat` | 源 item 直接预览，不创建二次 KSplat 任务 |

## 三、后续路线

### 3.1 三维模型格式

#### DAE / Collada 与 3DS

首期接入识别、模型摘要、声明贴图 refs / claims 和自包含 GLB 快显；范围以 `docs/spec/addp内置数据类型与文件格式规范.md` 为准。后续扩展应先用真实样本验证动画、复杂材质及单位表现，再讨论扩大范围。MAX、SKP、SGM 尚未接入。

2026-10-04 已在本地绑定的 Docker Assimp 转换器上复验 2 个 DAE、3 个 3DS 示例（包括多网格及 PNG 漫反射贴图），以及米/厘米与 X/Y/Z 上轴的 6 组 DAE 场景；单位缩放、轴向转换和子节点平移均保留在 GLB 节点变换中。统一发布校验已增加可显示场景、节点引用、无环单父层级及有限变换检查，并验证非法产物不会替换已有快显。此验收覆盖上述样例，不代表已支持动画或复杂材质，也不替代 Hosted 全平台 T4。

#### MAX、SKP 与 SGM 接入前验证

- MAX 是 3ds Max 原生完整场景，不能与 3DS 合并。Autodesk 明确说明原生 MAX 需由兼容版本的 3ds Max 打开。当前未接入原生解析和快显；通过 3ds Max 导出 FBX 后使用 ADDP 的 FBX 能力，不计为 MAX 原生支持。依据：[Autodesk MAX 格式说明](https://www.autodesk.com/support/technical/article/caas/sfdcarticles/sfdcarticles/What-file-formats-does-3ds-Max-import-and-export.html)。
- SKP 是 SketchUp 原生三维模型文件。当前绑定的 SuperMap iObjects C++ 12.1.0 Linux ARM64 完整 SDK 虽有 `ModelSKP` 枚举和 `UGSkpImportParams` 头文件，却不包含 SKP 解析库；原生调用 `UGFileParseManager::CreateFileParser(ModelSKP)` 返回空。当前环境不能直接读取 SKP，扩大支持前须确认可执行 SDK、文件版本范围和部署平台，不能仅凭接口名称声明能力。
- SGM 全称为 SuperMap Global Model，与 S3M 不同。依据：[SuperMap 模型数据说明](https://enhelp.supermap.io/Subject_introduce/Realspace/DataAndLayers/DataInRealspace/Model.htm)。当前 SDK 包含 SGM 解析库和自带的 `Resource/compass.SGM` 样例；2026-10-07 在临时验证副本中通过根 `make build-images` 标准入口运行 CTest 原生探测，成功读取最精细层 LOD -1 的完整骨架，得到 136 个顶点、94 个三角面；导出 OSGB 为 13328 字节，重新打开后顶点与三角面计数一致。读取探测副本的完整镜像构建、OSGB 导出探测副本的构建阶段及各自 4 项 CTest 均通过。SGM 直接导出 glTF 的探测返回失败；当前 glTF 解析器只提供读取实现，不能根据 `ModelGLTF` 枚举推断存在导出能力。

MAX、SKP、SGM 仍未注册 ADDP 格式插件。下一步优先评估 SGM 识别和显式 SGM→OSGB 转换，复用现有 OSGB 能力；SGM→GLB 快显的正式任务链路、贴图保真、单位和坐标变换仍待验证。本次探测只覆盖厂商自带的一份 SGM 样例，临时副本验证不替代工作区标准门禁或 T4，不上传 SDK、许可或厂商自带样例到公共仓库。

复验命令：在临时验证副本中运行 `make build-images IMAGE_BUILD_ARGS="--services supermap-workflow-engine --verify --jobs 1 --tag <独立验证标签>"`；原生探测由该副本的 CTest 调用，源码和结果留在操作系统临时目录。SGM→OSGB 探测副本仅构建并运行 SDK 构建阶段，不把它记为正式产品镜像或平台功能验收。

#### IFC / BIM

IFC 已进入 `model_3d` 和 GLB 快显主线，但不能只当普通 mesh。

后续动作：

1. 扩充失败边界样例：无几何表示、超大 BIM、异常单位、异常坐标范围、弱根元素模型。
2. 评估 IFC 前端快显体验：初始视角、楼层 / 构件树、属性查询、分类筛选。
3. 后续再讨论 IFC -> 3D Tiles、构件属性服务和空间树服务。

暂缓事项：

1. RVT、NWD、NWC 等专有格式暂不进入第一批。
2. 不把 IFC 并入 `fbx|obj|stl_to_glb` 普通 mesh 路线。

优先级：中。适合作为 BIM 专题单独推进。

#### 3MX

3MX 常见于 Bentley / ContextCapture 生态，属于倾斜摄影或大场景数据。

后续动作：

1. 收集真实样例，确认目录 / manifest 规则。
2. 定义 `format=3mx` 的 whole-scope detector、refs 和 claims。
3. 调研可部署转换器，优先目标为 3D Tiles。
4. 若转换器只能在特定平台运行，先讨论运行时边界。

优先级：低到中。需要真实样例后再设计。

#### SLPK / I3S

SLPK / I3S 属于 ArcGIS 生态分块三维场景。

后续动作：

1. 明确 SLPK 是单文件包还是展开目录作为主识别对象。
2. 调研 I3S 原生前端预览与 I3S -> 3D Tiles 转换成本。
3. 如果采用转换路线，结果仍应是业务存储中的 `format=3dtiles` item。

约束：不把 SLPK 伪装为 3D Tiles；转换结果才是 3D Tiles。

优先级：低。

#### STL 项目包

STL 当前只按单文件三维模型处理。类似 `files/ + images/ + README` 的 3D 打印项目目录，不能直接识别为 `format=stl + layout=multi`。

后续如要增强，只做目录级“3D 打印模型项目包概览”，不要把目录误识别为 STL 原生 multi item，也不要把 `images/` 当作 STL 纹理 refs。

优先级：低。

### 3.2 点云格式与预览

#### COPC 主线

COPC 是当前点云大数据量浏览和快显的唯一主线。

近期动作：

1. 持续做真实 NFS / MinIO 样例端到端回归，尤其是大 LAS、LAZ、E57、PCD legacy header 和 XYZ 文本边界。
2. 检查 `POINTCLOUD_WORK_DIR` / `CPL_TMPDIR` 容量配置，避免大点云生成 COPC 时被容器临时目录拖垮。
3. 持续验证 Giro3D COPC 预览的动态 LOD、HTTP Range、缓存释放、初始视角和交互性能。
4. 生成后的 COPC artifact 继续作为 Manager 私有快显产物；不自动创建业务 COPC item。

当前约束：

1. PDAL 写 COPC 的目标路径仍采用“工作目录文件 + 上传 Manager infra MinIO”单一路线。
2. 只有在目标 PDAL / GDAL 组合通过真实 `writers.copc -> /vsis3/` 验证后，才重新讨论直写 MinIO。
3. 不保留直写 MinIO 与本地上传双轨。

优先级：最高。点云收尾优先围绕这条主线做稳定性和部署验证。

#### LAZ / E57 / PCD / XYZ

这些格式已经接入 `point_cloud_copc_generation`，后续不单独设计原生渲染主线。

后续动作：

1. LAZ：继续走 COPC 快显；如需预算内基础预览，先验证压缩读取成本和失败边界。
2. E57：后续单独设计多站扫描的站点列表、站点选择和站点级可视化。
3. PCD：暂不做 binary / binary_compressed 原生抽样预览主线。
4. XYZ：大文件抽样读取、列语义扩展和列映射 UI 需先补规范。

优先级：中。以回归验证和失败边界收敛为主。

#### EPT / Potree

EPT / Potree 属于 whole-scope 点云数据集，不拆成大量普通文件 item。

后续动作：

1. 使用真实 EPT 样例做 NFS / 对象存储扫描验证。
2. 评估原生分块预览与转换到 COPC / 点云瓦片的取舍。
3. Potree 暂缓：`metadata.json` 命名过泛，需真实样例或更严格 manifest 规则后再进入内置 whole-scope detector。

优先级：中。适合作为点云主线收尾后的下一批格式。

#### 城市级点云与 3D Tiles

城市级点云 3D Tiles 暂缓。只有在明确“城市三维发布 / Cesium 场景集成 / 跨数据类型统一场景发布”价值时，再单独设计。

暂缓原因：

1. COPC 已能支撑当前点云快显和大数据量浏览目标。
2. 3D Tiles 点云涉及切片策略、样式、坐标系、场景发布和生命周期，不应混入 Manager 私有快显任务。
3. 如果未来推进，应作为业务数据准备或场景发布任务，而不是替代 `point_cloud_copc_generation`。

优先级：暂缓。

### 3.3 高斯泼溅格式

#### SPZ

SPZ 是后续高斯泼溅格式候选。

后续动作：

1. 确认前端高斯泼溅 renderer 是否稳定支持 SPZ。
2. 定义 `format=spz` descriptor、info provider 和 attributes。
3. 如需转换，新增专用 operator，不复用 GLB 快显任务。

优先级：低到中。

#### KSplat 渐进加载优化

当前 KSplat 生成已按场景中心组织 section。后续更理想的体验是按当前相机视野中心优先加载。

后续动作：

1. 确认当前 renderer 是否暴露可控的 section 优先级或加载队列。
2. 如可控，前端根据相机 target / frustum 动态调整加载优先级。
3. 如不可控，不 fork 第三方库前不做强改，避免维护成本不可控。

优先级：低。

## 四、近期收尾清单

点云收尾优先完成以下事项：

1. 回归 `las|laz|e57|pcd|xyz -> point_cloud_copc_generation -> manager.point_cloud_copc -> Giro3D COPC 预览`。
2. 回归源 `format=copc` item 的直接受控内容 URL / HTTP Range 预览。
3. 回归开发启动、局部重启、Docker Compose、生产启动、离线包和镜像推送清单中的 `pointcloud-workflow-engine`。
4. 确认文档中不再出现独立点云样本任务、旧式点云抽样主线或 LAZ / E57 原生渲染主线。
5. 确认 Manager 快显入口、普通 Preview 入口和受控内容接口都只消费同一条 COPC 渲染路线。

## 五、建议优先级

1. 先完成点云 COPC 主线收尾：真实样例、部署链路、工作目录容量、Giro3D 预览稳定性。
2. 再推进 EPT whole-scope 点云数据集评估：真实样例、manifest 规则、原生预览 / 转 COPC 取舍。
3. BIM 方向单独推进 IFC 深化：失败边界、构件属性、空间树、楼层和属性查询。
4. 普通三维格式如需继续扩展，优先验证 DAE / 3DS 首期边界，再扩展，复用 `model_3d_glb_generation + model3d_workflow`。
5. 城市级点云 3D Tiles、SPZ、KSplat 渐进加载优化暂缓到有明确场景价值后再开专题。
