## 八、后续开发顺序

| 优先级 | 下一步 | 进入条件 |
| --- | --- | --- |
| 1 | 补齐管理员部署清单接入的完整保存验收 | 现有导入预览及选择已有主机已复验；在隔离部署验证实际写入和失败处理，不重复创建个人主机/采集 |
| 2 | 完善 ADDP 服务与 Business 引擎的明确承载清单和接入 | 先明确声明来源、System 聚合版本及有效区间；沿管理员确认路径，不按地址猜测 |
| 3 | 补齐原功能表的服务质量、引擎专业指标及容器资源 | 确认专业凭据、对象归属、配额和 OS 支持，复用固定目录与唯一采集链 |
| 4 | Trace、慢接口与调用拓扑 | OpenTelemetry → Alloy OTLP → Tempo，先明确采样、传播、敏感内容与容量 |
| 5 | 生产发布及受控运维 | 真实平台 T5；SSH/初始化/防火墙/启停另有权限、计划、执行与审计确认 |

Trace 中 request_id、trace_id、execution 身份分别表达请求、调用链和业务执行；异步任务明确关联并创建新运行跨度，不能把长任务硬挂在创建请求下。慢请求保留须证明实际采样策略，随机头部采样不能保证保留全部慢请求。

受控运维中 ADDP 管理目标、计划、权限与审计，成熟执行设施实施变更。主机登记不默认保存 SSH 密码，采集身份不具备 Shell 权限；Monitor 不提供任意命令执行器，租户 Orchestrator 任务不隐含获得平台主机操作权。

### 9.3 验收状态与剩余缺口

完整样本比较正在沿原 `platform-node-metrics` 的 `complete-comparison` 场景补验收，自然采样预热不计入浏览器期限，但仍受原 1800 秒场景总预算约束；本轮不重复内存压力场景。受限 CPU 验收额度已确认，沿独立 `cpu-pressure` 场景实现；真实运行未取得通过证据。

资源告警正式身份链路已通过 [Hosted T4](https://github.com/pampa0629/addp/actions/runs/39016166744)（源码 `8111363d2`）：真实内存压力触发同一事件，来源缺样保持未知且不恢复，释放后恢复；两条通知均 delivered，首次 503 后自动重试共三次请求。正式身份拒绝、真实浏览器、后续中心/来源/控制面故障恢复及外层销毁零残留均完成。报告交叉核对了阈值、原始样本窗口、事件/投递身份和历史保留；本轮是单台 Linux VM、真实内存压力，不包含真实 CPU 加压或生产 T5。

主机新筛选与清单接入已通过本地分层门禁；个人 Safari 已复验组合筛选、详情返回、重置，以及清单导入、预览和已有主机选择，最近抓取成功且现有主机/采集数量不变；新建主机与采集的完整保存未执行。总览多真实主机、Hosted 完整时段比较和生产 T5 也未取得完整证据。

最近开发批次的 `make test-changed` 因测试连接预检未通过，不能计作聚合门禁通过；相关分项结果只证明各自范围。远端 CI 是否通过须核对对应源码与实际执行项，不以排队、路径跳过或旧批次结果代替。本文不保存运行编号和临时失败日志；正式测试产物由现有 CI/验收报告保存。
