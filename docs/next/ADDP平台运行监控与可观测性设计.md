## 二、后续开发顺序

| 优先级 | 下一步 | 进入条件 |
| --- | --- | --- |
| 1 | 验收 Business PostgreSQL 来源导入、部署登记及单主机承载声明 | 来源导出、System 聚合版本与声明有效区间已实现；真实接入 T4 待验，沿管理员确认路径，不按地址猜测 |
| 2 | 补齐原生宿主与多进程部署覆盖 | Linux VM 单新 Monitor 绑定已验；原生宿主与 Desktop VM 分别声明，多进程按各自实例身份验证，不在线改挂既有实例 |
| 3 | 补齐原功能表的服务质量、引擎专业指标及容器资源 | 确认专业凭据、对象归属、配额和 OS 支持，复用固定目录与唯一采集链 |
| 4 | Trace、慢接口与调用拓扑 | OpenTelemetry → Alloy OTLP → Tempo，先明确采样、传播、敏感内容与容量 |
| 5 | 生产发布及受控运维 | 真实平台 T5；SSH/初始化/防火墙/启停另有权限、计划、执行与审计确认 |

Trace 中 request_id、trace_id、execution 身份分别表达请求、调用链和业务执行；异步任务明确关联并创建新运行跨度，不能把长任务硬挂在创建请求下。慢请求保留须证明实际采样策略，随机头部采样不能保证保留全部慢请求。

受控运维中 ADDP 管理目标、计划、权限与审计，成熟执行设施实施变更。主机登记不默认保存 SSH 密码，采集身份不具备 Shell 权限；Monitor 不提供任意命令执行器，租户 Orchestrator 任务不隐含获得平台主机操作权。

## 五、服务承载清单接入边界

部署清单接入统一由 System 平台主机管理负责，v2 主机清单可省略采集并明确 ADDP 服务允许名单；需要采集时经 Console 一次性内存草稿将同一主机及来源交给 Monitor。协议和失败处理见正式规范 4.2，旧 Monitor 导入编排已删除。

macOS 原生宿主与 Docker Desktop Linux VM 分别登记，不能跨宿主绑定。接入结果只生成实际宿主上的 `ADDP_HOST_NODE_ID` 部署参数；新进程首次声明后仍由既有当前允许集合裁决，不自动修改全局 `.env`、重启服务或在线改挂旧实例。

## 六、Business 引擎接入设计

平台运维范围按实际运维责任确定，租户读取按对象权限确定。平台自管 Business 服务的部署、整体资源及可用性属于平台运维；租户自行部署的外部服务默认不纳管，委托监控须显式授权。平台角色不由运维关联获得租户连接凭据、表内容、SQL 或执行结果；共享主机和引擎的整体消耗不归算为某个租户用量。

区分纳管主机、实际引擎部署及 System Engine Instance。现有引擎地址去重按租户范围进行，同一部署可以对应多个登记；不按 engine_id 累加同一物理消耗。System 拥有部署身份和显式承载关联及其有效时间，Monitor 只消费授权投影。集群可以承载于多主机，云服务允许主机未知；不得按 IP、容器名或共享 VM 资源猜测关联。

租户登记与部署的关联须经服务端核验；租户外部引擎委托监控、租户用量归属和租户专业监控权限不在首批开放范围。平台维护同一底层故障事件，租户只读取获授权的影响提示。

来源导出与 System 部署登记、显式单主机关联已落地，契约见[平台运行观测规范 4.4](../spec/addp平台运行观测规范.md#44-平台引擎部署登记)。首批只接 Business PostgreSQL；文件、登记和关联均不证明实时在线或采集成功。代码与确定性验证不替代产品 T4，真实导入/登记验收仍待执行。

下一步先验收真实 PostgreSQL 部署来源到 System 身份与承载声明的链路，再接 Monitor 的引擎专用指标；多服务/集群、租户 Engine 关联、专业采集和租户用量归属仍未开放。新权限仅向既有平台系统管理员发布，运行验收需 System 正式迁移后重新完成密码/MFA 登录；一次性 Hosted 临时管理员如需新增部署接口用途，须按测试规范先明确限定范围。

### 部署登记 T4 限定方案（待确认）

复用 `platform-node-metrics` 的干净 Hosted Linux 一次性部署，增加独立 `engine-deployment-admission` 场景，不重跑旧服务宿主绑定专项。由既有 Business Compose 仅启动当次 PostgreSQL，运行正式只读导出入口；数据库仅作真实部署来源，不登记租户 Engine、不读取业务表、不进行压力测试。

临时平台系统管理员沿正式 Bootstrap、密码和 MFA 登录，仅在既有主机管理用途上补充当次 `/api/v1/system/platform/engine_deployments` 的读取、新建与带版本更新。真实 Console 页面导入无凭据清单、展示来源、显式选择当次主机并登记；正式 API 独立核对部署身份、声明主机及版本。验证刷新与详情恢复、重复登记拒绝、旧版本更新冲突且不覆盖新值，以及主机停用／恢复时当前关联的变化。保持生产角色、权限、Prometheus 身份和租户边界不变。

退出前停用当次部署登记及主机，声明历史留待整套临时数据库销毁，不增加删除 API 或 SQL 清理旁路。所有退出路径销毁本轮 Business 容器、网络、卷、应用、Infra、身份和凭据，分别核验零残留；业务报告在外层清理成功前不得声明整体通过。沿用 1800 秒场景预算、既有浏览器时限和 60 分钟 Job 上限。实现复用现有 wrapper、runner、browser 与 fixture 文件，同批同步闭合场景枚举、CI 登记检查和现有 `make test-node-metrics-online-runner` 门禁；不新增 workflow 或长期脚本。身份用途确认前不执行该专项。
