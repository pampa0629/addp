Trace 中 request_id、trace_id、execution 身份分别表达请求、调用链和业务执行；异步任务按运行观测规范第三批明确持久关联并创建短阶段独立 Trace，不能把长任务硬挂在创建请求下。慢请求保留须证明实际采样策略，随机头部采样不能保证保留全部慢请求。

受控运维中 ADDP 管理目标、计划、权限与审计，成熟执行设施实施变更。主机登记不默认保存 SSH 密码，采集身份不具备 Shell 权限；Monitor 不提供任意命令执行器，租户 Orchestrator 任务不隐含获得平台主机操作权。

## 五、服务承载清单接入边界

部署清单接入统一由 System 平台主机管理负责，v2 主机清单可省略采集并明确 ADDP 服务允许名单；需要采集时经 Console 一次性内存草稿将同一主机及来源交给 Monitor。协议和失败处理见正式规范 4.2，旧 Monitor 导入编排已删除。

macOS 原生宿主与 Docker Desktop Linux VM 分别登记，不能跨宿主绑定。接入结果只生成实际宿主上的 `ADDP_HOST_NODE_ID` 部署参数；新进程首次声明后仍由既有当前允许集合裁决，不自动修改全局 `.env`、重启服务或在线改挂旧实例。

## 六、Business 引擎接入设计

### 已确认的自带部署自动接入方向

2026-10-19 用户确认：Infra 与平台维护的 Business 部署统一作为 Platform 运维对象，租户连接、凭据、数据和任务继续按 Tenant 授权。日常入口改为部署侧自动发现、页面批量确认、随后自动更新来源与采集；不要求用户运行导出命令或传递 JSON。首次主机关联及扩大纳管范围须管理员确认；容器重建只更新运行来源，不自动迁移主机或授予租户权限。

实现顺序为：复用部署生命周期，统一只读发现本工作区 Infra/Business 实际 Compose 服务并自动发布有界无凭据快照；System 消费候选服务并维护确认的部署身份与承载声明；Monitor 按已实现的专业适配器配置采集。部署来源、管理员声明、实际可用性、采集结果分别表达，配置文件中的服务不等于已运行服务。发现失败清除当前有效候选，停服不等于删除已确认部署，观测故障不阻断业务启动。

发现只读取固定 Docker 字段，不读取 `.env`、容器环境变量、凭据或业务内容，不授予 System Web 服务 Docker 管理能力。快照由部署侧按作用域原子替换，Infra 与 Business 互不覆盖；未知服务与集群组件可以展示来源，但未适配能力明确标为不支持，不猜测集群、租户或物理消耗归属。首批专业指标依次覆盖 Infra PostgreSQL 与 Business PostgreSQL 的连接、事务、等待、回滚／死锁及容量；容器资源和其他引擎分别适配，主机总指标不冒充引擎指标。

自动来源刷新与已确认声明的存储、最小权限及并发契约需在实现相应阶段明确；既有手工导入不是长期并行路线，替代页面与正式前向迁移就绪时删除旧入口。旧手工登记 T4 不作为新自动链路验收；新链路须独立记录真实运行及全退出清理证据。当前本节为已确认方向，尚未实现的环节不能计为完成。

控制面先提供只读 `GET /platform/engine_deployments/discovery`：沿用非委托 Platform User 与 `platform.engine_deployment.read`，不接受 query/body。System 仅读取部署配置指定目录的 `infra.json/business.json`，不执行 Docker、不接受请求指定文件路径，不改变声明或权限。响应固定包含两个作用域，分别表达未配置、缺失、不可用、过期或有效快照；有效期限 120 秒，允许最多 30 秒时钟偏差，失败不得带旧候选或主机推断。批量确认写入未接入前，该只读能力不表示已完成自动纳管。管理员确认的版本与历史不随运行来源刷新改写，后续当前运行来源通过匹配已确认的来源键独立投影。

持续来源由部署侧独立观测进程每轮完成后间隔 30 秒刷新，不放入 System 请求或业务 Ready。复用同一发现入口和私有目录，Infra 启动／停止管理其生命周期，Business 与开发启动只确保同一工作区进程存在；启动结果与来源采样结果分别表达。进程只继承 Docker 所需环境，以私有运行记录和当次随机标识核对 PID 归属，拒绝操作不明进程；停止时立即将来源标为不可用，Hosted 退出同样须停止并确认无当次进程。观测进程只执行固定的只读 Docker 命令，不提供 Docker 变更入口，也不获得主机／部署登记、数据库访问或租户权限。

批量确认首批覆盖 Infra 与 Business 的两个单容器 PostgreSQL；其他服务显示发现事实及未适配原因，不将集群组件冒充完整引擎。唯一集合 POST 改为至多 16 个显式成员，各项只传作用域、服务名、来源事实摘要、名称、纳管意图及主机 UUID。服务端重新读取有效来源并校验摘要，按来源键排序后在同一数据库事务创建全部部署、声明及审计；重复成员、来源变化／过期、主机失效或任一写入失败均整批回滚。摘要不含每次刷新时间，也不充当持久资源 version；新建版本仍为 1，更新使用各自 version。PUT 只修改名称、纳管意图与主机，不接受客户端改写来源快照；来源运行变化独立投影，不覆盖声明历史。

确认快照统一为 `addp.engine-deployment-inventory/v1`，来源项目允许 `addp-infra/business`。已有根记录通过正式前向迁移规范化协议标识，稳定部署 ID、版本及声明时间不变；不可变声明历史和审计保留当时原始载荷，不增加旧协议读取分支。替代页面与批量 API 同批删除文件导入、单项原始来源创建、旧文件解析器及用户导出命令；失败和未知写入保留草稿、禁止自动重试，重新读取前不重复创建。

平台运维范围按实际运维责任确定，租户读取按对象权限确定。平台自管 Business 服务的部署、整体资源及可用性属于平台运维；租户自行部署的外部服务默认不纳管，委托监控须显式授权。平台角色不由运维关联获得租户连接凭据、表内容、SQL 或执行结果；共享主机和引擎的整体消耗不归算为某个租户用量。

区分纳管主机、实际引擎部署及 System Engine Instance。现有引擎地址去重按租户范围进行，同一部署可以对应多个登记；不按 engine_id 累加同一物理消耗。System 拥有部署身份和显式承载关联及其有效时间，Monitor 只消费授权投影。集群可以承载于多主机，云服务允许主机未知；不得按 IP、容器名或共享 VM 资源猜测关联。

租户登记与部署的关联须经服务端核验；租户外部引擎委托监控、租户用量归属和租户专业监控权限不在首批开放范围。平台维护同一底层故障事件，租户只读取获授权的影响提示。

持续发现、候选读取及管理员批量确认已实现，契约见[平台运行观测规范 4.4](../spec/addp平台运行观测规范.md#44-平台引擎部署登记)；普通操作不再导出或导入文件。两个单容器 PostgreSQL 自动接入的独立 T4 结果见[引擎指标证据][monitor-engine]，不包含专业指标采集。

2026-10-20 用户已确认 Infra／Business 各自独立的只读采集账号，由部署侧管理凭据；通过固定函数仅返回连接、事务、回滚、死锁、等待及数据库容量汇总，不读业务表、SQL 正文或租户凭据，不归算租户用量。先实现和验证数据库侧最小读取边界，再接入既有指标拉取及 Monitor 查询页面。多服务／集群、租户 Engine 关联和租户用量归属仍未开放。新自动流程如需扩展一次性 Hosted 临时管理员测试用途，须在具体调用范围明确后按测试规范确认，不沿用已被替代的手工导入验收。

2026-10-19 已确认的 Hosted 接入专项：沿用 `platform-node-metrics` 的一次性隔离部署及真实三员 Bootstrap／密码／MFA；临时平台系统管理员仅新增当次 `engine_deployments` 发现、列表／详情、两个 PostgreSQL 的批量创建及名称／启停／主机关联版本更新用途。覆盖重复成员／来源变化拒绝、第二项失败整批回滚、页面重读、权限拒绝及退役；只操作当次 Infra／Business PostgreSQL 容器与新建主机，不读取租户连接、业务数据或执行 SQL。Prometheus 身份及权限不变，不加压、不改个人环境；退出销毁当次身份、部署、容器、卷和仓库外凭据并核验零残留。按对应测试规范实施；真实执行及外层清理均通过前不计为 T4 通过。

### PostgreSQL 专业指标实施状态

独立采集身份和固定函数按[正式规范 4.6](../spec/addp平台运行观测规范.md#46-postgresql-数据库侧汇总读取边界)实现；两个作用域各有独立密码，仅执行固定汇总函数，不读取业务表、SQL 正文或租户凭据。SQL Exporter 与受控 mTLS 入口共用唯一版本化模板，关闭动态目标及缓存；查询失败不得带旧数据库样本，HTTP 200 或 Prometheus up 不作为采集成功证据。

账号安装和指标来源已由同一部署生命周期接入 Infra／Business 标准启停；四项输入、私有状态目录、明确端口及故障隔离见[正式规范 4.7](../spec/addp平台运行观测规范.md#47-postgresql-受保护的固定指标来源)。开关分别读取各自配置，默认关闭，不继承另一作用域的选择；启用先停止旧来源、核查无遗留会话，在 NOLOGIN 状态完整安装并更新／重载认证，复核后才开启 Login。停用先关闭本方来源及 Login，保留函数、配置、历史和数据卷；未知会话、凭据丢失或归属漂移拒绝自动修复。

Business 认证文件统一为仓库外受管目录、只读目录挂载；首次切换由部署方执行标准生命周期重建容器并保留数据卷。标准脚本不签发证书、不扩大 CA 信任、不由 Monitor 或 Web 请求重启数据库。具体实库、回归及 CI 结果按[采集来源与引擎指标证据][monitor-engine]分别记录；个人环境未切换或启用，不计为专业监控 T4/T5。

专业发现、Prometheus 接入、逐请求授权查询及页面已实现；T1／实源 T2／前端 T3、正式身份专业 T4 与后续来源 T2 见[引擎指标证据][monitor-engine]，按各自源码和执行项认定。专业 T4 不包含其后新增的主机导航，也不代表个人环境已经启用；多服务／集群、租户引擎关联和租户用量归属仍未开放。

### 后续自动接入的最小身份投影（已确认）

System 私有观测投影已在主机和模块实例基础上，按 2026-10-20 确认范围，在同一个 `/runtime/observability-identities` 内增加最多 1000 个当前有效平台引擎身份，仍仅固定 `addp-monitor`、非委托 Platform Service 和既有 `system.observability_identity.read` 可读；不新增角色分配，不授予后台创建／修改部署或租户 Engine 权限，不修改 IAM 内核。该投影与 Common 完整性校验已实现；T1／仓储 T2、Swagger 及断言修正见[引擎指标证据][monitor-engine]。投影、发现和专业查询的实现与验收分别核对，不由后台投影 T1 推导专业 T4 通过。

新增字段仅含部署 UUID、版本、作用域、引擎类型、有效承载主机 UUID 与无凭据来源键；不包含名称／地址清单、SQL 端口、数据库连接、Secret、租户登记或业务内容。System 继续唯一裁决启用部署和有效主机关联；Monitor 不读 System 私表。后台投影只用于有界发现与评估，用户专业指标 API 仍逐请求转交当前 User Token 给 System 核验引擎读取权；撤权、停用和来源变化不能由旧时序或后台身份兜底。沿现有五秒／四 MiB 上限预算，超量或控制面故障整份拒绝，不截断或伪装空列表。


### PostgreSQL 专业发现、查询与展示方案

沿用部署发现 → System 当前引擎身份 → Monitor 唯一 HTTP SD → Prometheus → Monitor 授权查询 → Console 页面这一条链，不新增手工登记采集目标、数据库凭据或租户 Engine 关联。权限沿用 `monitor.resource_observation.read` 与逐请求核验的 `platform.engine_deployment.read`，不新增权限／角色分配或调整 IAM 内核。

可信来源由部署侧仅读取固定 Docker 身份、Owner／作用域标签及指标容器的显式发布端口，核对采集器所绑定的数据库容器与当前 PostgreSQL 完全一致；不读取容器环境、SQL 端口、密码、文件 Secret 或数据库。来源端口和数据库端口分开，不按名称或 IP 猜测对应关系。无采集器、部分启动、归属不明、来源变化或过期分别表达，不因专业来源不可用清空合法主机和进程身份。

**已确认的后台读取扩展**：同一个 System 私有观测投影，仅为已纳管且有效关联主机的 Infra／Business PostgreSQL 增加指标 HTTPS 端点与当前数据库容器运行身份／启动时刻。既有后台身份及权限不变，字段不进入普通浏览器 DTO；不增加 SQL 地址、连接凭据、租户引擎或业务内容。System 继续唯一裁决管理有效性，Monitor 只核验固定 mTLS／CIDR／端口准入并派生采集标签。部署发现协议采用单一更新版本，旧读写路径同批移除；引擎确认摘要与不可变声明不包含采集配置，不让来源启停改写管理历史。

固定查询目录首期 12 项：总连接、活跃连接、空闲连接、事务内空闲连接、活跃等待、锁等待、IO 等待、最大连接数（均为数量）；每秒提交、每秒回滚、每秒死锁（各自为独立累计量的速率）；非模板数据库总容量（字节、页面自动换算）。这是整体 PostgreSQL 观测，不将采集事务当业务吞吐、不归算租户用量，也不凭连接数直接判断健康。

速率使用固定一分钟完整窗口，至少四次有效采样，并验证过去和当前属于同一服务启动／统计代际、无计数回退且窗口两端新鲜；重启、统计重置或统计关闭时留空，不补零、不跨代际计算。SQL Exporter 的 HTTP 200／up=1 仍不足以证明 SQL 成功，必须验证固定快照、采样时间与字段完整性；来源不可用或 SQL 失败清空当前值，缺样形成趋势断点。

接口为 `/platform/engine_resource_observations`（单部署、最多十二指标）、`/platform/engine_resource_summaries`（当前页部署的四项摘要）及 `/platform/engine_resource_trends`（单部署固定目录）。预算复用当前查询策略；用户 Token 每请求交 System 裁决，查询后再核对当前身份／权限／来源，不用后台权限或旧时序兜底。页面在运行监控下提供“引擎监控”，从现有 System 引擎部署列表进入；不让用户重复填写节点或端点，复用共享格式化、图表、自动刷新与 URL 恢复。

**已确认的首期历史范围**：即时值与最多七天趋势只读取当前 PostgreSQL 容器运行段；采集器重启但数据库运行身份不变时可延续，数据库容器重建后不混入旧容器数据。数据库进程重启或统计重置位置的速率仍按前述代际检查留空。退出容器历史及跨运行段拼接另定保留／授权规则。

验证沿既有 Monitor／System／Common T1、System 投影／Monitor PostgreSQL T2、固定指标 mTLS T2、Monitor／Console 前端门禁及 Swagger 覆盖；部署发现协议、标签和 Prometheus 配置变更同步既有 CI 登记。正式身份专业查询／页面 T4 沿下述已确认的限定 Hosted 用途执行，未执行、失败或清理不完整均不计通过。

2026-10-21 已确认的正式身份 T4 限定用途：沿同一一次性 Hosted 的 `engine-admission` 前置，只给当次临时平台管理员增加三个 `engine_resource_*` GET 的专业观测测试用途，并操作当次两个已接入 PostgreSQL 的真实 Console 引擎监控页面。验证固定目录、单位与零值、当前容器趋势、停用／来源缺失清空和恢复，以及无权限身份拒绝；沿正式密码／MFA、既有平台读取权限和独立 Prometheus 身份，不读取租户 Engine、SQL 正文、业务表或凭据，不改生产 IAM、不加压、不触及个人环境。仍使用原 1800 秒场景及 Job 60 分钟上限，退出销毁当次部署／身份／凭据并核验零残留；必须实际执行且清理通过后才计为 T4 通过。

## 服务实例配额与容器利用率（部署侧证明方式已确认）

2026-10-24 只读核对时，本机 Monitor、Meta／Transfer／Quality Worker 由标准开发入口作为 macOS 原生进程运行，未施加独立 CPU／内存配额。根 Compose 中 Meta／Transfer Worker 的限额示例仍是注释；Business 引擎容器的限额不属于这些原生进程。**开发方式保持原生**，不能为了展示配额把 Worker 改为容器。`GOMAXPROCS` 是 Go 并行度，`GOMEMLIMIT` 是 Go 运行时软限制，均不能替代操作系统硬上限，见 [Go runtime](https://pkg.go.dev/runtime#GOMAXPROCS)及[Go 内存软限制](https://pkg.go.dev/runtime/debug#SetMemoryLimit)。

2026-10-24 已确认的首期范围为**明确一实例一独立 Linux 容器**的运维观测：在实例详情分开显示进程 CPU／RSS 与容器整体用量／硬上界，不扩展批量列表的读取量、默认分页、告警或趋势。无明确配额不生成配额利用率，不用宿主总量补实例分母，不把进程 RSS 当作容器整体用量，不将超限等同泄漏；硬上界也不表示独享或保证可用容量。指标及计算条件统一见[正式规范 6.1](../spec/addp平台运行观测规范.md#61-固定指标目录)，单实例读取范围、固定目录与预算见[6.2](../spec/addp平台运行观测规范.md#62-资源查询与预算)。

原生开发不自动配置额度或修改部署限制；macOS 不生成组用量或有效零值，详情就近解释未接入，不铺四张空卡片。采样、完整部署证明、身份关联及正式身份验收分别判定，既有 CPU／RSS 验收用途不自动扩展为容器读取。

### 已确定：部署侧提供容器关联与完整限制层级

引擎发现与应用容器证明是两个事实来源，`infra`／`business` 引擎来源不能推断 ADDP Backend／Worker 所在容器。2026-10-24 已确认由**部署侧**发布有期限的只读证明，Common 仅采自身 cgroup，System 沿唯一私有投影精确关联当前实例，Monitor 按当前 User 的实例读取权限查询并在完成时重核。私有投影不代替用户授权，不改变 IAM、主机关联或普通实例 DTO；响应不含容器 ID、端点、内核身份或文件路径；应用不持有 Docker socket、不开放宿主 cgroup 层级、不扫描其他进程，不读取环境凭据或业务命令，也不修改现有容器命名空间／挂载配置或保留第二套降级路线。身份匹配、证明发布范围／有效期、指标口径及重核规则统一由[正式规范 6.1](../spec/addp平台运行观测规范.md#61-固定指标目录)维护；Platform User、Permission、System 读取裁决及查询预算统一见[6.2](../spec/addp平台运行观测规范.md#62-资源查询与预算)。

完整限制层级是有效证明的前提：父级约束仍作用于子级，cgroup 命名空间与子树挂载可能隐藏祖先；容器内有限的 `cpu.max`／`memory.max` 或 Docker inspect 配置额度均不能单独证明真实完整层级，见 [cgroup v2 层级规则](https://docs.kernel.org/admin-guide/cgroup-v2.html)及 [cgroup 命名空间](https://man7.org/linux/man-pages/man7/cgroup_namespaces.7.html)。共享容器、父级不可见、权限不足或 Docker Desktop 等不支持来源不提供有效证明；不通过提升应用权限或在业务容器内执行命令绕过。无有效证明时仅可沿当前声明边界读取绝对用量，无有限硬上界时不计算对应利用率，具体判定沿正式规范 6.1、6.2。

验证沿 Common 跨平台采样／固定文件解析及 Common／System／Monitor Go T1、部署发现 T1、System 精确身份／投影的进程登记 PostgreSQL T2、既有 cgroup-source Prometheus T2、前端单位／缺配额／共享边界拒绝 T1/T3，以及双模块 Swagger 生成／覆盖；按受影响 owner 扩散，同步 API、Swagger 与 CI 路径登记。Linux T2 仅用标准一次性受限设施，不修改个人资源限制。

固定版本、失败与修复结论及各层覆盖范围见[实例与服务发现证据][monitor-instance]。共享组 SDK T2 与受控页面 T3 不证明独立 Linux 容器的真实完整限制层级、正式身份的配额查询／页面或 Hosted T4；完整实机及正式身份 Hosted 仍待专门验收会话回传，未执行项不计通过。


## 服务同用途副本失联告警：已确认目标与部署事实来源

2026-10-25 已确认并接通按同一模块、Backend／Worker 角色及用途判断全副本失联的规则、持久运行确认、事件评估与页面。单副本失联只在列表展示，不同 Worker 用途不互代；首期只表达 System 心跳／租约失联，不证明进程退出或业务不可用。管理权限、候选范围、时长、资格重建、事件及显式通知订阅统一由[正式规范 7.1.1](../spec/addp平台运行观测规范.md#711-服务组失联规则)维护；后台投影不代替当前 User 的 System 模块读取裁决。

部署预期以**标准部署启动／停止入口**发布的应运行／计划停用声明为唯一来源，由 System 同一时点汇总正式登记与有效租约，Monitor 消费私有组投影。模块 `enabled` 不代表某类 Worker 已部署，缺席或历史登记总数不能推断应运行，也不能授予运行确认资格；不从 Docker 存活列表反推预期，不增加 Monitor 手工维护路线、远程 Shell、自动启停或扩缩容。持久预期不随发布器退出自动过期，计划停用必须明确发布；局部启停、发布失败隔离及真实 UTC 微秒变更标记统一见[正式规范 4.8](../spec/addp平台运行观测规范.md#48-服务部署预期与分组租约观测)。

用途对应 Meta `scan`、Transfer `sync`／`continuous_sync`、Quality `quality-bounded`；Backend 按角色分组，Security Worker 不在本批新增范围。`metadata.runtime_name` 可随再次登记更新，不能直接作为不可变部署身份；用途缺失或不规范时不得按模块名、PID、IP 或其他用途补算。分组与当前在线副本以 System 同一时点裁决为准，分组变化中断连续窗口，不改写旧事件证据。

标准入口的发布与生命周期职责沿规范 4.8：开发按本次已解析的后端及正式 Worker 单元，生产按 Compose／Profile 声明发布；生产 System 的只读目录挂载独立于指标开关且只有一个所有者，操作沿工作区生命周期锁串行。启动发布失败保留旧声明、报告可选观测故障，核心启动继续；停止须在第一项停止动作前成功发布计划停用。停止与启动读取同一根 `.env` 目录配置，局部停止仅改所选模块；发布失败不停止进程、不卸载 launchd、不执行 Compose down。文件发布不证明真实启动就绪或停止成功。

首次尚未在当前有效预期内观察到在线副本时保持“等待确认运行”，不触发或恢复，不将编译、初次登记等待或历史登记当成已运行。未知／System 失败中断窗口，不触发也不恢复；未部署、计划停用或模块停用不伪造活动事件恢复。确认后须真实同用途副本重新在线并满足恢复窗口才恢复同一事件。资格重新确认、Monitor 重启后的窗口、事务重核及通知边界沿规范 7.1.1；首次启动失败仍需另有部署结果事实，不在本批判断范围。

验证入口保持 `make test-dev-lifecycle`、Common／System／Monitor Go 门禁、System 分组同快照 PostgreSQL 门禁、`make test-monitor-postgres` 及既有前端门禁，沿既有自动发现及 Metrics 输入登记。发布协议、停止屏障与微秒标记的分批结果见[部署预期协议](../spec/testing/evidence/Monitor实例与服务发现历史证据.md#2026-10-25-服务组部署预期协议与只读租约汇总自动接入未完成)、[标准启停接入](../spec/testing/evidence/Monitor实例与服务发现历史证据.md#2026-10-25-标准启停接通服务组预期与停止前发布屏障)及[变更标记消歧](../spec/testing/evidence/Monitor实例与服务发现历史证据.md#2026-10-25-确认运行前置组预期变更标记消歧)；规则、受控时钟、数据库及页面分层结果见[规则与持久确认](../spec/testing/evidence/Monitor告警与规则历史证据.md#2026-10-25-服务组失联规则与持久确认)。各条证据的固定版本、失败与后续修复分别保留，不将前期未完成状态或无关聚合失败改写为当前整体结论。
