## Manager 数据预览显示“暂无数据”

若 Manager 已收到成功响应但页面没有数据，先在浏览器 Network 中核对预览请求的响应体，再跟踪 API helper、store 和预览组件的实际输入，区分空数据与前端取值错误。

`manager/frontend/src/api/client.js` 使用共享 `createAPIClient()` 的默认 `extractData=true`；拦截器提取 Axios response 的响应体。业务调用应按 helper 的真实返回结构取值，不把响应体再次当作 Axios response，也不盲目删除接口自身数据结构中的 `data` 字段。

排查顺序：

1. 核对预览请求 `GET /api/v1/manager/preview` 的状态、响应体及 locator；引擎列表走 Manager，资源树事实走 Meta。
2. 对照 `manager/frontend/src/api/dataExplorer.js` 的 `getPreview()` 与调用方，检查是否对已提取的响应再次访问 `.data`。
3. 对照[数据预览语义协议](../../../manager/docs/数据预览语义协议.md)，检查内容类型、预览材料与前端渲染能力是否匹配，不再按历史 `mode` 示例判断全部预览响应。
4. 修复后刷新页面并选择同一数据项验证；前端源码通常会热重载，无需为单个取值问题重启全部后端。

公共响应包装与 helper 返回值遵循 [API 设计规范](../../spec/addp-API设计规范.md)；组件和 store 不自行猜测 wrapper。回归入口为 `make test-manager-frontend`。

## Orchestrator 任务库搜索被异步选中清空

**现象**：点击任务库的“添加到画布”后立即输入“不存在”，本应显示“未找到匹配任务”，搜索框却变空，原任务列表重新展开。浏览器回归 `keeps task types collapsed and expands only matching search paths` 因而在 5 秒内找不到无匹配提示；本地偶尔通过、Linux CI 多次失败。另一种触发方式是先选中画布节点，在任务库仍加载时输入新搜索，库数据返回后搜索被清空。

**根因**：输入事件已正确更新过滤状态，较晚完成的来源定位覆盖了新输入。添加节点须先请求任务详情，响应返回后才自动选中新节点；原 `TaskPanel` 同时监听选中任务和匹配库节点，在监听触发时无条件清空搜索。任务库列表晚到、匹配节点由无变有，也会触发同一逻辑。自动选中还会将焦点移到画布，影响继续输入。不能仅凭最终输入框为空，就判定浏览器没有收到输入。

排查与修复顺序：

1. 同时记录真实 `input` 事件、过滤状态、任务详情／库列表响应及画布选中事件。核对是否出现“输入新词 → 过滤状态更新 → 响应返回 → 自动选中 → 搜索被清空”的顺序；只看截图或最终 DOM 无法确定原因。
2. 将来源定位绑定到用户意图发生的时刻：点击添加时定位已知来源；显式选择画布任务时才清除旧搜索。详情异步完成后的自动选中只更新高亮，并保留用户此后输入的搜索及编辑焦点。
3. 任务库节点晚到时，只在当前搜索为空且选中来源仍一致时展开和滚动；不得再次清空搜索。再次显式选择画布节点仍应能够重新定位来源。实现归属见 [TaskPanel](../../../orchestrator/frontend/src/components/TaskPanel.vue)、[DAGEditor](../../../orchestrator/frontend/src/components/DAGEditor.vue)；交互约定见 [Orchestrator 模块说明](../../../orchestrator/CLAUDE.md#定义保存与画布)。
4. 在[浏览器回归](../../../orchestrator/frontend/e2e/dag-layout-persistence.spec.js)的受控 API 夹具中分别延迟任务详情和库列表响应，在等待期间输入无匹配词，确认响应返回后搜索、无匹配提示和输入焦点仍保持；同时保留初始折叠、仅匹配路径、来源定位、刷新恢复和参数按钮入口检查。不要通过延长 5 秒断言预算或增加自动重试掩盖顺序错误。

标准验证入口：

```bash
make test-orchestrator-frontend
make test-frontend-ci-registration
```

修复提交 [`7681e0e4a7a18f19d5fb8f83fbcf20d17491fa90`](https://github.com/pampa0629/addp/commit/7681e0e4a7a18f19d5fb8f83fbcf20d17491fa90) 的 [Linux Orchestrator 前端 Job](https://github.com/pampa0629/addp/actions/runs/44066219500/job/133980459013)（`push`、attempt 1）已实际执行 `make test-orchestrator-frontend`：26 项单测、57 项浏览器回归及构建全部通过，包含原失败用例和新增的库列表晚到回归。本地同一前端门禁及 34 项 CI 登记检查也通过。该结果仅对应此固定提交的前端范围，不代表整个 workflow、PostgreSQL T2 或真实后端验收通过。

## 前端页面重启后白屏，Vite 提示依赖分块不存在

如果浏览器请求 `node_modules/.vite/deps/chunk-*.js` 返回缺失，而当前生成目录已不再引用该分块，先检查测试与开发进程是否共用预构建缓存。Standard 的自动组件导入会在页面请求时引入 `element-plus/es`；开发服务与 Playwright 服务共用 `.vite` 时，测试重新预构建可能替换正在使用的分块。

各前端浏览器夹具统一通过 `withFrontendTestIsolation()` 隔离缓存到仓库外的本轮临时目录，并关闭测试 HMR；门禁结束自动清理，开发缓存不受影响。不要维护模块自己的 `.vite-e2e` 路线。Standard 在 Vite 中显式预构建 `element-plus/es`；验证使用 `make test-standard-frontend`，并在测试完成后刷新实际开发页面，确认新建术语等入口可用。不应通过修改依赖锁文件或排除整个组件库绕过缓存问题。

另一种表现是 System 页面在 `ElConfigProvider` 的 `renderSlot` 抛出 `Cannot read properties of null (reading 'ce')`，同一个 Vue 运行时分块在调用栈中带有两组查询版本。2026-10-22 排查确认，Console 的真实 HMR 端口测试曾以 `ADDP_E2E=0` 启动 System；临时源码副本又将 `node_modules` 链接到开发目录，测试预构建因此覆盖活动缓存。重启 System 可以恢复页面，但预防复发必须修复测试入口：HMR 探针仍开启共享测试隔离，仅在当轮 `ADDP_BROWSER_RUN` 中声明 `hmr: true`，保留 HMR、隔离缓存并自动清理。`make test-common-frontend` 验证共享策略，`make test-console-frontend` 验证实际 Console／System HMR 和缓存生命周期。若个人环境已受影响，由用户执行 `./scripts/dev/restart.sh -system` 后再核验页面；AI 不自行重启。

Manager 复用同一共享隔离能力，测试 HTTP 与 WebSocket 不占用开发端口。`make test-manager-frontend` 包含数据探查血缘的实际画布高度、窗口缩放、层数请求与截断提示验证；测试完成后刷新运行中的开发页面，确认未被测试预构建破坏。现有 Makefile 和平台 CI 的 Manager 前端门禁自动发现 `e2e/*.spec.js`，无需另建测试启动路径。

Graph 若在首次打开本体详情时退回列表，检查 `logs/graph-frontend.log` 是否在同一时刻出现 `new dependencies optimized` 和 `optimized dependencies changed. reloading`。自动组件导入在初始扫描后生成的样式入口会触发重新优化与 iframe 刷新，中断尚未完成的 Console 地址同步。Graph 统一在启动时引入 Element Plus 样式，预构建已声明依赖和 `element-plus/es`，关闭运行时新依赖发现；不通过延时、重载或改导航协议修复。`make test-graph-frontend` 验证预构建配置，`make test-console-frontend` 验证真实父子页面导航。Vite 配置变更需要用户执行 `./scripts/dev/restart.sh -graph` 后，再在开发页面核验首次导航；AI 不自行重启。

## 血缘图自动适配后节点过小或偏离中心

血缘连线的交叉描边与主路径必须同步更新。G6 初次绘制路径可能早于 Dagre 最终布局；若只在 `afterDraw` 创建描边，旧路径即使与画布同色，也会进入整体包围盒，导致自动适配错误。共享 `LineageViewer` 在 `afterUpdate` 同步描边路径，并在 `afterrender` 完成一次视口适配。回归使用 `make test-manager-frontend`，其中双节点图的中心连线点击与来源执行跳转验证适配后的实际位置。
