# 数据脱敏与保护后续工作专题

更新日期：2026-10-28。负责会话：p145-security。

本文记录本会话的数据保护、数据脱敏待办与推进顺序。正式能力和约束以[实现规范](../spec/addp数据安全与隐私保护实现规范.md)为准，已实现内容及分层验证证据见 [Security 模块记录](../../security/CLAUDE.md)。跨领域的远期范围见[数据安全与隐私保护后续事项](../next/ADDP数据安全与隐私保护体系专题.md)。本文中的建议不表示新增范围已经获准实施。

## 一、已有基础与工作边界

- 掩码、固定值替换、SM3 哈希，以及四个已支持出口的逐字段算法与参数配置已具备；不能据此声称所有数据类型、引擎和执行形态均已覆盖。
- Manager、Develop、Service、Transfer 在各自已接入路径中消费同一套保护契约；尚不支持的受保护路径明确拒绝，不回退到未保护输出。
- 字段有默认方式。角色专用方式增加可用资格，多个角色的可用方式取并集；增加角色不自动改变默认方式，不新增“多角色自动取最严”或角色优先级排序。
- 普通预览和未保存特殊方式的查询采用默认保护。业务需要时，在查询、服务或任务配置中选择一次并保存；后续执行仍核验当前资格和方式修订，失效明确拒绝，不静默切回默认。
- 原值不属于角色脱敏选项，继续走既有精确出口、主体与期限的审批。执行历史只保留脱敏预览，需要原值时按当前授权重新查询。
- 本会话不处理数据项源授权管控的撤销，不处理栅格，也不恢复既往日志副本清理事项。Service 的应用凭据保护方式绑定继续暂缓。

## 二、剩余开发任务

| 编号 | 事项 | 当前缺口 | 建议顺序与准入 |
| --- | --- | --- | --- |
| DP-01 | Service SQL 服务的角色脱敏选择 | 当前角色方式只接入有确定 Meta 快照的原生单表服务；普通 SQL 服务尚未接入，非空选择明确拒绝 | 优先。先确认单表直接字段与别名的范围，修订规范后实施 |

SM3 是不可逆哈希脱敏，不等同于静态加密或透明解密。上述事项不包含未经确认的任意策略 DSL、自动角色优先级或新的数据访问授权体系。

### DP-01：建议首先推进的切片

建议目标是让已有登录用户角色方式覆盖常用 SQL 查询服务，沿用 Develop、Transfer 的共享字段选择与资格核验能力。

建议首期范围：

1. 单个普通表，Provider 能证明直接源字段及显式别名；同源字段的多个输出副本均执行对应方式。
2. 服务配置中选择一次并保存，默认方式和角色专用方式仍分开处理，不要求每次调用选择。
3. 保存、重新启用及实际调用按当前登录账号核验角色、目标字段和选项修订，不借用发布人或 Worker 的角色。
4. 资格撤销、自然到期、方式修订或来源变化时明确拒绝；保留失效选择，允许直接停用服务，显式移除选择后才能恢复默认方式。
5. AK/SK、匿名调用的角色方式绑定、联邦和指标来源不随该切片扩展。

范围确认后，先修订正式规范，再实现唯一主路径；同步检查 Service、Common、共享前端、Swagger 与现有门禁的真实影响范围。验收至少包含配置保存、别名与同源副本、正常输出、资格和方式分别失效、默认恢复，以及输出格式／续页的已支持边界。T0–T3 与真实运行分别记录。

### 本轮已修正：算法可见性与已有资源定位

针对 MongoDB `Outdoor.Persons / userInfo.phone` 的算法查找问题，已区分默认保护配置、显式字段规则和出口投影中的算法：默认方式保留前后字符，不代表 Manager 字段规则仍使用该算法；该资源当前预览规则为 SM3。摘要复用现有算法与参数说明，出口直接展示后端已返回的算法，同步状态单独保留，缺失算法不推测为默认掩码。

Manager 的“查看/配置”现在携带标准资源定位信息进入唯一受保护资源页面，优先打开未退出的已有详情；完整查找确认不存在且具有创建权限时才展示纳管窗口。只读查看无需创建权限；接口错误、身份不符、分页不完整和过期异步请求不会触发创建窗口。此修正没有改变源数据、算法、保护策略或授权，也没有新增 API。

本轮验证覆盖 Security 的单元、中英文受控浏览器与构建，以及 Manager 的入口权限和导航。它证明界面行为，不替代个人环境真实 HTTP／浏览器或 Hosted 的运行证据；具体门禁结果归档于模块记录。DP-01 至 DP-04 的开发缺口保持原有边界。

## 四、暂缓和不纳入本轮的范围

- **Service AK/SK 等应用访问方式与保护策略绑定**：按用户要求暂缓；不从应用凭据推导用户角色，不借用发布者身份。
- **静态加密的架构决定**：属于 DP-04 的前置讨论，当前不先行实现密钥或密文存储方案。
- **数据项源授权与栅格**：由对应会话处理，不作为本会话继续开发或验收的依赖事项。
- **既往日志与副本处置**：按用户决定搁置，不扩展为新的产品治理流程。

1. 当前优先建议推进 **DP-01：Service SQL 服务的角色脱敏选择**；先确认上述切片，再修订规范和实现。

3. 每次交付更新本专题的当前状态、剩余缺口和优先下一步，已完成内容回写正式规范及模块证据，不追加排队或重复状态流水。
4. 测试入口遵循[测试与验收规范](../spec/addp测试与验收规范.md)。实施前确定必需门禁，复用仍有效的验证；失败、跳过和未运行分别记录，不计为通过。
5. 涉及共享 Common 且需要本地运行验收时，由用户通过标准生命周期脚本重启；本会话不自行启停服务。
6. 湖南功能清单由 p0-hunan功能清单维护统一更新。本专题只提供任务与证据入口，不代替工作簿，也不把新增待办文档记为功能完成。
