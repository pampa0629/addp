# ADDP 模块依赖版本统一计划

## 一、当前问题概述

通过分析ADDP平台8个后端模块的依赖配置，发现以下共享依赖库存在版本不一致问题：

### 严重不一致（需立即处理）

1. **JWT认证库混用** - Meta模块使用v4.x，其他使用v5.x（API不兼容）
2. **MySQL驱动版本分散** - v1.7.0到v1.9.3跨度大
3. **MinIO客户端版本差异** - v7.0.63到v7.0.95
4. **Asynq队列库不一致** - v0.24.1与v0.25.1混用

### 轻微不一致（建议统一）

5. GORM小版本差异 - v1.31.0与v1.31.1
6. Redis客户端版本 - v9.16.0与v9.17.2
7. 几何处理库 - v1.5.7与v1.6.1

**影响模块**: System, Meta, Develop

**风险**: Meta模块从v4迁移到v5需要代码改动

**任务清单**:
- [ ] System: v5.2.0 → v5.3.0 (小版本升级)
- [ ] Meta: v4.5.0 → v5.3.0 (大版本迁移，需检查代码)

```bash
# 检查Meta模块中JWT的使用
```

- `jwt.StandardClaims` → `jwt.RegisteredClaims`

```bash
#!/bin/bash

set -e

echo "🔄 开始升级所有模块的共享依赖..."

# 定义升级函数
upgrade_module() {
    local module_path=$1
    local module_name=$2
    shift 2
    local deps=("$@")

    echo ""
    echo "📦 升级 $module_name 模块..."
    cd "$module_path"

    for dep in "${deps[@]}"; do
        echo "  ⬆️  $dep"
        go get "$dep" || echo "  ⚠️  $dep 升级失败（可能不需要）"
    done

    go mod tidy
    echo "  ✅ $module_name 完成"
    cd - > /dev/null
}
```

### 6.4 Meta模块JWT迁移测试（关键）

**检查代码位置**:
```bash
# 查找JWT v4 API使用
grep -r "jwt.StandardClaims" meta/backend/
grep -r "jwt.NewWithClaims" meta/backend/
grep -r "jwt.ParseWithClaims" meta/backend/
```

**v4→v5代码变更示例**:

```go
// v4 (旧代码)
type Claims struct {
    UserID   uint   `json:"user_id"`
    Username string `json:"username"`
    jwt.StandardClaims  // ❌ 旧API
}

token := jwt.NewWithClaims(jwt.SigningMethodHS256, Claims{
    UserID:   user.ID,
    Username: user.Username,
    StandardClaims: jwt.StandardClaims{  // ❌ 旧API
        ExpiresAt: time.Now().Add(24 * time.Hour).Unix(),
        IssuedAt:  time.Now().Unix(),
    },
})

// v5 (新代码)
type Claims struct {
    UserID   uint   `json:"user_id"`
    Username string `json:"username"`
    jwt.RegisteredClaims  // ✅ 新API
}

token := jwt.NewWithClaims(jwt.SigningMethodHS256, Claims{
    UserID:   user.ID,
    Username: user.Username,
    RegisteredClaims: jwt.RegisteredClaims{  // ✅ 新API
        ExpiresAt: jwt.NewNumericDate(time.Now().Add(24 * time.Hour)),  // 类型变更
        IssuedAt:  jwt.NewNumericDate(time.Now()),  // 类型变更
    },
})
```

**需要修改的文件**:

- [ ] `meta/backend/internal/api/auth_handler.go`
- [ ] `meta/backend/pkg/utils/jwt.go`

### 11.3 创建依赖版本检查脚本

创建 `scripts/dev/check-deps-version.sh` 脚本，用于定期检查各模块依赖版本一致性：

```bash
#!/bin/bash

set -e

echo "🔍 检查ADDP所有模块的依赖版本一致性..."
echo ""

# 定义需要检查的关键依赖及其期望版本
declare -A EXPECTED_VERSIONS=(
    ["github.com/gin-gonic/gin"]="v1.11.0"
    ["gorm.io/gorm"]="v1.31.1"
    ["github.com/golang-jwt/jwt/v5"]="v5.3.0"
    ["github.com/redis/go-redis/v9"]="v9.17.2"
    ["github.com/minio/minio-go/v7"]="v7.0.95"
    ["github.com/go-sql-driver/mysql"]="v1.9.3"
    ["github.com/hibiken/asynq"]="v0.25.1"
    ["github.com/jackc/pgx/v5"]="v5.7.2"
    ["github.com/twpayne/go-geom"]="v1.6.1"
)

# 模块列表
MODULES=(
    "common"
    "system/backend"
    "manager/backend"
    "meta/backend"
    "transfer/backend"
    "orchestrator/backend"
    "develop/backend"
    "gateway"
)

INCONSISTENT=0

# 检查每个模块
for module in "${MODULES[@]}"; do
    if [ ! -f "$module/go.mod" ]; then
        echo "⚠️  $module: go.mod not found"
        continue
    fi

    echo "📦 检查模块: $module"

    # 检查每个关键依赖
    for dep in "${!EXPECTED_VERSIONS[@]}"; do
        expected="${EXPECTED_VERSIONS[$dep]}"
        actual=$(grep "$dep" "$module/go.mod" | awk '{print $2}' | head -1)

        if [ -n "$actual" ]; then
            if [ "$actual" != "$expected" ]; then
                echo "  ❌ $dep: 期望 $expected, 实际 $actual"
                INCONSISTENT=1
            else
                echo "  ✅ $dep: $actual"
            fi
        fi
    done
    echo ""
done

if [ $INCONSISTENT -eq 0 ]; then
    echo "✨ 所有模块依赖版本一致！"
    exit 0
else
    echo "⚠️  发现版本不一致，请运行 bash scripts/dev/upgrade-deps.sh 统一版本"
    exit 1
fi
```
