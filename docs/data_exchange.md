体思路

  - 将空间数据导入/导出抽象成“数据交换子系统”，置于 transfer/ 或
    manager/ 中，对外提供统一 API，内部拆分为前端触发层、调度层、执行
    器层和日志监控层。
  - 统一使用作业流(Job)模型：一次导入/导出是一个 Job，对 Job 状态、进
    度、错误进行跟踪，便于在 manager/ 做数据治理与审计。
  - 设计可插拔的“适配器”接口实现对不同空间文件格式（Shapefile、
    GeoJSON、PostGIS 等）的读取/写入，集中管理在 common/geo 一类包
    下，避免重复实现。

  导入流程

  - 前端提交导入任务（文件元数据 + 参数）→ 后端校验 → 异步排队，避免
    大文件阻塞 API；可以用内置队列或轻量任务表 + Cron 驱动。
  - 导入执行器步骤化：Extract(读取文件) → Transform(投影/属性映射/质
    量检查) → Load(写入数据库)，中间产出可存储在临时表或缓存目录，方
    便回滚。
  - 数据质量控制：在 manager/ 侧配置规则（坐标系、字段完整性、空间拓
    扑检查），导入前跑快速校核，失败时反馈详细报告。
  - 元数据登记：导入成功后把数据集元信息、版本、来源记录到数据目录服
    务中，供后续检索。

  导出流程

  - API 接收导出请求（选择数据集、过滤条件、目标格式）→ 创建 Job → 查
    询数据库 → 流式写入目标文件，支持分页或分片以降低内存占用。
  - 对接缓存/临时存储：导出生成的空间文件放在临时对象存储或文件系统，
    前端通过一次性 URL/令牌下载，完成后清理。
  - 保持一致的安全策略：为导出设置权限、审计日志，以及敏感字段脱敏
    选项。

  通用设计考量

  - 日志与监控：每个 Job 写入细粒度日志（级别、时间、对象），并暴露
    Prometheus 指标或最少在日志中对接 ELK，便于排错。
  - 并发控制：根据数据库和文件系统能力设置导入/导出并发数；可在配置中
    心暴露参数。
  - 失败恢复：在 Job 模型中保存可重试点，支持用户手动重跑或自动重试；
    导入时保持幂等性（例如先写临时表、校验后再切换）。
  - UI 体验：前端增加进度条、校验报告预览、失败重试入口，复用 system/
    frontend 的状态管理模块。
