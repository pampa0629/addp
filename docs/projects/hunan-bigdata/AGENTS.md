# 湖南项目功能进展协作

本文件适用于本项目功能清单相关的开发、验收、进展汇报和表格维护，包括其他模块中的相关工作。仓库通用规则见根目录 [AGENTS.md](../../../AGENTS.md)。

- 功能清单为 `docs/projects/hunan-bigdata/functions-list.xlsx`，进展维护列为“建设功能清单”工作表的 M 列（`进展情况-codex`）和 N 列（`完成比例`）。
- 清单维护会话名称：**p0-hunan功能清单维护**；`threadId=01a148a9-8cca-7e02-ba2d-c8e21f379452`，`hostId=local`。该会话只负责核对实现与验证证据、维护表格及协调后续工作，不承担产品开发、修复或运行验收。用户已授权该会话将需要实施的事项发给对应负责会话，并要求其完成后按以下格式回报；具体实施由对应会话负责。
- 派发时说明对应清单行、具体任务、验收范围和回报接收会话；先核对已有进展，避免重复派发正在处理的事项或重跑仍有效的验收。涉及尚未确认的概念、架构或模块边界时，由实施会话按仓库规则先讨论确认。收到结果后由维护会话核对并即时保存到清单，不把任务已派发或 CI 排队记作功能完成。
- 开发会话完成与清单相关的功能、缺陷修复或验收后，必须按下列格式主动发送进展给上述维护会话，并继续向用户正常交付。用户已授权这类进展汇报，无需逐次确认；使用会话消息工具发送，不能仅在本会话最终答复中说明“待汇报”。
- 汇报前核对功能清单，使用 Excel 实际行号和功能名称定位，不混淆行号与 B 列序号；一项开发影响多行时逐项说明。暂时无法读取或匹配时，注明“行号待核对”，提供完整功能描述，不猜测行号、不因此阻断已授权开发与验证。
- 状态区分“已实现、部分实现、未实现”，同时说明验证层级。代码落地、测试通过、真实运行验收分别陈述；未运行、失败或跳过项不得计为通过，不用“已完成”掩盖仍有缺口的功能。
- M 列只概括完成程度、已具备能力和尚未完成或未验收的缺口，不累积排错、取证和 CI 排队流水；详细过程保留在已有证据记录中。
- N 列以数值百分比记录对该行功能范围的完成程度估算，显示为 `0%`–`100%`，通常以 5 个百分点为步长。结合功能描述、已实现范围和验证证据估算；明确未实现的功能记 0%，100% 仅用于该行要求已完成且验证充分的情况。只读调查、任务派发、CI 排队不提高比例；局部验证不外推整体完成，限定范围之外的扩展缺口不自动扣减原行已完成的要求。比例不是工时占比，也不替代 M 列的验收边界。
- 表格由维护会话统一更新。每次进展更新必须同步核对、维护对应行的 M、N 两列；比例判断未变时可保留原值，但须复核并在交付中说明。已有内容须先核对，新证据确认需要修订时再更新，不覆盖无关记录、其他列或其他工作表。每个单元格修改后立即保存，保留原有格式（N 列使用百分比格式）、打开密码和编辑密码；密码从同目录 `.env` 读取，不写入汇报或日志。

统一汇报格式（多项功能重复“对应功能”至“建议回填”部分）：

```text
接收会话：p0-hunan功能清单维护
来源会话：<开发会话完整名称、threadId>
汇报时间：<YYYY-MM-DD HH:mm，Asia/Shanghai>
对应功能：<Excel 行号、B 列序号、模块 / 功能名称；无法核对时注明>
当前状态：<已实现 / 部分实现 / 未实现>
本次实现：<具体行为、覆盖范围及边界>
剩余缺口：<尚未实现或未验收的内容；确无则写“无”>
验证结果：<实际执行命令、通过/失败/跳过/未运行、测试层级及覆盖范围>
证据位置：<关键代码/规范路径、提交 SHA、CI/验收报告链接；未提交时明确说明>
建议回填：<适合写入 M 列的简短进展，明确已具备能力和剩余缺口>
建议完成比例：<0%–100% 的估算及主要依据；由维护会话核对后写入 N 列>
```
