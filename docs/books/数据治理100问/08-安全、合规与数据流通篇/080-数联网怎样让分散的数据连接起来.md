# 080 数联网怎样让分散的数据连接起来？

## 一句话回答

> 数联网是在现有网络、算力和数据系统之上，通过统一身份、标识、目录、接入连接器和交付规则，把分散的数据资源、产品和服务组织成可以发现、授权连接和规范使用的数据流通网络。它不要求把全部数据集中起来，也不取消原有组织和权限边界；真正的互操作不仅需要网络和接口互通，还需要语义、质量和治理规则协同。

互联网让分散的计算机和服务能够相互连接，但数据能否跨组织流通，还要回答更多问题：有什么数据、由谁提供、怎样找到、谁能使用、如何交付、双方能否正确理解，以及使用过程怎样监管。

数联网试图为这些问题提供网络化、标准化的基础能力。

## 一、为什么还需要一张面向数据的网络

传统的数据流通通常采用点对点建设方式：

```text
系统A ──定制接口── 系统B
系统A ──文件任务── 系统C
系统B ──另一个接口── 系统D
系统C ──专线同步── 系统D
```

参与方较少时，这种方式简单直接；随着地区、行业和机构增加，容易出现：

- 每增加一个合作方都要重新对接；
- 同一数据在不同平台使用不同名称和描述；
- 身份和授权规则难以相互识别；
- 接口、文件和消息格式重复适配；
- 数据产品分散在多个目录中，难以发现；
- 调用、交付和使用记录无法贯通；
- 一个系统变化会影响多条定制链路。

数联网希望把大量定制连接逐步转变为基于共同规则的网络化连接：

```text
数据提供方 ─┐
行业平台 ───┼── 标准接入和流通网络 ── 数据使用方
城市节点 ───┤
企业节点 ───┘
```

各方仍需适配自己的本地系统，但跨主体部分尽量复用统一标识、身份、目录、接口和交付规则。

## 二、数联网是什么

“数联网”是我国数据基础设施建设语境中正在发展的技术路线之一。

《国家数据基础设施建设指引》提出，数联网由以下部分构成：

1. 数据流通接入终端；
2. 数据流通网络；
3. 数据流通服务平台。

其目标是提供一点接入、广泛连接、标准交付、安全可信、合规监管和开放兼容的数据流通服务。

从科普角度，可以把它理解为：

> 建立在现有通信网络和数据系统之上的数据流通网络，让数据资源、数据产品、数据服务以及参与主体能够按照共同规则连接起来。

相关架构、技术文件和标准仍在迭代，不同地区和行业也可能采用不同实现。因此，本问只讲相对稳定的功能框架，不把任何一个地方项目或厂商产品当作数联网的完整定义。

## 三、数联网连接的是什么

数联网并不只是连接数据库，它可能连接：

- 政府、企业、科研机构和其他数据主体；
- 城市、区域和行业数据节点；
- 数据资源和数据产品；
- 查询、核验、指标、地图和模型等数据服务；
- 文件、接口和实时数据流；
- 数据开发、联合计算和隐私保护计算能力；
- 支撑流通的目录、授权、合约和审计服务。

所以，数联网连接的是围绕数据流通形成的一组主体、资源、服务和能力，而不只是存放数据的机器。

## 四、数联网与互联网有什么不同

数联网需要使用互联网、专线、高速数据网络和其他通信设施，但不等于重新建设一张替代互联网的物理网络。

| 网络层次 | 主要回答的问题 |
| --- | --- |
| 互联网和通信网络 | 设备之间怎样建立连接并传输数据包 |
| 数联网 | 哪些数据资源和服务可以被发现、授权、交付和使用 |

互联网能够把请求送到一台服务器，却不自动知道：

- 服务器中的哪项数据可以对外提供；
- 请求者代表哪个机构和应用；
- 是否符合数据使用目的；
- 应返回原始数据、统计结果还是计算服务；
- 数据交付以后能否继续转交；
- 双方怎样理解字段、代码和指标口径。

数联网建立在通信连接之上，进一步提供面向数据流通的身份、目录、标识、授权、交付和治理能力。

## 五、可以用“局域网和广域网”理解吗

可以用这个类比入门：

- 数联网的“局域”部分，类似一个组织、城市或行业内部的数据连接；
- 数联网的“广域”部分，类似不同组织、地区和行业之间的数据互联互通。

但这种类比不能机械照搬。更准确的说法是“域内连接”和“跨域互联”。

### 1. 数据流通域不等于物理局域网

一个大型企业可能分布在多个城市，使用多个云平台和数据中心，却仍然属于同一组织和治理边界。反过来，两个租户即使部署在同一机房，也可能属于不同的数据流通域。

数据流通域主要依据：

- 组织和责任边界；
- 身份和信任体系；
- 数据治理规则；
- 授权和安全策略；
- 目录、标准和运营机制。

所以，它是逻辑和治理意义上的范围，不由地理距离和网络设备决定。

### 2. 域内连接类似组织内部的数据网络

在一个企业、城市或行业域内，可以统一：

- 主体和应用身份；
- 数据资源标识；
- 数据目录；
- 基础数据标准和语义；
- 数据服务入口；
- 授权、审计和运行规则。

组织内部的数据治理为这些能力提供基础，但二者不能画等号。数据治理还包括责任、标准、质量、安全和运营；数联网主要把治理成果转化为可连接、可访问和可交付的网络能力。

### 3. 跨域互联类似数据的广域网络

不同数据流通域之间通过共同规则互联：

```text
企业数据流通域 ──────┐
                      │
城市数据流通域 ── 跨域互联 ── 行业数据流通域
                      │
科研数据流通域 ──────┘
```

各方仍保留自己的数据、身份和治理自主权，只把经过登记和授权的资源、产品或服务提供给其他域。

跨域互联需要解决身份互信、目录协同、标识解析、接口兼容、授权衔接、语义映射和审计关联，远不只是把两张网络线路接通。

## 六、数联网是否要把数据集中到一个平台

数联网追求逻辑连接，不要求所有数据复制到统一数据库。

数据可以继续保存在：

- 来源部门的业务系统；
- 企业数据库和数据仓库；
- 对象存储和文件系统；
- 行业数据中心；
- 实时消息系统；
- 数据服务背后的原有平台；
- 可信数据空间和受控计算环境。

网络中可以流通：

- 数据目录和元数据；
- 查询和核验服务；
- 文件和批量数据；
- 实时数据流；
- 模型或算法服务；
- 计算任务和计算结果。

因此，数据可以留在原来的责任主体和存储环境中，在获得授权以后按需交付或计算。

但也不能反过来绝对宣称“数据永远不离开本地”。离线分析、大批量处理、网络隔离和应急使用等场景仍可能需要交付受控副本。是否移动数据，要根据用途、性能、安全和责任要求决定。

## 七、为什么需要数据标识

不同系统中可能存在大量名称相同的数据，例如“企业基本信息”“道路运行数据”和“设备状态”。仅靠名称无法稳定、准确地识别。

数联网需要让主体、节点、数据资源、数据产品或者服务具有可识别的标识，帮助系统回答：

- 这是什么对象；
- 由谁提供；
- 属于哪个版本；
- 当前是否有效；
- 到哪里查询目录信息；
- 应通过什么入口申请或访问；
- 与其他资源和服务有什么关系。

标识可以理解为数据对象在网络中的稳定编号，标识解析则根据编号找到相应的目录、服务入口或关联信息。

需要避免几个误解：

- 标识不等于物理存储地址；
- 获得标识不等于获得访问权限；
- 完成标识不等于证明数据权属；
- 数据更新后仍要处理版本和新旧关系；
- 同名数据不一定是同一对象，同一对象也可能存在多个产品形态。

## 八、标识、目录和发现怎样协同

标识回答“准确指向谁”，目录回答“它是什么、有什么特征”，发现回答“使用者怎样找到它”。

```text
数据资源或服务
      ↓
获得可识别标识
      ↓
形成标准目录描述
      ↓
目录在不同节点之间上报、同步或者查询
      ↓
使用者按主题、机构、地区和用途发现资源
      ↓
根据标识找到申请或访问入口
```

目录可以描述：

- 名称和业务含义；
- 数据提供方；
- 数据范围和更新频率；
- 质量状态和适用场景；
- 安全级别和申请条件；
- 服务方式、版本和有效状态。

全域目录不等于把全部数据集中存放，只是让分散的数据资源和服务能够跨节点被发现。

## 九、接入连接器发挥什么作用

接入连接器可以理解为参与方进入数联网的标准匝道。

一侧连接本地的：

- 数据库；
- 文件系统；
- 对象存储；
- 数据服务；
- 消息和实时流；
- 数据开发和计算平台。

另一侧按照共同规则与数据流通网络和其他节点连接。

连接器可能承担：

- 主体和应用身份认证；
- 本地数据资源和服务登记；
- 目录查询和标识解析；
- 请求、授权和使用策略传递；
- 文件、接口和数据流交付；
- 加密、完整性校验和异常处理；
- 日志和审计记录。

连接器不能自动理解所有本地系统。每个参与方仍需把自己的数据库、文件、接口和业务规则适配到连接器支持的形式。

## 十、怎样理解“一点接入”

“一点接入”主要表达：一个参与方按照共同规则完成接入后，可以在授权范围内发现和连接多个符合互联规则的节点与服务。

它降低的是重复对接成本，不是取消访问边界。

一点接入不等于：

- 自动获得全网数据；
- 所有目录中的数据都可以直接下载；
- 一个账号可以跨越全部组织和租户；
- 各地区和平台已经天然互信；
- 各种本地数据不再需要语义和接口适配。

“全域可见”通常应理解为资源或产品信息可以被发现，底层数据是否可用仍需身份、授权和场景判断。

## 十一、从发现到使用要经过哪些步骤

一次完整的数据访问可以简化为：

```text
发现数据资源或服务
        ↓
根据标识找到访问入口
        ↓
验证用户、机构和应用身份
        ↓
申请并判断用途、范围、期限和操作权限
        ↓
协商交付方式与使用规则
        ↓
交付数据、服务或计算结果
        ↓
记录调用、结果和后续处理
```

数据标识回答“访问什么”，主体身份回答“谁在访问”，应用身份回答“通过哪个程序访问”，授权规则决定“本次访问是否允许”。

第077问讨论的用户和应用身份，在数联网跨域访问中仍然适用，只是还要进一步处理不同组织之间的身份互信和授权衔接。

## 十二、数联网怎样完成数据交付

数联网需要适应不同的数据形态和使用方式，例如：

| 交付方式 | 典型用途 |
| --- | --- |
| API查询 | 核验、指标和按需查询 |
| 文件交付 | 批量和离线分析 |
| 数据流 | 实时事件和状态更新 |
| 数据同步 | 持续维护目标系统数据 |
| 模型或算法服务 | 返回预测、识别和评分结果 |
| 受控计算 | 数据不直接交付，只返回计算结果 |

标准交付需要对请求协议、数据格式、身份凭证、授权信息、传输状态、错误处理、完整性校验、日志和请求编号等形成共同约定。

标准不是要求所有数据变成同一种格式，而是让不同交付方式具有可以相互理解和适配的规则。

## 十三、互操作为什么不只是接口能够调用

互操作可以分为四个层次：

| 层次 | 主要问题 |
| --- | --- |
| 网络互通 | 节点之间能否建立连接并可靠传输 |
| 技术互操作 | 接口、协议、格式和连接器能否相互适配 |
| 语义互操作 | 双方是否用相同方式理解字段、代码、单位和口径 |
| 治理互操作 | 身份、授权、用途、责任、审计和退出规则能否衔接 |

例如，两个接口都返回JSON，只能说明格式相同。如果一个系统中的“销售额”含税，另一个不含税，数据仍然不能直接组合。

同样，两个节点能够相互认证，不代表使用目的、保存期限和转供条件已经达成一致。

因此：

> 网络和接口互通只是起点，语义和治理规则能够衔接，才是真正的数据互操作。

## 十四、数联网与数据目录有什么区别

数据目录主要解决：

- 有什么数据；
- 数据在哪里；
- 由谁负责；
- 具有什么特征；
- 怎样申请。

数联网还要解决：

- 不同目录怎样协同；
- 主体怎样可信接入；
- 标识怎样跨节点解析；
- 获得授权后怎样连接；
- 数据怎样规范交付；
- 流通过程怎样记录和监管。

可以把目录看作跨地区的商品索引；数联网还要提供道路、入口、身份、通行规则和交付机制。

## 十五、数联网与传统数据交换平台有什么区别

传统数据交换平台通常围绕已知参与方建立接口、文件和同步任务，擅长完成明确的点对点或中心辐射式交换。

数联网更强调：

- 多节点广泛连接；
- 跨目录发现；
- 统一身份和标识；
- 标准接入和交付；
- 不同平台之间互操作；
- 跨域流通过程监管。

数联网不会消灭传统交换任务。具体的数据同步、文件传递和服务调用仍需执行，只是跨地区、跨行业和多主体协作可以更多复用公共互联规则。

## 十六、数联网与数据服务有什么关系

数据服务是可以被调用的具体数据产品或能力，数联网帮助它：

- 获得可解析的标识；
- 进入可发现目录；
- 被其他节点查询和申请；
- 识别调用用户、机构和应用；
- 执行授权与调用策略；
- 跨平台规范交付；
- 形成可以关联的调用和审计记录。

一个数据服务不加入数联网也可以在组织内部运行。加入数联网的目标，是降低跨组织发现、接入和使用成本，而不是改变服务本身的业务含义。

## 十七、数联网为什么离不开数据治理

数联网能够连接数据，却不能自动把数据治理好。

如果源数据存在：

- 口径冲突；
- 代码不一致；
- 质量低下；
- 更新停止；
- 责任人不清；
- 权限和用途模糊；
- 服务版本混乱；

网络只会让问题传播得更快。

数据治理需要为数联网提供：

- 资源目录和元数据；
- 数据标准和语义映射；
- 质量状态；
- 分类分级；
- 责任主体；
- 授权和使用规则；
- 血缘和版本；
- 服务运营与退出机制。

数联网则把这些治理成果转化为可以跨节点执行的标识、目录、身份、策略和交付规则。

域内数联网可以依托一个组织已有的数据治理能力，但不能把“建设数联网”当作完成数据治理的替代说法。

## 十八、数联网与可信数据空间是什么关系

本问只作简要区分：

- 数联网更强调广泛连接、统一接入、跨域发现和标准交付；
- 可信数据空间更强调特定参与者之间的信任规则、数据使用控制和共同协作环境；
- 可信数据空间可以作为一个节点或者数据流通域接入数联网；
- 数联网也可以连接多个不同的可信数据空间和其他数据设施。

二者不是相互替代的两套封闭方案。第081问将继续讨论可信数据空间怎样在数联网连接基础上保障多方协作和受控使用。

## 十九、以制造业供应链为例

某制造企业需要与多家供应商、物流企业和金融机构协作。

### 1. 各参与方形成域内连接

制造企业在内部统一订单、产品、库存和供应商标识，治理相关数据并发布受控服务。供应商和物流企业也各自维护本地数据和责任边界。

### 2. 数据资源和服务接入网络

参与方通过连接器，把库存查询、订单状态、物流轨迹和资质核验等资源及服务登记到相应目录，并获得可识别标识。

### 3. 跨域发现和授权

制造企业发现物流状态服务后提出申请。物流企业确认调用应用、用途、订单范围和期限，只允许查询双方合作订单。

### 4. 标准交付和语义映射

数据通过接口交付。双方对产品编码、订单状态、时间和计量单位建立标准或映射，避免接口可调用但业务含义不一致。

### 5. 持续运营

请求、交付结果和异常进入审计。服务版本和目录发生变化时及时更新；合作终止后撤销调用权限并处理已有数据。

这个案例说明，域内治理形成可以提供的资源和服务，跨域数联网提供发现、连接和交付能力，双方的授权和语义规则决定数据能否真正被正确使用。

## 二十、常见误区

### 误区一：数联网就是新建一张通信专网

数联网使用现有通信网络，并在其上增加面向数据的身份、标识、目录、授权和交付能力。

### 误区二：建设数联网就是汇聚所有数据

数联网支持数据留在原责任主体，通过目录、服务和按需交付实现逻辑连接。

### 误区三：数据获得统一标识就证明权属

标识解决对象识别和解析，不能单独证明复杂的数据权利和责任关系。

### 误区四：数据能被发现就可以直接访问

目录可见不等于数据开放，仍需身份、授权、用途和服务策略判断。

### 误区五：接口格式统一就实现了互操作

真正的互操作还需要语义、质量、身份和治理规则能够衔接。

### 误区六：一点接入就是全网数据无条件可用

一点接入降低重复对接成本，不会取消组织、租户和数据授权边界。

### 误区七：数联网会取代所有数据交换平台

交换任务仍负责具体传输和同步，数联网主要提供跨平台、跨区域和多主体互联的公共规则与能力。

### 误区八：建好数联网就不再需要数据治理

没有清晰的目录、标准、质量、责任和安全规则，网络只会更快传播数据问题。

## 小结

数联网是在现有网络、算力和数据系统之上建立的数据流通网络。它通过身份、标识、目录、连接器和标准交付，让分散的数据资源、产品、服务和参与主体能够被发现并在授权范围内连接起来。

可以用互联网的局域网和广域网帮助理解，但更准确的说法是域内连接与跨域互联：组织、城市和行业可以形成各自的数据流通域，再通过共同规则相互连接。数据流通域由组织、信任和治理边界决定，不等于物理局域网。

数联网不要求把所有数据集中到一个平台，也不意味着一点接入后可以无条件使用全网数据。网络和接口互通只是基础，数据标准、业务语义、质量、授权、责任和退出机制能够协同，才是真正的数据互操作。
