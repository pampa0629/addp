# 082 数据跨境流动怎样兼顾业务需要与安全合规？

## 一句话回答

> 数据跨境流动不是简单判断“能不能传”，而是先识别谁把什么数据、因为什么目的、以什么方式提供给哪个境外接收方，再根据数据类型、主体身份、数量规模和业务场景选择适用的合规路径，并通过最小必要、技术保护、合同约束、审计和持续监测控制全过程风险。数据治理的作用，是让组织持续掌握哪些数据正在通过什么路径流向哪里，并让确有必要的数据安全、合规地发挥价值。

跨国贸易、运输、研发、生产、客户服务和人力资源管理都可能需要数据跨境流动。完全切断数据流动，会影响正常经营和国际协作；不辨数据类型和用途就直接传输，又可能损害个人权益、商业利益、公共利益和国家安全。

因此，数据跨境治理要兼顾两件事：促进必要的数据依法有序流动，防止不必要、不透明和失去控制的数据出境。

本问从数据治理角度介绍基本判断框架，不代替针对具体业务、行业和时点的专业法律意见。跨境规则具有较强时效性，涉及具体项目时仍需核对现行法律、政策和主管部门要求。

## 一、为什么数据跨境不是简单的“禁止或者放行”

同样是把数据提供给境外，风险可能完全不同：

- 一份不含个人信息和重要数据的产品目录；
- 一批客户姓名、联系方式和交易记录；
- 大规模人脸、健康或者金融账户信息；
- 可能影响公共安全和经济运行的重要数据；
- 一项只返回核验结果、不交付原始数据的服务。

如果把所有数据都当成同一等级，可能出现两个极端：

- 为了避免风险，把正常的国际贸易和生产协作全部阻断；
- 为了追求便利，只要加密或者签订商业合同就直接出境。

正确做法是先识别场景和数据，再匹配规则、控制措施与业务价值。

## 二、什么情况可能构成数据出境

数据出境不只是把文件复制到境外服务器，还可能包括：

- 向境外总部、子公司、供应商或者客户传输数据；
- 使用部署在境外的云服务、SaaS、分析平台或者人工智能服务；
- 把数据库备份、应用日志和监控信息保存到境外；
- 通过接口向境外系统持续提供数据；
- 允许境外人员远程查询、调取、下载或者导出境内系统中的数据；
- 境外技术支持人员远程进入境内系统处理故障；
- 跨国集团统一开展人力资源、财务、客户和供应链管理。

即使数据仍存储在境内，只要数据访问或者调用行为发生在境外，也可能属于数据出境。

反过来，境外机构的工作人员身处境内访问境内数据，而且数据没有传输到境外，不会仅因其所属机构位于境外就当然构成数据出境。

是否属于同一个集团、是否使用内部账号以及是否收费，都不能单独决定是否属于数据出境活动。需要看数据在哪里被访问和处理、接收方是谁以及实际流向哪里。

## 三、首先要建立跨境数据地图

组织在判断合规路径以前，应先持续掌握：

| 需要盘点的内容 | 主要问题 |
| --- | --- |
| 境内责任主体 | 谁决定出境目的和方式，谁负责批准和管理 |
| 境外接收方 | 谁接收数据，位于哪个国家或地区，是否继续转交 |
| 数据来源 | 数据来自哪些业务、系统、数据库、文件和接口 |
| 数据内容 | 包含哪些字段、人员、时间范围和敏感内容 |
| 数量规模 | 涉及多少人、多少记录，以什么频率持续出境 |
| 业务目的 | 为什么必须跨境，境外接收方实际承担什么工作 |
| 出境方式 | 文件、接口、数据库同步、远程访问还是系统托管 |
| 境外处理 | 怎样使用、保存多久、是否与其他数据结合 |
| 安全控制 | 怎样授权、加密、审计、撤销和处理安全事件 |

这张地图可以由数据目录、系统清单、接口目录、数据流向、处理活动记录和跨境台账共同构成。它不是为了申报而临时制作的一张表，而应随系统和业务变化持续更新。

如果组织不知道境外SaaS自动收集了哪些日志，也不知道海外总部能访问哪些境内数据库，就无法可靠判断数据类型、数量和适用路径。

## 四、跨境判断可以分为哪三个层次

可以按照以下顺序判断：

```text
第一步：这是不是数据出境活动
              ↓
第二步：涉及什么数据、主体和业务场景
              ↓
第三步：适用便利情形、安全评估、标准合同、认证还是特别规则
              ↓
无论适用哪条路径，继续落实必要性、安全保护和持续治理
```

这三个层次不能颠倒。

例如，不能只因为数据量没有达到安全评估门槛，就不再判断其中是否包含重要数据；也不能因为某个场景免予安全评估、标准合同或者认证，就认为所有安全和个人信息保护责任都被免除。

## 五、需要区分哪些数据类型

跨境治理至少需要区分：

1. **一般业务数据**：不包含个人信息、重要数据或者其他受特别制度管理的数据；
2. **个人信息**：与已识别或者可识别自然人有关的信息；
3. **敏感个人信息**：一旦泄露或者非法使用，容易侵害人格尊严或者危害人身、财产安全的个人信息；
4. **重要数据**：一旦遭到篡改、破坏、泄露或者非法获取、非法利用，可能直接危害国家安全、经济运行、社会稳定、公共健康和安全的数据；
5. **核心数据、国家秘密、工作秘密及其他特别数据**：按照相应法律和专门制度处理。

还要避免两个常见混淆：

- 企业内部所称“高度敏感数据”，不一定属于法律概念中的敏感个人信息，但仍可能属于商业秘密、重要数据或者其他应当严格保护的数据；
- 个人信息经过加密、编码或者去标识化后，通常仍然属于个人信息，只有达到无法识别且不能复原的匿名化效果，才可能不再作为个人信息处理。

## 六、一般业务数据能否正常跨境

国际贸易、跨境运输、学术合作、跨国生产制造和市场营销等活动中收集和产生的数据，如果不包含个人信息或者重要数据，按照当前国家层面一般规则，可以免予申报数据出境安全评估、订立个人信息出境标准合同或者通过个人信息出境认证。

这有利于正常经营数据依法有序流动。例如，产品型号、公开技术参数、普通货物状态和不关联个人的汇总信息，可以根据实际内容判断。

但不能只看业务名称。生产订单中可能附带联系人和手机号，车辆数据可能包含精确位置和车外人脸，普通设备日志也可能记录用户账号、IP地址和访问行为。只有完成字段级盘点，才能确认是否真的不包含个人信息或者重要数据。

## 七、个人信息出境需要关注什么

个人信息出境不只是选择一种程序，还可能涉及：

- 是否具有明确、合理的处理目的；
- 是否与该目的直接相关并符合最小必要；
- 是否依法履行出境告知义务；
- 依法需要时是否取得个人单独同意；
- 是否开展个人信息保护影响评估；
- 境外接收方能否履行保护义务；
- 个人怎样向境外接收方行使查阅、更正、删除等权利；
- 是否符合安全评估、标准合同、认证或者便利情形的适用条件。

向境外提供敏感个人信息时，还要进一步说明其必要性和对个人权益的影响，并采取更严格的保护措施。

需要特别注意：个人信息数量不是唯一判断因素。少量敏感个人信息也可能带来较高风险，少量个人信息出境即使免予三种主要程序，也不等于可以忽略告知、必要性和安全保护。

## 八、个人同意是不是万能通行证

不是。

取得个人同意，不能代替应当开展的数据出境安全评估、标准合同、认证或者个人信息保护影响评估，也不能把与业务无关的出境变成必要处理。

例如，境外总部根本不参与境内分公司的招聘决策，却要求上传全部求职者简历。即使求职者勾选了同意，也不能因此忽略目的是否合理、总部是否真正需要以及字段范围是否最小。

同时，也不宜简单表述为“所有个人信息出境都必须以同意为唯一依据”。按照当前官方解释，个人信息处理活动符合个人信息保护法规定的其他合法处理情形时，可以不以个人同意为处理依据，但仍应履行相应的出境告知等义务。

所以，应分别判断：处理个人信息的合法基础是什么，跨境提供还需要履行哪些特别义务。

## 九、重要数据怎样识别和管理

重要数据与企业自行划分的“重要资料”不是同一个概念。

国家建立数据分类分级保护制度，各地区、部门和行业领域可以制定重要数据目录或者识别规则。组织需要：

- 关注适用的地区、行业和领域目录；
- 按照相关规定识别、申报重要数据；
- 接到主管部门告知后及时纳入重点保护；
- 建立重要数据处理和出境变更的持续监测机制。

按照当前规则，未被相关部门、地区告知或者公开发布为重要数据的，数据处理者不需要自行把相关数据作为重要数据申报数据出境安全评估。

这不等于组织可以不盘点数据或者故意回避识别。只有知道自己处理哪些数据、达到什么精度和规模、可能造成什么影响，才能及时响应新的目录、行业规则和主管部门要求。

确需向境外提供重要数据的，应当依法通过数据出境安全评估，不能改用个人信息出境标准合同或者认证规避。

## 十、哪些场景可能适用便利安排

当前国家层面规则明确了若干便利情形，例如：

- 国际贸易、跨境运输、学术合作、跨国生产制造和市场营销中产生的数据，不包含个人信息或者重要数据；
- 境外收集和产生的个人信息传入境内处理后再向境外提供，处理过程中没有引入境内个人信息或者重要数据；
- 为订立或者履行个人作为一方当事人的合同，确需向境外提供个人信息；
- 依法开展跨境人力资源管理，确需提供员工个人信息；
- 紧急情况下为保护自然人的生命健康和财产安全，确需提供个人信息；
- 非关键信息基础设施运营者当年累计提供的个人信息符合相应数量条件；
- 自由贸易试验区负面清单以外的数据。

这些情形需要同时满足相应条件，不能只抓住一个场景名称。

例如，“跨国人力资源管理”并不意味着所有员工信息都可以出境。仍要判断劳动规则基础、实际管理需要、人员范围、数据字段和保存期限。

免予安全评估、标准合同或者认证，也只是免予特定程序；数据安全、个人信息保护、合同监督和事件处置等适用义务仍需履行。

## 十一、安全评估、标准合同和认证怎样区分

截至2026年8月，国家层面的一般适用关系可以简化如下：

| 情形 | 一般适用路径 |
| --- | --- |
| 关键信息基础设施运营者向境外提供个人信息或者重要数据 | 一般应开展数据出境安全评估；符合明确便利情形的，从其规定 |
| 非关键信息基础设施运营者向境外提供重要数据 | 数据出境安全评估 |
| 非关键信息基础设施运营者自当年1月1日起累计提供100万人以上个人信息，或者1万人以上敏感个人信息 | 数据出境安全评估 |
| 非关键信息基础设施运营者自当年1月1日起累计提供10万人以上、不满100万人个人信息，或者提供敏感个人信息且累计不满1万人，并且不包含重要数据 | 个人信息出境标准合同或者个人信息出境认证 |
| 非关键信息基础设施运营者自当年1月1日起累计提供不满10万人个人信息，且不涉及敏感个人信息或者重要数据 | 可以免予上述三种程序，仍需履行其他适用义务 |
| 符合明确便利情形或者自由贸易试验区相应安排 | 可以免予上述程序，仍需履行其他适用义务 |

这张表用于帮助理解一般框架，不代替完整适用判断。具体项目还要结合便利情形、重要数据、关键信息基础设施、行业规则、自由贸易试验区安排和最新政策核对。

三种路径也不能理解成自由选择的三个套餐：

- 达到安全评估条件的，不得通过标准合同或者认证规避；
- 标准合同是按照规定订立并备案的个人信息出境合同，不是普通商业合同；
- 认证需要由符合条件的专业认证机构开展，并接受持续监督；
- 不得通过拆分系统、主体、接收方或者批次规避数量门槛；
- 当年累计数量跨越适用门槛后，需要及时调整合规路径。

个人信息出境认证证书以及数据出境安全评估结果都有相应有效期和持续条件，不是一次完成以后永久有效。

## 十二、为什么要先判断出境的必要性

不能因为境外总部、境外平台或者供应商“可能用得上”，就把整张数据表全部传出。

可以依次追问：

- 境外接收方是否真正参与这项业务；
- 能否在境内完成计算，只提供必要结果；
- 能否去掉姓名、手机号、证件号码等无关字段；
- 能否用统计结果代替原始明细；
- 能否缩短时间范围和保存期限；
- 能否只提供相关订单、项目或者客户的数据；
- 能否用受控接口代替批量文件；
- 能否在境内完成汇总、脱敏或者匿名化。

最小必要不是简单减少几列数据，而是从业务目标反推最少的人员、字段、记录、频率、接收方和保存时间。

## 十三、境外接收方需要承担什么责任

境内数据处理者不能在数据发出以后就结束责任管理。还要了解和约束境外接收方：

- 只能按照约定目的和范围处理；
- 采取与风险相适应的安全措施；
- 不得擅自转交其他机构；
- 处理个人权利请求；
- 发生安全事件时及时通知并处置；
- 保存期限届满后删除或者匿名化；
- 接受必要的检查、审计和监督；
- 所在国家或地区法律和安全环境变化时及时协商。

如果境外接收方还会把数据交给其他国家、云服务商或者关联公司，就要继续识别后续接收方、流向和责任，不能把第一次出境当成数据流动的终点。

## 十四、可以采取哪些技术和管理措施

跨境安全措施可以包括：

- 出境前删除无关字段，开展必要的汇总、脱敏或者匿名化；
- 为境外应用建立独立身份，不共用境内人员账号；
- 通过受控接口提供数据，限制批量查询和下载；
- 对传输和存储进行加密并合理管理密钥；
- 限制用户、应用、用途、字段、频率和时间范围；
- 记录查询、下载、导出和异常访问行为；
- 对导出文件添加标识或者水印；
- 监测数据继续转交和异常流向；
- 管理日志、缓存、备份和临时文件；
- 到期撤销访问并验证删除；
- 建立误传、泄露和异常访问的应急机制。

技术措施能够降低风险，不能替代适用的法律程序。使用加密专线、可信数据空间或者隐私计算，并不自动获得数据出境豁免。

## 十五、跨境合规为什么不是一次性工作

以下变化可能影响原来的判断和合规安排：

- 数据用途发生变化；
- 数据字段、种类、敏感程度或者数量增加；
- 新增境外接收方或者继续转交方；
- 数据保存国家、地区或者期限改变；
- 云平台、接口和系统架构变化；
- 数据处理者或者境外接收方的实际控制权发生变化；
- 接收方所在地法律和安全环境变化；
- 当年累计数量跨过新的适用门槛；
- 新的重要数据目录或者行业规则发布；
- 发生数据安全事件。

因此，应把跨境数据台账与数据目录、分类分级、系统变更、接口管理、供应商管理、合同管理和安全监测联动起来。

已经通过安全评估、完成标准合同备案或者取得认证，也要持续确认实际用途、接收方、数据范围和数量仍与原安排一致。

## 十六、为什么还要关注行业和区域特别规则

国家层面一般规则之外，一些领域还可能受到专门制度约束，例如：

- 汽车和车联网数据；
- 金融、医疗健康和电信数据；
- 人类遗传资源信息；
- 测绘地理信息和高精度位置数据；
- 国家秘密、工作秘密和出口管制相关信息；
- 自由贸易试验区负面清单；
- 粤港澳大湾区等区域性跨境安排。

这些规则可能进一步明确重要数据范围、适用条件、接收区域和办理方式。

书稿不逐项展开，因为行业和区域规则变化较快。组织应先确定自己属于什么行业、位于什么区域、处理什么数据，再核对相应规定，不能只套用一张国家层面数量表。

## 十七、数联网和可信数据空间能否解决跨境合规

数联网可以帮助数据被标识、发现、连接和标准交付；可信数据空间可以通过成员规则、数字合约、使用控制、受控计算和履约证据降低多方协作风险。

这些能力可以支持跨境治理，例如：

- 记录数据来源和流向；
- 把用途、期限和接收方转化为使用策略；
- 采用数据侧计算，减少原始数据出境；
- 留存申请、交付、计算和删除证据；
- 连接境内外受控服务。

但它们仍然是实现和治理手段，不能替代法律上的数据类型判断和适用程序。

一项数据即使通过可信数据空间交付，只要构成数据出境，仍要判断是否涉及个人信息、重要数据以及安全评估、标准合同、认证或者其他规则。

## 十八、以跨国制造质量分析为例

某制造企业计划把境内工厂的生产、订单、客户和设备数据全部上传到境外总部，用于全球质量分析。

### 1. 先明确业务目的

总部实际需要分析零部件批次、缺陷类型和检测结果，并不参与境内客户管理和员工管理。

### 2. 盘点并缩小范围

企业去除客户姓名、联系人、员工信息和无关设备日志，只保留产品型号、零部件批次、生产时间、检测指标和缺陷代码。

### 3. 判断数据类型和路径

企业继续核查剩余数据是否包含个人信息、重要数据或者行业特别数据，并根据主体、数量、业务场景和适用规则确定跨境路径。

### 4. 受控提供

境外总部通过独立应用身份调用接口，只能查询批准的工厂、产品和时间范围，不允许下载全部生产明细或者转交其他关联公司。

### 5. 持续治理

总部只保存约定期限，并把质量分析结果反馈给境内工厂。新增数据字段、接收方、国家或者分析用途时，企业重新判断必要性和适用路径。

这个案例说明，跨境治理不是简单地禁止传输，而是通过数据治理把不必要的数据留在境内，让真正需要的数据以受控方式支持全球业务。

## 十九、常见误区

### 误区一：服务器在境内，就一定不存在数据出境

境外人员或者系统远程查询、调取、下载境内数据，也可能构成数据出境。

### 误区二：同一跨国集团内部传输不算跨境

集团内部仍存在不同境内外主体和处理地点，需要判断实际数据流向和适用规则。

### 误区三：数据加密或者去标识化后就不再受监管

加密和去标识化可以降低风险，但可恢复、可关联个人的数据通常仍然属于个人信息。

### 误区四：未达到安全评估门槛就什么都不用做

仍可能需要告知、个人信息保护影响评估、标准合同、认证、安全措施或者其他行业要求。

### 误区五：获得个人同意就可以任意出境

同意不能代替必要性、最小范围、安全评估和其他适用义务。

### 误区六：标准合同就是一份普通商业合同

个人信息出境标准合同具有规定的文本、适用条件和备案要求，不能用普通采购或者服务合同代替。

### 误区七：通过一次评估、备案或者认证便可永久使用

用途、数据范围、数量、接收方和保存期限变化，都可能要求重新判断或者调整安排。

### 误区八：跨境合规就是把所有数据都留在境内

治理目标是在安全边界内促进必要数据依法有序流动，而不是脱离业务需要一律阻断。

## 小结

数据跨境流动服务于贸易、研发、生产、管理和公共合作等真实需求，但不能只在传输发生时临时判断。组织需要建立持续更新的跨境数据地图，掌握境内责任主体、境外接收方、数据内容、数量、用途、系统路径和后续流向。

判断时，应先确认是否构成数据出境，再区分一般业务数据、个人信息、敏感个人信息、重要数据和特别数据，最后根据主体、数量、场景和现行规则确定便利安排、安全评估、标准合同、认证或者其他适用路径。免予特定程序不等于免除必要性、安全和个人信息保护责任。

真正有效的跨境治理，要把最小必要、接收方约束、技术保护、审计、变更管理和退出处置贯穿全过程。这样既能避免数据无序流出，也能让确有必要的数据安全、合规地支持跨境业务和价值创造。
