074 个人信息与敏感个人信息应如何识别和保护？

一句话回答

个人信息识别的关键，是判断数据能否直接或结合其他信息关联到自然人；敏感个人信息是其中一旦泄露或非法使用，容易严重侵害人格尊严或者危害人身、财产安全的部分。保护个人信息不能只靠“取得同意”或“做一次脱敏”，而要从处理目的、合法依据、最小必要、个人权利和全生命周期安全等方面共同落实。

第073问讨论了适用于各类数据的分类分级。本问聚焦个人信息，是因为个人不仅是需要保护的对象，也是对其个人信息享有知情、决定、限制、拒绝、查阅、更正和删除等权利的主体。

一、个人信息与敏感个人信息是什么关系

二者是包含关系：

个人信息
└── 敏感个人信息

可以把它们理解为：

  • 个人信息回答“这项信息是否与可识别的自然人有关”；
  • 敏感个人信息进一步回答“泄露或非法使用是否容易给这个人造成严重伤害”。

因此：

  • 所有敏感个人信息都是个人信息；
  • 不是所有个人信息都是敏感个人信息；
  • 普通个人信息同样受到保护，不能因为“不敏感”就随意处理；
  • 敏感个人信息需要更加严格的处理条件和保护措施。

《个人信息保护法》规定，个人信息是以电子或者其他方式记录的、与已识别或者可识别的自然人有关的各种信息，不包括匿名化处理后的信息。敏感个人信息则是一旦泄露或者非法使用，容易导致自然人人格尊严受到侵害或者人身、财产安全受到危害的个人信息。《中华人民共和国个人信息保护法》

二、怎样判断一项数据是不是个人信息

识别个人信息不能只扫描姓名、身份证号码和手机号，可以按照三个步骤判断。

1. 数据是否与自然人有关

常见个人信息包括：

  • 身份、联系方式和家庭信息；
  • 账号、设备标识和网络活动记录；
  • 交易、信用、教育和工作经历；
  • 照片、声音、视频和生物特征；
  • 位置、轨迹和出行记录；
  • 健康、诊疗和用药信息；
  • 偏好、评分、标签和算法推断结果。

个人信息不只来自个人主动填写，也可能由业务系统、设备、算法和关联分析产生。

2. 数据能否直接识别自然人

姓名、身份证号码、人脸、手机号等通常具有较强的直接识别能力。看到这些信息时，比较容易判断它们属于个人信息。

3. 数据能否结合其他信息识别或关联自然人

客户编号、设备标识、订单号和位置记录单独看未必写明姓名，但与账号表、地址表、日志或其他数据结合后，可能定位到具体个人。

因此：

判断个人信息不能只看字段名称，还要看数据内容、关联能力和实际使用环境。

一个字段在原系统中可能只是内部编号，进入统一数据环境并与其他数据关联后，就可能成为能够识别个人的线索。

三、算法生成的标签和画像是不是个人信息

如果标签、评分、偏好或画像能够关联到已识别或者可识别的自然人，通常仍应按个人信息处理。

例如：

  • “喜欢户外运动”关联到某个匿名群体，且无法定位个人时，未必是个人信息；
  • 同一标签写入具体客户账号，用于向该客户推荐产品时，就与个人建立了联系；
  • 信用评分、风险标签和健康预测即使不是由个人直接提供，也可能影响个人权益。

数据治理不能只保护来源字段，还要识别加工、关联和算法推断形成的个人信息及其用途。

四、怎样识别敏感个人信息

《个人信息保护法》列举了生物识别、宗教信仰、特定身份、医疗健康、金融账户、行踪轨迹等信息，以及不满十四周岁未成年人的个人信息。《中华人民共和国个人信息保护法》

实际工作不应只机械匹配这份列举，而应结合“信息类型、可能后果和处理场景”综合判断。

1. 信息是否属于典型敏感类型

例如医疗记录、金融账户、人脸特征、精确行踪和未成年人信息。

2. 泄露或非法使用会造成什么后果

重点判断是否容易导致：

  • 人格尊严受到侵害；
  • 身份冒用、诈骗或财产损失；
  • 人身安全受到威胁；
  • 歧视、不公平待遇或社会评价受损；
  • 行踪暴露或持续监控；
  • 未成年人权益受到伤害。

3. 数据组合是否放大风险

姓名本身可能只是普通个人信息，但姓名、证件号码、银行卡、位置和健康记录汇聚以后，整体风险会显著提高。

4. 使用场景是否改变影响

同一信息用于完成订单、公开展示、精准营销、信用评价和自动化决策，给个人带来的影响可能不同。

因此，敏感个人信息识别不能只维护一张固定字段字典，还要结合数量、组合、用途和实际影响持续判断。

五、敏感个人信息与其他高敏感数据有什么区别

敏感个人信息是明确的法律概念，保护重点是自然人的人格尊严、人身和财产安全。组织内部所说的“高敏感数据”则通常是风险管理标签，范围可能更广。

数据类型 主要保护的利益 是否必然属于个人信息
敏感个人信息 自然人的人格尊严、人身和财产安全 是
重要数据、核心数据 国家安全、经济运行、社会稳定、公共健康和安全等 不一定
商业秘密和保密商务信息 企业竞争利益和商业权益 不一定
核心算法、密钥和安全配置 技术、系统和访问安全 通常不是

一份数据可以同时具有多个身份。例如，大规模医疗健康数据必然涉及敏感个人信息，也可能在满足相应目录、规模和影响条件时涉及其他专门管理要求；但敏感个人信息不会自动等于重要数据，企业内部的“高敏感”标签也不能代替法定概念。

六、删除姓名以后还属于个人信息吗

不一定。需要区分去标识化与匿名化。

1. 去标识化

删除姓名、替换证件号码或者改用客户编号后，如果组织仍能借助映射表、账号体系或其他数据重新关联到个人，数据仍然属于个人信息。

2. 匿名化

只有经过处理后无法识别特定自然人且不能复原，才属于法律意义上的匿名化。匿名化后的信息不再属于个人信息。

两者的关键区别是能否重新识别：

处理方式 能否借助额外信息重新识别 是否仍按个人信息管理
去标识化 通常仍有可能 是
匿名化 无法识别且不能复原 否

是否真正达到匿名化，需要结合数据组合、外部可获得信息和重新识别能力判断。具体脱敏方法将在第076问讨论，本问只需要记住：看不到姓名不等于不再是个人信息。

七、保护个人信息首先要明确什么

每一项个人信息处理活动，都应当先回答：

  1. 为什么需要处理这些个人信息；
  2. 依据什么可以处理；
  3. 哪些信息对实现目的确有必要；
  4. 将由谁以什么方式使用；
  5. 是否会提供给其他组织或者公开；
  6. 保存多长时间，目的完成后怎样处置；
  7. 怎样让个人了解处理情况并行使权利；
  8. 如果发生泄露、篡改或丢失，怎样减少影响。

个人信息保护不能从“我们已经取得数据”开始，而应从“我们为什么可以处理”开始。

八、同意是不是处理个人信息的唯一依据

不是。

《个人信息保护法》规定了多种处理个人信息的情形，包括取得个人同意，为订立或履行个人作为一方当事人的合同所必需，依法开展人力资源管理所必需，履行法定职责或法定义务所必需，紧急情况下保护生命健康和财产安全，以及在合理范围内处理合法公开信息等。《中华人民共和国个人信息保护法》

这意味着：

  • 不能把“所有处理都必须取得同意”当作唯一规则；
  • 也不能把一次笼统同意当作所有后续处理的通行证；
  • 每项处理活动都应明确适用依据；
  • 以同意为依据时，同意应当在充分知情前提下自愿、明确作出；
  • 处理目的、方式或个人信息种类发生实质变化时，需要重新判断依据并依法履行相应程序。

例如，企业为履行订单处理收货地址，与把地址用于新的营销画像，是两项目的不同的处理活动，不能因为前者合理就自动认为后者也合理。

九、最小必要不只是“少收几个字段”

《个人信息保护法》要求处理目的明确、合理，与处理目的直接相关，并采取对个人权益影响最小的方式；收集个人信息应限于实现处理目的的最小范围，不得过度收集。国家统计局《中华人民共和国个人信息保护法》

最小必要至少包括：

  • 数据范围最小：只处理实现目的确实需要的数据；
  • 人员范围最小：只允许确有工作需要的人员访问；
  • 使用范围最小：不能把履约数据默认用于所有分析和营销；
  • 共享范围最小：只向确有必要的接收方提供必要内容；
  • 保存期限最小：目的完成后不应无限期保留。

即使一项数据可以合法取得，也不代表所有部门、应用、算法和合作方都可以使用。

十、告知、同意和单独同意有什么不同

1. 告知

组织在处理个人信息前，通常需要以显著、清晰易懂的方式，说明处理者、处理目的、方式、信息种类、保存期限以及个人行使权利的方法。

2. 同意

当处理活动以个人同意为依据时，个人应当在充分知情的前提下自愿、明确作出决定，并能够依法撤回同意。

3. 单独同意

处理敏感个人信息以及法律规定的特定活动时，需要个人针对特定处理活动单独作出明确决定，不能把它隐藏在一份笼统授权中。

告知不等于同意，同意也不能替代目的明确和最小必要。即使取得了单独同意，组织仍要证明处理敏感个人信息具有特定目的和充分必要性，并采取严格保护措施。

十一、敏感个人信息为什么需要更严格保护

处理敏感个人信息，除遵守一般个人信息保护要求外，还应重点关注：

  • 是否具有特定、明确的处理目的；
  • 是否具有充分必要性；
  • 是否采取与风险相匹配的严格保护措施；
  • 是否依法取得单独同意或者履行其他适用程序；
  • 是否告知处理的必要性及其对个人权益的影响；
  • 是否事前开展个人信息保护影响评估并记录处理情况；
  • 是否对接触人员、使用场景、提供对象和保存期限进行更严格限制。

《个人信息保护法》将处理敏感个人信息、利用个人信息进行自动化决策、委托处理、向其他处理者提供、公开、出境以及其他对个人权益有重大影响的活动，列为需要事前开展个人信息保护影响评估的情形。《中华人民共和国个人信息保护法》

更严格保护不等于一律禁止处理，而是要求目的更清楚、必要性更充分、影响评估更审慎、控制更严格。

十二、个人享有哪些与处理活动相关的权利

个人信息保护与一般数据安全的重要区别之一，是个人可以依法对处理活动行使权利。

常见权利包括：

  • 知晓个人信息怎样被处理；
  • 对处理活动作出决定；
  • 限制或拒绝处理；
  • 查阅和复制个人信息；
  • 更正、补充不准确或不完整的信息；
  • 在符合法定条件时要求删除；
  • 在以同意为依据时撤回同意；
  • 要求组织说明处理规则。

组织不能只在隐私政策中罗列这些权利，还需要提供便捷的申请渠道，并能够定位相关数据、核实身份、处理请求和反馈结果。

这对数据治理提出了直接要求：组织应当知道个人信息在哪里、由哪些任务和服务使用、复制到了哪些环境、形成了哪些派生结果，以及哪些数据已经超过保存期限。

十三、个人信息怎样纳入全生命周期治理

阶段 主要关注点
收集 目的、处理依据、告知和必要范围
传输与存储 访问边界、保存期限、备份和副本
开发测试 是否必须使用真实个人信息，能否使用处理后的数据
使用分析 是否超出原目的，算法推断是否影响个人权益
委托处理 受托方的目的、范围、责任和数据处置
对外提供 接收方、用途、必要性以及相应程序
公开 是否确有必要，是否会形成难以控制的传播
归档删除 主数据、缓存、临时文件和副本怎样协同处置
事件处置 及时补救、判断影响并依法履行通知报告义务

第075问和第076问将具体讨论隔离、授权、脱敏、加密、水印和审计。本问只强调：这些措施必须服从明确的处理目的和个人权益保护要求。

十四、组织怎样持续治理个人信息

1. 建立处理活动清单

不能只列有哪些敏感字段，还要记录由谁为了什么目的，以什么依据、方式和期限处理哪些个人信息。

2. 标明数据来源和流向

记录个人信息来自哪里，进入哪些系统、任务、服务、终端和外部机构，形成哪些派生数据。

3. 识别高风险活动

重点识别敏感个人信息、未成年人信息、自动化决策、委托处理、对外提供、公开和跨境等活动。

4. 明确共同责任

业务人员说明目的与必要范围，法务合规人员判断处理依据，数据与技术人员落实管理措施，安全人员评估风险并监督执行。

5. 支持个人行使权利

建立查阅、复制、更正、删除和撤回同意等请求的受理、核验、处理与反馈流程。

6. 定期复核并处置历史数据

复核处理目的、权限、保存期限、第三方和历史副本，业务结束或条件变化后及时调整。

一份“个人信息处理活动清单”通常比单纯的字段清单更重要，因为同一份数据可能被多个应用以不同目的处理，产生不同风险和责任。

十五、案例：订单履约与客户分析怎样划清边界

某零售企业通过线上渠道接受客户订单。

1. 完成订单

为了履行订单，企业需要处理客户姓名、联系方式、收货地址、订单内容和支付状态等个人信息，但仍应限制在完成交易和交付所必需的范围。

2. 开展客户分析

企业希望进一步分析消费偏好。此时需要重新判断：

  • 分析目的是否明确；
  • 采用什么处理依据；
  • 是否确实需要身份、地址和支付信息；
  • 能否使用去标识化数据或汇总结果；
  • 分析生成的标签和画像是否仍能关联到个人；
  • 结果将由谁使用，保存多长时间。

3. 开展精准营销

完成订单所必需的数据，并不当然可以无限期用于所有营销活动。用途改变后，需要重新判断处理依据、告知方式和个人选择权。

4. 委托外部服务商

如果企业委托外部机构发送消息或开展分析，还需要明确受托方的处理目的、方式、范围、保存期限和结束后的处置责任，并监督其履行约定。

企业没有因为保护个人信息而停止分析，而是把订单履约、客户分析和营销拆分为目的不同的处理活动，分别确定必要数据和使用边界。

十六、常见误区

误区一：只有姓名和身份证号码才是个人信息

能够结合其他信息识别个人的账号、设备标识、轨迹、标签和画像，也可能属于个人信息。

误区二：删除姓名以后就不再是个人信息

如果仍能借助其他数据重新关联到个人，只是完成了去标识化，而非匿名化。

误区三：取得一次同意，可以用于所有后续目的

同意针对具体处理活动，目的和方式发生变化后需要重新判断。

误区四：所有个人信息处理都必须依赖同意

法律规定了多种处理依据，关键是为每项处理活动找到适用依据，而不是机械索取同意。

误区五：业务上有用的数据都属于最小必要

“可能有用”不等于为实现当前目的确有必要。

误区六：公开可见的个人信息可以无限制使用

合法公开信息也应在合理范围内处理，并关注使用目的和对个人权益的影响。

误区七：普通个人信息不需要保护

敏感个人信息需要更加严格保护，但普通个人信息同样受到处理规则和个人权利约束。

误区八：敏感个人信息一律不能处理

在具有特定目的、充分必要性并采取严格措施的条件下，可以依法处理。

误区九：员工在内部访问不属于个人信息处理

查询、使用、加工和传输都是处理活动，内部人员同样受到目的、权限和责任约束。

误区十：算法生成的标签和画像不是个人信息

只要能够关联到已识别或可识别个人，就仍可能属于个人信息。

误区十一：敏感个人信息自动等于重要数据

二者保护利益、识别依据和管理要求不同，可能重叠但不能画等号。

误区十二：数据脱敏以后就可以任意共享

脱敏不一定达到匿名化，数据组合和使用环境仍可能带来重新识别风险。

小结

个人信息识别不能只依靠字段名称，而要判断数据能否直接或结合其他信息关联到自然人。敏感个人信息是个人信息中风险更高的部分，需要结合信息类型、数据组合、使用场景和对个人的潜在影响判断。

个人信息保护也不只是安全技术问题。组织需要为每项处理活动明确目的和合法依据，坚持最小必要，履行相应告知和同意程序，保障个人行使权利，并把保护要求贯穿收集、存储、开发、使用、提供和删除全过程。

真正成熟的个人信息治理，不是让组织完全不使用个人信息，而是让每一次使用都能回答：为什么处理、凭什么处理、处理多少、由谁使用、保存多久，以及个人怎样了解并影响这一过程。
