099 如何让 AI 问数准确、可靠、可追溯？

一句话回答

AI 问数的可靠性，不主要取决于模型会不会写 SQL，而取决于它是否被可靠的业务语义、指标定义、数据权限、查询校验、结果验证和证据记录共同约束。对无法确认的问题，系统应当澄清、拒答或请求人工确认，而不是生成看似完整的答案。

自然语言问数把数据查询的入口从表、字段和 SQL 转成了业务语言。它可以降低使用门槛，但也把“理解问题”变成了查询过程的一部分。用户说“本月销售额”“客户增长”“库存下降原因”，系统必须知道统计对象、时间口径、数据范围、计算方法和适用场景，才能生成有意义的结果。

因此，AI 问数不是把问题翻译成 SQL 就结束了。它需要把自然语言问题连接到经过治理的术语、指标、语义、权限、数据源和验证机制，并在无法确认时明确表达不确定性。

一、AI 问数有哪些类型

不同类型的问题，风险和验证要求不同：

  • 结构化数据查询：查询销售额、库存、客户数和项目进度；
  • 指标解释：解释指标定义、变化幅度、统计范围和适用场景；
  • 多轮分析：继续按区域、产品、时间和组织下钻；
  • 文档与数据结合：把制度、合同、报告和结构化数据放在同一分析中；
  • 预测和建议：根据历史数据预测趋势或提出行动建议。

一个只读的探索性查询，可以采用较轻的人工复核；进入经营决策、绩效考核、监管报送或客户服务的结果，则需要更严格的权限、证据和责任机制。不能用“SQL 执行成功”作为所有问数场景的统一可靠性标准。

二、第一步是确认用户真正要问什么

AI 应先识别问题中的业务对象、指标、时间范围、组织范围、过滤条件和比较基准。例如“本月销售额下降原因”至少涉及：

  • “销售额”是合同金额、订单金额、确认收入还是回款金额；
  • “本月”按哪个时区、哪个自然月和哪个业务时间统计；
  • “下降”与上月、去年同期还是预算比较；
  • 是否排除取消、退货、内部交易和测试数据；
  • “原因”是描述相关变化，还是要求证明因果关系。

当问题存在多个合理解释时，系统应主动追问，而不是根据语言习惯猜测一个口径。对“最近”“增长”“异常”“完成”等相对表达，也应明确时间基准和计算方式。

三、依赖语义层、指标平台和本体

可靠问数不应让模型直接遍历所有底层表并猜测字段含义，而应通过受治理的语义能力完成映射：

  • 通过业务术语和别名理解用户使用的词语；
  • 通过指标平台获取正式定义、公式、粒度、过滤条件、时间口径和版本；
  • 通过语义层把实体、维度、度量和关系映射到物理模型；
  • 通过本体或领域语义理解对象之间的业务关系和状态；
  • 通过数据目录和血缘选择有说明、有责任和有质量状态的数据源。

语义层和指标平台解决的是“应该怎样理解和计算”，本体可以补充复杂的对象、关系、状态和规则。它们共同减少模型仅凭字段名称和文本相似度进行猜测的风险。

四、查询生成必须受到约束

生成查询时至少需要限制：

  • 可访问的数据源、表、字段和数据产品；
  • 允许使用的实体关系、关联路径和计算函数；
  • 租户、组织、行级和列级权限；
  • 查询时间范围、返回行数、资源消耗和并发限制；
  • 是否允许导出、聚合、下钻和调用外部工具；
  • 是否禁止写入、删除、修改权限和执行其他危险操作。

生成的 SQL 或查询计划应经过语法、类型、权限、粒度、连接关系和资源消耗检查。查询生成与查询执行应有明确边界，默认优先使用只读能力，不能让模型通过拼接字段或改变查询方式绕过治理规则。

五、重点防止“算对了但问错了”

SQL 语法正确、执行成功，只能说明技术过程完成，不能说明业务答案正确。还需要检查：

  • 统计对象和事实粒度是否正确；
  • 去重方式、聚合方式和分母是否符合指标定义；
  • 使用了正确的时间字段、时区、快照日期和数据截止时间；
  • 维度关联、主数据映射和历史版本是否正确；
  • 金额、数量、库存等度量是否可加、半可加或不可直接相加；
  • 多对多关联是否造成金额膨胀和重复计数；
  • 迟到数据、缺失数据和质量异常是否影响结果。

特别要注意，不同业务指标的聚合性质不同。每日库存余额不能简单跨日期相加，客户数通常需要去重，比例指标也不能直接对各分组比例求平均。语义和指标定义必须把这些计算约束传递给查询生成和结果验证环节。

六、结果生成后还需要验证

结果验证可以包括：

  • 检查结果范围、空值、异常突变和历史趋势；
  • 与已发布指标、经营报表或抽样结果交叉验证；
  • 对重要指标执行独立计算或规则校验；
  • 检查数据更新时间、质量状态和来源是否满足要求；
  • 对异常结果给出异常说明，而不是自动编造原因；
  • 将预测、归因和建议与事实数据明确区分。

“销售额下降”是一个可以由查询直接计算的结果；“因为某个产品推广失败而下降”则是解释或因果判断，需要更多证据和业务分析。AI 可以列出相关变化和可能假设，但不能把相关性直接表述为已经证明的因果关系。

七、答案必须携带证据和上下文

一个可追溯的问数结果至少应说明：

  • 使用了哪个指标、定义、版本和适用范围；
  • 查询的时间范围、数据截止时间和更新时间；
  • 数据来源、资产名称、血缘和质量状态；
  • 过滤条件、组织范围、权限上下文和脱敏情况；
  • 使用的查询、查询计划或可读的计算过程；
  • 结果由哪个模型、提示词和工具版本生成；
  • 哪些内容是事实、推断、预测或建议；
  • 谁确认了结果，哪些问题仍然存在不确定性。

证据不一定意味着把复杂 SQL 全部展示给每个用户，但系统必须能够在需要时提供可复核的来源和计算记录。进入正式业务流程的结果不能只保留一段没有上下文的自然语言。

八、正确处理不确定性、澄清和拒答

问数系统应当把以下情况作为正常分支：

  • 存在多个同名指标或多个合理数据源；
  • 用户没有说明时间、组织或统计范围；
  • 数据缺失、过期、质量不达标或尚未完成同步；
  • 用户没有访问所需数据的权限；
  • 查询结果无法支持用户要求的因果结论；
  • 当前语义、指标或数据源尚未登记，无法安全映射。

此时系统可以提出澄清问题、返回可选口径、说明缺失条件、拒绝回答或转交人工。不能为了满足“必须回答”的要求而输出一个未经确认的精确数字。高风险业务还应要求数据责任人或业务负责人确认后再使用结果。

九、权限和安全贯穿整个问数链路

权限检查不能只发生在页面，还要贯穿：

  1. 用户和应用身份识别；
  2. 语义层和指标服务的对象、范围和用途控制；
  3. 查询生成和执行时的行列级权限；
  4. 工具调用、文档检索和外部服务访问；
  5. 结果展示、导出、缓存和日志保存。

对个人信息、敏感字段和商业秘密，应执行脱敏、聚合、禁止返回或人工审批。还要防止通过多轮提问、差分查询和小样本聚合推断敏感信息。系统应记录用户、应用、模型、查询、数据范围和结果交付，便于审计和问题复盘。

十、建立问数评测集和持续改进机制

问数上线前应建立覆盖不同风险和难度的评测集：

  • 常见业务问题和高频指标；
  • 同名不同义、同义不同名和多轮追问；
  • 不完整问题、相对时间和多种统计口径；
  • 权限不足、敏感数据和越权提问；
  • 异常数据、缺失数据和过期数据；
  • 需要拒答、澄清或转人工的高风险问题。

评测不应只看语言是否流畅，还要检查语义识别、指标选择、查询正确性、结果正确性、权限合规、证据完整性和拒答质量。持续运行中应收集用户反馈、人工修正和失败案例，对指标、模型、提示词、语义模型和工具版本进行回归测试。

十一、AI 问数与数据产品是什么关系

低频、低风险的探索性问题，可以由 AI 临时生成查询；但高频、重要、反复使用的结果，应沉淀为指标、语义模型、数据产品或服务，形成稳定的定义、质量、版本、权限和责任。

AI 可以成为数据产品的自然语言入口，但不应让每个用户从底层数据各自生成一套临时口径。重复出现的问数问题，往往说明组织需要建设或完善一个正式指标、数据服务或业务产品。

十二、案例：AI 查询“本月销售额下降原因”

某集团希望让区域负责人直接询问“本月销售额下降的主要原因是什么”。系统接入订单、发货、退货、库存和客户服务数据。

AI 首先确认“销售额”采用确认收入还是订单金额，明确“本月”的时间范围、时区和数据截止时间，并通过指标平台选择正式指标。随后，语义层负责关联区域、产品、渠道和订单事实，系统生成只读查询并检查粒度、重复关联、权限和资源消耗。

结果返回时，系统展示数值、变化幅度、指标口径、数据来源、更新时间和质量状态，并列出产品、区域、渠道和退货变化等证据。对于“原因”，系统只给出基于数据的相关性分析和待验证假设，不直接宣称因果结论。

如果数据不足、存在多个合理口径或用户没有访问明细数据的权限，系统应先澄清、降级为汇总结果或拒绝回答。进入库存、营销或客户服务行动前，还需要业务负责人确认。

十三、常见误区

误区一：只要 SQL 能执行，答案就一定正确

SQL 正确只说明语法和执行过程没有报错，不能证明指标、粒度、时间和关联关系正确。

误区二：让模型直接访问所有底层表

这会扩大权限、口径和资源风险，也让模型更容易从字段名称中猜错业务含义。应优先提供受治理的语义、指标和数据服务。

误区三：只在前端做权限控制

模型、查询服务、工具调用、缓存和结果交付都可能成为越权路径，权限必须贯穿完整链路。

误区四：只给数字不给口径、来源和时间

没有定义、版本、数据截止时间和来源，数字无法复核，也不能判断是否适合当前业务。

误区五：把相关性分析当成因果结论

数据变化可以提示可能原因，但真正的因果判断还需要业务机制、实验或其他证据支持。

误区六：遇到歧义时模型自行选择一个口径

歧义应通过澄清、展示可选口径或拒答处理，而不是把猜测伪装成精确答案。

误区七：不允许拒答，要求模型必须给出答案

强制回答会把数据缺失、权限不足和语义不清转化为幻觉结果。高质量系统必须能够说明不知道。

误区八：高频问数长期停留在临时 SQL

反复使用的问数结果应沉淀为受治理的指标、数据产品或服务，不能长期依赖不可追踪的临时查询。

小结

可靠的 AI 问数需要把自然语言问题约束在治理过的术语、语义、指标、数据源和权限范围内，并对查询计划、计算粒度、结果状态、来源证据和不确定性进行验证。

AI 不确定时应澄清或拒答；高频和重要问数结果应沉淀为版本化、可运营的数据产品或服务。系统还需要通过评测集、用户反馈和回归测试持续改进，而不是只在上线时验证几组示例。

真正成熟的 AI 问数，不是让模型回答更多问题，而是让每个回答都尽可能说明“依据什么数据、按什么口径、在什么范围内、何时生成、谁可以使用，以及哪些地方仍然不确定”。
