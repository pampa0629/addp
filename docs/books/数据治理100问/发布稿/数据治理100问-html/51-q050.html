050 时空数据在数据治理中发挥什么作用？

一句话回答

时空数据回答业务事实“在什么时间、什么位置发生”。时间帮助我们理解事件顺序、状态变化和数据鲜活度，空间帮助我们理解对象位置、范围、邻近关系和影响区域。在自然资源等行业中，空间范围甚至是业务对象本身的一部分。数据治理需要把时间、空间与实体、事件、指标和历史版本关联起来，使数据能够支撑定位、变化分析、统计、预测和业务决策。

时空数据不只是地图上的点线面，也不只是给普通数据增加一个经纬度字段。它表达的是业务对象在时间和空间中的存在、变化、关系与影响。

一、为什么业务分析经常离不开时间和空间

大多数业务数据至少隐含一个时间问题：什么时候产生、什么时候生效、什么时候失效、什么时候被处理。很多业务还同时隐含一个空间问题：在哪里发生、影响哪里、属于哪个区域、与哪些对象相邻。

例如，同一个“积水事件”如果没有时间和空间，就无法回答：

  • 什么时候开始、持续了多久；
  • 发生在哪条道路、哪个社区；
  • 当时的降雨量和水位是多少；
  • 哪些设施和人员受到影响；
  • 处置前后情况是否发生变化。

同样，“土地利用类型为工业用地”也不能脱离：

  • 这块土地的空间边界在哪里；
  • 这个分类在哪个调查时点有效；
  • 边界和利用类型是否经历过变更；
  • 它位于哪个行政区、规划分区或生态管控范围内。

只有把时间、空间和业务语义结合起来，数据才不只是一个孤立的数值或名称。

二、什么是空间数据

空间数据是描述对象位置、范围、形状以及空间关系的数据。常见形式包括：

类型 示例 主要表达内容
点 监测站、井盖、企业、地块中心点 位置和点状对象
线 道路、河流、管线、轨迹 连续路径和线性对象
面 地块、行政区、建筑轮廓、保护区 边界、范围和面状对象
栅格 遥感影像、地形高程、温度场、降雨场 按网格表达连续空间现象
轨迹 车辆、人员、船舶和设备移动路径 位置随时间的变化过程
地址和位置描述 门牌地址、地名、里程桩和网格编码 可定位的业务位置
空间关系 相交、包含、邻接、覆盖和距离 对象之间的空间联系

空间数据的价值不只是“在地图上画出来”。空间关系可以参与查询、统计、关联、规则判断和算法计算。例如，判断一个项目是否落在保护区内，计算道路周边500米范围内的服务设施，统计某行政区内不同地类的面积，都是空间治理支撑的业务能力。

三、什么是时间数据

时间数据不只是一个名为“更新时间”的字段。不同时间字段可能代表不同业务含义。

时间类型 说明 示例
事件时间 业务事件实际发生的时间 订单支付时间、告警发生时间
有效时间 某个事实在业务世界中生效的时间范围 土地规划用途生效时间
交易时间 系统记录或确认这项事实的时间 登记系统写入时间
观测时间 传感器或调查人员实际观测的时间 水位测量时间、调查时点
处理时间 数据被采集、加工或入库的时间 数据进入仓库的时间
发布时间 数据或成果被发布供别人使用的时间 指标发布日、地图成果发布日期
版本时间 某个模型、标准或数据版本适用的时间 分类标准版本生效时间

如果只保留一个“更新时间”，很容易把业务发生、数据采集、系统处理和对外发布混为一谈。

例如，一条土地利用变更记录可能在3月发生，4月被调查，5月进入系统，6月完成审核，7月发布。不同时间分别回答业务发生、调查、处理、确认和可使用的状态，不能互相替代。

四、有些业务对象本身就具有明确的空间范围

对于客户、订单和合同，空间通常是对象的一个属性，例如收货地址、项目所在地或合同履行地点。对于另一些行业，空间范围不是附加信息，而是业务对象定义的一部分。

1. 土地是典型的空间业务对象

自然资源领域中的土地、宗地、地块、规划分区、保护区和海域等对象，必须通过明确的空间范围来识别和管理。

如果只保存“地块编号、面积和土地用途”，却没有边界、坐标参考系和空间版本，就无法准确判断：

  • 这块土地究竟在哪里；
  • 它与哪些道路、河流、行政区和规划范围相交；
  • 两个系统中的地块是否指向同一空间对象；
  • 面积统计是否存在重叠、遗漏或边界不一致。

地块的空间边界发生分割、合并或调整时，往往不仅是图形变化，也可能影响权属范围、规划条件、供地合同、建设项目和后续利用评价。

2. 全国国土调查说明了空间的业务基础地位

我国通常按较长周期开展全国性国土调查，历史上大致间隔十年，并通过年度国土变更调查持续更新。其成果不只是绘制一张土地利用现状图，还要以具有明确空间范围的调查单元为基础：

  • 识别不同地类和利用状态的空间分布；
  • 统计各地区、各地类的面积和变化；
  • 支撑耕地保护、规划实施和用途管制；
  • 发现土地利用与批准、登记和建设情况之间的差异；
  • 为后续年度变化监测和管理决策提供基准。

这里的核心对象不是一张地图文件，而是带有空间范围、分类属性、调查时点、来源和版本的土地业务数据。

五、时间和空间如何共同描述业务对象

单独有空间，没有时间，无法知道对象何时有效；单独有时间，没有空间，无法知道变化影响哪里。

以土地为例，同一空间范围在不同时间可能具有不同：

  • 权属或使用权状态；
  • 规划用途和批准条件；
  • 实际利用类型；
  • 建设和开发状态；
  • 低效、闲置或盘活评价结果。

以道路为例，同一条道路在不同时间可能具有不同：

  • 交通组织和限行规则；
  • 施工、封闭和通行状态；
  • 拥堵程度和交通流量；
  • 周边设施和服务能力。

因此，治理体系需要同时管理：

  • 对象的空间身份和边界；
  • 对象的时间有效范围；
  • 状态或属性变化的事件；
  • 变化前后的版本和来源；
  • 变化对指标、模型和业务应用的影响。

六、时空数据如何让数据为业务增值

1. 定位与发现

用户可以按位置、范围、行政区、网格或附近对象查找数据，而不必先知道数据存在哪张表或哪个文件中。

2. 空间关联与叠加分析

将业务对象与行政区、规划范围、保护区、道路、管网和风险区进行空间关联，判断对象之间是否相交、包含、邻近或覆盖。

3. 按时间和空间统计指标

指标可以按日、月、调查期、行政区、网格、地类或风险等级汇总，形成更符合管理需要的分析视图。

4. 变化检测

比较不同时间的影像、地类、边界、设施状态和事件记录，发现新增、减少、迁移、扩张、闲置或异常变化。

5. 过程和轨迹分析

分析车辆、人员、设备或事件随时间和位置的变化，判断路径、停留、拥堵、覆盖范围和处置过程。

6. 风险识别与预测

将实时观测、历史事件、地形、设施、天气和业务规则结合起来，识别某个时间窗口内可能受影响的对象和区域。

7. 支撑业务行动

分析结果可以进入规划调整、巡查派单、资源调度、风险预警、项目核查和监管处置流程，而不只是停留在地图展示中。

七、时空数据与实体建模、维度建模是什么关系

时空数据治理不是脱离业务建模另起一套体系，而是把时间和空间纳入业务对象、事件和指标的表达。

可以这样理解：

  • 实体建模回答“管理的对象是什么”；
  • 空间建模回答“对象在哪里、范围多大、彼此如何关联”；
  • 时间建模回答“对象何时存在、何时生效、怎样变化”；
  • 维度建模回答“如何按时间、空间和其他维度计算和分析指标”；
  • 数据治理回答“这些定义、关系、来源、质量和版本如何持续维护”。

例如，土地全生命周期分析可能需要：

  • 以地块作为核心实体；
  • 以边界和空间参考系表达地块范围；
  • 以调查期、变更时间和有效期表达时态；
  • 以行政区、地类、规划用途和开发状态作为分析维度；
  • 以面积、闲置年限、开发强度和投入产出作为指标。

如果只做空间图层而没有实体和时间关系，难以解释历史和责任；如果只做表格指标而没有空间边界，难以判断统计范围和管理对象。

八、案例：土地全生命周期中的时空治理

1. 从空间对象确定管理边界

首先明确地块、宗地、规划单元、项目和权属范围等业务对象的定义。不同管理场景的空间单元可能不同，不能简单把某一张图层中的每个面都当作唯一业务实体。

例如：

  • 调查统计可能以调查地块和地类图斑为基础；
  • 不动产登记关注权利范围和登记单元；
  • 规划管理关注规划分区和控制范围；
  • 项目管理关注项目红线和建设范围；
  • 低效用地识别还需要关联投入、产出、利用状态和开发进度。

这些对象可能相互重叠、包含或存在映射关系，需要明确各自的业务语义和适用场景。

2. 记录空间和时间变化

土地利用类型发生变化时，不能只把原来的属性值覆盖为新值。治理体系还要记录：

  • 变化前后的地类和利用状态；
  • 变化发生、调查、审核和生效的时间；
  • 边界是否发生分割、合并或调整；
  • 变化依据、来源和责任主体；
  • 变化影响的规划、权属、合同、项目和指标。

土地对象几乎不会像普通交易记录一样“消失”。即使建设用地重新复垦，也通常是利用类型和管理状态发生变化。因此，时空治理更重视版本、演化和可追溯性，而不是只保留一条当前记录。

3. 支撑调查与后续指标分析

全国性国土调查可以形成阶段性空间和分类基准，年度国土变更调查持续记录变化。后续统计分析需要同时引用：

  • 调查或变更时点；
  • 当时有效的地类标准和行政区划；
  • 对应版本的空间边界；
  • 数据来源、调查方法和审核状态；
  • 面积计算和空间叠加规则。

只有这样，某个年份的耕地面积、建设用地面积或低效用地规模才具有可解释性，才能与其他年份进行合理比较。

4. 让分析进入业务处置

如果识别出某地块长期闲置或利用效率偏低，结果应进一步关联：

  • 权属和供地合同；
  • 规划条件和审批事项；
  • 项目建设和投资进度；
  • 周边基础设施和交通条件；
  • 后续盘活、整改或再开发措施。

这样，空间分析结果才能进入核查、盘活、再开发和监管决策，而不是只生成一张专题地图。

九、时空治理需要哪些基础信息

第051问将进一步讨论质量要求，本问先概括时空治理必须关注的基础信息。

1. 空间参考信息

需要明确坐标参考系、投影、单位、空间范围、数据比例尺或分辨率。不同来源的数据即使都能在地图上显示，也可能因为参考系和精度不同而不能直接叠加。

2. 空间对象和关系

需要说明几何代表什么业务对象、边界是否闭合、对象之间是相交、包含、邻接还是覆盖，以及空间关系是否随时间变化。

3. 时间语义

需要区分事件发生时间、有效时间、观测时间、处理时间、发布时间和版本时间，避免把“最新入库”当作“业务最新状态”。

4. 来源和版本

需要记录数据由谁、在什么时间、通过什么调查、采集、测绘或处理方法形成，使用了哪个分类标准、行政区划和模型版本。

5. 变化和历史

需要保留边界、属性、状态和关系的变化记录，使历史数据能够被重新解释，而不是只能看到当前快照。

十、空间数据应如何纳入统一数据治理体系

空间数据不需要被隔离为一套与其他数据完全不同的治理体系。它应当纳入统一的数据身份、元数据、标准、质量、血缘、权限和资产管理体系，同时扩展空间领域所需的专业能力。

统一治理可以包括：

  • 统一登记空间数据的来源、责任、版本和使用范围；
  • 将地块、道路、设备、项目等空间对象与业务实体关联；
  • 将空间数据与表、文档、事件和服务建立血缘关系；
  • 对空间字段、坐标参考系、空间范围和空间关系进行描述；
  • 按业务场景提供地图、空间查询、空间统计和分析服务；
  • 对空间数据的敏感范围、精度和对外发布进行控制。

物理上，空间数据可以继续存放在支持空间能力的数据库、文件、对象存储或专业引擎中；逻辑上，应当能够在统一目录和业务语义下被发现、理解和使用。

十一、什么时候需要引入专门的时空能力

如果业务只需要保存一个地址或行政区代码，使用普通字段和标准化地址能力可能已经足够。

以下情况通常需要更完整的时空数据治理和计算能力：

  • 业务对象本身由空间边界定义；
  • 需要进行相交、包含、邻近、缓冲或叠加分析；
  • 需要按空间范围和时间窗口持续统计；
  • 需要保存对象的历史边界和状态变化；
  • 需要处理轨迹、遥感影像、地形、三维或高频传感器数据；
  • 空间和时间分析结果会影响规划、监管、调度或风险处置；
  • 多来源数据的坐标、时间和空间单元不一致，已经影响业务结论。

是否引入专业引擎，不应由“数据看起来像地图”决定，而应由空间关系、数据规模、计算复杂度和业务时效要求决定。

十二、常见误区

误区一：时空数据就是在地图上展示的数据

地图只是时空数据的一种表现方式。空间关系、时间变化、指标计算和业务规则同样是治理对象。

误区二：给表增加经纬度字段就完成了空间治理

经纬度不能替代空间边界、坐标参考系、精度、拓扑和业务对象定义。

误区三：时间字段只保留最后更新时间

最后更新时间通常只是处理事实，不能替代事件发生时间、有效时间、观测时间和版本时间。

误区四：每一张空间图层都代表一个业务实体

图层是数据组织和展示方式，不一定对应业务实体。一个业务实体可能有多个空间表达，一个图层也可能混合多个业务概念。

误区五：当前地图可以替代历史版本

土地边界、规划条件、道路通行状态和风险范围都可能变化。没有历史版本，就无法解释过去的审批、统计和决策。

误区六：坐标转换以后数据就可以直接叠加

坐标转换只解决部分空间参考问题，不能自动解决比例尺、精度、边界、拓扑和业务分类差异。

误区七：空间数据应当独立于其他数据治理

空间数据仍然需要统一的实体、标准、元数据、质量、血缘、权限和资产管理，只是增加空间专业能力。

十三、实践检查清单

  1. 业务对象是否明确了空间范围、空间身份和适用场景？
  2. 时间字段是否区分事件、有效、观测、处理、发布和版本时间？
  3. 空间数据是否记录坐标参考系、范围、精度和数据来源？
  4. 是否区分空间图层、业务实体和空间关系？
  5. 边界、属性和状态变化是否保留了历史版本和变更依据？
  6. 时空数据是否能够与表、文档、实时事件和业务指标关联？
  7. 是否根据业务需求选择物理存储和空间计算方式，而不是盲目统一？
  8. 分析结果是否进入规划、监管、调度或其他实际业务流程？

小结

时间和空间不是数据治理之外的特殊装饰，而是许多业务事实的基本语义。时间说明对象何时发生、何时有效和怎样变化，空间说明对象在哪里、范围多大以及与什么对象发生关系。

在自然资源土地管理等行业中，空间范围甚至构成业务对象本身。全国性国土调查和后续年度变更调查，也说明空间数据治理不是一次性的地图制作，而是围绕调查单元、分类标准、空间边界、时间版本和指标统计持续运行的业务过程。

时空数据应纳入统一数据治理体系，同时保留自己的专业表达和计算能力。只有把时空信息与实体、事件、指标和业务行动连接起来，数据治理才能从“知道数据在哪里”进一步发展到“知道什么在何时何地发生，以及应该采取什么行动”。
