# 053 文档、图片、音视频等非结构化和多模态数据应如何治理？

## 一句话回答

> 非结构化和多模态数据既是业务实体与事件的重要记录和证据，也是结构化数据、标签、关系、轨迹和算法特征的重要来源。治理不能只把文件存入对象存储或建立下载目录，而要同时管理原始内容、技术与业务元数据、人工或 AI 提取结果、业务对象关系、质量、安全、版本和生命周期，使不同模态能够被发现、相互关联、参与计算，并让每项派生结论都能追溯到原始依据。

文档、图片、音频和视频看起来不像数据库表，却可能记录着表格字段无法完整表达的现场状态、业务过程和判断依据。如果治理体系只覆盖结构化表，组织对业务世界的认识就会缺少重要部分。

## 一、为什么这些数据必须一起参与治理

### 1. 业务实体和事件由多种数据共同描述

一个业务实体通常不只存在于一条数据库记录中。例如，一台设备可能同时关联：

- 设备台账中的型号、编号和责任部门；
- 设计说明书和维修规程；
- BIM 或三维模型中的位置和部件；
- 巡检照片和维修视频；
- 操作人员的语音记录；
- 传感器观测和告警事件；
- 故障工单和维修报告。

一次交通事故也可能涉及：

- 事故记录中的时间、位置和参与车辆；
- 道路监控视频；
- 现场照片；
- 报警和调度录音；
- 当事人的文字陈述；
- 车辆位置和行驶轨迹；
- 责任认定及后续处理文书。

这些内容即使暂时只是与实体或事件关联的材料，也能够补充上下文、提供原始证据、支持争议复核和还原业务过程。

因此，不宜一概把它们理解为次要“附件”。非结构化内容既可能是关联材料，也可能是具有独立证据价值的核心业务数据。

### 2. 内容经过提炼后可以参与后续计算

文档、图片、音频和视频中的信息，可以通过人工整理、规则处理或 AI 模型转换为结构化和半结构化结果，例如：

- 从合同中提取主体、金额、日期和关键条款；
- 从图片中识别车牌、交通违法行为和设施缺陷；
- 从录音中生成转写文本、诉求分类和关键词；
- 从视频中识别车辆、行人、事件和运动轨迹；
- 从巡检照片中识别裂缝、锈蚀和部件缺失；
- 从遥感影像中提取建筑物、道路、水体和土地变化。

这些派生结果可以进一步用于：

- 实体识别和跨系统关联；
- 标签画像和指标计算；
- 业务规则判断；
- 轨迹、过程和影响分析；
- 风险识别与异常发现；
- 模型训练、预测和推荐；
- 审核、派单和处置等业务流程。

治理目标因此不能停留在“文件可下载”，还要使其中有价值的信息能够可靠地进入数据开发和业务应用。

### 3. 不同模态可以相互补充和验证

同一业务事实由不同来源观察时，每种数据都可能存在局限。视频可能被遮挡，录音描述可能不完整，位置轨迹可能有漂移，结构化记录也可能录入错误。

例如，识别某起交通事件涉及的车辆时，可以综合：

- 卡口记录中的车牌和通过时间；
- 监控视频中的车型、颜色和行驶方向；
- 位置轨迹中的移动过程；
- 报警录音中的车辆特征描述；
- 现场照片中的碰撞痕迹；
- 车辆登记信息中的车型和所有人。

多种数据关联后，可以提高判断的完整性和可信度，也能发现相互矛盾的证据。

真正的多模态治理不是把多种文件放进同一个目录，而是让文字、图片、音频、视频、空间位置和结构化数据围绕同一业务实体或事件建立语义、时间和空间关系。

## 二、什么是非结构化和多模态数据

### 1. 非结构化不等于完全没有结构

“非结构化数据”通常指主体内容不能用固定二维表完整表达的数据，例如文档正文、图片像素、音频波形和视频画面。

但这些数据仍然具有多种结构：

- 文件有名称、格式、大小、校验值和目录；
- 文档有标题、章节、段落、页码和版本；
- 图片有尺寸、颜色空间、拍摄时间和设备信息；
- 音频有声道、采样率、时长和时间轴；
- 视频有编码、分辨率、帧率、片段和字幕；
- 内容中还可能包含人物、地点、设备、事件和关系。

因此，非结构化治理不是放弃结构，而是同时管理文件结构、媒体结构、内容结构和业务语义。

### 2. 多模态不只是多种文件类型

多模态强调不同信息表达方式共同描述一个对象、事件或问题。例如，在一次设备故障中：

- 传感器曲线说明数值怎样变化；
- 现场照片说明部件外观；
- 维修录音说明工程师的判断；
- 工单文本记录处理过程；
- 三维模型说明部件位置和组成关系。

如果这些数据没有共同的设备标识、事件标识、时间和位置，只是分别存放，就难以形成真正的多模态分析。

## 三、需要区分哪几个治理层次

非结构化和多模态数据至少应区分四个层次。

| 层次 | 主要内容 | 治理重点 |
| --- | --- | --- |
| 原始内容 | 原始文档、图片、录音和视频 | 完整保存、真实性、版本、安全和证据价值 |
| 技术与业务元数据 | 格式、时长、作者、位置、业务对象和事件 | 可发现、可理解、可关联和可控制 |
| 派生结果 | OCR文本、语音转写、标签、实体、轨迹、摘要和向量 | 模型版本、参数、置信度、质量和血缘 |
| 确认事实与业务结果 | 经规则或人工确认的违法、故障、投诉分类等 | 业务依据、责任、审核状态和后续处置 |

这几个层次不能混为一谈。

例如，从视频中识别出“车辆A疑似闯红灯”，属于模型派生结果；只有结合信号灯状态、车辆轨迹、适用规则和必要的人工审核后，才能形成相应业务认定。

## 四、为什么原始内容不能被 AI 结果替代

AI 能够从非结构化内容中提取信息，但提取结果是基于特定模型、参数和上下文形成的派生认识，并不等同于原始事实。

### 1. 提取可能存在错误

OCR可能把金额或证件号码识别错误；语音转写可能受口音、噪声和多人对话影响；图像模型可能漏检、误检或混淆相似对象。

### 2. 模型只能提取其被要求关注的内容

今天只提取合同金额，未来可能还需要分析违约条款。若只保存第一次提取结果而删除原文，就无法重新处理。

### 3. 原始内容具有证据和复核价值

事故视频、签署合同、检查影像和通话录音可能需要用于审计、复核或争议处理，摘要和标签不能替代原始证据。

### 4. 模型和规则会不断变化

模型升级后，可以基于原始数据重新提取并比较结果。没有原始内容，就无法验证新旧模型差异。

因此，派生结果应记录：

- 来源内容及其稳定标识；
- 来源中的页码、区域、时间片段或帧范围；
- 提取任务、模型、算法和版本；
- 提示、参数和必要处理步骤；
- 置信度和质量状态；
- 生成时间和适用范围；
- 是否经过人工复核；
- 修订、确认和失效状态。

## 五、怎样让内容与业务实体和事件建立关系

非结构化数据只有关联到业务上下文，才能从孤立文件变成可使用的数据。

常见关联方式包括：

- 业务系统在产生文件时直接写入客户、项目、设备或事件标识；
- 在文件交付清单中明确对象和批次；
- 通过时间、位置、设备、人员和业务编号进行匹配；
- 从文档或媒体内容中识别候选实体和关系；
- 由人工确认无法自动判断的关联；
- 通过血缘记录某个派生结果来自哪个内容片段。

关联关系本身也需要治理：

- 是源系统明确记录，还是算法推断；
- 使用了哪些匹配字段和规则；
- 置信度是多少；
- 是否经过人工确认；
- 在什么时间范围内有效；
- 对象合并、拆分或标识变化后如何更新。

不能因为两个文件名称相似，或者图片拍摄位置接近，就直接断定它们描述同一业务对象。

## 六、不同类型内容需要哪些元数据

所有内容都需要名称、来源、责任、版本、权限、时间和生命周期等通用元数据，不同模态还需要自己的专业信息。

| 内容类型 | 需要重点管理的元数据 |
| --- | --- |
| 文档 | 文种、作者、页数、语言、版本、签署和生效状态 |
| 图片 | 格式、尺寸、分辨率、拍摄时间、设备、方向和位置 |
| 音频 | 编码、采样率、声道、时长、语言和录制来源 |
| 视频 | 编码、分辨率、帧率、时长、时间范围、设备和拍摄位置 |
| OCR文本 | 来源页码和区域、模型版本、语言、置信度和版面关系 |
| 语音转写 | 来源时间片段、说话人、语言、置信度和校订状态 |
| 图像或视频识别 | 对象类别、位置框、时间片段、轨迹、模型和置信度 |
| 向量表示 | 来源内容、切分方法、嵌入模型、维度、版本和生成时间 |

媒体文件中的内嵌元数据可能缺失、错误或被修改，不能无条件视为权威。例如，图片拍摄时间应结合上传记录、设备时钟和业务事件判断。

## 七、非结构化和多模态数据如何进行质量治理

### 1. 通用文件质量

- 文件是否完整、可读取且未损坏；
- 格式和声明版本是否一致；
- 校验值是否与交付清单一致；
- 主文件和伴随文件是否齐全；
- 是否存在重复文件或错误版本；
- 文件是否按要求及时交付。

### 2. 文档质量

- 页码、章节和附件是否完整；
- 扫描内容是否清晰、方向是否正确；
- 文档版本、签署和审批状态是否明确；
- 当前是否生效，是否已被新版本替代；
- OCR文字是否达到目标用途要求；
- 表格、印章、批注和版面关系是否正确保留。

### 3. 图片质量

- 分辨率、清晰度、曝光和遮挡是否满足用途；
- 拍摄时间、位置和方向是否可信；
- 图片是否完整覆盖目标对象；
- 是否经过压缩、裁剪或编辑；
- 识别标签是否与图片区域正确对应。

### 4. 音频质量

- 音频是否完整，有无中断和明显失真；
- 采样率、声道和音量是否满足转写或分析需求；
- 噪声、重叠说话和口音是否影响识别；
- 录制时间、来源和说话人是否明确；
- 转写文本与时间轴是否对齐。

### 5. 视频质量

- 编码、分辨率、帧率和时长是否符合要求；
- 是否存在黑屏、花屏、缺帧或时间跳变；
- 摄像设备时间是否同步；
- 视频位置、视角和覆盖范围是否明确；
- 识别对象、事件和轨迹是否与正确帧段对应。

### 6. 多模态对齐质量

多种数据共同描述一个事件时，还要检查：

- 是否关联同一个业务对象；
- 时间范围是否重合或具有合理先后关系；
- 空间位置是否一致；
- 不同来源的分类和描述是否冲突；
- 缺少某种关键证据时能否形成结论；
- 模型提取结果能否追溯到具体内容片段。

质量要求必须联系业务用途。用于普通知识检索的OCR允许少量文字错误，用于识别合同金额、证件号码或交通违法的结果则需要更严格验证。

## 八、怎样组织存储、检索和计算能力

统一治理不意味着所有内容和索引都存放在同一种引擎中。

常见分工包括：

- 原始文档和媒体存放在适合大文件的文件系统或对象存储中；
- 文件、业务和治理元数据存放在可查询的元数据系统中；
- OCR和转写文本进入全文检索系统；
- 实体、标签和关系进入结构化数据或知识图谱；
- 向量表示进入适合相似度检索的向量索引；
- 视频事件和轨迹进入分析存储；
- 业务确认结果进入相应业务系统或治理数据层。

这些对象需要通过稳定标识和血缘关联。删除或更新原始文件时，系统应能够识别受影响的文本、标签、向量、实体、索引和业务结果。

## 九、向量数据库是不是治理非结构化数据的必要条件

向量表示可以将文本、图片、音频或视频片段映射为数值向量，用于语义检索、相似内容发现、聚类和 RAG 等应用。向量数据库或向量索引是实现这类能力的可选技术组件。

但生成向量不等于理解和治理了内容。向量通常不能单独回答：

- 原始内容来自哪里、由谁负责；
- 当前版本是否仍然有效；
- 内容是否完整、清晰和可信；
- 是否包含敏感信息；
- 哪个片段支持某项业务结论；
- 模型升级后哪些向量需要重建；
- 原始内容删除后相关向量是否应同步删除。

向量治理至少需要记录：

- 来源内容和具体切片；
- 切分、预处理和去重方法；
- 嵌入模型、版本和向量维度；
- 生成时间、语言和适用用途；
- 原始内容的权限和生命周期；
- 索引版本和重建状态。

如果只需要按文件名、字段或全文关键词检索，不一定要引入向量能力。技术选择应由检索和分析需求决定。

## 十、如何管理安全、隐私、版权和合规

非结构化内容的敏感信息经常隐藏在正文、画面和声音中，不能只根据文件名或目录判断。

可能需要识别和保护：

- 文档中的身份证号、联系方式、合同条款和商业秘密；
- 图片和视频中的人脸、车牌、住宅内部和屏幕内容；
- 音频中的声音特征、身份信息和私人谈话；
- 位置和轨迹中的个人活动规律；
- 医疗影像和检查报告中的健康信息；
- 带有版权或授权限制的图片、视频和文档。

治理时应明确：

- 数据采集是否合法、是否必要；
- 允许哪些人员和算法访问；
- 是否可以用于训练、分析或对外共享；
- 展示、下载和模型调用时如何脱敏；
- 原始内容、转写文本和向量是否继承同一权限；
- 保存多长时间，何时归档或删除；
- 删除原始内容后哪些副本和派生结果需要同步处理。

需要特别注意，派生数据也可能泄露原始内容。即使删除了录音，完整转写文本仍然保存了谈话；即使模糊了人脸，人物身份标签和轨迹也可能具有敏感性。

## 十一、案例：交通事件的多模态数据如何形成业务闭环

某城市希望利用道路监控、卡口、报警和事故处理数据，提高交通事件发现、车辆排查和处置效率。

### 1. 先围绕事件组织原始数据

一次交通事件可能关联：

- 事件编号、时间、地点和处理状态；
- 现场及周边监控视频；
- 卡口通过记录；
- 报警录音和调度记录；
- 现场照片和文字说明；
- 车辆登记和道路信息；
- 处置文书和确认结果。

治理体系应保留各项数据的来源、时间、位置、设备、版本和权限，并建立与交通事件和相关车辆的关系。

### 2. 从不同模态中提取候选信息

处理流水线可以：

- 从视频中识别车辆、行驶方向和轨迹片段；
- 从图片中识别车牌和车辆特征；
- 从报警录音中转写时间、地点和特征描述；
- 从文书中提取事件类型和处置结果；
- 将候选车辆与卡口记录和登记信息关联。

每个结果都要记录来源帧、时间片段、模型版本、置信度和处理状态。

### 3. 多源关联形成线索而不是自动定案

视频中的车辆轨迹、报警描述和卡口记录可以相互验证，形成待核查车辆和事件过程。系统还应展示矛盾信息，例如车牌识别结果不同、设备时间存在偏差或轨迹中间断裂。

模型结果可以帮助缩小排查范围、还原行驶过程，但不能仅凭相似度分数直接形成责任认定。正式业务事实仍需依据适用规则和审核流程确认。

### 4. 让确认结果进入后续业务

经确认的信息可以用于：

- 事件处置和案件流转；
- 交通违法统计和风险分析；
- 道路设施及信号优化；
- 高发事件地点识别；
- 模型效果评估和规则改进。

业务确认结果又可以作为经过标注的数据，帮助评估识别模型的准确率，但使用范围仍需符合隐私、安全和管理要求。

## 十二、怎样逐步开展治理

### 1. 从高价值业务实体或事件开始

先选择客户投诉、设备故障、交通事件、合同审查或现场巡检等具体场景，不要一开始就收集组织内所有文件和媒体。

### 2. 管好原始内容和基本元数据

确保文件完整、来源明确、身份稳定、权限可控、版本可追溯，并能关联业务对象。

### 3. 根据用途选择提取能力

需要全文搜索时可以优先OCR和语音转写；需要对象识别、轨迹分析或语义检索时，再引入相应模型和索引。

### 4. 建立派生结果的数据模型

明确实体、标签、关系、事件、时间片段、空间位置、置信度和确认状态，避免把所有 AI 结果塞入一个无法复用的文本字段。

### 5. 形成质量和人工复核机制

对高风险结论设置更高阈值和审核要求，记录误识别、漏识别和业务反馈，持续改进模型、规则和数据质量。

### 6. 打通业务使用和生命周期

让提取结果进入检索、分析、派单和处置流程，同时保证原始内容更新、失效或删除时，相关索引和派生结果能够同步管理。

## 十三、常见误区

### 误区一：上传到对象存储就完成了治理

对象存储解决文件保存问题，不能自动解决业务语义、关联、质量、权限、检索和生命周期。

### 误区二：非结构化数据完全没有结构

文件、媒体和内容都有结构，只是不能完全用固定二维表表达。

### 误区三：多个模态放在同一目录就完成了关联

真正的关联需要共同的实体、事件、时间、空间和可追溯关系。

### 误区四：生成向量就理解了内容

向量适合相似度和语义检索，但不能替代业务定义、版本、质量、权限和来源管理。

### 误区五：转写文本和摘要可以替代原始录音或文档

转写和摘要可能遗漏、误解或压缩信息，不能替代原始证据。

### 误区六：AI 识别结果可以直接作为业务事实

模型输出应保留置信度和依据，高风险结论还需要规则判断或人工确认。

### 误区七：只有原始文件需要安全控制

OCR文本、转写、标签、向量和轨迹同样可能包含或泄露敏感信息。

### 误区八：模型升级只需要重新部署服务

模型版本变化可能导致提取结果和向量发生变化，需要评估是否重算、怎样比较以及哪些下游受影响。

## 十四、实践检查清单

1. 非结构化内容是否关联到明确的业务实体、事件、时间和位置？
2. 是否区分原始内容、元数据、派生结果和经确认的业务事实？
3. AI 提取结果是否记录来源片段、模型版本、置信度和人工确认状态？
4. 不同模态之间的对象、时间和空间关系是否得到验证？
5. 是否根据文档、图片、音频和视频特点分别建立质量规则？
6. 原始内容、全文索引、向量和结构化结果是否通过稳定身份与血缘关联？
7. 权限、隐私、版权和删除要求是否传递到派生数据和索引？
8. 提取结果是否真正进入检索、分析、计算和业务处置流程？

## 小结

非结构化和多模态数据的价值有两个层次：它们首先补全业务实体和事件，保存现场状态、过程和原始证据；经过人工或 AI 提炼后，又能够形成实体、标签、关系、轨迹和特征，参与更多计算和业务流程。

治理的关键不是把所有内容强行变成表，也不是为每个文件生成一个向量，而是建立从原始内容到派生结果、再到业务事实和行动的可追溯链路。不同模态需要围绕共同的对象、时间和空间发生关联，AI 结果则必须保留来源、版本、置信度和确认状态。

当文档、图片、音视频和结构化数据能够共同解释业务，并在安全、质量和生命周期约束下持续参与分析与决策时，非结构化数据才真正从“文件材料”转化为能够为业务增值的数据资源。
