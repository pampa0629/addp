# 《数据治理100问》大纲

## 编者按

去年（2025年）参加 GISTC 并做了《时空数据治理体系建设实践和智能化初探》的报告后，我就想着报告中的内容进一步扩展并整理出来，以一问一答的方式，尽可能通俗、系统地介绍数据治理。当时已经拟定了《数据治理100问》的大纲，但那时 AI 的能力还不足以很好地协助完成这样一项长期写作，而仅靠自己，又很难持续投入足够的时间和精力，这件事便暂时搁置下来。

今年，Codex 与 GPT-6.5 的表现让人眼前一亮。我开始尝试以去年的报告全文和原有大纲为基础，通过与 AI 持续讨论、反复辨析和共同修改来完成这本书。AI 并不是代替作者写作，而是帮助我整理材料、检验结构、补充视角和加快表达；书中的观点、取舍和最终内容，仍需要在一次次交流中确认和修订。于是，便有了今天大家看到的这些文章。

后续计划按照每天一篇的节奏持续发布，直至完成这组“数据治理100问”。“一百问”是这本书的形式和起点，并不要求最终题目数量恰好为一百：重复的问题会合并，值得讨论的新话题也会继续加入。

欢迎大家留言批评、指正并提出改进意见，也欢迎提出自己关心的数据治理话题。我会根据实践、讨论和反馈持续修订，让这些内容不只停留在概念和规范上，而是能够真正帮助数据为业务增值。

## 一、书籍定位

本书以问答形式系统介绍数据治理的理念、业务价值、数据基础、组织机制、工程技术、平台运营、安全合规和发展趋势。

全书希望做到：

- 管理者能够理解数据治理为什么重要、如何组织和如何衡量成效；
- 业务人员能够理解数据如何形成价值，以及自己在治理中的责任；
- 数据和技术人员能够理解治理要求如何落实到数据、架构、平台和工程过程；
- 初学者可以按篇顺序阅读，专业读者也可以根据具体问题独立查阅；
- 不把数据治理等同于某一种方法、某一类平台或某一个技术名词。

## 二、目录组织方式

每篇使用一个子目录，每个问题使用一个独立的 Markdown 文件。问题文件采用三位全局编号，保证按文件名排序时与全书顺序一致。

目录结构示例：

    docs/books/数据治理100问/
    ├── 大纲.md
    ├── 01-总则与战略篇/
    │   ├── 001-数据治理的第一性原理.md
    │   ├── 002-数据治理为什么是一把手工程.md
    │   └── ...
    ├── 02-概念辨析篇/
    │   ├── 008-数据治理与数据管理.md
    │   └── ...
    └── 11-AI与前沿趋势篇/
        ├── 093-AI大模型与数据治理.md
        └── 097-RAG知识库知识图谱和向量数据库治理.md

采用篇章子目录而不是平铺 100 个文件，主要基于以下考虑：

- 根目录保持简洁，便于定位某一篇；
- 篇章边界清晰，适合逐篇审阅和发布；
- 后续增加插图、案例或参考资料时，可以放在对应篇章附近；
- 全局编号仍然保证问题的唯一性和稳定顺序。

## 三、单个问题的写作结构

每个问题原则上采用以下结构，根据内容需要可以适当增减：

1. 问题标题；
2. 一句话回答；
3. 为什么；
4. 核心概念；
5. 实践案例；
6. 常见误区；
7. 实践建议；
8. 延伸阅读。

写作时遵循以下原则：

- 先回答问题，再展开解释；
- 管理视角、业务视角和技术视角保持一致；
- 不堆砌术语，不把抽象名词当作答案；
- 案例优先使用通用企业场景，必要时补充时空数据和行业数据场景；
- 同一概念只保留一个稳定定义，相关问题通过链接互相引用；
- 涉及法规、标准和时效性较强的结论时，注明适用范围和时间；
- 每个问题既能独立阅读，又能在全书结构中形成连续认知。

## 五、后续编写顺序

正文原则上按照全书编号顺序逐题编写：

1. 创建对应篇章目录；
2. 创建问题 Markdown 文件；
