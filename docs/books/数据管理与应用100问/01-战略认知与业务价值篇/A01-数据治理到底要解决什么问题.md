# A01 数据治理到底要解决什么问题？

数据治理要让数据能够被可靠地使用，持续为业务增值。它既要解决数据使用中的障碍，也要帮助组织把已有数据组织成新的能力，支持更好的判断、行动和业务探索。

本书从这个目的出发理解数据治理。讨论标准、质量、模型、平台和组织职责时，都需要回答：这些工作帮助谁解决了什么问题，成果将怎样进入实际业务。

## 数据很多，为什么用起来仍然费劲

可以设想这样一次业务分析：各部门都有系统，也保存着不少数据，但要回答一个跨部门的问题，仍要临时找人提供资料。拿到以后，还得核对统计范围、解释字段含义、查找缺失信息，再把不同来源的数据拼起来。等到下一次分析，许多工作又要重做。

麻烦未必在于缺少数据。不同系统可能用不同编号记录同一个对象，同一个名称也可能代表不同范围。还有些数据不知道何时更新、由谁维护，业务人员很难判断是否适合当前用途。

这些问题会落到具体工作上：分析人员花时间核对资料，业务负责人等不到结果，产品团队无法稳定取得所需数据，交付团队在不同项目里反复处理相似问题。数据虽然已经存在，却没有形成可以方便使用的能力。

因此，治理需要追到这些障碍背后。有些问题来自记录方式和数据质量，有些来自业务口径和责任分工，还有些来自数据取得、加工和提供方式。只处理其中一处，往往不足以让业务持续用好数据。

如果不知道准备支持什么业务，治理也容易失去重点。面对大量数据，很难判断哪些差异必须统一、哪些错误需要优先处理，以及数据应更新到什么程度。业务用途为这些选择提供了依据。

## 把数据与业务需要连接起来

以低效用地识别作一个匿名情境示例。某发达地区土地资源紧张，希望了解哪些地块值得进一步核查。相关系统分别保存着土地、建筑和使用主体等资料，但这些资料能否共同支持识别，还需要验证。

首先要确定分析对象和判断依据。识别的是哪些地块，采用哪个时段的信息，哪些情况需要进一步核实，应由业务人员参与说明。

接下来，要把分散的数据联系起来。地块与建筑是否对应，使用主体是否一致，利用状况是否反映同一时期，都可能影响结果。资料缺失或相互矛盾时，还需要明确怎样核对、由谁确认。

数据治理就在这些具体工作中发挥作用。标准帮助大家一致理解对象、编码和指标；建模把对象及其关系表达清楚；质量检查帮助发现影响判断的问题；数据加工将分散记录转化为可分析的结果。这些能力相互配合，才能支持业务提出的问题。

结果还需要以合适的方式提供给使用者。业务人员应当看得懂筛选理由，能够追查相关资料，并把核查反馈带回来。数据的授权范围、维护责任和更新方式，也要在这个过程中明确。

平台可以让数据接入、处理和更新更稳定，让问题和结果更容易跟踪。不过，哪些情况需要核查、相关资料是否足以支持判断，仍需要业务人员参与。技术能力与业务责任都要进入实际工作。

在这个例子中，治理成果应当能够帮助业务部门取得有依据、可核查的识别结果。它的价值要通过后续使用来体现，不能只看汇聚了多少数据、增加了多少页面。

## 业务增值具体体现在哪里

“为业务增值”可以有多种表现。对使用者而言，可能是原来需要反复收集的资料能够直接取得，原来难以解释的结果有了明确依据，原来临时开展的分析能够按需要重复完成。

对业务负责人而言，价值可能体现为更早发现问题、更清楚地比较不同情况，或有更多证据支持资源安排。例如，低效用地识别可以帮助组织核查工作；设备运行数据与维护记录相互关联，可以为排查异常提供线索。数据支持的是具体判断和行动。

对产品与交付团队而言，经过治理的数据、规则和处理方法能够支撑产品能力，也有机会在不同项目中复用。是否可以复用，要看业务含义、适用条件和数据要求是否一致，不能只因为字段名称相似就直接套用。

控制风险也是价值的一部分。错误数据可能误导判断，不清楚的授权可能导致不当使用，责任不明则可能让问题长期无人处理。质量、安全和责任机制共同保障数据能够持续发挥作用。

评价治理成效时，可以从使用者的工作变化入手：取得数据是否更方便，核对和返工是否减少，结果是否被采用，业务问题是否得到改善。具体指标可以按场景选择，不必把所有成果压成一个分数。

业务最终效果还会受到管理决策、人员执行和其他条件影响。治理团队应说明自己提供了什么支持，以及这种支持在实际工作中怎样被使用，避免把所有变化都归于平台上线。

## 数据可用以后，还可能出现新的机会

治理的作用也会在新的使用中继续显现。

起初，一组数据可能只服务于一个明确任务。当对象关系、数据含义和使用条件逐步清楚以后，业务人员会更了解哪些信息可以组合、哪些问题值得进一步分析。其他团队也可能发现，这些成果能够支持自己的工作。

低效用地识别就是一个起点。相关数据得到核查和整理后，组织可能继续研究利用差异的原因，跟踪后续变化，或者把现有成果与更多土地管理环节联系起来。新的问题再推动数据补充、方法改进和能力扩展。

这意味着，数据治理既服务于已经提出的需求，也为发现新场景创造条件。业务人员在使用中体会到价值，才更有依据参与维护、提出需求，并支持下一阶段投入。持续投入与业务发展的关系，将在下一问中进一步讨论。

回到一项准备启动的治理工作，可以先用几句话把它说清楚：谁需要这些数据，准备作出什么判断或开展什么活动，当前困难在哪里，治理后希望发生什么变化。具体的方法和建设内容，应围绕这些问题逐步确定。
