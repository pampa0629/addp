# A02 数据治理做完一期以后，还需要持续投入吗？

需要。已有成果需要维护，业务发展也会带来新的数据需求。随着治理成果被使用、价值逐步体现，组织还会发现更多值得开展的场景。后续投入既用于让现有能力保持有效，也用于把数据带到新的业务活动中，继续创造价值。

一期完成，意味着约定范围内的工作达到交付要求。接下来做什么、投入多少，要根据业务需要和已有成果来判断。

## 已有成果仍要跟着业务变化

以低效用地识别为例。以下沿用某发达地区土地资源紧张的匿名情境，设想一期已经完成数据整理、识别规则配置和结果核查，并开始供业务人员使用。

验收时的识别结果，反映的是相应时点和条件下的情况。过了一段时间，地块的利用状况可能变化，新的调查资料也会进入系统。原来需要重点核查的地块，之后未必仍然符合筛选条件；原来没有发现问题的地块，也可能出现新的情况。

这些变化需要有人跟进。数据人员要检查新数据是否完整、能否与原有地块正确关联，业务人员要复核异常和反馈结果。如果上游接口或数据结构发生变化，技术人员还要调整处理过程。

即使页面和功能没有增加，这些工作也在持续发生。只保留软件运行费用，却没有安排数据更新、业务复核和问题处理，识别结果就可能逐渐过时。使用者一旦发现结果不再可靠，便会重新依赖线下调查和各自维护的台账。

因此，一期验收前就要考虑后续维护条件。哪些数据需要更新，哪些变化需要重新核查，由谁接手，都应当有安排。对维护工作的投入，保护的是已经形成的业务能力。

## 成果用起来以后，会出现新的问题

持续投入还有一个更积极的原因：当业务人员用上治理成果，他们会开始提出以前难以回答的问题。

在这个情境中，最初的需求只是找出值得核查的地块。假设识别结果能够解释、经过核查也确实有用，业务人员就可能继续追问：这些地块为什么没有得到充分利用？是信息不准确，还是实际存在需要进一步研究的原因？

为了分析这个问题，团队可能需要把利用状况与规划条件、设施配套、使用主体等信息联系起来。数据能够支持比较和排查，具体原因还需要结合业务调查分析。原先的一份识别结果，由此成为进一步研究的起点。

随后，新的需求还可能出现：有哪些地块更值得优先开展后续研究？相关措施实施后，利用状况是否改善？前后比较应使用哪些数据，又怎样保留当时的判断依据？

这些问题把治理从一次识别带向持续分析，也使数据逐步进入业务的研究、安排和效果评价过程。随着用途增加，原先延后的土地全生命周期治理，就可能获得更明确的实施理由。需要扩展哪些环节，可以由实际问题逐步确定。

新场景也可能来自跨业务的数据联系。某份原本只为一个任务整理的数据，在含义、质量和使用条件清楚以后，可能被另一个团队发现并使用。业务人员知道有哪些数据可以取得、哪些结果可以相信，才更有条件设想新的应用。

这也是数据治理过程中值得关注的变化：业务需求并不总能在项目开始时一次说清。有些机会，要等数据真正用起来以后才会显现。

## 能力积累，让下一步更有条件开展

开展第一个场景时，团队往往需要花不少精力寻找数据、理解含义、确认对象关系和协调责任。后续场景能否更顺利，取决于这些工作留下了什么。

如果低效用地识别只留下一个最终名单，其他人很难继续利用。如果同时保留了地块对应关系、数据来源、时间版本、识别依据和核查记录，后续研究就可以接着这些成果开展，减少重复查找和核对。

积累下来的还有处理方法与协作经验。稳定的数据更新可以自动执行，经过验证的检查规则可以继续使用，业务和技术人员也更清楚哪些问题应交给谁处理。新场景仍有新工作，但其中一部分可以建立在已有基础之上。

例如，后续要比较一块地在不同时点的利用情况，前期保留下来的地块身份和时间信息就可能派上用场；要研究识别差异的原因，已经核查过的对象关系和来源记录也能提供线索。前期投入的价值，因而可能在后续使用中继续体现。

组织对数据治理的认识也会随之改变。起初，业务人员可能只是在配合项目提供资料。当他们发现治理成果确实帮助自己减少重复核对、缩小调查范围，或者提出了值得研究的新问题，就更容易理解为什么要维护数据，也更愿意参与规则确认和需求讨论。

对管理者而言，已经被使用的成果提供了具体依据：哪些能力有用，哪些问题还没有解决，下一笔投入可能改善什么。治理团队不必始终靠描述一个宏大的远期目标争取支持，而可以拿已经发生的使用和反馈，讨论下一阶段的工作。

已有成果体现价值，增强组织信心；新的投入补充数据和能力，又为更多场景创造条件。这个过程能够推动治理与业务一起发展。

## 让每一阶段投入都有具体去处

持续投入应当逐步转化为可说明的工作。可以把投入分成三类，分别考虑：

| 投入类型 | 在这个情境中的用途 |
| --- | --- |
| 初期建设 | 整理数据、建立地块关联、确定识别依据，形成可使用的首期成果 |
| 日常维护 | 更新数据、复核异常、调整规则，保持现有识别能力有效 |
| 增量改进 | 补充新的数据与分析方法，支持原因研究、效果跟踪或其他业务场景 |

其中，业务人员的时间同样属于投入。某项关联是否正确、某种情况如何解释、分析结果能否用于实际工作，都需要相应人员参与。预算只覆盖基础设施和软件，并不能保证这些工作有人承担。

随着自动化、复用和源头改进逐步完善，同等范围内的重复劳动有条件减少。但如果数据范围扩大、更新要求提高、业务用途增加，总投入仍可能上升。应结合新增的能力和价值判断，不能单看费用是否比上一年更低。

每一阶段仍需明确范围和成果。已有能力的问题要处理，新场景要说明用途和所需资源，长期没有使用价值的工作也应调整或停止。持续治理不改变一期项目应按约定完成验收的要求。

一期结束时，可以与业务人员共同回顾：哪些成果已经用起来，帮助解决了什么问题；哪些能力需要继续维护；实际使用又提出了哪些值得尝试的新问题。把这些事实和需求摆在一起，下一阶段投入的方向才会清楚。
