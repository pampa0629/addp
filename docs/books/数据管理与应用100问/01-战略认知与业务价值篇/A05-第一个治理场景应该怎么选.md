# A05 第一个治理场景应该怎么选？

> 以下采用某发达地区土地资源紧张的情境示例，讨论为何先开展低效用地识别、后扩展土地全生命周期治理，不指向具体地区或项目。

第一个治理场景，应当让业务人员尽快用上成果，也让团队有条件把事情做成。可以先选一个迫切需要回答的问题，把所需数据、责任和使用过程做扎实，再根据实际效果扩大范围。

以一个土地资源紧张的发达地区为例。当地希望为发展腾出空间，既要关注新增用地，也希望弄清现有土地是否得到充分利用。面对这个需求，数据治理团队可以从低效用地识别入手，也可以规划覆盖土地全生命周期的治理体系。两者都有价值，但未必适合同时启动。

## 先回答眼前最需要回答的问题

低效用地识别首先要帮助业务部门判断：哪些地块值得进一步调查，依据是什么，应当先核查哪里。结果可以直接进入存量土地摸排和后续研判，使用者和用途比较容易明确。

土地全生命周期治理的范围更广。它要把土地在规划、供应、开发利用以及后续调整等过程中的数据联系起来，支持持续管理。做好这件事，需要梳理更多业务环节、历史记录和部门关系。

如果把完整生命周期作为一期目标，项目很可能在尚未产出低效用地识别结果之前，就先遇到大量跨系统关联、历史资料补齐和业务口径协调工作。这些工作有长期价值，但其中一部分未必影响眼前的识别任务。

因此，在这个情境下，可以先围绕低效用地识别确定一期范围，暂缓其他环节的全面治理。选择依据是当前业务的迫切程度与实施条件，而不能仅凭两个方案谁覆盖的功能更多来决定。

这个选择仍有前提：所需的关键数据能够取得，业务部门愿意参与确认识别依据，并且有人接手核查结果。如果连这些条件都不具备，就要先安排必要的数据调查和协调，不能因为“土地稀缺”就承诺马上完成识别。

## 首期范围怎样收住

“先做低效用地识别”仍然可以很大。是否覆盖全域、是否包括所有用地类型、是否补齐全部历史资料，都需要进一步取舍。

首期可以选择有代表性、资料条件较好、业务部门愿意配合的区域，在明确的用地类型和评价时段内开展工作。这样既能检验方法，又能看清投入主要花在哪里。选择样本时也要保留适当差异，避免只挑最整齐的数据，试点一扩大就失效。

具体应收住哪些范围，可以这样讨论：

| 首期需要明确 | 可以延后，但要说明边界 |
| --- | --- |
| 本次分析哪些地块、哪些用地类型，采用哪个时段的数据 | 不影响本次识别的其他区域和类型 |
| 用什么依据筛选，遇到缺失或冲突怎样处理 | 与当前识别无关的全量标准整理 |
| 哪些历史信息会影响判断，必须查清 | 对其余历史过程的全面补录与关联 |
| 谁接收结果、怎样核查、怎样反馈 | 对全部土地管理业务流程的统一改造 |

这里不能机械地把“历史数据”全部放到二期。例如，一块地为何尚未充分利用，可能需要结合建设阶段或其他历史情况判断。凡是会改变当前判断的事实，都属于一期必须处理的范围。

## 识别结果要能被核查和使用

选择一个小场景，并不意味着只做一张图或一个排名。

围绕低效用地识别，需要先讲清评价对象和依据。不同用途、发展阶段或实际条件的地块，是否可以直接比较，应由业务人员结合适用要求确定。数据团队负责把依据落实到数据和计算中，并把尚不能确认的地方暴露出来。

假设系统发现某地块的利用情况与预期有较大差异。业务人员打开结果时，应能看到地块位置、相关数据、评价时点和筛选理由，还能知道哪些信息不完整。若某项关键数据缺失，就应标明待核实，不能直接用零值参与排名。

数据关联也要经得起核对。地块、建筑与使用主体之间的关系没有确认，或者不同年份的数据被放在一起计算，都可能产生看似精确、实际难以解释的结果。发现差异后，应能返回来源查证。

系统筛选出的线索还要进入业务核查。对于证据不足或相互矛盾的地块，可以通过资料复核、实地调查和相关部门确认补充依据。核查结果应反馈到数据和识别规则中，后续地块情况发生变化时，也要及时更新。

这个例子的首期成果，可以是一组附带依据和核查状态的识别结果，以及支持它持续更新的工作安排。至于一块地是否最终认定为低效、是否适合再开发、如何处置，还需要相应的业务判断和程序，不能用筛选结果一并代替。

验收时，可以请实际使用者选取有代表性的地块，沿着数据来源、识别理由、核查反馈走一遍。除了检查结果，还要看一次更新能否顺利完成，发现错误后是否有人处理。

数据治理团队应对识别结果和使用支持负责；后续盘活土地的实际成效还受业务决策与实施条件影响，不宜全部算作系统上线就能交付的成果。

## 先做局部，也要为后续留下基础

暂缓土地全生命周期治理，意味着分阶段投入。首期仍应保留能够支持后续工作的基础信息，例如地块身份、空间范围、数据来源、时间版本和核查记录。

如果一期只在一份临时表格里维护地块名单，识别结果与原有地块无法稳定对应，后续再补充供应、建设和利用过程时，就可能从头核对。反过来，把当前需要的对象关系和来源记录清楚，经过业务核查的成果便有机会继续复用。

是否向全生命周期扩展，可以结合试点中暴露的业务需要判断。比如，业务人员不仅想知道哪些地块值得核查，还需要持续追踪其开发利用过程，现有数据又不足以回答，这就为下一阶段提供了具体任务。扩展应落实到新的用途、所需数据和责任安排，而不只是把原来延后的功能清单重新启动。

即使暂时不扩展，一期成果也需要维护。数据会更新，地块状况会变化，筛选依据也可能调整。首期立项时就应明确谁继续更新数据、谁复核异常，以及这些工作需要怎样的资源。

准备选择第一个场景时，可以先找未来真正使用成果的人，拿几块具体地讨论：得到哪些信息后，他能够作出什么判断；目前缺什么，谁能补上。谈清这些，再确定一期范围，比先列出一整套治理平台功能更有帮助。
