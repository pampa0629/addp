# 《人工智能（AI）100问》整体篇章评审

这份评审针对当前 Word 转换出的初步提纲，不评价尚未存在的正文。当前提纲已经覆盖人工智能的历史、机器学习、神经网络、大模型、智能体、工程基础、行业应用和未来趋势，适合作为素材池；它还不适合作为正式目录，主要原因是篇章边界和问题粒度仍需重构。书名确定为《人工智能（AI）100问》，但题目数量不要求严格等于 100。全书以科普为主线，同时要求技术描述精准、知识框架完整；有一定技术基础的读者也应能获得进一步收获。

## 已确认的编辑基线与下一步结构问题

### 1. 书名保留“100问”，题数不作为硬约束

按 Word 的标题样式统计，当前共有 9 篇、116 个二级条目。部分条目是补充笔记或待确认词组，并非完整问题；后续可以合并、拆分、迁移或删除，但不需要为了凑足或压缩到 100 而牺牲知识框架。工作阶段继续使用篇内临时编号，正式编号等篇章重构后再确定。

### 2. 采用科普主线，兼顾技术准确和框架完整

读者范围较宽，主线应让没有专业背景的读者能够理解；涉及模型、训练、工程和应用时，术语、关系和限制必须准确，不能用过度简化的比喻替代关键条件。有一定技术基础的读者，则应能通过完整的知识框架和延伸内容建立更系统的认识。

每一问可以采用分层表达：

1. 正文先回答问题，建立直观理解、概念边界和应用意义。
2. “延伸阅读”承载公式、算法细节、实现方法、工程权衡和进一步资料，避免主线被技术细节打断。
3. 与 ADDP、数据治理或时空数据相关的内容作为应用专题，明确这是应用视角，不把全书变成某个平台或某个行业的产品说明。

### 3. 稳定知识与快速变化的生态名词混在一起

“机器学习为什么能学习”“损失函数”“训练集与验证集”等内容相对稳定；MCP、skills、harness、智能体框架和本地部署工具变化很快。AI 巨头按本书约定主要讨论代表性人物，但人物选择仍需限定评价维度和时间范围。把稳定原理与快速变化的生态名词放在同一层级，会让目录很快过时。建议将全书分成“稳定原理”“工程方法”“应用专题”“持续变化的生态观察”四类，生态名词集中放在后者或附录，并在正文中注明适用时间。

## 篇章层面的观察

### 起源与概念篇

这是合适的开篇。“AI 有哪几大巨头”按本书约定主要讨论代表性人物，而不是公司名单；正文仍需限定“巨头”的评价维度和时间范围，避免把个人影响力、学术贡献、产业影响和企业排名混为一谈。

“AI 的三要素”统一采用算法、算力和数据这一口径，同时说明三者之间的依赖关系，避免与其他分类方式混用。“弱 AI、强 AI、超级 AI”“AI 与具身智能”适合保留，但应把概念定义、当前事实和推测性判断分开。

### 机器学习篇与神经网络基础篇

两篇的基本顺序合理，但分类维度交叉：按算法分类和按监督方式分类不是同一层级；“人工越多，智能越多”“垃圾进，垃圾出”也更像数据质量与人机协作的观点题。建议先给出一条清晰主线：数据与任务 → 学习范式 → 模型训练 → 评估和泛化，再把数据工程、标注和人类反馈分别放到对应位置。

“普通机器学习是否还有价值”和后面的“非大模型神经网络是否还有价值”存在重复，可以合并成一问，按任务、数据规模、成本、延迟和可解释性比较不同模型路线。

### 神经网络实用篇

当前把全连接、CNN、RNN、贝叶斯网络、GNN、扩散模型、GAN、强化学习放在一起，模型范式、应用领域和训练范式混杂。建议至少分成“判别与预测模型”“生成模型”“序列与图结构模型”“决策与控制”几个稳定小组；“CV 与 CNN 是否一回事”“NLP 与 RNN 的关系”属于概念关系题，应该服务于主线，不宜与具体模型名单并列。

“几个 benchmark 的开源 CNN 模型”过于依赖时间和版本，适合改成“如何选择模型和基准”，具体模型作为随正文更新的示例。

### 基础设施篇

这篇把数学、硬件、Python、AI Ops、ML Ops、数据标注、人类反馈和对齐放在一起，范围过宽。数学基础和硬件属于技术底座，Python 属于工具入门，MLOps 属于生命周期工程，标注、反馈和对齐属于数据与模型行为控制，建议拆分或分别归入相应篇章。

当前还缺少一条完整的模型生命周期：数据准备 → 训练 → 评估 → 注册与版本 → 部署 → 监控 → 反馈 → 再训练。仅列 AI Ops 和 ML Ops，读者难以看到这些概念怎样连成工程过程。

### 大模型篇

主体内容较完整，覆盖 Transformer、位置编码、token、注意力、微调、MoE、多模态、量化、蒸馏、部署和幻觉。但“注意力机制”“编码和解码”“KQV”“缓存命中”目前是悬空笔记，应整理为完整问题并统一 Q、K、V 的术语。

建议补充或明确以下内容：

- 预训练语料、数据治理、版权和隐私如何影响模型能力与风险。
- embedding、向量检索和向量数据库与 RAG 的关系。
- 推理成本、延迟、吞吐、上下文长度和 KV cache 的工程权衡。
- 大模型评估不能只看通用 benchmark，还要覆盖事实性、鲁棒性、安全性、偏见和业务任务效果。
- 提示词注入、工具权限和数据外泄等应用层风险，不能只用“幻觉”概括。

“迁移学习和蒸馏是什么关系”建议拆开：迁移学习是更大的方法范畴，蒸馏是模型压缩或知识迁移的一种具体方法。

### 智能体篇

这一篇抓住了当前应用热点，但现有条目更像技术名词清单：“LLM Wiki”“skills”“MCP”“harness”不宜直接作为面向读者的稳定问题。建议先建立智能体的稳定抽象：目标与任务分解、上下文、记忆、工具调用、检索、计划与执行、状态循环、权限与人工确认、可观测性与评估；然后把这些名词作为实现例子。LLM Wiki 可以作为一个新兴的知识组织模式单独解释：它把原始资料先编译成持久、互相链接、持续维护的知识库，再供检索或智能体导航使用；它是 RAG 的升级方向或组合模式，但不是没有治理要求的自动知识库。

还需要明确智能体与普通工作流、RAG 应用、函数调用和多智能体系统的边界，否则“有了大模型为什么还需要智能体”之后容易不断扩展概念。

### 扩展篇

这是目前最明显的“收纳篇”：AIGC、AI 编程、自动驾驶、数字人、边缘 AI、联邦学习、行业大模型、GIS、知识图谱、大数据、数据治理和企业应用属于不同维度。建议拆成至少两篇：

- **应用与行业篇**：AIGC、AI 编程、自动驾驶、数字人、边缘 AI、行业大模型、企业应用。
- **数据与组织篇**：联邦学习、高质量数据集、知识图谱、GIS/时空数据、大数据、数据治理和企业落地条件。

“Google 做的工作”以及“语义和本体”是原文补充笔记，当前不应作为正式目录项。

### 未来篇

世界模型、具身智能和液态神经网络可以组成前沿技术专题；数学发现、自主进化、AI Native、人的价值、取代人类则同时涉及研究判断、产品形态和社会议题。建议把“安全、责任与社会影响”单列一篇，把未来研究方向和价值讨论分开，避免把可验证的技术趋势与预测性观点混在同一篇。

## 当前提纲的主要缺口

以下内容在现有条目中没有形成足够明确的入口，建议在定稿前判断是否补入：

- **可靠性与评估**：任务指标、数据集划分、离线与在线评估、基准污染、业务验收、回归测试和持续评估。
- **安全与责任**：隐私、版权、偏见、公平、可解释性、对抗攻击、提示词注入、越权调用、审计和人工兜底。
- **推理工程**：服务化、批处理、缓存、量化、成本、延迟、吞吐、资源调度和故障降级。
- **数据与表示**：embedding、向量检索、数据合成、数据版本、数据血缘、数据契约和数据质量闭环。
- **任务类型**：推荐、时间序列、异常检测、因果推断或决策优化等非聊天任务，至少需要说明大模型并不覆盖全部 AI 问题。
- **开源与闭源路线**：模型 API、本地模型、开源权重、商业服务和供应商锁定之间的选择依据。
- **人机协作边界**：哪些环节适合自动化，哪些环节需要人工复核、审批或承担责任。

这些是结构缺口，不代表每项都必须新增为独立问题；可以合并进现有问题或用附录承载。

## 题目表达和术语清理

正式整理时，建议统一大小写、标点和问句形式，并优先处理以下明显问题：

| 原文 | 建议处理 |
| --- | --- |
| `ai`、`AI` 混用 | 统一为 `AI`，专有英文缩写保持统一大小写 |
| `embedding` 写成 `emboding` | 改为 `embedding`，并与“嵌入”建立对应关系 |
| `KQV` | 统一写作 `Q、K、V`，说明 Query、Key、Value |
| `reAct` | 统一写作 `ReAct` |
| `one shot`、`few shot` | 统一写作 `one-shot`、`few-shot`，并说明是否包含 zero-shot |
| `drop（剪枝？）` | 已确认是 dropout，改为讨论 dropout 与过拟合；不要与 pruning（剪枝）混称 |
| `还有那些重要的硬件？` | 改为“还有哪些重要的 AI 硬件？” |
| `端到端和段到段` | 核对是否都想表达“端到端”；若要区分概念，必须重新命名 |
| `AI自主进化ai` | 删除重复词并明确讨论对象 |
| `AI与gis` | 统一为 `AI 与 GIS` |
| `AI有哪几大巨头` | 改为生态角色或模型提供方的选择问题 |
| `大模型的反思，reAct` | 拆开“反思机制”和“ReAct 方法”，避免把不同层次概念并列 |
