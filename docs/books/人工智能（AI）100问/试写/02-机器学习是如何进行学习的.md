# 机器学习是如何进行学习的

机器学习中的“学习”并不是机器像人一样理解知识。人先确定模型要完成什么任务、会收到什么输入、应该给出什么输出，以及如何评价结果。训练程序再利用大量示例（即训练数据）调整模型的内部参数。训练的目标是让模型遇到没见过的新输入时，也能给出有用的结果。

## 先把任务说清楚

下面以有监督学习中的配送时间预测为例。业务方提供历史订单的出发地、目的地、下单时间、天气、交通状况和最终送达时间。模型的任务不是泛泛地“学习配送”，而是根据订单的特征，预测最终送达时间。有监督学习的训练样本包含已知结果；其他学习方式如何获得训练信号，本书将在后续问题中介绍。

如果业务方把目标改成“判断订单是否会超时”，模型要解决的就从回归问题变成了分类问题。如果业务方还希望系统决定把订单分配给哪辆车，系统就要解决决策或优化问题。任务定义不同，数据组织方式、损失函数和评价指标也会不同。

## 模型怎样找到规律

模型可以看成一个带有可调整参数的计算函数。训练开始时，模型的参数尚未调好，因此预测往往不准确。训练程序把训练样本输入模型，得到预测结果，然后把预测结果与样本的已知结果比较，算出误差。优化算法根据误差调整模型参数。这个过程反复进行后，模型在训练数据上的表现通常会逐步改善。

以线性回归为例，模型的计算方式可以写成：

```text
y' = b + w₁x₁ + w₂x₂ + … + wₙxₙ
```

其中，`x` 是输入特征，`w` 是特征对应的权重，`b` 是偏置，`y'` 是预测结果。训练线性回归模型时，优化算法要找到一组较合适的权重和偏置，使预测结果与真实结果之间的差异尽可能小。神经网络同样包含可调整的参数，但神经网络可以用多层结构和非线性变换表示更复杂的关系。

## 为什么能用于新数据

如果模型只记住训练样本，模型可以在这些样本上取得很高分，却无法处理新订单。这是过拟合的一种表现。训练的目标是让模型学到能够用于新数据的规律，这种能力称为泛化。训练数据只是用来学习的例子；模型还需要在没有参与训练的新订单上保持可接受的效果。

为了检查模型是否能够处理新数据，开发者通常把可用数据划分为训练集、验证集和测试集。开发者用训练集调整模型参数，用验证集比较不同方案并调整超参数，最后才用测试集估计模型面对新数据时的表现。如果开发者反复根据测试集结果修改模型，测试集的信息就会间接进入模型选择过程，最终评价可能过于乐观。

开发者还需要根据任务选择评价指标。评价配送时间预测时，开发者可以看平均误差；评价超时判断时，开发者可以同时关注精确率和召回率。如果漏掉一个高风险订单的代价远高于多提醒几个普通订单，开发者就不能只看总体准确率。

## 数据为什么决定学习的上限

模型只能依据提供给它的输入和目标寻找规律。历史数据存在错误标签、缺失字段、采样偏差或与未来环境不同，模型就可能学到不稳定甚至错误的关系。

“垃圾进，垃圾出”并不是说算法没有作用。这句话提醒开发者：模型训练前要检查数据是否能代表目标场景，标签是否表达了真正要优化的结果，以及训练数据和上线数据的分布是否存在明显差异。

人的参与也不会自动提高模型的表现。业务人员和开发者可以定义任务、补充标签、检查异常、选择评价标准和修正结果。任务目标是否更明确、训练数据是否更合适、评价结果是否更可信，决定了这些工作能否帮助系统可靠地完成任务。

## 延伸阅读

### 线性模型已经包含机器学习的主要结构

线性回归中已经有输入特征、权重、偏置、预测值、损失和参数更新这些核心元素。吴恩达的机器学习基础课程通过“模型描述”“代价函数”“梯度下降”和“线性回归的梯度下降”等小节，说明模型怎样根据特征作出预测，以及训练时怎样调整参数。[吴恩达机器学习课程（哔哩哔哩）](https://www.bilibili.com/video/BV164411b7dx/)

### 交叉验证与业务验收

当数据量有限或需要比较多个模型时，开发者可以使用交叉验证，观察模型在不同数据划分下的表现。留作最终评价的测试数据仍应保持独立。业务验收还要考察数据延迟、错误代价、人工复核、响应时间和成本等条件。scikit-learn 中文社区的译文说明了训练集、验证集、测试集的分工，以及反复使用测试集可能造成的信息泄漏。[交叉验证：评估模型表现（scikit-learn 中文社区）](https://scikit-learn.org.cn/view/6.html)

前面介绍的任务定义、训练和评价方法并不只适用于大模型。在结构化数据、低延迟和资源受限的场景中，线性模型、决策树等方法仍可能是更合适的选择。本书后续还会介绍不同机器学习方法的特点，并在神经网络篇中进一步讨论反向传播、激活函数和梯度下降。
