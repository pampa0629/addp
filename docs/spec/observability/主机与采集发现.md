主机与模块绑定、纳管接入、采集发现、引擎部署及 PostgreSQL／Redis／MinIO 专业来源以本专题为权威正文；共同身份、权限与交付边界见[总规范](../addp平台运行观测规范.md#三对象与模块边界)。章节号沿用总规范编号，命令在仓库根目录执行。


## 4.1 主机与服务绑定

主机保存 `display_name`、`node_kind=physical|virtual`、`addresses`、`enabled`、`version` 及 UTC 创建/更新时间。名称是可编辑属性，地址允许为空；`enabled` 表示纳管意图，不表示电源或网络状态。编辑采用版本 CAS；首期只停用纳管，不提供主机物理删除或关机。

主机的允许模块集合明确列举模块服务 Client 与模块名；“添加模块”表示允许这些服务声明部署于该主机，不是安装服务。集合为空不允许绑定，不能根据浏览器提交或来源标签自行扩权。

部署为实际所在进程注入 `ADDP_HOST_NODE_ID`。System 在首次登记时固定实例的节点声明，按当前主机状态和允许集合裁决 `unbound/bound/rejected`；同一实例重登记不得改挂主机。位置变化产生新实例身份，历史声明不反写。非法部署输入仅停用绑定并记录安全诊断，不阻断合法业务登记和续租；API 仍严格拒绝恶意或非规范请求。

缺少或失效的主机关联不阻断实例自身资源观测，也不改变租约。引擎部署的显式承载声明由 System 维护，首批单主机关联见 4.4；不以数据库地址、容器名或 VM 总消耗推断。

## 4.2 管理员确认的部署清单接入

唯一导出入口 `scripts/infra/node-metrics.py export-admission` 输出 `schema=addp.host-admission/v2`。默认核验已运行的本地 Linux/Docker Desktop 受控 node_exporter，包含主机和采集配置；显式 `--host-only` 只声明当前原生 macOS/Linux 宿主，不访问 Docker 或采集凭据，要求明确物理/虚拟类型。`--module` 可重复指定该宿主允许的 ADDP 模块，生成既有固定模块 Client 对应关系；不按进程名、地址或容器名发现承载，不包含 Business 租户引擎。

清单最多 16 KiB，根字段仅为 `schema/host` 和可选 `collection`。主机字段为 `display_name/node_kind/addresses/allowed_module_bindings`；采集存在时仅允许 `monitor_kind=host_resources`、`source.type=node_exporter` 及显式 HTTPS `/metrics` 端点。拒绝旧版本、未知字段、身份和凭据；空采集对象不等于省略。Desktop 来源声明独立 Linux VM，原生宿主不得据此归入 VM。名称与地址不作为稳定身份或自动合并键，清单本身不授予权限。

System `/host-admission` 是 Console 中唯一接入编排入口；独立模块打开该跨模块流程时先进入 Console，再接受草稿。管理员导入后预览并显式选择已有主机或按清单创建；已有主机不被改写，当前读取必须仍启用且类型匹配，创建仅用既有 `platform.host_node.create`。主机保存结果或当前读取结果生成 `ADDP_HOST_NODE_ID` 部署参数；只应用于实际部署在该宿主上的新进程，不修改全局 `.env`、不自动重启、不在线改挂已有实例。

采集可选。存在来源且用户有独立 Monitor 管理权限时，System 通过共享 Console 内存导航草稿将同一主机和来源交给 Monitor 原新建页面。草稿最多 4 KiB、60 秒、一次消费，绑定当前身份/权限及精确目的路由；只允许当前同源 iframe 取回，不写 URL、浏览器存储或最近访问。取消、另行导航、身份或权限变化、退出与超时均清除；端点仍由 Monitor 重新验证，不据草稿授予权限。页面刷新仅恢复 URL 中稳定主机 ID，不恢复未保存来源。

两个 Owner 分别写入：System 创建成功后冻结该主机，未知创建结果或版本冲突阻止再次创建并要求核验；明确拒绝可修正重试。转到 Monitor 后固定所交接的主机，只保存采集，不再创建主机；明确的采集失败仅重试该配置，未知结果或冲突先到原列表核验。清单与主机身份选择在授权/页面变化后失效，迟到响应不能恢复旧草稿。Monitor 原导入、主机创建编排及私有解析器删除，采集管理只消费已存在的 System 身份。

## 4.3 采集目标与认证发现

当前主机采集配置由 Monitor 管理，含主体、固定来源类型、受控端点、启停及独立版本。同一主体和类别最多一个启用来源。模块进程来源来自 System 首次登记的不可变采集声明，随当前租约自动投影，无需每次重启人工登记。

Prometheus 只通过 Monitor 的单一认证 HTTP SD 获取全量有界快照；不分页、不接受调用者标签。身份标签由控制面覆盖，按实际端点去重；已结束实例、停用主机或目标、失效绑定从成功快照移除。控制面失败返回错误，不伪装成功空列表。

发现刷新为 30 秒。Prometheus 在发现失败时可能保留旧快照，因此当前查询和告警仍重新裁决主体及配置；发现列表不能作为读取授权或即时停采保证。紧急阻断依靠凭据撤销或网络策略，历史按原身份与保留期存在。

主机列表与采集配置区分纳管、启停和实际采集结果；配置版本不符、证据过期或无资源读取权时不得沿用“最近成功”。列表按当前页一次去重批量读取，不逐行扇出、跨页预取或拆请求绕过预算；观测失败仍保留配置管理能力。

## 4.4 平台引擎部署登记

引擎部署属于平台运维对象，与租户 Engine Instance 分开。System `/platform/engine_deployments` 提供集合 POST 批量确认、GET 分页/详情和 PUT 管理更新，分配稳定 `deployment_id`；支持 Infra 与 Business 的标准单容器 PostgreSQL／Redis／MinIO，显式关联一个已纳管主机。其他服务只显示发现事实与未适配原因；集群多主机、云服务及租户引擎关联尚未开放。不接受 `tenant_id/engine_id`、连接凭据或 SQL，不从 Web 请求执行 Docker 或数据库探测。

“配置引擎监控”是管理部署监控开关的页面入口。弹窗按 Infra／Business 展示全部已经登记的部署及新发现候选，已登记行按稳定部署身份合并，来源缺失或不可用时仍可管理已有行。已登记行按实际 `enabled` 初始化勾选；首次勾选支持的新部署时须核对名称和实际承载主机，保存后登记并启用。未适配候选继续灰显。切换标签保留当前编辑，重新读取恢复服务端状态。详情只读展示监控配置，沿原权限与版本编辑名称和承载主机。停用仍保留部署记录和承载声明。来源项目、容器身份与数据库端口沿 4.5，Docker Desktop 只可关联 virtual 主机。

保存前列出拟启用及停用的引擎，提交只包含变动的行。首次登记沿原 POST 批次，已有部署沿原版本 PUT 逐项提交，分别遵守 create／update 和 host_node.read 权限。两种写入可在一次确认中顺序执行，失败停止后续提交；部分保存或结果未知时显示已确认的结果并要求重新读取核对，不自动重试。

实际采集状态单独展示。具备现有 Monitor 观测权限时，使用已启用且承载关联有效的部署读取一次既有引擎摘要，按部署身份核验，只展示返回的采集状态和时间。查询失败或超预算标为未知，不拆请求绕开预算，不阻断配置修改。

POST 仅接受 `items`，每次 1—16 个显式成员；成员为 `scope/service/fingerprint/display_name/enabled/declared_node_id`。服务端重读来源，验证 120 秒时效和预览事实摘要，再按来源键排序、整批事务写入；任何来源过期、变化、重复、主机无效或写入失败均整批回滚。摘要不含每次刷新时间，不代替持久资源版本。确认后的规范快照为 `addp.engine-deployment-inventory/v1`；旧根记录由前向迁移规范化，不改稳定身份、版本或不可变历史。

部署详情通过同一只读发现接口展示最近一次来源，按已确认的 Docker Engine、Compose 项目和服务匹配；不按名称、端口或地址猜测。来源过期、不可用、运行环境不符或服务未发现时不展示旧容器为当前结果；容器运行身份变化只更新来源展示，不改部署 ID、声明版本、主机关联或历史。容器运行状态不等于数据库可用或专业采集成功。来源单独刷新不清除管理草稿，也不解除写入冲突阻断；切换账号、对象或关闭详情后，迟到响应不得恢复旧来源。

来源按 Docker Engine ID、Compose 项目和服务唯一，停用也不可重复登记。PUT 仅接受名称、纳管意图、主机与当前 `version`，不接受客户端重写来源；实时运行变化由发现结果表达。列表只接受 `page/page_size/search/node_id/engine_type/scope`，scope精确限定infra或business，按已确认来源项目addp-infra或business在计数／分页前过滤；响应的只读scope由同一来源事实派生，不持久化第二份范围、不按显示名识别。类型精确限定postgresql、redis或minio并在计数／分页前过滤，名称按字面片段搜索，主机筛选按声明身份；详情不接受 query。请求正文最多 32 KiB，拒绝未知字段、重复键、大小写别名及附加 query。结果未知或来源变化时保留草稿并停止提交，必须显式重读核对，不自动重试创建。

创建与更新在同一 PostgreSQL 事务保存根版本、声明有效区间及统一审计；并发旧版本返回 409，不自动刷新版本重试。声明时间统一取数据库时间，表示管理员声明的生效/结束时刻，不能回填为实际部署历史。闭合历史不可更改或删除；首批不物理删除部署。读取在同一快照核对当前主机和部署纳管状态：有效关联为 `bound`，停用或 Desktop 主机类型变化为 `rejected`，保留原声明；这些状态均不表示服务在线、专业指标采集成功或租户业务可用性，不参与业务 Ready。

接口仅接受非委托 Platform User，独立 `platform.engine_deployment.read/create/update`，创建/更新还须 `platform.host_node.read`；迁移 000220 只向既有平台系统管理员发布三项权限，并沿既有触发器推进授权版本、撤销相关旧刷新族。其他角色、Tenant、Service、委托调用不因部署登记获得权限。界面保留冲突或失败输入；CAS 冲突和结果不明确时停止再次提交，只允许用户显式重新读取核对，首次登记则关闭后刷新列表，不构造已成功身份。

T0 权限目录/Swagger、T1 输入与身份拒绝、T2 PostgreSQL 唯一性/CAS/声明历史/审计回滚及权限前向迁移、System/Console 前端门禁沿现有注册自动发现。精确 T2 入口为 `make test-system-iam-postgres SYSTEM_IAM_POSTGRES_TEST_ARGS="--package repository --test engine-deployments"`、同参数的 `--package api`（HTTP Handler 与 PostgreSQL 审计事务）和 `--package migration`；本地须使用标准脚本核验的 `addp_iam_test`。产品接入 T4 与上述确定性验证分开登记，尚未通过不能写作真实运行已验收。

引擎监控入口先按部署来源分为“Infra 基础设施”和“Business 业务引擎”，默认Infra。两者仍是Platform运维对象，不表示Tenant范围或新增授权。每个范围以卡片展示当页已纳管的全部已支持引擎类型，卡片显示名称、类型、明确承载主机、实际采集状态和该类型四项摘要；不再以数据库类型下拉作为入口。沿System同一scope列表一次查询、每页20项，再沿Monitor既有混合类型摘要一次查询；不跨页预取、不逐卡片查询指标、不扩大100序列预算。搜索沿既有防抖／Enter与可见性规则，切换scope重置页码并清除原观测。URL保留scope、搜索与页码；详情按当前System事实校正scope与引擎类型，返回列表保持来源、搜索和页码。原按类型列表路径删除，详情固定指标目录、权限及采集来源不变。

## 采集来源统一部署分组（2026-11-04）

完整本地ADDP启动／重启负责恢复已启用且已安装的本机主机来源及Infra／Business引擎来源，再刷新部署事实；局部模块启动和Hosted精确进程启动不执行该恢复。主机沿唯一安装证明核验，只恢复匹配的既有容器；引擎沿原来源身份／账号核验，正常来源不重建。首次安装、证明失效、身份或输入变化、迁移及改账号／认证仍须部署者显式应用，不因应用重启扩大操作范围。Infra管理指标中心和本域专业来源，Business管理本域专业来源，主机每台部署一份，不因承载两域而重复部署。

全量本地启动结束输出一次监控摘要：复用Infra容器归属及运行／健康检查报告指标中心、已选择的控制入口，复用统一来源status列出主机及两域来源；服务进程运行与采样分开表达。该摘要只读，不读取业务数据、账号私钥内容或浏览器Token，不另建指标有效性判断；明确提示实际采样、关联与有效指标须在Monitor核对。恢复或摘要失败不阻止其他业务启动，但保留可选观测失败的非零退出状态；局部及Hosted启动不执行摘要，也不改变模块自身Ready条件。

当前只读状态与本次启动阶段结果分别表达：启动中遇到日志配置预检、指标配置预检、可选Infra健康、可选设施应用、日志端口读取或采集恢复失败时，在本次启动进程内保存固定阶段名称；末尾列出这些阶段及摘要自身失败，不回显原始错误或凭据，不以随后正常清除前序失败，也不将前序失败表述为当前来源仍失败。阶段记录不持久化、不重试操作；早期具体原因仍以当次原输出为证，当前检查正常不能补造历史根因。

主机恢复安装事实采用同一规范化比较：仅Docker HostConfig的 `Dns`、`DnsOptions`、`DnsSearch` 三个已存在字段允许将JSON null规范化为空数组，二者均表示未配置该容器的DNS覆盖，依据[Moby v28.5.1网络配置](https://github.com/moby/moby/blob/v28.5.1/daemon/container_operations.go#L63-L76)。非空数组、字段缺失、其他类型及其他HostConfig字段不作此归一化，仍严格比较；输入／容器／网络／挂载／安全身份不放宽。读取既有证明与新快照沿同一函数比较，健康检查不重写证明、不收养新容器，不为表示差异要求用户重建来源。

主机模板与 TLS 文件的跨次安装证明比较仅忽略 `st_dev`（文件系统设备号）的数值差异；该字段须仍为有效非负整数。内容摘要、inode、大小、mtime／ctime、文件模式、UID／GID、文件集合和路径继续精确核验，Docker Engine／内核、容器、网络、挂载、卷及安全事实不变。同次读取前后和同次安装／恢复操作中的稳定性核验仍包含设备号，防止读取或操作期间切换文件系统。该比较规则不重写证明，不重建健康来源，不为设备号单独变化要求重新应用。

### 采集项目与来源隔离

同一 Docker Engine 上的一套 ADDP 部署，主机、Infra 与 Business 专业采集来源共用固定名称 `addp-metrics-sources` 的 Compose 项目。分组仅用于部署呈现与操作组织，不改变平台／租户归属、数据库部署、指标中心、账号权限和采集协议。主机服务保留唯一名称；引擎采集服务以 scope 前缀区分。各来源私有声明仍是唯一部署输入，不另存集中配置副本。统一入口 `metrics-sources.py` 只依次操作选定来源，失败独立汇报。

共用项目不表示共用信任域：每个引擎来源保留专属私有卷、账号与证书，仅加入原数据库的明确私网；主机来源独立使用宿主／Desktop 网络视图。PostgreSQL Exporter 与 mTLS 入口继续分容器，数据库凭据不交给入口容器。Redis／MinIO 与 CDC 固定来源统一使用各自精确采集镜像中的工具读取及初始化本方私有卷，不借用被监控引擎的镜像，不挂载引擎数据卷。读取辅助容器以非 root、无网络、只读卷运行；初始化辅助容器仅在本方私有卷使用 root 与 CHOWN，运行中的采集进程仍为非 root、只读文件系统。Redis／MinIO 安装声明必须标记私有卷工具来自采集镜像；旧 scratch 采集安装须由部署者显式 `up`，不自动迁移或退回引擎镜像。所有查询、清理和恢复必须同时限定项目及明确服务集，并核验工作区、scope、当前数据库身份；禁止项目级 `down`、`--remove-orphans`、跨来源清理和自动采用同名陌生资源。选择单个来源不得启动、重建或停止其他来源。

### 旧来源退役边界

原带工作区摘要的项目仅允许显式 `up` 中按来源退役：先核验所选服务的容器、工作区／scope、专属卷和主机私有网络归属，全部通过才精确移除该来源，再沿固定名称部署。遇到未知资源立即拒绝；不删除数据库、业务卷或指标历史。不保留旧发现／旧恢复路径；普通 `recover` 遇到旧安装声明应提示显式应用，不构建镜像、不迁移、不重新安装账号。应用失败只清理当次来源，不声称整批回滚或无采集间断。实际采集成功仍须 Monitor 验证。

## 4.5 部署侧自动发现来源

### 快照读取、发布与访问

唯一 Docker 读取入口为 `scripts/utils/deployment-inventory.py`。Infra、普通 Business 启停和开发启动按各自作用域刷新。部署侧仅访问本地 Unix Socket Context 的 Linux Docker 或 macOS Desktop Linux VM，按 Compose project 与 working_dir 核对当前工作区。最多读取 128 个容器、64 个服务，每服务最多 16 个容器，每容器最多 64 个实际端口。每条 Docker 命令最多 10 秒，整轮最多 30 秒，前后核对 Engine 身份及服务运行身份、状态、启动时间、重启次数和端口。

`addp.deployment-discovery/v2` 快照最多 256 KiB，以 UTC 标明读取时间，分别发布 `scope=infra|business` 和 `state=available|unavailable`。独占私有目录内按作用域加锁，使用私有临时文件原子替换。发布失败不留半份结果，来源失败发布不可用并清除有效候选。成功空集合与不可用分开，未知组件只标记未分类。快照不含环境变量、密码、SQL、租户或授权，不按容器事实推断集群、主机关联或专业观测能力。部署读取器不调用 System API 或数据库。

System `GET /platform/engine_deployments/discovery` 仅接受有 `platform.engine_deployment.read` 的非委托 Platform User，无 query 或 body。只读 `ADDP_DEPLOYMENT_DISCOVERY_DIR` 下固定的两份快照。开发入口注入工作区私有目录，其他部署缺少配置时明确标记。读取校验私有目录和普通文件的类型、权限及大小，拒绝符号链接、错误作用域、身份或端口，以及重复或未知 JSON 字段。响应固定分列两域的未配置、缺失、不可用、过期或有效状态，单侧故障不清除另一侧有效结果。有效窗口 120 秒，来源时钟最多领先 30 秒，过期仅保留读取时间。Web 服务不执行 Docker 或接受调用者文件路径。候选读取不写纳管、历史或租户权限。[平台引擎部署登记](#44-平台引擎部署登记)

### 观测进程的启动与退出

- **启动**。Infra 启动观测器，Business 和开发启动幂等确保其存在，开发入口同时刷新两域。每轮完成后间隔 30 秒。观测器只继承 Docker 所需环境，不继承 ADDP／SQL 凭据或开发生命周期锁。私有运行记录、当次随机标识和实际命令共同证明 PID 归属。只有源码或 Docker 环境指纹变化时才替换已确认归属的进程，先确认旧进程退出。
- **就绪**。新一代在既有控制锁内校验并移除上一代 ready 后启动，仅等待本代首次发布。环境未变的幂等启动保留记录。就绪记录的文件类型、UID、私有权限、单链接和大小校验仍适用，避免把原子替换后的上一代零链接描述符当作就绪。启动记录发布失败须回收新子进程。
- **取消**。SIGTERM／SIGINT 仅锁存停止请求，通过非阻塞唤醒管道中断空闲等待。主循环、锁等待和读取在明确的检查点退出。Docker 命令只启动一次，分段等待同一子进程，不重置预算。取消先回收当次自有子进程，停止信号次数及期限沿原控制流程。
- **清理与取证**。观测器退出仅在即时取得快照锁时失效来源。Infra 停止控制方先核验归属和退出，再取锁立即使两域快照不可用。未知进程不得接管或停止，未确认退出保留运行记录。退出或失效未确认时报告失败，实际 Infra 停服仍继续，Hosted 不计零残留。只追加有界诊断，包括最后归属判定、Linux 进程状态及固定等待类型、SIGTERM 挂起／屏蔽／忽略／处理状态和直接子进程数。不可读或非 Linux 标为未知。诊断不输出命令行、路径、运行标识或原始 proc，不改变控制流程，根因仍须实际证据。

### 数据库专业来源的共同发现规则

PostgreSQL、Redis 和 MinIO 经同一 v2 快照发布专业来源。查找限定共享 `addp-metrics-sources` 项目和同域服务名。核对工作区 Owner、作用域、服务标签、当前数据库容器完整 ID 与启动时刻，以及唯一显式的 HTTPS `9443/tcp` 映射。只读发现核对前后运行事实，不读取环境、Secret、采集密码、TLS 文件或 SQL。专业来源状态独立于基础部署状态。[采集来源统一部署分组](#采集来源统一部署分组2026-11-04)

<a id="postgresql-source-pair-discovery"></a>

| 来源 | 容器和网络的独有约束 |
| --- | --- |
| PostgreSQL | 同域 `<scope>-postgres-metrics`（SQL Exporter）与 `<scope>-postgres-metrics-web`（mTLS 入口）各有一个运行中的常驻容器。入口共享 Exporter 网络命名空间，唯一端口映射记录在 Exporter，入口自身无发布端口。两者都缺失为 `not_deployed`。缺一侧、重复、身份／网络命名空间错配或端口不符为 `unavailable`。 |

### CDC 基础设施组件的自动发现

**组件身份与发布**。标准 Infra Compose 的 `redpanda` 和 `kafka-connect` 依现有只读发现自动纳入，每服务最多一个运行实例。稳定身份由 Docker Engine、标准项目和组件名构成，本次运行以完整容器 ID 和启动时刻区分。来源还须匹配工作区、服务、私网及唯一显式 HTTPS 端口。System 私有快照通过 `infrastructure_components` 发布状态和集合，`unavailable` 时返回空集合。无需创建引擎登记或主机关联。部署缺失、来源未启用、核验失败分别表达，容器重建后须重新匹配。PostgreSQL 继续沿引擎部署与原授权读取。

**统一准入与失败隔离**。主机、进程、引擎和 `cdc_resources` 共用 HTTP SD、mTLS、端点去重表和预算。身份快照或结构错误、重复声明或已解析物理端点、总预留超限及整批截止时间失败均拒绝整批。先按已声明启用或可用来源预留，完成所有地址解析和去重后，再以固定 IP 检查动态来源。单个动态来源的连接、解析、防护或采集探测失败只剔除自身，手工主机来源仍沿保存准入和运行时地址策略，解析失败也只剔除自身。禁止因剔除释放预留、重新解析、重试或沿用旧地址。实际运行状态仍按当前身份和采样表达。

**部署与采样**。仅 Infra 两类来源可用统一入口安装。未安装不自动创建，恢复精确匹配当前身份、TLS、配置及原采集镜像，失配时拒绝。私有卷及辅助容器沿[采集项目与来源隔离](#采集项目与来源隔离)，来源生命周期不管理组件数据卷、连接凭据或 Connector 配置，也不重启组件。Connect 只开放私网 Jolokia 只读采样，开发宿主访问须显式限于 `127.0.0.1`，不发布宿主原生 JMX 端口。[CDC 部署与恢复](../../../scripts/infra/docs/指标中心与来源.md#cdc-部署与配置)

通过 `sourceserver` 的单次完整投影和私有 mTLS `/metrics` 发布，无任意地址或 JMX 查询入口。共同截止时间 4 秒，每次上游响应最多 1 MiB，Redpanda 最多 4096 样本，Connect 最多 256 Connector／1024 Task。Jolokia 只读属性白名单，禁止 write、exec、list、search 和其他属性。超限、协议异常或必需读取失败使整个组件采集失败，不复用旧样本。空集合可成功，Jolokia 仅以 `404 + javax.management.InstanceNotFoundException` 表示无匹配 MBean，其他 404 或拒绝均为失败。仅发布固定聚合与有界标签，不发布 Connector、Topic、Group、MBean 名称、连接凭据、配置、事件正文或异常原文。[Jolokia 属性级权限](https://jolokia.org/reference/html/manual/security.html)

| 组件 | 固定来源、读数与缺样口径 |
| --- | --- |
| Redpanda | 仅读 `/public_metrics`。展示磁盘总量、空闲、使用率及不可用分区，详情显示消费组已提交分区数及待消费记录数。所有已提交分区都须有对应末端 offset 才发布积压。空消费组的分区数可为零，积压留空。 |
| Kafka Connect | 仅读 `/connectors?expand=status` 及两组 Jolokia 属性，Task 的 offset 提交失败比例、Debezium PostgreSQL streaming 的连接和延迟。固定目录为 Connector／Task 总数、失败数、运行／暂停 Task 数、有 offset 样本的 Task 数和最大失败比例、streaming／已连接及有延迟样本的 Connector 数和最大源端延迟。空 Connector 计数可为零，缺 streaming 或 offset 属性留空。失败比例为原生 0～1，展示可换算百分比。延迟从毫秒换算秒，`-1` 留空，其他负值保留表示时钟偏差。两项都不能代表整链路延迟或失败率。 |

**页面与访问边界**。唯一入口 `/cdc-resources` 以 `view=tasks|resources` 区分任务与运行资源。入口、页签和默认视图按当前 Tenant／Platform Context 及权限选择。跨域显式 URL 原样保留，只显示身份提示，不发起另一域请求。离开视图后禁止其继续规范化路由或请求数据。

- **Tenant 任务链路**。须同时有 `transfer.task.read` 和 `monitor.execution.read`。沿 Transfer 列表的 `change_detection=cdc` 服务端筛选与任务详情读取源／目标、当前代次和公开捕获状态，最近 execution 通过 Monitor 原授权详情读取 continuous 诊断并提供跳转。当前缓冲、源端槽及 WAL 风险、捕获延迟分别消费 `capture.buffer_observation`、`capture.postgresql_observation`、`capture.delay_observation` 的 Owner 投影及采样时间，与最近执行历史分开。暂停、失败、过期及各采样独立性沿正式契约。页面不推断来源、不按消费组 offset 重算、不以 Infra 数据库或组件极值代替任务事实。未启动、无任务、缺样和撤权分别表达，任务或 Context 变化及失败清除旧值。[任务源端指标](../tasks/Transfer数据库CDC.md#postgresql-任务源端指标) · [任务消息缓冲](../tasks/Transfer数据库CDC.md#任务消息缓冲持续观测)
- **Platform 运行资源**。须为有 `monitor.resource_observation.read` 的非委托 Platform User。只显示共享 Connect／Redpanda，常用指标直接展示，其余在卡片内展开。Redpanda 首页优先展示磁盘使用率、不可用分区及剩余磁盘，消费组积压不代表 Transfer 已应用进度。Infra PostgreSQL 保存任务、捕获登记、运行租约和目标提交后的同步位点。其连接、锁、容量沿引擎监控，数据库汇总槽和 WAL 不代替任务源端风险。Transfer 服务和 Continuous Worker 归服务监控。此入口不扩展引擎、主机或业务读取权。

**查询契约**。`GET /platform/cdc_resource_observations` 无 query，返回至多两个当前组件，区分发现不可用与成功空集合。`GET /platform/cdc_resource_trends` 只接受一个当前 `component_id`、该类型固定 `metrics`（最多十二项）及 RFC3339 `start/end`。仅读取当前容器 ID、启动时刻和受控地址的最多七天历史。即时集合总时序计入整批预算，两入口共用查询策略、并发和点数上限。每值要求唯一且同次抓取的 up 与 observed_at 证据，故障、过期或缺样不回用旧值。返回前重核身份与策略，变化即丢弃。响应限公开组件身份、类型、本次启动、采集状态及固定序列，Docker Engine、容器 ID、私网地址和凭据不公开。

**验收边界**。候选读取、持续发布、专业采集和授权查询分别验证。CDC 的确定性 T1 与真实组件 T2 沿标准门禁，容量专项在 34 目标基线上加入两个真实 CDC 来源，保留 36 个基线并验证 38／39 的全局边界和恢复。受控 HTTP SD 不计正式 System／Monitor 发现或页面通过。[CDC 隔离验证](../../../scripts/infra/docs/指标中心与来源.md#cdc-隔离验证) · [容量验收规则](../addp平台运行观测规范.md#62-资源查询与预算)

## 4.6 PostgreSQL 数据库侧汇总读取边界

首期支持 Infra 与平台自管 Business 的 PostgreSQL 15。数据库侧唯一活动版本为 `scripts/infra/postgres-observation/000003_replication_slots.sql`，由部署 Owner 通过来源生命周期安装。前两版是不可变历史，角色及固定函数沿同一事务前向升级，权限集合保持原范围。安装不进入 System IAM 迁移。[数据库侧安装入口](../../../scripts/infra/docs/指标中心与来源.md#postgresql-固定汇总边界)

### PostgreSQL 最小授权与认证

- 每实例分别使用 `addp_infra_observer` 或 `addp_business_observer`，密码独立。非登录的 `addp_observation_owner` 仅继承 `pg_read_all_stats`。采集 Login 无角色成员资格，只授当前维护连接库 CONNECT、私有 schema USAGE 和无参数 `addp_observation.snapshot()` EXECUTE。安装在单事务内核验作用域、SCRAM 校验值、身份标记、成员资格、schema／函数归属和 ACL。陌生对象、额外权限、PUBLIC 业务读权或不安全默认授权均拒绝并回滚。SCRAM 校验值由部署侧通过私有 stdin 的 psql 变量传入，原始密码不参与 SQL 文本，校验值不进入参数、普通配置、发现、System API 或日志。
- 函数使用固定 `pg_catalog, pg_temp` 搜索路径、全限定目录和固定 SQL，采集 Login 无权更改。只读默认值及三秒语句超时是附加约束。PUBLIC 授权可叠加，单角色 REVOKE 无法覆盖。安装只核查所连数据库，启用前须选无业务对象的维护库并限制跨库连接。不得全局撤销其他用户的权限，也不得以本库核验声称全实例业务隔离。[PostgreSQL 函数权限](https://www.postgresql.org/docs/15/sql-createfunction.html) · [统计角色](https://www.postgresql.org/docs/15/predefined-roles.html)
- `source.py` 生成唯一采集 Login 的 HBA 首部块。仅许可字面量维护库及显式私网／回环 CIDR 的 SCRAM，拒绝其他库、Unix socket 和物理复制连接，保留其他用户原记录。块内只声明作用域、维护库和有界规范 CIDR，无凭据。首部位置、归属、作用域、声明与规则须匹配。残缺标记、原块漂移、其他非注释记录含保留账号或超预算均拒绝。相同输入幂等，经验证的本方块才可按部署者显式输入更新 CIDR。维护库名按字面量引用，例如 `all` 不解释为通配符。HBA 只约束新会话，启用前须确认无遗留连接，遇未知会话拒绝且不自动终止。[PostgreSQL 15 HBA](https://www.postgresql.org/docs/15/auth-pg-hba-conf.html)
- 在同一数据库部署锁内，先停已核验的旧来源并复核当前容器、私网、账号归属及无旧会话。先安装 NOLOGIN，再原子更新并重载 HBA。确认无遗留会话后启用 Login，实际认证成功才启动来源。首次随机生成密码，后续沿用私有文件。现有账号丢失本方凭据时拒绝自动重置。停用仅关闭本方来源及 Login，保留函数、配置、历史和数据卷。失败不沿用旧来源或报告就绪。角色与 HBA 由部署 Owner 操作，System Web、普通发现和 Monitor 后台身份不承担写入职责。[账号与 HBA 准备](../../../scripts/infra/docs/指标中心与来源.md#postgresql-账号与-hba-准备)

### PostgreSQL 固定数据库汇总

函数只返回一行 19 个有类型字段。采集排除本次会话，不输出数据库、表、用户、PID、客户端地址或 SQL。[PostgreSQL 统计字段](https://www.postgresql.org/docs/15/monitoring-stats.html)

| 字段组 | 口径 |
| --- | --- |

## 4.7 PostgreSQL 受保护的固定指标来源

### PostgreSQL 配对传输与来源恢复

唯一 `scripts/infra/postgres-observation/lifecycle.py` 接入 Infra／Business 标准启停。两域配置和仓库外凭据独立，默认关闭，不随指标中心自动启用。选中来源须提供本域证书和显式监听，标准入口不分配端口、不签发 CA 或扩大信任。来源仅连接已核验的本机受管 PostgreSQL 15 私网地址。可选来源失败返回非零，核心服务继续运行。[配对部署与启停](../../../scripts/infra/docs/指标中心与来源.md#postgresql-配对部署与启停)

Business 运行 HBA 由部署者在仓库外的工作区专属目录维护，容器以只读父目录挂载，唯一文件为 `/etc/addp-postgres-auth/pg_hba.conf`。首次沿 `business/postgres/pg_hba.conf` 生成，后续保留经核验的采集块。只有运行文件仍与上次生成事实一致才可按新模板生成，拒绝外部改写或链接。内容变化在受管目录锁内按输入版本原子替换，保留属主和模式，内容相同保留 inode。目录准备不安装角色或重载数据库，也不证明采集已生效。Infra 继续使用数据目录中的 HBA。[Business 认证准备与拒绝边界](../../../scripts/infra/docs/指标中心与来源.md#postgresql-账号与-hba-准备)

- **SQL Exporter**。独占 T2 与正式模板共用 0.24.11 多架构固定摘要。配置由 `source.py` 生成，只调用 4.6 的函数，关闭 ping、缓存和动态目标。每作用域单连接、零空闲连接、四秒查询上限。密码只在部署者私有的只读来源配置内，避免进入环境、参数、发现或普通 DTO。SQL 仅限受控 Docker 私网，生产数据库 TLS 另行认证。[SQL Exporter 固定版本](https://github.com/burningalchemist/sql_exporter/tree/0.24.11)
- **mTLS 配对**。Exporter 只听共享网络命名空间内的 `127.0.0.1:9399`。Nginx 在 `9443` 提供 mTLS，只挂载服务端证书和 CA，与数据库密码隔离。两容器均使用非特权 UID／GID、只读文件系统、无 capabilities 和固定资源限制。仅允许无 query 的 GET `/metrics`。配置、重载、诊断及其他路径或方法拒绝。保持 `ssl_verify_client on`，缺失或校验失败的客户端证书将内部 496／495 映射为 403，不转发上游。准入只认可明确 TLS 证书拒绝或 HTTP 401／403，通用 400 不作保护证据。宿主端口只映射在 Exporter，配对缺失、重复、错配及运行身份规则统一见[配对发现](#postgresql-source-pair-discovery)与[只读配对排查](../../../scripts/infra/docs/指标中心与来源.md#postgresql-source-pair-troubleshooting)。
- **恢复**。全量开发启动在刷新快照前检查已选择且已安装的两域来源。单模块及 `ADDP_ONLINE_HOST=1` 入口不执行。健康且声明匹配时原样保留，仅恢复同一数据库容器的停止来源或更新其启动事实。锁内核对工作区、Engine、项目／服务、完整数据库容器 ID、私有状态、凭据、TLS、现有采集权限及固定快照，前后数据库事实变化即拒绝。新容器、停库、账号停用、权限／文件漂移、状态丢失或符号链接均拒绝自动接管。恢复仅读取既有授权，不安装、轮换或启用账号，不写或重载 HBA，不执行管理 SQL、签发证书或启动数据库。失败只清理本次拥有的来源，继续业务启动并保留失败结果。宿主或 Docker 未执行全量启动时，无无人值守恢复保证。[已安装来源恢复](../../../scripts/infra/docs/指标中心与来源.md#engine-source-recovery) · [全量启动范围](../addp平台运行观测规范.md#已安装引擎采集来源的统一恢复)

### PostgreSQL 采样、查询与验收范围

`source.py` 生成唯一 `addp_postgresql_` 指标目录，使用 4.6 的有类型汇总。时间为 Unix 秒、容量为字节、连接为数量，累计量使用 `_total`，`counter_epoch` 覆盖统计代际和服务启动。标签不包含数据库名、SQL 或租户。统计关闭不输出三个事务累计值，不补零。固定版 SQL Exporter 在 SQL 失败时仍可能返回 HTTP 200 和累计 `scrape_errors_total`，此时禁止输出旧数据库样本。up 只证明传输可达，累计错误数不直接表明当前失败。有效观测必须验证固定字段、当前运行身份及新鲜采样时间。

经 [4.5](#45-部署侧自动发现来源) 的 v2 快照进入 System 私有投影，沿 Monitor mTLS／CIDR／端口准入、端点去重和预算。缺失、停用、归属不明或容器变化只移除该来源，其他合法身份继续发布。模板不能直接登记成主机或租户 Engine。查询按当前 User 及 System 双侧权限裁决并在结束时重核，即时和最多七天趋势只读当前数据库容器运行段。采集器重启可沿同一数据库运行身份延续，数据库容器重建不拼接旧段。数据库进程重启或统计重置处按代际留空速率。[查询授权与预算](../addp平台运行观测规范.md#62-资源查询与预算) · [当前容器段](../addp平台运行观测规范.md#63-趋势时段比较与总览)

部署及门禁命令归 Infra 指南。数据库侧 T2 核验本库最小授权与认证，来源 T2 另核对双域生命周期、mTLS 拒绝、SQL 失败无旧样本、恢复时新采样、统计关闭及原文件恢复。目录准备、容器就绪和清理各自有证据，不能替代当前采样、授权查询或页面验收。正式身份 Hosted 已有固定版本的双域接入、查询／趋势及停源恢复记录，限该次范围。冷准备失败、Linux T2 复验和个人 Safari 另计，当前 HEAD、其他集群、自然留存与生产 T5 不能从原记录外推。[来源隔离验证](../../../scripts/infra/docs/指标中心与来源.md#postgresql-来源隔离验证) · [固定版本与实际结果](../testing/evidence/Monitor采集来源与引擎指标历史证据.md#pg-source-history) · [共享目录缺口](../testing/evidence/Monitor采集来源与引擎指标历史证据.md#pg-directory-history)

### 采集身份与部署边界

- Infra 用 `addp_infra_observer`，Business 用 `addp_business_observer`。不同物理实例的账号、密码和权限独立。采集容器只持有本方采集凭据，部署管理员凭据仅用于当次安装的 stdin，不传入来源、发现、命令参数或日志。
- 最小 ACL 从完整 reset 构建，仅允许 `HELLO`、`PING`、`INFO`。HELLO 用于 RESP3 认证，关闭客户端名称／版本上报、维护通知、重试及数据库切换。无键模式、频道或额外 selector，不授权命令类别、业务键、脚本、诊断或管理命令，包括 GET／SCAN／KEYS、CONFIG、ACL、CLIENT LIST、SLOWLOG、MONITOR 和写命令。停用须完整 reset/off，清除命令、键、频道和密码后拒绝既有及新会话读取。仅设 off 仍可能让既有会话保有命令权限。
- `INFO` 可读取实例级元数据，ACL 不提供 INFO 字段级限权，也不依赖已弃用的首参数规则。固定采集内核只请求 server、clients、memory、persistence、stats、errorstats 六个分区，输入最多 256 KiB。只发布固定数值、采样时间和私有代际，原始 INFO、键名／值、客户端或复制地址、路径、命令参数、凭据及错误原文不得进入 DTO、指标标签、普通错误或日志。采集不执行 INFO ALL、键扫描或慢日志读取。[Redis ACL](https://redis.io/docs/latest/operate/oss_and_stack/management/security/acl/) · [INFO](https://redis.io/docs/latest/commands/info/)
- 账号由部署 Owner 管理。数据卷私有目录中的本方记录仅含无凭据的随机 Owner 标识与账号规则，合入唯一原生 ACL。记录损坏时保留原业务认证并跳过可选账号，来源拒绝接管。已有账号无本方状态或凭据、容器或私网身份不符、记录损坏或权限漂移均拒绝，不能自动重置陌生账号。配置默认关闭且两域独立。来源只连接已核验的 Redis 私网地址，通过无 query 的 mTLS `GET /metrics` 暴露固定结果。来源故障不影响业务 Ready，持久化或清理失败须明确报告。[原生 ACL 与启停](../../../scripts/infra/docs/指标中心与来源.md#redis-原生-acl-与启停) · [配置与凭据](../../../scripts/infra/docs/指标中心与来源.md#redis-配置与凭据) · [既有来源恢复](../../../scripts/infra/docs/指标中心与来源.md#redisminio-恢复与校验)

### 固定指标与有效性

Redis 复用 `engine_resource_observations`、`engine_resource_summaries`、`engine_resource_trends`。按 System 当前用户有权读取的实际引擎类型选择目录，拒绝未知类型和跨类型指标，浏览器提交的类型、端点不构成授权。查询结束重核用户、部署版本、主机关联、容器与来源，传输和预算统一沿总规范。[资源查询与预算](../addp平台运行观测规范.md#62-资源查询与预算)

| 分组 | 固定目录 |
| --- | --- |
| 资源与连接（10 项） | 运行时长。分配内存、RSS、maxmemory、不计入限额的内存、参与限额的内存、限额占用率。当前／最大／阻塞连接。 |
| 吞吐与命中（7 项） | 一分钟处理命令、键命中、键未命中、淘汰、拒绝连接和 OOM 速率，以及一分钟键命中率。 |
| 持久化状态（5 项） | loading、AOF 开关、最近 RDB 保存、AOF 写入与 AOF 重写结果。 |

单次最多 12 项，详情仅查询当前组，趋势仅查询当前指标，禁止拆分全目录请求绕过预算。列表先按类型筛选再分页，Redis 每对象固定读取分配内存、限额占用率、当前连接和每秒命令四项，混合引擎摘要按每对象四项预留整批预算。类型、分组、指标和趋势范围沿原 URL 恢复，容量和时长用共享格式化，状态说明贴近指标。

- **快照**。来源 up 须唯一且为 1，必需字段来自同次 scrape，采样时刻贴近 scrape。有效 errorstats 分区内无 OOM 记录才按零处理。缺必需分区或字段、`ERRORSTATS_DISABLED`、重复字段或代际、非法整数或状态、非 standalone 模式、启动身份错配或快照不一致时拒绝相应快照，不补零或回用旧值。传输可达不证明 Redis 读取成功。
- **时间与速率**。趋势最多七天，限当前容器运行段。INFO 私有 `run_id` 须在采样前后相同，用于区分同容器内进程重启，来源自身重启不代表 Redis 重启。`run_id` 不公开为用户标签，不能替代当前容器、来源或主机关联的裁决。按 15 秒采集，完整一分钟窗口至少四个样本，两端完整新鲜、包含一分钟前边界、`counter_epoch` 一致且无可见重置，才计算计数速率和命中率。离散采样无法识别全部区间内重置。当前连接和命令包含采集连接与命令，表示实例整体值，阻塞连接数单独不足以判定故障。
- **比率**。限额占用率为 `(used_memory-mem_not_counted_for_evict)/maxmemory`，显示百分数且不裁剪到 100%。扣减超过分配内存则拒绝，maxmemory 为零时留空，不以宿主或容器内存补分母。该值不表达 RSS、硬限额或 OOM 保证。命中率按完整窗口的 hits／misses 增量计算，无查找增量时留空。
- **持久化**。布尔值为 0／1。AOF 开启时写入及重写结果都须来自同次采集且有效。关闭时仅两项结果缺省，其余指标继续按完整快照展示。RDB 返回 ok 只表达上次保存结果，不能确认配置启用或备份可恢复。
- **无定义原因**。仅当前授权且校验通过的即时响应处于 collecting、比率为 no_data 时，才用同一评估与采样时点的有效 maxmemory 精确零值，或同一完整一分钟的有效命中与未命中速率均为精确零，分别解释未设置上限和无键查询。四舍五入后的零、陈旧或缺失的依赖不作依据。指标卡与选中趋势旁只解释当前值，历史断点保留，证据不足或来源失败继续显示通用缺样。撤权或对象变更时清除，列表不补查依赖。

## MinIO 专业观测首期边界（2026-11-02 已确认）

### MinIO 采集身份与授权

- 两域各用独立的非 root 原生 Access Key，唯一内联策略为 `admin:Prometheus`。不授予 S3、内置 readonly／diagnostics 或 `admin:*`。这是 MinIO 内部身份，原生权限可能读取含桶级元数据的完整运维指标。来源的端点和字段过滤约束实际输出，与服务端权限分别核验。
- 采集侧只持该 Access Key／Secret Key，按原生 HS512 签发最长 300 秒的 JWT，`issuer=prometheus`、`subject=Access Key`。根凭据仅供当次部署管理，不交给采集容器。固定数值输出排除桶名、对象名及内容、节点地址、磁盘路径和原始响应。
- 固定版本的普通 `mc admin user svcacct enable/disable` 会移除内联策略。启停仅用同镜像的 `minio-observation-status`，通过锁定的管理 SDK 一次提交状态和唯一策略，并重读核验。工具只访问容器内回环 9000，凭据走私有 stdin，不接受自选端点、策略或其他管理操作。缺工具的镜像在创建账号前拒绝。固定原生读回把资源 `*` 存为 `**`，只认这一精确形状，不接受继承父账号策略。[MinIO 账号与凭据](../../../scripts/infra/docs/指标中心与来源.md#minio-账号与凭据)
- 部署 Owner 按工作区、作用域、Docker Engine、Compose 服务、镜像和数据卷核验归属，创建前持久化私有归属意图。名称、描述、parent 及内联策略须与本方事实相符。同卷重建可复用账号，异卷、外来身份、策略漂移或凭据丢失时拒绝接管。创建结果未知须先核对，不自动另建。来源默认关闭，准备失败保留现有来源，进入替换阶段后失败或停用则先清理本方来源和配置卷，再关闭本方 Key 并验证旧 JWT 被拒绝。失败须报告，MinIO 与业务 Ready 独立判定。配置、启停及私有材料处理统一见 Infra 指南。[部署配置与作用域](../../../scripts/infra/docs/指标中心与来源.md#minio-部署配置与作用域) · [启停与失败清理](../../../scripts/infra/docs/指标中心与来源.md#minio-启停与失败清理)

### MinIO 原生读取、指标与缺项

来源仅读已核验的当前私网 IP:9000。原生指标固定访问 `/minio/metrics/v3` 下的 `/system/process`、`/cluster/health`、`/cluster/usage/objects` 和 `/api/requests`。整轮最多 3 秒、5 次读取，含采集后重读进程边界。每响应最多 256 KiB、4096 样本，关闭重定向、代理、重试及任意 DNS。前后启动时刻须一致、运行时长不得回退，整轮失败不回用旧值。仅将同容器按 S3 操作名分片的同一计数或在途值求和。标签限原生 server／name／type 并核对 `type=s3`，拒绝重复、额外主体或非法数值。输出前移除原生标签，仅保留固定数值、采集时间、独立的扫描时间及按部署与进程启动计算的私有计数代际。跨端点读取不承诺原子性。

来源与 Redis 共用固定 HTTP／TLS 服务内核，非 root、只读、0.25 CPU／128 MiB。mTLS TLS 1.3 仅允许无 query 或请求体的 `GET /metrics`，单并发，失败返回 503 且无失效数据。证书由部署方提供，来源不签发 CA。私有材料及网络边界见[部署配置与作用域](../../../scripts/infra/docs/指标中心与来源.md#minio-部署配置与作用域)。

| 分组 | 固定目录 |
| --- | --- |
| 容量与状态（10 项） | 进程运行时长、在线与离线盘数、可用总容量和剩余容量、空间占用率、最近扫描的对象容量／对象数／桶数／统计距今秒数。 |
| 请求与流量（7 项） | S3 请求速率、在途数、4xx／5xx 错误速率、5xx 占比、S3 发送与接收字节速率。 |

来源只输出原始数值，由唯一查询层计算速率及占比。即时、摘要、趋势复用引擎资源查询的当前用户重核、当前容器段及最多 12 项预算。详情只读选中分组，列表固定为总容量、剩余容量、空间占用率与请求速率四项，不跨部署合计。显示、图例、视口及刷新沿[资源查询与预算](../addp平台运行观测规范.md#62-资源查询与预算)和[趋势与展示口径](../addp平台运行观测规范.md#63-趋势时段比较与总览)。

- **来源有效性**。同次唯一 `up=1`、`observed_at`、进程 `start_time` 与 `uptime` 均须有效，启动时间在当前容器边界后且不晚于采集时刻。核验字段唯一、非负及同次采样。MinIO 的 procfs 启动估算与应用运行时长使用不同基准，不以 `start_time + uptime` 等于采集时刻为条件。当前来源或权限失效时清除即时值，保留仍合法的历史点。
- **缺项**。固定版本 `MetricValues.Set` 仅发布大于零的值。离线盘、在途或 5xx 为零时可无系列，尚未扫描也可无对象统计。HTTP 200 或 UP 只表明相应读取成功，不能证明 17 项齐全。单项分别验证唯一系列、非负值和同次采样，缺席留空，不清除其他有效项、补零或改用 v2／其他接口。明确零值须另有可靠生产端事实。
- **容量与扫描**。空间占用率须总容量大于零且剩余不超总量。容量是 MinIO 可见存储，不能解释为对象占用或独占物理盘，两个 Desktop 部署共享底层时不相加。对象统计须有同次合法的最近扫描时间，距今按查询评估时刻计算，允许扫描早于本次容器启动。新鲜 scrape 不证明最近扫描同样新鲜，扫描统计不参与实时健康或告警。
- **速率与错误**。一分钟窗口须完整、至少四样本、无重置，`counter_epoch` 与启动身份一致。5xx 占比还要求请求增量大于零，错误增量不超请求增量。4xx 仅按客户端错误口径展示，不能单凭它判定存储故障。

### 证书预检与 MinIO 验收入口

采集 HTTPS 入口沿 Infra 统一严格证书预检。保留各来源目录、文件预算和保护规则，PostgreSQL 仍用原三文件目录和两容器部署，SQL 连接独立。非自签发叶证书 AKI 与 CA SKI 沿严格链校验，叶证书 SKI 可选。只核验本地材料，不新增网络请求或使既有安装证明失效。诊断仅取当次 OpenSSL 标准错误码及本地公钥比较，最多解析 4 KiB、8 条标准错误行。未知码、分类冲突、无依据或超预算均报未确认，保留原阶段、非零退出和清理结果。实际 mTLS、客户端认证及新鲜样本仍须验证。[证书预检](../../../scripts/infra/docs/指标中心与来源.md#证书预检)

固定版本的隔离来源 T2、受控查询与页面、个人 Safari 实测各自认定。受控前端步骤通过但整 Job 取消的记录保持原结论。全指标、七天趋势、跨 Docker 停机恢复和正式身份 Hosted 全链路仍缺独立通过证据。部署可用、账号准备、清理和实际页面覆盖按各自回执认定。[MinIO 采样发现与验证](../../../scripts/infra/docs/指标中心与来源.md#minio-采样发现与验证) · [分层历史证据](../testing/evidence/Monitor采集来源与引擎指标历史证据.md#minio-source-history)

## 4.8 服务部署预期与分组租约观测

服务失联的预期来源唯一属于标准部署入口。受管目录中的 `service-expectations.json` 使用 `addp.service-expectations/v1`，包含工作区摘要 `deployment_id`、单调递增的 `revision` 和按模块／角色／用途排序且唯一的 `groups`。每组仅含 `module_name`、`role=backend|worker`、`runtime_name`、`expected_replicas`（1—1000）、`desired_state=running|planned_stopped` 与 UTC `changed_at`；Backend 用途为空，Worker 必须与正式登记的用途相同。最多1000组、256 KiB，重复键、未知字段、非法或未来时间拒绝。发布器沿既有私有目录、所有权检查、互斥锁与原子替换；相同声明重发不推进版本或时间，局部启停保留其他组，失败保留旧文件。组实质变更的changed_at使用真实UTC微秒且严格晚于该组原值，拒绝停滞／回退时钟，不合成未来时间；同秒停用、重启或副本变更不得复用旧标记。没有存活进程扫描、手工管理第二路线或个人服务自动启停。

用途对应 Meta `scan`、Transfer `sync`／`continuous_sync`、Quality `quality-bounded`；Backend 按角色分组，Security Worker 不在本批新增范围。`metadata.runtime_name` 可随再次登记更新，不能直接作为不可变部署身份；用途缺失或不规范时不得按模块名、PID、IP 或其他用途补算。分组与当前在线副本以 System 同一时点裁决为准，分组变化中断连续窗口，不改写旧事件证据。

System 在唯一 `/runtime/observability-identities` 中只读提供 `service_groups`：声明身份／版本、同一控制面 `observed_at` 及每组预期、正式登记总数与当前在线副本数。在线仅表示登记状态UP且租约晚于同一观测时间，不要求绑定主机或已接指标；不同Worker用途不互代。读取声明前后内容变化时清除该子域。全域状态为 `available/unconfigured/unavailable`；可读组为 `observed`，计划停用或模块停用为 `paused`，模块未登记或活跃Worker用途不明为 `unknown`。零在线只是租约事实，不在System产生失联／恢复结论。组候选最多10000个登记，共用原五秒／四MiB预算；仅组文件异常或组预算耗尽使子域不可用，数据库事务失败仍拒绝整份投影。Common客户端核验可解码子域的形状和时间，非法子域清为空的不可用状态，保留合法的独立资源身份；响应JSON无法解码或原控制面身份异常仍拒绝整份响应。

模块 `enabled` 不代表某类 Worker 已部署，缺席或历史登记总数不能推断应运行，也不授予运行确认资格。持久预期不随发布器退出自动过期，计划停用必须明确发布。

该私有观测投影沿现有固定 Monitor 后台身份读取，本投影不新增角色、权限、凭据或浏览器 DTO。标准开发／生产停止入口先发布所选模块的计划停用，失败立即退出，尚不停止任何服务。

开发启动使用所选后端及正式Worker单元，生产启动使用当前Compose与Profile声明，不由存活进程反推预期。Compose声明副本取规范化的scale／deploy.replicas，两者不一致拒绝；零副本或未选Profile不声明运行，完整计划将已有但不再选中的组置为计划停用，局部开发启动仍保留其他组。启动发布故障沿可选观测边界报告，核心启动继续，不能把原声明解释为本次启动成功。

生产System的受管目录只读挂载独立于指标开关且只有一个所有者，标准操作沿既有工作区生命周期锁串行。停止与启动读取同一根 `.env` 目录配置，局部停止仅改所选模块；计划停用发布失败不停止进程、不卸载 launchd、不执行 Compose down。文件发布不证明真实启动就绪或停止成功。

首次运行确认、连续窗口与告警规则管理权限统一见 [7.1.1](../addp平台运行观测规范.md#711-服务组失联规则)；部署声明和组计数只提供事实，失联／恢复仍由 Monitor 按该规则判定，不能把文件发布或零在线直接当作告警验收。

### 开发 Backend 启动失败

标准开发入口在成功发布运行预期后，为所选 Go Backend 开始本次尝试。受管目录中的 `service-startup-results.json` 使用 `addp.service-startup-results/v1`，以同一 `deployment_id` 和模块定位最近尝试，保留尝试标识、开始时间及可选失败时间和固定原因 `build_failed`、`process_exited`、`readiness_timeout`。选择性重试只替换所选模块，旧尝试不得写入新尝试。只记录实际执行到的检查，进程退出优先于同次就绪超时；不公开原始错误、命令、路径、PID 或凭据。无明确结果、未执行、探测暂停或文档无法核验不产生失败。生产、Worker、Agent 和 Copilot 另行接入。

System 按同一部署和当前 Backend 运行预期核验，并剔除计划停用、已被有效在线实例或失败后登记覆盖的记录。标准生产入口使用同一发现目录时清除开发结果，不把它作为生产部署的结果。只读 `GET /api/v1/system/platform/module_startup_failures` 复用一方平台用户和 `platform.module.read`，返回模块、失败时刻及固定原因。服务监控在原权限下独立展示，不插入实例列表或影响其分页。本投影不进入失联告警、租约或就绪判定。控制面未就绪时由启动终端提供诊断。
