[返回平台运行观测总入口](../addp平台运行观测规范.md#四主机接入与采集发现)

主机与模块绑定、纳管接入、采集发现、引擎部署及 PostgreSQL／Redis／MinIO 专业来源以本专题为权威正文；共同身份、权限与交付边界见[总规范](../addp平台运行观测规范.md#三对象与模块边界)。章节号沿用总规范编号，命令在仓库根目录执行。


## 4.1 主机与服务绑定

主机保存 `display_name`、`node_kind=physical|virtual`、`addresses`、`enabled`、`version` 及 UTC 创建/更新时间。名称是可编辑属性，地址允许为空；`enabled` 表示纳管意图，不表示电源或网络状态。编辑采用版本 CAS；首期只停用纳管，不提供主机物理删除或关机。

主机的允许模块集合明确列举模块服务 Client 与模块名；“添加模块”表示允许这些服务声明部署于该主机，不是安装服务。集合为空不允许绑定，不能根据浏览器提交或来源标签自行扩权。

部署为实际所在进程注入 `ADDP_HOST_NODE_ID`。System 在首次登记时固定实例的节点声明，按当前主机状态和允许集合裁决 `unbound/bound/rejected`；同一实例重登记不得改挂主机。位置变化产生新实例身份，历史声明不反写。非法部署输入仅停用绑定并记录安全诊断，不阻断合法业务登记和续租；API 仍严格拒绝恶意或非规范请求。

缺少或失效的主机关联不阻断实例自身资源观测，也不改变租约。引擎部署的显式承载声明由 System 维护，首批单主机关联见 4.4；不以数据库地址、容器名或 VM 总消耗推断。

## 4.2 管理员确认的部署清单接入

唯一导出入口 `scripts/infra/node-metrics.py export-admission` 输出 `schema=addp.host-admission/v2`。默认核验已运行的本地 Linux/Docker Desktop 受控 node_exporter，包含主机和采集配置；显式 `--host-only` 只声明当前原生 macOS/Linux 宿主，不访问 Docker 或采集凭据，要求明确物理/虚拟类型。`--module` 可重复指定该宿主允许的 ADDP 模块，生成既有固定模块 Client 对应关系；不按进程名、地址或容器名发现承载，不包含 Business 租户引擎。

清单最多 16 KiB，根字段仅为 `schema/host` 和可选 `collection`。主机字段为 `display_name/node_kind/addresses/allowed_module_bindings`；采集存在时仅允许 `monitor_kind=host_resources`、`source.type=node_exporter` 及显式 HTTPS `/metrics` 端点。拒绝旧版本、未知字段、身份和凭据；空采集对象不等于省略。Desktop 来源声明独立 Linux VM，原生宿主不得据此归入 VM。名称与地址不作为稳定身份或自动合并键，清单本身不授予权限。

System `/host-admission` 是 Console 中唯一接入编排入口；独立模块打开该跨模块流程时先进入 Console，再接受草稿。管理员导入后预览并显式选择已有主机或按清单创建；已有主机不被改写，当前读取必须仍启用且类型匹配，创建仅用既有 `platform.host_node.create`。主机保存结果或当前读取结果生成 `ADDP_HOST_NODE_ID` 部署参数；只应用于实际部署在该宿主上的新进程，不修改全局 `.env`、不自动重启、不在线改挂已有实例。

采集可选。存在来源且用户有独立 Monitor 管理权限时，System 通过共享 Console 内存导航草稿将同一主机和来源交给 Monitor 原新建页面。草稿最多 4 KiB、60 秒、一次消费，绑定当前身份/权限及精确目的路由；只允许当前同源 iframe 取回，不写 URL、浏览器存储或最近访问。取消、另行导航、身份或权限变化、退出与超时均清除；端点仍由 Monitor 重新验证，不据草稿授予权限。页面刷新仅恢复 URL 中稳定主机 ID，不恢复未保存来源。

两个 Owner 分别写入：System 创建成功后冻结该主机，未知创建结果或版本冲突阻止再次创建并要求核验；明确拒绝可修正重试。转到 Monitor 后固定所交接的主机，只保存采集，不再创建主机；明确的采集失败仅重试该配置，未知结果或冲突先到原列表核验。清单与主机身份选择在授权/页面变化后失效，迟到响应不能恢复旧草稿。Monitor 原导入、主机创建编排及私有解析器删除，采集管理只消费已存在的 System 身份。

## 4.3 采集目标与认证发现

当前主机采集配置由 Monitor 管理，含主体、固定来源类型、受控端点、启停及独立版本。同一主体和类别最多一个启用来源。模块进程来源来自 System 首次登记的不可变采集声明，随当前租约自动投影，无需每次重启人工登记。

Prometheus 只通过 Monitor 的单一认证 HTTP SD 获取全量有界快照；不分页、不接受调用者标签。身份标签由控制面覆盖，按实际端点去重；已结束实例、停用主机或目标、失效绑定从成功快照移除。控制面失败返回错误，不伪装成功空列表。

发现刷新为 30 秒。Prometheus 在发现失败时可能保留旧快照，因此当前查询和告警仍重新裁决主体及配置；发现列表不能作为读取授权或即时停采保证。紧急阻断依靠凭据撤销或网络策略，历史按原身份与保留期存在。

主机列表与采集配置区分纳管、启停和实际采集结果；配置版本不符、证据过期或无资源读取权时不得沿用“最近成功”。列表按当前页一次去重批量读取，不逐行扇出、跨页预取或拆请求绕过预算；观测失败仍保留配置管理能力。

## 4.4 平台引擎部署登记

引擎部署属于平台运维对象，与租户 Engine Instance 分开。System `/platform/engine_deployments` 提供集合 POST 批量确认、GET 分页/详情和 PUT 管理更新，分配稳定 `deployment_id`；支持 Infra 与 Business 的标准单容器 PostgreSQL／Redis／MinIO，显式关联一个已纳管主机。其他服务只显示发现事实与未适配原因；集群多主机、云服务及租户引擎关联尚未开放。不接受 `tenant_id/engine_id`、连接凭据或 SQL，不从 Web 请求执行 Docker 或数据库探测。

“配置引擎监控”是管理部署监控开关的页面入口。弹窗按 Infra／Business 展示全部已经登记的部署及新发现候选，已登记行按稳定部署身份合并，来源缺失或不可用时仍可管理已有行。已登记行按实际 `enabled` 初始化勾选；首次勾选支持的新部署时须核对名称和实际承载主机，保存后登记并启用。未适配候选继续灰显。切换标签保留当前编辑，重新读取恢复服务端状态。详情只读展示监控配置，沿原权限与版本编辑名称和承载主机。停用仍保留部署记录和承载声明。来源项目、容器身份与数据库端口沿 4.5，Docker Desktop 只可关联 virtual 主机。

保存前列出拟启用及停用的引擎，提交只包含变动的行。首次登记沿原 POST 批次，已有部署沿原版本 PUT 逐项提交，分别遵守 create／update 和 host_node.read 权限。两种写入可在一次确认中顺序执行，失败停止后续提交；部分保存或结果未知时显示已确认的结果并要求重新读取核对，不自动重试。

实际采集状态单独展示。具备现有 Monitor 观测权限时，使用已启用且承载关联有效的部署读取一次既有引擎摘要，按部署身份核验，只展示返回的采集状态和时间。查询失败或超预算标为未知，不拆请求绕开预算，不阻断配置修改。

POST 仅接受 `items`，每次 1—16 个显式成员；成员为 `scope/service/fingerprint/display_name/enabled/declared_node_id`。服务端重读来源，验证 120 秒时效和预览事实摘要，再按来源键排序、整批事务写入；任何来源过期、变化、重复、主机无效或写入失败均整批回滚。摘要不含每次刷新时间，不代替持久资源版本。确认后的规范快照为 `addp.engine-deployment-inventory/v1`；旧根记录由前向迁移规范化，不改稳定身份、版本或不可变历史。

部署详情通过同一只读发现接口展示最近一次来源，按已确认的 Docker Engine、Compose 项目和服务匹配；不按名称、端口或地址猜测。来源过期、不可用、运行环境不符或服务未发现时不展示旧容器为当前结果；容器运行身份变化只更新来源展示，不改部署 ID、声明版本、主机关联或历史。容器运行状态不等于数据库可用或专业采集成功。来源单独刷新不清除管理草稿，也不解除写入冲突阻断；切换账号、对象或关闭详情后，迟到响应不得恢复旧来源。

来源按 Docker Engine ID、Compose 项目和服务唯一，停用也不可重复登记。PUT 仅接受名称、纳管意图、主机与当前 `version`，不接受客户端重写来源；实时运行变化由发现结果表达。列表只接受 `page/page_size/search/node_id/engine_type/scope`，scope精确限定infra或business，按已确认来源项目addp-infra或business在计数／分页前过滤；响应的只读scope由同一来源事实派生，不持久化第二份范围、不按显示名识别。类型精确限定postgresql、redis或minio并在计数／分页前过滤，名称按字面片段搜索，主机筛选按声明身份；详情不接受 query。请求正文最多 32 KiB，拒绝未知字段、重复键、大小写别名及附加 query。结果未知或来源变化时保留草稿并停止提交，必须显式重读核对，不自动重试创建。

创建与更新在同一 PostgreSQL 事务保存根版本、声明有效区间及统一审计；并发旧版本返回 409，不自动刷新版本重试。声明时间统一取数据库时间，表示管理员声明的生效/结束时刻，不能回填为实际部署历史。闭合历史不可更改或删除；首批不物理删除部署。读取在同一快照核对当前主机和部署纳管状态：有效关联为 `bound`，停用或 Desktop 主机类型变化为 `rejected`，保留原声明；这些状态均不表示服务在线、专业指标采集成功或租户业务可用性，不参与业务 Ready。

接口仅接受非委托 Platform User，独立 `platform.engine_deployment.read/create/update`，创建/更新还须 `platform.host_node.read`；迁移 000220 只向既有平台系统管理员发布三项权限，并沿既有触发器推进授权版本、撤销相关旧刷新族。其他角色、Tenant、Service、委托调用不因部署登记获得权限。界面保留冲突或失败输入；CAS 冲突和结果不明确时停止再次提交，只允许用户显式重新读取核对，首次登记则关闭后刷新列表，不构造已成功身份。

T0 权限目录/Swagger、T1 输入与身份拒绝、T2 PostgreSQL 唯一性/CAS/声明历史/审计回滚及权限前向迁移、System/Console 前端门禁沿现有注册自动发现。精确 T2 入口为 `make test-system-iam-postgres SYSTEM_IAM_POSTGRES_TEST_ARGS="--package repository --test engine-deployments"`、同参数的 `--package api`（HTTP Handler 与 PostgreSQL 审计事务）和 `--package migration`；本地须使用标准脚本核验的 `addp_iam_test`。产品接入 T4 与上述确定性验证分开登记，尚未通过不能写作真实运行已验收。

引擎监控入口先按部署来源分为“Infra 基础设施”和“Business 业务引擎”，默认Infra。两者仍是Platform运维对象，不表示Tenant范围或新增授权。每个范围以卡片展示当页已纳管的全部已支持引擎类型，卡片显示名称、类型、明确承载主机、实际采集状态和该类型四项摘要；不再以数据库类型下拉作为入口。沿System同一scope列表一次查询、每页20项，再沿Monitor既有混合类型摘要一次查询；不跨页预取、不逐卡片查询指标、不扩大100序列预算。搜索沿既有防抖／Enter与可见性规则，切换scope重置页码并清除原观测。URL保留scope、搜索与页码；详情按当前System事实校正scope与引擎类型，返回列表保持来源、搜索和页码。原按类型列表路径删除，详情固定指标目录、权限及采集来源不变。

## 采集来源统一部署分组（2026-11-04）

完整本地ADDP启动／重启负责恢复已启用且已安装的本机主机来源及Infra／Business引擎来源，再刷新部署事实；局部模块启动和Hosted精确进程启动不执行该恢复。主机沿唯一安装证明核验，只恢复匹配的既有容器；引擎沿原来源身份／账号核验，正常来源不重建。首次安装、证明失效、身份或输入变化、迁移及改账号／认证仍须部署者显式应用，不因应用重启扩大操作范围。Infra管理指标中心和本域专业来源，Business管理本域专业来源，主机每台部署一份，不因承载两域而重复部署。

全量本地启动结束输出一次监控摘要：复用Infra容器归属及运行／健康检查报告指标中心、已选择的控制入口，复用统一来源status列出主机及两域来源；服务进程运行与采样分开表达。该摘要只读，不读取业务数据、账号私钥内容或浏览器Token，不另建指标有效性判断；明确提示实际采样、关联与有效指标须在Monitor核对。恢复或摘要失败不阻止其他业务启动，但保留可选观测失败的非零退出状态；局部及Hosted启动不执行摘要，也不改变模块自身Ready条件。

当前只读状态与本次启动阶段结果分别表达：启动中遇到日志配置预检、指标配置预检、可选Infra健康、可选设施应用、日志端口读取或采集恢复失败时，在本次启动进程内保存固定阶段名称；末尾列出这些阶段及摘要自身失败，不回显原始错误或凭据，不以随后正常清除前序失败，也不将前序失败表述为当前来源仍失败。阶段记录不持久化、不重试操作；早期具体原因仍以当次原输出为证，当前检查正常不能补造历史根因。

主机恢复安装事实采用同一规范化比较：仅Docker HostConfig的 `Dns`、`DnsOptions`、`DnsSearch` 三个已存在字段允许将JSON null规范化为空数组，二者均表示未配置该容器的DNS覆盖，依据[Moby v28.5.1网络配置](https://github.com/moby/moby/blob/v28.5.1/daemon/container_operations.go#L63-L76)。非空数组、字段缺失、其他类型及其他HostConfig字段不作此归一化，仍严格比较；输入／容器／网络／挂载／安全身份不放宽。读取既有证明与新快照沿同一函数比较，健康检查不重写证明、不收养新容器，不为表示差异要求用户重建来源。

主机模板与 TLS 文件的跨次安装证明比较仅忽略 `st_dev`（文件系统设备号）的数值差异；该字段须仍为有效非负整数。内容摘要、inode、大小、mtime／ctime、文件模式、UID／GID、文件集合和路径继续精确核验，Docker Engine／内核、容器、网络、挂载、卷及安全事实不变。同次读取前后和同次安装／恢复操作中的稳定性核验仍包含设备号，防止读取或操作期间切换文件系统。该比较规则不重写证明，不重建健康来源，不为设备号单独变化要求重新应用。

### 采集项目与来源隔离

同一 Docker Engine 上的一套 ADDP 部署，主机、Infra 与 Business 专业采集来源共用固定名称 `addp-metrics-sources` 的 Compose 项目。分组仅用于部署呈现与操作组织，不改变平台／租户归属、数据库部署、指标中心、账号权限和采集协议。主机服务保留唯一名称；引擎采集服务以 scope 前缀区分。各来源私有声明仍是唯一部署输入，不另存集中配置副本。统一入口 `metrics-sources.py` 只依次操作选定来源，失败独立汇报。

共用项目不表示共用信任域：每个引擎来源保留专属私有卷、账号与证书，仅加入原数据库的明确私网；主机来源独立使用宿主／Desktop 网络视图。PostgreSQL Exporter 与 mTLS 入口继续分容器，数据库凭据不交给入口容器。Redis／MinIO 与 CDC 固定来源统一使用各自精确采集镜像中的工具读取及初始化本方私有卷，不借用被监控引擎的镜像，不挂载引擎数据卷。读取辅助容器以非 root、无网络、只读卷运行；初始化辅助容器仅在本方私有卷使用 root 与 CHOWN，运行中的采集进程仍为非 root、只读文件系统。Redis／MinIO 安装声明必须标记私有卷工具来自采集镜像；旧 scratch 采集安装须由部署者显式 `up`，不自动迁移或退回引擎镜像。所有查询、清理和恢复必须同时限定项目及明确服务集，并核验工作区、scope、当前数据库身份；禁止项目级 `down`、`--remove-orphans`、跨来源清理和自动采用同名陌生资源。选择单个来源不得启动、重建或停止其他来源。

### 旧来源退役边界

原带工作区摘要的项目仅允许显式 `up` 中按来源退役：先核验所选服务的容器、工作区／scope、专属卷和主机私有网络归属，全部通过才精确移除该来源，再沿固定名称部署。遇到未知资源立即拒绝；不删除数据库、业务卷或指标历史。不保留旧发现／旧恢复路径；普通 `recover` 遇到旧安装声明应提示显式应用，不构建镜像、不迁移、不重新安装账号。应用失败只清理当次来源，不声称整批回滚或无采集间断。实际采集成功仍须 Monitor 验证。

## 4.5 部署侧自动发现来源

唯一 Docker 读取实现位于 `scripts/utils/deployment-inventory.py`，由 Infra、普通 Business 启停和开发启动按各自作用域自动刷新，不调用 System API 或数据库。发现协议为 `addp.deployment-discovery/v2`，最多 256 KiB；仅核验本地 Unix Socket Context 的 Linux Docker 或 macOS Desktop Linux VM，以当前工作区的 Compose project/working_dir 校验归属。最多读取 128 个容器、64 个服务、单服务 16 个容器和单容器 64 个实际端口，整体 Docker 读取期限 30 秒；前后读取服务运行身份、状态、启动时间、重启次数、端口及 Docker Engine 身份一致才输出。

快照区分 `scope=infra|business`、`state=available|unavailable`，带 UTC 读取时间；成功空集合与失败分别表达。未知组件只标记未分类，不猜测集群、主机关联、引擎专业监控或租户归属。快照不含环境变量、密码、SQL、租户或授权，System Web 服务不因此获得 Docker 权限。

快照写入部署用户独占目录，独立作用域锁内完成读取并以私有临时文件原子替换；发布失败不写半份数据，来源失败则发布不可用结果并清除有效候选。不得把磁盘中较早快照当作实时服务状态。

System `GET /platform/engine_deployments/discovery` 仅接受非委托 Platform User 与已有 `platform.engine_deployment.read`，不接受 query/body；只读 `ADDP_DEPLOYMENT_DISCOVERY_DIR` 下固定的两个作用域文件，不执行 Docker 或接受请求文件路径。开发入口注入工作区私有目录，其他部署未配置则明确返回未配置。成功响应固定包含两个作用域，分别标记未配置、缺失、来源不可用、过期或有效；普通文件及目录须为私有权限，符号链接、非普通文件、超预算、重复或未知 JSON 字段、错误作用域、来源身份及端口均拒绝。有效窗口为 120 秒，最多允许来源时钟领先 30 秒；过期仅保留读取时间，不保留服务或来源身份，单侧失败不抹除另一侧合法结果。

持续来源由同一入口的独立部署观测进程发布，每轮完成后间隔 30 秒；不在 System 请求中执行 Docker。Infra 启动管理进程、停止时核验退出；Business 和开发启动幂等确保其存在，开发启动同时注入实际目录并刷新两组快照。观测器只继承 Docker 所需的环境，不继承 ADDP／SQL 凭据或开发生命周期锁；通过私有运行记录、当次随机标识及实际命令核对 PID，拒绝接管或停止不明进程；标准启动发现源码或 Docker 运行环境指纹变化时只替换已核验归属的观测进程。需要新建观测进程时，在既有控制锁内先校验并移除上一代 ready 记录，再启动本代进程；已有归属进程须先确认退出，运行环境未变的幂等启动保留当前记录。ready 只等待本代首次发布，避免原子替换将读取中的上一代文件描述符变成零链接；文件类型、UID、私有权限、单链接和大小校验不放宽。启动记录发布失败须回收刚创建的子进程；停止立即将两组来源置为不可用。停止观测失败不阻止实际 Infra 停服，但退出码须反映无法确认清理，Hosted 不得将其计为零残留。

观测进程退出时仅在即时取得快照锁的情况下失效来源，不等待其他写入者；停止控制流程负责确认进程退出、再取得快照锁并清空两组来源。锁竞争不能阻塞观测进程退出；控制流程无法确认退出或清空来源时仍须报告失败，不删除尚未确认退出的运行记录。退出核验失败仅追加有界、脱敏的即时诊断：最后归属判定、Linux进程状态及固定等待类型、SIGTERM挂起／屏蔽／忽略／处理状态、直接子进程数量；不可读取或非Linux时明确未知，不输出命令行、路径、随机运行标识或原始proc文件。诊断不能改变信号次数、期限、归属裁决或记录保留，也不能代替实际根因证据。

SIGTERM／SIGINT处理器只锁存停止请求，由非阻塞唤醒管道打断原30秒空闲等待；不在异步处理器直接抛退出异常，避免信号命中Python析构器时成为被忽略异常。主循环、锁等待和Docker读取在显式检查点响应停止；Docker命令仍仅启动一次，分段等待同一子进程，不重置原单次10秒／整轮30秒预算。取消读取先回收当次自有子进程，再按原非阻塞失效及退出核验流程清理；归属、单次停止信号与未退出保留记录不变。

PostgreSQL／Redis／MinIO 专业来源沿同一发现文件发布：部署侧仅核对 PostgreSQL 配对来源或 Redis／MinIO 单来源的 Owner、scope、project、数据库容器完整 ID／启动时刻及显式 HTTPS 发布端口；不读环境、Secret 或 SQL。采集身份不加入管理员确认摘要或不可变部署声明，公开发现 DTO 排除专业端点。

该接口不创建纳管身份、不更改管理员声明、历史或租户权限；管理员批量确认遵循 [4.4](#44-平台引擎部署登记)，专业来源的私有投影与准入见 [4.7](#47-postgresql-受保护的固定指标来源)。候选读取、来源自动发布、专业采集与用户查询分别验证，不以发现成功代替产品接入验收。

<a id="postgresql-source-pair-discovery"></a>

PostgreSQL 只读发现在共享 `addp-metrics-sources` 项目中按同一作用域的 `<scope>-postgres-metrics`（SQL Exporter）和 `<scope>-postgres-metrics-web`（mTLS 入口）定位配对来源。每个服务须恰有一个正在运行的常驻容器，且项目、工作区 Owner、作用域、服务标签、当前数据库容器完整 ID 及启动时刻均匹配。mTLS 入口须共享该 Exporter 的网络命名空间。唯一显式的 HTTPS `9443/tcp` 映射记录在 Exporter 容器上，入口容器自身的发布端口应为空。两个服务都未发现时记为 `not_deployed`。配对不全、重复、身份或网络命名空间错配、端口不符时记为 `unavailable`。专业来源状态与基础数据库部署状态分别判定。[采集来源统一部署分组](#采集来源统一部署分组2026-11-04)

Redis 和 MinIO 的只读发现在共享 `addp-metrics-sources` 项目内按 `<scope>-redis-metrics` 或 `<scope>-minio-metrics` 服务名定位唯一来源。发现时核对工作区 Owner、作用域及服务标签、当前数据库容器的完整 ID 与启动时刻、私网网络 ID 和唯一显式的 `9443/tcp` HTTPS 映射，并复核前后事实一致。[采集来源统一部署分组](#采集来源统一部署分组2026-11-04)

Redis 私有来源字段沿同一v2文件的 `redis_metrics` 发布，形状复用唯一 `EngineMetricsSource`：状态、HTTPS端点、当前数据库容器完整ID和启动时刻。无源为 `not_deployed`，错配或重复为 `unavailable`。只读发现不读取采集密码、TLS 文件或容器环境。System独立校验与单个运行中redis容器精确相符、快照时效、来源键及已纳管主机绑定，仅向既有Monitor后台身份提供该最小字段；普通浏览器发现和持久声明均不含专业端点。Redis与PostgreSQL分别失效，不能互相顶替；Monitor仍沿唯一准入和HTTP SD，以真实引擎类型标记来源，不新增并行查询入口或租户归算。

MinIO 复用上述平台部署登记、主机绑定与私有来源链路，平台部署类型沿已有发现协议使用 `minio`（不是租户 S3 插件标识）。`minio_metrics` 复用同一私有字段形状。Infra数据库可在多个网络，但来源必须只加入同一数据库的标准 `addp-network`；Business为 `business-network`。只读核对网络ID及Compose归属，不以网络名称猜测。登记只保留9000 API端口，不接收9001控制台端口。来源缺失、错配或关闭独立失效，公开DTO及声明不含端点；Monitor沿同一准入和HTTP SD发布真实minio类型。本批不新增权限、角色、租户关联、查询指标或页面指标。前向迁移只扩展平台部署类型和来源服务匹配约束，保留既有身份、历史与权限。

### CDC 基础设施组件的自动发现

CDC 基础设施组件首期覆盖当前标准 Infra Compose 项目的 `redpanda` 和 `kafka-connect`，每个服务最多一个运行实例。部署侧沿现有只读发现核验工作区归属、Docker Engine、Compose 项目和服务，采集来源同时绑定当前容器完整 ID、启动时刻、私网及唯一显式 HTTPS 发布端口。System 沿唯一私有观测投影发布核验后的当前事实，Monitor 复用统一 HTTP SD、mTLS 准入、端点去重与容量限制。组件按部署事实自动纳入，用户读取继续由平台权限裁决。PostgreSQL 继续沿各自引擎部署及原授权读取。

用户确认统一来源失败隔离：进程、引擎和 CDC 动态来源的连接、解析、防护或采集探测失败，仅使该来源退出本轮发现，不发布未经准入的端点；其他合法来源继续发布。手工主机来源继续由保存时准入和运行时地址策略管理，运行时解析失败同样只剔除自身。身份快照、身份结构、重复声明／已解析物理端点、总预留容量、整批截止时间仍是全局门禁，任何失败都拒绝整批。容量在探测前按已声明启用／可用来源预留，剔除失败来源不能腾出名额绕过总限额。先完成全部地址解析及去重，再对固定 IP 做动态来源准入，避免失败来源掩盖重复端点；不重复解析、不重试、不复用失败来源的旧地址。发现剔除不表示来源健康，资源查询仍按当前身份与实际采样表达未连接／缺样。

私有观测快照以 `infrastructure_components` 独立发布 CDC 部署事实，包含发现状态和组件集合；发现不可用时集合为空且状态明确为 unavailable，不冒充部署清单为空。每项以 Docker Engine、标准 Infra 项目及组件名形成稳定身份，容器 ID 和启动时刻表达本次运行。来源沿既有私有指标传输字段形状复用，不创建平台引擎登记、不授予主机关联。Monitor 的 `cdc_resources` 与现有主机、进程、引擎目标共享一份端点去重表与预算。

两个组件的部署缺失、来源未启用或核验失败分别处理。容器重建后原来源失效，只有当前容器及来源重新匹配后才采集。空 Connector 或消费组清单是独立的运行事实，缺样不填零，组件汇总不用于推算单个任务的端到端延迟。采集仅发布固定指标与有界标签，发现和指标均不携带连接凭据、Connector 配置、事件正文或异常原文。当前个人部署已有 34 个目标，启用两个新目标前在隔离环境验证至少 36 个目标的并存采集、超额和恢复。

CDC 来源安装与恢复沿统一 `metrics-sources.py` 入口，仅允许 Infra 的 `redpanda`、`kafka-connect` 两种来源。启用、监听地址和 TLS 材料由各自部署配置声明，未安装的来源不因重启而自动创建。安装只构建／应用当前来源，恢复只使用已安装的精确镜像及私有材料；身份、TLS、来源配置或来源镜像失配时拒绝恢复。来源私有卷由其自身的固定镜像初始化，不使用 Redpanda 或 Connect 镜像作为初始化工具；运行进程仍以非 root、只读文件系统及受限资源启动。CDC 生命周期不管理组件数据卷、连接凭据和 Connector 配置，也不重启组件。Connect 的只读 JMX 白名单由标准 Infra Compose 挂载，JMX 端口用于私网只读采样；开发宿主访问仅显式绑定 `127.0.0.1`，不继承 Infra 对外监听地址。

CDC 固定来源复用 `sourceserver` 的单次完整投影和私有 mTLS `/metrics`，不提供任意地址或 JMX 查询入口。Redpanda 只读取 `/public_metrics`，聚合磁盘与不可用分区；消费组积压只在每个已提交分区都有对应末端 offset 时发布，空消费组只发布分区数为零，不伪造积压值。Kafka Connect 只读取 `/connectors?expand=status` 和两个固定 JMX 属性集合：Task 的 offset 提交失败比例，以及 Debezium PostgreSQL streaming 的连接状态、源端延迟。只输出固定状态计数和最大值，不输出 Connector、Topic、Group 或 MBean 名称。源端延迟为 Debezium 的毫秒值换算秒，offset 失败比例为原生 0～1 比例，均不能解释成整条链路延迟或失败率。

CDC 页面唯一入口为 `/cdc-resources`，以 `view=tasks|resources` 区分任务链路和运行资源；默认按当前 Tenant／Platform Context 进入对应视图。页签和视图内容按当前 Context 及功能权限显示：Platform 仅显示有权读取的运行资源，Tenant 仅显示同时具备两项读取权限的任务链路，不提供另一域的可点击页签。显式 URL 指向另一域时仅显示身份范围提示，保留该 URL；离开的子视图不得再规范化路由或请求数据。Tenant User 的任务链路要求 `transfer.task.read` 与 `monitor.execution.read`，直接沿 Transfer 正式任务列表的 `change_detection=cdc` 服务端筛选和任务详情读取源／目标定位符、捕获代次及公开捕获状态，沿 Monitor 既有授权执行详情读取该任务最近 execution 的 continuous 诊断。源／目标不从部署范围推断，Connector／Topic 私有名称不进入页面；积压与提交位置只展示 Owner 最近观测及其采样时间，不用 Broker 消费组 offset 重算，不把历史 execution 样本当成当前任务状态。任务当前消息缓冲沿 Transfer 的 `capture.buffer_observation` 展示保留范围、目标提交位置及积压位点差，暂停期间继续由 Owner 采样，失败或过期时隐藏数值；与最近 execution 的历史采样分开。PostgreSQL 源端沿 Owner 的 `capture.postgresql_observation` 展示当前任务 generation 已登记且已取得所有权的逻辑槽活跃状态、WAL 保留字节距离、待确认字节距离及 PostgreSQL 原生保留风险；沿 `capture.delay_observation` 展示本任务 Connector 的 Debezium streaming 连接状态与事件捕获延迟。两项只读采样互不阻断，分别处理缺失、身份错配、不可用和过期，不使用 Infra PostgreSQL 或组件最大值替代。完整语义见 [Transfer 数据库 CDC](../tasks/Transfer数据库CDC.md#postgresql-任务源端指标)。完整诊断跳转既有执行详情，不复制诊断页面。未启动、无任务、缺样与失去读取权限分别表达，Context／任务变更及失败清除对应旧值。Platform User 只读取运行资源；跨 Context 不发起另一域的请求，不自动切换身份或扩大权限。

运行资源中的组件即时读取使用 `GET /platform/cdc_resource_observations`，不接受 query，按当前部署事实返回至多两项；发现 unavailable 与 available 的空集合分别表达。读取沿非委托 Platform User 的 `monitor.resource_observation.read`，不授予引擎、主机或业务数据读取权。运行资源仅展示实际承担 CDC 捕获和缓冲的 Connect、Redpanda 共享组件，不提供通用 PostgreSQL 部署选择。Infra PostgreSQL 保存任务、捕获登记、runtime lease 和目标提交后的同步位点，其通用连接／锁等待／容量指标沿引擎监控读取，不能以其逻辑槽或 WAL 汇总推断 CDC 源端风险。源数据库必须由任务配置确定；未建立任务与源复制资源的正式关联前，不展示部署级复制槽汇总作为任务指标。Redpanda 首页优先展示磁盘使用率、不可用分区与剩余磁盘；消费组积压置于详情并明确其不能代表 Transfer 已应用进度，任务积压继续沿 Owner committed position 诊断。Transfer 服务及 Continuous Worker 的进程指标复用服务监控，不在此复制通用资源页面。

组件固定目录按每类最多十二项查询：Redpanda 为磁盘总量／空闲／使用率、不可用分区、消费组已提交分区数及待消费记录数；Connect 为 Connector／Task 总量、失败 Connector／Task、运行／暂停 Task、offset 提交观测 Task 数与最大失败百分比、Debezium streaming Connector／已连接数、有延迟样本 Connector 数与最大源端延迟秒数。所有指标均来自现有固定采集器；没有消费组时积压不补零，空 Connector 为有效零计数，未初始化延迟无值，原生负延迟保留表示时钟偏差，不能作为端到端延迟。页面常用指标直接展示，其余在卡片内部展开。

`GET /platform/cdc_resource_trends` 只接受一个当前 `component_id`、该类型固定 `metrics`（最多十二项）及 RFC3339 `start/end`。最多七天，只读取当前容器 ID、启动时刻和受控实例地址，不拼接旧运行段。查询复用同一策略、并发和点数预算；即时集合的总时序数计入整批预算。每个值要求唯一、同次抓取的 up 与 observed_at 证据；来源故障、过期、缺样不回用旧值。返回前重读组件身份与查询策略，变化时丢弃本次结果。响应只含公开组件身份、类型、本次运行开始时刻、采集状态和固定序列，不含 Docker Engine、容器 ID、私网地址或凭据。


Jolokia 必须使用属性级只读白名单，禁止 write、exec、list、search 和其他属性；不发布宿主机原生 JMX 端口。每次采集共享 4 秒截止时间，单次上游响应最多 1 MiB，Redpanda 最多 4096 个样本、Connect 最多 256 个 Connector / 1024 个 Task。超限、协议异常或必需读取失败时整个组件返回采集失败，不保留上次样本。空集合允许成功；Jolokia 对没有匹配 MBean 返回的 `404 + javax.management.InstanceNotFoundException` 表示空集合，其他 404 和权限拒绝仍为失败。尚未出现的 streaming / offset 属性不生成零值，Debezium 的延迟 `-1` 表示尚无事件或指标已重置，不生成延迟值；同时发布有延迟样本的 Connector 数，其余负值保留以反映时钟偏差。新增来源的 T1 与真实组件 T2 沿既有 Monitor 门禁执行；它们通过不等同于统一发现、36 目标并存或页面验收通过。[Jolokia 属性级权限](https://jolokia.org/reference/html/manual/security.html)

## 4.6 PostgreSQL 数据库侧汇总读取边界

Infra 与平台自管 Business 的 PostgreSQL 分别由部署 owner 通过唯一来源生命周期安装版本化的 `scripts/infra/postgres-observation/000003_replication_slots.sql`，不进入 System IAM 迁移；前两版保留为不可变历史。支持 PostgreSQL 15 数据库侧读取及可选来源部署；专业来源发现、Monitor 授权查询与页面沿本文同一观测链实现。数据库侧验证只证明其读取边界，不能替代专业查询与页面的正式身份 T4。

各实例分别使用 `addp_infra_observer` 或 `addp_business_observer`，密码独立；非登录的 `addp_observation_owner` 仅继承 `pg_read_all_stats`，Login 无任何角色成员资格，不获该统计角色、业务对象或服务管理权限。安装在单事务中校验作用域、SCRAM 校验值、身份标记、成员资格、schema／函数归属与 ACL；陌生对象、额外权限、PUBLIC 业务读权或不安全默认授权均拒绝并回滚，不接管或全局撤销其他用户权限。Login 只授当前连接库 CONNECT、私有 schema USAGE 和唯一无参数 `addp_observation.snapshot()` EXECUTE。密码校验值通过部署侧私有 stdin 的 psql 变量注入，不进入参数、普通配置、发现快照、System API 或日志；原始密码不参与 SQL 文本。

固定函数返回一行、19 个有类型字段：采样时间、服务启动时间、统计代际、统计开关；当前客户端连接、活跃、空闲、事务内空闲、活跃等待、活跃锁等待、活跃 IO 等待及最大连接数；非模板数据库的事务提交／回滚／死锁累计值及容量字节。排除本次采集会话，不输出数据库／表／用户名称、PID、客户端地址或 SQL。等待仅计 active，空闲 ClientRead 不作为压力；事务保留 PostgreSQL 原累计口径，包含采集自身带来的事务，不冒充业务吞吐或租户用量。统计关闭时三项累计值为 NULL；容量不完整不能填零，超过 256 个非模板数据库拒绝而非截断。统计代际覆盖数据库集合与各库统计重置，配合服务启动时间裁决后续速率窗口。复制槽额外输出本实例逻辑槽数、不活跃逻辑槽数，以及从当前 WAL 位置到最早非空 restart LSN 的字节差。用最早位置计算重叠 WAL，不相加，不输出槽名或 LSN，不代表数据卷实际占用，也不证明这些 WAL 仍可回放。主库没有非空保留点时字节差为 0，恢复中的实例字节差为空。读取不创建、不删除或推进槽。

函数采用固定 `pg_catalog, pg_temp` 搜索路径、全限定目录和固定 SQL，Login 不可更改函数；只读默认值和三秒语句超时是附加约束，不能替代对象权限或来源侧期限。PostgreSQL 的 PUBLIC 授权可叠加，单个角色 REVOKE 不能覆盖它；当前安装核查只覆盖所连数据库。正式部署须选择无业务对象的维护连接库，并以认证／网络策略限制其他数据库连接；未完成该部署准入不启用采集，不声称已经隔离整个实例的所有业务库。安全依据见 [PostgreSQL 函数权限](https://www.postgresql.org/docs/15/sql-createfunction.html)、[统计角色](https://www.postgresql.org/docs/15/predefined-roles.html)及[统计字段](https://www.postgresql.org/docs/15/monitoring-stats.html)。

验证复用独占 `make test-monitor-metrics`；精确数据库专项为 `make test-monitor-metrics MONITOR_METRICS_TEST_ARGS=--case=postgres-observation`。私有 PostgreSQL 强制 TCP SCRAM，覆盖真实密码、固定数值与独立目录对照、等待／锁等待、统计关闭／重置、越权拒绝、临时关系遮蔽、重入／密码轮换、陌生身份、默认权限漂移和失败回滚；业务对象夹具仅用 `addp_test`，认证拒绝探测另使用镜像自带 `postgres`，退出按原门禁核验物理零残留。默认完整门禁仍执行全部指标链路及该专项，现有 Monitor metrics CI 按声明自动发现新增 SQL 与探针；不新建 Job、不修改生产权限、不修改个人库。

数据库认证准入沿同一 `source.py` 的唯一规则生成器：部署 owner 在角色／函数归属校验通过后，才可为该实例对应的采集 Login 生成置于 `pg_hba.conf` 最前的受管块。只允许显式维护连接库、显式私网／回环 CIDR 与 SCRAM；拒绝该 Login 的其他数据库、Unix socket 和物理复制连接，不修改其他用户的既有记录。维护库名按字面量引用，不能把 `all` 等特殊词误作通配符。认证规则不代替函数和对象权限，也不授予 Monitor 编辑认证文件的能力。

受管块包含无凭据的作用域、维护库与有界规范 CIDR 声明；原文件其余内容原样保留。既有块不在首部、作用域冲突、声明／规则漂移、残缺标记、非注释记录含保留采集账号标识或超量输入均拒绝，不修补覆盖。相同输入幂等，部署 owner 明确提交的新 CIDR 可替换经核验的本方块；来源启动前仍须确认文件原子替换、数据库配置重载及真实认证结果。HBA 只约束新连接；正式安装须先停止旧来源，并确认该受管账号没有遗留连接，存在旧会话则拒绝激活，不自动终止不明会话。当前先由独占 T2 验证生成与认证，不自动更改个人实例。T2 仅在其原生 `addp_test` 与镜像自带 `postgres` 之间验证跨库连接拒绝，不创建新 database，不读取业务表；覆盖允许连接、错误密码、回环／Docker 私网、跨库／socket 拒绝、管理员连接不受影响及原文件恢复。规则依据为 [PostgreSQL 15 HBA](https://www.postgresql.org/docs/15/auth-pg-hba-conf.html) 的首条匹配和特殊词引用语义。

## 4.7 PostgreSQL 受保护的固定指标来源

PostgreSQL 来源由唯一部署入口 `scripts/infra/postgres-observation/lifecycle.py` 管理，分别接入 Infra 与 Business 标准启停。`ADDP_POSTGRES_METRICS_ENABLED=false` 独立选择来源，不依赖中心开关；选中后必须提供仓库外三文件 `ADDP_POSTGRES_METRICS_TLS_DIR` 和显式本机 `ADDP_POSTGRES_METRICS_LISTEN=IP:端口`，不自动分配或避让端口。`ADDP_POSTGRES_METRICS_STATE_DIR` 是可选私有状态根目录，按作用域隔离凭据和生成配置。默认使用当前部署用户仓库外、工作区摘要隔离的状态目录；状态、密码及 TLS 私钥不进入发现、环境变量或参数。标准脚本不签发或追加 CA 信任。来源仅连接本机受管 Docker PostgreSQL 15 的实际私网地址；独立来源故障报告非零可选结果，核心服务继续运行。

活动安装版本为 `000003_replication_slots.sql`，前两版只保留为历史。部署输入仍只决定本方 Login 的启停；原函数输出形状在同一事务内前向升级，权限集合保持原有范围。启用先停止旧来源、验证工作区／容器／私网／角色归属和无遗留采集会话；同一数据库部署锁下先完整安装为 NOLOGIN，再按唯一规则生成器原子更新 HBA、检查语法并重载，确认无旧会话后才完整复核并开启 Login。密码首次随机生成，后续沿用私有文件；已有账号但凭据丢失时拒绝自动重置。停用只关闭本方采集容器及已验证归属的 Login，保留函数、配置、历史和数据卷，不终止未知数据库会话。失败不得保留运行中的旧来源或宣称就绪，不重启数据库、不撤销其他用户权限。账号安装及数据库操作仅由部署 owner 执行，不交给 System Web、普通发现进程或 Monitor 后台身份。

Business PostgreSQL 的运行认证文件由部署 owner 在仓库外维护，唯一容器路径为 `/etc/addp-postgres-auth/pg_hba.conf`，只读挂载其父目录，不再单文件绑定仓库模板。标准 Business 启动入口在启动 PostgreSQL 前准备该目录；默认状态目录为当前部署用户的 `~/.local/state/addp/<工作区路径摘要>/postgres-auth`，可由 `ADDP_POSTGRES_AUTH_STATE_DIR` 显式指定仓库外绝对目录。目录归属绑定当前工作区，不接管其他 owner、符号链接、硬链接或被外部改写的文件。模板仍为 `business/postgres/pg_hba.conf`，首次原样复制，后续保留经校验的采集首部块；模板和运行文件之间不存在双轨读取。模板有明确更新时，只有运行文件仍与上次生成事实一致才可重新生成，不覆盖人工漂移。

部署侧文件更新使用同一受管目录锁、输入版本校验及同目录原子替换，保持原文件属主和模式；数据库容器无写权。该入口不保存数据库密码、不签发证书、不安装角色、不重启或重载运行数据库。首次切换由部署方使用标准 Business 启动入口重建容器，保留数据卷；后续认证安装仍须先检查归属／遗留会话、更新文件、检查 `pg_hba_file_rules` 并重载及验证连接。文件准备成功不能计为专业采集已生效。Infra 仍使用其数据目录内的认证文件，不为统一形式迁移数据。

来源模板 `scripts/infra/postgres-metrics.yml` 与独占 T2 共用固定 SQL Exporter 0.24.11 多架构摘要；固定配置唯一生成实现为 `scripts/infra/postgres-observation/source.py`，只查询 4.6 的函数，关闭 ping、缓存和动态目标，不接受用户 SQL。每个作用域独立来源、单 SQL 连接、零空闲连接，查询上限四秒。数据库密码只在部署用户私有的只读来源配置内，不进入环境变量、命令参数、发现快照或平台 DTO。源侧 SQL 当前限定受控 Docker 私网；生产数据库 TLS 另须认证，不把本机 T2 计为生产验收。

SQL Exporter 只监听其网络命名空间的回环 HTTP `127.0.0.1:9399`，同命名空间 Nginx 在 `9443` 提供独立 mTLS。TLS 进程仅挂载自己的服务端证书／CA，不挂载含数据库密码的来源配置；两进程均使用显式非特权 UID/GID、只读文件系统、移除全部 capabilities 及资源限制。外部只允许无 query 的 GET `/metrics`，配置、重载、exporter 自身诊断、其他路径及方法均拒绝；凭据不因持有采集证书而可读取。保持 `ssl_verify_client on`；Nginx 的客户端证书缺失／校验失败（内部 496／495）统一返回 403，不转发上游。来源准入仍只认可明确的 TLS 证书拒绝或 HTTP 401／403，不把通用 400 当作保护证据。没有默认宿主机端口；标准 Infra／Business 入口仅按各自显式开关部署，不自动修改个人环境选择。

当前固定输出 `addp_postgresql_` 前缀的指标，对应 4.6 的有类型汇总；指标目录与来源配置的唯一生成实现为 `scripts/infra/postgres-observation/source.py`。时间输出 Unix 秒，容量为字节，连接为数量，累计量后缀 `_total`。累计量带固定计算的 `counter_epoch`，同时覆盖统计代际与服务启动时间；代际信息独立表达，不以数据库名、SQL 或租户作为标签。统计关闭时不输出三项累计值，不填有效零。

所选版本在 SQL 失败时可能仍返回 HTTP 200 和累计 `scrape_errors_total`，此时不得输出旧数据库样本。HTTP `up` 只证明传输可达，累计错误计数也不是当前失败状态；专业读取必须验证固定样本及新鲜采样时间。T2 覆盖权限撤销后的两次真实失败、错误计数递增与无旧样本、恢复新样本、统计关闭／恢复，以及错误客户端证书、明文 HTTP、路径和方法拒绝。精确入口为 `make test-monitor-metrics MONITOR_METRICS_TEST_ARGS=--case=postgres-source`，默认完整门禁同样包含；业务／Infra 全退出核验由同一门禁负责。

PostgreSQL 专业来源经 [4.5](#45-部署侧自动发现来源) 的同一发现文件进入 System 私有观测投影；Monitor 继续统一 mTLS／CIDR／端口准入、端点去重及样本预算。专业来源缺失、停用、归属不明或数据库容器变化时只移除该来源，不清空合法主机／进程身份。

该契约包含可选部署生命周期及独占传输验证，不代表个人实例已经启用或专业页面已通过正式身份 T4。用户授权及当前容器运行段分别沿 [6.2](../addp平台运行观测规范.md#62-资源查询与预算)、[6.3](../addp平台运行观测规范.md#63-趋势时段比较与总览)，不将来源模板直接登记成节点或租户 Engine。数据库侧、来源 T2 与专业查询／页面 T4 的固定版本、失败及未覆盖项见[采集来源与引擎指标证据](../testing/evidence/Monitor采集来源与引擎指标历史证据.md)，不外推当前 HEAD 或生产验收。上游行为参照 [SQL Exporter 固定版本](https://github.com/burningalchemist/sql_exporter/tree/0.24.11)；不引入 PostgreSQL exporter 已弃用的自定义查询作为并行路线。

完整开发启动（无参数或 `-all`）在刷新发现快照前，分别按根与 Business 配置自检已安装的 PostgreSQL 来源；单模块及 `ADDP_ONLINE_HOST=1` 入口不执行。关闭／未配置的作用域不接触 Docker 或数据库；无私有安装状态时不自动安装。健康且声明匹配的来源不重建、不改文件；来源停止或同一数据库容器启动时刻改变时，复用唯一来源生成／启动实现恢复。恢复须锁内核对工作区、Docker Engine、项目／服务、旧部署文件中的完整数据库容器 ID、现有凭据与 TLS，并通过采集账号的固定只读权限及快照校验；数据库前后事实变化则拒绝。新数据库容器、停用数据库、账号停用、权限漂移、私有状态缺失／漂移或符号链接均拒绝，不自动接管。

自动恢复不安装、轮换或启用账号，不写／重载 HBA、不执行管理 SQL、不创建证书或启动数据库。恢复失败只回收当次明确拥有的来源，报告可选能力不可用并继续业务启动；不会把恢复进程加入只读部署发现观测器。根与 Business 配置在独立子进程清空采集变量后分别加载，不能因继承根开关而启用 Business。正常停用仍沿原部署入口；后续完整启动不重新启用已停用的采集账号。宿主／Docker 不执行标准完整启动时不承诺无人值守恢复，不安装系统自启动或定时任务。门禁沿既有 Infra／开发生命周期确定性入口与 PostgreSQL 来源 T2，实际结果按测试规范分别记录。

## Redis 专业观测首期边界（2026-11-01 确认，分阶段实施）

Infra 与平台自管 Business 的 Redis 是两个独立 Platform 运维对象；首期仅支持标准部署中的单机 Redis 7，不包含 Cluster、Sentinel、FalkorDB、外部租户引擎或租户用量归算。沿既有管理员确认、System 当前部署／主机关联、私有来源投影、Monitor HTTP SD、Prometheus、当前 User 授权查询及 Console 引擎页接入；不得另建手填连接、JSON 导入或 Monitor 直连数据库路径。System 沿同一管理员确认接口接入 Redis，仍只允许 Platform 自管 Infra／Business、显式有效主机关联和既有平台权限；不因部署发现直接创建纳管身份。

数据库侧分别使用独立的 `addp_infra_observer`、`addp_business_observer`；不同物理引擎中的同名账号不共享密码或权限。部署 owner 持有私有凭据及管理身份，采集进程只持本方采集凭据，不复用默认用户、Business admin 或可读业务键的 reader。准确命令白名单为 `HELLO`、`PING`、`INFO`：HELLO 用于现有 Go Redis 客户端的 RESP3 认证握手，关闭客户端名称／版本上报、维护通知、自动重试和数据库切换。账号无键模式、频道或其他 selector，不授 `@read/@connection` 类别、GET／SCAN／KEYS、脚本、CONFIG、ACL、CLIENT LIST、SLOWLOG、MONITOR、持久化管理或写命令。账号配方从完整 reset 构建，停用配方同时清空命令／键／频道／密码，不仅设 off；既有会话不能因 off 继续读取。配方生成不代表正式部署已经安装，账号归属、启停、持久化及凭据丢失拒绝必须在部署生命周期接通后另验。

`INFO` 权限允许实例级运维元数据，不保证服务端只返回产品列出的字段；键模式不能限制无键参数命令，不依赖已弃用的首参数 ACL。采集器仅请求固定 server／clients／memory／persistence／stats／errorstats 分区，按固定字段输出数值；原始 INFO、键名／值、客户端／复制地址、路径、命令参数及凭据不得进入 DTO、指标标签、普通错误或日志。依据：[Redis ACL](https://redis.io/docs/latest/operate/oss_and_stack/management/security/acl/)、[INFO](https://redis.io/docs/latest/commands/info/)。当前首批采用部署专用固定采集内核并复用仓库已有 Go Redis 客户端，不引入默认 INFO ALL／键扫描的通用 exporter 或新依赖；Monitor Web 不调用该读取内核。

固定读取包括运行时长、Redis 分配内存、RSS、maxmemory、参与限额判定的内存、当前连接／maxclients、阻塞连接、处理命令、键查找命中／未命中、淘汰、拒绝连接及 OOM 累计值，以及 loading、AOF 开关／最近写入／重写、最近 RDB 保存结果。当前连接包含采集连接，命令累计包含采集命令；不虚构业务连接数或业务 QPS。阻塞连接不直接表示故障。OOM 仅在有效 errorstats 分区内没有 OOM 记录时表示零；缺分区／字段、ERRORSTATS_DISABLED、无效整数／状态、重复字段、非 standalone 模式或启动身份不一致须拒绝相应快照，不能补零。输入解析上限256 KiB，不输出原始内容。

查询的内存限额占用率为 `(used_memory-mem_not_counted_for_evict)/maxmemory`，不剪裁100%；扣减大于分配内存时拒绝，不制造负数或有效零。maxmemory=0时不计算比例，不用主机／容器内存作分母。该比例不是RSS／容器硬限额或OOM安全保证。命中率沿完整评估窗口的hits／misses增量，无查找请求时不计算；计数速率是Redis实例整体值。AOF关闭与失败分开解释；RDB返回ok不证明配置已启用或已有可恢复备份。不请求SLOWLOG正文、keyspace扫描、大键／热键或自动阈值告警。

专业趋势限当前容器运行段、最多七天，且以 INFO run_id 分隔同容器内的进程重启；来源重启不伪造数据库重启，采样前后须核对同一run_id。缺样、重置可见或身份变化处不计算速率；离散INFO不能保证识别采样间所有统计重置。run_id仅为私有采样身份，不作为用户标签；来源端点身份和当前容器仍由部署侧及System裁决，不以run_id替代主机关联。采集默认关闭，失败不影响数据库／业务Ready；来源启停、账号漂移拒绝和清理沿部署owner职责，不由Web或只读发现进程实施。

Redis专业查询复用engine_resource_observations／engine_resource_summaries／engine_resource_trends，按System当前User裁决的引擎类型选择固定目录，查询后重核用户、部署版本、有效主机、容器及来源；不从浏览器提供类型或端点取得授权。固定目录22项：运行时长；分配内存、RSS、maxmemory、不计入限额的内存、参与限额的内存及限额占用率；当前／最大／阻塞连接；一分钟处理命令、键命中／未命中、淘汰、拒绝连接和OOM速率，以及一分钟键命中率；loading、AOF开关、最近RDB保存／AOF写入／AOF重写结果。布尔状态保持0／1；RDB成功仍不证明备份可恢复。比率使用百分数，maxmemory=0或无查找增量时留空，不输出0％。

一分钟指标沿现有15秒采样与完整窗口要求：至少四样本、有一分钟前边界、当前及历史边界快照新鲜且完整、无可见重置、counter_epoch精确相同；同一容器内Redis进程重启也留空。INFO计数不可证明观察间未发生不可见重置；不夸大此覆盖。来源up必须唯一且为1，必需原始字段同次scrape且采样时刻贴近scrape。AOF开启时，最近写入和重写结果均须来自同次采集，且为0或1。AOF关闭时，两项结果均缺省，其余指标仍按完整快照展示。错误、必需字段缺样、重复代际或不一致快照不得带出旧值。Redis与PG共用唯一Prometheus传输、批量摘要、归一化、并发／点数预算和结束前授权重核。

单次最多12项的现有预算不扩大。Redis详情按“资源与连接”（10项）、“吞吐与命中”（7项）、“持久化状态”（5项）显式切换，仅查询当前组；趋势仅查询选中指标，不暗中拆分全目录请求绕预算。列表按类型筛选后分页，Redis摘要固定为分配内存、限额占用率、当前连接、每秒命令四项；两类摘要均每对象四项，统一预留整批预算。类型、指标／分组及趋势范围随原URL恢复，未知类型和跨类型指标拒绝。说明位于指标旁tip；零内存限额显示未设置上限，状态按各自语义显示，容量和时长用共享格式化。

Redis详情的空值解释仅使用当前已授权、已校验的同一即时响应：采集状态为 collecting、比率为 no_data，且同一评估／采样时点的有效 maxmemory 为零时，说明当前未设置内存上限、当前占用率无法计算；同一完整一分钟的有效命中与未命中速率均精确为零时，说明当前没有键查询、当前命中率不计算。不能用显示四舍五入后的零、陈旧或缺失的依赖、不同采样时点或当前值推断历史空点的原因。具体说明就近显示于该指标卡和选中趋势旁，只解释当前值，保留历史曲线及原断点；证据不足或来源失败仍用通用缺样说明，撤权／对象变更同步清除。列表摘要不额外查询依赖，不改变数值、公式、目录、权限或预算。

账号持久化由标准 Redis 启动和唯一 `scripts/infra/redis-metrics.py` 生命周期管理。Infra保留default账号的原密码／权限，Business保留原admin／reader配方；两者生成唯一运行ACL文件，不同时使用requirepass或旧ACL文件路线。采集账号的两行受管记录位于Redis数据卷的私有目录：无凭据的随机部署owner标识和唯一账号规则，启动时严格校验后合成到运行ACL。采集记录损坏时跳过该可选账号并输出固定诊断，保留原业务认证；生命周期拒绝接管，不能把启动成功视为观测恢复。只在VM内原子替换本方记录，不依赖macOS共享目录动态更新；不调用会持久化所有用户运行修改的ACL SAVE，不重写其他用户规则。首次切换由用户沿标准入口重建Redis容器并保留数据卷，AI不重启个人服务。

根和Business的 `ADDP_REDIS_METRICS_ENABLED=false`、TLS目录、显式监听及仓库外私有状态分别加载，不相互继承；密码首次随机生成，后续沿用，发现已有账号而无本方状态／凭据时拒绝，不自动重置。状态绑定工作区、Docker Engine、Compose项目／服务和具备同项目标签的Redis数据卷，当前容器须唯一、运行中且仅有一个受管私网。账号变更前后核对当前容器事实；部署锁内核对本方磁盘记录和当前精确ACL，陌生账号、权限漂移、丢失状态、符号链接或未预期的文件内容均拒绝接管。

启用先停止已核验的旧来源，再以部署管理员身份安装／启用最小采集账号并持久化；停用先停来源，再完整reset/off清权并持久化，保留数据卷、私有密码和身份供再次显式启用。写入失败不得宣称持久化成功，运行态或磁盘态可能不一致时报告失败并尽力清权，不以重启修复。管理员密码仅经当次stdin进入受控redis-cli子进程，不进入长期采集容器、命令参数、发现或日志；原生ACL读取及本方记录更新不执行业务命令、不改其他账号。来源故障不阻断数据库／业务Ready，停止清理失败仍通过退出码反映，不虚报零残留。

来源为独立、非特权、只读、限额的部署容器，复用固定采集内核和现有Go客户端；仅连接当前Redis实际私网IP。配置／采集密码／TLS材料经有归属标签的专用临时卷传入，长期来源不挂载Docker Socket、Redis数据卷或管理员凭据；停用清理本方容器和该配置卷。对外只提供mTLS GET /metrics，无query、动态目标或其他管理入口，证书由部署方提供，不签发或扩大CA信任。固定数值、采样时间及私有运行代际输出不包含原始INFO／run_id／错误文本；传输可达不代表当前读取成功。标准Infra／Business启停接续调用生命周期；未配置且无本方状态时不操作Redis，不引入定时任务或只读发现进程写职责。

已接通账号配方、固定采集内核、原生ACL持久化及标准Infra／Business来源启停；具体本地分层证据见[采集来源历史证据](../testing/evidence/Monitor采集来源与引擎指标历史证据.md#redis-账号持久化与来源生命周期2026-11-01)。发现／System类型扩展、Monitor目录／页面已在工作区接通，迁移261须待前置259／260提交后发布；本地来源T2、原生PromQL边界与受控页面T3分层记录，真实身份T4未运行。T1沿Monitor Go和配置入口自动发现；T2沿 `make test-monitor-redis-source` 复用现有Redis独占夹具、固定镜像、随机密码及物理零残留核验，不读取或修改个人Redis。Monitor门禁、根串行集成及Release作业自动发现同一专项，禁止使用局部协议通过代替已部署来源、页面、CI或Hosted通过。

## MinIO 专业观测首期边界（2026-11-02 已确认）

固定版本的原生 `mc admin user svcacct enable/disable` 只提交状态，会移除内联策略；本产品禁止调用该路径。启停唯一走同一镜像内的部署专用工具，沿该镜像已锁定的 MinIO 管理库，在一次请求中同时提交状态和唯一 `admin:Prometheus` 策略，随后重读原生策略及状态。工具只访问容器内回环9000，凭据仅从私有stdin输入，不提供任意端点、策略或管理操作；没有该工具的镜像在创建账号前拒绝。固定版本会将提交的资源通配符 `*` 持久化为 `**`，原生读回只按此唯一固定形状核验，不能把继承父账号策略视为合法结果。

首期仅覆盖仓库固定`RELEASE.2025-10-15T17-29-55Z`的Infra／平台自管Business单容器MinIO，两个独立Platform运维对象，不含集群／外部租户引擎、桶级明细、租户用量归算、自动告警或压测。复用原部署发现、System管理员确认及有效主机、私有来源、HTTP SD／Prometheus、当前User与Console链路；不新增手填连接、导入或Monitor直连S3路线。原生接口只使用v3，不与v2并行。

固定目录17项，容量与状态10项：MinIO进程运行时长、在线盘数、离线盘数、MinIO报告的可用总容量／剩余容量、空间占用率，以及最近扫描的对象容量／对象数／桶数量／统计距今秒数。请求与流量7项：S3请求速率、在途请求数、4xx／5xx错误速率、5xx占比、S3发送／接收字节速率。沿现有最多12项预算分两组显式查询；固定原生端点为`/minio/metrics/v3/system/process`、`/cluster/health`、`/cluster/usage/objects`、`/api/requests`（后者均相对于v3前缀），不抓根目录、桶端点或任意query。容量来自MinIO可见存储，不代表对象占用或独占物理盘，Desktop下两部署共享底层容量不能相加。对象统计明确标记最近扫描与距今时间，无扫描不补零、不参与实时健康或告警；不把fresh scrape等同fresh scan。速率沿完整窗口、启动身份及重置保护；分母为零不计算错误占比，4xx不直接视作存储故障。跨端点采样不声称原子快照；来源／权限失败不保留失效即时值，不抹去仍合法的历史点。

来源适配只输出固定原始数值，速率、空间占比与错误占比由唯一查询层计算。当前固定版本的`MetricValues.Set`只发布大于零的值，实测零离线盘数、零在途／5xx及尚未扫描的对象统计会缺席；不能据HTTP200把缺席系列补为0，也不能宣称健康时17项均有值。接口成功但某项未发布与整个来源失败分别表达；若需明确零值，须另行确认可靠的生产端事实协议，不启用v2或其他接口兜底。

MinIO来源仅读部署方提供的当前私网IP:9000，以受限账号签发短JWT；每轮总限三秒、固定四端点并在前后重读进程边界，共最多五次读取，每响应256KiB、最多4096样本。关闭重定向、代理、重试与任意DNS；原生启动时刻必须一致、运行时长不回退，失败整轮不输出旧样本。固定单容器中只对S3操作名分片的同一计数／在途指标求和，标签只允许固定端点原生的server／name／type并核对type=s3；重复、额外主体或非法数值拒绝。所有原生标签在输出前删除，计数仅保留由部署身份与进程启动边界计算的私有代际摘要；扫描时间独立保留，不与采集时间混同。

TLS来源复用Monitor内部唯一固定来源HTTP／TLS服务内核：非root、只读、0.25CPU／128MiB，mTLS TLS1.3，仅GET /metrics、无query／请求体，单并发，失败503且无失效数据。Redis沿同一内核删除重复HTTP／TLS实现，仍保留各自协议与字段适配。来源配置只含受限AK／SK、明确当前MinIO容器／启动身份和目标IP，不含根凭据、Docker Socket或数据卷；部署方提供证书，不签发CA。来源启停、私有卷及发现／查询／页面继续分层验证，不将账号准备或来源运行计为完整17项产品验收。

主机 node_exporter 与 PostgreSQL／Redis／MinIO 的采集来源共用证书预检内核，在原信任链、服务器用途、监听 IP SAN 和密钥配对校验中启用 OpenSSL `-x509_strict`，提前拒绝缺少非自签发叶证书 AKI、CA SKI 或其他严格链约束的材料；不把可选的叶证书 SKI 单独设为必填。各来源保留自己的目录形状、文件预算和保护检查，PostgreSQL 原三文件目录及读取上限不变；只统一 HTTPS 采集入口的证书验证，不改变 SQL 连接或两容器部署。`check`、`up` 和 `recover` 复用同一校验，不降级重试、不改写证书或私钥，不增加网络请求。主机启用时在原部署输入检查中验证；安装证明的 schema、指纹／元数据、归属及拒绝规则不变，校验失败不使既有证明失效或触发恢复变更。停用、未启用和仅导出原生宿主声明仍可执行，不要求有效证书。预检通过仍不代表实际 mTLS、客户端认证或新鲜采样通过。

上述预检的诊断沿原中文部署入口展示，使用封闭的证书链／必要扩展、尚未生效、过期、服务器用途、监听 IP SAN、密钥不匹配及未确认类别；仅从同次失败的 OpenSSL 标准验证错误码及本地公钥比较取得依据。错误文本只解析最多 4 KiB、最多 8 条标准错误行；未知码、不同类别冲突、缺少依据或超预算均为未确认，不从路径、证书主题或自由文本猜测。协议来源只传递封闭类别，统一入口在 `check/up/recover` 使用同一中文映射，保留原非零退出、阶段和清理未确认标记，不输出证书内容、主题、路径、命令或凭据，也不增加校验命令／重试。

两个部署使用各自独立、非root的MinIO原生受限Access Key（service account），仅附加自定义内联策略`admin:Prometheus`，不得授予S3权限、内置readonly／diagnostics或admin:*。它是MinIO内部采集凭据，不是ADDP角色或Service Principal，不改生产IAM内核。该原生权限允许全套运维指标，可能包含桶级元数据，不能宣称仅能读取17项；实际采集仅允许上述端点及固定数值字段，进入Prometheus前排除桶名、对象名／内容、节点地址、磁盘路径及原始输出，过滤不冒充权限隔离。采集侧只持该受限Access Key／Secret Key，按MinIO原生HS512、issuer=prometheus、subject=Access Key生成最多300秒JWT，不持root密钥、不照搬mc默认百年Token，不增加续期运维进程。

唯一部署owner复用固定镜像内mc与既有Docker归属／私有文件内核，核验工作区、scope、Docker引擎、Compose项目／服务、固定版本镜像和命名数据卷；凭据、安装日志状态仅保存在仓库外0700目录／0600文件，密钥不进入argv、外部环境、日志或System普通DTO。管理身份只在当次安装／核验内使用。创建前写入私有归属意图，原生账号的名称／描述／parent／明确内联策略必须与本方事实一致；同卷容器重建可复用账号，异卷、外来账号、策略漂移或凭据丢失拒绝接管／自动重置。显式安装／应用进入来源替换阶段后失败或停用时，先移除经核验的本方来源及配置卷，再关闭本方原生Key并核验旧JWT拒绝，不撤销其他账号、修改root或重启MinIO；账号／策略沿MinIO原生数据卷持久化，不复制第二份用户库或在启动时批量重写IAM。未知创建结果不自动再造账号，后续先核对本方事实并失败关闭。

账号生命周期、固定原始指标适配和受管mTLS来源已接入标准启停；发现／System私有来源、HTTP SD、固定查询与页面已接通；个人部署实际应用和正式身份全链路验收分别记录。来源选择默认关闭，失败不阻断MinIO与业务Ready；标准启动／停止负责本方账号启停，账号准备不能报告为专业指标已接入。隔离T2使用当次两MinIO与独立账号，验证指标读取、S3列桶／读写／用户管理拒绝、错误／过期JWT拒绝、策略漂移、停用／恢复、数据库重启持久化与scope隔离；不读取或修改个人环境。T0/T1、独占T2、受控页面与正式身份T4分别记录；CI及Hosted由专门会话安排回传，本会话不触发、重跑或设置定时任务。

MinIO固定查询复用engine_resource_observations／summaries／trends及现有当前User重核、预算和当前容器段边界。十项容量／状态与七项请求／流量分组按需读取，列表仅取总容量、剩余容量、空间占用率和请求速率四项，不跨部署合计。基础来源有效只要求同次唯一up、observed_at、进程start_time及uptime、当前容器启动边界；start_time沿固定MinIO的procfs启动估算，uptime沿应用启动记录计算，不能假定二者同一计时基准，不使用start_time＋uptime＝采集时刻的等式作为有效性条件。仍核验原始字段唯一、非负、同次采样、启动时刻在当前容器边界后且不晚于采集时刻；每项再独立核验唯一系列、非负值与同次采样，缺席单项不使其他项失效、不补零。空间占用率须总容量大于零且剩余不超总量；扫描值须有同次合法最近扫描时间，统计距今以查询评估时刻减该时间，不要求扫描发生于当前容器启动后。计数速率要求一分钟完整边界、四样本、无重置、相同counter_epoch与进程启动身份；5xx占比还要求请求增量大于零且错误增量不超请求增量。当前采集失效清除即时值，合法历史点保留。提示紧贴指标，容量不声称独占物理盘，4xx不等同存储故障。用户可用现有组页签、图例／悬停／缩放及隐藏暂停刷新；不新增权限、路由、自动告警或Hosted用途。本批本地T1／PromQL T2／受控页面T3分别验证，CI与Hosted仍由专门会话回传。

## 4.8 服务部署预期与分组租约观测

服务失联的预期来源唯一属于标准部署入口。受管目录中的 `service-expectations.json` 使用 `addp.service-expectations/v1`，包含工作区摘要 `deployment_id`、单调递增的 `revision` 和按模块／角色／用途排序且唯一的 `groups`。每组仅含 `module_name`、`role=backend|worker`、`runtime_name`、`expected_replicas`（1—1000）、`desired_state=running|planned_stopped` 与 UTC `changed_at`；Backend 用途为空，Worker 必须与正式登记的用途相同。最多1000组、256 KiB，重复键、未知字段、非法或未来时间拒绝。发布器沿既有私有目录、所有权检查、互斥锁与原子替换；相同声明重发不推进版本或时间，局部启停保留其他组，失败保留旧文件。组实质变更的changed_at使用真实UTC微秒且严格晚于该组原值，拒绝停滞／回退时钟，不合成未来时间；同秒停用、重启或副本变更不得复用旧标记。没有存活进程扫描、手工管理第二路线或个人服务自动启停。

用途对应 Meta `scan`、Transfer `sync`／`continuous_sync`、Quality `quality-bounded`；Backend 按角色分组，Security Worker 不在本批新增范围。`metadata.runtime_name` 可随再次登记更新，不能直接作为不可变部署身份；用途缺失或不规范时不得按模块名、PID、IP 或其他用途补算。分组与当前在线副本以 System 同一时点裁决为准，分组变化中断连续窗口，不改写旧事件证据。

System 在唯一 `/runtime/observability-identities` 中只读提供 `service_groups`：声明身份／版本、同一控制面 `observed_at` 及每组预期、正式登记总数与当前在线副本数。在线仅表示登记状态UP且租约晚于同一观测时间，不要求绑定主机或已接指标；不同Worker用途不互代。读取声明前后内容变化时清除该子域。全域状态为 `available/unconfigured/unavailable`；可读组为 `observed`，计划停用或模块停用为 `paused`，模块未登记或活跃Worker用途不明为 `unknown`。零在线只是租约事实，不在System产生失联／恢复结论。组候选最多10000个登记，共用原五秒／四MiB预算；仅组文件异常或组预算耗尽使子域不可用，数据库事务失败仍拒绝整份投影。Common客户端核验可解码子域的形状和时间，非法子域清为空的不可用状态，保留合法的独立资源身份；响应JSON无法解码或原控制面身份异常仍拒绝整份响应。

模块 `enabled` 不代表某类 Worker 已部署，缺席或历史登记总数不能推断应运行，也不授予运行确认资格。持久预期不随发布器退出自动过期，计划停用必须明确发布。

该私有观测投影沿现有固定 Monitor 后台身份读取，本投影不新增角色、权限、凭据或浏览器 DTO。标准开发／生产停止入口先发布所选模块的计划停用，失败立即退出，尚不停止任何服务。

开发启动使用所选后端及正式Worker单元，生产启动使用当前Compose与Profile声明，不由存活进程反推预期。Compose声明副本取规范化的scale／deploy.replicas，两者不一致拒绝；零副本或未选Profile不声明运行，完整计划将已有但不再选中的组置为计划停用，局部开发启动仍保留其他组。启动发布故障沿可选观测边界报告，核心启动继续，不能把原声明解释为本次启动成功。

生产System的受管目录只读挂载独立于指标开关且只有一个所有者，标准操作沿既有工作区生命周期锁串行。停止与启动读取同一根 `.env` 目录配置，局部停止仅改所选模块；计划停用发布失败不停止进程、不卸载 launchd、不执行 Compose down。文件发布不证明真实启动就绪或停止成功。

首次运行确认、连续窗口与告警规则管理权限统一见 [7.1.1](../addp平台运行观测规范.md#711-服务组失联规则)；部署声明和组计数只提供事实，失联／恢复仍由 Monitor 按该规则判定，不能把文件发布或零在线直接当作告警验收。

### 开发 Backend 启动失败

标准开发入口在成功发布运行预期后，为所选 Go Backend 开始本次尝试。受管目录中的 `service-startup-results.json` 使用 `addp.service-startup-results/v1`，以同一 `deployment_id` 和模块定位最近尝试，保留尝试标识、开始时间及可选失败时间和固定原因 `build_failed`、`process_exited`、`readiness_timeout`。选择性重试只替换所选模块，旧尝试不得写入新尝试。只记录实际执行到的检查，进程退出优先于同次就绪超时；不公开原始错误、命令、路径、PID 或凭据。无明确结果、未执行、探测暂停或文档无法核验不产生失败。生产、Worker、Agent 和 Copilot 另行接入。

System 按同一部署和当前 Backend 运行预期核验，并剔除计划停用、已被有效在线实例或失败后登记覆盖的记录。标准生产入口使用同一发现目录时清除开发结果，不把它作为生产部署的结果。只读 `GET /api/v1/system/platform/module_startup_failures` 复用一方平台用户和 `platform.module.read`，返回模块、失败时刻及固定原因。服务监控在原权限下独立展示，不插入实例列表或影响其分页。本投影不进入失联告警、租约或就绪判定。控制面未就绪时由启动终端提供诊断。
