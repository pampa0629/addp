# Outdoor 数据治理与指标实现规范

本文维护已经确认并落地的 Outdoor 样板链路，业务口径以[Outdoor 业务语义](../concepts/Outdoor业务语义.md)及 Owner 当前发布修订为准。业务样例不能进入 ADDP 通用默认值。未闭合的治理、语义查询和 Model 追溯见[后续专题](../next/Outdoor业务数据治理推进方案.md)。

## 一、唯一生产路线

```text
Meta 扫描物理事实 + Standard 发布语义定义
  -> Model 审批实体/逻辑表并创建或校验正式目标结构
  -> Transfer：MongoDB -> PostgreSQL ODS
  -> Develop：ODS -> DIM/DWD -> DWS
  -> Quality：ODS、DIM、DWD、DWS 分阶段门禁
  -> Orchestrator：引用各 Owner 持久任务，控制唯一 DAG
  -> Model 发布指标实现 -> Service 冻结消费契约 -> Workbench 应用
```

Standard 拥有术语、数据元、码值和单值指标定义；Model 拥有概念实现映射、逻辑表/关系、计算语义及不可变实现修订。Meta 拥有真实技术身份，Catalog 只维护企业目录与治理关联，不复制指标实现。Transfer 不认识 Model，只做贴源跨引擎同步；Develop 从 PostgreSQL ODS 起步，覆盖正式 DIM/DWD/DWS；Quality 只负责其固定修订和问题事实。各 Owner 保持独立定义、执行授权与生命周期。

本样板直接把实体映射到事实/维度逻辑表，不另建实体型中间表、发布组、staging/sealed 批次或第二套输出表。单表 overwrite 事务不等于跨表原子发布；质量失败阻止后继，不回滚已提交上游，不能声称失败回滚或服务发布隔离。

## 二、贴源与治理事实

ODS 保留源人员、活动及带原始 `member_index` 的活动成员。MQL 仅投影对象字段、展开成员数组等确定性结构整理，不解释 Standard 码值、不递归自动摊平 BSON、不回填推定身份到源 MongoDB 或 ODS。

当前主领队唯一由活动维度加工产生：非空 `leader.personid` 优先，缺失才取原始 `member_index=0` 的 `personid`，两者皆空保持 NULL 并告警。不能先过滤状态再取首位、取最小非空位置、按角色或创建账号猜人；非空原 leader 即使与首位冲突也不覆盖。DWD 读取治理后的活动维度，不重复实现优先级。

有效活动具有可解析日期，不晚于本次执行日期，且源状态非草稿/取消；历史 published/registration_closed 的归类按明确码值修订处理。强度保留最终数值语义：ODS 贴源，DIM/DWD 使用 decimal 显式转换，失败为 NULL 交 Quality 观测，不按 int 截断。

| 正式表 | 粒度与要求 |
| --- | --- |
| `dim_outdoor_person` | 每人一行，稳定 ID 与授权展示属性 |
| `dim_outdoor_activity` | 每活动一行，原/标准状态、日期、有效性、主领队与名称 |
| `dwd_outdoor_participation` | 有效活动的人员＋活动复合键；合格成员并集主领队，去重后保留 `is_current_leader` |
| `dws_outdoor_person_metric` | 每人＋指标＋定义修订＋范围一行，仅两项预计算次数，含零活动人员 |

参加事实纳入 signup/leader/leader_group 成员及明确主领队，主领队即使成员状态缺失或不在成员数组也必须进入；替补、占坑、浏览及人员侧摘要不参与该事实生成。不补造源人员身份，不以人员主档缺失直接丢弃合法活动引用。附加队员与 AA 名单不自动纳入。

## 三、指标与服务发布

Standard 的每个 MetricDefinitionRevision 表示确定粒度的一个标量；方向性比率以主体→比较对象为一个指标，Service 可在同次查询中组合两个方向，不把响应结构反写为指标定义。

- 主领队次数：按人员对当前主领队活动 ID 去重。
- 参加次数：按人员对合格成员并集当前主领队活动 ID 去重。
- 定向重叠率：相同有效活动范围内 `|A∩B|/|A|`，交换角色得到反向；零分母为 0，同人且集合非空为 1，未知主体无结果。

Model 明确事实表、稳定字段、主体维度、活动去重键、DATE、固定过滤及角色，不接受未经定义的附加口径。参数使用显式起止半开区间、total/month、forward/both；月桶包含原始区间相交月份并补零，两个方向在同一查询快照计算。计数和比率保持精确类型，不经浮点展示反写原值。

生产实现冻结数据库无关计划包，由精确版本引擎编译器及同一 PreparedQuery 提供 ReadSet、OutputLineage 和执行；规范见[引擎插件接口](addp引擎插件接口规范.md)及[Model 约束](../../model/docs/model概念与数据约束规范.md)。不保存另一份固定 SQL 事实，不在 Service/Workbench 回退为客户端聚合或 Outdoor 专用分支。

来源、定义修订、字段或编译器变化后显式发布新的 Model 实现、Service 重绑和 Workbench Revision，历史修订不改写；服务 ID、配置并发 version、消费指纹和计算修订分别表达。Service 输出主体稳定标识及显式名称，Workbench 不从另一目录当前页补姓名。

两项次数与重叠率共享同一日期/粒度语义。Component 每个只消费一个 Service；不同指标组合为多个 Component，参数与选择绑定显式关联，不扩展未确认的多指标查询或硬编码选项。全期卡片、月图、下钻明细使用同一已发布契约。

去重明细由 Model 同一实现修订明确启用，冻结独立 details 计划，经 Service 单独发布；Workbench 选择传主体与 bucket，明细保留原日期半开区间，不在前端换算月份。分页总量与同口径汇总对账，不补零；源在两个请求间变化时不承诺跨请求快照一致性。

## 四、分阶段质量与编排

唯一全量刷新由三个 ODS 同步、四个 Model 创建/校验结构、四个 Develop ETL、四个 Quality 节点组成，共 15 步。质量主表和参照表显式绑定相应上游 `outputs.target_locator`，不依赖方案默认物理表；手工与定时触发引用同一 DAG，是否启用 Cron 由实际配置决定。

| 阶段 | 必须阻断的约束 | 告警及解释 |
| --- | --- | --- |
| ODS | 三张源非空、人员/活动键、成员活动引用、允许状态、原数组位置组合键 | 缺人员/状态、主档引用、非草稿缺日期、昵称空白；原始同人同活动重复不直接当错误 |
| DIM | 键完整唯一、规范状态/有效性、有效日期及非未来、非空主领队的人员引用、源优先级一致 | 缺领队/昵称分别观测，不因告警消失证明推定正确 |
| DWD | 人员＋活动键、两类外键、参加状态、日期/强度/领队标志与 DIM 一致，合格源成员与主领队均有事实 | 只对明确纳入范围对账，不把排除记录当遗漏 |
| DWS | 人员＋指标＋修订＋范围键、两项指标/版本、非负非空值、人员引用、每人两行及独立活动去重对账 | NULL 不当 0，明细行数不冒充去重活动数，昵称缺失独立告警 |

质量执行成功只代表阻断级门禁通过，不代表所有告警或数据缺陷消失；各项命中不能跨项相加为去重坏记录数。问题 scope 随目标/参照范围变化，旧 scope 工单不伪装自动解决。人工接受历史异常按精确记录、固定规则修订和有效目标保留审计；新异常和已恢复后复发不继承旧接受结论。

已确认不继续追溯或归并缺失历史人员，不补造 ID、昵称或成员状态，也不清除源缺陷来追求全绿。接受异常不表示数据已修复，后续调查须有新的业务范围确认。

## 五、概念追溯与隐私

业务实体直接映射对应事实/维度表，Participation 的两条关联映射到人员与活动维度。概念映射只提供追溯、审批和影响确认，不执行数据加工。活动实体的 current_leader_of 表达人员→活动关系；参加事实 person_id 外键不能冒充主领队关系。

当前 LogicalField→EntityAttribute 不能直接表达关系派生字段，TableRelation 编辑也不开放维度→维度关系；主领队 ID/昵称因此是加工结果字段，不伪造普通属性映射。若扩展关系派生映射，先单独确认概念与唯一技术路径。

Copilot 只消费批准的语义与授权事实，昵称不当唯一身份，缺少定义/字段/口径时结构化澄清。电话、OpenID、人脸、原始样本不进入默认模型上下文；源 MQL 金样用于开发回归，不成为并行生产指标接口。完整语义查询尚需后续闭环，不能由 Catalog 替代执行引擎。

## 六、验证

按实际变更选择 Standard/Model/Service/Workbench/Quality/Transfer/Develop 的根 `make test-module MODULE=<owner>`，共享分析编译扩散到 Common PostgreSQL/MySQL 金样，工作区聚合使用 `make test-changed`。线上配置验收与代码门禁、专用 T4 分别记录，不把某次业务快照数值固定为通用 CI 期望。

固定最小夹具覆盖主领队优先级、原始成员首位、状态缺失、合法成员并集、重复引用、零分母、非整月范围、未知主体、质量阻断/恢复及历史异常接受。父/子 execution 与明确目标形成追溯，不将临时运行 ID、页面修订号或个人数据写成长期规则。保留未完成的企业编目与跨层语义查询证据见后续专题。
