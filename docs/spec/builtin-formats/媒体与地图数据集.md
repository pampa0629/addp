## ENVI 双文件只读

首期预算：头文件最多 1 MiB / 64 个已解释字段，数据文件最多 512 MiB（含 header offset）；数值类型为 Byte、Int16、UInt16、Int32、UInt32、Float32、Float64。整数 NoData 必须为该类型内可表示的整数，浮点 NoData 不得溢出或下溢为零，允许浮点 NaN；不通过类型提升或舍入修补声明。更大文件和 64 位整数暂不纳入本阶段。

2026-11-02 用户批准首期 NFS / MinIO ENVI 读取和 COG 页面预览。canonical `format=envi`、`data_type=media`、`layout=multi`；只接受同目录的一份数据文件（主角色 `raster`）和一份 `.hdr`（角色 `header`），两者均必需。实现与分层验收范围见[正式证据](../testing/evidence/资源读取与预览历史证据.md#envi-双文件读取与-cog-hosted-t4)，限定样例不代表任意数值类型页面、版本或容量均已通过。ENVI 不能冒用已有 HFA `img` 身份，单个 `.img`、`.dat` 或 `.hdr` 后缀均不能证明 ENVI 数据项。

唯一配对必须由已观察文件与完整、有界头文件共同证明。支持追加 `.hdr` 或替换数据扩展名的命名方式，但存在多个候选头文件、一个头文件对应多份数据或与其他强内容身份冲突时拒绝认领；保留真实文件名称和大小写，不替用户选择一个候选。主内容仍为数据文件，不把头文件作为独立影像。

首期为 `ENVI Standard` 的基础整数和实数栅格，支持 BSQ / BIL / BIP、大小端、header offset、NoData 与已声明的 CRS / 网格。头文件必须完整读取且不得包含重复或矛盾字段；尺寸、数据类型和原始文件大小须相符，不把截断或附加内容当作完整组成。未知资源语义、外部 DEM 等引用、分类 / 光谱库 / 虚拟镶嵌、压缩封装与复数暂不支持，明确拒绝而不忽略依赖。首期不写入或导出 ENVI。

已观察到 ENVI 头签名及匹配命名的主文件，在头字段不支持、尺寸不符、旁文件或配对歧义时保留 `envi/multi` 身份和 `composition_complete=false`，不认领未证明的头文件、不沿普通 IMG 单文件路径读取。只有完整证明才能输出双文件 refs、申请精确授权及绑定 Native；强内容签名已确认的其他格式不被同名头文件改认。

Meta basic / deep 扫描消费相同的组成证明，写入精确 refs 与完整状态。对象检测器保持桶内路径，持久化计划独立投影为含桶名的完整路径；`format_info.envi.header_path` 必须与同一投影后的 header ref 完全相等，不能在消费端接受两种路径或从 refs 回填矛盾证明，投影不得修改检测器原始事实；只成功认领这两份文件，不扩展为目录或对象 prefix。System 沿现有不可变 Grant 冻结完整清单；主文件旧许可不得自动升级为双文件许可，组成变化须重新批准。元数据事实不是允许读取的回执。Manager 必须消费当前完整组成及当前裁决，并在私有暂存范围内交付精确文件；GeoPython 仍由 GDAL ENVI 驱动读取像元，再沿既有 COG 路线生成与预览，不直接打开含其他文件的业务目录。头文件、数据文件和产物的版本、失败回收与清理须分别验证。

正式验收须覆盖三种交错、大小端、像元及完整缺失掩膜、网格 / CRS、两份源文件逐字节下载、COG 页面与缓存，以及缺失组件、歧义配对、外部引用、部分许可、组成变化、撤销及完整清理。新增 ENVI 场景不能借用既有 IMG / JPEG2000 通过结果。SKP 精确组成授权仍关闭。

依据：[GDAL ENVI 驱动](https://gdal.org/en/stable/drivers/raster/envi.html)、[ENVI Header Files](https://www.nv5geospatialsoftware.com/docs/ENVIHeaderFiles.html)。

## GRIB2 单文件只读（限定范围已验收）

2026-11-03 用户批准 `format=grib + data_type=container + layout=single`：自包含 GRIB2 中每条单场消息作为独立二维 `array` child，以文件中消息序号定位，不按同名要素合并，不把不同网格塞进共同波段。查看要素、单位、起报／有效时间、层次及各自网格，复用共享有界网格切片；不新增任务、产物或数据类型。实现、本地验证和正式 Hosted 分别记录，批准不等于验收完成。 当前限定 NFS／MinIO、三类规则网格消息的正式 Hosted 已通过，受验 `6e7ae8755`、运行 `41572302717`；四份原件、数值／掩膜、页面可见切片、精确元数据授权撤销和全部清理已独立核验，详见[正式证据](../testing/evidence/资源读取与预览历史证据.md#grib2-单文件读取与切片--数值通过及页面收口)。不外推到其他编码、产品模板或全量生产能力。

唯一数值路线为现有 GeoPython 的 GDAL GRIB 驱动。完整主文件先在私有快照内核消息长度、分节顺序、计数和尾标，禁止未解释的前后缀、截断及部分成功。首期接受规则经纬网模板3.0、+i 正向、逐行南北向扫描（标志0／64），产品模板4.0／4.8和数值模板5.0简单打包／5.4 IEEE Float32/64；其余网格、扫描、产品／数值编码及本地扩展明确拒绝，不静默忽略。单消息多场、GRIB1、复杂／旋转／不规则网格及其他压缩后续处理。

文件最大128 MiB、最多128消息，单场最多16777216网格点、全文件最多67108864点；每消息保留有界原模板及 GDAL 元信息。只接受无bitmap或消息内显式bitmap，拒绝引用先前／外部bitmap。有效掩膜按文件bitmap及受支持扫描顺序独立计算；GDAL的缺失替代值不能将合法同值像元判缺失。数值仍只由 GDAL 解码，bitmap／结构检查不是第二数值解码器。禁用单位归一化、经度重排、外部 `.idx`、PAM、overview及目录发现；不把主文件同目录其他文件纳入读取。每场独立打开自己的精确消息字节，不以多波段打开掩盖异质网格。

GRIB 数值为解码后的物理值，`value_mode=decoded_native_units`，保留文件声明单位和经度；不称为压缩位流或 NetCDF 的 `raw_storage`，不自动转摄氏、转换时间／层次单位、重采样或换列。共享切片的最大4096点／每边128、源版本绑定、变化后刷新和取消沿用现行契约。首期不返回地图 footprint，不开放 COG 快显／专业计算或导出。原件经现有内容出口完整下载；新格式不自动扩大现有 System 精确内容源授权准入。元数据查看复用现行 `metadata_target`／`metadata_read` 契约，仅返回结构投影；元数据 Grant 不证明内容完整性，也不替代既有 Manager 内容读取权限与 Security 校验。SKP 精确组成授权仍关闭。

实施同步 Common／GeoPython／Meta／Manager、共享切片显示及 i18n；标准 Native 入口、共享扩散 Go／PG、前端与同一 Manager Hosted 的独立 case 同次接线。正式验收须逐消息核数值／bitmap／单位／网格／时间、异质网格及重复要素不混淆、原件 API／按钮下载、真实切片和源变化／坏输入拒绝、全部源／临时对象／部署清理；不能借用 NetCDF 已通过证据。

依据：[GDAL GRIB](https://gdal.org/en/stable/drivers/raster/grib.html)、[ECMWF 消息结构](https://confluence.ecmwf.int/spaces/MTG2US/pages/514756246/About+GRIB+data+format)、[bitmap](https://codes.ecmwf.int/grib/format/grib2/sections/6/)。

## NetCDF 单文件只读

canonical `format=netcdf`、`data_type=container`、`layout=single`。经典内容签名CDF-1/2/5（经典、64位偏移、64位数据）沿既有路线读取；`.nc`/`.cdf`/`.nc4`仅候选，不能把任意HDF5当作NetCDF，也不登记通用HDF5签名为NetCDF身份。2026-11-02用户确认增加NetCDF-4首期：仅自包含、根组内的基础数值网格及常规无损压缩。GeoPython内部原生HDF5组成预检必须先通过，数值和公开属性仍只由GDAL netCDF多维API读取；不增加服务、权限、第二数据读取器或写入能力。实现、本地验证和正式Hosted分别记录，范围确认不代表验收通过。

NetCDF-4只接受文件起始的标准HDF5签名、单一原生文件驱动和完整根组。组成预检枚举全部根链接及数据集（最多512个，含维度占位对象），拒绝外部/软/用户链接、硬链接别名、子组、命名或复杂类型、外置raw storage和虚拟数据集；不能只抽查选中变量，也不能用GDAL读取成功或主文件SHA代替完整性检查。只支持标准整数/IEEE实数及单字节字符结构，属性限固定长度文本及基础数值；用户VLEN、枚举、复合和引用类型均拒绝。正常维度绑定中的`DIMENSION_LIST`和`REFERENCE_LIST`是唯一引用例外，必须核固定类型和形状、文件内目标、轴序/维长度、维度标记及双向绑定，不因属性同名就放行。`REFERENCE_LIST.dimension`只接收标准32位有符号或无符号整数（包括源字节序），统一无损读为Int64后检查非负、轴范围及双向绑定；拒绝负值、越界及其他类型，不依赖宿主HDF5版本选择解析分支。依据[HDF5维度标尺规范](https://hdfgroup.github.io/hdf5/develop/_h5_d_s__u_g.html)及[netCDF-4格式说明](https://docs.unidata.ucar.edu/netcdf-c/current/file_format_specifications.html)，该字段属于内部维度标尺引用，不是用户数值读取路线。内部HDF5事实还须与同文件netCDF根组的变量、类型和维度逐项对应；`_NCProperties`等标记不能单独证明格式或组成。

NetCDF-4允许连续或分块布局，以及无filter、deflate、shuffle、fletcher32内置无损filter；未知/重复filter及不符声明的参数拒绝，动态filter、VOL和VFD插件禁用。单chunk解码不超过16MiB，属性数量/长度沿用现有有界预算；检查器在独立短进程中限制30秒CPU及30秒墙钟时间，失败或超时拒绝，不回退到HDF5驱动或其他读取器。文件和声明预算不等于恶意原生文件的完整内存安全认证，不声称在所有宿主OS上具备进程硬内存限额。NetCDF-4嵌套分组、外部引用、跨文件、任意CF语义和复杂类型不在本阶段；合法但未支持的文件明确报告未支持，不称为格式非法。

Meta通过既有执行期容器Provider记录有界变量/维度/类型/单位/原属性和精确源内容SHA256。变量保留真实名称、维序、维大小及原生类型；数值变量的二维切片是临时预览网格，不新建数据项、任务或业务产物，不把整个多变量文件当单张影像或普通表。非数值/标量/一维变量可查看结构，但不宣称支持二维绘图。变量清单/属性超预算拒绝完整标记，不静默截断。用户须明确选择变量；二维网格取该变量最后两维，所有前导维必须显式指定一个零起始索引。窗口最多4096格，每边不超过128格；没有默认读取完整数组的入口。

预览沿Manager唯一`/preview`契约传递有界变量/维索引/窗口选择，沿现有普通文件语义核当前Tenant、精确主文件及manager.data_item.read与manager.content.read、未受管原值保护检查，检查源SHA256；源变化暂停预览并提示刷新元数据。此阶段不扩大System新源授权准入格式范围，不把内容权限核验声称为精确组成源Grant验收。GDAL只打开授权主文件的私有快照且只允许netCDF驱动，不解析用户传入的GDAL子数据集字符串、不访问远程数据源或旁文件。主文件最大128MiB，下载与快照读取均受限；原始字节与存储不改写，临时文件随调用清理，不产生持久缓存或新结果登记。

数值属性统一通过GDAL已有的`ReadAsRaw`按声明的原生数值类型解码，不调用新版绑定才有的Int64便利方法，也不经double或字符串转换读取64位属性；类型、元素数量和原始缓冲长度必须一致，不增加按版本分支。2026-11-01用户确认：GDAL继续独占原值及属性读取，GeoPython统一按各自声明的原生数值类型计算有效掩膜，切片和定位坐标轴共用该实现；删除`MDArray.GetMask()`路径，不按GDAL版本分支。`_FillValue`须为一个数值，`missing_value`可为非空数值列表，`valid_min`/`valid_max`为单值，`valid_range`为有序双值且不得与前两者并存。比较采用精确保留的整数/浮点标量，不把整数转为double或将属性强转为变量类型；NaN无效，显式缺失标记和范围在原存储值域判定，范围端点包含在内。GDAL返回的属性视图出现非数值类型、错误数量或范围冲突时拒绝该切片；定位轴无效则不定位。属性视图不等于经典CDF文件头的独立完整校验：GDAL把零长度数值属性呈现为标量，当前路线不能证明这类源声明的原始长度，不据此声称所有畸形文件均可识别。保持原受控原值预览边界：未声明的默认填充值、推导有效范围和辅助坐标传播均不自行补入，不宣称完整CF校验；Infinity按原值保留，仅由显式标记/范围决定有效性。数值预览保留原存储值文本、有效掩膜和scale_factor/add_offset原属性，不以JavaScript Number承载Int64/UInt64，不隐式把原存储值改为物理量。时间维保留units/calendar和原值，不猜Unix时间或公历。仅明确原生CRS、可证明的规则一维坐标轴及受支持二维网格可产生切片空间事实；未知CRS、曲线网格、未知坐标含义不自动定位、不默认4326。变量的空间信息不提升为整个父容器统一extent。跨文件聚合、外部变量、复杂复合类型、写出及科学计算均不在首期。

## IMG / ERDAS Imagine

遥感 IMG 首期指 ERDAS Imagine HFA，canonical `format=img`、`data_type=media`、`layout=single`。`.img` 为候选，实际读取必须由 GDAL HFA 驱动验证，不能把 ENVI、磁盘镜像或其他同后缀文件当作 HFA。元数据通过执行期绑定的 `RuntimeMediaInfoProviderFactory` 调用 GeoPython `raster_inspect`，不把 GDAL 嵌入 Go 进程。

首期只支持实数像元的自包含 HFA 主文件；复数波段拒绝隐式取实部或幅度，需先显式转换；波段须具有一致的数据类型及 NoData 声明，不把异构声明静默压成 TIFF 的共同属性；包含 `.ige` spill、RRD 引用列表（首期包括内部 overview 引用）、dependent file 或其他外部组件时拒绝深扫和生成，不隐式读取目录或对象 prefix。后续多组件支持须先明确 Meta 精确 refs 与访问计划，不用同名猜测或整目录授权补齐。GDAL 官方驱动边界见 [HFA](https://gdal.org/en/stable/drivers/raster/hfa.html)。

尺寸、编码、文件大小写入 `type_info.media`；HFA 驱动、波段数、波段数据类型、NoData、profile 和检查完整状态写入 `format_info.img`；源坐标系和像元覆盖范围写入 `capabilities.spatial`，缺失时保持未知。检查失败不得保留旧的完整标记或空间摘要。

浏览器不直接解码 IMG。Manager 仅在完整 HFA 检查成功后提供既有 `generate_raster_cog` 动作，经受管 COG 结果沿既有 Range 地图渲染；源 item 始终保持 `format=img`，COG 为派生产物。本期不支持 IMG 写出，不把可注册、可扫描和可预览等同于全部厂商变体支持。


## GRD / Surfer 数值网格

`format=grd`、`data_type=media`、`layout=single` 包含 Golden Software Surfer 单波段数值网格，`.grd` 仅为候选。唯一读取入口先核完整有界 framing，再按内容选择原生驱动：`DSRB` 对应 Surfer 7／GS7BG，`DSBB` 对应 Surfer 6 Binary／GSBG，`DSAA` 对应 Surfer 6 ASCII／GSAG；不是读取失败后的回退。GMT/netCDF、Northwood 等同后缀编码不在本范围。复用 GeoPython `raster_inspect`／`raster_load` 和执行期 `RuntimeMediaInfoProviderFactory`，不在 Go 中加载 GDAL，不增加服务、商业 SDK 或权限。

只读取不超过 64 MiB 的单一主文件，支持版本 1／2 的一个完整 GRID／DATA，至少两行两列、正有限节点间距、零旋转与 Float64 数值；拒绝未知／重复段、fault 结构、尾随内容、截断、无效尺寸／长度、非有限声明及非有限有效值。版本 1 的大于 BlankValue 的非标准化缺失标记不交给只按相等比较的原生掩膜解释，首期明确拒绝；标准允许的其他表达不因此宣称为非法 GRD。版本 2 按 BlankValue 相等语义读取。节点坐标与像元覆盖边界分别核对：源数据从最小 Y 行开始，GDAL 读取按顶部行组织，半像元换算不得改变节点位置。

Surfer 6 Binary 使用完整 56 字节头、正的有符号 16 位宽高（至少两行两列）、有限且严格递增的 XY 节点范围及连续 Float32 像元；主文件同样不超过 64 MiB，长度精确等于头加全部像元。固定 NoData 按 Float32 的 `1.701410009187828e38` 精确比较，不把其他有限数值变为空值，不提升源精度；全缺失网格可读取。原生打开后逐块比较 GDAL 像元的精确 NoData 判定与原生有效性掩膜，任一点不等价则拒绝读取；例如当前 GDAL 把约 `2e38` 的有效 Float32 误判为缺失时，不允许静默进入后续计算，也不新增掩膜修补／转换路线。拒绝非有限头／像元、截断、尾随内容、不可表示的间距／半像元边界。节点从最小 Y 行开始存储，GDAL 返回顶部行在前。

Surfer 6 ASCII 仅接受大写 `DSAA`、五行 ASCII 头（LF／CRLF），字段以空格／制表符分隔，像元可跨行；主文件不超过 64 MiB，头不超过 200 字节、单数值 token 不超过 128 字节。宽高为至少两行两列的正整数；完整扫描有限十进制／科学计数数值，数量须与尺寸精确相符，不接受 BOM、非 ASCII、注释、逗号、未知尾随 token、截断、非有限值或非零数下溢为零。XY 节点范围和半像元边界沿用有限、正间距与可表示性约束。以 GSAG 原生 Float64 解码文本；保留其二进制浮点表示，不承诺任意精度十进制。文本固定 NoData 为 Float64 `1.70141e38`，不混用 Binary 的 Float32 常量；全缺失网格允许读取。逐块核对原生像元与源文本 Float64 语义、精确 NoData 与原生 mask，不等价即拒绝，不改数值／mask、不新增转换路线。`profile=surfer6_ascii`，无版本字段。

宽高、`encoding=GS7BG`、`GSBG` 或 `GSAG`、源大小写入 `type_info.media`；`format_info.grd` 保存 `profile=surfer7_binary`、`surfer6_binary` 或 `surfer6_ascii`、驱动、完整标记、波段类型／NoData 及源节点网格事实。Surfer 7 保存头内的版本 1／2；Surfer 6 没有版本字段，不伪造版本号。读取在隔离主文件快照内进行，不发现、认领或读取 `.gsr2`、PAM／PRJ、外部 overview 等旁文件。三种主体的 XY 范围与节点间距均不证明 CRS；元数据不推断 EPSG，未知坐标系不开放 Manager 地图生成。用户在工作流中显式声明 `source_crs` 时，沿用既有执行期 CRS 赋值与 GeoTIFF／COG 输出，不回写源文件或源元数据。

本阶段不开放 GRD 写出；定位导出及旁文件交付方案另行确认。格式登记、原生读取、Meta／Manager 消费与正式 Hosted 分别记录，不用单独原生测试代替页面或三引擎验收。依据：[Surfer 6 ASCII 官方结构](https://surferhelp.goldensoftware.com/topics/ascii_grid_file_format.htm)、[GSAG 驱动](https://gdal.org/en/stable/drivers/raster/gsag.html)、[Surfer 6 Binary 官方结构](https://surferhelp.goldensoftware.com/topics/surfer_6_grid_file_format.htm)、[GSBG 驱动](https://gdal.org/en/stable/drivers/raster/gsbg.html)、[Surfer 7 官方结构及 NoData 版本语义](https://surferhelp.goldensoftware.com/topics/surfer_7_grid_file_format.htm)、[GS7BG 驱动](https://gdal.org/en/stable/drivers/raster/gs7bg.html)、[官方 GSR2 定位信息](https://surferhelp.goldensoftware.com/subsys/Golden_Software_Reference_File.htm)。

## JPEG2000

canonical `format=jpeg2000`、`data_type=media`、`layout=single`，候选扩展名为 `.jp2` 和 `.j2k`，分别对应 JP2 文件容器与原始 JPEG2000 codestream；它们不归入普通 JPEG。首期仅接受自包含、单 codestream 的 JP2 Part 1 或原始 J2K，由既有 GeoPython `raster_inspect` / `raster_load` 的 JP2OpenJPEG 驱动确认；不支持 JPX 多图像／外部片段组合，不新增服务或 JPEG2000 写出路线。

只读取主文件；隔离源快照后以 `GEOREF_SOURCES=INTERNAL` 读取内部 GeoJP2／GMLJP2，关闭远程 GML，使用 raster-only 原生打开。世界文件、PAM `.aux.xml`、外部 overview 和产品目录不被认领或读取；仅有外部定位的文件保持无定位，不猜 EPSG:4326。首期不展开嵌入 GML 矢量层。驱动的定位来源与 codec 边界见 [GDAL JP2OpenJPEG 官方说明](https://gdal.org/en/stable/drivers/raster/jp2openjpeg.html)。

宽高、编码 `JP2OpenJPEG`、原大小和 MIME 写入 `type_info.media`；`format_info.jpeg2000` 保存 `driver`、`profile=jp2/j2k`、完整标记及波段摘要；内部 CRS 和 extent 写入 `capabilities.spatial`。检查失败清除旧媒体、空间和格式摘要；有损源保留解码后像元语义，不声称恢复压缩前像元。实数、同类型／同 NoData 波段沿用现有栅格限制。

Manager 仅对已完整检查且有 CRS／extent 的源开放既有 COG 生成；浏览器只渲染受管 COG，不直接解码 JPEG2000。对象内容分派不得因 `image/jp2` MIME 将源认作浏览器图片；无 COG 时使用现有不支持直接预览提示，不返回源图片 URL 或 base64。无定位可查看元数据和下载原文件，不开放地图生成。缓存复用和删除沿用 COG 生命周期。本地原生测试与正式 Hosted 分别记录，不以注册或本地测试代替正式验收。

## 图片

### 识别与组织

| 维度 | 取值 |
|---|---|
| `layout` | `single` |
| `data_type` | `media` |
| `format` | `jpeg`、`png`、`gif`、`tiff`、`webp`、`bmp`、`image` |
| 主资源 | `meta_item.full_name` 指向图片文件 |

`image` 是图片兜底格式，只在无法稳定识别具体图片格式时使用。JPEG、PNG、GIF、TIFF 等具体格式应优先写入具体 `format`。GeoTIFF 不新增独立基础格式，表达为 `format=tiff + capabilities.spatial`。COG 是 TIFF 的云优化 profile，不新增 `format=cog`。

TIFF / GeoTIFF 如果存在 `.tfw`、`.tifw`、`.wld`、`.prj`、`.aux.xml`、`.ovr`、`.hdr` 等同 basename sidecar，应按 `layout=multi` 归并为一个 item，primary content 仍为 `.tif` / `.tiff`。如果没有 sidecar，则按普通 `layout=single` 图片 item 处理。具体 ref 白名单见 [ADDP 数据项探测器规范](../addp数据项探测器规范.md)。

主 TIFF 完整文件名追加 `.aux.xml` 得到 GDAL PAM 文件名，例如 `image.tif.aux.xml`。Meta 将存在的 PAM 登记为可选 `auxiliary_metadata`。计算和 COG 生成沿[栅格计算与成果契约](../addp栅格计算与成果契约规范.md)读取。

WebP、BMP 的 descriptor 与 `MediaInfoProvider` 统一由图片插件持有，默认 `single + media`，保留 `.webp` / `image/webp` 和 `.bmp` / `image/bmp`、`image/x-ms-bmp` 识别事实。头部摘要读取上限为 1 MiB，只返回编码像素宽高、`encoding=webp/bmp` 和 canonical MIME，不声明缩略图、EXIF 或 ICC 色彩配置，也不凭解码器默认模型补填 `color_space`。WebP 覆盖 VP8、VP8L、VP8X 头部；动画画布尺寸由 VP8X 提供，帧摘要按下述有界动画规则读取。BMP 覆盖 BITMAPINFOHEADER / V4 / V5 的无压缩 8/24/32 位及解码器支持的默认 RGBA bitfields，含 top-down；其他位深、压缩或 DIB 变体明确拒绝。非法、截断、格式不符或超预算头部返回错误；摘要成功不代表完整像素数据有效。Manager 沿用媒体原始内容 URL 预览，实际渲染取决于浏览器。

SVG、AVIF、HEIC / HEIF 仍只有 descriptor；在仅能 raw / range 预览时，不应标记为后端已经具备 `MediaInfoProvider`。

### 工作流普通图片导出

工作流 `raster_save` 的普通图片出口支持 PNG 与 JPEG，使用既有目标资源授权、发布和自动扫描。输出故意不携带原栅格 CRS、网格、GCP、RPC、EXIF 或定位旁文件，不提供 GIS 定位成果。PNG 保留 Byte／UInt16 像元、灰度／RGB 与 alpha；JPEG 仅接受全部有效的 Byte 灰度／RGB，明确有损，质量整数 1–100、默认 90。不自动拉伸、缩减位深、展开色表、挑选波段或合成透明背景。不支持的输入须在目标写入前拒绝；PNG 完整像元及有效覆盖回读、两类单文件与去定位检查通过后才发布。详细约束见 [栅格计算与成果契约规范](../addp栅格计算与成果契约规范.md)。IMG 写出暂缓，既有 IMG 输入及 COG 派生能力不受影响。

### attributes 写入

| 分区 | 写入内容 |
|---|---|
| `item` | `layout`、`data_type`、`format`；TIFF sidecar multi item 还应写入 `refs` |
| `type_info.media` | `kind=image`、`mime_type`、宽高、`encoding`、`color_space`、`size_bytes` 等媒体信息 |
| `format_info.<format>` | EXIF、TIFF tag、压缩方式等格式私有信息；TIFF 使用 `format_info.tiff.profile` 表达 `plain_tiff` / `geotiff` / `cog` |
| `capabilities.spatial` | 图片 GPS 或 GeoTIFF 可确定空间信息 |

### 预览读取

图片预览面向 `data_type=media`。如果图片包含 GPS 或 GeoTIFF 空间信息，可以额外启用空间能力展示，但图片本身仍是 `media` 类型。

JPEG EXIF 摘要通过现有 `MediaInfoProvider` 一次读取提供，由 Meta 写入 `format_info.jpeg`：`exif` 记录有效的 `orientation`（1–8，含镜像方向）、`make`、`model`、`date_time_original`、`offset_time_original` 和 `subsec_time_original`。拍摄时间保留源字符串，未知时区不推断为本地或 UTC；不以文件修改时间替代。宽高继续表示编码像素尺寸，不因方向标签交换、不改写像素。

曝光与焦距摘要直接读取 Exif IFD 的以下标签，JSON 值为数值：

| 源标签 | `format_info.jpeg.exif` 字段 | 单位 | 类型与数量 |
| --- | --- | --- | --- |
| ExposureTime（33434） | `exposure_time_seconds` | 秒 | RATIONAL，1 |
| FNumber（33437） | `f_number` | 无单位 | RATIONAL，1 |
| ExposureBiasValue（37380） | `exposure_bias_ev` | EV | SRATIONAL，1 |
| FocalLength（37386） | `focal_length_mm` | 毫米 | RATIONAL，1 |

曝光时间、F 值和焦距须大于零；曝光补偿允许负值和零。分母为零、类型或数量错误、越界数据记为 invalid 并省略该字段，其他合法字段保留。缺失标签不补值，不从 APEX 快门或光圈标签推导曝光时间或 F 值。此阶段不解析 MakerNote 或缩略图。GPS 支持范围见下述独立规则。相关 tag 定义见 [CIPA Exif 规范](https://www.cipa.jp/std/documents/e/DC-X008-Translation-2019-E.pdf)。

感光度摘要同样直接读取 Exif IFD，不统一命名为 ISO，也不通过不同定义的参数互相补值：

| 源标签 | `format_info.jpeg.exif` 字段 | 类型与数量 |
| --- | --- | --- |
| PhotographicSensitivity（34855） | `photographic_sensitivity` | SHORT，非空数值数组，保留源数量和顺序 |
| SensitivityType（34864） | `sensitivity_type` | SHORT，1，取值 0–7 |
| StandardOutputSensitivity（34865） | `standard_output_sensitivity` | LONG，1 |
| RecommendedExposureIndex（34866） | `recommended_exposure_index` | LONG，1 |
| ISOSpeed（34867） | `iso_speed` | LONG，1 |

拍摄感光度及三个 LONG 参数须大于零；类型 0 是源声明的“未知”，类型缺失时不补为 0。`photographic_sensitivity` 的 65535 按源编码保留，仅表示达到 SHORT 上限（实际值可能更高），不能显示为准确 ISO；Manager 为该字段提供中英文提示。类型 1–7 分别表达 SOS、REI、ISO Speed 及其组合，按源值译名展示。类型、数量、值或偏移非法时省略对应字段并记录 `exif_status=invalid`，合法的其他摘要仍保留；不据这些字段诊断文件的全部跨标签合规性。未实现 ISO Speed Latitude、SpectralSensitivity、OECF 或 MakerNote 中的厂商参数。沿用总读取预算，不增加像素解码或第二解析路线。上述定义参见 [JEITA/CIPA Exif 感光度标签和附录 G](https://home.jeita.or.jp/tsc/std-pdf/CP-3451D.pdf)。

分、秒须在 [0, 60) 内，按 `度 + 分/60 + 秒/3600` 校验总量；支持带小数的分。缺失标签不补默认值，类型、数量、方位、分母、范围或偏移非法时省略对应字段并记 `exif_status=invalid`，其他合法字段保留。GPSVersionID 缺失记 invalid，但不为其补版本；仅诊断受支持标签，不宣称验证全部 EXIF 合规性。

GPS 接收机时间与相机 `DateTimeOriginal` 独立，明确采用 UTC，不补相机时区或把接收机时间认作快门时间。源日期必须为真实公历日期（年份 0001–9999）；源时、分分别在 [0, 24)、[0, 60)，普通秒在 [0, 60)，普通时间合计须小于 24 小时。仅 GPS 摘要合法且日期和时间都完整时，在同一 `gps` 命名空间生成 `date_time_utc`，使用 RFC3339 UTC 字符串；从源分数精确合计后截取到纳秒，不将浮点舍入造成的次日误写为源日期。`23:59:60` 至 `23:59:61` 之前的闰秒源分量可保留，但此阶段不验证具体闰秒日期、不生成 RFC3339 时间；不把闰秒归一化到次日。缺日期或时间只保留已有合法源字段，不借用文件修改时间、相机时间或当前日期。刷新删除任一标签时同时清除旧组合时间。

移动速度、移动方向与图像方向均为独立源事实。合法零值保留，参考标签缺失时不补标准默认值，不转换速度单位或真北／磁北参考，也不以另一个方向的参考补值。移动方向不等同于图像方向；图像方向不等同于像素旋转的 Orientation，不生成相机姿态、设备轨迹或额外空间能力。类型、数量、参考枚举、分母、方向范围或偏移非法时只省略对应字段并记 invalid；此时也不生成统一拍摄点或组合 UTC 时间。刷新删除任一源标签须清除该旧字段，不能沿用旧单位或参考。

测量方式、DOP、差分修正状态和水平定位误差分别保留，不补缺失标签。GPSMeasureMode 不等同于 GPSStatus，也不据海拔是否存在推断二维或三维；GPSDOP 在二维测量中表达 HDOP，在三维测量中表达 PDOP，方式缺失时不判定其类型，不换算为米制误差。差分修正源 0 和两个 RATIONAL 源零值均保留；不将差分修正解释为 RTK fixed / float，不给定位质量评级，不计算误差圆或影像覆盖。非法类型、数量、枚举、分母或偏移只省略对应字段并标记 invalid，合法源字段保留，此时仍不生成统一拍摄点或组合 UTC 时间；刷新须清除已移除的源字段。沿用 APP1 总预算与同一 GPS IFD，不新增能力或另一解析路径。

目的地经纬度分量与方位、目的地方位角与参考、目的地距离与单位分别保存为独立源标签；经纬度沿用分、秒与总量约束，纬度不超过 90 度、经度不超过 180 度。合法零值保留，部分标签缺失不补标准默认值，不借用拍摄点经纬度或其他方向参考；K / M / N 为距离单位千米、英里、海里，不是速度单位。只记录源值，不换算单位或真北／磁北，不根据方位角与距离计算目的地点，不生成公共拍摄点、导航路线、设备轨迹或覆盖。非法类型、数量、枚举、分母、范围或偏移只省略对应字段并记 invalid，其他合法源字段保留，并阻止统一拍摄点与组合 UTC 时间；成功刷新须清除已移除的目的地标签。

媒体内容成功描述后，Meta 整体替换此次描述拥有的 `type_info.media`、`capabilities.spatial` 和当前 `format_info.<format>` 命名空间；本次未返回的事实须清除，其他命名空间保留。因此同一 JPEG 移除 EXIF / GPS、失去可用定位或移除基准时，刷新不能沿用旧拍摄位置、旧 SRID 或旧源标签。内容读取或描述失败时返回错误，不将失败当成成功空快照。

只有 EXIF 摘要为 `parsed`、经纬度及各自方位都合法，且未显式声明测量中断（V），才能生成 `capabilities.spatial.capture_location`。源 `map_datum` 为去掉外围空白、忽略大小写的 `WGS-84` 时，拍摄位置的 `srid=4326`；缺失、非法或其他基准不推断 SRID，不转换坐标，合法坐标仍可记录但不可当作 WGS84 上图。不会由 GPS 元数据生成影像覆盖 `extent`、顶层 SRID、像元 transform 或空间字段；海拔源值和海平面参考仅留在原生 GPS 摘要，不混为椭球高。GPS 卫星信息和处理方法标签尚未支持。定义见 [JEITA/CIPA Exif GPS 标签](https://home.jeita.or.jp/tsc/std-pdf/CP-3451D.pdf)。

JPEG 只扫描图像扫描数据前的 marker segment，总源读取预算为 1 MiB，支持非 seekable 输入及 TIFF 两种字节序。相机字符串与小数秒长度最多 1024 字节；未知或部分未知的拍摄时间不补值。`exif_status` 表示 `absent`（完整检查后没有 EXIF）、`parsed`（支持范围内摘要合法）、`invalid`（EXIF IFD 结构、受支持字段或 marker 非法，包括重复 tag 和 EXIF APP1）、`budget_exceeded`（无法在预算内完成检查）；非法或未完成检查不得被标记为没有 EXIF。非法 EXIF 不阻止已确认的像素尺寸返回，仅保留合法字段；重复 EXIF APP1 不选择其中任意一份。如果标准 JPEG 解码器不能在预算内确认尺寸，则返回解析错误，不输出猜测尺寸。实际 I/O 错误和取消仍返回错误，不吞为缺失元数据。

#### GIF / WebP 动画摘要

GIF 和动画 WebP 继续使用 `single + media + kind=image`。图片插件通过现有 `MediaInfoProvider` 提供 `format_info.gif.animation` / `format_info.webp.animation` 摘要对象，包含 `summary_status`；只有 `parsed` 才输出完整 `frame_count` 和 `duration_ms`。摘要对象在刷新时整体替换，避免旧帧数与新状态混合。这里的时长是单轮各图像帧的源编码延时合计（毫秒），不乘循环次数、不采用浏览器最短帧延时、不表达无限循环的总播放时长，也不写入 `type_info.media.duration_ms`。GIF 以 Image Descriptor 计帧，Graphic Control Extension 的百分之一秒延时乘 10；缺少控制扩展的帧按源默认零延时计。WebP 以 ANMF 计帧，延时直接为毫秒。宽高仍是画布尺寸。

头部确认沿用 1 MiB 上限；包括头部在内的总顺序读取不超过 8 MiB，最多 10000 帧和 65536 个块（GIF 含数据子块）。不解压或缓存压缩像素，只按块长度跳过。GIF 必须读到 Trailer，动画 WebP 必须完成 RIFF 声明边界内的 chunk 检查；未完成时不输出部分帧数或时长。`invalid` 表示非法长度、越界帧、重复/错误控制块或截断；`budget_exceeded` 表示读字节、帧或块超预算；GIF Plain Text 或交互等待控制为 `unsupported`，不把文本渲染或用户输入等待猜成普通图片动画。非动画 WebP 为 `not_animated`，保留原有头部摘要，不扫描像素以构造帧事实。摘要只校验受支持的容器结构，不保证压缩像素可解码；实际 I/O 错误及取消返回错误，非法动画结构仍保留已确认画布尺寸。

依据：[GIF89a](https://www.w3.org/Graphics/GIF/spec-gif89a.txt) 的 Graphic Control Extension 和 Image Descriptor，以及 [WebP RIFF](https://developers.google.com/speed/webp/docs/riff_container) 的 ANIM、ANMF 和 chunk 边界。

#### TIFF 云优化布局提示

COG仍是TIFF的profile，Go格式层仅提供 `cog_check_level=heuristic` 的有界布局提示，不替代GDAL完整COG验证、像素解码或OGC合规认证。空间定位、CRS和overview分别从自身事实读取，不是该布局提示的必需前提：小图可以没有overview，无定位源不得为通过识别而补造坐标系或网格。

Classic TIFF沿唯一布局核验路径检查完整主/overview/mask目录与SubIFD引用、唯一有序tag、正尺寸/瓦片尺寸、索引类型与数量、元数据和索引均位于瓦片前、各图像瓦片的行序及整体低分辨率先于高分辨率的数据顺序、非重叠区间和已确认的文件长度/EOF。最多256个目录、131072个瓦片，仍复用既有前/后各1 MiB元数据窗口，不增加全像素读取或Runtime依赖；顺序源读满预算但尚未确认EOF时保持未知，可seek源在合并窗口后也保留已确认的大小事实。GDAL结构声明若出现在官方头位置，须按固定长度行和声明大小完整解析；声明已被不兼容修改、畸形或未支持结构时不能给出正向提示，不能在任意位置搜到COG字符串就认定。无声明并不当然为非COG，仍须由同一物理布局核验决定。

只有上述有界结构核验通过时才输出 `profile=cog`、`is_cloud_optimized=true` 和 `cog_check_level=heuristic`。不满足、预算/元数据窗口不足或尚未支持的BigTIFF、稀疏索引与复杂排列均不输出云优化布尔值，不把未知写成false；仍保留实际已读的普通/GeoTIFF profile、瓦片和overview摘要。物理像素、压缩内容、完整覆盖、无定位边界和页面展示分别验收。依据：[GDAL COG结构、可选overview及头声明](https://gdal.org/en/stable/drivers/raster/cog.html#file-format-details)。

#### TIFF 页目录与分页基础预览

Classic TIFF 的 `format_info.tiff` 增加 `page_summary_status`、`page_count` 和 `pages`。`pages` 按顶层 next-IFD 链顺序列出主图像，每项包含从 0 起的 `ifd_index`、`width`、`height`；不遍历 SubIFD，不把 NewSubfileType 的降采样图像（bit 0）或透明掩膜（bit 2）计入页面。标准 SubfileType 的 reduced-resolution 标记同样排除。多页仍是一个 `media` item，不因内部页数变成 sidecar `multi` 或 container；原有媒体宽高保持首 IFD 的编码尺寸，空间事实与 COG 判定保持原边界。

页目录最多遍历 256 个 IFD，复用 TIFF 元数据窗口（前 1 MiB；seekable 源可另读后 1 MiB），不扫描像素内容。`page_summary_status=parsed` 时才输出完整 `page_count` 和 `pages`；循环、非法 IFD、重复 tag、非法尺寸或子文件类型为 `invalid`，元数据窗口不覆盖所需目录或 IFD 数超预算为 `budget_exceeded`，BigTIFF 为 `unsupported`。不输出部分目录冒充完整页数。页数统计不校验压缩像素是否可解码。

普通 TIFF 的分页基础预览消费已扫描的完整页目录，经既有 `storage-stream` Range URL 用 geotiff.js 按选中 IFD 读取；页目录缺失或不完整时提示深度刷新，不从第一幅图像推断文件只有一页。每次只渲染选中页，输出最长边不超过 1024 像素，源图像超过 1600 万像素则拒绝基础解码；不预加载所有页面，不退回整文件 URL 下载。GeoTIFF 的空间预览继续使用既有栅格/COG 路线。原始下载仍输出完整源 TIFF，不输出当前 canvas。

基础颜色显示支持无符号 8/16 位 RGB、1/2/4/8/16 位黑白或灰度，以及 geotiff.js 支持的调色板和 8 位 CMYK/YCbCr/CIELab 转换。RGB/灰度可带一个标准 alpha 通道，保留零透明度并处理关联 alpha。无附加通道的单波段 Float32／Float64 灰度页按当前预览采样的有效值最小值和最大值线性拉伸，恒定有效值显示为中灰，GDAL NoData 和非有限值显示为透明。MINISWHITE 反转灰阶。其余浮点、有符号采样或非标准通道沿不支持采样提示。压缩支持沿既有解码库，页目录解析成功后仍须实际解码像素。

依据：[TIFF 6.0](https://image-js.github.io/tiff/media/TIFF6.pdf) 的 IFD、NewSubfileType 与 SubfileType 定义。

GIF、WebP、TIFF 等多帧或多页图片仍表达为 `kind=image`。动图播放、帧数、页数、首帧缩略图等属于媒体信息或内容读取能力，不应改写为 `kind=video`。

大图、GeoTIFF、多页 TIFF 等不应依赖全量 base64 作为首屏预览。Manager 应优先使用 raw / range URL、缩略图、降采样或切片能力；后端是否生成缩略图由 `MediaThumbnailReader` 或后续媒体读取能力声明。

### 格式约束

- 不得给图片写入 `type_info.table.fields`。
- 不得把所有图片都视为空间数据。
- 不得把 GeoTIFF 表达为新的基础数据类型。
- 不得把 COG 表达为新的基础 `format`；COG 只能作为 `format_info.tiff.profile=cog` 或 Manager COG 生成结果表达。

## PMTiles 矢量瓦片集

### 识别与组织

| 维度 | 取值 |
|---|---|
| `layout` | `single` |
| `data_type` | `media` |
| `format` | `pmtiles` |
| 主资源 | 一个 `.pmtiles` 对象或文件；`full_name` 直接指向该单文件 |

`pmtiles` 表示 PMTiles v3 单文件瓦片归档。Meta 可以用 `.pmtiles` 扩展名形成候选，但落库前必须通过 Range Read 读取并校验 127 字节 header：magic 必须为 `PMTiles`、version 必须为 `3`、目录和数据区间必须落在对象大小内。一个 PMTiles 文件严格形成一个 item，不把内部瓦片展开成子 item。

ADDP 当前业务矢量瓦片集只接受 `tile_type=mvt`，瓦片矩阵集固定为 `WebMercatorQuad`，坐标语义固定为 XYZ。MVT tile compression 必须为 `gzip`；Service 读取 tile bytes 后必须返回 `Content-Type: application/vnd.mapbox-vector-tile` 和 `Content-Encoding: gzip`。PMTiles v3 的 header 与 metadata 是唯一格式事实源，不引入 ADDP 私有 sidecar manifest。

### attributes 写入

| 分区 | 写入内容 |
|---|---|
| `item` | `layout=single`、`data_type=media`、`format=pmtiles`，`refs` 只记录当前文件 |
| `storage` | 当前 PMTiles 文件的 `physical_path`、大小、修改时间等存储事实 |
| `format_info.pmtiles` | `spec_version`、`tile_type`、`tile_compression`、`internal_compression`、`min_zoom`、`max_zoom`、`addressed_tiles_count`、`tile_entries_count`、`tile_contents_count`、`clustered` |
| `capabilities.spatial` | header 中的 WGS84 bounds 与固定 `EPSG:4326` extent；中心点只保留在 `format_info.pmtiles.center` |

### 消费要求

Service 发布静态二维瓦片时只接受 Business 存储中 `format=pmtiles + layout=single` 的 ResourceLocator。发布时从 Meta attributes 冻结 item 指纹、对象路径、PMTiles v3 header 摘要和空间范围；运行时从 System 获取当前存储连接，通过 engine provider Range Read PMTiles。不得保存裸存储路径、存储凭据，或直接引用 Manager infra 快显缓存。

Manager infra 中的 PMTiles 缓存只有通过 `vector_tile_set_generation` 原子写入用户选择的 Business 存储、校验完成并经 Meta 扫描后，才成为可发布的 `pmtiles` data item。缓存 artifact 只可作为执行复用候选，不能替代业务任务身份或 Service 依赖。

## Raster mosaic

### 识别与组织

| 维度 | 取值 |
|---|---|
| `layout` | `whole` |
| `data_type` | `media` |
| `format` | `raster_mosaic` |
| 主资源 | whole scope 根目录或 prefix，`mosaic.addp.json` 是 manifest，不是 `full_name` |

`raster_mosaic` 是由 ADDP mosaic 生成任务产生的栅格镶嵌数据集。内置 descriptor 使用确定性文件名 `mosaic.addp.json` 作为候选识别事实，不声明 `.json` 扩展名，避免和普通 JSON 冲突。Meta 落库前必须读取 manifest 内容确认 schema、`format=raster_mosaic`、`data_type=media` 和 `layout=whole`，不得仅根据文件名或 leaf COG 后缀判定。

### attributes 写入

| 分区 | 写入内容 |
|---|---|
| `item` | `layout=whole`、`data_type=media`、`format=raster_mosaic`、`scope_exclusive=true`、`claim_policy=whole_scope` |
| `storage` | whole scope 根范围的 `physical_path`、总大小等存储事实 |
| `format_info.raster_mosaic` | `manifest_ref`、`index_ref`、`overview_ref`、leaf 数量、COG 校验摘要等格式私有事实 |
| `capabilities.spatial` | mosaic 的 CRS、extent、分辨率范围等空间能力 |

whole item 不应把全部 leaf COG 展开写入 `item.refs`。leaf COG、overview、index、tiles、stats、styles 等都是 mosaic item 内部组成；是否展示单个 leaf COG 由 Manager 读取 manifest/index 后提供内部查看能力。

### 消费要求

Manager 预览应消费已入库的 `format=raster_mosaic` item，读取业务存储中的 manifest、index、overview COG 和 leaf COG window。常规在线预览不得重新调用 GeoPython Workflow；重建 overview、重建 leaf COG、重算 stats 或重建 tile cache 应进入任务体系。

## 视频

### 识别与组织

| 维度 | 取值 |
|---|---|
| `layout` | `single` |
| `data_type` | `media` |
| `format` | `mp4`、`mov`、`mkv`、`avi`、`webm`、`video` |
| 主资源 | `meta_item.full_name` 指向视频文件 |

`format` 表达视频文件或容器格式。H.264、H.265、AV1、VP9、AAC、Opus 等编码不作为基础 `format`，也不作为当前 `MediaInfo` 主事实；如需保留，应进入受控 `format_info.<format>` 或后续媒体提取结果。

`video` 是兜底格式，只在无法稳定识别具体视频容器时使用。第一阶段视频格式目标是稳定识别、记录轻量元信息，并支持 raw / range / stream 播放链路，不要求后端转码。

### attributes 写入

| 分区 | 写入内容 |
|---|---|
| `item` | `layout`、`data_type`、`format` |
| `type_info.media` | `kind=video`、`mime_type`、宽高、`duration_ms`、`encoding`、`size_bytes` 等当前通用媒体信息 |
| `format_info.<format>` | 容器版本、轨道摘要、metadata atom、字幕轨、封面帧等格式私有信息 |
| `capabilities.extraction` | 仅在已有明确抽帧、OCR、语音转写或字幕提取任务状态时写入 |

### 预览读取

视频预览面向 `data_type=media + type_info.media.kind=video`。Manager 应优先使用 range / stream URL 播放，不应通过后端全量 base64 返回视频内容。转码、抽帧、封面图、字幕提取和语音转写属于后续媒体处理能力，不是格式识别的前置条件。

Search 或语义索引可消费 `capabilities.extraction` 或外部索引引用，但不应把抽帧结果、完整字幕或语音转写全文直接塞入 `attributes`。

### 格式约束

- 不得把视频编码当作基础 `format`。
- 不得把视频写入 `type_info.document` 或 `type_info.table`。
- 不得因为视频包含音轨就拆成多个基础 data item。

| `item` | `layout`、`data_type`、`format` |
| `type_info.media` | `kind=audio`、`mime_type`、`duration_ms`、`encoding`、`size_bytes` 等当前通用媒体信息 |
| `format_info.<format>` | ID3 / Vorbis comment / RIFF chunk / 封面图等格式私有信息 |
| `capabilities.extraction` | 仅在已有明确语音转写、音乐识别或摘要任务状态时写入 |

### 预览读取

音频预览面向 `data_type=media + type_info.media.kind=audio`。Manager 应优先使用 range / stream URL 播放；语音转写、摘要、声纹、音乐识别等属于后续提取或语义能力，不是音频格式识别的前置条件。

### 格式约束

- 不得把音频写入 `type_info.document`。
- 歌词、转写全文和封面大图必须作为提取结果或内容读取结果管理，不进入基础 attributes。
