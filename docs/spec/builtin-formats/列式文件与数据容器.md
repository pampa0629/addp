# 内置格式：列式文件与数据容器

分别维护列式 / 记录文件、表目录、工作簿、地理数据库和压缩包的规则；布局与数据类型以各节为准。

## Excel

### 识别与组织

| 维度 | 取值 |
|---|---|
| `layout` | `single` |
| `data_type` | `container` |
| `format` | `excel` |
| 主资源 | `meta_item.full_name` 指向工作簿文件 |

当前阶段 Excel 文件先作为一个容器 item。内部 sheet 是内部子 item，不自动展开为独立 `meta_item`。

### attributes 写入

| 分区 | 写入内容 |
|---|---|
| `item` | `layout`、`data_type`、`format` |
| `type_info.container` | `children`、`default_child`、`child_count`、sheet 摘要 |
| `format_info.excel` | 工作簿版本、sheet 数量、默认 sheet、采样策略等工作簿或格式层事实 |

### 内部读取

Manager 可以基于 `type_info.container.children` 展示 sheet 列表；进入某个 sheet 的表格内容读取时，应由容器读取能力定位内部对象，再交给 `TableInfoProvider` / `TableSampleReader` 归一为表语义。

当某个 sheet 被归一为 table item 或 table describe 结果时，`sheet_name`、`sheet_index` 等当前表级来源原生事实写入 `type_info.table.native`，不得写入 `format_info.excel`。外层工作簿的 `sheet_count`、`default_sheet` 等工作簿级事实只写入 `format_info.excel`，不得重复写入 `type_info.container.native`。

### 格式约束

- 不得把所有 sheet 字段合并成外层工作簿的 `type_info.table.fields`。
- 不得改变 Manager / Transfer 的外层 item 路由语义。

## Parquet / ORC / Avro / Iceberg

### 识别与组织

| 场景 | `layout` | `data_type` | `format` |
|---|---|---|---|
| 单个 Parquet 文件 | `single` | `table` | `parquet` |
| 满足 whole-scope 探测规则的 Parquet 表目录 | `whole` | `table` | `parquet` |
| 单个 ORC 文件 | `single` | `table` | `orc` |
| 单个 Avro 文件 | `single` | `table` | `avro` |
| Iceberg 表目录（规范示例，未内置注册） | `whole` | `table` | `iceberg` |

Parquet、ORC、Avro 是表格型数据的文件格式，不应直接称为“湖表”。当前 Parquet descriptor 只声明 `single` 和 `whole`，没有 `multi` 文件组路径。目录或 prefix 只有在启用 whole-scope 探测且满足强匹配与组成规则时，才归并为 `layout=whole + data_type=table + format=parquet`；不能仅凭多个文件具有相同后缀就归并。whole-scope 识别与归属由 Meta 的 item detector 裁决，Manager 不临时拼装目录表。单文件与 whole-scope 的记录须与[规范总览](../addp内置数据类型与文件格式规范.md#总览)及[概念文档支持汇总](../../concepts/addp数据类型和格式体系图.md#当前支持汇总)保持一致。

以下示例与 `common/dataitem/resolve_test.go` 中的分区表识别、独立同级表保留测试一致，均以 `dataset` 为扫描范围并启用 whole-scope 探测：

| 已观察的 Parquet 文件 | 识别结果 |
|---|---|
| `dataset/dt=2026-05-05/part-000.parquet`、`dataset/dt=2026-05-06/part-001.parquet` | 分区路径构成强匹配，形成一个 `full_name=dataset`、`layout=whole`、`data_type=table`、`format=parquet` 的 item，独占范围内已认领的数据文件 |
| `dataset/sales.parquet`、`dataset/customers.parquet` | 没有满足 whole-scope 的强匹配条件，保留两个独立的 `single + table + parquet` item |

whole-scope 识别结果不代表各数据文件的表结构已通过一致性检查；后续描述和读取仍由 Parquet scope provider 校验字段结构及 GeoParquet 空间元数据，冲突时明确失败。Iceberg 的 `whole + table + iceberg` 仅为规范示例，当前没有内置 descriptor 或 plugin，不计入已接入格式。

### ORC 单文件只读

ORC 的唯一解码路线为 GeoPython Runtime 内部固定 `pyorc==0.12.0`（Apache ORC C++），Common 只保留运行时单文件 table 工厂和类型保真适配。单个 ORC 保持 `single + table + orc`，不得伪装容器／GDAL 图层，不先转换其他格式，也不引入第二个解码器或独立服务。工厂绑定现有 source-only access plan 后，提供 Describe、逻辑窗口样本和连续批量 reader；Meta、Manager、Transfer 分别消费同一绑定接口。静态工厂登记与运行时可执行能力分开报告。

根为非空 struct；标量支持元数据、分页及连续批量读取，嵌套 struct/list 仅支持元数据与分页预览。根 struct 的整行 NULL 无法保真映射为普通表格行，明确拒绝，不转成所有字段 NULL；支持 boolean、有符号整数、float/double、string/char/varchar、binary、decimal、date、timestamp 和 timestamp instant。字段保留原生类型、可空性与 decimal precision/scale；所有 ORC 类型均可空。bigint 与 decimal 在 Runtime 批次协议中采用精确十进制文本，binary 采用 base64，绑定 reader 恢复有符号 int64 与 bytes；原始空值、空文本和空二进制保持区分。时间固定以 UTC reader 解释底层值：无时区 timestamp 交付无偏移 ISO 文本，instant 交付带 Z 的 ISO 文本，保留九位纳秒，不通过默认 Python datetime 的微秒转换。非有限浮点数拒绝，不能通过 JSON 变成 null。

嵌套对象以 `type=json + fields` 声明完整成员，数组以 `type=array + element + element_type` 声明完整元素类型，允许二者组合，最多 16 层、1024 个类型节点（含根），空 struct 拒绝。分页按顶层字段选择，不解释点号为子路径、不摊平数组；NULL 对象、成员全为 NULL 的对象、NULL 数组、空数组及 NULL 元素保持不同。递归 bigint/decimal/binary/timestamp 沿用同一精确协议；每个顶层结构值编码最多 1 MiB，单批递归访问最多 65536 个值节点，超限整批拒绝。`OpenTableReader` 在任何嵌套 schema（即使只选择标量列）读取前拒绝，防止目标 writer 隐式把结构写成文本；平面文件的批量读取不变。结构事实与元数据、分页内容共用同一 schema，不从 JSON 内容猜测类型。

元数据使用 footer 声明的精确行数，`format_info.orc` 记录 schema、compression、stripes、源版本及 `validation=footer`；该状态不代表所有数据页已解码。分页和连续读取核对同一次描述绑定的源版本；版本变化拒绝继续，不重绑定新文件。对象存储使用限定同一对象与版本的 Range，挂载文件使用同一文件描述符 seek；单批重新打开后按行定位，不逐批整文件下载。源内容读取沿现有 access plan，不枚举同目录文件、不扩大权限。

预算固定为：源编码大小 256 MiB、单次打开累计读取 128 MiB、单次字节读取 4 MiB、256 列、4096 stripes、每批最多 2000 行、单值 1 MiB、行响应 16 MiB。解析在既有原生子进程启动器内执行，60 秒墙钟／30 秒 CPU 限时退出，Linux 同时限制 4 GiB 地址空间；不把地址空间限制当作 RSS 配额。预算不足、损坏、截断、未知压缩、类型不支持及源变化均明确失败，不交付部分成功。当前不支持 whole／分区目录、Map／Union、嵌套批量传输、加密、Hive ACID 合并、ORC 写出或 SQL 联邦查询。默认不提供断点恢复 marker。

标准验证覆盖 Common、GeoPython、Meta、Manager、Transfer 的 T0–T3、原生依赖生命周期和 Linux 产品镜像；真实普通用户的扫描、分页、原文件下载、批量读取与清理由正式 Hosted 独立记账，代码与单测不能计为 Hosted 已通过。

### Avro 单文件读取

Avro 首期读取标准 Object Container File（`Obj` 加版本字节 1），根 schema 必须为非空 record。字段支持 `boolean`、`int`、`long`、`float`、`double`、`bytes`、`string` 及这些类型与 `null` 组成的二分支 union；分别保留标准类型、64 位整数、二进制及 schema 声明的可空性，不从样本猜测类型。基础标量读取之外，2026-11-14 用户确认扩展 date 和 decimal 的元数据、分页与连续读取及 Parquet 转存；本地时间戳、时刻、嵌套 record、array/map、enum、未注解 fixed、多类型 union、其他逻辑类型与外部 schema 注册表消息仍明确拒绝，不丢弃类型注解后降级为普通标量。

日期仅接受 `int + logicalType=date`，按自 1970-01-01 起的有符号天数解释为无时区公历日期，交付 `YYYY-MM-DD`，沿用平台 0001–9999 年范围，不添加时刻或时区。定点小数接受 `bytes/fixed + logicalType=decimal`（含已声明 fixed 的具名引用），保留 precision、scale 及可空性；precision 为 1–1000，scale 缺省 0 且须在 0 至 precision 之间，fixed 的容量必须满足其声明精度。原值按大端补码精确解释为整数再按 scale 输出定点文本，保留尾零与 null，不经浮点、不舍入、不把超精度值按普通 bytes 接受。源 schema 原样保留在 `format_info.avro.schema`；唯一 Go codec 只处理 schema 对应的物理编码，逻辑解释在同一 reader 交付边界执行，合法符号扩展不能因重编码最小化被误拒。Transfer 沿现有 Parquet DATE/DECIMAL writer，字段类型、日期、定点值和精度由独立回读验证；代码通过不等于页面或 Hosted 通过。

2026-11-14 用户确认增加 `long + logicalType=timestamp-millis/timestamp-micros/timestamp-nanos`。字段归一为 `type=timestamp`，`temporal.unit=ms/us/ns`、`temporal.timezone=UTC`；UTC来自格式规定的绝对时间语义，不猜测或恢复生产者原时区，自定义时区属性不改变该标准语义，源schema仍保留。Describe、分页样本和连续批次保持原始有符号int64计数，不经浮点或Go/Python微秒时间对象；HTTP预览复用共享时间序列化，固定3／6／9位小数及Z，正确处理负计数。原始int64全范围可读取和转存，超出共享0001–9999年预览日历的毫秒／微秒值明确拒绝ISO预览，不截断、不换单位或变为NULL。Transfer复用现有Parquet原生时间写入器，保留物理INT64、原单位和`TIMESTAMP(isAdjustedToUTC=true)`，不支持转存到尚不能保留原始时间计数的其他目标。未注解long仍是bigint，`local-timestamp-*`、`time-*`和未知逻辑类型继续拒绝。

元信息、分页样本和连续读取共用 Common 的单一流式 reader。描述读取到 EOF 后才给出精确行数；分页从起点按逻辑行跳过，不生成源字节索引。字段选择沿共享接口执行，断点 marker 明确拒绝。支持 OCF `null`、`deflate` 和 `snappy` 压缩；schema/头部最多 1 MiB，字段最多 1024 个，每块编码及解压后数据最多 16 MiB、记录最多 100 万条，读取检查取消、块长度、sync marker、Snappy CRC 和末尾残留。预算按块约束，不代表整次扫描的固定时间或总 I/O 上限。

`type_info.table` 保存字段及完整描述得到的行数；`format_info.avro` 只保存源 schema 和 codec。读取要求标量编码可由同一 codec 精确重现，拒绝越界整数、非最短 varint、非法布尔值，不允许解码器静默截断；解析失败通过既有明确解析错误传递，Meta 不得退回基础摘要冒充读取成功。不提供 Avro writer、whole scope 合并或 date/decimal/上述UTC时间戳之外的逻辑类型。实现使用固定 Apache-2.0 纯 Go codec，不依赖商业 SDK。验证由既有 Common Go T1 自动发现，Meta/Manager/Transfer 消费沿共享格式接口回归；真实存储和页面验收单独记账。2026-11-08，NFS/MinIO各三种codec、每源2503行的Meta结构、Manager分页/原件按钮及Transfer→Parquet完整字段/类型/可空性/数值回读已通过[限定正式Hosted](../testing/evidence/资源读取与预览历史证据.md#avro-单文件标量读取--hosted-验收)，临时任务/物理输入输出及隔离部署/Infra清理完成；不扩张上述首期边界、全部生产者或容量认证。

2026-11-14，日期与bytes／fixed定点小数已通过[限定正式Hosted](../testing/evidence/资源读取与预览历史证据.md#avro-日期与小数正式-hosted)：NFS／MinIO各三种codec、2503行／源，Meta字段、API与实际分页、六个Transfer→Parquet产物共15018行完整类型／数值／空值回读及完整清理通过。MinIO原件完整下载，NFS原件按当前契约明确拒绝；本轮小数为Decimal(38,6)，不外推全部精度、生产者或容量；该轮未覆盖时间戳，嵌套及Avro写出仍未支持。

2026-11-14，UTC毫秒／微秒／纳秒时间戳已通过[限定正式Hosted](../testing/evidence/资源读取与预览历史证据.md#utc-时间戳限定正式-hosted-通过)：固定产品与业务／身份夹具源码`7af201a28f237a0ef88aa27a8129e54042ff5d8f`，Run43584189240／Job132415063748。六源三codec、2503行／源，Meta十三字段、API与实际页面分页、六份Parquet全部15018行的原始时间计数／单位／UTC注解／空值及完整清理均通过。保留原日期、小数和基础字段；MinIO原件下载已验，NFS原件保持403边界。截图中的长值裁切不计完整文字展开已验；日历预览范围、本地时间戳／时刻／嵌套／whole／写出未开放的边界不变。

依据：[Apache Avro OCF 与 schema 规范](https://avro.apache.org/docs/1.12.0/specification/)。

### Feather V2 单文件只读

2026-11-08确认首期：`single + table + feather`，`.feather`及`.arrow`统一表示同一种Arrow IPC file，文件头尾均须为`ARROW1`；不把IPC stream或Feather V1当作兼容分支。唯一数据面复用GeoPython内部现有PyArrow，不新增服务、Runtime或解码依赖；Common的`RuntimeTableProviderFactory`绑定精确单文件source-only access plan，Meta描述、Manager逻辑分页与Transfer连续批量读取消费同一绑定，不先转换成其他格式。

支持非空平面schema：boolean、有符号int8/16/32/64、float32/64、UTF8 string及binary；保留字段名、顺序、原生类型与nullable，不从值猜测类型。64位整数以十进制文本过Runtime批次协议后恢复int64，二进制以base64恢复bytes，NULL／空文本／空二进制区分；非有限浮点数拒绝，不转NULL。首期拒绝unsigned、float16、null-only类型、large/view/fixed-width、嵌套、dictionary、extension及duration，不忽略扩展注解、展开结构或转成文本。支持无压缩、LZ4与ZSTD；不支持写出、目录合并、Feather V1或IPC stream。

日期支持 `date32[day]` 和整日对齐的 `date64[ms]`，以 `YYYY-MM-DD` 交付，日期范围为公历 0001 至 9999 年。定点小数支持 Decimal128（精度 1–38）和 Decimal256（精度 1–76），小数位数须在 0 至 precision 之间。字段保留原生类型、精度、小数位数及可空性。批次与预览使用定点文本保留尾零，Transfer 转存 Parquet 时使用现有 DATE 和 DECIMAL 写入器保留逻辑类型。

时刻支持 Arrow `time32[s/ms]`、`time64[us/ns]`，时间戳支持 `timestamp[s/ms/us/ns]` 及其带源时区的声明。Runtime 批次以有符号十进制计数文本传递，Common 恢复整数；预览保留单位对应的小数位和本地／绝对时间区别，Meta 保留源时区标识。Transfer 转存 Parquet 使用标准 TIME／TIMESTAMP 逻辑类型，秒精确扩展为毫秒，乘法溢出明确拒绝。带时区时间戳保留绝对时间计数并使用标准 `ARROW:schema` footer 保存源时区标识；ADDP 回读使用 Parquet 的物理单位并恢复兼容的源时区。缺少源时区标识的 UTC-adjusted 时间戳按 UTC 展示。带源时区的 Parquet 输出要求同文件的字段可用 Arrow schema 描述，Decimal 精度上限为 76。Transfer 首期仅支持将保留这些原生整数时间字段的表写为 Parquet；字段映射可以重命名，不允许改类型。

描述只在逐个解码并验证所有record batch结构后给出精确总行数；batch数量不是行数。`type_info.table`记录字段／精确行数／大小，`format_info.feather`记录已校验的Feather版本2、batch数、源版本及`validation=batch_structure`，不声称全部业务值已通过JSON交付检查。分页和连续读取只输出所选逻辑行窗口；跨batch定位，不全表转pandas，批次内按同一schema精确编码。完整schema先准入再选择字段，不能用标量投影绕过未支持类型。返回完整批次或明确失败，不交付部分成功；不发布源字节访问索引或断点marker。

源沿共享表格源读取器：NFS使用同一文件描述符seek，MinIO用同一对象及ETag的条件Range；描述与后续读取冻结同一source_version，发生变化返回`FEATHER_SOURCE_CHANGED`／HTTP409并要求刷新，不重新绑定新版本。坏声明或不支持内容返回脱敏`FEATHER_READ_REJECTED`／HTTP400；原生进程退出或超时返回`FEATHER_READ_FAILED`／HTTP500，不回显凭据／路径／原生异常。预算为编码源256MiB、每次打开累计读取128MiB、单次4MiB、footer1MiB、256列、4096batch、单个解码batch64MiB／100万行、每次返回2000行、单值1MiB、行响应16MiB。沿现有原生子进程启动器执行，60秒墙钟／30秒CPU，Linux地址空间4GiB；这些预算不等同RSS配额或全容量认证。

Common与GeoPython确定性及真实原生进程测试、Meta／Manager／Transfer共享消费回归走标准入口；新增Python测试必须同次加入`make test-geopython-workflow`显式清单。独立Hosted须另验普通用户扫描／页面／原件下载／Transfer批量落地与完整清理；代码、样例和本地通过均不计正式验收通过。

依据：[Apache Feather V2定义](https://arrow.apache.org/docs/python/feather.html)、[Arrow IPC file规范](https://arrow.apache.org/docs/format/Columnar.html#ipc-file-format)。

### attributes 写入

| 分区 | 写入内容 |
|---|---|
| `item` | `layout`、`data_type=table`、`format`、可选 `refs`、whole scope 的 `scope_exclusive` 和 `claim_policy` |
| `type_info.table` | 字段、原始字段类型、行数或估算行数、`native.partition_columns` |
| `format_info.<format>` | 文件 footer、编码、压缩、row group、schema 版本、manifest 摘要、scope 文件清单等格式私有信息 |
| `capabilities.partitioning` | 分区数量、分区样例、分区范围等分区事实 |
| `capabilities.statistics` | Meta 扫描是否采样、采样规模等紧凑过程事实；格式 footer 的原生列统计保留在 `format_info.<format>`，不得旁路承载数据剖析结果 |

GeoParquet 不是独立 format。GeoParquet 文件继续使用 `format=parquet + data_type=table`；Parquet footer 中 `geo` key 的原生标准字段写入 `format_info.parquet.geo`，归一化后的主几何列、几何列、拓扑类型、CRS 和文件范围写入 `capabilities.spatial`。几何列在 `type_info.table.fields` 中统一映射为 `geometry`，不得同时保留为 `string` 或 `bytes`。

Parquet whole scope 的描述、分页样本和连续读取共用同一个文件打开路径。内容 reader 已提供 Range 且可取得正数文件大小时，使用 `contentio.ReaderAt` 读取 footer 和实际需要的 row group，不先整文件下载；分页继续按 row group 行数跳过并在组内定位。只有源未提供 Range 或可用大小时，才按流式输入契约读取完整文件。此约定不声明任意 footer／单页的固定内存上限，也不提供源文件快照。

普通 Parquet 的有符号 `INT(8/16/32, true)` 逻辑类型归一为 `int`，`INT(64, true)` 归一为 `bigint`；不能因整数带逻辑注解而把字段归为 `string`。字段类型、可空性与整数值在 Common writer 写出后重新描述、预览和连续读取时保持一致。

未带逻辑注解的 Parquet `BYTE_ARRAY` / `FIXED_LEN_BYTE_ARRAY` 是二进制，字段归一为 `bytes`，分页和连续读取返回独立 `[]byte`；空字节与 null 保持区分。带 UTF8 注解的文本仍为 `string`，Decimal、UUID、JSON 与 GeoParquet WKB 继续按各自已声明语义处理，不按字节内容猜测文本。

普通 Parquet 的 Decimal 读取按 footer 的 `DECIMAL(precision, scale)` 解释底层有符号整数，`FieldInfo` 保留 `type=decimal`、原始类型、`precision` 和 `scale`。样本、分页与连续读取统一返回保留 scale 的定点十进制字符串，不经过浮点转换；null 保持 null。现有 parquet-go 0.25.1 支持的物理编码为 `INT32`、`INT64` 和大端补码 `FIXED_LEN_BYTE_ARRAY`；标准允许的 Decimal `BYTE_ARRAY` 尚受该依赖限制，当前不支持。whole scope 中 Decimal precision 或 scale 不一致时拒绝归并，不按首个文件解释后续值。[编码定义](https://github.com/apache/parquet-format/blob/master/LogicalTypes.md#decimal)。

Parquet writer 沿用 ADDP 可移植 Decimal 定义范围 `1 <= precision <= 1000`、`0 <= scale <= precision`，必须显式声明 precision，不能为未声明精度的来源选择默认值。precision 不超过 9 时写 `INT32`，不超过 18 时写 `INT64`，其余写满足声明精度的最小宽度 `FIXED_LEN_BYTE_ARRAY`，均带 `DECIMAL` 注解。行值接受精确十进制字符串、`json.Number` 和整数；科学计数法按十进制运算精确缩放。拒绝浮点值、非法文本、超 precision 值及必须舍入才能适配 scale 的值；可以无损移除多余的尾零。null 只允许写入可空 Decimal 字段。普通 Parquet 和 GeoParquet 共用同一 Decimal writer，不保留 Double 写出分支。

当前依赖对固定长度字节列按无符号字节比较，不能据此生成 Decimal 的有符号 min/max。writer 对固定长度 Decimal 列不写范围统计，避免下游基于错误统计跳过数据；精确行数、值与 Decimal 注解仍正常写出，整数物理编码的统计保留。

当前内置 GeoParquet 能力以稳定的 GeoParquet 1.0 / 1.1 为边界：

- reader 支持文件侧 `encoding=WKB`，默认以 WKB 二进制值向通用 table 消费链路输出，并可按调用方契约归一为 EWKB 或 WKT；遇到 GeoArrow 单几何类型编码、GeoParquet 2.x 或其他未知编码必须明确报不支持，不得按普通 Parquet 字符串列降级。
- writer 在 table 字段包含 `geometry` 时固定写出 GeoParquet 1.1.0：文件几何列使用 Parquet `BYTE_ARRAY`，footer `geo.columns.<name>.encoding` 固定为 `WKB`。写入行值可为 WKB 或 EWKB 二进制，落盘前统一转成不携带内嵌 SRID 的标准 WKB；不得把 geometry 序列化为字符串。geometry 字段必须在 `SpatialInfo.geometry_columns` 中逐一声明，并且必须给出有效主几何列；writer 必须逐行拒绝 GeoParquet 1.1 不支持的 M/XYZM 布局以及与已声明拓扑、维度不一致的值。普通 Parquet 不含 geometry 字段时继续走原非空间 writer。
- `crs` 缺失时按 GeoParquet 规范归一为 `OGC:CRS84`；`crs=null` 表示 CRS 未知；PROJJSON 中存在确定 authority/code 时可归一为 `crs_ref` / `srid`，不得从名称猜测 EPSG。
- GeoParquet reader 必须把 `crs` 的 PROJJSON 原文同时保留为 `format_info.parquet.geo` 格式事实，并以 `definition_encoding=projjson` 归一进入 `capabilities.spatial.crs_definitions`，供后续格式写出复用；有 authority/code 时 definition ID 使用对应 `crs_ref`，没有时使用定义文本计算 `ADDP:CRS:<sha256>`，不得把“已知但无 authority ID”降级成未知 CRS。
- writer 对 `OGC:CRS84` 省略 `crs`，对未知 CRS 明确写 `crs=null`。`EPSG:4326` 在 GeoParquet 1.1 明确覆盖为 x/y（经度/纬度）轴序时与 `OGC:CRS84` 等价；没有 PROJJSON 定义时允许按默认 CRS 写出。其他已知 CRS 必须从 `SpatialInfo.crs_definitions` 取得 `definition_encoding=projjson` 且 ID 与几何列 `crs_ref` 一致的定义。GeoParquet format plugin 通过通用 CRS 定义写出需求 provider 声明缺少的 `projjson` 表达；Transfer 在创建 writer 前按该声明调用 GeoPython Workflow `crs_to_projjson`，只替换本次 execution 使用的 `SpatialInfo` 副本。writer 不负责从 WKT、ESRI WKT 或 PROJ4 猜测转换，转换能力不可用或结果不匹配时必须明确失败。
- writer 可从主几何列的 `SpatialInfo.extent` 写出二维 `bbox`；只接受有限且最小值不大于最大值的范围。坐标转换不属于 GeoParquet writer，Transfer 必须在进入 writer 前完成。
- whole-scope Parquet 数据集的各数据文件必须具有一致的几何列、编码和 CRS；冲突时扫描或读取明确失败，不得以第一个文件覆盖其余文件。
- 不含 `geo` footer metadata 的普通 Parquet 沿用非空间表格主路径，不根据列名或二进制内容猜测几何列。

`whole` item 的范围由 `meta_item.full_name` 表达，`item.scope_exclusive=true`、`item.claim_policy=whole_scope` 表达独占语义。`refs` 只包含规范认定的数据文件或 manifest 关键资源，不包含 `_SUCCESS`、`_metadata`、`_common_metadata`、CRC 等辅助文件，除非具体格式规范另有说明。

### 表格读取

上层统一按 `data_type=table` 消费。Parquet 单文件的元信息、分页样本和连续读取分别走 `TableInfoProvider`、`TableSampleReader`、`TableReaderProvider`；whole-scope 表分别走 `ScopeTableInfoProvider`、`ScopeTableSampleReader`、`ScopeTableReaderProvider`，内容 I/O 由 contentio 收口。单文件写出通过 `TableWriterProvider` 获取；不能从 whole 布局声明推断已有 scope writer，也不提供 Parquet 的 multi reader / writer 路径。其他格式的 multi 接口及引擎原生表接口遵循各自能力规范，不向 Manager / Transfer 暴露 `filetable` / `laketable` 两套业务概念。

### 格式约束

- 不得把多个独立 sibling Parquet 文件误合成一个 `whole` item。
- 不得将 Parquet 文件组登记为 `layout=multi`，或为旧示例保留 multi 读写分支。
- 不得把 Parquet 直接叫作湖表。
- 不得在 Manager 中按目录临时拼装 scope 表；whole scope 必须由 Meta 已入库 item 表达。
- 不得新增 `geoparquet` format、data type 或第二套 reader / writer；GeoParquet 必须由现有 Parquet plugin 精化空间事实。

## SQLite / GeoPackage

### 识别与组织

| 格式 | `layout` | `data_type` | `format` | 主资源 |
|---|---|---|---|---|
| SQLite | `single` | `container` | `sqlite` | SQLite 文件 |
| GeoPackage | `single` | `container` | `geopackage` | GeoPackage 文件 |

容器文件本身先作为一个 item；`meta_item.full_name` 指向容器文件。内部表、view、图层等先写入 `type_info.container.children`。

### attributes 写入

| 分区 | SQLite | GeoPackage |
|---|---|---|
| `item` | `layout`、`data_type`、`format` | `layout`、`data_type`、`format` |
| `type_info.container` | 内部表、view、默认入口、对象数量 | 内部 layer、表、默认入口、对象数量 |
| `format_info.sqlite` | SQLite 版本、内部表数量、表清单、pragma 摘要 | 不适用 |
| `format_info.geopackage` | 不适用 | gpkg 容器级元数据和 layer / table 统计摘要 |
| `capabilities.spatial` | 仅 SpatiaLite 等可确认空间能力时写入 | 外层容器不写入；选中具体 layer 后由 child `TableInfo.SpatialInfo` 表达空间字段、SRID / CRS、extent 和空间索引 |

当内部表、view 或 layer 被归一为 table describe 结果时，SQLite `sqlite_master.type` 只映射到 `type_info.table.kind`。当前不为 SQLite / GeoPackage 增加表级 native key；page size、page count、内部表 / 视图 / 索引数量等是容器或文件级事实，继续留在 `format_info.sqlite/geopackage`。

### 内部读取

Manager 展示容器 children 时消费 `type_info.container`；进入内部表或 layer 预览时，由容器读取能力定位内部对象，再交给 table info / sample reader 和 spatial 横切能力处理。

GeoPackage layer 的样本读取与连续 `TableReader` 共用相同行值转换：仅按 `gpkg_contents`／`gpkg_geometry_columns` 登记的真实几何列解码 GeoPackageBinary，复用 `common/spatial` 输出标准编码，不重投影坐标。默认读取编码为 `ewkb`，显式支持 `wkt`、`wkb`、`ewkb`、`geojson`；WKB／EWKB 行值为 `[]byte`，EWKB 使用图层声明的 SRID，null 保持 null。容器 child 的读取选项使用同一默认编码，使 Manager 原有容器子表路线直接消费标准 EWKB；不得把原始 GP header 字符串或其 Base64 当作 EWKB。编码错误须返回读取错误，不得静默丢行。普通 SQLite／未登记为几何的 BLOB 保持原字节，即使其字段名或内容与几何相似也不作空间推断。


### 格式约束

- 不得把容器内所有表字段合并成外层 item 的 `type_info.table.fields`。
- 不得把容器内单个表或 layer 的字段、样本行、空间字段、SRID、extent、空间索引等 child 内容写入外层容器 attributes。
- 不得把 GeoPackage 的格式私有元数据混入 `capabilities.spatial`。

## File Geodatabase / Personal Geodatabase

### 识别与组织

| 格式 | `layout` | `data_type` | `format` | 主资源 |
|---|---|---|---|---|
| File Geodatabase | `whole` | `container` | `filegdb` | 后缀为 `.gdb` 且包含合法 FileGDB 系统文件的目录整体 |
| Personal Geodatabase | `single` | `container` | `pgeo` | 可由 GDAL PGeo 驱动打开并识别地理数据库系统表的 `.mdb` 文件 |

FileGDB 的 `.gdb` 目录是一个 data item，目录内 `a*.gdbtable`、`a*.gdbtablx`、索引和系统文件不得分别落为 item。PGeo 的 `.mdb` 文件是一个 data item。两者的 feature class、普通 table 和 feature dataset 先写入 `type_info.container.children`；选中具体 child 后再归一为 table 内容和空间能力。

### attributes 写入

| 分区 | FileGDB | PGeo |
|---|---|---|
| `item` | `layout=whole`、`data_type=container`、`format=filegdb`、`scope_exclusive=true`、`claim_policy=whole_scope` | `layout=single`、`data_type=container`、`format=pgeo` |
| `type_info.container` | feature dataset、feature class、table 的轻量 children、默认入口和数量 | feature class、table 的轻量 children、默认入口和数量 |
| `format_info.<format>` | GDAL driver/version、FileGDB 版本、域/关系/附件等受控摘要 | GDAL driver/version、MDB 版本、域/关系等受控摘要 |
| `capabilities.spatial` | 外层容器不写入；由选中 child 的 table describe 结果表达 | 外层容器不写入；由选中 child 的 table describe 结果表达 |

### 读写与运行时边界

- FileGDB 的内置开源数据面固定使用 GDAL OpenFileGDB；支持 child table/feature class 读取和新目标 FileGDB 写出。
- PGeo 的内置开源数据面固定使用 GDAL PGeo + unixODBC / MDB Tools，只允许读取，不提供 `.mdb` 写回。
- GDAL 原生依赖由受控 GIS 运行时承载，不嵌入 Meta、Manager 或 Transfer Backend 进程；业务模块通过统一 Provider 契约消费，不直接执行 `ogrinfo`、`ogr2ogr` 或拼接驱动参数。
- child 几何行值进入 ADDP 数据面后统一使用 EWKB，并通过 `SpatialInfo` 携带 geometry field、type、dimension、SRID / CRS 和 extent；不得把 FileGDB/PGeo 私有 geometry blob 暴露给 Transfer。
- Oracle 目标只通过 Oracle Engine 的 `TableWriteSessionProvider` 写普通表和 `MDSYS.SDO_GEOMETRY`。该路径不得创建 `SDE` schema、修改 geodatabase system tables、注册 feature class 或宣称 Enterprise Geodatabase 支持。

Manager 一次性成果交付可将授权的 PostGIS 单个二维图层写成新 FileGDB，封装为 `<name>.gdb.zip`。ZIP 内保留一个原名 `<name>.gdb/` 顶层目录，下载交付与源 FileGDB 的 whole 身份分别处理。首期限制单具名 XY 几何列、明确 CRS 和可无损映射的常规标量字段。写入后回读检查，完成包才发布到会话的精确对象。失败不交付半成品。

### 格式约束

- FileGDB/PGeo 的 domain、subtype、relationship class、attachment、topology、network dataset 和 annotation 不得静默丢失；第一阶段发现后写入受控摘要并明确标记不支持传输。
- FileGDB 写出第一阶段只承诺普通 table / feature class、二维 geometry、字段、CRS 和记录，不承诺 ArcGIS 高级 geodatabase 行为。
- PGeo 是 legacy source-only 格式，不建立写入 provider 或兼容回退路径。
- Enterprise Geodatabase、ArcGIS SDE 注册与版本化属于数据库 workspace 能力，不属于 `filegdb` 或 `pgeo` format provider。

## ZIP / 压缩包

### 识别与组织

| 维度 | 取值 |
|---|---|
| `layout` | `single` |
| `data_type` | `container` |
| `format` | `zip` |
| 主资源 | `meta_item.full_name` 指向 ZIP 文件 |

ZIP 压缩包先作为一个容器 item。压缩包内部 entry 是内部子对象，不自动展开为独立 `meta_item`。

### attributes 写入

| 分区 | 写入内容 |
|---|---|
| `item` | `layout`、`data_type`、`format` |
| `type_info.container` | entry 轻量 `children`、`default_child`、`child_count` |
| `format_info.zip` | `entry_count`、`file_count`、`directory_count`、`sampled_children`、`children_truncated` 等容器统计 |

`type_info.container.children` 只能记录 entry 定位和摘要，例如 `name`、`kind`、`data_type`、`path`、压缩前后大小、压缩方法和可推断的 child `format`。不得把 entry 的字段、行样本、文档正文或媒体内容写入父容器。

### 内部读取

Manager 展示 ZIP 容器时消费 `type_info.container`。进入某个普通文件 entry 的内容预览时，由 `ContainerChildResolver` 把 entry 解析为 stream child resource，再交给对应 data type 的 info provider / content reader 处理；不得在 Manager 或 Meta 中为 ZIP 单独解压并绕过通用链路。

### 格式约束

- 不得把压缩包内文件内容、字段数组、行样本或正文片段写入外层容器 attributes。
- 不得把 ZIP 内部文件的格式识别结果提升为父容器 `format`。
- RAR、TAR 等其他压缩格式进入内置主线前，应先明确 descriptor、MIME、解包依赖和 entry 读取边界。
