## `load` 文件字段类型契约

GeoPython `load` 读取 `shp/geojson/gpkg/kml/gml/fgb` 空间文件及单文件 `parquet/feather` 时，以读取器提供的源 Schema 为类型事实。在转换为 pandas / GeoDataFrame 之前，将有符号与无符号整数按源位宽映射为 pandas 可空 `Int8/16/32/64`、`UInt8/16/32/64`，布尔映射为可空 `boolean`；无空值、含空值、全空及空批使用相同规则。整数不能先经过 Float64，禁止事后按数值整除特征猜回整型；大于 `2^53` 的整数及源类型边界必须保持精确。

空间文件唯一读取主线为 Pyogrio Arrow 读取与上述类型映射，不依赖 GeoPandas 默认引擎或 `PYOGRIO_USE_ARROW` 环境变量，也不回退到 NumPy / Fiona。Parquet 与 Feather 从已解析的本地文件流读取 Arrow Table，复用同一类型映射；非整型、非布尔字段继续由原生 Arrow→pandas 转换处理，不全表调用 `convert_dtypes()` 或统一改成 ArrowDtype。源 Schema 的实数即使全为 `1.0/2.0` 也保持实数，字符串、空串、空值、字段顺序、行序及既有索引值／名称／顺序不得因本次修复改写，实际整型索引列同样映射为可空整型；空间文件保留读取器返回的几何与 CRS。

类型承诺以文件驱动实际提供的 Schema 为边界：不补造 KML 等格式未声明的整型，不恢复源文件已丢失的数值，不扩展既有多图层选择或 GeoParquet 空间解释能力。CSV、Excel、JSON、内联 GeoJSON、MongoDB 以及数据库读取的推断／Schema 策略不在此首批修复中；JSON 与浏览器大整数表示是独立边界。文件 `save` 消费正确的内存类型，不在写出时猜测修复；目标格式的原生表达限制仍须单独验证。

验证复用根 `make test-geopython-workflow` 已登记的 `test_io_operators.py`，覆盖源整数位宽／符号、空值与全空／空批、布尔、真实浮点及其他字段不被重分类、六类空间文件、外部无 pandas 元数据的 Parquet/Feather、保存重载独立 OGR/Arrow 核验及筛选／属性／拓扑 DAG 消费。现有 engines 影响选择、GeoPython GDAL CI 和依赖安装覆盖，无新入口或 Job；不重复已通过的业务 T4 或容量验收。

## `distance_to` 活动几何列

距离计算分别使用源图层与目标图层各自的活动几何列（active geometry），两个几何列名称可以不同，也可以同时存在名为 `geometry` 的其他列；不得按固定列名选择几何或改名覆盖其他列。结果沿既有主线复制源图层，保留源的活动几何名称、CRS、行序、索引与其他属性，并追加或更新数值 `distance` 列；两个输入均不改写。

源图层的活动几何列若名为 `distance`，必须在计算及写结果前明确报错，避免数值结果覆盖几何。错误提示应说明冲突并引导用户先手动重命名源几何列再执行，不自动改名，也不新增输出列名参数。目标图层的活动几何列名为 `distance` 不构成冲突；源图层已有普通数值 `distance` 列时，仍只在结果副本中更新该列。算子返回结构化领域错误，由执行适配层按既有工作流显示语言生成中英文提示，不新增语言状态或改写公共运行时的错误前缀。

两个输入（包括空批）均须声明相同、已知的投影 CRS，各自两个水平轴的线性单位换算因子须相同、有限且为正，沿用既有矢量拓扑算子的投影单位校验。CRS 按解析后的语义相等判断，不比较原始字符串；地理、地心、未知或不匹配 CRS 明确拒绝，并提示用户先显式重投影。仅单位同为米并不足以允许不同投影之间计算。

距离仍按原目标几何整体集合计算最近平面距离，数值单位就是该 CRS 的水平坐标单位：米制 CRS 输出米，英尺制 CRS 输出对应英尺，不默认米，不自动重投影或换算单位；也不表示椭球测地距离。两源几何、CRS 和属性保持不变。空值及空几何处理沿现有计算主线，本次不另设新策略；既有端口、最近距离算法、保存与权限不变。CRS 拒绝复用现有提交显示语言翻译主线，不新增语言状态或旧准入兼容模式。

回归沿既有 `test_engine.py`／`test_operator_metadata.py` 和根 `make test-geopython-workflow`，覆盖默认／不同活动几何列、同名非活动几何诱饵、冲突拒绝及改名后执行、目标同名可用、双语错误、原属性／索引／两源不变、米／英尺数值原单位、等价 CRS 表达，以及任一侧未知／地理／地心／不同投影与空批准入拒绝；分类表按已注册的矢量几何处理集合核对，既有 GeoPython 和平台登记 CI 覆盖，无新测试入口或依赖，不重跑已过业务 T4 或容量。

## `vector_reproject` 算子契约

`vector_reproject` 是空间坐标参考转换算子，只负责 geometry 批转换，不负责外部数据源接入、字段保留或写出。

```python
def vector_reproject(
    input_gdf: gpd.GeoDataFrame,
    source_crs: str = "",
    target_crs: str = "EPSG:4326",
) -> gpd.GeoDataFrame:
    ...
```

| 参数 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `input_gdf` | `GeoDataFrame` | 是 | 无 | 输入几何批。direct 调用时由 `binary_payload` 解码得到，workflow 调用时由上游节点传入。 |
| `source_crs` | `string` | 条件必填 | 空 | 源 CRS。若输入批本身没有 CRS，则必须显式提供。 |
| `target_crs` | `string` | 否 | `EPSG:4326` | 目标 CRS。GeoJSON 标准导出默认使用该值。 |

| 输出 | 类型 | 说明 |
| --- | --- | --- |
| `default` | `GeoDataFrame` | 转换后的几何批，只保留 geometry 和原有属性列；direct 二进制调用时由运行时重新编码为 `binary_payload`。 |

`vector_reproject` 的 direct 调用约定如下：

1. `binary_payload.content_type` 必须为 `application/vnd.apache.arrow.stream`。
2. `binary_payload.encoding` 必须为 `arrow`，且 Arrow 批只能包含一个 geometry 列。
3. geometry 列元素必须为 EWKB 二进制值，Arrow schema metadata 必须声明 `addp.geometry.encoding=ewkb`；HTTP `binary_payload.metadata` 中也必须声明 `geometry_encoding=ewkb`。
4. 算子只转换 geometry，不得接管 Transfer 的 load/save、checkpoint、属性字段重排或 GPKG 中间产物。
5. 失败时必须返回明确错误，不得静默退回原坐标。
6. 输出 `binary_payload` 仍为 Arrow + EWKB，只包含转换后的 geometry 列；输出 metadata 中 `source_crs` 和 `target_crs` 都应写入输出几何当前 CRS，不能继续保留输入 CRS。

## `crs_to_projjson` 算子契约

`crs_to_projjson` 是 CRS 定义表达转换算子，只把同一 CRS 的 WKT、ESRI WKT、Proj4 或 authority ID 规范化为 PROJJSON，不读取 geometry、不改变坐标，也不负责格式写出。

```python
def crs_to_projjson(
    crs_ref: str,
    definition_encoding: str = "",
    definition: str = "",
) -> dict:
    ...
```

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `crs_ref` | `string` | 是 | 平台 CRS 身份；支持 `EPSG:<code>` 或带定义的 `ADDP:CRS:<sha256>`。 |
| `definition_encoding` | `string` | 条件必填 | `definition` 非空时必须为 `wkt`、`esri_wkt`、`proj4` 或 `projjson`。 |
| `definition` | `string` | 条件必填 | 源 CRS 定义。只有 `EPSG:<code>` 可以省略并由 Runtime 本地 PROJ 数据库解析。 |

输出 `result` 固定为以下结构：

```json
{
  "crs_ref": "EPSG:3857",
  "definition_encoding": "projjson",
  "definition": "{...}"
}
```

direct 调用规则：

1. `execution_modes` 只声明 `direct`，请求和响应只使用普通 JSON，不使用 `binary_payload`。
2. 输入编码必须显式分派到对应 PROJ parser，不得使用启发式文本猜测。
3. `EPSG:<code>` 使用 Runtime 随附的本地 PROJ 数据库解析，Runtime 必须禁用网络 CRS / grid 获取。
4. EPSG 源定义必须和本地 authority 定义等价；冲突时失败。输出 PROJJSON 顶层 `id` 固定为输入 authority/code。
5. `ADDP:CRS:<sha256>` 必须带定义；输出顶层 `id` 固定为 `{"authority":"ADDP","code":"CRS:<sha256>"}`，不得因序列化变化重算平台 ID。
6. 输出必须是可解析的 JSON object、包含非空 `type`，并保持输入 `crs_ref`；失败不得返回原定义或伪造未知 CRS。

## 多距缓冲与质心入口契约

GeoPython `batch_buffer(input_gdf, distances, resolution=16)`（多距缓冲）位于“矢量处理 / 几何构造”，仅 workflow/read。输入为具有活动几何列的单个 GeoDataFrame；保留其实际活动几何列、原属性及各字段类型、源 CRS，不自动投影或把坐标单位当成米。每个距离调用既有 `buffer` 的完整缓冲语义，不生成环带、不融合不同源要素；零距离与负距离沿用普通缓冲，可能生成空几何。此项不改变普通缓冲的几何准入与坐标系政策。

`distances` 为有限数值的 JSON 数组，布尔值、字符串、空值及非有限值拒绝；保留数组顺序和重复距离。`resolution` 为正整数，默认16。空距离数组或空源批返回相同 Schema 的空图层。输出只有一个默认 `default: geodataframe` 端口，不再返回图层列表；结果依距离顺序、再依源行顺序展开，重建 RangeIndex，追加 NumPy `float64` 类型的 `distance` 列标明该行使用的缓冲距离。结果不增加隐式来源字段，追溯源要素可使用保留的业务标识列。任何源列（包括活动几何列）名为 `distance` 时整批明确报错；用户须在上游手动改名，不覆盖、不自动改名。重复源列名同样拒绝。

公开元数据显式声明 `distances` 为 `array`、`item_type=float`，`resolution` 为 `integer` 且默认16，输出声明与实际单图层一致。下游直接连接既有 `save`，不新增列表展开器、列表保存旁路或动态输出端口。计算节点只读且不产生持久成果；保存、权限、扫描和血缘继续使用既有主线。旧列表结果不保留兼容路径。

`centroid`（计算质心）已经逐要素处理一个完整图层。删除 `batch_centroid`（多图质心）的函数、注册与独立入口；多个图层各接普通质心节点，分别保持其属性、CRS 与来源。含已删除 ID 的工作流需显式改写，不设置别名或自动重定向，不自动拼接不同 Schema 或 CRS 的图层。

计算与保存的精度验证分开取证：多距结果逐行与同一运行时的单距原语比较完整 WKB；工作流在计算完成、进入保存节点之前记录不可变 WKB，独立 OGR 全量重载后逐字节核对，并检查属性、类型、CRS、几何结构及固定点缓冲样例的包络、面积和顶点半径。此验证不设置 epsilon、舍入、精度网格或坐标归一化；单个坐标相邻可表示值与正负零变化也必须拒绝。不同 GEOS 版本重新计算缓冲区时可产生不同三角函数尾数（GEOS 3.13 引入 `Angle::sinCosSnap`），不能把“两个版本重新计算后 WKB 相同”作为保存保真的替代证据。生产计算仍沿普通缓冲，保存仍保留本次计算的原始坐标；版本差异不触发兼容计算路径或重写成果。参见 [GEOS 3.13 官方变更记录](https://github.com/libgeos/geos/blob/3.13.0/NEWS.md)。

验证沿用 `make test-geopython-workflow`，在既有 `test_engine.py`、元数据与多端口回归中覆盖距离展开与精确单距结果、非标准活动几何列、可空整型／布尔等属性、输入不变、空结果与零负距离、重复距离、参数拒绝与字段冲突、中英文运行错误、默认／显式端口及真实保存重载；Develop 沿 `make test-develop-frontend` 验证发现、参数、接线与移除入口。根入口文件列表及现有 Platform CI 的 GeoPython、Develop frontend 和平台一致性门禁已覆盖，无新增依赖、Job 或永久脚本；这些确定性验证不替代新的普通用户 T4，也不重复既有业务 T4 或容量矩阵。

多距缓冲、距离计算与近接检查的已类型化参数错误经共享工作流核心保留受控原因、失败节点序号和登记参数，不再通过普通ValueError丢弃原因。异步 `INVALID_PARAMS` 及统一失败页按[执行监控规范](../tasks/执行监控.md#租户执行诊断)展示；算法准入、计算、保存和既有错误语义不变，近接数值计算失败不误作参数错误。回归只新增本传播链、投影拒绝及共享页面的确定性测试，不重复已通过业务T4或容量。

## 拓扑构面契约

GeoPython `polygonize`（拓扑构面）位于“矢量处理 / 线网处理”，仅支持 workflow，效果为 `read`。唯一输入 `input_gdf` 是当前工作流的 GeoDataFrame：仅接受二维、坐标有限的 LineString / MultiLineString，使用实际 active geometry 列；非空批中的空值、空几何、无效线或 Z/M 输入明确拒绝，不能静默丢弃。允许空批，保留源 CRS（包括未定义事实），不自动重投影。

所有输入线共同构成一个平面线网，先在真实交点处打断并去除重合线段，再提取闭合区域。内部自交线按真实交点构面；嵌套边界保留孔洞和其独立闭合面。首版不提供容差吸附、补缝、端点延伸或短线删除，不修改源数据、不继承源线业务属性。该算法在内存中处理完整线网，不能宣称固定内存或大规模容量已认证。

输出复用两个既有 `geodataframe` 端口：默认端口 `result` 每行一个 Polygon，仅含 `geometry`；`diagnostics` 为未参与构面的线段，字段为 `issue_type + geometry`，类型值为 `dangle`（悬挂或孤立余线）、`cut_edge`（两端相连但未参与构面的边）、`invalid_ring`（构面阶段发现的无效环）。两端口均保留源 CRS，空结果保留相同 Schema。诊断对应打断、去重后的线网，不承诺原始线 ID 追溯；余线可能是合法业务对象，不自动判为质量不合格。无闭合区域时返回空面及实际诊断，不补造面。

Develop 按 Runtime 元数据动态发现和显示端口，默认引用选取 `result`，显式 `port=diagnostics` 读取诊断；两者可分别连接既有矢量 `save` 节点。纯计算和预览不产生持久输出、Meta 扫描或血缘，保存继续使用现有授权及成果主线，不新增 Adapter 或 direct 路径。辅助诊断不替代独立拓扑质检、源线关联或评分体系。

验证沿用 `make test-geopython-workflow`，覆盖真实线网构面、交点与重合、孔洞、余线类型、零容差边界、输入拒绝、CRS/属性/源数据不变及两端口 DAG 保存重载。新用例加入根入口的显式文件列表，既有 Platform CI 的 GeoPython Job 和 engines 路径选择自动覆盖，无新增依赖、API 或 CI Job；确定性回归不替代完整 ADDP T4 验收。

## 重合规整契约

GeoPython `normalize_line_network(input_gdf, id_field)`（重合规整）位于“矢量处理 / 线网处理”，仅 workflow/read。输入为单个有效、有限二维 XY LineString / MultiLineString 图层，使用实际 active geometry 列。要求已知投影 CRS，两个水平轴具有相同有限正线性单位；不隐式重投影。拒绝非 GeoDataFrame、重复列名、缺失／空几何或空部件、非线、Z/M、非有限坐标及无效线，允许空批。`id_field` 显式指定现有非几何唯一非空标量列，不用索引或存储 FID 推断来源。内部自交／自叠、同源多部件以及跨要素的精确重合均可规整。

保留每个原始部件的各次线段出现，按全部原始顶点、真实点交会及重合的起止端点细分；普通折点和闭环原首尾同样作为原顶点形成边界。只对精确相交位置切分，不使用容差、精度网格、舍入、吸附、延伸或近邻回退。每个输出片段为具有两个不同 XY 端点的直线段，正反等价的片段只保留一份，不把平行近邻或仅部分重合的未细分段直接等同。连续重复坐标形成的零长度原段不生成边或明细，但原段编号仍按原始相邻坐标对计数，因此可以出现编号间隔；不修改输入坐标或源文件。不同采样顶点、完全重复、反向重复和同源多次经过均以实际精确覆盖规整；不连接相邻边或调用链路合并。

双端口均为 geodataframe，保留原 active geometry 列名和 CRS、重建 RangeIndex：

- 默认 `result` 每唯一边一行 LineString，仅有几何、Int64 `edge_id` 和 Int64 `occurrence_count`，不选主来源、不聚合／复制任何业务字段。边方向固定为端点按 XY 字典序较小者到较大者；边号按源行／原部件／原段／沿原段片段首次出现从1递增，只是本次双结果的关联标识。`occurrence_count` 计该边的原始经过次数，同源重复经过也计入，不是不同来源 ID 数。
- `members` 每次正长度片段经过一行，保留全部源列／类型及原 ID，几何为该片段按原始经过方向排列的两个端点，追加 `edge_id`、`source_id`（保持原标识列类型）、Int64 `source_part_no`／`source_segment_no`／`piece_no` 和 Boolean `is_reversed`。部件号、原始段号从1起，`piece_no` 在每个原始段内按原方向从1开始；明细按源行、原部件、原段和片段顺序输出。`is_reversed` 表示本次经过相对唯一边方向是否相反。各次经过均单独保留，不能按 source_id 去重或将多来源拼成字符串。

源列与上述任一固定输出字段（含 `occurrence_count`）冲突即整批拒绝，不覆盖或自动改名；空批保留双端口完整 Schema 和所有源列类型。`members` 是逐片段来源关系，不宣称零长度重复坐标已存入明细或可以仅凭唯一边重建原业务要素。原图层与业务属性不变，不把该规整结果自动判断为业务正确，不推断桥隧或层级。

### 重合规整与链路合并的显式几何组合

首版复用既有算子，不新增算子、API、端口或业务实体：`normalize_line_network(source, id_field)` 的默认 `result` 输入 `merge_line_chains(..., id_field="edge_id", match_fields=[])`。空一致字段必须显式给出，表示业务属性差异不阻止几何连接；仍按全图端点度在分支处停止，无隐式吸附、补缝、简化或按角度选主路。规整输出的 `occurrence_count` 不作为一致字段，不因来源经过次数变化阻止连接；不从多来源中取首值／多数值、拼接或聚合业务属性。

三份成果配套保存，分别使用既有 `save`：

- `chains`：链路合并默认 `result`，仅实际 active geometry、Int64 `chain_id`／`member_count`，不提升原业务属性。`member_count` 是组成该链的唯一边数量，不是原要素数或原始经过次数。
- `chain_edges`：链路合并的 `members`，保留每条唯一边的原方向几何、`edge_id`／`occurrence_count`，追加所属 `chain_id`、链内 `member_no`、本级 `source_part_no`（唯一边为单部件，因此均为1）和 `is_reversed`（唯一边相对链方向）。每条唯一边恰好归属一条链。
- `edge_sources`：重合规整的 `members`，保持全部原业务列／类型及每次经过的原方向几何，包含 `edge_id`、原 `source_id`、原 `source_part_no`／`source_segment_no`／`piece_no` 与 `is_reversed`（原经过相对唯一边方向）。同源重复经过仍逐次保留。

仅用同次计算的 `edge_id` 连接两级明细，不靠 FID、坐标近邻或几何长度猜来源；链号／边号不宣称跨批稳定。两级 `is_reversed` 异或得到原经过相对最终链的方向；链内顺序取 `chain_edges.member_no`，原段内顺序取 `edge_sources.piece_no`。同名字段须按成果限定含义，原输入即使有业务 `chain_id`／`member_no` 仍只在 `edge_sources` 原样保留，不与本级技术链号／序号混写；本轮不生成扁平化关联表或新派生字段。规整原有保留字段冲突仍整批拒绝，不静默改名。

精确计数须满足：`sum(chains.member_count) == len(chain_edges)`；按边计的 `chain_edges.occurrence_count` 等于该边在 `edge_sources` 的经过行数，其总和等于 `len(edge_sources)`。链内每个有向片段须与本级边及原经过通过两级方向标记精确对应，原属性／NULL／Int64／Boolean／CRS不变；源内存与源文件不变。零长度原段沿规整契约不生成明细，原段号允许间隔，不承诺由三成果还原这些重复坐标。三成果的业务关系不塞入 Meta 技术血缘。

GeoPython `check_line_self_intersection(input_gdf, id_field)`（线内自交）位于“矢量处理 / 拓扑检查”，仅支持 workflow/read。输入及来源标识复用线交／线内自叠的校验：实际 active geometry、有效有限二维 XY LineString / MultiLineString、已知投影 CRS 且两水平轴具有相同有限正线性单位换算因子；拒绝缺失、空几何或空部件、非线、Z/M、非有限坐标和无效线，允许空批。`id_field` 为显式唯一非空非几何标量列，不推断主键或以行索引/FID替代来源，保留原类型。自交或回折本身不等于无效线，不因此拒绝。
