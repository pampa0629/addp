## `vector_reproject` 算子契约

`vector_reproject` 是空间坐标参考转换算子，只负责 geometry 批转换，不负责外部数据源接入、字段保留或写出。

```python
def vector_reproject(
    input_gdf: gpd.GeoDataFrame,
    source_crs: str = "",
    target_crs: str = "EPSG:4326",
) -> gpd.GeoDataFrame:
    ...
```

| 参数 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `input_gdf` | `GeoDataFrame` | 是 | 无 | 输入几何批。direct 调用时由 `binary_payload` 解码得到，workflow 调用时由上游节点传入。 |
| `source_crs` | `string` | 条件必填 | 空 | 源 CRS。若输入批本身没有 CRS，则必须显式提供。 |
| `target_crs` | `string` | 否 | `EPSG:4326` | 目标 CRS。GeoJSON 标准导出默认使用该值。 |

| 输出 | 类型 | 说明 |
| --- | --- | --- |
| `default` | `GeoDataFrame` | 转换后的几何批，只保留 geometry 和原有属性列；direct 二进制调用时由运行时重新编码为 `binary_payload`。 |

`vector_reproject` 的 direct 调用约定如下：

1. `binary_payload.content_type` 必须为 `application/vnd.apache.arrow.stream`。
2. `binary_payload.encoding` 必须为 `arrow`，且 Arrow 批只能包含一个 geometry 列。
3. geometry 列元素必须为 EWKB 二进制值，Arrow schema metadata 必须声明 `addp.geometry.encoding=ewkb`；HTTP `binary_payload.metadata` 中也必须声明 `geometry_encoding=ewkb`。
4. 算子只转换 geometry，不得接管 Transfer 的 load/save、checkpoint、属性字段重排或 GPKG 中间产物。
5. 失败时必须返回明确错误，不得静默退回原坐标。
6. 输出 `binary_payload` 仍为 Arrow + EWKB，只包含转换后的 geometry 列；输出 metadata 中 `source_crs` 和 `target_crs` 都应写入输出几何当前 CRS，不能继续保留输入 CRS。

## `crs_to_projjson` 算子契约

`crs_to_projjson` 是 CRS 定义表达转换算子，只把同一 CRS 的 WKT、ESRI WKT、Proj4 或 authority ID 规范化为 PROJJSON，不读取 geometry、不改变坐标，也不负责格式写出。

```python
def crs_to_projjson(
    crs_ref: str,
    definition_encoding: str = "",
    definition: str = "",
) -> dict:
    ...
```

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `crs_ref` | `string` | 是 | 平台 CRS 身份；支持 `EPSG:<code>` 或带定义的 `ADDP:CRS:<sha256>`。 |
| `definition_encoding` | `string` | 条件必填 | `definition` 非空时必须为 `wkt`、`esri_wkt`、`proj4` 或 `projjson`。 |
| `definition` | `string` | 条件必填 | 源 CRS 定义。只有 `EPSG:<code>` 可以省略并由 Runtime 本地 PROJ 数据库解析。 |

输出 `result` 固定为以下结构：

```json
{
  "crs_ref": "EPSG:3857",
  "definition_encoding": "projjson",
  "definition": "{...}"
}
```

direct 调用规则：

1. `execution_modes` 只声明 `direct`，请求和响应只使用普通 JSON，不使用 `binary_payload`。
2. 输入编码必须显式分派到对应 PROJ parser，不得使用启发式文本猜测。
3. `EPSG:<code>` 使用 Runtime 随附的本地 PROJ 数据库解析，Runtime 必须禁用网络 CRS / grid 获取。
4. EPSG 源定义必须和本地 authority 定义等价；冲突时失败。输出 PROJJSON 顶层 `id` 固定为输入 authority/code。
5. `ADDP:CRS:<sha256>` 必须带定义；输出顶层 `id` 固定为 `{"authority":"ADDP","code":"CRS:<sha256>"}`，不得因序列化变化重算平台 ID。
6. 输出必须是可解析的 JSON object、包含非空 `type`，并保持输入 `crs_ref`；失败不得返回原定义或伪造未知 CRS。

## 拓扑构面契约

GeoPython `polygonize`（拓扑构面）位于“矢量处理 / 几何处理”，仅支持 workflow，效果为 `read`。唯一输入 `input_gdf` 是当前工作流的 GeoDataFrame：仅接受二维、坐标有限的 LineString / MultiLineString，使用实际 active geometry 列；非空批中的空值、空几何、无效线或 Z/M 输入明确拒绝，不能静默丢弃。允许空批，保留源 CRS（包括未定义事实），不自动重投影。

所有输入线共同构成一个平面线网，先在真实交点处打断并去除重合线段，再提取闭合区域。内部自交线按真实交点构面；嵌套边界保留孔洞和其独立闭合面。首版不提供容差吸附、补缝、端点延伸或短线删除，不修改源数据、不继承源线业务属性。该算法在内存中处理完整线网，不能宣称固定内存或大规模容量已认证。

输出复用两个既有 `geodataframe` 端口：默认端口 `result` 每行一个 Polygon，仅含 `geometry`；`diagnostics` 为未参与构面的线段，字段为 `issue_type + geometry`，类型值为 `dangle`（悬挂或孤立余线）、`cut_edge`（两端相连但未参与构面的边）、`invalid_ring`（构面阶段发现的无效环）。两端口均保留源 CRS，空结果保留相同 Schema。诊断对应打断、去重后的线网，不承诺原始线 ID 追溯；余线可能是合法业务对象，不自动判为质量不合格。无闭合区域时返回空面及实际诊断，不补造面。

Develop 按 Runtime 元数据动态发现和显示端口，默认引用选取 `result`，显式 `port=diagnostics` 读取诊断；两者可分别连接既有矢量 `save` 节点。纯计算和预览不产生持久输出、Meta 扫描或血缘，保存继续使用现有授权及成果主线，不新增 Adapter 或 direct 路径。辅助诊断不替代独立拓扑质检、源线关联或评分体系。

验证沿用 `make test-geopython-workflow`，覆盖真实线网构面、交点与重合、孔洞、余线类型、零容差边界、输入拒绝、CRS/属性/源数据不变及两端口 DAG 保存重载。新用例加入根入口的显式文件列表，既有 Platform CI 的 GeoPython Job 和 engines 路径选择自动覆盖，无新增依赖、API 或 CI Job；确定性回归不替代完整 ADDP T4 验收。

## 几何检查与修复契约

GeoPython `check_geometry`（几何检查）和 `repair_geometry`（几何修复）属于“矢量处理 / 几何处理”，只支持 workflow、效果为 `read`，使用既有 `geodataframe` 输入与默认 `result` 输出。两者要求有限二维 XY 坐标（空值和空几何按下文处理），拒绝 Z/M 和非有限坐标，不静默降维；逐要素处理，不改写源，保留原属性、行数、顺序、索引、active geometry 列名及源 CRS（包括未定义事实）。它们检查和修复单个几何的平面有效性，不判断跨要素重叠、覆盖缝隙、悬挂线或业务质量，不吸附、补缝、延伸或重投影。

`check_geometry(input_gdf, valid_field="geometry_valid", reason_field="geometry_reason")` 在原数据副本中增加布尔有效性字段和字符串原因字段，使用 GEOS 平面有效性定义。空几何是有效几何；缺失几何为 false、原因为 `Missing Geometry`；其余原因为 GEOS 的 `Valid Geometry` 或具体无效原因（底层诊断文本，不作为界面翻译词条）。输出字段名须为非空、无首尾空白的不同字符串，且不能与任何源列冲突；冲突明确失败，不覆盖业务字段、不自动改名。

`repair_geometry(input_gdf)` 固定使用 GEOS/Shapely `make_valid(method="linework", keep_collapsed=True)`，仅修复非空且无效的几何。按边线和奇偶内外规则恢复有效性，不按 shell/hole 标签猜测业务意图。合法几何、缺失值及空几何保持原样；非有限 XY 或 Z/M 输入明确拒绝，不能静默删点或降维。一个源要素仍对应一行，完整保留修复产生的多部件、GeometryCollection 和退化线／点，不筛掉低维部分、不自动拆行。下游如需纯面须显式筛选，并遵守目标格式对混合几何的限制。若修复结果仍无效则执行失败，不能冒充修复成功。

验证沿用 `make test-geopython-workflow` 的既有 `test_topology_operators.py`、元数据和协议文件，Platform CI GeoPython Job 自动覆盖 engines 路径；不新增依赖、标准入口、HTTP API、Adapter、保存或扫描路径。覆盖真实自交与塌缩几何、属性及 CRS 不变、字段冲突、空批、源不变、工作流发现和检查→修复→复查→保存重载。原拓扑构面完整 T4 证据仅证明 `polygonize`；新增算子的确定性回归不冒充新的真实 T4。

## 参考吸附契约

GeoPython `snap_geometry(input_gdf, reference_gdf, tolerance)`（参考吸附）位于“矢量处理 / 几何处理”，仅支持 workflow/read，使用两个既有 `geodataframe` 输入与默认 `result` 输出。两个输入都必须声明相同的已知投影 CRS，其两个水平轴须具有相同、有限且为正的线性单位换算因子；容差是用户显式填写的有限非负数，单位就是该 CRS 的水平坐标单位，不固定为米。地理坐标、未知或不匹配 CRS 明确拒绝，用户须先使用既有重投影节点；不隐式投影或把度当米。

只接受有限二维 XY 几何，拒绝 Z/M、非有限坐标和非空无效几何，用户须显式修复输入。缺失值、空几何及空输入批保持原样；参考中的缺失值与空几何没有顶点，整个参考为空时输出输入副本。输入属性、行数、顺序、索引、active geometry 名及源 CRS 保留；输入和参考均不被改写。

参考图层的原有顶点按 XY 去重、排序形成固定点集。每个输入原始顶点只按原始 XY 位置查询一次最近参考顶点；正容差仅允许原始距离严格小于容差的候选，恰在边界时不移动；零容差不移动。等距候选按参考 X、再 Y 的升序唯一决胜，与图层行序及空间索引遍历顺序无关。选定后一次替换输入坐标，不使用已移动位置再匹配，禁止连锁越界。例如原点与参考点 0.5、1 米共线、容差 0.75 米时，只能移动到 0.5 米。

唯一技术路线为原始顶点空间索引查询、原始 XY 欧氏距离核验和坐标数组副本重建；不提供连续吸附模式或回退。只移动输入原有顶点，不插点、不删点、不造参考交点、不向参考线段上的任意最近位置投影，不迭代移动参考。保持几何部件结构、环闭合及行对应关系。任意一行结果无效（例如多个顶点吸到同一点造成塌缩）时整个算子明确失败，不保留部分结果、不回退源几何、不自动修复或删行；可由用户调整容差或参考后重新执行。此能力不保证图层间无重叠或无缝隙，不做补缝和端点延伸。参考顶点、索引及坐标数组在内存中，不承诺固定内存或大规模容量认证。

纯计算不产生持久输出；保存、扫描、血缘及权限沿用既有节点主线。确定性验证沿用 `make test-geopython-workflow` 的 `test_topology_operators.py`、元数据及协议回归，覆盖固定参考顶点、容差边界、米／英尺单位、CRS 拒绝、空缺失处理、原属性与两源不变、无效输出拒绝、工作流发现和双输入→吸附→保存重载；既有 Platform CI GeoPython Job 的 engines 路径选择和根入口文件列表已覆盖，不新增依赖、HTTP API、CI Job 或保存旁路。已有构面和单要素修复 T4 不作为本算子的真实 T4 证据。

## 面叠检查契约

GeoPython `check_polygon_overlap(input_gdf, id_field)`（面叠检查）位于“矢量处理 / 几何处理”，仅支持 workflow/read。输入为单个有效、有限二维 XY Polygon / MultiPolygon 图层，使用实际 active geometry；拒绝缺失、无效、非面、Z/M 和非有限坐标，不自动修复。空面不产生重叠，空批保留结果 Schema。CRS 必须是已知投影坐标系，两个水平轴具有相同、有限且为正的线性单位换算因子；不隐式重投影，不把度当面积单位。

`id_field` 必填，显式引用现有非几何标量列，值必须非空且唯一，字符串不能全为空白；不推断主键、不使用 DataFrame 索引冒充来源标识。结果固定为 `source_id_a`、`source_id_b`、Float64 `overlap_area` 和 active `geometry` 列，双方标识保留来源列类型。按输入行位置确定 A/B，同一无序要素对只输出一次，顺序按 A、B 的原始行位置递增；不按标识值排序，不复制其他业务属性，不修改源图层。

唯一计算主线为空间包围盒索引筛选候选，再计算真实交集并只保留面部分。每对的所有面部分合在一行 MultiPolygon 中，线点接触不输出。包含和完全重复同样报告；三个面共同重叠分别输出实际要素对，不融合为一个问题区。所有正面积重叠均报告，无忽略阈值或精度网格；面积是交集面的平面面积，单位为源 CRS 水平单位的平方（米或英尺等），不转换为平方米、不做测地面积。不能表示为有限正 Float64 的面面积明确失败，不伪装无重叠。

结果使用默认 `result` geodataframe 端口并保留源 CRS，保存接既有 `save`；纯计算不发布成果、扫描或产生持久血缘。不检查覆盖缺口、图层间拓扑、不自动决定重叠归属或修改公共边界，也不扩展 Quality 规则、评分和工单。索引和结果驻内存，候选及输出可能随相交要素对增长，不承诺固定内存或大规模容量。

验证沿用 `make test-geopython-workflow`，覆盖普通重叠、包含、重复、孔洞、多部件及混合维度交集、仅线点接触、微小正面积、稳定去重、来源标识与 CRS 拒绝、空批、两源标识类型、源不变、工作流发现及保存重载。现有 Platform CI GeoPython Job 和 engines 影响选择覆盖本次变更，无新依赖、API、权限、测试入口或 CI Job；旧构面、修复、吸附 T4 不作为本算子的真实 T4 证据。
