#### 隔离夹具与身份边界

`make test-online ONLINE_SUITE=pg-source-authorization` 仅使用 GitHub Hosted disposable、正式 IAM、共享生命周期及既有 PG 业务源；不连接个人库。办理者、消费者、业务确认者及组织维护者职责分离：消费者沿原 Meta 基础扫描／目录、Manager 读取功能，不获签发／委托；集中扫描、范围刷新及 Transfer 功能仅按各切片明确授权，数据 Grant 不代表引擎管理权。

所有人员 Role Scope 精确绑定当前 `tenant_id`／tenant；缺失、跨 Tenant、Platform 及携带遗留字段的 Department／Project Group Scope 均拒绝。组织事实独立核 `organization.departments`／`project_groups`。成员退出不改角色／功能 Permission，不删除组织 Grant；仅退出阶段按正文重认证，其他阶段沿原凭据和期限，不为通过断言增权或换身份。

#### 公共清理与证据要求

以下仅为 PG 各切片共用；NFS／MinIO 的身份、预算和资源收尾仍按各自小节，不扩大适用范围。

- **预登记与恢复**：命令、物理目标、任务在发送／创建前登记。成败／中断均按原编号回收本轮全部接收主体的当前来源；未知响应、任务、锁和源恢复仍按专项规定处理。保留签发／撤销／到期历史，不删历史凑零。
- **分层收尾**：领域收权与 Hosted 账号、源容器、Infra 销毁分别取证，清理失败使整套失败，不能由容器销毁抵消；其他 suite 的永久审计／设施例外不套用 PG 销毁要求。
- **安全报告**：仅归档身份引用、状态、计数／行数及边界摘要；不含凭据、业务原值或原始响应。凭据仅 owner-only 临时文件／进程内存，各诊断另守其白名单。
- **标准入口**：`make test-pg-authorization-online-runner` 覆盖确定性反例／生命周期并纳 Online／Platform；各专项保留分层入口。按固定源码认真实 T4，首过前仅手动、不加夜间；方法、局部或本地通过不补认当前 HEAD／完整 T4。

### PG 整引擎导航

复用原 PG 完整套件、普通 User 和正式 Grant API；120 秒扫描、45 秒根 Grant／75 秒到期观察不变。按[公共身份与清理](#隔离夹具与身份边界)执行，不替代两段浏览器、1500 串行及原 90 秒七档负载。

整引擎序列按[共同断言](#整引擎导航共同断言)；PG 独有要求是自有 Business 容器创建真实空 schema，basic 为零 DataItem／一个节点，未来表与原表均真实读两行，旧命令重放不复活。精确路径／命令预登记，物理空 schema 随独占容器销毁。

**负载凭据与审计。** 并发前、90 秒窗口外沿 Client Credentials 取得同一 Manager Runtime／Tenant 的机器 Token，核 ServicePrincipal 与原准备身份相同，仍为 5 分钟有效期。窗口内人员／机器凭据固定、401 不重试、不延长有效期；不能无限复用前段 Token。七档采样与唯一未授权批量对照共用该 Runtime，人员分别为 reader／outsider；完整审计含 2640 次采样及唯一 403。对照按独立真实请求窗口核唯一 403，采样按原七档窗口／数量／唯一请求身份核 200，不按状态丢弃其他记录；查询上限多留一条发现超量，不加请求或预算。

本次 PG Hosted 不包含 NFS／MinIO 整引擎 T4；它们按下述独立版本认定，不启用 CPU 切换。

### 授权生命周期与来源

隔离身份与安全收尾已集中到篇首[公共前提](#隔离夹具与身份边界)，本节只保留各阶段的差异。固定版本结论见[规则与分版本证据](#规则与分版本证据)。

#### 单表授权生命周期

单张普通表依次核无权拒绝、有限期 Grant、重复签发拒绝、精确 basic 强制重扫后身份／边界不变、撤销和自然到期；直接批准阶段相邻已扫描表始终拒绝。须真实 Manager 预览，不用 System read-check 代替；到期前后同一消费凭据，不调时钟／人工撤销代替自然到期。

#### 个人与组织来源

正式 IAM 先建成员关系再签会话，同权限普通成员／旁观者分离。同一 DataItem 的个人、部门、项目组三种来源须准确并集；全部记录按直接接收主体过滤。节点／单项及父／子节点也独立签撤，撤一来源不改其余，最后来源撤销／到期才拒绝；原编号重放不续期／复活，无个人排除或 Deny-only 入口。逐阶段核真实预览，旁观及相邻表拒绝；收尾覆盖全部主体。

#### 成员退出与 API 重新登录

已有租户管理员经正式 IAM API 结束部门、项目组关系，不新造受限 IAM 自定义角色。每次退出后旧 Token 在 AuthContext／Manager 均 401；原账号正式重登录后，先仍凭项目组读，退出最后组织后拒读。人员身份、Tenant Membership、四项消费 Permission 不变，组织 Grant／直接历史保留；只失成员来源，不全组撤权。

#### 成员退出后的浏览器刷新

保持同一 Console／Manager 会话，页面重读触发既有 401 静默刷新：每次仅轮换一次 Refresh Cookie，Console／iframe 身份和新 Token 收敛，iframe、路由、资源选择保持，无重复登录或页面级 Forbidden。仍有项目组时显示两行，最后来源消失则数据项级拒绝并清旧行。协调仅传本轮标识／阶段；Playwright 原始输出与失败附件在 Secret 目录，公开仅状态／计数。此阶段不含业务批准或其他引擎。

#### 读取功能权限反向门禁

复用业务确认 User，AuthContext 精确保留原 Catalog 确认权限且无 `manager.data_item.read`；办理者仅签本轮单表限时 Grant。预览前后均核 Grant 有效且完整绑定，Manager 仍 `403/permission_denied`，仅错误、无数据／元数据。不得靠自动撤 Grant、源规则或 Security 拒绝充数。事后显式撤 Grant、核历史，失败走全主体清理，账号功能／凭据不变。

#### 新成果初始授权

仅 `pg-source-authorization`、Hosted 标记及 `addp_online` 同时满足时，PG fixture 给登记连接账号 `public` schema 的 `CREATE`；不授已有表 INSERT／UPDATE／DELETE、所有权或超级用户权，其他 suite 只读。新表归创建连接账号，数据库访问条件、平台功能与 DataItem Grant 分别验证，建表失败不算自动授权拒绝。

原授权／工作区后，同一消费 User 仅补 Transfer 创建／读取／执行／删除及派生 Execution Authorization 功能；增加 Backend／Worker，各 System／Meta／Transfer 独立 OAuth Client。精确限时源 `metric_people` 同步到随机唯一 PG 表，关闭任务自带扫描；Meta 只能产生一个识别该叶子的 basic 子执行，不给消费者签发／委托资格。

物理成功后须后台自动产生唯一 `task_production` Grant，绑定原执行、DataItem／边界、人类来源及独立机器签发者，期限等于唯一输入来源；不用机器 Token 直接触发签发。Manager 实读两行、旁观拒绝；撤源后成果仍读，撤成果后拒绝。

历史候选用随机成果名的字面量 `table_search`（不与 `catalog_path` 同提，后者会含节点 Grant），仍逐项严格核 typed path、execution、产出来源、接收方；名称不证明归属。签后／撤源／撤成果均同候选范围，截断／外来候选即失败。未知响应恢复只查已捕获任务的执行及该成果候选；先关源授权，核清可能丢失回执的成果 Grant，再删定义，历史保留、物理表随独占容器销毁。本阶段须独立固定版本 T4，旧生命周期通过不能补证。

#### Catalog 集合的确定性验证

Catalog PostgreSQL 以真实 HTTP 核功能与资源范围独立：同 Tenant 功能权限下当前项目组成员可访，退出后列表／详情不可达，集合／成员条目仍留存；部门可见性另限条目，失成员不删条目。即使仍为成员，缺功能也不可读写。本层为真实 Catalog PG＋受控 AuthContext，不代 OAuth／PG 内容读取 T4。

### 读取裁决性能采样约束

下述串行／并发矩阵共用本节，观察器与归因限制沿[尾延迟诊断](#审计尾延迟诊断)，不改变既有业务／浏览器／收权断言。

- **实际读取**：PG 预览核精确列／值／行数；沿[分页契约](../../../../manager/docs/数据预览语义协议.md#表格预览分页)，已知 `total` 须精确，未知须 `total=null` 且 `has_more=false`，无权／撤销／到期拒绝保持。
- **固定输入**：原消费 User／凭据／有效 Grant，不延时、刷新身份或重试失败。AuthContext、完整 Grant 历史及 Meta 指纹／组成边界在各轮／单元前后相同；漂移、HTTP 拒绝、传输／响应异常或超预算即失败，保留已采计数并走原 finally；凭据只在内存比较。
- **计时**：正式 `POST /system/engine-access/read-checks/manager-preview` 仅只读裁决，成功只能有有效 `observed_at`，不签权／代真实内容读取。耗时为 GatewayClient 发 HTTP 至 JSON 解码的完整往返，含身份解析／Meta 事实查询，不当纯规则／SQL 耗时或直接对比旧服务端整数毫秒日志。
- **统计**：保留毫秒原样本和预热／成功／失败计数，预热／失败不入有效分位数；nearest-rank 算每轮与合并 P50／P95、列轮间范围，不删异常值／加性能阈值制造稳定。

`make test-pg-authorization-online-runner` 仅证确定性方法，真实样本仍归原 PG Hosted；只用 disposable 原账号／测试授权，不新增 suite／入口／依赖／权限／生产 API 或触碰个人持续授权。

### 固定目标读取裁决性能样本

在首个既有限时单表 Grant 已验证可读后、重扫及撤销场景之前，复用 `public.metric_people`，串行采集三轮各 500 次正式请求，共 1500 个正式样本。每轮另做 10 次预热；请求间隔 10ms、轮间间隔 1s 均不计入请求耗时，全段预算 90s。

### 依赖故障、直接授权与内容变化

旧 `c8977cecb` 的通过、原件、清理及缺口归[篇首旧许可模型证据](#规则与分版本证据)，System 并发 T2、Runner 与真实 T4 分开认定。各故障只动本轮 disposable，由单一 Hosted 协调器沿标准生命周期操作；核真实监听、同构建新进程与其他 Owner 未重启，失败仍恢复依赖并按[公共收尾](#公共清理与证据要求)清理，不改源边界／权限／凭据或生产同步周期。

#### Security 首次保护投影

Hosted 必须启动同源 Security 并先于 Manager Ready。服务启动后新建 Tenant，首次 Meta 扫描前用 `online-api.wait_manager_read_boundary` 对正式 Manager 读取接口有界等精确 Engine 首次保护同步。仅初始化 `security_protection_required` 可等，其他拒绝／畸形／超时即失败；保护就绪后未授权须由 System Grant 链拒绝，该保护错误不算未授权通过，不跳保护／补 checkpoint／增消费权绕过。

#### Meta 事实依赖离线与恢复

有效 Grant 下标准停 Meta，事实查询／Manager 读取明确依赖不可用，不回退原生读取、伪装未扫描或造替代授权。恢复不重扫，身份、批准摘要、历史不变，原 Grant 恢复实读且相邻表仍拒绝，最后撤销。只证事实依赖可用性，不证同身份组成扩大／列授权。

#### Catalog 业务批准闭环

前段完成后，对原无权相邻单表增加 Catalog（不启 Asset／Portal、不扩引擎）。负责人仅目录读取／盘点／编目／共享确认；办理者另有独立办理，消费者不变。沿正式基础扫描自动建档、责任／边界、确认及办理 API，Catalog／System 各自 OAuth 自动受理签发；脚本不持机器 Token，不直写批准／Grant，不配置旧逐项许可，请求只绑业务批准／Meta 边界。

仅确认仍拒读；签后核 DataItem 指纹／边界、接收方／期限及唯一历史，再由 Manager 实读。显式撤销沿 System 原路径，旁观拒绝；同参／撤后重放不重发／续期／复活。历史不能代实际访问。

#### Catalog 可选依赖离线与恢复

沿该业务 Grant 及原凭据停 Catalog：Manager 仍读、System 历史不变；新办理明确模块／代理不可用且零 Grant。合格办理者可独立发直接授权命令给旁观者、核读后撤，失败业务请求不得自动转换。

离线仍可撤原 Grant，预览须拒绝；恢复后重放原已签发请求不复活，新失败请求无受理／签发。不重扫、改持久启用声明或新增角色；未受理请求不等同停机前已受理、可沿原窗口续办的请求。

#### 普通表内容变化

Business 自有普通表仅固定新增／更新／删除／恢复基线；每次精确 `basic + force`，Meta ID、fingerprint、边界与 Grant 历史不变，有效 Grant 实读变化／恢复后内容。撤 Grant 后再变内容、重扫／重放均不恢复权，旁观及相邻表拒绝；退出恢复基线。只证 single 内容更新，不证同身份组成扩大、列授权或 multi／whole；边界变化匹配另由 System PG 判定层 T2 覆盖。

### 授权工作区与办理身份

#### 正式身份与办理角色

身份职责见[Role 规范](../../addp权限与角色发布规范.md#五role)。沿原 PG Hosted／隔离表／正式登录，办理者组合既有“数据授权办理员”内置角色，统一承担直接批准与业务确认后的办理；`catalog.entry.read`、`system.engine_access_fulfillment.create` 必须来自该角色，不重复塞自定义角色，不增加消费功能或办理者数据读取权。

`make test-authorization` 核权限目录；`make test-system-iam-postgres SYSTEM_IAM_POSTGRES_TEST_ARGS="--package migration --test unified-data-authorizer"` 核前向迁移、角色分配保持、主体授权版本推进、旧会话回收及重启幂等，原全量 IAM PG 自动发现。

#### 工作区前置清理

成员退出保留的组织 Grant 是必要事实，不能假设只剩个人来源。先沿[公共收尾](#公共清理与证据要求)撤本轮全部有效个人／组织来源、留完整历史，核零后才签工作区预登记单表 Grant；清理失败即停，不进浏览器／新增 Grant，不靠删历史／改退出规则凑计数。

#### 授权视图与实际撤权

“新增授权／当前授权／全部记录”互斥同排。PG 共享树混选项／真实节点：默认直属当前及未来、节点独立递归，选叶不改父、筛选不缩范围、重叠不替换；选择仅草稿，完整准备后批量确认，失败沿原逐项命令恢复。当前授权核表名／树叶精确过滤、接收方类型／账号及来源展开；全部记录保持有效／撤销／到期差异。办理者在真实 System 页撤预登记限时单表 Grant，当前移除、历史留原号／撤销，同消费浏览器重读 Manager 拒绝并清旧行。

#### 导航零写入与请求分类

精确目标 Engine 的 `POST /catalog/children`、`POST /authorization-nodes/query` 仅树／节点读取，此场景其余非 GET 引擎请求均检查变更；不把所有 POST 当写，也不泛化排除漏掉 Grant／委托。导航零写，最终规则变更仅撤预登记 Grant。

#### 专用环境与当前身份

使用[T4 常规 macOS 专用部署](../T4-Online验收规范.md#专用环境)，Host Gate 启动 System／Gateway／Meta／Catalog／Asset／Portal／Console；`business/scripts/online-engine-fixture.sh`在同一永久 PG Engine 幂等准备 `public.addp_online_catalog_fixture`。专用 `SYSTEM_SERVICE_CLIENT_SECRET`缺失须在启动前拒绝，不改变普通部署可留空的 Ready 边界。

真实 User 先 AuthContext 核 Tenant／精确 Permission，业务 API 只经 Gateway、不直连 owner 或 SQL；唯一数据库例外为[System owner 只读证据](#oauth-自动签发的只读观察)。

#### 目录初始化与来源幂等

预置可引用 Standard Domain／Department；正式 Meta 扫描后按 fingerprint 等唯一 CatalogEntry。首次可用预置域／部门／当前 User 把永久源的 discovered 项初始化为稳定 curated 夹具，后续仅临时编目并按[公共收尾](#恢复清理与审计留存)恢复完整聚合。重复真实扫描核 fingerprint／Entry UUID 幂等、inventory／governance 视图、覆盖率固定维度及精确来源解析。

#### 资产发布与临时资源清理

以 Entry UUID 建 AssetComponent，发布后 Portal 返回同身份，并由 AssetCategory 树／子树列表及真实分类页发现唯一 Asset 卡片和目录名。临时 Asset 按 `published → offline → deleted`，先核空 Category 从 Portal 消失，再删 Asset-owned 目录；双方 GET404 及 Portal Asset404 共同证明临时资源归零，不由编目恢复代替。

#### 来源展示与共享历史浏览器

同专用 User 登录 Console，核覆盖率／详情／Domain、Department、Engine 名称选择器，warning/error 即失败。该次登录 Token 只读当前 Entry 及本轮精确共享确认，不增账号／决定／授权。

- 技术来源在 1440px／900px 核 API 引擎名／类型、项名／类型、完整路径；双列宽度、长指纹省略、悬浮／聚焦全文、Tab 移出关闭及刷新恢复与 Console T3 共用 helper。
- 共享历史核本确认接收方姓名、可选账号编码、“当前账号”及刷新一致；候选核姓名／登录名，只读选当前账号、不发业务命令。
- 既有 helper 仅允许首次匿名 Refresh401 单列最多一次，认证消费后 API 失败仍失败。唯一报告 `addp.enterprise-catalog-publishing-browser/v3`绑定本确认，完整来源／双视口／刷新／当前账号布尔断言；缺项／错类型／新增共享命令拒绝。受控校验不代真实 Runner T4。

#### 弃用与责任变更

同 fixture 经 `curated → deprecated → curated`，弃用中用现有 User 增／移可选技术负责人，不造账号／部门／权。实际责任变更保持弃用、业务定义／语义／可见范围／来源；撤弃用不恢复认证，旧版本 `409 catalog_entry_version_conflict`零副作用。按[公共收尾](#恢复清理与审计留存)恢复，审计／并发版本不回滚；跨部门发现范围／权限交集仍由 T2 证明，不以单账号 T4 代替。

#### 普通只读共享受理

专用 User 必须当前业务负责人、显式共享确认及独立办理 Permission，管理员预置有效引擎管理委派；不自动赋权／建委派，不查询／初始化／改直接授权配置。正式准备、双服务 OAuth 反查／首次受理均走产品链。

请求显式十分钟，办理窗口仍首次受理起最多五分钟。同决定编号换用途、同办理编号换决定均 `409 catalog_sharing_decision_conflict`，原决定／回执不变、不增编号；可有操作审计，须数据库计数、不猜预期数量。同参重放完整绑定、受理／截止时间不变；丢弃已提交响应只证调用方恢复，不冒充服务间断网／进程重启。User Token 进机器反查／受理拒绝，pending／错绑定／恢复失败不算通过。

受理不等于 Grant 或可读；后台签发沿[只读观察](#oauth-自动签发的只读观察)，不借机器写 Grant，此 suite 不验源内容读取。

#### 恢复清理与审计留存

通用要求沿[T4 数据、超时与清理](../T4-Online验收规范.md#数据超时与清理)，仅正式 API 变更，三类分别认定：

| 对象 | 收尾边界 |
| --- | --- |
| 临时编目／弃用／责任变更 | 成败均 finally 恢复已保存完整聚合并回读。写响应未知先查当前状态，不重发原命令；恢复失败整套失败。 |
| 临时 Asset／Category | 按[发布与删除顺序](#资产发布与临时资源清理)核 Portal 消失及各 owner404，不能用 Catalog 恢复代删资产。 |
| 不可变审计 | 业务决定、核清办理、System 回执、自动 Grant 及签发审计作为专用 Tenant 长期事实保留，不随临时资产删除。 |

### OAuth 自动签发的只读观察

沿[专用身份](#专用环境与当前身份)，User 正式发受理，生产 Catalog 用自身 OAuth 自动签发，验收不借其身份。System owner 既有夹具仅在回环 `addp_online`以只读可重复读事务，按精确 Tenant／Engine／请求号核受理、唯一 Grant 和成功审计，重放后签发时间／审计次数不变。

`grant_write`通过须原受理窗口内恰一 Grant＋一成功审计；`source_content_read`仍 `not-run`，签发不推出实际可读。此连接禁初始化身份／迁移／写入，不是人类 API、Catalog 副本或访问裁决。

确定性协议／准入归 `make test-online-runner`，真实 PG 查询／只读拒写归 `make test-system-iam-postgres`；完整 OAuth 仍须原手工 T4 实际执行，层级不互代。

本 suite 的隔离部署前提见[T4 专用环境](../T4-Online验收规范.md#专用环境)；本节只维护该 MySQL 消费链的专用准备、断言与收尾。

### 环境与身份准备

Host Gate 全量启动 System、Gateway、Service、Workbench 和 Console；`business/scripts/online-workbench-mysql-fixture.sh` 使用外部环境变量启动 `business-mysql`，重建仓库既有 `customers + orders` 确定性数据并创建仅有 `SELECT` 的专用账号，同时为 Playwright 安装专用 Chromium。

专用环境长期预置指向该账号的 MySQL Engine Instance，身份由 `ADDP_ONLINE_WORKBENCH_MYSQL_ENGINE_ID` 提供；suite 不创建、修改或删除 Engine Instance。

两个真实 User Token 各自先校验 AuthContext，均属于同一 Tenant，且不得是个人会话或平台管理员 Token。

| 身份 | 本场景职责 |
| --- | --- |
| 非管理员专用 User | 不含管理员角色，只具备 Service/Workbench 场景权限，负责发布与消费。 |
| API 消费方管理员 | 独立 `ADDP_ONLINE_TEST_TENANT_ADMIN_ACCESS_TOKEN` 必须属于 User、含 `tenant.administrator` 角色并具备当次 API 消费方生命周期所用权限，仅负责消费方及凭据生命周期。 |

### 服务发布与应用草稿验证

非管理员 User 的所有平台操作只经 Gateway：检测 SQL 输出契约，发布私有主 Query Service `commerce-order-analysis` 和同契约未授权 Query Service `commerce-order-analysis-denied`，读取主服务 Consumer Descriptor，创建 Data Application 草稿并执行查询。SQL 只 JOIN 既有表并排除姓名、邮箱、电话和地址；MySQL 将 `BOOLEAN` 暴露为 `TINYINT`，publisher 只把已知语义的 `active_customer` 显式发布为 `bool`，Service 再按冻结契约归一化 `0 | 1`。

API 层还要验证 `order_no` cursor、五类动态筛选、decimal/boolean/timestamp/null、完整有限 CSV，以及无 SpatialInfo 时 Map 不可用。浏览器使用非管理员专用 User 登录 Console 并核对浏览器 AuthContext 与 API User 身份一致，在同一应用草稿中依次打开两个 Component 的正式编辑器，验证 Table 两行结果、Chart canvas 和无空间契约下不存在 Map。

浏览器经正式 Service API 更新主服务的公开默认字段策略以改变 `contract_fingerprint`；刷新同一应用后 Component 编辑器必须显示契约变化告警并禁用预览查询。API 层同时确认已保存快照仍持有旧指纹，不增加 Workbench 执行 API 或测试旁路。

### API 消费方身份与数据面

Tenant Administrator 只经 System 正式 API 创建一个仅授权主 Query Service 的 API 消费方及一枚凭据，按下表核对成功、越权拒绝和删除后的凭据失效。凭据只保存在 suite 进程内存；报告、日志和错误不得包含完整 API Key。

| 核对项目 | 实际请求与判定 |
| --- | --- |
| 已授权服务 | 主 Query Service 返回 200。 |
| 同 Tenant 未授权服务 | 同契约未授权 Query Service 返回 `403 api_consumer_service_denied`。 |
| 控制面拒绝 | `GET /api/v1/system/tenant/api-consumers` 返回 `401 api_consumer_control_plane_denied`。 |
| 删除后的旧凭据 | 删除 API 消费方后，旧凭据调用主 Query Service 须在 45 秒内收敛为 `401 api_consumer_credential_invalid`；超时失败。 |

控制面统一拒绝规则见 [Gateway 认证边界](../../../../gateway/docs/gateway架构说明.md#2-路由平面)；本场景只验证表中控制面请求，不代表所有 `/api/v1/*` 路由均已逐项验收。Gateway 30 秒正缓存和 Service 逐请求复核见[缓存与撤销](../../../../gateway/docs/gateway架构说明.md#4-缓存与撤销)；45 秒为本场景的撤销收敛上限，凭据可提前失效。

### 临时资源收尾

`finally` 只按本轮捕获 ID 删除 API 消费方及其级联凭据、未发布 Data Application 和两个 Query Service，并逐项验证 404 或凭据失效；Fixture 和全套 ADDP 再由 Host Gate 统一停止。最终发布运行态由 Outdoor 双服务场景验收，不能为自动清理增加已发布应用强删旁路。

## catalog-domain-overview

### 跨域样本与权限断言

准备阶段通过正式 API 创建另一业务域并发布临时数据元；生效后冻结完整响应，业务验收身份只读引用该标准。

场景创建运行编号隔离的消费 Domain、五类标准草稿和 Model Entity，在临时属性中引用该数据元；等待真实 owner 变化源使五类身份及模型条目收敛，核对稳定身份、精确域类型统计/覆盖率、跨域目标归属、使用位置和 Model 草稿未冻结修订的事实。

普通读者必须对 inventory 总览、列表、跨域目标解析及专业引用接口被明确拒绝或不可发现；governance 总览不得泄露草稿。

### 清理与源标准保持

退出按依赖逆序通过正式 API 删除消费侧专业对象并验证零残留；再次比较被引用数据元完整响应不变。

生效标准及目录审计历史保留至本次部署销毁，不绕过历史保护删除；共享 Hosted 清理必须证明应用、Infra 卷及临时凭据零残留，任何失败都不得计通过。

### 验证层级与未覆盖项

确定性协议与异常清理由 `make test-catalog-domain-online-runner` 验证；T2 验证迁移、归档、事务变化捕获、分页和修订证据；T3 使用真实 Console/Catalog 前端验证总览导航、权限与刷新。T0–T3 通过不代表真实 T4 已执行，文档下载故障注入和全量跨域关系不由本场景宣称覆盖。

### 接入与身份

手动 `manager-internal-artifact-lineage` 的 `filegdb-authorization`，标准 `make test-manager-online-runner`。仅 NFS／GeoPython，独立消费 User 六项读取／扫描／执行观察，既有 source initializer 办整项 Grant；旁观者仅同租户 `manager.content.read`、`manager.data_item.read`，无数据 Grant／组织关系，不改主账号／办理者权限。根导航的树观察附加资格见[独立阶段](#nfs-整引擎导航固定-08484e4e7-完整-hosted-已通过)，不扩大内容权。

Meta basic 形成一个 whole DataItem，正式身份清单只读，`.gdb`为一叶、不列内部碎片；精确项批量选节点仅展开当前已识别项，不含未来独立项。`scope`绑定 NFS、DataItem、FileGDB 根／规则，内部新增子表不改摘要；错根、越界引用、缺事实／不完整组成拒绝。签前重核基础事实／办理资格，浏览器不自造 scope。Runtime 挂本轮只读 NFS 客户端、不挂宿主源目录；`noac`／`soft`仅测试选项、不改产品默认。

主账号获权后，对原／新增子表分别“主账号读成功→同 locator 旁观 403 且无内容→主账号仍读”，前后主 Grant 历史／来源不变、旁观关系空，同一凭据，核 `ungranted_account_initial_child_denied`、`ungranted_account_new_child_denied`。缺功能、跨租户、匿名或 Security 未就绪不当此反例。全阶段清理见下节，不补额外账号／功能／数据授权。

### 内容读取与下载

每次子表、成员流／`storage-assets`及 Range 按当前 User 核整项 Grant、撤销／到期、Security 及实际 Runtime 根；父只展示 Meta 索引，basic 未索引显示未知，不以服务身份补读。成员读取不变授权；无权、同 Grant 字节／Range、旁观、撤权／到期逐项验。

整目录 ZIP 沿同 Grant，保 `.gdb`根、层次、原名／原字节；能力声明实际可下且 `requires_current_user=true`，不由引擎能力推所有格式可下。按物理源快照独立核成员集合／CRC／逐成员 SHA-256／附件头，完整接收才保存。覆盖原／新增子表 ZIP、四授权状态、旁观、Manager 崩溃／NFS 断连后原 Grant 恢复，逐请求及最终 Manager 无临时包描述符。源变化／取消／打包读取失败的终止交付和清理由 Go T1，按钮／认证／失败不保存／附件原名由前端 T3；均不代真实 ZIP T4。

### 浏览器渲染与保存

同一正式 Console／Manager iframe、原普通 User 和整项 Grant，不替响应或改内部状态。每次操作恰一条绑定 locator／当前 User 的精确请求；下载证 Bearer、无 Cookie／URL 凭据，公开材料不含 Token，导航零业务／授权写，各页面阶段操作前后源／Grant 历史／来源保持。

| 页面切片 | 不可省略的断言 |
| --- | --- |
| 单元格与切换 | `initial_points`等真实渲染后按 label／value 逐格核两行，真实选择器切 `added_points`一行、旧行清空，页内／总数一致，两次请求各一次成功；归档两截图及 DOM 单元格，检查 `real_browser_child_cells_and_switch`。下载或截图行数不代表单元格通过。 |
| 分页与复位 | 保原 2＋1 行，仅新增阶段添 23 行 `paging_points`。默认 20 行，首 0–19、次 20–22、首→次重读；切 added 再回 paging 均重置首／20。逐格值、当前／总数、页码／前后按钮／清旧和状态截图，逐请求 child/page/page_size。新增 `real_browser_child_pagination_and_reset`；旧 24 项目标和子表切换通过不证明分页已验，原读取／下载／撤权／到期均保留。 |

| 同次响应取证 | 测试复制页面同一次 fetch 响应，原件照常交页面，副本与保存 ZIP 逐字节比较并分别归档，再核源成员／CRC／大小／摘要。每阶段下载恰一次；禁止可能重发 URL 的 Playwright `response.body()`、额外请求／网络替换／产品改动，复制缺失／失败、重复或字节异均失败。 |

### 故障恢复与清理

故障仅独占部署：Manager 强退／源断连后保原源和 Grant，恢复重新按原权读取；环境不可用不是 403，不加产品重试／看门狗／故障收权。断连前真实路径可读，停后须有界 I/O 失败；`mounted_path`仍可读或超时都保失败，不能以停 NFS 动作代实际断连。

SIGKILL 仅验已持本轮临时 Grant 的子进程；存活外层和 Hosted 生命周期按预登记收权，核撤销史／有效来源 0、自有源和 NFS 导出销毁，原件／新增子表／撤权／到期断言不减。旁观仍无有效关系、临时身份随部署销毁。失败也核临时 ZIP 句柄及领域收权，不能只靠设施销毁，清理失败即整轮失败；整机／Runner 失联不在子进程保证范围。

### 标准入口与覆盖范围

- 新增授权的身份清单还须通过正式 `SetupRouter` 装配回归：真实 User 凭据经权限门禁后，由 System 自身的租户机器身份查询 Meta；Owner 不可用仍返回 503，不返回空清单或重试 POST。标准入口为 `make test-system-iam-postgres SYSTEM_IAM_POSTGRES_TEST_ARGS="--package api --test authorization-facts"`，复用已有 API PostgreSQL 门禁。

- 最小门禁：Common/Meta/System/Manager Go T1；`make test-meta-postgres META_POSTGRES_TEST_ARGS="--test authorization-facts"`；`make test-system-iam-postgres SYSTEM_IAM_POSTGRES_TEST_ARGS="--package engineaccess --test file-composition"`；`make test-common-frontend`、`make test-system-frontend`、`make test-manager-frontend`；`make test-authorization`。沿已有 Make/CI owner 自动发现，无新增测试 database 或服务依赖。

- 上述 PostgreSQL 门禁使用真实数据库与 User 身份、正式签发／撤销／拒绝命令，Meta／源 Provider 为受控夹具；浏览器 T3 采用受控 HTTP 响应。它们均不能代替真实 NFS FileGDB 子表读取的跨服务 T4。后者须单独核对签发、实际行读取、容器内新增子表、撤权、到期和清理，不将此次协议实现推广为其他 whole 格式已接入。
