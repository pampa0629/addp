## starrocks-consumer-flow

StarRocks 首版只认证 `default_catalog` 内部普通表的只读接入。手动 Hosted Linux x86_64 场景 `starrocks-consumer-flow` 复用正式 Business 固定双架构镜像、初始化入口及独占持久卷，先验证业务 reader 原生拒写、容器重建后 Backend ID 与用户数据保留，再登记当次随机回环 SQL 端口；不读取个人 `.env`，不启动或接管个人 Business 服务。退出检查当次容器、卷和镜像零残留，私有凭据不进入报告。

Business 后续增加 `customers`（5行）、`products`（6行）和 `orders`（10行）业务示范，保留两行 `source` 精度样例。页面场景的扫描目录断言相应要求恰好四张表，再从中定位 `source`；不能放宽为任意目录或因返回顺序改变而选错表。双架构 T2 的 Business 阶段核对21条新记录、三表关联、金额39179.40、日期／布尔／空值、用户修改保留和删除一条样例后重启补齐。初始化每轮先移除上轮完成标记，全部样例和 reader 验证成功后才重新写入，避免旧标记使本轮初始化提前健康。下述旧 T4 记录仍只证明各自精确源码，不自动证明新增样例的页面消费。

样例初始化在 `1b9b5673b1ec73e92f734c1dc1e5dfbd910d5d00` 的 [amd64 Job118415804534](https://github.com/pampa0629/addp/actions/runs/39357512438/job/118415804534) 和 [ARM64 Job118415804566](https://github.com/pampa0629/addp/actions/runs/39357512438/job/118415804566) 通过原生／Provider／Business T2，无跳过且清理零残留。本机 reader 与管理员预览核对四表、金额及 NULL／空串，仅属本机交互；新增四表的普通 User Hosted 仍缺，不由旧 T4 或上述 T2 补证。

## highgo-consumer-flow

2026-11-13 确认的 business 授权范围：HighGo `customers/products/orders/order_items/orders_replace_online`、PG `orders`共六表，仅独立准备 User 精确 targets deep 扫描、签六 read；消费 User 无扫描 execute/read，业务前清准备凭据。公共 Meta 只核身份／字段／主键、拒内容属性；正式受保护 Manager API 及 Console 核四业务表的 11 具名约束、10 索引、键／列顺序、普通表无分区及精确行数。PG 订单两次 snapshot replace 到 HighGo 哨兵表，逐值核七字段／金额、无重复，保留原生源表保护；写后由任务自动扫描，消费 User 不补手扫。

停服前原身份撤六 Grant 并核隐藏／拒读，未知／失败签发也记私有意图清理；销毁当次平台、业务容器、卷和身份、核零残留，不归档凭据。`make test-highgo-online-runner`覆盖反例／生命周期，Online／Platform 检查登记。business 与下述 `sql-timeout`独立认定，不包含增量 upsert、CDC、空间或分区表页面，真实首过前不加夜间。

HighGo 页面 SQL 超时与恢复扩展（2026-11-13 已确认范围）复用本套件的独占 Linux x86_64、既有镜像和回环随机端口，仅操作合成 `addp_business.addp_engine_probe`。控制身份在原生事务中持有该表的排他锁，最长240秒；Manager／Develop 使用普通消费身份执行已授权的只读表查询。必须先在源端确认它真实等待本次持有连接，再核对正式失败面板及稳定错误分类；超时不以主动取消、错误凭据或保护拒绝替代。释放锁后分别核验正常预览／查询恢复，保留原生持有连接、等待连接及清理证据，不新增产品超时配置、重试或权限兜底。

夹具 `barrier acquire|observe|release manager|develop` 仅允许既有 Hosted 身份和归属容器，阶段各自只派发一次；派发前写入私有意图，结果未知不重发。释放同时核对本次PID、application_name、数据库及控制账号，不凭旧PID终止其他会话。日志只输出运行标识、阶段、连接ID和等待分类，不输出原始SQL或凭据。等待者还须持有探针表未获准的relation锁并由本次控制PID阻塞，SQL类型明确区分表目录核验 `table_catalog` 与内容读取 `table_read`；Manager实时目录核验本身也是源端SQL，不将其误记成分页内容读取。同套件通过显式 `highgo_case=sql-timeout` 选择独立超时用例，默认 `business` 仍保留原业务断言。超时用例仅部署并登记HighGo，启动System／Security／Meta／Manager／Develop，独立准备User仅补齐 `meta.scan_task.execute/read`，对探针表作精确基础扫描并签发唯一read Grant。消费User仅有既有SQL池场景的8项查询／预览权限，无扫描、授权办理或Transfer权限。进入业务页面前移除登记与准备凭据，退出前由原独立身份撤销精确Grant并验证拒绝。必须独立证明Manager HTTP504与 `preview_sql_execution_timeout` 持久失败面板、Develop执行终态与 `sql_execution_timeout` 诊断、对应原生等待消失、表锁释放及两处真实页面恢复；不以主动取消或权限拒绝代替。业务场景按上述六表范围迁移 Meta 契约，两种用例结果不得互相替代。尚未取得真实结果前不计页面或Hosted通过。验证仍由 `make test-highgo-online-runner` 自动覆盖，不另设套件、端口或定时任务。

## hdfs-spark-consumer-flow

**部署与入口。** 手动 GitHub Hosted Linux x86_64；`scripts/test/online-hosted-hdfs-gate.sh` 复用共享 Hosted 生命周期。Business 管当次 Hadoop、两套 Spark Master／Worker、PostgreSQL、MinIO，以及 MySQL／Doris 扩展夹具；System helper 管普通消费 User 与独立登记／准备身份。HDFS storage Engine 与 Spark general Engine 分别经 System API 登记、连接测试。Spark Workflow 由 `scripts/utils/hosted-online.sh` 调用根 `make build-images` 构建并使用镜像默认入口，核对镜像 ID、入口、提交和运行容器；不得覆盖 command、启动原生 Workflow 服务或直接调用 Runtime 代替 Develop 执行；须核对 Runtime 与 Develop 的同一 execution 状态。Linux 夹具使用宿主网络与回环地址，真实 Worker 执行分布式任务，不能用 `local[*]`。

**授权准备（2026-11-03／04 已确认）。** 只消费既有精确授权契约：独立管理员经 System `authorization-facts` 取得 Meta 持久身份及完整边界；边界缺失、替换或不完整即失败。消费账号先拒读，正式签发后再沿其过滤目录核名称、类型和指纹；不能把未获权账号的目录当授权发现接口或改由管理员代读。

## 关系型引擎消费链路

### OceanBase

OceanBase 消费链路 T4 使用专用 OceanBase CE MySQL 模式 Fixture 和永久 `engine_type=oceanbase` Engine Instance。Fixture 固定维护一个 5 行非空间 InnoDB watermark 源表和一个同构空目标表；suite 必须经 Meta 扫描取得两个 ResourceLocator，以同一条 bounded watermark Transfer 任务依次验证首批 5 行、源表确定性更新/新增后的 2 行增量，以及再次执行的 0 行空增量。目标采用 `upsert` 和唯一稳定键 `id`，不得把 OceanBase 降格注册为 MySQL 或为模块增加类型分支。首批与增量完成后，Manager 表预览、Develop SQL 和临时 Query Service 必须通过各自正式数据出口读取同一目标 ResourceLocator，并得到一致 checksum，最终固定为 6 行且无重复键；Manager 预览还必须确认扫描结构中的完整列顺序。临时 Transfer 任务和 Query Service 必须按捕获 ID 删除并确认 404；物理 Fixture 在成功、失败和中断退出路径恢复源表基线与空目标表后停止。该 suite 只登记手工 `workflow_dispatch`，首次真实通过前不得增加定时触发。

### TiDB

TiDB 消费链路 T4 复用同一个关系引擎 owner 断言，在带 `self-hosted`、`macOS`、`addp-online` 标签的专用 Runner 上使用固定官方 digest、无数据卷的 PD/TiKV/TiDB 三组件 Fixture 和永久 `engine_type=tidb` Engine Instance。Fixture 固定重建 5 行非空间 watermark 源表和同构空目标表；suite 必须经 Meta 扫描取得 ResourceLocator，以同一条 bounded watermark + upsert Transfer 任务验证 5/2/0 三次读取计数，并由 Manager、Develop 与临时 Query Service 对最终 6 行结果计算相同 checksum。上层模块只消费通用 ResourceLocator、SQLDialect 和 Provider，不得把 TiDB 登记为 MySQL 或增加 `tidb` 类型分支。临时任务和服务必须按捕获 ID 删除并确认 404；成功、失败和中断退出路径都必须执行 `down --volumes --remove-orphans` 并验证三组件容器零残留。该 suite 首次真实通过前只登记手工 `workflow_dispatch`，不得增加定时触发。

### KingbaseES

KingbaseES 消费链路 T4 复用同一个关系引擎 owner 断言，仅在带 `self-hosted`、`Linux`、`X64`、`addp-kingbase` 标签的受保护 Runner 上使用固定 SHA-256 的 V9R1C10 `V009R001C010B0004` 官方介质和 owner 正规 License。Fixture 每轮启动无卷 `DB_MODE=pg` disposable 容器，固定重建 5 行非空间 watermark 源表和同构空目标表，并输出 owner-only Engine 描述；通用注册器以最小权限 Provisioner Token 通过正式 System API 创建当次 `engine_type=kingbase` Engine Instance。suite 经 Meta 扫描取得 ResourceLocator，以 bounded watermark + `ON CONFLICT` upsert 验证 5/2/0 和最终 6 行 checksum，并由 Manager、Transfer、Develop、Service 经各自正式出口取得一致结果。上层模块只消费通用 ResourceLocator、SQLDialect 和 Provider，不得增加 `kingbase` 分支。成功、失败和中断路径都必须删除本轮平台库、Engine Instance、容器、镜像、临时任务、服务和 owner-only 凭据目录，验证零残留；License 和镜像 tar 不归档。首次真实通过前只允许手工 `workflow_dispatch`。

### openGauss

2026-11-03 用户确认本轮精确授权准备：仅在当次隔离部署中复用独立来源授权办理身份的既有十一项资格，普通消费 User 仍保持原十六项功能 Permission。准备阶段先扫描 `public.addp_online_consumer_source`、`public.addp_online_consumer_target` 的持久身份，再经 System 正式事实核对及命令为同一普通 User 签发这两张表的精确 `read` Grant；不授权 schema、其他表或个人环境。Grant 后必须由该普通 User 通过原过滤目录核验身份；失败即终止，不能改用管理员代读或跳过唯一项断言。准备进程退出后、业务断言开始前，清除办理与登记凭据，保留原 5/2/0、checksum、原生物理及清理断言。确定性标准入口为 `make test-opengauss-online-runner`，由既有 `test-online-runner` 聚合发现；修后 T4 仍须独立记录真实结果。

openGauss 消费链路 T4 复用上述关系引擎 owner 断言，但只在 GitHub Hosted `ubuntu-24.04` x86_64 profile 上运行。生命周期从固定 SHA-256 的 openGauss 6.0.6 LTS 官方介质启动独占容器，创建 `addp_online` 平台库、非默认 Tenant、最小权限消费 User、只含 `system.engine.create/read/execute` 的 Engine Provisioner 和临时 `engine_type=opengauss` Engine Instance。Business Fixture 只管理数据库并输出 owner-only Engine 描述，不调用 System API；System IAM owner helper 只创建身份和 Token，通用 Online 注册器使用 Engine Provisioner Token 通过正式 System API 注册并验证 Engine。Fixture 以 `public` schema 作为 namespace，使用 openGauss 原生 `MERGE` 推进相同的 5/2/0 watermark 数据集；Manager、Transfer、Develop 和 Service 必须通过与 OceanBase 相同的通用 ResourceLocator、SQLDialect 和 Provider 路径得到同一 6 行 checksum，上层模块不得新增 `opengauss` 分支。当次 Engine Instance 只随 disposable 平台库销毁，Token 和连接凭据只保存在不归档的 owner-only `runner.temp` 目录；Engine 注册后必须在进入业务断言前从进程环境清除 Provisioner Token 与数据库凭据，业务证据不得包含凭据。该 suite 在首次真实通过并确认构建身份、清理和零残留证据后，同时保留手工 `workflow_dispatch` 并登记每日夜间 `schedule`；定时事件只能选择 openGauss Hosted Job，其他 Online Job 必须显式排除定时事件。

## Transfer 仅新增 MySQL 同步

Transfer 仅新增 MySQL T4 使用永久 PostgreSQL 与 MySQL Engine Instance，并由专属复合 Fixture 管理两端物理表。真实 User 必须从 Console 页面选择源表和目标库、进入字段映射、通过正式“分析源数据并推荐精度”接口把无声明精度的 PostgreSQL `numeric` 收敛为不会截断当前值的 MySQL `DECIMAL(6,2)`，再以主键 `id` 作为唯一 watermark 创建任务。页面自动执行的首轮必须读写 6 行；Fixture 同时修改 `id=1` 并新增 `id=7` 后，用户从任务详情再次执行必须只读写 1 行。最终 MySQL 目标必须共 7 行、`id=1` 保持首轮值、`id=7` 为新增值且无重复键，以证明单字段水位只覆盖严格递增新增、不承诺旧记录更新。浏览器还必须断言任务配置的 `tie_breaker=[]`、目标 `upsert` 键为 `id`，捕获并删除临时任务且确认 404；Fixture 在全部退出路径删除两端固定表并停止两个容器。该 suite 只登记手工 `workflow_dispatch`，首次真实通过前不得增加定时触发。

## transfer-relational-sql-etl

Transfer 关系型 SQL ETL T4 `transfer-relational-sql-etl` 唯一使用 GitHub Hosted `ubuntu-24.04` x86_64 临时部署，不保留 macOS 专用 Runner 路径。生命周期复用 `scripts/utils/hosted-online.sh`，从零建立独立 Infra、非默认 Tenant 和最小权限测试 User；System-owned IAM helper 创建身份，独立 Engine Provisioner 通过正式 System API 注册当次 PostgreSQL、MongoDB、Doris、ClickHouse 与 MinIO Engine Instance，注册后清除 Provisioner Token；业务 User 不持有 `system.engine.read/execute`，只从 Meta 读取同 Tenant 引擎投影。Business Fixture 管理当次独占数据库容器、固定源表、源集合、写入拒绝目标及 tmpfs MinIO，并输出 owner-only Engine 描述，不调用 System API。数据库用户只能读取源表并在指定 schema 创建、管理自己的目标表。真实 User 必须从 Console 选择源表，确认单语言引擎只显示固定 `SQL` 而不提供 MQL、语言下拉或高级 SQL 编辑入口，通过基础构造器选择输出字段并配置两个参数化行过滤，再选择 PostgreSQL 目标位置创建 snapshot 任务。浏览器必须断言保存事实只有标准 `source.query` SQL statement 与类型化 parameters，其中 decimal 过滤值以字符串保存而不是 JavaScript Number；下一步字段映射只包含实际投影字段，并等待 Worker 读写恰好 2 行。Fixture 必须核对目标行集合、金额汇总和列顺序，以同时证明过滤、投影和精确参数绑定语义。临时任务必须通过正式 API 删除并确认 404。成功、失败和中断退出路径均销毁当次业务容器、Infra、平台数据卷及 owner-only 凭据目录，检查零残留；Engine Instance 与身份随平台库销毁。凭据不进入日志或 Artifact。该 suite 只登记手工 `workflow_dispatch`，首次真实通过前不得增加定时触发。

ClickHouse 夹具分阶段记录镜像拉取、容器启动、进程及 SQL 就绪、端口读取和样本初始化。就绪等待共用 240 秒预算，单条探针在 10 秒或剩余预算耗尽时终止。 SQL 探针返回 ClickHouse 的 `NETWORK_ERROR`（210）时，在同一预算内继续检查。镜像拉取、容器启动、端口读取和每条样本初始化命令分别在 300、60、10 和 30 秒终止。上述命令收到终止信号后有 5 秒退出时间，随后强制停止，并由原 Hosted 退出路径清理。原始诊断输出只写入当次凭据目录，归档仅保留固定阶段和退出状态。

### Manager 私有导入

同一 `transfer-relational-sql-etl` suite 在其他传输场景前执行 Manager 私有 Shapefile 导入。真实 Console 弹窗上传固定两点 ZIP，核对目标命名空间、CPG 编码、当前 User 的持久 `sync` 任务和 Transfer execution，等待准确 Meta 子扫描及资源树刷新。Transfer 是实际读写和血缘的唯一 owner；浏览器不复制后台导入 HTTP 路线。Business `manager-import` 独立核对完整 PostGIS 行值、点坐标与 SRID，不调用平台响应计算期望。

`manager-private-import.json` 使用 `addp.manager-private-import/v3`，包含两阶段 `addp.manager-private-import-browser/v1`：必须核对 source commit、当前 User／Tenant／Run ID、准确 Transfer／Meta UUID、当前发起 User 与真实父执行，以及非上传者启动同任务时的零读写拒绝和普通 User 直接 Inspect 拒绝。失败时经真实 Transfer 执行详情核对安全诊断；缺少任一页面或领域证明不得登记通过。上传一经接受即捕获 task／execution 身份，后续页面失败也须清理；后续其他场景失败不抹去已完成的独立领域证据，但不能登记完整 suite 通过。完整 suite 版本以当前登记为准。

完整 suite v16 增加私有导入初始 Grant 验收。浏览器按原预算读取同一 Transfer 执行的授权终态，签发后重新打开目标命名空间。普通上传者通过正式 Manager 预览读到两点，旁观者目录隐藏且预览拒绝。既有准备身份只查询与原执行和精确目标匹配的 `task_production` 历史，核对唯一 `until_revoked` 的 `read` Grant、当前接收者及 Meta 授权边界，然后正式撤销并验证历史、目录隐藏与预览拒绝。浏览器失败后使用已记录的原执行检查并撤回已签发 Grant，临时部署仍按原流程销毁。

导入完成后的刷新与 Monitor 导航顺序由既有 Manager 嵌入式 T3 延迟响应回归单独证明，Hosted 导入成功不替代该竞态回归。沿用 `make test-transfer-online-runner`、Manager 前端门禁和原 Hosted workflow；实际结果见[私有导入历史证据](../验收证据索引.md#manager-预览与私有导入历史证据)。

同一入口验证普通 User 经正式 Manager `/uploads` 上传一个 CSV 和五份 Shapefile 组成文件至独占 Business MinIO。MinIO 复用独占 tmpfs 生命周期，Provisioner 登记当次业务 Engine。等待上传响应中的真实 Meta UUID，核对 `source=manager`、当前 User/Tenant、准确 Engine、deep 深度和直接上传来源。

同一普通 User 在自动扫描完成后仍应看到空目录。独立准备身份只给当次 `transfer-upload/upload-check.csv` 和 `transfer-upload/points.shp` 签发有效期 15 分钟的精确 `metadata_read` Grant，复用现有事实核验和正式撤权命令。普通 User 的功能权限集合保持原样。普通目录和详情须返回两个相同身份的结构项。结束时撤销两条 Grant，并核对目录为空、两项详情均返回 404。签发部分失败或断言失败也执行撤权核验。

受控只读探针固定在当次 Hosted PostgreSQL，只核对与该扫描同一租户、引擎及执行时间范围内的持久事实。独立物理夹具读取六个对象的实际字节、SHA-256、大小、ETag 和修改时间。CSV 的 Meta 列与 storage 大小须为相等正整数，修改时间按同一时刻比较，ETag 原样相等。Shapefile 须只有一个 multi 逻辑项，大小等于五份实际对象之和，引用集合准确。`manager-object-upload.json` 按 `addp.manager-object-upload/v2` 绑定当次源码、Run/User/Tenant、Engine、上传响应、Meta UUID、授权与撤权、结构及物理事实。上传对象随当次 tmpfs 容器销毁，由 Hosted 退出路径核对零残留。

### 写入失败与证据边界

Transfer 的 `transfer-relational-sql-etl` Hosted T4 在同一普通 User／Tenant 下追加 Doris、ClickHouse 各两个合成失败场景，沿用现有 suite、生命周期、浏览器和 CI 入口，不复用个人开发部署。独占目标使用固定摘要镜像和随机回环端口，Doris 复用 Business 唯一 FE／BE 启动入口，在夹具实例开启严格写入并限制目标分区范围；ClickHouse 使用 CHECK 约束。四份 Python 生成的创建配置必须经真实 Go planner 纯解析校验，目标使用 database 父节点的 `parent_locator + name`，不得提交 `target.locator`；此跨语言回归纳入既有 runner、Go T1 与 CI 登记检查。1001 行源输入按显式顺序进入同一批次，先提交 1000 行，再因原生约束拒绝末行；另以末行非法 JSON 验证本批无新增行。两者均保留预置哨兵行，独立物理读取分别必须得到 1001 行与 1 行，不能用 execution 的 `records_written=0` 推断目标为空。每个任务必须为 failed、使用不同执行 UUID 且关闭自动扫描，目标 Meta 事实前后保持未扫描；同一登录身份在真实 Transfer 执行详情页核对安全诊断、终态和执行编号，并生成截图，禁止恢复原始 error_msg 或暴露运行时正文。提交标记仍由原生 T2 验证，专业 API 不为验收暴露私有 checkpoint。任务按当次所有权清理，容器／卷在成功、失败及中断路径销毁并核验零残留。runner 通过不计为 T4 通过，首次真实 Hosted 成功须另记证据。

写入安全诊断 v3 的原生门禁与 Hosted 验收分别认定：原生通过不能替代新版 T4，未进入四个 Provider 写入失败场景的前置失败不能计为 v3 T4 通过；新版 T4 必须在同一 suite 中核对安全原因码、可确定的写入列序号与声明类型、目标可能已改变标记及实际物理行数。历史结果与范围限制见[其他验收证据索引](../验收证据索引.md#addp-验收证据索引)。

各层的统一安全诊断断言见[关系型写入与安全诊断门禁](../Owner补充门禁.md#关系型写入与安全诊断门禁)。

### ClickHouse 二进制传输

复用当次 ClickHouse 和 PostgreSQL 夹具及原普通 User。ClickHouse 源表的 `Nullable(String)` 列以独立的 `addp:type=bytes` 注释行声明类型，样本为 `4100FF42`、`4142`、空字节串和 SQL `NULL`，另保留普通文本列。独立准备身份通过正式 Meta API 完成初始 PostgreSQL 扫描和 ClickHouse 精确源表扫描，仅为普通 User 签发两张源表的精确 `read` Grant。普通 User 通过目录读取定位源表和目标 schema，经 Gateway 创建并启动手动 `bounded snapshot` 任务，原有权限集合不扩张。任务读取原生表，批大小为 2，显式映射到新的 PostgreSQL 原生表。须按同一个执行 UUID 核对发起人、成功终态、Worker 首次 attempt 的开始与完成事件，以及两次各 2 行的进度。此独立段先取证，再执行现有私有导入、血缘和写入失败场景；写入失败专用目标仍须保持未扫描。

Business 夹具独立查询两端完整行集合，按 ID 比较十六进制、字节长度、空值标识和文本，核对 PostgreSQL 列是可空 `BYTEA`。任务定义经正式 API 删除并回读 404。准备身份撤销 ClickHouse 源表 Grant，再由普通 User 确认原源表读取裁决返回 403。业务容器、数据卷和凭据目录由现有 Hosted 退出路径销毁并核验。`clickhouse-binary-roundtrip.json` 绑定当次提交、Run、User/Tenant、源扫描、Grant 与 Transfer UUID，记录批次、物理值和清理结果。该收据与完整 suite 及基础设施清理分别认定。

创建二进制任务前，复用 Transfer Hosted 连续执行场景的只读检查，等待当次租户的 Transfer Security 保护投影完成初始化。Hosted 准入、Manager 就绪和 Worker 注册分别有独立证据。投影等待失败时停止场景，不创建任务、不更改保护状态。

### 字段级血缘验收

MongoDB 源集合由独立准备身份通过正式 Meta 精确扫描建立目录事实，并通过 System 的精确授权事实确认 `transfer_fixture.activities` 已持久化。普通 User 按集合目录路径查询 Meta 单项，签发前必须返回 404；复用 `ExactRecordGrants` 签发精确 `read` Grant 后，查询必须返回 200 且集合指纹与准备时的事实及 Grant 一致。读取观察固定使用普通 User 已具备权限的 `manager-preview` 检查，签发前与撤权后返回 403，签发后返回 200 并包含观察时间。两次 MongoDB 到 PostgreSQL 传输各核对三行。Grant 覆盖后续编排和浏览器的来源读取，在退出时精确撤销，并核对同一目录路径返回 404、内容读取检查返回 403，以及原 MongoDB 传输任务被拒绝且零读写、不提交扫描。授权部分成功或后续场景失败也执行撤权。`mongodb-source-access.json` 独立登记授权、传输与清理证据，未完成的检查不计为通过。完整 suite 报告从 `v17` 起登记该项。

普通 User 的字段图验收核对可见端点、结构哈希、观察状态与真实 execution 摘要，并检查转换字段及任意 evidence 已被投影隐藏。`direct/derived` 通过当轮独占平台库的受控只读事务核验，查询精确绑定当前 User、Tenant、执行 UUID、两端 Engine/DataItem/字段及结构哈希，并与同一不可变 observation 的转换类型比较。历史图同时限定实际 `as_of`。原生表、SQL 查询、MongoDB、编排、历史结构和宽表复用该取证路径，浏览器只读取普通用户图。

关系型 SQL ETL 和 Continuous Hosted 场景通过普通 User 的 Meta API 核对同级 DataItem 与祖先节点的可见身份。扫描基线及后续比对使用当轮独占 `addp_online` 的只读事务，以正式响应中的 Tenant、Engine、DataItem 身份限定同级项和祖先链，核对扫描时间、深度、状态与同级项统计。查询绑定当轮 Infra PostgreSQL 容器，原始查询结果仅用于内存比对，收据只保留断言结果和必要的身份。目录、预览及授权拒绝继续由原普通 User 请求验证。

字段血缘仍归同一 `transfer-relational-sql-etl`，普通 User 无管理员角色，具有 `meta.lineage.read`、`manager.data_item.read`、`manager.content.read`，不授 `catalog.entry.read`。复用本节前述授权、只读取证与隔离部署；具体矩阵如下，补充边界集中见下表，不逐轮重复。

| 链路 | 独有业务断言 |
| --- | --- |
| 原生表与 SQL | snapshot 字段改名、decimal 精度转换、同目标 replace 映射更新及两跳搬运；Meta 自动采集真实成功 execution，核精确字段／结构、direct／derived、旧入边关闭和两跳不串字段。Provider 可完整证明的单来源 SQL 需记录映射；opaque、unresolved 或不完整证据声明 unavailable，不能伪造同名来源。 |
| MongoDB → ODS | 独占 tmpfs MongoDB 7.0 与 PG，MongoDB 登记账号只读源库。透明 MQL `$project` 六项显式映射，别名仅用于字段映射，冻结结构保留 `title.date`、`title.level`、`leader.personid`、`leader.userInfo.nickName` 精确点号名。同任务执行两次，目标身份稳定、仅最新成功入边活跃；每轮等自动元数据／血缘，不手工补扫或 collect。物理核六列完整行集，页面切日期／昵称聚焦并展示跨引擎来源。 |
| 编排 ODS → DIM → DWD | Develop／Orchestrator／Monitor 同提交预检；只补两模块任务创建／读取／执行／删除、Develop 数据读写、Monitor 执行读取、System 执行授权权限。夹具先建并扫描空 DIM／DWD；同一编排连续两轮执行 ODS Transfer、DIM relation、DWD JOIN。日期从 MongoDB 经 ODS／DIM 三跳到 DWD，昵称改名为 direct、强度表达式为 derived。Monitor 核每轮三子执行的实际 owner／任务／父 UUID；Develop 只读安全资源引用、顶层 outputs 和行数，字段映射／hash 取 Meta，URI 按不带选择器 item_id 的规范路径比较。物理核 DIM 三行、DWD 两行及真实日期类型。 |
| DWD 结构演进 | 同夹具真实改昵称列、date→timestamp，正式扫描使旧关系失效后，第三次执行原编排，不增定义或权限。浏览器只展示第三轮新结构；v5 留两代结构和历史取证，物理核新列、timestamp 及完整行集。四图 unavailable、stale／closed 和历史时点的精确要求见下表。源／ODS／DIM hash 与身份须稳定。 |
| 宽表 | 500 列、2 行源经两跳搬运；只扫描初始源，目标和血缘自动形成。整表请求不传 limit，核 1500 字段节点、1000 活跃关系、三表 hash 与两次 execution；页面首／中／末搜索聚焦、适应窗口、拖拽和自动布局，物理核两目标全部列／类型／行多重集合。字号、几何与采样口径见下表及[性能采样](#性能采样口径)。 |

浏览器登录并核 User／Tenant 后才监听业务错误，登录前 refresh 401 不算业务请求，之后的 401／403／503 不得忽略。Manager iframe 仅发一次 `subject_kind=data_item&granularity=field` 整表查询，切字段只本地聚焦，不请求 Catalog 摘要。自动采集不能由手工 collect 代替，编排父执行不生成伪资源边，第二轮不保留首轮活跃边。

清理集中执行：三个 PG 原生任务、MongoDB 查询任务、SQL 任务均以 Run ID 命名；两个 Develop 任务和一个编排定义经正式 API 删除、回读 404，源集合／表、六个目标及其他矩阵物理表随 Business 夹具清理。新增依赖登记统一 Hosted 清单，不访问本地业务容器或授消费 User 基础设施管理权。完整物理核验在全部浏览器／多来源场景结束后执行，详见下表。确定性入口为 `make test-online-runner`、`make test-platform`，T4 为 `make test-online ONLINE_SUITE=transfer-relational-sql-etl`；宽表等扩展无真实 Hosted 结果不计完成，首过前不加 schedule。

现行场景还应满足以下补充约束；字段值来源、schema snapshot、租户授权及 `unavailable` 的定义仍以[数据血缘能力规范](../../addp数据血缘能力规范.md#61-字段级首期契约)为准。

| 场景 | 必须核对的边界 |
| --- | --- |
| 自动扫描与采集 | 等待目标 DataItem 和当次字段证据自动收敛。命名空间锁可能使额外手动扫描跳过范围，即使扫描执行成功也不能证明目标已经入库；不得用手工补扫或 collect 代替自动链路。 |
| 编排重跑 | 两轮各自的父、子 execution UUID 必须不同，字段及资源边只能引用实际 Transfer / Develop 子执行。按规范资源路径核对 ReadSet 与 relation 参数；不从 Orchestrator 依赖生成来源边，不从安全执行投影读取 operations 或 schema_snapshot。 |
| 结构演进 | 将 DWD 的 `person_nickname` 改为 `person_display_name`，`activity_date` 从 date 改为 timestamp without time zone；同一编排和任务定义完成第三轮；正式扫描后、重写前，四张当前字段图均为 unavailable、各只保留根节点且无来源边，旧字段名查询为 404。旧 hash + 第二轮父执行完成时间的历史图保留原字段、原 direct 日期及第二轮证据，DWD 入边在第三轮前为 stale、之后为 closed，观察不晚于历史查询时点；第三轮只引用当次子执行。 |
| Transfer 多来源查询 | 在原生源和已完成 replace 的映射表上声明两个 `query.inputs`，真实 CTE / JOIN / UNION ALL 产生四行结果。每个原始来源结构分别冻结，同一结果字段的多来源记为精确 derived，只有 JOIN / 行筛选作用的输入不生成字段值来源边；三层冻结结构、目标完整行集合和列顺序必须一致。 |
| 布局与曲线 | 820×667px 的真实三跳图适应窗口后字段行完整可见；表卡向左、向下各移动 30px 后，曲线端点偏差不超过 2px。几何取证等待实际绘制帧，不能读取适应窗口之前的旧帧。自动布局、搜索、收起 / 展开、Console iframe 原生全屏进出与字段精确聚焦保持有效。 |
| 500 列宽表 | 两行源、两跳搬运形成 1500 个字段节点、1000 条活跃关系；逐项核对三张表的结构 hash 和两次真实 execution。两张目标表各 500 个非空 bigint 列，完整物理行多重集合一致。四表以内适应窗口保留可读字号；宽表概览不要求同时看清 500 行，重新定位字段必须恢复至少 11px。 |
| 独立验证与清理 | 浏览器与多来源场景全部结束后，由标准 Hosted 生命周期统一验证 ODS / DIM / DWD、多来源目标及宽表的完整物理行集合和类型；浏览器不提前调用同一验证入口。所有本轮任务和编排定义经正式 API 删除并确认 404，业务容器、Infra 与凭据目录零残留。 |

字段图首次断言不匹配时，验收脚本保存有界的脱敏诊断，并在收敛或超时后更新终态。诊断绑定实际查询的 DataItem 和字段，保留首次与末次观察中的节点、边、转换类型、执行 UUID 和权限过滤标志，以及预期边集合。字段名仅保留该断言声明的名称，转换类型仅保留固定枚举，执行标识仅保留规范 UUID。数组最多各 100 项，诊断不复制原始响应、任意 evidence、表达式或样本。诊断只说明当次断言差异，完整验收结果继续由 suite 和清理收据共同判定。

MongoDB 夹具必须等待容器 PID 1 成为正式 `mongod`，再进行认证及 ping 探测；[官方镜像入口](https://github.com/docker-library/mongo/blob/master/7.0/docker-entrypoint.sh) 在初始化阶段会启动临时实例、创建账号，再关闭临时实例并执行正式进程，仅认证及 ping 成功不能证明切换完成。两项就绪条件使用同一个有界等待；数据与最小读取权限只初始化一次，失败时不重试部分写入、不发布引擎描述文件。原始启动及驱动错误只留在退出即清理的凭据目录，CI 日志仅输出固定错误分类和非秘密容器状态。

#### 扫描调用链与读取隔离

同一 Transfer Hosted suite 复用既有上传者和同 Tenant、持有完全相同业务权限的另一个普通 User，不新增角色授权。正式对象上传后，上传者须在 Monitor 详情与执行树中读取同一实际 Meta UUID，树只有该扫描且无虚构父执行。有界私有导入后，上传者须读取真实 Transfer 父执行及其唯一 Meta 子扫描；另一 User 可读持久任务的父执行及仅含父执行的过滤树，但不能由父读取权取得该一次性扫描。Meta 专业详情与 Monitor 详情、树、事件四个入口均须返回 404，响应仅含错误字段，不能用缺少 Owner 读取权限的 403 代替身份隔离证明。执行树不得截断、重复、丢失或混入其他 UUID；详情与树中的扫描投影保持一致。

`scan-trace-visibility.json` 使用 `addp.scan-trace-visibility/v1`，绑定源码、Run、两位 User、原有权限、实际父子 UUID、各自可见节点及四个拒绝入口。收据保留公开执行 DTO 中身份、来源、状态与直接父关系的最小投影，以及每个拒绝入口实际返回的 HTTP 状态与响应字段名，不保存任意 metadata、配置或凭据。仅两条链路都通过后保存独立收据，后续场景失败仍保留该证据。Monitor 链路与读取隔离从 v14 起纳入完整 suite，ClickHouse 二进制传输从 v15 起纳入。标准入口继续为 `make test-transfer-online-runner`，真实验收仍走既有 `transfer-relational-sql-etl` Hosted。现有登记检查锁定新版报告和隔离断言。

#### 性能采样口径

宽表交互性能采样沿用同一 Hosted suite，在同一登录上下文的新页面中读取真实 1500 字段节点、1000 条关系图；该页面不安装用于几何取证的 Canvas 观察器。首、中、末字段分别从按钮的真实点击事件计时，到所选字段以至少 11px 字号居中绘制后、下一稳定动画帧结束，并保存 CPU 采样。结果写入 `transfer-wide-native-focus.json` 与三个 `.cpuprofile` 文件，每个页面仍只加载一次字段图。该计时排除字段搜索、Playwright 定位等待和详细几何记录成本，但包含轻量绘制探针及 CPU 采样开销；不能与原有包含导航、请求及自动化验证的总时长直接计算加速比。既有整图完整性、精确映射、拖拽端点与清理断言仍在原验证页面执行。

首次字段图绘制和自动布局复用同一轻量采样实现。首次绘制从字段级切换的真实事件开始，使用浏览器 Resource Timing 中对应字段图请求的 `responseEnd` 分离网络与响应处理，记录响应完成到可读字段稳定绘制的时间；不将 Console 导航或 Playwright 等待计入此段。自动布局从工具栏按钮的真实点击开始，到布局按钮恢复可用且全图下一稳定绘制帧结束；全图适应窗口后的字段字号仅记录，不套用字段聚焦的 11px 要求。两者只观察当前画布实际可见字段，不将图引擎在离屏位置进行的文字测量算作完成。计时与 CPU 采样分别归档为 `transfer-wide-native-render.json`、`transfer-wide-initial.cpuprofile` 和 `transfer-wide-layout.cpuprofile`。该采样不重查字段图、不安装详细几何观察器，也不改变产品布局和 API。

几何验证、包含导航 / 请求 / 自动化等待的端到端时间、原生点击采样和本地受控夹具是不同口径。只有相同环境、相同采样口径的结果才可比较；本机与 Hosted 不直接计算性能倍率。CPU 累计归因可能嵌套，不能相加；采样会话总时长不等于原生点击耗时。单轮独占 Runner 的观察值包含轻量探针和 CPU 采样开销，不构成固定延迟目标或性能保证。

### 部署、身份与事件闭环

独立 GitHub Hosted Linux x86_64，复用共享 Hosted 生命周期，仅手动调度，真实首过前不加夜间运行。Business 创建业务 Kafka、logical WAL PostgreSQL 源／目标和确定性数据，不拿 Infra Kafka 当业务源或复用个人容器。普通 User 经 Gateway 控制任务，正式 Worker 执行；独立 oracle 核 snapshot、upsert、delete。System-owned helper 经正式 IAM Service 建 User／Role／Session，不改产品 IAM。Worker 强退只能 pin 当次 PID，恢复走标准启动入口，不增加产品故障参数、测试 Supervisor 或受控授权 Gate。

Transfer／Monitor 核 started、累计提交进展、唯一终态与恢复链；Owner 不可用时失败关闭。正式撤权前，Owner／Monitor 各读至少两页并留首游标；撤权后旧 Token 为 401，同一 Monitor-only User 重新登录持旧游标仍被两端拒绝，Monitor 列表／总数均零。同租户无 Owner 读取权与跨租户身份也为空／零。证据只留身份、页数、事件数、游标与封闭断言，不含配置、业务值、原始 checkpoint、内部 Worker／租约或完整响应。此项不验证 30 天清理、180 天概览删除、其他 Owner 或 Kafka HA。

持续写入分页沿同一 Kafka 任务：Monitor 每页两条读首批后追加业务消息，等目标和 Owner 证实提交，再续原游标；拼接结果须等于追加后两端从头读取的完整顺序。真实 Console 核自动续页、手动刷新、行数，进展确认后才做原 Worker 失联，页面收敛到原执行失败诊断及唯一终态。合成 Meta 一次性执行的 1000／1201 条分页、截断和展示上限独立认定，见[大量事件分页与截断验收](../../tasks/执行监控.md#大量事件分页与截断真实入口验收)。

### 实故障告警与通知

产品规则不在本页重复维护，统一见[捕获失败](../../tasks/Transfer同步执行.md#cdc-捕获持续失败告警2026-11-14-已确认)、[不可恢复风险](../../tasks/Transfer同步执行.md#cdc-任务不可恢复风险告警2026-11-13-已确认)、[性能规则](../../tasks/Transfer同步执行.md#cdc-任务持续性能告警2026-11-14-已确认)及[通知契约](../../tasks/Transfer同步执行.md#租户告警通知与渠道投递)。本场景的故障注入与 oracle 如下。

**捕获失败。** 正式暂停目标消费，仅暂停当前 generation 的 Connector，推进中的明确失败样本累计至少 60 秒才开 warning。确认后短暂停本轮独占 Connect，unknown／过期缺样保持确认、LastObservedAt 和零恢复通知；解除暂停、确认仍失败，再正式恢复 Connector，以新鲜 healthy 关闭原事件。核 opened／resolved 两条 HMAC 实收和 delivered 审计。退出解除故障，不恢复目标消费、不操作个人服务或源槽，随后继续风险／重建；捕获 warning 不代恢复丢失 critical。

**不可恢复风险。** 仅该场景给消费 User 增告警读取／确认、Webhook 目标创建／读取／删除及投递读取，不扩大共享夹具权限。暂停消费并添源事件，Infra owner 按精确 generation 截断自有消息主题，使 committed 早于最早可恢复位置；删除本 Connector，核槽不活跃及 publication 单表归属后删槽，两类 critical 各唯一打开。短暂停独占 Business PG，新鲜缺样保持确认、最后观测时间和零恢复通知，退出先解除暂停。正式 Stop 关闭旧代次，再以变更后真实源表三字段新建替代任务／新目标，核完整 snapshot、正常槽／WAL／延迟／缓冲后停止清理。Stop 不可逆，不重启旧任务；新任务健康不是遗失事件自动恢复，不造 WAL／磁盘压力。

**性能故障。** 同一任务三条正式 warning，可选 backlog_threshold="256" 是 offset 距离而非消息条数。目标表事务锁阻止提交；独占 Connect 临时 CFS quota3000／period100000（0.03CPU，整数百分比规避 systemd 取整），至多 60000 条、每条 label7000 字节的源记录，消费批次 1000；Connector `max.batch.size=64`、`max.queue.size=128`避免大批停顿。只认不同新鲜样本：有消息且提交不变 180 秒、计数持续推进且延迟>60 秒满 180 秒，分别触发默认规则；积压>256 满 300 秒才开可选规则，读回阈值／持续时间。保留活动样本、部分告警与窗口，不以 Pause、假时钟／JMX／Owner 事实制造停滞。

三条确认后正式 Pause，连续 32 秒核消费两规则暂停评估、同一事件／LastObservedAt 不变且无关闭通知，捕获延迟独立评估。Resume 记录新 execution，后继风险沿它核自动恢复。再暂停自有 Connect／消息代理，分别取得新鲜 unavailable（不要求串行探测有效期重叠），三规则 unknown、事件／LastObservedAt 不变且无关闭通知。解除故障、恢复 Connector 配置、释放目标锁和 CPU 限制后，消费归零、延迟<=30 秒满 60 秒、积压严格<128 满 60 秒，各以新鲜样本／恢复窗口关闭原事件，核三类 opened／resolved 共六条签名实收和 delivered。

清源记录后只收清理完成之后的新鲜零积压；目标按主键排序取最多三行，数据库内核精确两行、三字段和原值，仅返回布尔值，空值按原 psql 文本投影，不读回未清大行。风险段绑定正式 Pause 后任务 `last_execution_id`；若故障引发自动恢复，原 execution failed、新 execution 的 `recovered_from_execution_id`精确指向原值，task／generation 不变，不能改旧终态。

**触发前 Pause／评估器重建。** 同一性能故障先取得至少 30 秒但未满阈值的真实 pending，三规则无 incident／生命周期／投递／签名接收。Pause 后两消费规则 inactive、trigger_since／recovery_since 清空，持有期间继续为零；捕获类不随 Pause 清零。Resume 仅接受请求后的全新 trigger_since，180／300 秒临界前必须有无事件／投递实证，完整窗口后才触发，不增任务／权限／时钟替身。

重建变体在暂停清窗后只终止本轮 Monitor，pidfd 证旧进程退出，经 `scripts/dev/start.sh -monitor` 起新进程；PID 不同、构建二进制摘要相同、环境无验收 Token。暂停任务的 execution／generation 不变，新进程下一次评估 reset_at 晚于重建完成、窗口／通知仍空，然后才 Resume 累计。只证明暂停清窗跨重建，不要求重建删除有效窗口，不把停机算新窗口。两次 Resume 经原 User／Gateway 各发一次、独立 HTTP 等 60 秒，其余客户端时限不变；失败保留未知结果不重试。恢复后三性能事件最多等 600 秒，缺样仍中断窗口并重新累计，临界前零事件与完整同一新窗口不放宽。

窗口与零计数由 Infra owner 沿精确容器／只读 PG helper，在同一 SQL 快照按 Tenant／Task／generation／规则／目的地返回安全窗口和计数，对照正式 UserAPI 和签名端；不跨请求误判临界点，不读凭据或开调试口。复用 pending 观察替代预热空等，场景／分发预算 1650／1700 秒，覆盖重建及缺样重计；原轮通过不追认新增变体。

**告警页面。** 共用同一任务／generation、故障与签名目标；每阶段重新核普通 User、页内分页及正式 API，页内找到本任务，不增权。不重发未知操作，Runner 移除对应 API 确认，每事件只由页面确认一次；仅安全回执，不归档目标地址整页截图或登录输出。

### 删除、扫描与清理

Kafka 删除使用原身份／总预算，分组认定：

| 组别 | 唯一操作与后置条件 |
| --- | --- |
| 硬终止拒删 | 保留原恢复断言；只读 PG 证明仅旧 invocation 未确认退出且尚无删除登记。经 Gateway 一次 DELETE，独立 HTTP60 秒覆盖现有 45 秒 runtime stop；要求 502／503、任务仍可读、未确认会话／外部操作登记不变。失败回执分删除前事实、请求／响应、定义读回、删除后事实，仅闭集 transport_timeout／transport_unavailable／invalid_response／contract_failed 和已收状态；不存异常／正文，不重发。该任务单独记账留外层部署销毁。 |
| 正常退出删除 | 另建自有任务／独立目标，同业务输入经 Worker 真实写 DLQ，正常 Stop 确认会话退出后正式删 200、回读 404、精确 Infra DLQ 缺失，原授权历史仍可读。原生只取证，不改会话、任务、Kafka、围栏或权限。 |

专业 DTO 的 `initial_authorization`仅接受既有状态／受控 code，拒 Grant 引用、领取进度、凭据及附加字段；Monitor 通用投影无此字段。业务首败与清理失败分别保留，后者不覆盖前者；除已证实拒删的硬终止任务外，均等终态、正式删除、回读 404。两组及其余领域清理、外层零残留完成才可整套通过。

末尾 bounded 定时任务须自动 deep 完成、精确字段与物理行集；`metadata_scan.basic_execution_id`、deep UUID、生产 UUID 三者不同，basic／deep 均成功、继承原定时人类来源和直接父关联，另一 User 两扫描均不可读。关自动扫描、仅 basic 或仅受理 deep 都不算通过，不降为 basic。

finally 恢复／清除规则、临时记录、锁会话、Connector 配置、CPU 配额及暂停状态。CPU 用 quota=-1 且读回 cgroup `cpu.max`，不能用无更新语义 `--cpus 0`；Connector 凭据只私有 stdin。逐项记录领域清理与外层应用／Business／Infra／私有凭据清理；领域拒删留存不能写作零项，外层零残留独立证明。记录不保存业务值或凭据。

### continuous 治理与位点恢复试点

本节是[continuous 领取与会话交接](../../tasks/Transfer同步执行.md#continuous-领取与会话交接)的待实施标准。先在隔离部署用正式 Worker 和**业务 Kafka → PostgreSQL** 覆盖以下三个窗口，每个窗口独立制造中断并接管。按分区记录同一批数据在故障前的已提交位置、业务目标行、目标应用账本、Infra checkpoint，以及接替者首次读取的位置。须能证明实际中断落在指定窗口。

| 注入中断的位置 | 接替者的起点 | 通过条件 |
| --- | --- | --- |
| 目标事务提交前 | 批首的已提交 `next_offset` | 未提交的业务写入与账本均回滚，Infra checkpoint 保持批首。接替者重读该批，提交后业务行、账本和 checkpoint 均与预期批末一致。 |
| 目标事务已提交，Infra CAS 尚未成功 | 同一批首 | 业务行与目标账本已到批末，Infra checkpoint 仍在批首。接替者实际重读该批，目标账本吸收重复记录，业务效果不重复，随后 CAS 推进到批末。 |
| Infra CAS 已成功 | 批末记录之后的 `next_offset` | 目标数据、账本和 checkpoint 均已提交。接替者从该位置消费下一条可区分的消息。旧 token 的迟到 CAS 被拒绝，旧批次无法覆盖目标端的较新结果。 |

在同一 Kafka 试点分别核对以下治理和恢复行为：

- 运行任务 A 并预留空闲槽，另准备具备业务领取条件的 B。分别中断企业治理到 System、System 到 Worker 的链路。确认到期后 B 仍 pending，A 保持原 execution 和租约，且可提交新批次。仅恢复连接不能领取 B，新确认到达后才能领取。另在同一轮第一个 `ClaimNext` 发出后、第二个发出前撤销资格，核验第一笔的数据库结果及第二笔未发起。
- 分别正常退出与强退持租约的 Worker。核对正常退出已关闭 runner、旧 execution 的 `worker_shutdown` 及失败计数未增加；强退时没有停止确认，过期前不能接管。允许两个合格 Worker 同时争用，最终只有一个新会话，恢复记录关联原 UUID，token 递增，任务 `desired_state` 未被退出改写。
- 通过运行失败与租约过期验证指数退避、上限和熔断。反复断开与恢复治理，核对同一 pending recovery、连续失败数、`recovery_not_before` 未被重置。冷却到期但无资格时保持待领，有资格且实际领取后才进入 `half_open`。验证成功提交 position 后重置连续失败状态，并保留本次恢复审计。用户 Pause、Stop 或 schema 阻塞期间不能因治理恢复而重启。

**第二阶段使用 PostgreSQL CDC。** 初始快照完成后固定本任务的 capture generation、源端 slot/publication、Connector 及其数据 topic。在 Worker 交接期间向源表写入可区分的增删改，分别核对 Connect 捕获位点和 Transfer 分区 `next_offset`。允许捕获继续推进；新 Worker 使用原 generation、原捕获资源和新的 execution，从 Transfer 已提交位置恢复目标应用。核对最终目标行集、目标账本和 checkpoint 连续推进，确认没有重新拍快照、重建 generation 或执行 CDC Stop 清理。LSN、Connect offset 和 Kafka group offset 均不能代替目标应用的恢复起点。资源身份按本节既有取证范围在进程内核验。

本地与 Compose 分别用原入口确认 System 注册、停领及重新注册后恢复领取，无需企业治理凭据。精确截止时刻和同轮两次领取可用可控时钟及调用记录验证；三个提交窗口和 CDC 交接须用真实数据面验证并分别留证。既有 Hosted 收据和 runner 测试不计作本试点通过。

## FTP 普通 User 消费（ftp-consumer-flow）

**授权规则与证据版本。** 现行直接授权见[授权上下文规范 5.5.5](../../addp授权上下文规范.md#555-直接授权业务批准与明确交接)，不再设置逐 DataItem 直接许可；来源并集、撤销与源 Deny 退役见[访问规则生命周期](../../addp授权上下文规范.md#553-责任变化与访问规则生命周期)及[System IAM 迁移说明](../../../../system/docs/IAM数据模型与迁移规范.md#持续节点-grant-与源-deny-退役2026-11-02)。当前 FTP runner 已改用直接 Grant 请求，但仍请求旧源 Deny Permission、调用建立／释放接口，并保留相关回执断言；下文的 Deny、解除和同目标有效 Grant 唯一性要求属于尚未对齐的旧版场景，不能作为当前操作指引或新模型通过证据。历史固定版本、失败、清理结果及各格式独有断言继续保留；完成标准入口适配并取得新版本真实 Hosted 结果前，不计当前授权链路闭环。

### IFC／3DS 快显扩展验收（实施中）

**IFC 固定 Linux 原生 profile。** 在同一已核标签、Run ID、镜像及默认入口的 Model3D 产品容器，给实际实体挂外部 HTTP 图片及绝对 FIFO，不换转换器／options。真实 IfcConvert 预算内完成，HTTP 哨兵连接和所有方法调用零、FIFO 无写方仍完成，输出无图／纹理且盒体几何通过；记录真实二进制 hash／version，不拿下载包 hash 代执行文件 hash，清临时目录／哨兵线程。仅证固定几何和两种引用，不代表任意 IFC 外部资源支持，也不代 FTP 授权／页面。

### OBJ／MTL 精确组成扩展

同一 `ftp-consumer-flow` 入口将三个来源各扩展一个静态 OBJ profile，不新增 suite 或消费 Permission。固定样例必须含两份同目录 MTL（文件名含内部空格），两者分别引用子目录中同名、异色的 PNG；主文件、两 MTL、两 PNG 构成一个精确授权 DataItem，源 ZIP 必须保留这五个相对成员及逐文件原字节，不能按 basename 合并。基础识别与执行前重核采用 `composition_complete/material_libraries`；不能使用旧 deep 猜测路线，也不能把 MTL 伪装成贴图。嵌套 MTL、链接及不完整声明拒绝，图库限定 PNG/JPEG，深度几何摘要不修改组成事实。

页面必须分别生成并渲染两种颜色、缓存重开且不新增执行；GLB 独立检查两材质与两三角形绑定、UV、六顶点、2×1 几何尺寸及两份嵌入 PNG 的像元和源字节。仅修改一份 MTL 的图片声明、保持主 OBJ 不变后，完整 basic 重新扫描必须改变边界，旧 Grant 拒绝；后续新 Grant／旧 Deny、解除恢复、旧产物边界隔离、撤权及任务定义／成果删除复用既有生命周期矩阵。FTP、NFS、MinIO 各自留证，不用 Runtime 单元或单来源成功替代完整 T4。原 Manager 多格式 suite 的 MinIO OBJ 和 DAE 夹具须同步使用同一精确批准入口，以保持既有消费者可运行；物理样例与通过范围仍按各自报告区分。

### 模型原始读取授权收敛与 STL 三来源 profile

模型源下载验收必须点击 Manager 的实际下载按钮，核对其当前 User Bearer、无 Cookie／ticket、HTTP 200、浏览器保存成功及建议文件名。归档字节必须来自该次浏览器实际保存的文件，再与独立的固定源文件逐字节核对；完整组成 ZIP 须逐一核对原始相对成员及字节。HTTP 响应用于核对同一次请求及附件头，不能把浏览器调试接口捕获的空响应体当作实际下载内容，也不再额外调用 API 替代保存文件。403／401 或取消不得触发文件保存或成功提示。下载回执必须包含实际按钮、认证请求、已读取保存文件及文件名证据，缺失时拒绝计为页面通过。

同一 suite 在每个来源的批准前、完整组成 Grant 生效后、最终撤销后，逐一请求 `storage-stream`、`storage-assets` 与 `downloads/file`。主文件和每条已确认依赖均分别证明：批准前与撤销后为源权限拒绝且无内容字段；批准后流／资源出口逐字节匹配固定源文件，逻辑下载匹配完整组成，不借原来的终态执行授权或 Resource Ticket。工件中的 `raw_source_reads` 保留三阶段的准确出口、格式、原路径、状态及获准字节摘要，不保存凭据或拒绝响应正文。System／Manager T1、T2 另证明 Engine 版本变化、组成不完整、属性查询与打开之间撤权、服务不可用及 Resource Ticket 均不能变成源读取 Allow；非模型出口保持原有范围。

STL 首版沿同一 FTP／NFS／MinIO 精确组成、执行授权、受控暂存和发布链迁移，不新建 Runtime 算子或任务类型。使用仓库固定 ASCII 单 solid 三角面，Meta basic 必须提交 `format_info.stl.composition_complete=true` 和唯一必需 `model` 主 ref，不以 deep `scan_complete` 补造资格。生成前重核实际源结构，并将同一份已核验字节暂存；该阶段模型总量限 64 MiB，超限明确拒绝，不改走目录复制或旧挂载路径。

三个来源各独立证明：生成前的基础 STL 页面通过当前 User Bearer 获取原字节、无 Cookie／ticket、无转换执行并实际渲染；随后正式页面生成、发布的 GLB 实体渲染与重开缓存复用、授权撤销后缓存及再次生成拒绝、任务定义删除保留已观察执行历史、独立成果删除和所属暂存清理。GLB 必须自包含，无外部 buffer/image URI、无 image/texture 引用，允许转换器生成默认材质；物理 oracle 核验唯一三角面的位置、索引覆盖、场景实例变换后的实际几何和有限 bounds，不以顶点数或页面状态替代。来源未声明的单位／坐标系不得反写为源事实。ASCII 多 solid、任意 STL 文件与超限转换均不由该固定样例通过而追认；格式严格解析矩阵由 p82 负责。Hosted 的排队或本地 runner 单测通过不计真实 T4 完成，实际固定 SHA、工件和结果另入证据索引。

### NFS／MinIO IFC／3DS／DAE／OBJ 精确组成 profile

同一 `ftp-consumer-flow` Hosted 入口必须分别执行 FTP、NFS 与 MinIO 三个来源 profile，使用不同 Engine、独占源目录及独立工件目录；NFS／MinIO 结果分别保存在最终报告的 `nfs_profile`／`minio_profile`，不能复用 FTP 的读取或 GLB 证据充数。NFS 夹具仅在独占 Linux Hosted Runner 使用既有 NFS lifecycle 创建只读导出，退出删除导出与自有目录，不启动或更改个人开发机的 NFS 服务。`make test-common-nfs-integration` 在该夹具上验证普通文件 Facts、完整和范围读取，以及 Catalog／Facts／内容共同拒绝根内链接、根外链接、目录链接和 FIFO。

NFS 来源由 Provider 读取，Runtime 仅收受控暂存、不接宿主路径；其余沿[共同验收矩阵](#ifc3ds-快显扩展验收实施中)，Deny 缺口仍按篇首处理。三来源及生命周期各自成功才计整套通过，单测／排队不代 T4。

MinIO 用对象原生路径逐项确认主文件及 PNG/JPEG 组成，DAE 覆盖桶根与嵌套前缀，deep 摘要不能补造／覆盖组成。四格式沿共同矩阵；DAE／3DS／OBJ 各自验证组成变化及旧产物隔离，OBJ 只改 MTL、不改主 OBJ。旧 Deny 反例不当现行指引；新格式独立留证，不由缺该格式的历史 T4 追认。

自包含 GLB 在现有 `ftp-consumer-flow` 三来源 profile 中单独验收，不进入原五格式生成／缓存／成果删除列表。必须证明 basic 唯一主项、批准前与撤权后三个原始出口 403、批准后源字节相同；同名源改为合法 GLB2 外部 URI 时不重新扫描也拒绝，恢复后可读。页面必须直接渲染固定三角形、使用当前 User 请求无 ticket/cookie、Range 对应同份文件、真实点击下载并核对保存文件及原始名称，且没有模型转换请求。原五模型完整场景继续运行，不以 API-only 证据替代按钮与渲染。

模型原始下载的 Hosted 证明必须分开记录并验证三层名称：响应头解码原名、真实页面 Blob 下载链接的 `download` 属性、浏览器建议保存名。前两层与源名称逐字相同；第三层按已实际复现的固定 Chromium 样例验证，首空格 GLB 仍保留原样输入，建议名 `_原名 %.GLB` 作为浏览器观察记录，不能归因于平台改名。实际保存文件须在名称断言前留存，单文件在浏览器测试中比对源摘要，独立 Runner 再逐字节核验原始文件及 ZIP 成员；缺失任何一层、任意改名、错误原名响应头、非 Blob 保存或损坏字节均拒绝。ZIP 内路径和成员名继续精确保真，原五模型及三来源场景不减少。此分层边界不追认旧失败的 Hosted，也不改变产品下载协议。


### glTF multi 三来源 profile

同一 `ftp-consumer-flow` 扩展 FTP、NFS、MinIO 的静态 core glTF 2.0，不新增 suite、服务、任务类型或消费 Permission。主 manifest 及已确认外部 buffer/PNG/JPEG 构成一个 multi DataItem；正式批准展示并冻结完整精确组成，三个原始内容出口和转换执行共用该边界。基础结构不完整、主清单变化、越界/软链接、未知扩展及未授权依赖拒绝；静态转换不得因旧目录访问方式读取业务源的其他内容。

固定 profile 使用红蓝两个三角面板、原目录中同名的两张 PNG 和带首空格/字面百分号的 buffer。Runner 独立核对原文件 ZIP 的四个成员、路径和逐字节内容；生成 GLB 核对两材质与两三角形绑定、UV、场景、尺寸和嵌入 PNG 像元，页面真实按钮保存、红蓝实体渲染、缓存重开均须取证。组成变化、撤权、定义与成果分别删除及精确清理沿共同矩阵逐来源执行，保留原六格式覆盖；Deny 反例按篇首缺口处理。data URI、bufferView 图片、版本/扩展/URI/长度反例由格式和 Runtime 标准门禁验证，固定外部资源 Hosted 不外推为任意模型、动画、大场景或容量认证。


### FBX 严格单主文件扩展

`ftp-consumer-flow` 沿同一入口扩展 FTP／NFS／MinIO 的 Binary 7400 静态无贴图 FBX，不增加服务、任务类型、消费 Permission 或父目录授权。Meta basic 必须保存固定 profile 的完整结构证明与唯一主 `model` ref；授权查询只读持久事实。正式 Grant／Deny、执行授权、KindFile 精确暂存及原始三个出口使用同一主项身份，SKP 继续不准入。

各来源使用同一合法固定源及独立 Engine、工件目录。必须核对实际 GLB 的几何、材质、场景变换和无媒体／动画／蒙皮／形变；页面生成与缓存重开、真实原文件按钮保存、源字节和名称、原始 Range 均独立留证。保持相同路径、大小及旧完整事实，把版本改为未准入值后，原始三个出口必须拒绝；恢复原文件后仅按原批准边界恢复。撤权后的缓存／生成拒绝、定义／成果删除及清理沿共同矩阵逐来源验证；Deny／解除仍为篇首所述旧场景。旧 box／vCube 的历史转换或基础预览证据不代替新严格 profile；不为迁就旧样例放宽格式验证，来源与转换层的失败分别记录。

## PostgreSQL 与 MySQL 的连接池配置生效

**准入与身份。** `sql-pool-consumer-flow` 仅手动 Hosted Linux x86_64：独占可销毁 PG／MySQL，随机回环端口，各一张合成表及只 SELECT 账号；沿标准 preflight、构建指纹及保护投影就绪。登记 User 持既有 `tenant.infrastructure_administrator`，同 User 从 System 页面只保存本轮两引擎配置，核 Tenant／主体／角色／权限。独立准备身份扫描并签发两表精确 read，页面阶段移除两类准备 Token。普通消费 User 仅八项：引擎／Meta 目录、Manager 数据项／内容、Develop 查询任务读取／执行、数据读取、执行授权签发，不随配置阶段增权。

**四次配置更新。** 每引擎先由真实 Manager 预览／Develop SQL 建立空闲连接，然后 System 页面依次改：① `127.0.0.1`→同实例 `localhost`，走“同一实际引擎”确认并核容器 ID／原生身份；②同表同 SELECT 范围的第二数据库账号；③该账号密码；④最大空闲 1→0，最大连接一直 2，前三步留一闲置、最后无闲置。库名／端口／Engine Instance 来源、两 Grant 与八 Permission 不变，数据库账号不是 ADDP User。

PG 初始化 TCP 含回环显式 `scram-sha-256`，socket 仅内部初始化；MySQL 原生密码。启动 ADDP 前，两库全新连接须证错误密码认证拒绝、正确密码成功，不能以 trust／网络失败充数。密码阶段一次改源端，再以全新连接证旧拒新成，才页面保存。每次保存后正式连接测试恢复 online，但不再次增 version。逐阶段核真实请求／连续版本、两消费页面结果、当前账号原生语句及活动会话、旧连接释放／新账号接替、消费进程未重启；缺阶段、源漂移、复用别账号连接或泄漏凭据均失败。私有材料不归档，日志只提取会话标识／分类，不留原 SQL。
