## starrocks-consumer-flow

手动 Hosted Linux x86_64，仅认证 `default_catalog` 内部普通表只读。Business 固定双架构镜像／唯一初始化、独占持久卷；核 reader 拒写、重建后 Backend ID／用户数据保留及随机回环 SQL 端口。就绪须 BE 心跳和首份非零磁盘容量，不调低阈值或重试有副作用 DDL。

与 GaussDB 共用下节五表精确授权准备及只读 SQL 流程：消费八项功能、无扫描权，等待 `manager,develop` 保护投影，六服务同提交。StarRocks 字段顺序 `name,id,amount,optional_text`、复合主键 `name,id`，NULL 与空串不同；核 bigint `9007199254740993`、Decimal(38,18)、中文／尾空格和原值参数，不由样本猜结果类型。

四表目录必须恰为 source、customers、products、orders，再定位 source；新样例 5／6／10 行及原 source 两行的初始化、关联金额 39179.40、补齐／保留用户修改由 [Business 入口](../../../../business/README.md)与原生 T2 维护，不把 T2 或本机管理员预览当新增样例普通 User Hosted。

入口 `make test-starrocks-online-runner`、`make test-common-starrocks`；后者分别核 Linux ARM64／amd64 的原生、Provider、持久化。退出核自有容器／卷／镜像，凭据不归档。未认证 Transfer 写入、Spark、外部 Catalog／视图、跨批快照或分布式部署。

## gaussdb-consumer-flow

隔离账号凭一份 schema 节点 read Grant 查询已有表和授权后新增表。另一 schema 的对照表已被 Meta 识别，源库 reader 也具有 SELECT，平台仍须在来源核权阶段拒绝。撤销节点 Grant 后，以同一账号重跑原新表查询。两次拒绝均须没有结果，源端不能新增目标表读取；日志计数涵盖直接 SELECT 和 Provider 实际使用的游标声明。

**当前准备范围。** GaussDB `addp_acceptance.source`、StarRocks `business.source`精确 read；StarRocks `business.customers/products/orders`仅 metadata_read。独立准备 User 只对五表定向 deep／办理，消费删除扫描 execute/read、保留八项查询／预览功能；业务前清登记／准备凭据。公共 Meta 只身份／字段／主键、拒统计泄漏，精确行数／完整属性从受保护 Manager 预览核。metadata-only 可见但拒内容；签发前登记私有意图，失败／未知也清理，停服前撤五项并核隐藏／拒读。

手动 Hosted Linux x86_64，固定官方介质和 `business/gaussdb/`唯一初始化；reader 仅 USAGE／SELECT，无权表／无 USAGE schema 隐藏。保持原生 A 模式空串→NULL，不改模式／增权／填空值迁就测试。System 独立登记 `engine_type=gaussdb`；新 Tenant 保护投影只读等待 `--wait-protection-owners manager`，SQL 扩展等待 `manager,develop`，不能补标记、固定 sleep 或重试预览绕 `security_protection_required`。

同一普通 User 的 Manager API／Console、Develop 全表 SQL 与文本／整数参数查询，核原生字段／主键顺序、precision／scale、bigint 与 Decimal 精确字符串、中文尾空格／NULL。关键值为 `9007199254740993`、`12345678901234567890.123456789012345678`，参数 `中文' OR 1=1 --`原样绑定、整数 3 只返目标一行。无任务保存／写入／DDL／其他语言资格。

GaussDB 两条浏览器读取成功后，准备账号撤销此次精确 read。消费账号沿同一工作台执行接口再次提交首条 SQL，核对新的执行号、源读取前的授权拒绝和空结果。浏览器证据、撤权回执和拒绝执行分别归档，任何阶段失败均沿原入口完成清理。此项等待新版 Hosted 实测。

## highgo-consumer-flow

手动 Hosted Linux x86_64、既有固定镜像／唯一初始化，独立登记／准备／消费。business 仅 HighGo `customers/products/orders/order_items/orders_replace_online`与 PG `orders`六表：准备者精确 deep／六 read，消费无扫描 execute/read，业务前清准备凭据。Meta 只身份／字段／主键；Manager API／Console 核四业务表 11 具名约束、10 索引、键列序、无分区及行数。PG 订单两次 snapshot replace 到 HighGo 哨兵，逐值七字段／金额、无重复、源表保护；写后自动扫描，不补手扫。

`highgo_case=sql-timeout`与默认 business 独立，只登记 HighGo 和 System／Security／Meta／Manager／Develop。准备者精确 basic 扫 `addp_business.addp_engine_probe`并签唯一 read；消费仅 SQL 池八权限、无扫描／办理／Transfer，页面前清登记／准备凭据。

- 自有控制事务锁探针表，最长 240 秒；源端证明本次实际连接被本控制 PID 阻塞，区分 `table_catalog`目录核验与 `table_read`内容 SQL，不以 pending、取消、错凭据或保护拒绝充超时。
- `barrier acquire|observe|release manager|develop`每阶段只一次，预写私有意图，未知不重发；释放核 PID／application_name／库／控制账号，不终止旧 PID 他会话。
- Manager 须 HTTP504／`preview_sql_execution_timeout`持久面板，Develop 须终态／`sql_execution_timeout`；释放后原生等待消失、表锁释放且两页面恢复。日志只阶段／连接 ID／分类，不含 SQL／凭据。

两 case 均原身份撤精确 Grant／验拒绝，未知签发清理，自有平台／容器／卷／身份零残留。入口 `make test-highgo-online-runner`及原 Online／Platform 登记；独立超时通过不代 business 迁移，不扩 upsert、CDC、空间或分区表页面，未实际完成不计 T4／夜间。

## 关系型引擎消费链路

四引擎共用 bounded watermark＋稳定主键 id：源 5 行、同构空目标，Meta 扫描取得 ResourceLocator，同一任务验证 5／2／0 三次读数，目标 upsert 最终 6 行／无重复键。Manager 预览完整列序、Develop SQL、临时 Query Service 经各自正式出口核同目标 checksum；上层只用 ResourceLocator、SQLDialect、Provider，不降格为 MySQL 或加厂商分支。任务／服务按 ID 删并回读 404，所有退出路径核自有夹具与数据恢复／销毁；每个 profile 单独取证。

### OceanBase

专用 OceanBase CE MySQL 模式、永久 `engine_type=oceanbase`，5 行非空间 InnoDB 源。Fixture 退出恢复源基线／空目标再停止；仅手工 workflow_dispatch，首过前无 schedule。

### TiDB

GitHub Hosted Linux x86_64 手工运行。固定版本通过现有 `pg_source_commit` 参数传完整 SHA，由 Job 核对检出版本及主线祖先关系。每次使用一次性平台库、租户和引擎登记，独立办理账号签发授权，普通消费账号执行查询。原 5／2／0 消费断言使用两张精确授权的表。另一个 database 的直接节点 Grant 覆盖已有表和签发后新建的表。范围外 database 建立同名表，源库账号能读取两边，以验证平台裁决。五次串行 Develop 执行分别记录执行 ID、Grant 请求 ID 与对应窗口的 TiDB 业务 SELECT 计数差值，预期依次为 1／1／0／0／0。前两项分别断言唯一结果行的 BIGINT 主键为 JSON 字符串 `"37"`、`"41"`，结果不符时只保留返回行数、主键值类型及合规的数字主键。后三项为跨库同名表、JOIN 无权表、撤权后原 SQL 重跑，须取得授权阶段的明确拒绝。失败也归档已取得的证据，回收本轮 Grant 并核对读取已拒绝。固定 digest 的无卷 PD／TiKV／TiDB 退出时执行 `down --volumes --remove-orphans`，检查容器、网络和卷零残留。

### KingbaseES

受保护 `self-hosted/Linux/X64/addp-kingbase`，固定 SHA-256 V9R1C10 `V009R001C010B0004`官方介质／正规 License，无卷 `DB_MODE=pg`。Provisioner 正式登记当次 `engine_type=kingbase`，原生 ON CONFLICT upsert。删当轮平台库／Engine／容器／镜像／任务／服务／owner-only 凭据，License 与镜像 tar 不归档；首过前仅手动。

### openGauss

Hosted `ubuntu-24.04` x86_64、固定 SHA-256 的 6.0.6 LTS 官方介质／独占容器。Business 仅建 DB／私有描述，不调 System；System helper 建身份，独立 Provisioner 仅 `system.engine.create/read/execute`正式登记当次 `engine_type=opengauss`，业务前清 Token／DB 凭据。

准备 User 沿既有十一项资格，只扫 `public.addp_online_consumer_source/target`并签两精确 read，消费十六项功能不变；授权前正式 System 事实核边界，授权后消费过滤目录核身份，不代读／跳唯一项。清准备／登记凭据后走共用矩阵；namespace 为 public、原生 MERGE。Engine／身份随 `addp_online`销毁，凭据仅非归档 owner-only runner.temp。

入口 `make test-opengauss-online-runner`由原 `make test-online-runner`聚合发现；真实首过且构建／清理／零残留证据齐后才手动＋每日 schedule，schedule 只选本 Hosted Job、其他 Online 显式排除。其他三厂商首过前不加定时。
