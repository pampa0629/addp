## PostgreSQL：共享目录取证与后续复验

- **已确认现象**：Docker Desktop 4.49.0／Apple Virtualization／VirtioFS 下，宿主原子替换已有文件名后，容器能 stat 却不能读到新内容；新文件名及同内容不替换可读。无数据库的独立普通文件复现也失败，正反顺序对照支持目录枚举影响可见性；不是 HBA、SQL、fchown 或默认临时路径才会触发的问题，不能据此指定唯一上游缺陷或固定恢复 TTL。
- **安全边界**：同内容发布经版本、归属和权限检查后保留 inode；真实变更仍原子替换，读取不可见仍拒绝。没有引入等待／重试、原地覆盖或放宽认证；夹具在物理发布时记录恢复版本，避免读回首败被后续 CAS 错误覆盖。早期目录失败项目均按归属核验清零，清理成功不代表目录认证通过。
- **后续通过范围**：初始化临时 socket 被误判 Healthy 后，改为等待正式 TCP 服务。固定基线 `4d8a8cc2e3b391cdfe2cdc46707d131397b25dac` 叠加该 Compose 修复，在一次性 Lima Linux ARM64 的 `--case=postgres-observation` 完整通过，139 项配置／27 项生命周期、目录认证／原子更新／重载／还原通过，容器、网络、卷、临时文件及专属 VM 清理完成。11 月 8 日本机 `--case=postgres-source` 严格证书整轮也通过目录可见性和完整恢复；原记录未另列该次固定 SHA。
- **仍未关闭**：后续成功不能证明早期 Desktop 共享层问题已根除，独立候选版本／共享实现的专项验证没有完成。具体排查与维护窗口要求统一见[共享目录故障说明](../../../guide/troubleshooting/开发服务与构建.md#docker-desktop-共享目录原子替换后容器读不到文件)。
