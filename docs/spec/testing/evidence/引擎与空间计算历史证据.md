### MinIO 容量隔离准入

2026-11-10，复用仓库 MinIO observation Compose 的单个 Business 测试服务，使用独立项目、命名卷和动态回环端口。镜像为仓库锁定的 `RELEASE.2025-10-15T17-29-55Z`，原生源码 `9e49d5e7a648f00e26f2246f4dc28e6b07f8c84a`，本机 Docker Linux ARM64。临时探针通过原生签名请求核对三个人工构造的桶、已知对象字节及普通桶读账号、纯前缀读账号和前缀读加桶位置查询账号。管理员仅用于建立夹具与对照，个人 Business/Infra 服务及凭据不参与。

- **缺样**：首轮扫描前，非空桶和空桶的 `AccountInfo` 都为 0 字节、0 对象。管理员的 `DataUsageInfo` 此时为零时间、无桶统计。首轮扫描后，非空桶显式为 4,194 字节、2 对象，空桶显式为 0 字节、0 对象。可区分两态的是管理接口的桶统计是否存在，`AccountInfo` 没有提供这项信息。
- **权限**：普通账号只返回其可访问的两个桶。纯前缀账号读指定对象、列指定前缀成功，桶根列表、隐藏对象和 S3 ListBuckets 均为 403，`AccountInfo` 返回空桶列表。仅增加 `s3:GetBucketLocation` 的对照账号仍无法列桶根或读隐藏对象，`AccountInfo` 却返回整个桶的 4,194 字节、2 对象，含隐藏的 4,093 字节。三个非管理账号访问 `DataUsageInfo` 均为 403，管理员对照返回三个桶；其 `capacity=true` 响应也未返回磁盘容量字段，与[该固定版本先序列化、后填充容量字段的实现](https://github.com/minio/minio/blob/9e49d5e7a648f00e26f2246f4dc28e6b07f8c84a/cmd/admin-handlers.go#L845-L875)一致。
- **时效**：新增 211 字节对象后立刻可读，统计仍为 4,194 字节、2 对象。约 96 秒内未达到 4,405 字节、3 对象的预期，`lastUpdate` 却从 12:41:18 推进到 12:42:18（北京时间）。该时间是汇总更新时间，不能证明单桶最新写入已计入。

前两次探针因 `AccountInfo` JSON 字段大小写和 `bucketsUsageInfo` 字段名解析错误提前退出，均未认定通过。第三次默认配置保留统计未在窗口内收敛的退出，已证反例不因退出而抹去。命令 `python3 /tmp/addp-minio-capacity.tcHtyg/probe.py`，脱敏原件为同目录 `attempt1.log`、`attempt2.log`、`attempt3.log` 及对应 JSON 报告。

另起同版本临时实例，仅以 `MINIO_SCANNER_SPEED=fastest` 做正向对照。写入后约 2 秒观察到扫描汇总更新为 4,405 字节、3 对象，约 10 秒观察到 `AccountInfo` 缓存跟上。命令 `python3 /tmp/addp-minio-capacity.tcHtyg/fastest/probe.py` 退出 0，原件见同目录 `run.log` 与 `report.json`。该耗时仅适用于这次加速夹具。四次独立项目的容器、网络和卷均已清零。
