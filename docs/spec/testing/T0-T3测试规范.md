## T0-T1

Metrics T2 的固定窗口探针将依赖准备／测试二进制编译与真实执行分别计时：测试产物只放当次私有工作目录，准备最多 180 秒；原固定窗口执行上限保持 60 秒，显式 Go 超时同为 60 秒。编译失败或超时禁止执行遗留产物，执行失败／超时不得重试或计通过；仍完整执行 CPU、进程、HTTP、磁盘、IO、网络、文件系统及 inode 断言。Job 20 分钟与退出清理边界不变，新增计时和失败拒绝回归沿原 Metrics 标准入口运行。

### Go HTTP 追踪第一批本地验收

2026-10-20 用户确认仅本地验证。T1 必须覆盖 Gateway 外部上下文重置、内部 Context/流式响应传播、外部重定向清除上下文、有限属性和敏感值反例、异常结束/4xx 语义、队列满及导出失败不阻塞业务；日志验证规范 ID、精确过滤、游标筛选绑定及独立正文权限。客户端不得以无 Context 的旧重载作为兼容路线。

本地 T2 使用标准 make test-monitor-traces 的一次性 TLS Alloy/Tempo/MinIO 及日志链，真实 Go → Python → Go 请求驱动 Server/Client Span、尾采样、Tempo 读取、Loki 日志关联、匹配调用边及故障/停止恢复；等待实际 120 秒决策，不降低产品阈值。校验 TLS/身份拒绝、普通采样与异常/慢请求优先、队列/容量缺口、无敏感属性和退出零残留。受控身份不冒充正式密码/MFA T4；不得接入个人服务或复用其秘密。

Trace 查询 T1 必须覆盖单请求四并发、所有请求及 System 裁决共用八个活动上游预算、主体限额、结果顺序、超时/失败取消、累计 Span 超限及任何错误不返回部分数据。容量专项每档通过当前 User 路径一次抽查二十条调用链，每条须为五 Span／两条匹配边，保留整次五秒上限；一次超时不能靠分拆小查询或减样本计为通过。

容量专项使用同一标准入口 `make test-monitor-traces MONITOR_TRACES_TEST_ARGS=--capacity`，负载与资源上限、判定线沿运行观测规范 6.5。普通 T2 不隐式执行 20 分钟压力负载；其配置及报告判定由现有平台 T0/Monitor T1 自动发现覆盖，完整容量专项显式执行并独立报告。保持真实 120 秒尾采样、自然落盘与 72 小时配置，禁止通过缩短保留或直写对象“加速”容量结论；短测外推不能计作 72 小时实留验收。本次不运行 Hosted。

Python 第二批同步 HTTP Trace 沿 Common Python、Agent/Copilot 原标准入口验证；共享 ASGI/HTTPX/日志内核及严格部署解析、mTLS OTLP 接收、队列和退出预算均在单一路径覆盖。必须有并发上下文隔离、合法 Server/Client 父子关系、外域重定向剥离、流式最终 body/EOF/关闭及取消/发送失败、无敏感属性/异常正文、Ready/认证拒绝和关闭/配置失败回归。不新增全局自动 instrument，不把 Trace 接入记为全量 HTTP 质量采集或异步/SQL 覆盖；跨 Go/Python 的真实 Alloy/Tempo T2 和未执行项单独报告。本批不运行 Hosted、容量或 72 小时长测。

T3 沿 Console iframe 验证 Trace 查询/详情/调用关系、日志跳转、URL 恢复、双语、无权限及撤权清空/迟到响应隔离；不允许向浏览器转发 Tempo/Loki 原始 DTO。新增标准门禁必须同次登记 CI 选择、受影响路径和清理契约。本轮不扩展 Hosted 身份、流程或运行范围；未跑、失败、跳过分别记录。

正式身份本地入口的资源守卫确定性验证沿`make test-monitor-traces-local-runner`，纳入既有Platform门禁与CI登记，不启动隔离部署。覆盖统一四秒预算跨步骤递减、进程创建和最后读取／解析超时拒绝、成功与失败的分步计时、锁等待与取消清理分离、监测循环保留失败明细、取消后进程组回收及诊断脱敏；保留OOM、非零退出、硬配额与4 GiB停止线反例。等待优化仅用短时只读探针对照，不以空闲态读取通过替代繁忙阶段的稳定性验收；本批不启动新的正式身份窗口、不运行Hosted、容量或定时。

经用户确认的繁忙专项诊断复用上述确定性入口，须覆盖40分钟全程、30分钟构建和180秒启动的绝对截止递减，原构建／部署调用及三组前后六次守卫检查、120／300秒观察、单次失败直接传播且恢复编排包装、不调用身份／业务／页面路径，以及四秒／五秒边界、各阶段最小样本拒绝和分步统计。实际40分钟隔离运行另记本地技术诊断证据，不计正式身份或Hosted通过；不运行容量模型或定时。

T0-T1 必须：

- 不依赖已经启动的 ADDP 服务。Infra 生命周期单测必须同时隔离容器状态与宿主机监听查询，使用夹具内的端口事实；真实端口探测由专门的端口解析回归覆盖，不能让 mock Docker 与真实 lsof 混合决定启动行为。观测平台夹具必须清除父进程的个人观测选择、部署路径和传输配置，再应用用例显式输入。
- 不连接开发业务数据库。
- Online 浏览器源码的语法门禁必须按所属模块的 ESM 契约显式校验，使用 Node --check --input-type=module 从 stdin 读取源码；不得把不同 Node 小版本的文件模式检查返回 0 等同于完整回调语法有效。根 .node-version 是 Node 主版本唯一事实源，运行前按二进制实际版本核对，不根据安装目录或别名推断。非法语法必须在所属 runner 的后续确定性测试与夹具编译之前拒绝。
- 可重复执行，失败后不留下外部状态。
- 需要 Online 条件的测试默认不进入普通语言测试；对应专用门禁显式开启并拒绝意外 Skip。
- 模块门禁执行平台 T0 和 Go T1 时必须移除 `*_POSTGRES_TEST_DSN`、`ADDP_*_INTEGRATION` 等 T2 显式开关；只在对应 T2 步骤保留调用方提供的条件，避免平台内嵌单元测试绕过 owner 锁并清理共享测试库。
- 模块生命周期公共契约必须在 T1 覆盖 `starting → registered`、`registered → recovering → registered`、确定性拒绝进入 `failed`、取消后 `stopped` 与限时注销。
- Backend 路由测试必须证明 `/health/live` 不触发外部调用，`/health/ready` 只在自身必需 Infra 和 System 注册都就绪时返回 200，业务路由在 Not Ready 时返回 `503 module_not_ready`。
- Worker/Scheduler 测试必须证明未注册或 `recovering` 时不领取新工作，恢复后无需重启进程即继续领取。

各 Runtime 的原生依赖、SDK 边界及专项断言见[Owner 补充门禁](Owner补充门禁.md#addp-owner-补充门禁)。

### 线拓扑手工容量基线

链路合并新增显式手工 `profile=chains`，沿 `TOPOLOGY_CAPACITY_PROFILE=chains make test-vector-topology-capacity` 只运行其独立5类15档，不运行原线叠／自叠矩阵、观测或旧新对照，也不重复业务T4。长开放链、连续分支网、单个大闭环及大量独立四边小环各为1000／10000／100000个原始LineString部件；高阶公共端点为128／512／2048条支线。每部件一条源记录、字段宽度固定、EPSG:3857和整数XY；长链／大环打乱源顺序并交错原方向。连续分支网每10部件含T形分支及经尾线相连的挂环，相邻单元端点精确连接但grade变化断链；按全图度先于属性判断，每单元固定输出5链。小环每4部件输出1链，高阶节点不选择主路、每部件独立输出。高阶三档分别涉及8128／130816／2096128对真实端点相交检查。新增报告为v3，历史报告保持原版本与范围。

同一固定源码／镜像／Runner，各档独立默认入口容器、串行、一次测量，保持4 CPU／2 GiB／无额外swap／全流程180秒，Job上限90分钟。输入生成、完整读取、源核验、计算、result及members双保存、独立原生OGR重载和末轮源不变核验全部计入180秒；就绪与镜像构建另记。仅外部0.25秒cgroup采样，不包装生产几何函数或增加内部采样；实际加载的merge_line_chains函数须与源码哈希和编译代码绑定。各阶段耗时、完整容器内核峰值、worker高水位、CPU／OOM／swap、原始样本及超限阶段分别保留。失败不重试或扩大预算，清理成功继续其他档，清理失败停止；任一未通过仍使门禁非零退出。

双份GPKG完整重载按闭式构造逐行核共同字段、全部原属性／NULL／Int64／Boolean、业务来源、链号／成员顺序／原部件号／反向标记及精确原坐标、链接缝和CRS，每个原始部件恰好出现一次；预期不得调用生产图遍历或合并算法。主链与明细分别保存全量校验摘要、字节大小及哈希，输入内存和原文件前后不变。大文件按原容量生命周期清理，归档仅有摘要时不声称离线物理重读；所有本轮容器／registry／标签／工作目录按归属清理，无全局prune。结果只定位这些固定构造在原预算内的通过档及首个超限档，不认证精确最大容量、稳定吞吐或任意属性／复杂线网。小样本和篡改负例仍由现有Native／capacity-runner及Python CI登记覆盖，无新增公共入口或日常大负载。

线叠和线内自叠沿 `make test-vector-topology-capacity` 执行独立手工 Linux 容量基线，不归入业务 T4，不重新执行已通过的普通用户扫描、血缘与地图验收。新增 `.github/workflows/vector-topology-capacity.yml` 仅接受 workflow_dispatch，无日常或夜间大规模负载；确定性小样本与资源／登记负例沿 `make test-geopython-workflow`、`make test-vector-topology-capacity-runner` 及平台 Python CI 登记门禁。

线内自叠求交收集采用每源最多2048个原始候选对的有界向量化批次，逐段索引查询、配对顺序、交集后精确去重及一次融合语义不变。实现调整先沿既有 Native 入口验证不足、恰好、超过2048对、跨批与跨源去重、完整原始配对顺序和异常不保存，再复验原15档与10万要素观测对照；不重复已通过的业务T4。跨历史轮次的性能比较必须列明源码、镜像、版本和Runner差异，不能冒充同Runner受控前后对照。

矩阵共15档：成对分布且各含10段的稀疏图层1000／10000／100000条，分别测跨源线叠和每源自叠；单条1000／10000／100000段长线测自叠；密集100／300／1000条同线或单要素重复部件分别测线叠／自叠。跨源密集1000条应产生499500对，每源重复仅按唯一位置计长。预期身份、顺序、坐标和长度由闭式公式生成，不调用生产相交算法。

标准镜像构建入口生成产品镜像；每档独立默认入口 Runtime 容器，网络隔离、不发布宿主机端口、不启动 System 或个人服务。容量 worker 在同一容器内调用唯一生产 load／检查／save 主路径；这是组件级 Native 容量证据，不是认证 HTTP 业务链。固定4 CPU、2 GiB、memory-swap与memory相等（cgroup swap.max=0）。每档worker从进程启动到输入生成、完整读取／计算／保存／重载独立核验总计180秒，默认入口就绪和镜像构建另行计量；超时立即终止该档独占容器，下一档使用新容器，不重试业务、不调大预算。超时、OOM或结果不符均不计通过，完整矩阵继续记录其他档，任一非通过使门禁非零退出。

按阶段保存时间、worker峰值RSS、容器内进程高水位采样、cgroup内存峰值／CPU用量／OOM与swap事件及原始采样。容器峰值从默认入口启动计，包含Runtime、生成和worker，不将其伪称纯计算峰值；worker计量与容器总量分列。逐行核完整几何与来源、FID不能替代业务ID、原坐标单位、CRS、去重长度、输出Schema和行序；源内存表示与原文件哈希必须不变。仅保留报告、完整校验摘要、文件大小与哈希、失败阶段及日志，合成大文件与临时旁文件在每档退出后清理；归档没有大文件时不能声称离线重新读取。Runtime／私有registry／本轮唯一产品标签与工作目录须按归属清理，保留普通构建缓存，不执行全局prune。

容量 worker 仅在调用生产计算的观测上下文中记录原始自叠交集收集与一次融合的聚合耗时、调用次数及融合输入片段数，退出后恢复原函数；不替换几何运算。独立采样线程按0.25秒记录当前阶段及 cgroup memory.current，按阶段汇总采样到的最大当前用量；这是阶段采样值，不是内核逐阶段峰值，累计 memory.peak 仍独立报告。准备、归一及计长等开销留在计算总耗时中，全部观测开销计入原180秒预算。失败保留阶段观测，不用未完成记录替代通过。

另有显式手工 `profile=observation`（标准入口 `TOPOLOGY_CAPACITY_PROFILE=observation make test-vector-topology-capacity`）：只执行10万源要素的稀疏线内自叠，不执行15档矩阵或业务T4。同一Job/Runner、同一次产品镜像构建，按ABC、BCA、CAB交错顺序各测三次，每次独立容器；4CPU/2GiB/无额外swap/全流程180秒及完整源不变、坐标/ID/长度/CRS oracle均不变。A只保留各组共同的外部cgroup采样；B增加收集/融合聚合计时包装，不启动内部采样；C再增加0.25秒内部阶段采样及进度JSON写出。A的未观测计时/调用数报告null，不伪造零；A/B不生成内部采样文件。常规六阶段计时和阶段进度写出三组一致，不属于本次差分归因范围。

九次原始结果必须绑定测量ID、组别、重复号、源码、镜像ID、Runner及版本；逻辑输入摘要与完整结果摘要全部一致后才汇总。GPKG文件创建时间可能不同，只要求各次源字节前后不变，不要求跨次文件字节相同。报告各组墙钟、计算、CPU秒和内核累计内存峰值的中位数及范围，以中位数B−A估计包装影响、C−B估计内部采样及写出影响、C−A估计内部观测总体影响；保留负差值。小样本与Runner漂移仍影响差分，不视为精确因果测定或生产SLA。任一未通过/清理失败不得以其余部分结果认证整套通过；九次180秒均包含各自观测开销。

显式手工 `profile=comparison` 仅量化分批求交的旧／新实现净收益，不执行15档或业务T4。采用同一Job/Runner、同一次标准产品镜像构建的基础镜像与依赖，固定10万稀疏自叠要素；四组配对按旧新、新旧、旧新、新旧交错，共八个独立默认入口容器，均为A观测模式（共同外部cgroup采样，无内部计时包装／采样）。4CPU/2GiB/无额外swap/每次全流程180秒不变，不重试失败测量。

旧实验镜像从本轮产品镜像推入本轮私有registry后得到的精确manifest digest派生，并核验对应image ID，只用固定提交 `8a3006670e7f6cfaddf018253515ccb37ab5bc78` 的标量交集收集器替换当前收集器，并移除该实验镜像中不使用的分批常量／私有辅助函数；其余当前源码不变。当前分批收集器及辅助定义必须精确匹配 `adb605b67676bc4396307bc9ea7449c63de183bc`。固定Git源码读取要求标准CI完整历史（fetch-depth: 0），缺失历史时失败而不回退。旧源码仅作本次测试归档与临时派生镜像输入，不进入产品目录或提供运行时兼容参数。归档两份完整模块、固定Git来源、模块／收集器哈希和仅这三个定义变化的AST核验。镜像证明旧RootFS为同一产品镜像全部层加唯一COPY层，默认入口、环境及工作目录等执行配置一致；worker在原预算内读回实际加载模块与收集器哈希，错绑、额外代码差异或版本／逻辑输入／完整成果摘要不一致均拒绝汇总。

八次结果必须全部通过并清理成功才给出旧／新墙钟、计算、CPU秒及内核峰值的中位数和范围；逐配对保留旧减新、比例、计算时间降低百分比以及各非计算阶段，不用历史Runner结果代替对照。配对与组中位数分别报告，正／负差均保留；小样本、CPU频率／缓存及时间漂移仍可能影响测量，只认证本输入与原预算，不外推其他拓扑算子、密集／长线规模或生产SLA。共享镜像、临时旧镜像标签、registry与本轮目录均按归属清理，不改产品实现、不执行全局prune。

本轮矩阵和180秒为待实测的验收边界，不承诺所有档能通过；不因小样本或某次测量推出生产SLA、稳定吞吐或任意复杂线网容量。实际性能和规模通过范围须按固定源码与隔离资源的原始结果另报。

## T2

T2 使用真实但可丢弃的基础设施，并满足：

- CI Job 使用独占 Service 和随 Job 销毁的数据库。
- 托管外部服务的 owner gate 必须在脚本头声明 `# ADDP_T2_SERVICES=<service,...>`；模块门禁、CI 注册和后续新增数据库类型都消费该声明，不按数据库名称维护发现分支。
- owner 自建的临时服务通过 `ADDP_T2_OWNED_SERVICES` 和 `ADDP_T2_COMPOSE_FILE` 登记，必须拥有独立 Compose 项目、回环随机端口以及退出清理和零残留检查。镜像使用固定 tag 与 digest；需要沿用仓库源码构建时，允许引用仓库内的单一 Dockerfile，但外部基础镜像须固定 tag 与 digest，Git 源码须在同一构建步骤中核对固定提交，构建上下文须位于仓库内，Dockerfile 与本地复制输入须登记到 `ADDP_T2_INPUT_FILES`；目录声明以 `/` 结尾，递归覆盖该仓库子树的新增、修改和删除，构建检查与变更选择共用同一覆盖判定。登记检查拒绝仓库外路径、构建参数覆盖和未固定源码；门禁必须实际构建，不接受开发环境已有同名镜像作为构建证据。
- 必须由调用方注入连接条件的 owner gate 同时声明 `# ADDP_T2_REQUIRED_ENV=<name[|alternative],...>`，逗号表示“同时需要”，竖线表示等价的安全前置条件。`make test-module` 与 `make test-changed` 必须在执行任何 T0/T1 前一次性检查全部所需条件，缺失时失败关闭并给出 owner、变量及安全测试环境提示；`--dry-run` 仅展示计划，不要求真实连接条件。CI 登记检查必须确认对应 Job 显式提供每组条件中的至少一个变量。
- 需要 owner 持有合法 License 或受控介质的门禁必须声明 `# ADDP_T2_OWNER_MANAGED=<runtime>`，只通过 owner 受控 Linux 主机上的 `make test-integration-owner-managed` 人工执行，不进入 GitHub Actions、普通 `make test-integration` 或 macOS 定时巡检。登记检查必须拒绝 workflow 调用这类目标及其聚合入口。脚本必须验证官方介质与 License SHA-256、拥有 disposable 容器全生命周期并验证零残留。
- 本地共享 `addp-postgres` 只允许使用 `addp_test` 与 `addp_iam_test`，并且只能通过根 `Makefile` 或 `scripts/test/` 的标准入口操作。
- 本地 PostgreSQL T2 门禁必须由调用方显式提供测试 DSN 或端口；不得在未提供时回退到 `.env` 的首选端口。调用方先用 `bash scripts/infra/status.sh` 核实 ADDP Compose 实际映射。标准 PostgreSQL 门禁在执行测试或清理前，必须核对本地回环连接的端口与当前工作区 `addp-postgres` 的实际 Compose 映射一致，且 database 仅为 `addp_test` 或 `addp_iam_test`；容器不存在、归属不符或映射不一致时直接失败，不根据 `.env` 猜测。门禁前置检查不得输出一个写死首选端口的可复制连接命令。GitHub Actions 的独占 Service 与辅助 macOS CI 的独占临时 PostgreSQL 使用各自入口显式配置的端口和 database，不套用本地共享 Infra 校验。
- 禁止为单次验证直接创建或删除数据库；现有标准入口不能满足隔离时，先完善入口及自动清理。
- 门禁在任何破坏性动作前校验数据库身份，拒绝开发库、生产库或不满足 owner 安全约束的连接。
- 每个场景只清理自己拥有的 Schema 或带唯一运行标识的事实，并验证零残留。
- 门禁拒绝意外 Skip，避免“命令成功但测试未运行”。
- Common PostgreSQL 的默认 `make test-common-postgres` 保持完整门禁，同时覆盖表写入准备、安全列演进和空间结构拒绝。真实低权限账号必须在没有数据库级 CREATE 权限时完成已有 schema 下的建表与 upsert 准备；缺失 schema 仍须按数据库权限拒绝或创建，测试结束清理本轮 schema、账号及授权并验证零残留。仅验证查询读取集合、输出血缘及查询会话值表示时，可在同样的显式测试连接条件下运行 `bash scripts/test/common-postgres-gate.sh --test query-read-set`；该分组包含真实资源改名及同名重建的定位身份案例，以及 BYTEA 的 NULL／空值／非 UTF-8／别名／表达式／跨批次保真和文本、精确 numeric、JSON 表示回归，保留数据库身份检查、Skip 拒绝和场景清理。分组结果只证明所选范围，不替代完整 T2 门禁；CI 继续使用无分组选项的默认入口。
- HighGo 写入沿用 Common PostgreSQL 标准入口：默认完整门禁及 `bash scripts/test/common-postgres-gate.sh --test highgo-write` 在 disposable PostgreSQL 上回归独立 HighGo 驱动和共享写入协议，由既有 Hosted Common PostgreSQL Job 覆盖。`--test highgo-write --highgo-native` 为显式原生认证，必须注入全部 `ADDP_TEST_HIGHGO_*` 连接字段，强制 TLS 并先核验 V4.5；只在本次成功创建的随机 schema 内操作合成数据，不创建／删除 database。提交、Abort、失败批次原子回滚与类型往返结束后逐一清理已知测试表，以 RESTRICT 删除自有 schema 并验证零残留；失败不自动重试写入。协议回归与原生认证分别报告，不互相替代。
- Manager 派生任务定义、语义唯一约束、资源绑定与资源回收的持久化契约由 `make test-manager-postgres` 在真实 PostgreSQL 中覆盖；同一门禁的 Service 用例依赖 PostGIS，验证生成目标的 3857 类型声明、2D／Z／M／ZM 保留、空目标校验、未声明旧目标拒绝及无内容 SELECT 权限的目录核验，清理自建 Schema 与事务内角色并核对零残留。该门禁只允许本地 `addp_test` 或 CI 随 Job 销毁的 disposable database；CI 复用固定摘要的 PostGIS 15-3.4 镜像。同一门禁使用独占 Meilisearch 验证技术与正文快照任意顺序并存、重复提交、空值清除及单指纹删除；本地标准脚本自动创建临时容器并在退出时删除，CI 使用随 Job 销毁的固定摘要 Service，禁止连接开发内容索引。
- Orchestrator 的独立进程故障回归归入既有 `make test-orchestrator-postgres`：测试进程运行正式监督器，在提交与等待阶段分别强制终止持有租约的运行者，再由新进程验证过期失败收敛、不重发请求、旧租约写入拒绝、子执行引用保留及唯一终态事件。HTTP Provider 是受控夹具，因此不作为 T4 真实拓扑验收。Go 测试自动发现和现有 Hosted PostgreSQL Job 覆盖同一入口，无新增基础设施依赖；子进程和当次数据库事实必须在成功、失败路径清理并核对残留。

Spark 发布、原生转换、关系型写入及血缘采集器的专项回归见[Owner 补充门禁](Owner补充门禁.md#addp-owner-补充门禁)；Hosted 跨模块写入失败断言见[关系型 SQL ETL 场景](scenarios/同步与引擎消费.md#transfer-relational-sql-etl)。

## T3

T3 的 PR 主路径使用独立端口、受控 API 夹具和非个人登录态。真实 System、Gateway、owner Backend、真实身份与数据源的浏览器链路归入 T4，不与确定性浏览器测试混跑。

确定性 Playwright 统一通过 `scripts/test/frontend-browser-gate.mjs` 启动，模块 `package.json` 的 `addpBrowserTest.fixtures` 只声明夹具 owner、可选 base 和就绪路径。启动器每轮分配回环临时端口，并保留端口租约直到退出，避免同机门禁在探测与 Vite 绑定之间选择同一端口；实际绑定仍使用 `--strictPort`，外部抢占时明确失败，不复用其他服务。各 Playwright 配置使用 `common-frontend/basic/src/utils/browserTestIsolation.mjs` 的 `withBrowserTestIsolation`，由共享实现统一生成 CLI、代理环境、baseURL、就绪地址和独立结果目录；断言与跨模块夹具通过 `browserTestOrigin` 获取当轮地址，不保留固定端口路径。每个 Vite `webServer` 设置 `ADDP_E2E=1`、回环 host、`reuseExistingServer: false` 和 `gracefulShutdown: { signal: 'SIGTERM', timeout: 5000 }`。Vite 继续使用共享 `withFrontendTestIsolation` 关闭 HMR，缓存与 owned PID 记录置于当轮运行目录，清理前核验当轮进程标识，旧 PID 记录不得授权停止无关进程；成功、失败及 SIGINT/SIGTERM 路径清理当轮进程、缓存、运行目录和端口租约，成功删除结果目录，失败保留独立截图、trace 与非敏感运行清单。CI 从 `${runner.temp}/addp-<owner>-playwright-results-*/` 收集当轮失败证据。登记检查在 `make test-platform` 中拒绝旧启动路径、模块自行覆盖隔离字段、缺失共享 Vite 隔离及跨模块夹具依赖遗漏；共享库单测覆盖并发、失败和中断清理。Online T4 的专用部署配置不套用此确定性夹具规则。

固定源码副本可以通过符号链接复用已安装的第三方依赖，但共享前端源码必须属于当轮源码输入。`withFrontendTestIsolation` 在 `ADDP_E2E=1` 时统一将 `@addp/common-frontend` 定位到该 helper 所在源码树的共享库根目录，保留模块的具体子路径 alias，避免依赖链接把共享认证和组件解析回另一份工作区，造成同页双实例。非测试模式保持原配置；共享单测覆盖对象／数组 alias 与已有配置保留，消费模块浏览器门禁覆盖实际认证和选择交互。

需要验证真实 HMR 的端口集成测试也必须设置 `ADDP_E2E=1`，通过 `ADDP_BROWSER_RUN` 提供当轮临时 `runtimeDir`，并显式声明 `hmr: true`。共享 `withFrontendTestIsolation` 只为这类探针保留原 HMR 配置，缓存、源码定位、PID 登记及退出清理仍走同一隔离实现；不得用 `ADDP_E2E=0` 绕过隔离。Console 的 `devPorts.test.js` 验证 Console／System 的实际 HMR 代理、各自缓存归属及退出清理，由既有 `make test-console-frontend` 和 Console CI 自动发现。

浏览器测试重点证明布局、路由、权限反馈、状态恢复、关键交互和响应式行为，不重复后端已经覆盖的全部字段或业务规则。

前端矩阵 Job 按 `playwright: true` 声明统一上传失败输出目录，产物按模块、工作流运行与 attempt 区分。运行浏览器门禁的步骤通过 `TMPDIR` 对齐测试临时目录与上传步骤使用的 `runner.temp`。System 浏览器门禁保留失败时的 trace、截图与页面上下文；角色分配用例分阶段确认角色选择、下拉菜单关闭、授权原因和提交条件，避免只在最后的按钮点击处报告超时。
