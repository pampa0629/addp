## T0-T1

GeoPython原生长门禁必须在每个失败发生时即时输出完整nodeid、setup/call/teardown阶段及现有traceback，再继续原定测试集合；仍保留最终pytest汇总和非零结果。不通过提前停止、筛除原用例、新增重试或延长既有Linux Job 60分钟预算取得通过。即时诊断由唯一 conftest 报告 hook 实现；并行 Worker 的报告必须由控制端即时输出，不能依赖 Worker 中不存在的终端记者。串行及分布式 setup/call/teardown 控制都须证明诊断早于后续用例报告，标准Make入口及CI自动发现不变；用独立子pytest中的“先失败、后续测试继续”控制验证诊断先于后续执行出现。

GeoPackage 的顶点提取 CRS 拒绝夹具固定使用标准 `srs_id=-1` 的未定义笛卡尔 SRS，独立核对 `gpkg_contents`、`gpkg_geometry_columns`、SRS 记录和 OGR 原生读取事实，不依赖 `CreateLayer(None)` 的版本默认值。OGR 可返回合成工程 CRS，但按[文件载入契约](../workflow/矢量算子契约.md#load-文件字段类型契约)，GeoDataFrame 的 CRS 必须为 `None`。原 CRS 拒绝诊断、下游不保存、三份成果的独立 OGR 核验及源／已有成果不变断言保持。独立载入回归同时验证 0 号未定义地理 SRS、双图层精确绑定和无 EPSG 标识的自定义 CRS。标准定义见 [GeoPackage Requirement 11](https://www.geopackage.org/spec/#r11)。此为原生确定性验证，不扩大实际 Hosted T4 证据。

指标部署的 Business PostgreSQL Compose 只读渲染仍使用原命令和单次15秒期限，不重试或放宽只读挂载、禁用自动创建认证目录的断言。失败时仅输出固定阶段、启动／等待／回收耗时、退出状态与有界的自有Docker／Compose进程树状态；复用部署发现的有界proc读取和等待白名单，不输出命令行、环境、原始配置或stderr、端点、凭据、路径或PID。测试命令使用独立进程组，超时后仅终止该组并限时回收直接子进程，不扩大配置渲染期限、不接管Docker daemon。正常通过保持静默；超时、取消、非零退出和清理未确认都不得计为成功。进程树证据只用于区分卡住的层级，不据此推断Docker繁忙或配置权限根因。确定性负例和原真实Compose检查沿既有指标配置准备入口及 `make test-dev-lifecycle` 自动发现，原生采样T2和Linux复发结论仍分别验证。

Metrics T2 的固定窗口探针将依赖准备／测试二进制编译与真实执行分别计时：测试产物只放当次私有工作目录，准备最多 180 秒；原固定窗口执行上限保持 60 秒，显式 Go 超时同为 60 秒。编译失败或超时禁止执行遗留产物，执行失败／超时不得重试或计通过；仍完整执行 CPU、进程、HTTP、磁盘、IO、网络、文件系统及 inode 断言。Job 20 分钟与退出清理边界不变，新增计时和失败拒绝回归沿原 Metrics 标准入口运行。

### Go HTTP 追踪第一批本地验收

本节按验收职责归组，保留原标题供旧链接定位。Trace、HTTP 质量与本机窗口的产品规则分别以[Trace 契约](../addp平台运行观测规范.md#65-分布式追踪与日志关联二期第一批)、[HTTP 质量契约](../addp平台运行观测规范.md#64-http-接口质量分阶段接入)和[正式身份本机闭环](../addp平台运行观测规范.md#正式身份的本机隔离闭环)为准；本节只补充测试断言。实际结果查[Monitor 历史证据](evidence/Monitor历史证据.md)。

下列确定性回归复用既有 owner、runner 和 CI 自动发现，不启动真实服务、安装依赖或发起新验收窗口。真实 T2、本机正式身份、Hosted T4、容量及长时留存分别报告；未运行、失败和跳过均不算通过。原失败必须保留，诊断不得增加重试、补读、业务请求或等待预算，不根据后续通过反推根因。摘要仅用有界闭集字段，不保留命令、路径、端点、凭据或原始错误正文。各项额外限制如下。

#### Trace 传播、查询与容量

- Go T1：Gateway 重置外部上下文，内部 Context／流式响应正确传播，外域重定向剥离上下文；验证有限属性与敏感值反例、异常结束／4xx、满队列及导出失败不阻塞业务。日志核验规范 ID、精确过滤、游标筛选绑定及独立正文权限；不保留无 Context 的旧客户端重载。
- 查询 T1：单请求四并发，全部请求及 System 裁决共用八个活动上游预算；覆盖主体限额、结果顺序、超时／失败取消、累计 Span 上限，任何错误不返回部分数据。容量抽查必须一次经当前 User 查询二十条链，每条五 Span／两条匹配边，整次五秒；不得拆小查询或减样本。
- `make test-monitor-traces`：一次性 TLS Alloy／Tempo／MinIO 与日志链，真实 Go → Python → Go，核 Server／Client Span、实际 120 秒尾采样、Tempo／Loki 关联、调用边、故障和停止恢复、TLS／身份拒绝、普通与异常／慢请求优先、队列／容量缺口、无敏感属性和零残留。受控身份不替代密码／MFA T4，不使用个人服务或秘密。
- 显式容量入口 `make test-monitor-traces MONITOR_TRACES_TEST_ARGS=--capacity`：沿[容量契约](../addp平台运行观测规范.md#隔离容量基线)执行 20 分钟负载，普通 T2 不隐式执行。保留真实 120 秒尾采样、自然落盘和 72 小时配置；不缩短保留或直写对象，短测不证明 72 小时实留。
- Python 同步链：Common Python、Agent／Copilot 的唯一 ASGI／HTTPX／日志内核覆盖并发上下文、合法父子关系、外域重定向、流式最终 body／EOF／关闭、取消及发送失败、敏感属性／异常正文、Ready／认证拒绝和关闭／配置失败。不开全局自动 instrument，不外推异步／SQL 或全量 HTTP 质量。
- Python 证书夹具：当次私有 OpenSSL 配置、显式 `req -config`、子进程局部 `OPENSSL_CONF`，不污染父环境、不用系统默认或 `/dev/null` 长期路径。沿 `make test-common-python` 验真实 mTLS／官方 protobuf、CA／叶子用途及名称、身份和隐私投影、无重试重定向、每次接收恰好一次、2 秒导出和原 flush／退出预算；`force_flush` 不等于投递成功。测试诊断仅封闭异常类别／TLS 验证码，不改产品软依赖或吞错路径，退出清材料。
- Console iframe T3：查询、详情、调用关系、日志跳转、URL 恢复、双语、无权限／撤权清空及迟到响应隔离；Tempo／Loki 原始 DTO 不进浏览器。

#### HTTP 质量、来源与页面

- Common Python／Agent／Copilot 原入口验证唯一中间件所有权和正式注册：Trace 开关独立、全量完成计数、最终发送／未完成失败／完成后后台错误、活动请求回落、模板及敏感属性；512 组合或 4 MiB 超限整源失败，独立 Registry 不带默认 CPU／RSS。严格部署输入、私有证书／mTLS／端点拒绝、启动失败和退出回收均须覆盖。
- `make test-monitor-metrics MONITOR_METRICS_TEST_ARGS=--case=http-quality` 及默认 all 覆盖真实 SDK／HTTP SD／mTLS／Prometheus、Monitor 完整一分钟窗口、缺样／身份互串拒绝、规则打开／签名重试／恢复和零残留。原 Trace 回归独立报告；共享 Python、消费者、来源夹具、依赖及部署输入须纳入既有登记，不新增 Hosted 旁路。
- Go／Python 调度内核：失败耗尽后仍保留全部恢复额度；晚切换也可恢复，切换不突发、不补发／借额／重复启用；核三源总量与固定模板轮转。退出预算回执覆盖早期失败、停源／未启动来源、缺失／损坏／不一致和敏感字段拒绝。停流零分母或缺样不得恢复同一告警，固定窗口由原 promtool T2 验证。
- Python 启动回执覆盖复制、安装、导入、配置、指标／HTTP 就绪和身份发布；安装诊断 64 KiB。首来源失败仍检查两源，停止／退出或恢复发现失败不得覆盖首败。导入回归先建立不存在路径的负缓存，再模拟安装生成模块并经真实 bootstrap 使其可导入，不执行 pip 或借已有依赖。ImportError 仅保留白名单发行包版本与固定组件，不输出任意模块路径；真实 shell cleanup 配 Docker 替身证明唯一 down 带 `python-http` profile、私有目录已删且原失败仍非零。
- 两源唯一 256 MiB tmpfs 必须显式 `exec/nosuid/nodev`；noexec、缺标志或读取失败均禁止安装／启动，本地扩展加载成功后才导入框架。回执核实际挂载布尔值、扩展成功和白名单组件／版本。依赖提取使用各消费者当前正式 HTTP 四项声明，保留 extras／约束原文，拒绝缺项／重复／串用，两份 requirements 均是固定输入。挂载单项通过不代表 Linux 实链通过。
- 页面共享断言由受控夹具和真实用例共用：七项汇总、六项排行及顺序、自然趋势有效点和画布数值，篡改数值／身份、无有效趋势及陈旧 Agent 均拒绝。先等宿主与模块 canonical query 一致再重载，核单 iframe、控件和实际查询。存活／停源分回执；同页刷新清旧数据、详情提示、空汇总／排行／趋势及 Agent 新鲜度分别核验。来源退出在线列表时不强求新增离线行。
- 停源历史沿 Common 客户端、Monitor Go／Swagger 和前端门禁，核当前用户精确授权、注销／租约、未知／冲突来源、同地址换实例、绝对离线前区间、登记前／保留边界、缺样与真零、URL 刷新及撤权清图。Linux T2 另验已存 Prometheus 样本在停源后经原趋势查询读取，不把存活历史或空数据记为停源历史通过。

#### 资源守卫、采样与清理交接

以下回归沿 `make test-infra-runtime-log-lifecycle`、既有 Metrics 配置门禁和 HTTP／Trace local runner，实际 Linux 结果由原自然 HTTP Job 独立验证。夹具只用临时小文件、受控原生子进程与时钟，不运行 Docker 或真实 Go 编译负载。Linux／Darwin 适配与模拟结果分列；未覆盖平台不算通过。

| 测试主题 | 必须保留的断言与限制 |
| --- | --- |
| 守卫与目录错误 | 固定容器枚举、inspect、卷／私有目录步骤、失败子类／退出码，超限保留数值和维度；不忽略短命容器。原同一次 `du` 的四秒期限内，仅分类已捕获 ≤4 KiB stderr，覆盖消失、权限、I/O、混合、未知、空及超预算；只有私有目录命令设 C locale。命令耗时、完整采样耗时和开始时余额分列，非零不重试。原 Job 成败均归档预算报告七天，报告缺失不是完整证据。 |
| 路径归属 | GNU／BSD 严格解析、当次相对身份 SHA256 与 project 隔离；六个固定准备目录及任意深度后代按首层精确匹配，拒绝未知／近似／嵌套同名、穿越、引号、控制字符、符号链接。≤4 KiB／八行，去重及混合／超限拒绝；保持原 sample 首个 du 失败、命令数和后续统计停止。旧 other 不回填，新分类不证明删除者。 |
| 采样／清理锁 | 真实私有文件锁证明采样先开始时不删资源，清理先发布时不新增读取；首读失败后仍失败并释放锁等待原清理，不重采样或再终止已清理进程。锁等待和回执读取共用四秒，清理等待不重置 120 秒。Shell 继承锁描述符须覆盖 Python 退出后的删除，退出即释放；错归属、超时或获取失败不走无锁备用路线。 |
| 四阶段编译 | 唯一 `compile_stages` 顺序为 `process_source→resource_windows→http_query→http_alert`，无旧字段；原子回执保留前序、归属和清理字段，拒绝重复、越序、倒退、未知或失败后继续。真实 shell 替身及正式 probe 函数覆盖成功、非零／信号、超时／取消未完成。公共窗口及两类 HTTP 编译共用受管内核；采样快照与最终观察分列，缺任何完整阶段不得通过，取证失败不覆盖编译首败。 |
| 稳定读取与恢复 | 组出生、UID、会话归属、启动自停登记、停止确认和全量读取；未知组不发信号。锁阻止新阶段启动／旧组回收，元数据不能提前丢失；同四秒内预留 50 毫秒，finally 恢复，取消／超时先恢复再终止回收。后代消失但根仍在时统计完整；根缺失、确认不稳、余额不足或失归属均失败，恢复错误不覆盖首败。 |
| 停止等待 | 逻辑时钟验证 D／T 混合至截止仍拒绝且恢复，单次读耗尽与多次快返分列，核成员变化与最后完整快照；未知状态归 other，不增读取／信号。100 毫秒前或无 D 不读等待位置；之后每次暂停至多一组、≤64 成员、每份 ≤128 字节且只读 D。固定 proc 目录前后核身份／状态，拒绝复用、变更、消失、权限／符号链接／畸形；白名单／other／0／不可用、角色和 D 到停止计数均脱敏。截止仍有 D 的重放必须失败、恢复且不进入 du，候选类别不作根因。 |
| 卷检查点 | 同一原 exec 内唯一进入／返回标记，完整成功不改变统计和命令数；无标记、仅进入、返回后仍超时、重复／逆序／畸形／截断或读失败均拒绝。输入 ≤4 KiB、摘要 ≤512 字节；保留完整失败边界和取消／诊断耗时，不产生成功样本或继续私有目录扫描，标记不能替代 du／数字／配额核验。非卷测量或其他线程不读残片，到期不得靠输出处理变成功。 |
| 卷消失与等待摘要 | 同一挂载表核卷根／后代、多卷／重复／混合／越界／截断，≤16 条／4 KiB 输入、512 字节摘要。取消前冻结准确构建阶段与失败时间，不追加正文。命令等待覆盖即时退出、连续 TimeoutExpired、累计／最大非负超出量、早返零、余额 <50 毫秒按实际 timeout、创建前失败；取消的一秒等待排除。摘要仅四个固定整数、≤512 字节，不含逐次列表；合法多线程 CPU 可大于墙钟，不能据此定 daemon／VM 根因。 |
| 窗口夹具隔离 | 提取正式函数时用私有环境快照，排除外层 `ADDP_HTTP_BUDGET_RECEIPT`，不读／建／锁外层回执；受管分支自行建回执。覆盖外层尚未发布及已有他轮内容，父环境与文件／锁不变。`resource_windows` 使用原 Go 参数、环境、cwd、180 秒准备和 60 秒执行；缺阶段／前败／越序及信号／超时不执行二进制、不补造事实。暂停新阶段期间写入不变、du 失败仍失败、finally 恢复及超时回收；原四秒／1200 秒／配额保持。 |

#### 产品构建与命令关联诊断

以下只消费受控 BuildKit 字节、代理环境替身和已有归档；不执行 apt、网络探针、镜像构建或额外 Docker 命令，不读取代理日志补填。确定性通过只证明诊断契约，历史 APT 根因、删除者、繁忙稳定性及产品闭环仍按实际证据判断。

| 测试主题 | 必须保留的断言与限制 |
| --- | --- |
| APT 归属与分类 | 仅精确 `product_image` 命令的唯一失败 `RUN apt-get` 步骤；排除 CACHED、其它步骤、成功输出和包名／版本／哈希中的 407／502。索引／deb／dpkg／未知及固定错误类别分别验证；官方源协议／仓库／套件、FROM 缺失／多候选、三层代理来源和恶意 URL 脱敏。≤128 KiB 输入、4 KiB 摘要及集合限额，超限明确未知，不截断冒充完整；原首因／哈希保留。 |

T0-T1 必须：

- 不依赖已经启动的 ADDP 服务。Infra 生命周期单测必须同时隔离容器状态与宿主机监听查询，使用夹具内的端口事实；真实端口探测由专门的端口解析回归覆盖，不能让 mock Docker 与真实 lsof 混合决定启动行为。观测平台夹具必须清除父进程的个人观测选择、部署路径和传输配置，再应用用例显式输入。

### 线拓扑手工容量基线

标准入口为 `make test-vector-topology-capacity`，仅由 `.github/workflows/vector-topology-capacity.yml` 手动选择；不进入日常／夜间大负载，不重复业务 T4。确定性小样本、篡改、资源／profile／身份／清理和登记反例沿 `make test-geopython-workflow`、`make test-vector-topology-capacity-runner` 与既有 Python CI 覆盖。容量结果只定位固定构造的通过档与首个超限档，不认证精确最大容量、稳定吞吐、任意复杂线网或生产 SLA。

#### 所有容量 profile 的共同约束

- 固定源码、产品镜像、依赖和 Runner；标准镜像构建后，每档独立默认入口 Runtime 容器，网络隔离、不发布宿主端口、不启动 System／个人服务。同容器 worker 走唯一生产 load／检查／计算／save 路径，这是 Native 组件容量，不是认证 HTTP 链。
- 串行、每档一次，4 CPU／2 GiB，memory-swap 等于 memory（`swap.max=0`）。worker 启动至生成、完整读取、源 oracle、计算、全部保存、独立 OGR 全量重载和末轮源不变核验共 180 秒；构建／Runtime 就绪另记，Job 90 分钟。超时终止当档独占容器，不重试、扩预算、减样、跳过完整 oracle 或优化算法以制造通过。
- 原始数据、字段宽度、显式业务 ID、EPSG:3857 整数 XY 按矩阵固定；FID 不替代业务 ID。闭式预期不得调用生产几何／求交／去重／图遍历算法。核全部原坐标、几何类型、XY 维度／M 标记／有效性、来源／顺序／方向、原生 Schema／类型、NULL、Int64、Boolean subtype 和 CRS，源内存及原文件哈希前后不变。
- 流式 OGR 重载每表一次核字段名／顺序／类型／CRS，绑定字段索引、原生 getter 与 NULL 状态，逐行核全部属性精确值／Python 类型及 FID。固定属性与编码器只初始化一次；保持原 `sort_keys/ensure_ascii`、空格及实际 OGR／浮点值，完整摘要须与冻结旧标量参考逐字节一致。旧参考仅作小样本等价测试，门禁无新旧读取切换。正反例含 typed NULL、大 Int64、Boolean、Unicode 和真实污染，不得在源检查提前失败冒充目标阶段拒绝。
- `grade` 物理为 OGR Integer64，`load` 后无 NULL 也须为 pandas `Int64`，不接受 NumPy `int64`／Float64／object 兼容路线；继承字段保持 dtype，生成字段另按算子契约。源摘要包含索引类型／名称／值，小样本核大于 `2^53` 的整数、NULL 和 Boolean 贯穿加载、全部输出与 OGR。详见 [`load` 字段类型契约](../workflow/矢量算子契约.md#load-文件字段类型契约)。
- 保存源码及实际加载编译代码绑定、各阶段耗时、worker 峰值 RSS／进程高水位、cgroup CPU／OOM／swap、原始 0.25 秒外部样本与失败阶段。容器 `memory.peak` 是自默认入口启动的累计内核峰值，不能称纯计算或阶段峰值；阶段 `memory.current` 最大采样值只称采样峰值，短阶段没样本须写未观测。
- 保存完整校验摘要、文件大小／SHA、checkpoint、失败日志和清理证明；合成大文件及旁文件每档退出后删除，仅存摘要不表示可离线物理重读。按归属清本轮容器、registry、唯一标签及工作目录，保留普通构建缓存，不全局 prune。超时／OOM／结果不符均失败，清理成功继续余档，清理失败停止；任一未通过使总门禁非零，不用部分结果认证整套通过。

- 报墙钟／计算／CPU 秒／累计内核峰值的中位数及范围，保留 B−A、C−B、C−A 和负差。小样本及 Runner 漂移限制因果解释，任一失败／清理失败不得认证整组。

`profile=comparison` 只量化分批求交旧／新净收益：同 Job／Runner／镜像依赖、十万稀疏自叠、A 模式，旧新／新旧交错四对、八个独立默认容器，共同预算不变，不重试。

- 旧实验镜像从本轮私有 registry 的精确产品 manifest digest 派生并核 image ID；只以 `8a3006670e7f6cfaddf018253515ccb37ab5bc78` 的标量收集器替换当前收集器，移除实验镜像不使用的分批常量／私有 helper，其余源码不变。当前分批定义精确匹配 `adb605b67676bc4396307bc9ea7449c63de183bc`。
- CI `fetch-depth: 0`；缺历史即失败，不回退。旧代码仅作测试归档及临时派生输入，不进产品或运行时兼容参数。保留两份完整模块、固定来源／哈希及仅三定义变化的 AST 核验；旧 RootFS 为原全部层加唯一 COPY，入口／环境／cwd 一致，worker 原预算内读回实际模块／收集器哈希。
- 错绑、额外代码差异或版本／逻辑输入／完整成果摘要不一致均拒绝。八次全部通过且清理成功后才汇总墙钟／计算／CPU 秒／内核峰值的中位数和范围，保留每对旧减新、比例／降低百分比及非计算阶段，正负差均保留。历史 Runner 不替代受控对照，小样本／频率／缓存／漂移限制外推；不认证其它拓扑、密集／长线或生产 SLA。

## T2

T2 使用真实但可丢弃的基础设施，并满足：

- CI Job 使用独占 Service 和随 Job 销毁的数据库。
- 托管外部服务的 owner gate 必须在脚本头声明 `# ADDP_T2_SERVICES=<service,...>`；模块门禁、CI 注册和后续新增数据库类型都消费该声明，不按数据库名称维护发现分支。
- owner 自建的临时服务通过 `ADDP_T2_OWNED_SERVICES` 和 `ADDP_T2_COMPOSE_FILE` 登记，必须拥有独立 Compose 项目、回环随机端口以及退出清理和零残留检查。镜像使用固定 tag 与 digest；需要沿用仓库源码构建时，允许引用仓库内的单一 Dockerfile，但外部基础镜像须固定 tag 与 digest，Git 源码须在同一构建步骤中核对固定提交，构建上下文须位于仓库内，Dockerfile 与本地复制输入须登记到 `ADDP_T2_INPUT_FILES`；目录声明以 `/` 结尾，递归覆盖该仓库子树的新增、修改和删除，构建检查与变更选择共用同一覆盖判定。登记检查拒绝仓库外路径、构建参数覆盖和未固定源码；门禁必须实际构建，不接受开发环境已有同名镜像作为构建证据。
- 必须由调用方注入连接条件的 owner gate 同时声明 `# ADDP_T2_REQUIRED_ENV=<name[|alternative],...>`，逗号表示“同时需要”，竖线表示等价的安全前置条件。`make test-module` 与 `make test-changed` 必须在执行任何 T0/T1 前一次性检查全部所需条件，缺失时失败关闭并给出 owner、变量及安全测试环境提示；`--dry-run` 仅展示计划，不要求真实连接条件。CI 登记检查必须确认对应 Job 显式提供每组条件中的至少一个变量。
- 需要 owner 持有合法 License 或受控介质的门禁必须声明 `# ADDP_T2_OWNER_MANAGED=<runtime>`，只通过 owner 受控 Linux 主机上的 `make test-integration-owner-managed` 人工执行，不进入 GitHub Actions、普通 `make test-integration` 或 macOS 定时巡检。登记检查必须拒绝 workflow 调用这类目标及其聚合入口。脚本必须验证官方介质与 License SHA-256、拥有 disposable 容器全生命周期并验证零残留。
- 本地共享 `addp-postgres` 只允许使用 `addp_test` 与 `addp_iam_test`，并且只能通过根 `Makefile` 或 `scripts/test/` 的标准入口操作。
- 本地 PostgreSQL T2 门禁必须由调用方显式提供测试 DSN 或端口；不得在未提供时回退到 `.env` 的首选端口。调用方先用 `bash scripts/infra/status.sh` 核实 ADDP Compose 实际映射。标准 PostgreSQL 门禁在执行测试或清理前，必须核对本地回环连接的端口与当前工作区 `addp-postgres` 的实际 Compose 映射一致，且 database 仅为 `addp_test` 或 `addp_iam_test`；容器不存在、归属不符或映射不一致时直接失败，不根据 `.env` 猜测。门禁前置检查不得输出一个写死首选端口的可复制连接命令。GitHub Actions 的独占 Service 与辅助 macOS CI 的独占临时 PostgreSQL 使用各自入口显式配置的端口和 database，不套用本地共享 Infra 校验。
- 禁止为单次验证直接创建或删除数据库；现有标准入口不能满足隔离时，先完善入口及自动清理。
- 门禁在任何破坏性动作前校验数据库身份，拒绝开发库、生产库或不满足 owner 安全约束的连接。
- 每个场景只清理自己拥有的 Schema 或带唯一运行标识的事实，并验证零残留。
- 门禁拒绝意外 Skip，避免“命令成功但测试未运行”。
- Common PostgreSQL 的默认 `make test-common-postgres` 保持完整门禁，同时覆盖表写入准备、安全列演进和空间结构拒绝。真实低权限账号必须在没有数据库级 CREATE 权限时完成已有 schema 下的建表与 upsert 准备；缺失 schema 仍须按数据库权限拒绝或创建，测试结束清理本轮 schema、账号及授权并验证零残留。仅验证查询读取集合、输出血缘及查询会话值表示时，可在同样的显式测试连接条件下运行 `bash scripts/test/common-postgres-gate.sh --test query-read-set`；该分组包含真实资源改名及同名重建的定位身份案例，以及 BYTEA 的 NULL／空值／非 UTF-8／别名／表达式／跨批次保真和文本、精确 numeric、JSON 表示回归，保留数据库身份检查、Skip 拒绝和场景清理。分组结果只证明所选范围，不替代完整 T2 门禁；CI 继续使用无分组选项的默认入口。
- HighGo 写入沿用 Common PostgreSQL 标准入口：默认完整门禁及 `bash scripts/test/common-postgres-gate.sh --test highgo-write` 在 disposable PostgreSQL 上回归独立 HighGo 驱动和共享写入协议，由既有 Hosted Common PostgreSQL Job 覆盖。`--test highgo-write --highgo-native` 为显式原生认证，必须注入全部 `ADDP_TEST_HIGHGO_*` 连接字段，强制 TLS 并先核验 V4.5；只在本次成功创建的随机 schema 内操作合成数据，不创建／删除 database。提交、Abort、失败批次原子回滚与类型往返结束后逐一清理已知测试表，以 RESTRICT 删除自有 schema 并验证零残留；失败不自动重试写入。协议回归与原生认证分别报告，不互相替代。
- Manager 派生任务定义、语义唯一约束、资源绑定与资源回收的持久化契约由 `make test-manager-postgres` 在真实 PostgreSQL 中覆盖；同一门禁的 Service 用例依赖 PostGIS，验证生成目标的 3857 类型声明、2D／Z／M／ZM 保留、空目标校验、未声明旧目标拒绝及无内容 SELECT 权限的目录核验，清理自建 Schema 与事务内角色并核对零残留。该门禁只允许本地 `addp_test` 或 CI 随 Job 销毁的 disposable database；CI 复用固定摘要的 PostGIS 15-3.4 镜像。同一门禁使用独占 Meilisearch 验证技术与正文快照任意顺序并存、重复提交、空值清除及单指纹删除；本地标准脚本自动创建临时容器并在退出时删除，CI 使用随 Job 销毁的固定摘要 Service，禁止连接开发内容索引。
- Orchestrator 的独立进程故障回归归入既有 `make test-orchestrator-postgres`：测试进程运行正式监督器，在提交与等待阶段分别强制终止持有租约的运行者，再由新进程验证过期失败收敛、不重发请求、旧租约写入拒绝、子执行引用保留及唯一终态事件。HTTP Provider 是受控夹具，因此不作为 T4 真实拓扑验收。Go 测试自动发现和现有 Hosted PostgreSQL Job 覆盖同一入口，无新增基础设施依赖；子进程和当次数据库事实必须在成功、失败路径清理并核对残留。

Spark 发布、原生转换、关系型写入及血缘采集器的专项回归见[Owner 补充门禁](Owner补充门禁.md#addp-owner-补充门禁)；Hosted 跨模块写入失败断言见[关系型 SQL ETL 场景](scenarios/同步与引擎消费.md#transfer-relational-sql-etl)。

## T3

T3 的 PR 主路径使用独立端口、受控 API 夹具和非个人登录态。真实 System、Gateway、owner Backend、真实身份与数据源的浏览器链路归入 T4，不与确定性浏览器测试混跑。

确定性 Playwright 统一通过 `scripts/test/frontend-browser-gate.mjs` 启动，模块 `package.json` 的 `addpBrowserTest.fixtures` 只声明夹具 owner、可选 base 和就绪路径。启动器每轮分配回环临时端口，并保留端口租约直到退出，避免同机门禁在探测与 Vite 绑定之间选择同一端口；实际绑定仍使用 `--strictPort`，外部抢占时明确失败，不复用其他服务。各 Playwright 配置使用 `common-frontend/basic/src/utils/browserTestIsolation.mjs` 的 `withBrowserTestIsolation`，由共享实现统一生成 CLI、代理环境、baseURL、就绪地址和独立结果目录；断言与跨模块夹具通过 `browserTestOrigin` 获取当轮地址，不保留固定端口路径。每个 Vite `webServer` 设置 `ADDP_E2E=1`、回环 host、`reuseExistingServer: false` 和 `gracefulShutdown: { signal: 'SIGTERM', timeout: 5000 }`。Vite 继续使用共享 `withFrontendTestIsolation` 关闭 HMR，缓存与 owned PID 记录置于当轮运行目录，清理前核验当轮进程标识，旧 PID 记录不得授权停止无关进程；成功、失败及 SIGINT/SIGTERM 路径清理当轮进程、缓存、运行目录和端口租约，成功删除结果目录，失败保留独立截图、trace 与非敏感运行清单。CI 从 `${runner.temp}/addp-<owner>-playwright-results-*/` 收集当轮失败证据。登记检查在 `make test-platform` 中拒绝旧启动路径、模块自行覆盖隔离字段、缺失共享 Vite 隔离及跨模块夹具依赖遗漏；共享库单测覆盖并发、失败和中断清理。Online T4 的专用部署配置不套用此确定性夹具规则。

固定源码副本可以通过符号链接复用已安装的第三方依赖，但共享前端源码必须属于当轮源码输入。`withFrontendTestIsolation` 在 `ADDP_E2E=1` 时统一将 `@addp/common-frontend` 定位到该 helper 所在源码树的共享库根目录，保留模块的具体子路径 alias，避免依赖链接把共享认证和组件解析回另一份工作区，造成同页双实例。非测试模式保持原配置；共享单测覆盖对象／数组 alias 与已有配置保留，消费模块浏览器门禁覆盖实际认证和选择交互。

需要验证真实 HMR 的端口集成测试也必须设置 `ADDP_E2E=1`，通过 `ADDP_BROWSER_RUN` 提供当轮临时 `runtimeDir`，并显式声明 `hmr: true`。共享 `withFrontendTestIsolation` 只为这类探针保留原 HMR 配置，缓存、源码定位、PID 登记及退出清理仍走同一隔离实现；不得用 `ADDP_E2E=0` 绕过隔离。Console 的 `devPorts.test.js` 验证 Console／System 的实际 HMR 代理、各自缓存归属及退出清理，由既有 `make test-console-frontend` 和 Console CI 自动发现。

浏览器测试重点证明布局、路由、权限反馈、状态恢复、关键交互和响应式行为，不重复后端已经覆盖的全部字段或业务规则。

前端矩阵 Job 按 `playwright: true` 声明统一上传失败输出目录，产物按模块、工作流运行与 attempt 区分。运行浏览器门禁的步骤通过 `TMPDIR` 对齐测试临时目录与上传步骤使用的 `runner.temp`。System 浏览器门禁保留失败时的 trace、截图与页面上下文；角色分配用例分阶段确认角色选择、下拉菜单关闭、授权原因和提交条件，避免只在最后的按钮点击处报告超时。
