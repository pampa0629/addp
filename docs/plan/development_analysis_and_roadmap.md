## 1. 研发现状分析

### 1.1 整体架构状态
ADDP 已经构建了一个非常完整的微服务体系，涵盖了数据生命周期的各个阶段：
- **数据管理层 (Meta, Manager, Transfer)**: 已成熟。能够完成元数据扫描、数据导入导出和基础管理。
- **计算与编排层 (Orchestrator, Develop, Engines)**: 已具备基础能力。支持工作流编排和 SQL/Notebook 开发。
- **知识层 (Graph)**: 处于**关键突破期**。
    - ✅ **本体建模 (Phase 1)**: 已完成，支持定义实体和关系。
    - ✅ **图探索与可视化 (Phase 3)**: 已完成，基于 G6 实现了交互式浏览器。
    - ✅ **图算法分析 (Phase 4)**: 已完成，支持 PageRank, Louvain 等核心算法。
    - ✅ **图谱构建 (Phase 2)**: 已实现（基于 Copilot 抽取），目前重点在于链路集成。
- **交互层 (Agent)**: 已搭建框架。基于 LangGraph + FastAPI，具备对话能力，但缺乏深度集成 ADDP 业务数据的“专业知识”。

### 1.2 核心矛盾与缺口
目前系统存在一个明显的**“能力断层”**：
- **有“能力”无“链路”**: Graph 模块已具备强大的 Copilot 抽取能力，但构建入口与 ADDP 核心资产（Meta/Manager）之间存在断层。目前依赖手动上传文件，缺乏从“元数据资产 $\rightarrow$ 自动建图”的无缝触发机制。
- **有“壳”无“核”**: Agent 模块虽然能对话，但尚未深度消费 Graph 模块的知识服务（Graph RAG），导致 AI 助手在处理复杂关系查询时仍依赖于简单的 LLM 推理，而非基于事实的知识图谱。

## 2. 后续研发优先级推荐

我建议接下来的研发重心应围绕 **“闭环知识流”** 展开，优先级排序如下：

### 🚀 最高优先级：增强构建链路的自动化与集成度 (Graph Phase 2 增强)
**目标**: 实现从 ADDP 管理的数据资产一键生成知识图谱。
- **关键任务**:
    - **资产集成**: 集成 `meta` 和 `manager` 模块，允许用户直接选择已扫描的资产 $\rightarrow$ 定义抽取规则 $\rightarrow$ 自动触发 Copilot 构建。
    - **结构化建图**: 扩展构建能力，支持从结构化数据库表（通过映射关系）直接转化为图谱节点和关系。
    - **增量更新机制**: 实现当底层数据资产变化时，图谱能够自动或半自动地同步更新。

### 🎯 次高优先级：实现“知识 $\rightarrow$ 智能”的深度集成 (Graph Phase 5 + Agent)
**目标**: 让 Agent 成为知识图谱的自然语言接口。
- **关键任务**:
    - **Knowledge Service API**: 在 Graph 模块中封装一套面向 Agent 的 API（例如：`query_relation(entity1, entity2)`，`get_neighborhood(entity)`）。
    - **Graph RAG 插件**: 为 Agent 开发专门的 Graph Tool，使其在回答问题前先在图谱中检索关系路径。
    - **自然语言 $\rightarrow$ Cypher**: 实现简单的 NL2Cypher 转换，允许用户通过对话执行复杂的图查询。

### 🛠️ 中优先级：增强“分析 $\rightarrow$ 决策”的闭环 (Graph Phase 4 增强)
**目标**: 将图算法的结果转化为业务洞察。
- **关键任务**:
    - 将图算法（如 Louvain 社区发现）的结果回写到 PostgreSQL 或 Neo4j 属性中，方便在 `manager` 模块中进行过滤和预览。
    - 在前端增加算法结果的对比分析视图。

## 3. 建议的实施路线图 (Roadmap)

| 阶段 | 重点 | 核心交付物 | 预期效果 |
| :--- | :--- | :--- | :--- |
| **短期 (1-4周)** | **链路集成** | `Asset-to-Graph-Trigger` $\rightarrow$ `Neo4j` | 用户可以一键将数据库表或文件资产转化为知识图谱 |
| **中期 (4-8周)** | **智能增强** | `Graph-RAG-Tool` $\rightarrow$ `Agent` | Agent 能回答“A 和 B 之间有什么间接关系？” |
| **长期 (8周+)** | **生态融合** | `Meta` $\rightarrow$ `Graph` $\rightarrow$ `Agent` 全链路 | 实现“扫描 $\rightarrow$ 建图 $\rightarrow$ 对话分析”的自动化全流程 |

## 4. 总结

**当前最应该做的事情：全力推进图谱构建与数据资产的深度集成。**

虽然已经具备了强大的抽取能力，但只有将构建入口与 Meta/Manager 资产打通，才能真正实现从“数据管理”到“知识管理”的自动化演进。
