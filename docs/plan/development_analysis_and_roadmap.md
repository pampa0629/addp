# Graph 与 Agent 后续能力方向

状态：候选方向，未作为当前排期或已获准架构改造。已实现的本体 CRUD、图谱构建/材料审核、图浏览、图算法和基础 Knowledge Service API 以[Graph 模块说明](../../graph/CLAUDE.md)为准，不再保存旧“整体成熟度”、阶段完成勾选或按周估算。

## 待确认方向

| 方向 | 当前边界与前置问题 |
| --- | --- |
| 从已管理资源构建图谱 | 当前材料与构建链路已有实现；直接选取 Catalog/Meta 资源、结构化映射和数据变化驱动构建仍须确认来源 owner、读取授权、范围、去重及可重放证据，不能把 Asset 当作技术数据源 |
| Agent 消费 Knowledge Service | 基础 API 已有，正式 Tool/SDK/精确委托、受限输出、权限与评测仍须按[Tool 开放规范](../spec/addp智能体Tool开放规范.md)及[Agent 后续事项](../next/ADDP智能体能力开放体系专题.md)逐项接入 |
| 自然语言图查询 | 先明确只读执行边界、参数化、查询范围、成本预算、错误和证据；不能直接执行模型生成的任意 Cypher |
| 图分析结果复用 | 结果回写或跨运行对比须先确认结果 owner、持久化用途、目标授权与唯一输出契约，不凭算法可运行直接增加业务属性写入 |

Ontology 自有定义与 Graph 当前职责保持现行边界；是否迁移先按[Ontology 后续设计](../next/ADDP%20Ontology最小设计契约.md)另行确认，不把旧路线图当作切换许可。

## 推进与验证

先选定一个有真实用户价值的场景，再确认数据和操作范围、修订概念/规范及实施。复用 `make test-module MODULE=graph`、Agent eval 和各实际 owner 的标准入口；受控模型或 API 夹具不替代真实授权、真实来源和跨模块消费的验收。不重列已经落地的基础 API，不以旧阶段号推导当前优先级。
