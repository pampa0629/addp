# 湖仓一体化设计方案

> 状态：历史方案已收口。当前实现以 provider 化 engine plugin 体系为准。

本文记录湖表识别、扫描和预览的当前结论，不再描述旧的文件系统与对象存储继承方案。引擎接口规范见 [../spec/addp引擎插件接口规范.md](../spec/addp引擎插件接口规范.md)，对象存储/NFS 路径规则见 [../spec/addp存储引擎路径体系规范.md](../spec/addp存储引擎路径体系规范.md)。

## 当前结论

- 对象存储和文件系统分开建模。
- MinIO/S3 使用 `bucket -> prefix -> object`。
- NFS 使用透明挂载根 `root -> dir -> file`。
- 目录发现统一走 `CatalogProvider.ListChildren`。
- 文件/对象读取统一走 `ContentReadableProvider.OpenContent`。
- 湖表识别由 Meta 扫描服务结合 `common/format/plugins/parquet` 完成。
- Manager 湖表预览组合 `CatalogProvider`、`ContentReadableProvider` 和 Parquet 解析能力完成。

## 湖表识别规则

| 形态 | 识别结果 | 说明 |
| --- | --- | --- |
| 目录下包含一组兼容 schema 的 Parquet 文件 | `table` | 目录即表。 |
| 单个 `.parquet` 文件 | `table` | 文件即表。 |
| 非表格文件 | `file` 或 `object` | 按存储引擎语义保留叶子类型。 |

## 模块分工

- Meta：扫描 bucket/root、prefix/dir 和 object/file，识别 table 语义并写入 `meta_item`。
- Manager：展示目录型表格节点，使用 Parquet provider 做预览。
- Develop：通过支持湖表的查询引擎访问湖表。
- Transfer：Parquet 读写属于 Transfer 执行面，后续按 Transfer 模块适配层收口配置来源。
