# ADDP 数据导入后续事项

已实现的导入动作、Transfer sync、私有来源绑定与写后扫描见[任务体系规范](../spec/addp任务体系规范.md#manager-导入的任务与执行边界)及[Manager 资源动作规范](../../manager/docs/数据预览与资源树实现规范.md#4-与导入和导出)。本文只保留未确认增强与验收缺口，不保留旧 connector、内联凭据、固定业务库、耗时排期或示意代码。

## 一、当前范围

现有入口支持 Shapefile ZIP/相关文件导入数据库表，由 Manager 上传并调用 Transfer 正式 User Client 创建和启动 sync；成功接收与 pending 不证明业务写入、扫描、索引或最终页面均成功。当前执行策略和限制以正式契约、能力及 Swagger 为准，不从早期方案宣称全部格式/目标均已支持。

## 二、保留与失败补偿待确认

当前上传源前缀为 `tenant_<tenant_id>/import/<date>/<upload_uuid>/`，实现与回归见[导入服务](../../manager/backend/internal/service/import_service.go)及[来源测试](../../manager/backend/internal/service/import_service_test.go)。[MinIO 初始化](../../scripts/infra/init-minio.sh)中的旧七天规则只覆盖 `temp/`，不能据此宣称当前导入源会七天自动清理。

后续须先确认上传源保留、失败任务重试、未绑定/绑定后失败的补偿，以及正在使用的源与已过期源如何区分，再沿[资源回收规范](../spec/addp-cleanup体系规范.md)实现唯一清理路线。不能直接扩大 bucket 生命周期、清空前缀或删除仍被任务引用的源文件来完成清理。

## 三、后续能力

| 候选 | 实施前确认 | 验收 |
| --- | --- | --- |
| 更多格式 | 复用实际 Format reader、refs 与目标 Provider 能力，不按扩展名注册专用 connector | 按格式/目标覆盖真实读写、编码、空间与拒绝组合 |
| 大文件与分片上传 | 总量、单包/单文件/解压预算、取消及暂存所有权 | 超限、路径、异常包与中断后的有界资源清理 |
| 多文件批量导入 | 每项独立身份、任务/execution、同名冲突及部分失败 | 无覆盖混淆、不伪装整批事务、成功/失败逐项追溯 |
| 进度与历史 | 复用 Transfer/Monitor 事实；确有独立价值后再讨论 import session | 不新增 Manager 通用执行列表或第二套进度状态机 |
| 完整用户闭环 | 同一普通 User、精确目标、正式资源动作 | 上传→写入→Meta 扫描→Manager 发现/预览→Develop locator 读取 |
