# 铁路占耕地面积计算 - 实施计划

## 需求描述

基于 `data/` 目录下的空间数据，实现以下完整链路：

1. **定时数据同步**：将 `data/` 目录下的空间数据同步到业务 MinIO
2. **自动计算**：同步完成后自动触发工作流，计算铁路（30米缓冲区）占用的耕地面积
3. **服务发布**：将计算结果发布为可查询的数据服务

**核心计算逻辑**：
```
railway.shp → buffer(30m) → intersection(farmland.shp) → get_area → 汇总面积
```

**触发机制**：Orchestrator 编排，定时触发（如每日凌晨2点），Transfer 同步完成后自动触发 Python Workflow 计算。

---

## 数据说明

`data/` 目录下相关文件：
- `railway.shp` + 附属文件 - 铁路线数据
- `farmland.shp` + 附属文件 - 耕地数据
- `terrain.tif` - 地形数据（本期不使用）
- `规划用地.shp` 等其他数据（本期不使用）

---

## 整体架构

```
Orchestrator 编排（定时 Cron 触发，每日凌晨2点）
  │
  ├─ Step 1: Transfer 任务（数据同步）
  │    local_directory engine (data/ 目录)
  │      ├─ railway/railway.shp  → MinIO: transfer-data/railway/railway.shp
  │      └─ farmland/farmland.shp → MinIO: transfer-data/farmland/farmland.shp
  │
  └─ Step 2: Python Workflow 任务（面积计算，依赖 Step 1）
       load(MinIO/railway.shp)
         → buffer(30m)
         → intersection( load(MinIO/farmland.shp) )
         → get_area
         → save(PostGIS: public.railway_farmland_result, mode=replace)

Service 发布
  └─ 基于 public.railway_farmland_result 表发布空间服务（WFS + REST Query）
```

## 任务拆解

### 阶段一：Transfer 本地目录引擎扩展

#### 任务 T1：local_engine 支持 `local_directory` 类型

**涉及文件**：
- `transfer/backend/internal/service/local_engine_service.go`
- `transfer/backend/internal/service/execution_engine_service.go`
- `transfer/backend/internal/api/local_engine_handler.go`

**设计要点**：

**connection_info 结构**：
```json
{
  "base_path": "/app/data"
}
```

**文件扫描逻辑**（ListFiles，复用 ListTables 接口）：
- 递归扫描 `base_path` 下的空间文件
- 返回**相对路径**（相对于 `base_path`），例如：
  ```
  railway.shp
  farmland.shp
  subdir/extra.shp
  terrain.tif
  ```
- 支持的扩展名：`.shp`、`.tif`、`.tiff`、`.geojson`、`.gpkg`、`.json`
- **子目录处理**：递归扫描，返回 `子目录名/文件名` 格式的相对路径
- 对于 Shapefile，只列出 `.shp` 主文件，不列出 `.dbf`、`.shx`、`.prj` 等附属文件

**连接测试逻辑**（testConnection）：
- 检查 `base_path` 是否存在
- 检查是否为目录
- 检查是否可读

**execution_engine_service.go 中的解析逻辑**：

`resolveLocalEngine` 增加 `case "local_directory"`：
```go
case "local_directory":
    basePath, _ := connInfo["base_path"].(string)
    // 从 taskConfig 中取 file 字段（相对路径）
    relFile, _ := taskConfig["file"].(string)
    // 拼接完整路径
    fullPath := filepath.Join(basePath, relFile)
    taskConfig["file_path"] = fullPath
    taskConfig["type"] = inferReaderType(relFile)  // 根据扩展名推断
```

**推断 Reader 类型**：
- `.shp` → `shapefile`
- `.tif` / `.tiff` → `geotiff`（暂不支持，报错提示）
- `.geojson` / `.json` → `geojson`
- `.gpkg` → `geopackage`

**Transfer 任务配置示例**：
```json
{
  "name": "同步铁路数据到MinIO",
  "type": "sync",
  "config": {
    "source": {
      "scope": "local",
      "engine_id": 1,
      "file": "railway.shp"
    },
    "target": {
      "scope": "system",
      "engine_id": 2,
      "bucket": "transfer-data",
      "prefix": "railway/",
      "file_name": "railway.shp",
      "file_type": "shapefile"
    }
  }
}
```

### 阶段二：Python Workflow load 算子支持 MinIO

#### 任务 T2：load 算子实现从 MinIO/S3 下载文件

**涉及文件**：
- `engines/python-workflow/operators/io_operators.py`

**当前状态**：`source_type=file` 时，有一个 TODO，假设文件在本地路径。

**需要实现**：当 `connection_info` 中包含 `endpoint`（MinIO/S3 特征）时，先下载到临时文件，再用 geopandas 读取。

**实现逻辑**：
```python
elif source_type == 'file':
    if connection_info and 'endpoint' in connection_info:
        # 从 MinIO/S3 下载
        local_path = _download_from_minio(connection_info, path)
        gdf = gpd.read_file(local_path)
        os.unlink(local_path)  # 清理临时文件
    else:
        # 本地文件
        gdf = gpd.read_file(path)
```

**MinIO 下载实现**（复用 boto3/minio-py）：
- 从 `connection_info` 中取 `endpoint`、`access_key`、`secret_key`、`bucket`
- `path` 为对象路径（如 `railway/railway.shp`）
- Shapefile 需要下载全套文件（`.shp` + `.shx` + `.dbf` + `.prj`）下载到同一临时目录

### 阶段四：Python Workflow 计算任务

#### 任务 T4：创建铁路占耕地面积计算工作流

通过 Develop 前端（工作流设计器）创建并保存为任务，或直接通过 API 创建 `develop.spatial_tasks` 记录。

**工作流定义**：
```json
{
  "nodes": [
    {
      "id": "load_railway",
      "operator": "load",
      "params": {
        "source_type": "file",
        "engine_id": 2,
        "path": "railway/railway.shp",
        "format": "shapefile"
      }
    },
    {
      "id": "buffer_railway",
      "operator": "buffer",
      "params": {
        "input_gdf": {"$ref": "load_railway"},
        "distance": 30,
        "crs_unit": "meters"
      },
      "depends_on": ["load_railway"]
    },
    {
      "id": "load_farmland",
      "operator": "load",
      "params": {
        "source_type": "file",
        "engine_id": 2,
        "path": "farmland/farmland.shp",
        "format": "shapefile"
      }
    },
    {
      "id": "intersect",
      "operator": "intersection",
      "params": {
        "gdf_a": {"$ref": "buffer_railway"},
        "gdf_b": {"$ref": "load_farmland"}
      },
      "depends_on": ["buffer_railway", "load_farmland"]
    },
    {
      "id": "calc_area",
      "operator": "get_area",
      "params": {
        "input_gdf": {"$ref": "intersect"},
        "unit": "square_meters"
      },
      "depends_on": ["intersect"]
    },
    {
      "id": "save_result",
      "operator": "save",
      "params": {
        "input_df": {"$ref": "calc_area"},
        "target_type": "table",
        "engine_id": 1,
        "schema": "public",
        "table": "railway_farmland_result",
        "mode": "replace"
      },
      "depends_on": ["calc_area"]
    }
  ]
}
```

**说明**：
- `engine_id=2` 对应业务 MinIO（system engine）
- `engine_id=1` 对应业务 PostgreSQL（system engine，带 PostGIS）
- buffer 的 30m 需要坐标系转换：数据若为 WGS84（EPSG:4326）地理坐标，30度米需先投影到适当投影坐标系再计算，再投影回来（见下方坐标系注意事项）

**坐标系处理**：
- 若数据已为投影坐标系（米），直接 buffer(30)
- 若数据为 WGS84（度），buffer(30) 实际上是 30 度，不是 30 米——需要在工作流中先用 `reproject` 算子转换到 EPSG:32650 或 EPSG:4526（中国区域），buffer(30)，再转回 WGS84
- 需确认 `railway.shp` 的坐标系（`.prj` 文件）

> **待确认**：查看 `data/railway.prj` 确定坐标系后，决定是否需要加 reproject 步骤。

## 关键技术细节

### Shapefile 的子目录规范

`data/` 目录结构应规范化，Shapefile 相关的附属文件（`.shx`、`.dbf`、`.prj`、`.cpg`、`.qmd`）与主文件在同一目录。ListFiles 只返回 `.shp`，但实际读取时 Reader 需要自动找同目录附属文件（Shapefile Reader 已支持）。

**Transfer 同步时**：需同步整个 Shapefile 组（.shp/.shx/.dbf/.prj），否则目标端无法读取。
- S3 Writer 目前对 Shapefile 的处理：将多文件打包为 zip 上传，或逐个上传？需确认。
- Python Workflow 的 load 算子从 MinIO 下载 Shapefile：需下载 `.shp` 及所有同名附属文件。

### buffer 的距离单位问题

`railway.shp` 的坐标系决定 buffer 参数：
- 如果是 **CGCS2000 或 WGS84**（地理坐标，单位：度）→ 需要先投影
- 如果是 **EPSG:4525 等投影坐标**（单位：米）→ buffer(30) 直接是 30 米

**检查方式**：查看 `data/railway.prj` 内容。若包含 `PROJCS` 则是投影坐标，若只有 `GEOGCS` 则是地理坐标。

### MinIO bucket 和路径规划

| 数据 | Bucket | 对象路径 |
|------|--------|---------|
| railway.shp | `transfer-data` | `railway/railway.shp`（zip包，含附属文件） |
| farmland.shp | `transfer-data` | `farmland/farmland.shp`（zip包，含附属文件） |

> 使用业务 MinIO（端口 9002），bucket 名称需在系统中预先创建。
