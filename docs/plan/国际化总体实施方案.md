# ADDP 国际化（i18n）总体方案

## Context

ADDP 当前为纯中文硬编码界面，定位为 CBB 开发包，未来需要支持国际用户。
目标：支持多语言（初期 zh-cn + en），运行时动态切换（无需重启），架构上预留未来扩展到更多语言的能力。

---

## 技术选型

| 层 | 技术 | 说明 |
|---|---|---|
| 前端 | vue-i18n v9 | Vue 3 官方，支持运行时动态切换 |
| 后端 | go-i18n/v2 | Go 生态主流，TOML 格式，线程安全 |
| 语言持久化 | localStorage + `Accept-Language` 请求头 | 前后端解耦，用户偏好跨页面保持 |

---

## 文件组织原则（就近原则）

翻译文件与源码同目录，模块间完全独立：

```
common-frontend/basic/src/
└── i18n/
    ├── zh-cn.json   ← 共享 UI 组件文本
    └── en.json

common-frontend/map/src/
└── i18n/
    ├── zh-cn.json
    └── en.json

system/frontend/src/
└── i18n/
    ├── zh-cn.json   ← system 业务词汇
    └── en.json

common/middleware/i18n/
├── i18n.go          ← 中间件 + GetLang + 公共 key 常量
├── translator.go    ← 全局 Bundle + T() / TWithDetail() / RegisterBundle()
└── locales/
    ├── zh-cn.toml   ← 仅通用错误（err.invalid_id / err.unauthorized / err.invalid_params）
    └── en.toml

system/backend/
└── i18n/
    ├── i18n.go      ← 模块 i18n 包：业务 key 常量 + init() 注册
    └── locales/
        ├── zh-cn.toml   ← system 业务错误消息
        └── en.toml
```

**原则**：
- `common/middleware/i18n/locales/` 只放 3 个通用 key（`err.*`）
- 各模块业务消息就近放在自己的 `i18n/locales/` 下，通过 `init()` 注册到全局 Bundle
- 每个模块有独立的 `i18n/i18n.go` 包，定义本模块的 key 常量

其余每个模块（manager, meta, transfer, develop 等）结构相同。

## Key 命名规范

格式：`<模块>.<功能>.<词汇>`，公共词汇用 `common` 前缀：

```json
// common-frontend/basic/src/i18n/zh-cn.json
{
  "common": {
    "confirm": "确定",
    "cancel": "取消",
    "save": "保存",
    "delete": "删除",
    "loading": "加载中...",
    "success": "操作成功",
    "failed": "操作失败"
  }
}

// system/frontend/src/i18n/zh-cn.json
{
  "system": {
    "user": {
      "title": "用户管理",
      "username": "用户名",
      "password": "密码"
    }
  }
}
```

## 前端架构设计

### 1. `useAddpI18n()` composable（放在 common-frontend/basic）

统一初始化 vue-i18n 实例，各模块引入使用，避免重复配置：
- 读取 localStorage 中用户偏好语言
- 初始化 vue-i18n 并合并公共翻译 + 模块翻译
- 暴露 `locale`（响应式）、`t()`、`switchLang()` 方法

### 2. `LangSwitcher.vue` 组件（放在 common-frontend/basic）

- 下拉选择切换语言，风格与主题切换器一致
- 放置在 console 右上角导航栏（与主题 ThemeSwitcher 并排）
- 切换时：更新 vue-i18n locale + 更新 localStorage + 更新请求头

### 3. Element Plus 语言同步

切换语言时同步更新 `ElConfigProvider` 的 locale，确保 Element Plus 组件（日期选择、表格等）也切换语言。

```js
// console 顶层 App.vue
const elementLocale = computed(() =>
  currentLang.value === 'zh-cn' ? zhCn : enUs
)
```

### 4. 动态切换（无需刷新）

vue-i18n v9 的 `locale` 是响应式的，切换后所有 `t()` 调用自动更新，无需刷新页面。

## 后端架构设计

### 中间件（放在 common/ 中）

```go
// common/middleware/i18n/i18n.go
// 从 Accept-Language 请求头提取语言，注入 context
func I18nMiddleware() gin.HandlerFunc
func GetLang(c *gin.Context) string
```

### 全局 Bundle + RegisterBundle 机制

`common/middleware/i18n/translator.go` 维护一个全局 `goi18n.Bundle`，通过 `RegisterBundle()` 允许各模块在 `init()` 中注册自己的翻译文件：

```go
// common/middleware/i18n/translator.go

// 公共 key 常量（仅通用错误）
const (
    MsgInvalidID     = "err.invalid_id"
    MsgUnauthorized  = "err.unauthorized"
    MsgInvalidParams = "err.invalid_params"
)

// RegisterBundle 供各模块在 init() 中注册自己的翻译文件
func RegisterBundle(fs embed.FS, dir string)

// T 根据 Accept-Language 头翻译消息，fallback 到 zh-cn，再不存在则返回 key 本身
func T(c *gin.Context, messageID string) string

// TWithDetail 翻译并追加动态详情（如 err.Error()）
func TWithDetail(c *gin.Context, messageID, detail string) string
```

### 各模块 i18n 包（就近原则）

每个模块在自己的 `i18n/` 包中定义 key 常量并通过 `init()` 注册翻译文件：

```go
// system/backend/i18n/i18n.go
package i18n

import (
    "embed"
    commoni18n "github.com/addp/common/middleware/i18n"
)

//go:embed locales/*.toml
var localeFS embed.FS

const (
    MsgTokenGenFailed     = "system.auth.token_gen_failed"
    MsgRegisterDisabled   = "system.auth.register_disabled"
    // ... 其他业务 key
)

func init() {
    commoni18n.RegisterBundle(localeFS, "locales")
}
```

### TOML 格式（go-i18n/v2 section 格式）

```toml
# system/backend/i18n/locales/zh-cn.toml
[system.auth.token_gen_failed]
other = "生成令牌失败"

[system.auth.register_disabled]
other = "注册功能已关闭"

[system.log.not_found]
other = "日志不存在"
```

```toml
# common/middleware/i18n/locales/zh-cn.toml（仅 3 个通用 key）
[err.invalid_id]
other = "无效的ID参数"

[err.unauthorized]
other = "未授权"

[err.invalid_params]
other = "无效的请求参数"
```

### Handler 中的调用方式

```go
// system/backend/internal/api/auth_handler.go
import (
    commoni18n "github.com/addp/common/middleware/i18n"
    sysi18n "github.com/addp/system/i18n"
)

// 调用方式：commoni18n.T(c, sysi18n.MsgXxx)
c.JSON(http.StatusInternalServerError, gin.H{
    "error": commoni18n.T(c, sysi18n.MsgTokenGenFailed),
})
```

## Swagger 双语注解规范

使用 `|` 分隔，中文在前，英文在后：

```go
// @Summary 获取用户列表 | Get user list
// @Description 根据条件分页查询系统用户列表 | Query system user list with pagination
// @Param page query int false "页码，默认1 | Page number, default 1"
// @Param tenant_id header string true "租户ID | Tenant ID"
// @Success 200 {object} response.Data "返回用户列表 | Return user list"
```

统一在 Phase 5 批量处理现有注解。

## 扩展性设计

未来添加新语言（如繁中、日文）只需：
1. 在各模块 `i18n/` 目录添加对应 JSON 文件（如 `zh-tw.json`）
2. 后端 `locales/` 添加对应 TOML 文件
3. `LangSwitcher.vue` 的语言列表增加一项

无需修改任何框架代码。

---

## 验证方式

- 前端：切换语言后所有文本立即更新，F5 刷新后保持所选语言
- 后端：携带 `Accept-Language: en` 请求头，API 错误消息返回英文
- Element Plus：日期选择器、表格分页等组件跟随语言切换
- Swagger UI：注解以 `中文 | English` 格式显示
