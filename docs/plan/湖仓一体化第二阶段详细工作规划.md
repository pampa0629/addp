# 湖仓一体化第二阶段详细工作规划

> 状态：历史计划精简版。当前优先按 provider 化引擎体系验证功能。

## 已收口的技术方向

- 湖表识别依赖 Meta 扫描和 `common/format/plugins/parquet`。
- 对象存储和 NFS 目录发现统一使用 `CatalogProvider`。
- 文件/对象内容读取统一使用 `ContentReadableProvider`。
- Manager 预览通过 provider 与格式解析器组合完成。

## 第二阶段重点

1. 验证 MinIO/S3 中“目录即表”和“文件即表”两种 Parquet 表格形态。
2. 验证 NFS 中根目录文件、普通目录文件和表格目录。
3. 验证 Manager 对 table 语义资源的字段、行样本和错误提示。
4. 验证 Develop 查询链路对表格资源的访问方式。
5. Transfer Parquet 读写事项单独跟踪，见 [../next/transfer基于common-engine-format改造设计.md](../next/transfer基于common-engine-format改造设计.md)。
