# 湖仓一体化第二阶段详细工作规划

> 基于：docs/plan/湖仓一体化设计方案.md  
> 日期：2026-04-16  
> 范围：Develop、Transfer、Manager 模块（后端 + 前端）

## Context

第一阶段 MVP 已完成：FileSystemPlugin 接口、CompositeItemDetector 体系、Parquet 解析器、Meta 模块 FileSystemScanService（含 LakeTableDetector 链路全部打通）、Manager 模块 LakeTablePreviewProvider。

第二阶段目标：
1. 让用户能在 SQL 工作台中直接查询湖表，并支持联邦查询（湖表 + 关系型表跨源 JOIN）
2. 让 Transfer 支持 Parquet 作为独立数据源和目标（数据入湖/出湖）
3. 前端完整呈现湖表能力（Manager 展示、Develop 查询、Transfer 导入导出）

**架构决策（已确认）**：
- DuckDB 不注册到 System，是 Develop 模块的内部能力
- 后端 `ListEngines` 接口在返回结果末尾追加虚拟 DuckDB 条目（`engine_type="duckdb"`, `id=0`），不写入数据库
- 前端 QueryEditor 检测到 `engine_type === "duckdb"` 时，路由到 `/develop/duckdb/query`，其余引擎走原有 `/develop/execute`
- 删除独立的 `FederatedQuery.vue` 页面和导航入口，统一入口为 QueryEditor 下拉选择
- DuckDB 开放联邦查询能力：湖表（Parquet on MinIO/S3）+ 关系型表（PG/MySQL）跨源 JOIN
- ParquetWriter 从 S3Writer 中提取为独立插件，S3Writer 改为调用 ParquetWriter
- Service 模块湖表发布（`service_type="lake"`）列为第三阶段，DuckDB 以 `common/duckdb/` 共享库形式内嵌，不依赖 Develop 模块

## 二、后端工作项

### 2.1 Transfer 模块：ParquetReader + ParquetWriter

**目标**：支持"关系型数据库 → Parquet → MinIO"（数据入湖）和"MinIO Parquet → 关系型数据库"（湖到仓）。

**关键文件**：
- 新增：`transfer/backend/internal/plugin/reader/parquet_reader.go`
- 新增：`transfer/backend/internal/plugin/writer/parquet_writer.go`
- 修改：`transfer/backend/internal/service/execution_engine_service.go`（注册插件）
- 修改：`transfer/backend/internal/plugin/writers/s3_writer.go`（提取 parquet 逻辑，改为调用 ParquetWriter）

**ParquetReader 设计**：
```
输入：MinIO/S3 路径（支持单文件或目录，目录则读取所有 .parquet 文件）
实现：
  1. 通过 FileSystemPlugin 列出目录下所有 .parquet 文件
  2. 按文件顺序流式读取，使用 common/format/parquet Parser
  3. 实现 Reader 接口：ReadBatch(batchSize) → []Record
依赖：common/format/parquet/parser.go（复用现有 Parser）
```

**ParquetWriter 设计**：
```
输入：Record 流 + 目标 MinIO/S3 路径
实现：
  1. 从第一批 Record 推断 Schema（字段名 + 类型映射）
  2. 按 batchSize 分片写出（part-0001.parquet, part-0002.parquet...）
  3. 写完后触发 Meta 重新扫描（发布 Redis 事件）
依赖：github.com/parquet-go/parquet-go（已在 common/go.mod 中）
```

**重构 S3Writer**：将 S3Writer 中的 parquet case 分支提取到 ParquetWriter，S3Writer 改为调用 `ParquetWriter.Write()`，消除重复。

### 2.2 Develop 模块：DuckDB 联邦查询引擎

**目标**：在 SQL 工作台中支持联邦查询——湖表（Parquet on MinIO/S3）和关系型表（PG/MySQL）可在同一 SQL 中查询和 JOIN。

**关键文件**：
- 新增：`develop/backend/internal/service/duckdb_service.go`
- 新增：`develop/backend/internal/service/sql_rewriter.go`
- 新增：`develop/backend/internal/api/duckdb_handler.go`
- 修改：`develop/backend/internal/api/router.go`（注册新路由）
- 修改：`develop/go.mod`（添加 DuckDB CGO 依赖：`github.com/marcboeker/go-duckdb`）

**duckdb_service.go 设计**：
```go
type DuckDBService struct {
    systemClient *client.SystemClient
    metaClient   *client.MetaClient
}

func (s *DuckDBService) ExecuteQuery(ctx, tenantID, sql string) (*QueryResult, error)
  1. 获取租户下所有引擎（SystemClient.GetEnginesByTenant）
  2. 初始化 DuckDB 内存连接
  3. 挂载对象存储引擎（MinIO/S3）：
       INSTALL httpfs; LOAD httpfs;
       SET s3_endpoint='...'; SET s3_access_key_id='...'; ...
       -- 每个引擎用独立命名空间：engine_name → httpfs 配置
  4. 挂载关系型引擎（PG/MySQL）：
       INSTALL postgres; LOAD postgres;
       ATTACH 'postgres://...' AS {engine_name} (TYPE postgres, READ_ONLY);
       INSTALL mysql; LOAD mysql;
       ATTACH 'mysql://...' AS {engine_name} (TYPE mysql, READ_ONLY);
  5. 调用 SQLRewriter 改写 SQL（仅改写湖表引用，关系型表引用已通过 ATTACH 可直接访问）
  6. 执行改写后的 SQL，返回结果
```

**sql_rewriter.go 设计**：
```go
// 仅改写湖表引用（关系型表通过 ATTACH 已可直接用三段式访问）
// 输入：SELECT * FROM my_minio.warehouse.orders o JOIN my_pg.public.customers c ON o.id=c.id
// 输出：SELECT * FROM read_parquet('s3://bucket/warehouse/orders/*.parquet') o JOIN my_pg.public.customers c ON o.id=c.id
func Rewrite(ctx, sql string, metaClient MetaClient, tenantID string) (string, error)
  1. 解析 SQL 中的三段式表引用（engine.schema.table）
  2. 查 Meta 判断是否为 lake_table（item_type="lake_table"）
  3. 是湖表 → 替换为 read_parquet('physical_path/*.parquet')
  4. 非湖表（关系型表）→ 保持原样（DuckDB 通过 ATTACH 直接访问）
```

**duckdb_handler.go API**：
```
POST /api/develop/duckdb/query
  Request:  { sql: "...", timeout: 30 }
  Response: { columns, rows, execution_time_ms }

GET /api/develop/duckdb/sources
  Response: 当前租户下所有可查询的数据源列表
  {
    lake_tables: [{ engine, schema, table, fields }],  // 湖表
    relational:  [{ engine, schema, table }]           // 关系型表（PG/MySQL）
  }
```

**命名空间约定**（用户文档）：
```
湖表：    {minio_engine_name}.{bucket_or_prefix}.{table_dir}
关系型表：{pg_engine_name}.{schema}.{table}
跨源 JOIN 示例：
  SELECT o.*, c.name
  FROM my_minio.warehouse.orders o
  JOIN my_pg.public.customers c ON o.customer_id = c.id
```

### 3.1 Manager 前端：湖表展示

**目标**：在数据探索树中正确展示 lake_table 节点，提供预览和 Schema 信息，并支持跳转到联邦查询。

**关键文件**：
- 修改：`manager/frontend/src/components/explorer/ExplorerTree.vue`
- 修改：`manager/frontend/src/components/explorer/PreviewPanel.vue`
- 修改：`manager/frontend/src/views/DataExplorer.vue`

**具体改动**：

1. **ExplorerTree.vue**：
   - 为 `item_type="lake_table"` 节点添加专属图标（区别于普通 object 节点）
   - 节点标签显示：`表名 (N files, X MB)`（从 attributes 读取 file_count、total_size）
   - 右键菜单：预览数据、查看 Schema、在联邦查询中打开（跳转 Develop）

2. **PreviewPanel.vue**：
   - 检测 `item_type="lake_table"` 时，调用 Manager 预览 API（已有 LakeTablePreviewProvider）
   - 展示 Schema 面板：字段名、类型（从 attributes.fields 读取）
   - 展示统计信息：文件数、总大小、格式（parquet/orc/avro）
   - 展示数据预览表格（前 N 行）

3. **DataExplorer.vue**：
   - 添加"在联邦查询中打开"按钮，点击跳转到 Develop 模块并预填 SQL：
     `SELECT * FROM {engine}.{schema}.{table} LIMIT 100`

## 六、验证方式

1. **Transfer Parquet**：
   - 创建任务：PostgreSQL → Parquet → MinIO，验证文件写出和分片命名
   - 创建任务：MinIO Parquet → PostgreSQL，验证数据读入和类型映射
   - 触发 Meta 扫描，验证 lake_table 被识别（item_type="lake_table"）

2. **DuckDB 湖表查询**：
   - 在 Develop 工作台选择"联邦查询"模式
   - 执行 `SELECT * FROM my_minio.warehouse.orders LIMIT 10`
   - 验证 SQL 改写正确，结果返回

3. **DuckDB 联邦查询**：
   - 执行跨源 JOIN：`SELECT o.*, c.name FROM my_minio.warehouse.orders o JOIN my_pg.public.customers c ON o.customer_id = c.id`
   - 验证 PG 表通过 ATTACH 可直接访问，湖表引用被正确改写

4. **Manager 展示**：
   - 在数据探索树中展开 MinIO 引擎，验证 lake_table 节点显示（含文件数和大小）
   - 点击湖表节点，验证预览面板显示字段列表和数据预览

5. **端到端**：
   - PostgreSQL 数据 → Transfer 导出为 Parquet → MinIO
   - Meta 扫描识别为 lake_table
   - Manager 预览数据
   - Develop 联邦查询（湖表 JOIN 关系型表）
