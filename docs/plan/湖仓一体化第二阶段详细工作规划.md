# 文件与目录表格后续验收

文件/对象的目录叶子身份与表格内容语义以[元数据 attributes 规范](../spec/addp元数据attributes规范.md)、[类型与格式能力规范](../spec/addp数据类型与格式能力规范.md)和[路径规范](../spec/addp存储引擎路径体系规范.md)为准。DuckDB 联邦消费见[引擎插件规范](../spec/addp引擎插件接口规范.md)。本文仅列尚需按实际场景补证的组合，不重复保留已完成 Provider 改造阶段。

## 待补证范围

1. MinIO/S3 的 single Parquet 对象、whole scope 目录及 schema 不兼容/空目录的边界。
2. NFS 根文件、深层文件与目录表格的路径保真、资源定位、字段和有界样本；目录不能因含 Parquet 就无条件认定为表。
3. 同一真实资源的 Meta 识别、Manager 预览、Develop 查询与 Service 显式发布快照一致；权限撤销、内容变化和缺少读取能力明确拒绝，不按名称重绑。
4. Transfer 读写沿[当前架构](../../transfer/docs/design.md)与[同步支持矩阵](../../transfer/docs/transfer-任务语义与同步模式.md)选择实际组合；不从 descriptor 或已有预览推断 writer、增量或事务支持。

## 验证与维护

先核对已有 owner/T4 报告，已有证据仅在版本、输入与范围仍有效时复用。缺口按实际 owner 使用 `make test-module MODULE=meta`、`make test-module MODULE=manager`、`make test-module MODULE=develop`、`make test-module MODULE=service` 或 `make test-module MODULE=transfer`；真实对象存储及文件系统体验和工程门禁分别记录，不把本清单写成全平台尚未实现。

每个组合取得证据后从清单移除，必要稳定约定回写正式规范；不继续按阶段、日期或场景运行追加历史。
