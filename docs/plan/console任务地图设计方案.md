# Console 任务地图设计方案

> 设计日期：2026-04-09  
> 背景：当前 Console 首页以模块卡片为主，对新手不友好，用户不知道从哪里入手。本方案将首页从"模块目录"改造为"任务地图"，以用户目标为导向，提供状态感知的动态引导。

---

## 一、核心问题诊断

当前 Console 是**模块驱动**的导航，而用户的思维是**任务驱动**的。

用户想的是"我要把一批 CSV 数据变成可查询的 API"，但系统呈现的是"这里有 Transfer、Meta、Manager、Service 四个模块"。两种语言之间没有翻译，导致新手迷失。

---

## 二、设计目标

- 新手登录后，能在 30 秒内找到自己该做什么
- 老手不受影响，仍能快速直达目标模块
- 不需要用户自己选择"角色"或"模式"
- 随着用户使用深入，引导内容自动演进

---

## 三、核心设计思路

### 3.1 状态感知替代角色选择

没有预设角色，通过**资源状态推断用户阶段**：

| 状态 | 判断条件 | 用户阶段 |
|------|----------|----------|
| 未初始化 | 引擎数 = 0 | 新租户，需要先配置 |
| 已就绪 | 引擎 > 0，数据集 = 0 | 等待接入数据 |
| 有数据 | 数据集 > 0，服务 = 0 | 可以开发和发布 |
| 活跃 | 服务 > 0 | 关注运营和质量 |

### 3.2 动态场景推荐（≤3个）

场景不是静态列表，而是基于状态动态推荐，每次最多展示 **2-3 个最相关场景**，避免选项过多带来的认知负担。

```
状态：引擎=0
  → 只显示：[配置数据引擎]

状态：引擎>0，数据集=0
  → 显示：[接入第一批数据]  [了解平台能做什么]

状态：数据集>0，服务=0
  → 显示：[发布数据服务]  [开始数据开发]  [建立数据标准]

状态：服务>0，活跃用户
  → 显示：[查看运行状态]  [接入更多数据]  + 最近访问
```

## 五、六大核心场景定义

每个场景卡片包含：目标描述 + 涉及模块路径（可点击直达）+ 当前进度（后期迭代）。

| 场景 | 用户目标 | 工作流路径 |
|------|----------|------------|
| 数据接入 | 把外部数据引入平台 | 配置引擎 → Transfer → Meta → Manager |
| 数据服务 | 把数据变成可查询 API | Manager → Service → 测试 |
| 数据开发 | SQL 分析、Notebook、工作流 | Develop → Orchestrator |
| 数据治理 | 建立标准、保证质量 | Standard → Quality → Monitor |
| 数据建模 | 建立逻辑模型和指标 | Standard → Modeling |
| 知识图谱 | 构建和发布知识服务 | Graph → Service |

## 六、Header 导航调整

### 现状问题

Header 中的群组 Tab（数据准备、数据治理、开发监控……）是模块优先的导航，与任务地图首页逻辑冲突，两套导航并存会造成困惑。

### 调整方向

群组 Tab **保留但降级**为专家快捷入口，同时新增**全局搜索**作为核心导航工具：

```
[Logo]  [🔍 搜索模块、功能、数据...]  [群组Tab(收窄)]  [用户]
```

**全局搜索能力：**
- 输入"发布 API" → 直接跳到 Service 模块
- 输入"数据质量" → 跳到 Quality
- 输入"PostgreSQL" → 跳到对应引擎配置
- 支持模糊匹配和中文描述搜索

### 三类用户的导航路径

| 用户类型 | 主要导航方式 |
|----------|-------------|
| 新手 | 首页任务地图 → 场景引导 |
| 中级用户 | 全局搜索直达 |
| 老手 | Header 群组 Tab 快速切换 |

## 七、AI 助手兜底

**定位**：当用户仍然搞不清楚时的最后一道引导。

**实现方式**：
- 右下角固定浮动按钮："不知道从哪开始？"
- 点击后侧边滑出 Agent 对话面板
- Agent 理解用户意图，给出模块跳转链接（不只是文字说明）
- 示例：用户说"我想把 PostgreSQL 的数据发布成 API"，Agent 回复并附带直达链接

## 八、技术实现要点

### 8.1 状态数据获取

前端并发调用各模块现有 list 接口（`page_size=1`），从响应的 `total` 字段取数，**无需新增任何后端接口**。任何一个请求失败不影响其他数字显示（`Promise.allSettled`）。

```js
const [engines, datasets, services, tasks] = await Promise.allSettled([
  api.get('/api/v1/system/engines?page_size=1'),
  api.get('/api/v1/meta/items?page_size=1'),          // 数据集总数
  api.get('/api/v1/service/services?page_size=1'),
  api.get('/api/v1/monitor/executions?status=running&page_size=1'),
])
```

### 8.2 最近访问

存 `localStorage`，记录最近 5 个访问记录，纯前端实现，零后端成本：

```js
{ module, page, label, timestamp }
```

### 8.3 场景进度追踪

初期**不做**，场景卡片只作为入口。后期迭代时再加进度状态。

### 8.4 全局搜索

仅搜索**功能入口**（模块名、页面名、功能描述），不包含数据资产（数据资产搜索已由 Portal 模块承担）。

实现方式：预置静态 JSON 索引 + 前端 fuse.js 模糊匹配，零后端成本，响应 < 10ms：

```js
// 搜索索引示例
[
  { label: '数据传输任务', module: 'transfer', page: 'tasks', keywords: ['导入', '同步', '接入数据'] },
  { label: '发布查询服务', module: 'service', page: 'query-services', keywords: ['API', '发布', '接口'] },
  { label: 'SQL 工作台',   module: 'develop',  page: 'sql',           keywords: ['查询', '开发', 'SQL'] },
  // ...
]
```

### 8.5 Agent 侧边面板

右侧侧滑抽屉（Drawer），宽度 380px，可拖拽调整。Agent 回复中包含可点击的模块跳转链接，点击后主区域直接导航。面板展开状态存 `localStorage`。

```
┌──────────────────────────────┬──────────────────┐
│   当前模块内容（iframe）      │  AI 助手          │
│                              │  ─────────────── │
│                              │  [对话内容]       │
│                              │  [跳转链接]       │
│                              │  [输入框]         │
└──────────────────────────────┴──────────────────┘
```

## 九、实施阶段建议

### 阶段一：首页改造（核心）
- 新增状态快照区域（需要聚合接口）
- 实现动态场景推荐逻辑
- 最近访问（localStorage）
- 所有模块折叠展示

### 阶段二：Header 搜索
- 新增全局搜索框
- 静态索引实现模块/功能搜索

### 阶段三：AI 助手浮动入口
- 右下角浮动按钮
- 接入 Agent 模块

### 阶段四：场景进度追踪（后期迭代）
- 场景卡片显示完成状态
- 跨模块工作流进度

## 十、已确认决策

| 事项 | 决策 |
|------|------|
| 状态数据获取 | 前端并发复用现有 list API（`page_size=1` 取 total），无需新增接口 |
| 全局搜索范围 | 仅功能入口（模块/页面/功能描述），数据资产搜索由 Portal 模块承担 |
| Agent 面板形式 | 右侧侧滑抽屉，380px，支持跳转链接，状态存 localStorage |
