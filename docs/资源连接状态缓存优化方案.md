# 资源连接状态缓存优化方案

## 问题背景

当Meta元数据扫描页面打开时，前端会调用`listAvailableSchemas` API获取可用的Schema列表。后端需要实时连接每个存储引擎来获取Schema信息，如果某些存储引擎（如MongoDB）离线，连接会等待超时（3秒），导致页面加载缓慢。

## 优化目标

1. **页面瞬间打开**（< 100ms）：优先返回缓存状态
2. **状态实时更新**：后台异步检测真实连接状态
3. **用户体验友好**：显示"检测中"→"在线/离线"的状态变化

## 架构设计

### 数据流程

```
用户打开页面
    ↓
Meta读取System缓存状态 (100ms)
    ↓
前端立即显示缓存状态 + "检测中"指示器
    ↓
Meta后台启动异步检测任务
    ↓
检测完成 → 更新System缓存 → 推送前端更新
```

### 核心组件

#### 1. System模块 - 状态缓存

**新增字段** (`system.engines` 表)：

```sql
connection_status VARCHAR(20)  -- online/offline/unknown/checking
last_check_at     TIMESTAMP    -- 上次检测时间
check_message     TEXT         -- 检测结果消息（错误信息）
```

**新增API**：

```
PUT /api/internal/engines/:id/connection-status
Body: {
  "connection_status": "online|offline|unknown|checking",
  "check_message": "连接成功 / 错误信息"
}
```

#### 2. Meta模块 - 快速响应 + 异步检测

**`ListAvailableSchemas` 改进**：

```go
func (s *ScanServiceNew) ListAvailableSchemas(resourceID, tenantID uint, token string) ([]*models.SchemaInfo, error) {
    // 1. 先获取资源（包含缓存的connection_status）
    resource, err := s.resourceService.GetResourceByID(resourceID, tenantID, token)
    if err != nil {
        return nil, err
    }

    // 2. 如果状态是offline且检测时间<5分钟，直接返回空列表+缓存状态
    if resource.ConnectionStatus == "offline" &&
       time.Since(*resource.LastCheckAt) < 5*time.Minute {
        return nil, fmt.Errorf("resource offline (cached): %s", resource.CheckMessage)
    }

    // 3. 如果状态是unknown或检测时间>5分钟，启动后台异步检测
    if resource.ConnectionStatus == "unknown" ||
       time.Since(*resource.LastCheckAt) > 5*time.Minute {
        go s.asyncCheckResourceConnection(resourceID, tenantID, token)
    }

    // 4. 尝试实时连接（快速超时3秒）
    scan, err := plugins.NewScanner(resource)
    if err != nil {
        // 连接失败，启动后台更新状态
        go s.updateResourceStatus(resourceID, "offline", err.Error())
        return nil, fmt.Errorf("failed to create scanner: %w", err)
    }
    defer scan.Close()

    // 5. 返回Schema列表
    schemasInfo, err := scan.ListSchemas()
    if err != nil {
        go s.updateResourceStatus(resourceID, "offline", err.Error())
        return nil, err
    }

    // 6. 连接成功，更新状态为online
    go s.updateResourceStatus(resourceID, "online", "")

    return schemasInfo, nil
}
```

**后台异步检测**：

```go
// asyncCheckResourceConnection 异步检测资源连接状态
func (s *ScanServiceNew) asyncCheckResourceConnection(resourceID, tenantID uint, token string) {
    // 先标记为checking
    s.updateResourceStatus(resourceID, "checking", "正在检测连接...")

    resource, err := s.resourceService.GetResourceByID(resourceID, tenantID, token)
    if err != nil {
        s.updateResourceStatus(resourceID, "unknown", err.Error())
        return
    }

    // 尝试连接
    ctx, cancel := context.WithTimeout(context.Background(), 3*time.Second)
    defer cancel()

    if err := dbbridge.TestConnection(ctx, resource); err != nil {
        s.updateResourceStatus(resourceID, "offline", err.Error())
    } else {
        s.updateResourceStatus(resourceID, "online", "连接正常")
    }
}
```

#### 3. Meta Worker - 定时健康检查

**新增定时任务**（每5分钟）：

```go
// PeriodicHealthCheck 定期检查所有引擎的连接状态
func (w *Worker) PeriodicHealthCheck() {
    engines := w.getAllEngines()

    for _, engine := range engines {
        go w.checkEngineHealth(engine)
        time.Sleep(100 * time.Millisecond) // 避免并发过高
    }
}
```

#### 4. 前端优化

**状态显示逻辑**：

```javascript
// 加载Schema列表
const loadSchemas = async () => {
  loadingSchemas.value = true
  let cachedStatus = null

  try {
    // 1. 获取可用Schema（优先返回缓存）
    const availableRes = await metaApi.listAvailableSchemas(resourceId)
    availableSchemas = availableRes.data || []
    cachedStatus = availableRes.connection_status // 返回缓存状态
  } catch (error) {
    // 2. 如果报错，检查是否是offline缓存
    if (error.cached && error.status === 'offline') {
      ElMessage.warning(`存储引擎离线（缓存状态）: ${error.message}`)
      cachedStatus = 'offline'

    showCheckingIndicator.value = true
    // 轮询等待状态更新（或使用WebSocket）

}
```

## 缓存策略

1. **初次访问**：unknown → checking（后台检测）→ online/offline
2. **5分钟内**：直接返回缓存状态，不重复检测
3. **5分钟后**：返回缓存 + 启动后台检测更新
4. **定时任务**：每5分钟主动检测所有资源

## 注意事项

1. **缓存时效**：5分钟是推荐值，可配置
2. **并发控制**：后台检测需限流，避免同时检测所有资源
3. **错误处理**：网络故障时不应频繁重试
4. **状态一致性**：确保System和Meta的状态同步
