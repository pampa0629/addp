## 主题系统架构

### 主题类型

ADDP 平台支持 **5 种主题模式**，定义在 `common-frontend/basic/src/config/themes.js` 中：

| 主题值 | 主题名称 | 图标 | 是否深色 | 说明 |
|--------|---------|------|---------|------|
| `system` | 跟随系统 | Monitor | 跟随系统 | 根据操作系统设置自动切换浅色/深色 |
| `light` | 浅色模式 | Sunny | `false` | 传统浅色主题，白色背景 |
| `dark` | 深色模式 | Moon | `true` | 传统深色主题，深灰色背景 |
| `blue` | 蓝色模式 | Cloudy | `true` | 深色系，蓝色调背景和边框 |
| `purple` | 紫色模式 | MagicStick | `true` | 深色系，紫色调背景和边框 |

### 主题配置文件

主题模式、图标与 `isDarkTheme` 由[themes.js](../../basic/src/config/themes.js)维护，模式应用、系统偏好与监听清理由[useTheme](../../basic/src/composables/useTheme.js)统一实现，不在模块复制配置表或 `applyTheme`。

新增主题时，同次补充主题配置、完整 CSS 变量和 ThemeSwitcher 所需图标映射；深色系设置 `isDarkTheme: true`。现有图标已在映射中时直接复用，不重复导入。所有主题使用同一切换与初始化路径。

### 主题 CSS 变量定义

完整变量和值以[共享 theme.css](../../basic/src/styles/theme.css)为准；新增变量必须覆盖所有实际配色，不能只修改文档中的示例值。

#### 浅色模式（`:root`）

`:root` 提供浅色默认变量；`light` 不依赖额外主题 class。

#### 深色模式（`html.dark`）

`html.dark` 提供深色变量并启用 Element Plus 深色样式。

#### 蓝色模式（`html.blue`）

`html.blue` 提供蓝色配色，与 `dark` class 一起使用。

#### 紫色模式（`html.purple`）

`html.purple` 提供紫色配色，与 `dark` class 一起使用。

### 深色系主题的双重 class 机制

深色使用 `dark`，蓝色使用 `dark blue`，紫色使用 `dark purple`。共同的 `dark` 让 Element Plus 深色 CSS 生效，具体配色再由对应主题变量覆盖，避免为每种深色系主题重复实现组件样式。

`system` 根据操作系统偏好选择浅色或深色，由共享 `useTheme` 监听偏好变化；业务模块不另写 class 切换逻辑。

### Element Plus 深色模式集成

各模块静态引入 Element Plus 深色 CSS 与共享主题 CSS，具体导入顺序和挂载前初始化见[主题接入步骤](#1-css-变量定义位置)。深色 CSS 由 `html.dark` 控制生效，不需要动态加载，也不会因静态导入而强制所有页面使用深色。

### 自动过渡动画

主题颜色过渡由共享 `theme.css` 维护，组件不重复配置整套全局过渡。该文件也排除了消息、加载层、iframe、媒体及部分动画组件等无需过渡的元素；不要把主题过渡理解为每个元素都必须产生动画。

### Console 与模块通信

主题消息仍由现有 Console Store 与共享 composable 维护，业务模块不直接实现 postMessage 协议。

#### Console（发送方）

[Console theme Store](../../../console/frontend/src/store/theme.js)复用 `useTheme({ listenToConsole: false })`，监听 `theme.mode`，向当前模块 iframe 发送 `theme-change` 消息；消息包含 `source: 'addp-console'`、mode、isDark 和 timestamp。目标 origin 从各 iframe 的实际地址取得，不使用文档中的固定端口或统一猜测值。

#### 模块（接收方）

模块在挂载前初始化 `useTheme({ listenToConsole: true, storageKey: 'theme-mode' })`，具体示例只在[接入步骤](#1-css-变量定义位置)维护。共享 composable 在 iframe 内接收主题消息，模式应用与系统主题监听仍复用同一实现；在组件局部持有其监听时，按生命周期调用返回的 `cleanup()`。

当前主题接收实现按 hostname 比较来源，并检查消息 type/source；它不等同于认证消息的 origin/source 校验，不能作为 Token 或权限通信模板。认证与 Console 入口边界遵循[登录认证规范](../../../docs/spec/addp登录认证的统一要求.md#五console-与-iframe)。

## Element Plus 组件覆盖

### 全局覆盖规则

`theme.css` 已经为 Element Plus 组件提供了全局深色系主题覆盖样式，**无需在各模块中重复覆盖**。

**深色系主题选择器**（`html.dark, html.blue, html.purple`）下已覆盖的组件：

- `el-empty`：空状态
- `el-pagination`：分页器
- `el-dialog`：对话框
- `el-drawer`：抽屉
- `el-input`：输入框
- `el-textarea`：文本域
- `el-select`：下拉选择器
- `el-table`：表格
- `el-card`：卡片
- `el-dropdown`：下拉菜单
- `el-tree`：树形控件
- `el-tabs`：标签页
- `el-breadcrumb`：面包屑
- `el-descriptions`：描述列表
- `el-menu`：菜单组件

**覆盖样式示例**（在 `theme.css` 中）：

```css
/* 深色系主题和紫色主题、蓝色主题共享这些样式 */
html.dark,
html.blue,
html.purple {
  .el-card {
    background-color: var(--addp-bg-primary) !important;
    border-color: var(--addp-border-color) !important;
  }

  .el-empty {
    background-color: transparent !important;
  }

  .el-pagination button,
  .el-pagination .el-pager li {
    background-color: var(--addp-bg-primary) !important;
    color: var(--addp-text-primary) !important;
  }
}
```

### 组件级覆盖

如果需要在特定组件中覆盖 Element Plus 样式，使用 `:deep()` 选择器：

```vue
<style scoped>
.my-table :deep(.el-table__header) {
  background: var(--addp-bg-secondary);
}
</style>
```

## 主题系统实施指南

### 关键实施步骤

#### 1. CSS 变量定义位置

颜色定义统一位于[theme.css](../../basic/src/styles/theme.css)。模块 `main.js` 在 Element Plus 基础 CSS 之后导入深色变量和共享主题，并在 `app.use()` 完成后、挂载前初始化：

```javascript
import 'element-plus/theme-chalk/dark/css-vars.css'
import '@common-ui/styles/theme.css'
import { useTheme } from '@common-ui'

const { init: initTheme } = useTheme({
  listenToConsole: true,
  storageKey: 'theme-mode'
})
initTheme()
app.mount('#app')
```

Console 自身使用其 theme Store，不按模块示例再建一份监听；模块特有覆盖只处理自身领域样式。

#### 2. 布局组件中禁止硬编码背景色

Layout 的 header、sidebar 使用 `--addp-bg-primary`，content、main-content 和 iframe 的 content-only 使用 `--addp-bg-secondary`；边框使用 `--addp-border-color`。不要在局部组件保留固定浅色背景，也不要因主题不同复制整套布局。

#### 3. 组件样式必须使用 !important

组件级背景与关键容器覆盖需要使用 `!important`，确保 ADDP 变量覆盖 Element Plus 默认背景；有边框覆盖时也使用对应变量。全局 Element Plus 覆盖由共享 `theme.css` 负责，模块不重复维护同一规则。

#### 4. iframe 模式特殊处理

Layout 在 iframe 模式只渲染内容区域与 `<router-view>`。容器避免固定高度和嵌套滚动，并使用共享主题变量，例如：

```css
.content-only {
  width: 100%;
  height: auto;
  min-height: 100vh;
  padding: 20px;
  margin: 0;
  background: var(--addp-bg-secondary) !important;
  overflow: visible;
  box-sizing: border-box;
}
```

### 常见问题和解决方案

#### 问题 1：切换主题后某些区域颜色不变

依次检查 HTML 主题 class、目标变量的 `getComputedStyle` 计算值、元素实际背景/边框，以及命中的样式来源。排除缺少共享 CSS、Layout 硬编码、变量定义遗漏和局部覆盖优先级问题；具体配色以源码为准，不按旧排障日志中的固定色值判断。

#### 问题 2：Console 与 iframe 模块主题不同步

确认 Console 主题模式已更新、目标 iframe 存在且地址可解析，再检查模块是否在挂载前调用主题初始化、启用 `listenToConsole` 并使用一致的 `theme-mode`。按共享 Store 与 composable 的实际消息路径定位，不以某条历史控制台日志出现与否判定成功，也不为排障放宽认证消息来源校验。

#### 问题 3：CSS 变量值正确但界面仍不变化

在开发者工具中查实际生效的属性与优先级，确认 Element Plus 默认背景、内联样式或局部覆盖是否挡住 ADDP 变量。通用问题在共享 `theme.css` 修正，局部领域问题在组件 scoped / `:deep()` 范围修正；不要给每个模块复制同一份全局覆盖。

### 验证清单

- [ ] 深色变量与共享主题 CSS 的导入顺序正确，模块挂载前已初始化共享 `useTheme`。
- [ ] Layout、普通组件及 iframe 内容容器的背景、文本、边框均使用 ADDP 变量；需要的关键覆盖具有正确优先级。
- [ ] Console 切换 light、dark、blue、purple 时，模块界面与 Element Plus 组件同步变化。
- [ ] system 模式随系统深浅偏好更新；蓝色与紫色保持对应配色和 `dark` class。
- [ ] 独立顶层入口与 Console iframe 均验证，内容不出现固定浅色区域或多余嵌套滚动。
- [ ] 新增主题变量覆盖全部配色；组件局部使用的监听按生命周期清理。

静态检查、组件测试与浏览器验收分别记录结果，统一按[测试与验收规范](../../../docs/spec/addp测试与验收规范.md)选择标准入口；样式源码核对不计作浏览器交互通过。

## 常见问题（FAQ）

### Q1: 为什么不能使用硬编码颜色？

**A**: 硬编码颜色会导致主题切换无法生效。所有颜色必须通过 CSS 变量引用，以支持主题切换（浅色/深色/蓝色/紫色模式）。

### Q2: 如何在模板中动态设置颜色？

动态样式允许使用 `:style` 绑定计算属性或响应式变量，颜色值仍引用 ADDP CSS 变量，不写死具体色值；静态样式继续放在 class 中，见[内联样式规则](工程约束.md#23-禁止使用内联样式)。

### Q3: 如何覆盖 Element Plus 组件的样式？

优先复用全局覆盖；确需组件局部覆盖时使用 `:deep()`，见[Element Plus 组件覆盖](#element-plus-组件覆盖)。背景覆盖与关键容器优先级要求见[主题接入规则](#3-组件样式必须使用-important)。

### Q4: 新增的 CSS 变量是否需要同步到所有主题？

**A**: 是的。在 `theme.css` 中新增变量时，必须同时为所有主题（`:root`、`html.dark`、`html.blue`、`html.purple`）定义值。

### Q5: 如何测试不同主题的效果？

通过 Console 的主题选择器切换，并检查独立顶层界面与 iframe；`system` 模式还要验证系统深浅偏好变化。开发者工具用于检查 class 和计算样式，不能替代[主题验证清单](#验证清单)中的真实交互。

### Q6: 为什么蓝色/紫色主题需要同时添加 `dark` class？

这是 Element Plus 深色 CSS 与具体配色共同生效的机制，见[双重 class 规则](#深色系主题的双重-class-机制)。

### Q7: 如何新增自定义主题？

按[主题配置规则](#主题配置文件)同步配置、所有变量与必要图标映射，不在模块单独实现新的切换路径。
