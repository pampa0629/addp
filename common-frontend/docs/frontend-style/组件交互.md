## 业务域选择

业务域选择统一使用共享 `BusinessDomainSelect`，选项构造、层级缩进、搜索和名称展示见[基础控件的业务域选择契约](../components/基础控件与工具.md#业务域选择)。父域与子域均可选；缩进不改变筛选语义，不自动把父域选择解释为包含所有子域。

Standard 是层级事实源。Catalog 分页候选及导航分面由后端返回权威路径，前端不得根据名称猜测层级。模块负责权限、加载和业务特殊选项，共享组件负责统一渲染与交互。

## AI 助手入口规范

ADDP 各模块的 AI 助手属于同一类平台能力，入口和基础交互必须保持一致：

- 默认使用 `MagicStick`（魔法棒）作为入口图标，并使用统一的按钮尺寸、悬浮反馈和打开动效；不得在不同模块使用含义不一致的图标或自定义一套入口样式。
- 默认将入口固定在页面右下角，使用浮动按钮呈现。入口必须位于当前模块内容层级之上，但不得遮挡主要操作、编辑器内容、结果区域或对话框；窄屏和 iframe 模式下应自动避让边缘和底部操作栏。
- 入口按钮必须提供国际化的 `aria-label` 和 Tooltip（例如“打开 AI 助手”）；不能只依赖魔法棒图形表达含义。加载、禁用和错误状态需要有明确的视觉状态，并通过共享状态播报能力提供可访问反馈。
- 打开的助手面板应复用统一的尺寸、层级、标题栏、关闭行为、加载状态、错误提示和输入/提交区域风格。关闭面板后应保留已生成内容和会话状态，除非用户明确结束当前会话或页面生命周期结束。
- 入口和面板优先复用 `common-frontend` 的共享组件、主题变量和交互能力；不得在各业务模块重复实现同一套视觉规则。若尚无合适的共享能力，应先评估抽取到 `common-frontend`，再由模块提供业务内容。
- 只有在业务上下文确实要求其他入口位置或交互方式时才允许偏离，并须在对应模块文档中说明原因和适用范围；偏离不得改变魔法棒的语义和助手面板的基础交互约定。

## 表单规范

### 1. 表单布局

使用 Element Plus 的 `el-form` 组件并绑定 `rules` 与字段 `prop`。以下为接入片段，`t` 复用模块既有国际化上下文，标签借用 System 的现有词条；`form`、提交与取消处理由 Owner 提供，词条归属见[国际化规范](../../../docs/spec/addp国际化开发规范.md#组件使用)：

```vue
<template>
  <el-form :model="form" :rules="rules" label-width="120px">
    <el-form-item :label="t('system.iam.users.username')" prop="username" required>
      <el-input v-model="form.username" :placeholder="t('common.input')" />
    </el-form-item>
    <el-form-item :label="t('system.iam.users.email')" prop="email">
      <el-input v-model="form.email" :placeholder="t('common.input')" />
    </el-form-item>
    <el-form-item>
      <el-button type="primary" @click="handleSubmit">{{ t('common.submit') }}</el-button>
      <el-button @click="handleCancel">{{ t('common.cancel') }}</el-button>
    </el-form-item>
  </el-form>
</template>
```

### 2. 表单验证

使用 Element Plus 的内置验证，`rules` 用 `computed` 按当前语言生成；`usernameLengthMessage`（含 3–20 边界）与 `emailFormatMessage` 为 Owner 提供的响应式翻译文本。`blur`、必填、长度和邮箱格式仅为前端示例，业务约束与服务端校验仍归 Owner：

```javascript
import { computed } from 'vue'

const rules = computed(() => ({
  username: [
    { required: true, message: t('common.required'), trigger: 'blur' },
    { min: 3, max: 20, message: usernameLengthMessage.value, trigger: 'blur' }
  ],
  email: [
    { required: true, message: t('common.required'), trigger: 'blur' },
    { type: 'email', message: emailFormatMessage.value, trigger: 'blur' }
  ]
}))
```

## 表格规范

以下基础表格和分页示例用于管理列表的领域操作。数据预览和查询结果的共享表格、分页及格式化契约见[数据服务结果渲染器](../components/预览与结果展示.md#数据服务结果渲染器)与[表格预览组合边界](../ARCHITECTURE.md#表格预览组合边界)，消费模块保留数据加载与领域操作，不复制共享结果实现。

### 1. 基础表格

以下为接入片段，`t` 复用模块国际化上下文。`name`、`email` 是示例行字段，映射、数据读取、操作权限与编辑／删除处理由 Owner 负责；邮箱标签借用 System 的现有词条，实际模块使用自己的业务词条。

```vue
<template>
  <el-table :data="tableData" stripe>
    <el-table-column prop="name" :label="t('common.name')" width="180" />
    <el-table-column prop="email" :label="t('system.iam.account.email')" />
    <el-table-column :label="t('common.actions')" width="180">
      <template #default="{ row }">
        <el-button size="small" @click="handleEdit(row)">{{ t('common.edit') }}</el-button>
        <el-button size="small" type="danger" @click="handleDelete(row)">{{ t('common.delete') }}</el-button>
      </template>
    </el-table-column>
  </el-table>
</template>
```

### 2. 分页表格

页码、每页条数和总数由 Owner 提供，分页变化后的加载或切片也由 Owner 处理；本片段只示意管理列表布局。分页内置文案跟随 [Element Plus locale](../../../docs/spec/addp国际化开发规范.md#element-plus)，不另写固定语言。

```vue
<template>
  <div class="table-container">
    <el-table :data="tableData" stripe>
      <!-- 表格列 -->
    </el-table>

    <el-pagination
      v-model:current-page="currentPage"
      v-model:page-size="pageSize"
      :total="total"
      :page-sizes="[10, 20, 50, 100]"
      layout="total, sizes, prev, pager, next, jumper"
    />
  </div>
</template>

<style scoped>
.table-container {
  display: flex;
  flex-direction: column;
  gap: 16px;
}
</style>
```

## 按钮规范

示例复用已有公共词条；按钮尺寸与样式在模板中表达，具体动作、可用性和权限由 Owner 决定。页面中的业务操作文案使用本模块词条，词条归属见[国际化规范](../../../docs/spec/addp国际化开发规范.md#key-命名)。

### 1. 按钮类型

```vue
<template>
  <!-- 主要操作 -->
  <el-button type="primary">{{ t('common.save') }}</el-button>

  <!-- 次要操作 -->
  <el-button>{{ t('common.cancel') }}</el-button>

  <!-- 成功操作 -->
  <el-button type="success">{{ t('common.confirm') }}</el-button>

  <!-- 警告操作 -->
  <el-button type="warning">{{ t('common.warning') }}</el-button>

  <!-- 危险操作 -->
  <el-button type="danger">{{ t('common.delete') }}</el-button>

  <!-- 信息操作 -->
  <el-button type="info">{{ t('common.info') }}</el-button>

  <!-- 文本按钮 -->
  <el-button text>{{ t('common.detail') }}</el-button>
</template>
```

### 2. 按钮尺寸

```vue
<template>
  <el-button size="large">{{ t('common.save') }}</el-button>
  <el-button>{{ t('common.save') }}</el-button>
  <el-button size="small">{{ t('common.save') }}</el-button>
</template>
```

### 3. 按钮组

```vue
<template>
  <el-button-group>
    <el-button type="primary"><el-icon><ArrowLeft /></el-icon> {{ t('pagination.prev') }}</el-button>
    <el-button type="primary">{{ t('pagination.next') }} <el-icon><ArrowRight /></el-icon></el-button>
  </el-button-group>
</template>
```

## 对话框规范

示例沿用模块已初始化的 Vue I18n，公共按钮使用 `common.*`，业务标题和字段使用所属模块词条；初始化与词条归属见[国际化规范](../../../docs/spec/addp国际化开发规范.md#前端规范)。初始焦点按下方类型规则安排，`opened` 时的共享聚焦只作安全补充，不能代替初始焦点安排；关闭后恢复到稳定触发控件。

### 1. 基础对话框

以下只读详情示例使用公共词条；内容由宿主通过默认插槽提供：

```vue
<script setup>
import { ref } from 'vue'
import { useI18n } from 'vue-i18n'
import { focusElement } from '@common-ui'

const { t } = useI18n()
const dialogVisible = ref(false)
const triggerButton = ref(null)
const closeButton = ref(null)
const restoreTriggerFocus = () => focusElement(triggerButton.value)
</script>

<template>
  <el-button ref="triggerButton" @click="dialogVisible = true">
    {{ t('common.detail') }}
  </el-button>
  <el-dialog
    v-model="dialogVisible"
    class="addp-dialog"
    :title="t('common.detail')"
    width="min(500px, calc(100vw - 24px))"
    @opened="focusElement(closeButton, { preserveDialogFocus: true })"
    @closed="restoreTriggerFocus"
  >
    <slot />
    <template #footer>
      <el-button ref="closeButton" @click="dialogVisible = false">
        {{ t('common.close') }}
      </el-button>
    </template>
  </el-dialog>
</template>
```

### 2. 表单对话框

表单复用上例的 `addp-dialog` 外壳、可见状态和关闭恢复处理；以下仅展示替换正文的字段片段，以 System 用户表单的现有词条为例。Owner 提供 `form`、`usernameInput` 和校验／提交处理，将标题设为 `t('system.iam.users.edit')`；页脚按取消、保存排序，分别使用 `t('common.cancel')`、`t('common.save')`。初始焦点优先指向首个主要输入，打开后的补充聚焦目标改为 `usernameInput`，仍传 `preserveDialogFocus: true`。

```vue
<template>
  <el-form :model="form" label-position="top">
    <el-form-item :label="t('system.iam.users.username')">
      <el-input ref="usernameInput" v-model="form.username" />
    </el-form-item>
    <el-form-item :label="t('system.iam.users.email')">
      <el-input v-model="form.email" />
    </el-form-item>
  </el-form>
</template>
```

所有业务对话框使用共享 `addp-dialog` 类。该类统一标题、正文、页脚间距，并限制正文最大高度；内容超过可用高度时只滚动正文，标题和操作按钮保持可见。宽度必须同时声明桌面目标宽度和 `100vw - 24px` 的窄窗口上限，不能只写固定像素宽度。

页脚操作按钮默认作为一组整体右对齐，不得把取消按钮和主操作分散到页脚两端。组内从左到右依次为取消、关闭或返回等次要操作，危险但非推荐的操作，以及唯一推荐的主操作；主操作始终位于最右侧。只有一个关闭按钮时，该按钮也保持右对齐。页脚允许按钮在窄窗口下换行，不能让按钮或文字溢出对话框。字段较少的业务表单优先使用顶部标签，避免长标签在窄窗口中挤压输入区域。

`ElMessageBox.confirm` 类确认框使用共享 `addp-message-box` 类，并显式传入已国际化的确定、取消按钮文案，不得依赖 Element Plus 的默认语言。按钮组整体右对齐，取消在确认左侧、确认位于最右侧；删除、清空等不可逆操作的确认按钮必须使用危险样式。

弹窗打开后必须有明确且安全的初始焦点：表单弹窗优先聚焦首个主要输入字段，只读弹窗优先聚焦关闭按钮，包含不可逆操作的弹窗优先聚焦取消按钮。关闭弹窗后应把焦点恢复到触发该弹窗的控件；下拉菜单项触发或连续弹窗等无法依赖组件默认恢复的场景，调用方必须显式恢复到稳定的触发按钮。弹窗继续使用 Element Plus 的焦点陷阱和 `Esc` 关闭能力，不在业务模块重复实现焦点循环。

打开动画结束时的初始聚焦不得覆盖用户已经在弹窗内进行的输入或下拉选择。该场景统一调用共享 `focusElement(target, { preserveDialogFocus: true })`；明确的用户操作（例如加载最新版本后重新定位）仍可使用普通聚焦。不要以增加固定等待或自动重开下拉框掩盖迟到的焦点覆盖。

## 消息提示规范

以下示例的消息调用放在已取得组件 `t` 的操作处理函数中，导入保持模块顶层；文案在调用时按当前语言解析，是否提示及其结果语义由业务 Owner 决定。语言切换、已有校验错误和新消息的实际表现由消费模块浏览器回归核对，验证分层见[工程约束](工程约束.md#测试规范)与[国际化验证方式](../../../docs/spec/addp国际化开发规范.md#验证方式)。

### 1. Message 消息

```javascript
import { ElMessage } from 'element-plus'

// 成功
ElMessage.success(t('common.success'))

// 警告
ElMessage.warning(t('common.warning'))

// 错误
ElMessage.error(t('common.failed'))

// 信息
ElMessage.info(t('common.info'))
```

### 2. MessageBox 确认框

确认框的共享样式、国际化按钮、危险操作和焦点要求统一见[对话框规范](#对话框规范)；确认后的领域操作仍由业务模块处理。

### 3. Notification 通知

以下以 Owner 已确认的保存成功结果为例：

```javascript
import { ElNotification } from 'element-plus'

ElNotification({
  title: t('common.success'),
  message: t('common.saveSuccess'),
  type: 'success'
})
```

## 无障碍规范（Accessibility）

### 1. 语义化 HTML

使用正确的 HTML 标签：

```vue
<template>
  <!-- ✅ 正确 -->
  <header>页头</header>
  <nav>导航</nav>
  <main>主内容</main>
  <footer>页脚</footer>

  <!-- ❌ 错误 -->
  <div class="header">页头</div>
  <div class="nav">导航</div>
</template>
```

### 2. ARIA 属性

为交互元素添加 ARIA 属性：

```vue
<template>
  <button
    :aria-label="t('common.close')"
    @click="handleClose"
  >
    <el-icon><Close /></el-icon>
  </button>
</template>
```

### 3. 键盘导航

确保所有交互元素可通过键盘访问：

- Tab：焦点移动
- Enter / Space：确认操作
- Esc：关闭对话框/弹窗

### 4. 动态状态播报

校验、保存、执行等异步状态不能只依赖颜色、加载图标或短暂提示。业务页面应使用共享 `StatusAnnouncer` 播报进行中和校验结果；普通进度使用 `role="status"` 和 `aria-live="polite"`，需要用户立即处理的错误继续使用具备 alert 语义的错误提示组件，避免同一消息重复播报。

纯图标按钮必须提供国际化的 `aria-label`。Tooltip 只用于视觉说明，不能代替按钮的可访问名称。

### 5. 可拖拽分隔条

可拖拽分隔条必须同时支持键盘操作：使用 `role="separator"`、正确的 `aria-orientation`、`aria-valuemin/max/now` 和受控区域 `aria-controls`；方向键逐步调整，`Home` / `End` 跳到最小/最大尺寸，并提供清晰的 `:focus-visible` 状态。

### 6. DAG 编辑交互

Canvas DAG 编辑器的节点导航、端口拖拽与键盘依赖编辑统一见 [DAG 键盘与依赖编辑](../../dag/README.md#键盘与依赖编辑)。当前节点名称和校验问题数量通过带名称的共享 `StatusAnnouncer` 播报。

DAG 连线不得要求进入全局“连线模式”。画布边是依赖关系的唯一编辑事实源，表单操作必须复用同一套环路、重复连接校验和历史记录。
