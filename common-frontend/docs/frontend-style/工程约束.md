## 组件开发规范

### 1. 新建共享组件

当需要创建可复用的组件时，遵循以下规则：

#### 1.1 创建前检查与唯一所有权

创建前检索、复用与提炼、领域适配边界及重复职责判定统一遵循[开发原则的唯一实现规则](../../../docs/spec/addp开发原则.md#8-dry-dont-repeat-yourself--不要重复自己)。检索范围包括 `common-frontend/` 和各业务模块中的组件、composable 与工具函数；已有契约缺少稳定的通用能力时扩展原实现，不新建旁路组件。

模块可以保留只负责数据适配、领域编排或依赖装配的薄适配器。替换旧实现时，同一次变更删除旧组件、旧导出和旧调用路径，不保留兼容分支。

跨模块共享组件必须增加最小充分测试；容易再次被复制的关键能力应增加所有权测试，约束消费端组合规范实现而非直接重写，验证分工见[测试规范](#测试规范)。

#### 1.2 组件分类

按[共享前端架构的子包职责](../ARCHITECTURE.md#目录结构)选择 Basic、Map、Chart、DAG、Graph 或 Agent UI 入口；文件预览使用 `basic/src/previews.js` 独立入口。依赖、别名与 Vue 单一实例的接入要求见[接入与验证](../ARCHITECTURE.md#接入与验证)。

#### 1.3 组件导出

公共导出维护在所属子包入口，文件预览遵循独立入口约束。以下仅演示基础组件的导出：

```javascript
// common-frontend/basic/src/index.js
export { default as MyComponent } from './components/MyComponent.vue'
```

#### 1.4 组件使用

以下使用基础组件别名 `@common-ui`；其他入口与按需依赖见[共享前端使用方法](../ARCHITECTURE.md#使用方法)：

```vue
<script setup>
import { MyComponent } from '@common-ui'
</script>

<template>
  <MyComponent />
</template>
```

### 2. 组件样式规范

#### 2.1 Scoped 样式

所有组件必须使用 `<style scoped>`，避免样式污染：

```vue
<style scoped>
.my-component {
  background: var(--addp-bg-primary);
  padding: 16px;
}
</style>
```

#### 2.2 深度选择器

需要修改子组件样式时，使用 `:deep()` 选择器：

```vue
<style scoped>
.my-component :deep(.el-input__wrapper) {
  background: var(--addp-bg-secondary);
}
</style>
```

#### 2.3 禁止使用内联样式

**禁止**在模板中使用 `style` 属性：

```vue
<!-- ❌ 错误 -->
<div style="background: #ffffff; color: #303133;">内容</div>

<!-- ✅ 正确 -->
<div class="content-box">内容</div>

<style scoped>
.content-box {
  background: var(--addp-bg-primary);
  color: var(--addp-text-primary);
}
</style>
```

**例外情况**：动态样式可以使用 `:style` 绑定，但值应来自计算属性或响应式变量。

## 性能优化规范

### 1. 组件懒加载

对于大型组件，使用懒加载：

```javascript
const MyComponent = defineAsyncComponent(() =>
  import('./components/MyComponent.vue')
)
```

### 2. 列表虚拟滚动

对于超长列表，使用虚拟滚动：

```vue
<template>
  <el-table-v2
    :columns="columns"
    :data="data"
    :width="700"
    :height="400"
  />
</template>
```

### 3. 图片懒加载

```vue
<template>
  <el-image
    :src="imageUrl"
    lazy
  />
</template>
```

## 国际化规范

语言代码、词条归属、初始化和请求语言统一遵循[国际化开发规范](../../../docs/spec/addp国际化开发规范.md#前端规范)，整体流转见[国际化体系图](../../../docs/concepts/addp国际化体系图.md)。本规范只保留界面接入要点。

### 1. Element Plus 国际化

Element Plus locale 必须随当前 Vue I18n locale 响应式切换，日期、分页和选择器等组件与业务界面保持同一语言，不能在 `app.use(ElementPlus)` 中固定中文。可参考[System 根组件](../../../system/frontend/src/App.vue)中 `el-config-provider` 与计算属性的组合。

### 2. 自定义国际化

模块使用共享 `createAddpI18n()` 初始化，沿用 `zh-cn`、`en` 和 `addp-lang`，合并公共词条与本模块 `src/i18n/` 词条。不要另建 `createI18n()` 实例或复制共享词条；同名命名空间合并不能删除未覆盖的公共词条。

初始化示例只在[统一初始化规范](../../../docs/spec/addp国际化开发规范.md#初始化)维护；iframe 模块启用 Console 语言监听，Console 自身使用 `listenToConsole: false`。组件使用 `t()` 或共享 `useAddpI18n()`，请求统一携带当前 `Accept-Language`。

验证页面及 Element Plus 文本即时切换、刷新后语言保持和 Console 与 iframe 同步，具体要求见[国际化验证方式](../../../docs/spec/addp国际化开发规范.md#验证方式)。

## 代码规范

### 1. 命名规范

- **组件文件名**：PascalCase（大驼峰），如 `UserList.vue`
- **组件名称**：与文件名一致
- **变量/函数**：camelCase（小驼峰），如 `userData`、`fetchUserList()`
- **常量**：UPPER_SNAKE_CASE（大写下划线），如 `API_BASE_URL`
- **CSS 类名**：kebab-case（短横线），如 `.user-list-container`

### 2. 文件组织

```
module/frontend/
├── src/
│   ├── api/              # API 接口
│   ├── assets/           # 静态资源
│   ├── components/       # 组件
│   ├── router/           # 路由
│   ├── store/            # 状态管理
│   ├── views/            # 页面
│   ├── utils/            # 工具函数
│   ├── App.vue
│   └── main.js
└── package.json
```

### 3. 代码注释

为复杂逻辑添加注释：

```javascript
/**
 * 获取用户列表
 * @param {Object} params - 查询参数
 * @param {number} params.page - 页码
 * @param {number} params.pageSize - 每页数量
 * @returns {Promise<Array>} 用户列表
 */
async function fetchUserList(params) {
  // 实现代码
}
```

## 测试规范

门禁选择与执行命令统一见[标准入口](../../../docs/spec/addp测试与验收规范.md#三标准入口)，环境与证据层级见[测试分层](../../../docs/spec/addp测试与验收规范.md#二测试分层)。前端专项门禁用于对应范围验证，不能代替受影响的完整模块门禁。

### 1. 单元测试

沿用 owner 已有测试框架和标准入口，不统一要求新建 Vitest 工程。共享组件测试与消费模块组合验证的归属、入口统一见[共享前端测试说明](../../README.md#测试)。

断言应覆盖本次变化涉及的输入输出、状态和交互，不能只套用通用的 Hello 文本示例。

### 2. E2E 测试

确定性 Playwright 的夹具、端口、进程与清理规则见 [T3 规范](../../../docs/spec/testing/T0-T3测试规范.md#t3)，启动器和配置接入见[浏览器测试隔离](../../README.md#浏览器测试隔离)。断言地址使用共享 `baseURL` / `browserTestOrigin`，不固定 Console 端口、默认账号或密码，也不复用正在运行的开发服务。

涉及真实 System、Gateway、owner Backend、身份与数据源的链路，按[T4 Online 规范](../../../docs/spec/testing/T4-Online验收规范.md)选择已登记 suite 与规定测试部署；执行入口见本节篇首。确定性夹具回归不能计为真实链路通过。

静态检查、单元测试、确定性浏览器回归和真实运行验收分别记录命令、结果与覆盖范围；未运行、失败或跳过项不能计为通过。

## 版本控制规范

### 1. Git 提交消息

使用语义化提交消息，按实际变更选择 `feat`、`fix`、`style`、`refactor`、`docs` 或 `perf`，需要时注明模块 scope，例如 `docs(common-frontend): 整理主题接入规范`。提交与验证规则统一遵循[开发原则](../../../docs/spec/addp开发原则.md)。

### 2. 分支策略

单人开发阶段，人工和 AI 直接使用 `main`，不创建 develop、feature 或 fix 分支。Renovate 自动依赖升级是唯一例外，使用 `renovate/` 前缀并在合并或关闭后删除；以[仓库工作规则](../../../AGENTS.md)为准。
