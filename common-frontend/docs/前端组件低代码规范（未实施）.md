# 微前端组件（SuperMap-Micro-Widget）规范（初稿）

> 本文档参考SuperMap微前端组件规范，适用于ADDP平台的前端组件开发

## 设计

### 1. 整体设计

微前端组件系统采用分层架构，主要包括：

- **mse-lowcode** - 低代码平台层
  - **mse-console - 控制台/入口
  - 核心模块：
    - **mse-widgets-basis** - 组件基础框架
    - **mse-amis-editor** - 页面设计器
    - **mse-flowgram** - 流程编排设计器
    - **mse-code-editor** - 代码编辑器
    - **mse-package-plugin** - 插件打包
  - 底层引擎：
    - **amis** - 渲染引擎
    - **lowcode-engine** - 低代码引擎

### 2. 微组件设计

微组件包含以下核心部分：

#### 组件入口
- **组件标识 (type)** - 组件的唯一标识符
- **属性定义 (props)** - 组件配置属性
- **状态定义 (state)** - 组件内部状态
- **组件信息 (info)** - 元数据信息

#### 主渲染器
- 基于React/Vue3框架实现
- 纯函数式组件，由props驱动

#### 设置器
- **配置内导框** - 组件属性配置面板
- **石棺配置面板** - 样式配置
- **监听事件定义** - 组件可监听的事件
- **触发事件定义** - 组件可触发的事件

#### 组件样式
- **全局样式变量** - 主题级别的样式定义
- **组件自定义样式** - 组件特有的样式

#### 事件配置面板
提供可视化配置：
- **微组件** - 组件级别配置
- **页面** - 页面级别配置
- **弹框** - 弹窗交互配置
- **服务（API）** - 接口调用配置
- **自定义（JS）** - 自定义脚本

### 3. 基座设计

基座架构分为三层：

#### basis层
- **core** - 核心层
  - **components** - 组件库
    - **Common** - 公共组件（Style、InitRuntime、InitDepLibs）
    - **MsePageViewer** - 页面查看器
    - **MsePageEditor** - 页面编辑器
  - **Loader** - 加载器系统
    - **ReactLoader** - React组件加载器
    - **Vue3Loader** - Vue3组件加载器
    - **RemoteLoader** - 远程模块加载器（CSSLoader、JSLoader）
  - **Runtime** - 运行时环境
    - **RunEnv** - 运行环境
    - **AmisEnv** - Amis环境
- **interface** - 接口定义层

## 一、工程结构

### 1. 目录规范

规范化的目录结构是保证项目可维护性和工具链可交互性的基础。建议采用如下单仓库多组件的结构：

│   └─── vite-env.d.ts

## 二、组件库（资产包）

组件库（资产包）是将散落的组件、插件和资源组织成一个整体，供低代码引擎加载的集合。

### 1. assets.json

这是组件库的核心清单，由打包工具中的插件自动生成，声明了组件库的元信息、包含的组件、配置器（setter）和插件等。

#### 关键字段说明

- **name** - 组件库名称（统一使用中文）
- **code** - 组件库唯一标识（统一使用英文）
- **version** - 组件库版本
- **description** - 组件库描述
- **packages** - 组件库依赖（npm或其他第三方依赖）
- **widgets** - 组件列表

#### 示例

```json
{
  "name": "示例组件库",
  "code": "smwWidgetDemo",
  "version": "1.3.1",
  "description": "smw 示例组件",
  "packages": [
    {
      "name": "超图 3D 资源",
      "code": "SuperMap3D",
      "version": "1.0.1",
      "type": "script",
      "path": [
        "/widgets/config.js",
        "/widgets/aa.css"
      ]
    }
  ],
  "widgets": [
    {
      "name": "React 示例组件",
      "code": "smw-react-demo",
      "description": "React 示例组件",
      "icon": "fa fa-user",
      "framework": "react"
    }
  ]
}
```

### 2. 入口文件 index.ts

该文件是组件库的UMD打包入口，负责将组件和其低代码描述一并导出。引擎通过该文件获取组件的运行时实体和配置描述。

```typescript
import { Border1Widget } from './border_1'
import Package from '../package.json'
import type { LibraryInfo } from '@smw-lowcode/smw-widget-basis'

const libraryInfo: LibraryInfo = {
  name: '测试组件库',
  code: Package.name,
  description: Package.description,
  version: Package.version,
  widgets: [
    Border1Widget
  ]
}

export default libraryInfo
```

### 3. 第三方依赖资源

#### 依赖资源元数据

- **name** - 资源名称
- **version** - 资源版本
- **code** - 资源唯一标识
- **loadType** - 加载方式（npm或script）
- **urls** - 加载路径（可以动态解析公共变量）

#### a. npm依赖示例

对于外部依赖（如Ant Design、Lodash），应在assets.json的packages项中声明，并通过urls指定其CDN地址，以避免重复打包和版本冲突。低代码引擎会统一管理这些依赖的加载。

```json
{
  "packages": [
    {
      "name": "antd",
      "version": "5.12.0",
      "library": "antd",
      "type": "npm",
      "urls": [
        "https://unpkg.com/antd@5.12.0/dist/antd.min.js",
        "https://unpkg.com/antd@5.12.0/dist/antd.min.css"
      ]
    }
  ]
}
```

#### b. script路径依赖

对于有些无法通过npm安装到工程里面，统一打包的依赖，可以通过动态<script>标签加载。

```json
{
  "packages": [
    {
      "name": "SuperMap3D",
      "version": "5.12.0",
      "library": "SuperMap3D",
      "type": "script",
      "urls": [
        "https://unpkg.com/SuperMap3D@5.12.0/dist/SuperMap3D.min.js",
        "https://unpkg.com/SuperMap3D@5.12.0/dist/SuperMap3D.min.css"
      ]
    }
  ]
}
```

## 三、组件（物料）

组件是资产包的基本单元，其开发需要遵循"配置驱动"和"高内聚"的原则。

### 1. 组件入口 (index.ts)

此文件是单个组件的入口，负责导出组件的React或Vue3实现和其低代码物料描述。

#### 定义并导出内容

- **IProps** - 组件配置属性
- **IState** - 组件状态属性
- **WidgetCode** - 组件唯一标识
- **WidgetInfo** - 组件元数据信息

```typescript
import type { WidgetInfo } from '@smw-lowcode/smw-widget-basis'
import widget from './widget'
import { Border1WidgetPlugin } from './config'

// 组件编码（组件库内保持唯一）
export const WidgetCode = 'border_1'

// 组件 props 定义
export interface IProps {
  w: number
  h: number
  backgroundColor: string
  dur: number
  colors: string[]
  body: any
  render: any
}

// 组件 State 定义
export interface IState {
  loading: boolean
}

// 组件信息
export const Border1WidgetInfo: WidgetInfo = {
  // ... 组件元数据
}
```

### 2. 渲染器

渲染器是组件的核心，负责根据配置属性（props）进行UI渲染。它必须是一个纯函数式的React/Vue组件，其行为完全由props驱动。

#### Vue3 (widget.vue)

```vue
<script setup lang="ts">
import { ref, onMounted } from 'vue'
import { smwEvent } from '@smw-lowcode/smw-widget-basis'
import { IProps } from 'index.ts'

// 组件状态
const state = ref<IState>({...})

// 组件属性
const props = defineProps<IProps>({...})

// 组件触发事件
const onClick = () => {
  console.log('btn click...')
  props.smwEvent.emit('click', { anb: 123 })
}

// 组件监听事件
onMounted(() => {
  props.smwEvent.on('message', (args: any) => {
    console.log(args)
    alert('监听到事件触发')
  })
})
</script>
```

#### React (widget.tsx)

```typescript
import React from 'react'
import type { RendererProps } from 'smw-core'
import { ScopedContext } from 'smw-core'
import './style.css'

export default class LeafletWidget extends React.Component<IProps, IState> {
  static contextType = ScopedContext

  constructor(props: RendererProps) {
    super(props)
    this.props = props
    this.handleClick = this.handleClick.bind(this)
  }

  componentDidMount() {
    this.context?.registerComponent(this)
  }

  componentWillUnmount() {
    this.context?.unRegisterComponent(this)
  }

  doAction(action: any, args: any) {
    const actionType = action ? action.actionType : ''
    if (actionType === 'message') {
      // 处理消息
    }
  }

  render() {
    // 渲染逻辑
  }
}
```

## 四、公共APIs

### 1. 路由

#### Router结构说明

| API              | 函数签名                         | 说明                                                                 |
| ---------------- | -------------------------------- | -------------------------------------------------------------------- |
| getCurrentRoute  | () => Route                      | 获取当前解析后的路由信息，RouteLocation结构详见下面说明             |
| push             | (target: string \| Route) => void | 路由跳转方法，跳转到指定的路径或者Route                             |
| replace          | (target: string \| Route) => void | 路由跳转方法，与push的区别在于不会增加一条历史记录而是替换当前的历史记录 |
| open             | (target: string \| Route) => void | 新Tab页打开路由                                                      |

#### Route（路由信息）结构说明

| 参数     | 说明                                     | 类型       | 可选值      | 默认值 | 备注                                       |
| -------- | ---------------------------------------- | ---------- | ----------- | ------ | ------------------------------------------ |
| path     | 当前解析后的路径                         | String     | -           | -      | 必填                                       |
| hash     | 当前路径的hash值，以#开头                | String     | -           | -      | 必填                                       |
| host     | ip+端口                                  | string     | -           | -      | 必填                                       |
| query    | 当前的路径query对象                      | Object     | -           | -      | 必填，代表当前地址的search属性的对象       |
| protocol | 网络协议                                 | http/https | -           | -      | 选填                                       |
| fullPath | 包括search和hash在内的完整地址           | String     | -           | -      | 选填                                       |

#### 使用示例

```javascript
import { useRouter } from '@mse-lowcode/mse-widget-basis'

const router = useRouter()

// 获取路由信息
router.getCurrentRoute()

// 路由跳转
router.push('/home')
router.push({ path: '/user', query: { id: 1 } })

// 替换当前路由
router.replace('/login')

// 新标签页打开
router.open('/detail')
```
