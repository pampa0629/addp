# 数据源选择器使用指南

本文档介绍 `common-frontend` 提供的数据源选择器组件的使用方法。

## 📋 概述

数据源选择器提供统一的数据源（表/对象）选择体验，支持：
- **多种数据源类型**：关系型数据库、NoSQL、分布式计算、对象存储
- **灵活配置**：根据模块需求过滤引擎类型和节点类型
- **两种 UI 形式**：Dialog（对话框）和 Card（卡片）
- **自动几何列检测**：自动检测空间表的几何列信息
- **单选/多选模式**、**懒加载优化**

**核心组件**：
- **DataSourceSelector**：核心选择器，提供完整功能
- **DataSourceSelectorDialog**：Dialog 包装，适合弹窗场景
- **DataSourceSelectorCard**：Card 包装，适合嵌入表单

**API 模块**：
- **dataSource.js**：封装 4 个数据源 API，自动处理认证

**后端支持**：
- **树构建器**：[common/resource/tree_builder.go](../../common/resource/tree_builder.go) - 统一的树构建逻辑
- **API 实现参考**：[service/backend/internal/api/data_source_handler.go](../../service/backend/internal/api/data_source_handler.go)

## 组件使用

### 1. DataSourceSelector

核心数据源选择器组件（[源码](../basic/src/components/DataSourceSelector.vue)）。

**关键 Props**：

| Prop | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `apiBaseUrl` | String | **必填** | API 基础路径，如 `/api/service` |
| `engineTypes` | Array | `[]` | 过滤引擎类型，如 `['postgresql', 'mysql']` |
| `dataSourceTypes` | Array | `[]` | 过滤数据源类型，如 `['database', 'object_storage']` |
| `selectableNodeTypes` | Array | `['table', 'object']` | 可选节点类型 |
| `selectionMode` | String | `'single'` | 选择模式：`'single'` 或 `'multiple'` |
| `enableGeometryDetection` | Boolean | `true` | 是否自动检测几何列 |
| `showGeometryTag` | Boolean | `true` | 是否显示几何标签 |
| `treeHeight` | String | `'400px'` | 树的高度 |

**关键 Events**：

| Event | 参数 | 说明 |
|-------|------|------|
| `@update:selection` | `selection: DataSourceSelection | Array` | 选择变化 |
| `@engine-change` | `engineId: Number` | 引擎切换 |
| `@geometry-detected` | `result: Object` | 几何列检测完成 |

**使用示例**：

```vue
<template>
  <DataSourceSelector
    api-base-url="/api/service"
    :engine-types="['postgresql', 'mysql']"
    :selectable-node-types="['table']"
    @update:selection="handleSelection"
  />
</template>

<script setup>
import { DataSourceSelector } from '@addp/common-frontend'

const handleSelection = (selection) => {
  console.log('选中:', selection)
  // { engineId, schema, tableName, fullName, locator, hasGeometry, ... }
}
</script>
```

### 2. DataSourceSelectorDialog

Dialog 包装（[源码](../basic/src/components/DataSourceSelectorDialog.vue)），适合弹窗场景。

**额外 Props**：`visible`、`title`、`width`、`confirmText`、`cancelText`

**额外 Events**：`@confirm`、`@cancel`、`@update:visible`

**使用示例**：

```vue
<template>
  <DataSourceSelectorDialog
    v-model:visible="dialogVisible"
    api-base-url="/api/service"
    title="选择数据表"
    @confirm="handleConfirm"
  />
</template>

<script setup>
import { ref } from 'vue'
import { DataSourceSelectorDialog } from '@addp/common-frontend'

const dialogVisible = ref(false)

const handleConfirm = (selection) => {
  console.log('确认选择:', selection)
}
</script>
```

### 3. DataSourceSelectorCard

Card 包装（[源码](../basic/src/components/DataSourceSelectorCard.vue)），适合嵌入表单。

**额外 Props**：`title`、`shadow`、`showHeader`

**使用示例**：

```vue
<template>
  <DataSourceSelectorCard
    api-base-url="/api/transfer"
    title="选择数据源"
    :engine-types="['postgresql', 'mysql']"
    @update:selection="form.dataSource = $event"
  />
</template>
```

## API 模块

**dataSource.js**（[源码](../basic/src/api/dataSource.js)）提供 4 个核心 API：

| API | 说明 | 后端端点 |
|-----|------|---------|
| `getEngines(apiBaseUrl, options)` | 获取引擎列表 | `GET /engines` |
| `getEngineTree(apiBaseUrl, engineId, options)` | 获取树结构（预加载） | `GET /engines/:id/tree` |
| `getNodeChildren(apiBaseUrl, nodeId)` | 懒加载子节点 | `GET /nodes/:id/children` |
| `detectTableMetadata(apiBaseUrl, params)` | 检测表元数据 | `GET /tables/metadata` |

**工具函数**：
- `parseLocator(locator)` - 解析 Locator URI
- `extractDataSourceSelection(node, options)` - 从树节点提取选择信息

**认证**：自动从 `localStorage` 读取 `token`，添加 `Authorization: Bearer <token>` 头。

## 树结构规范

### TreeNode 结构

后端返回的树节点必须符合以下结构（详见 [tree_builder.go](../../common/resource/tree_builder.go:11-22)）：

```typescript
interface TreeNode {
  id: string                    // 节点唯一标识（使用 locator 值）
  label: string                 // 显示标签
  type: string                  // 节点类型（见下表）
  locator: string               // ResourceLocator URI
  icon?: string                 // 图标名称
  hasChildren?: boolean         // 是否有子节点
  children?: TreeNode[]         // 子节点数组（初始为 []）
  metadata?: Record<string, any> // 元数据
}
```

### 节点类型

| type | 说明 | 适用引擎 |
|------|------|----------|
| `engine` | 引擎根节点 | 所有 |
| `schema` | Schema | PostgreSQL, MySQL, Doris, ClickHouse |
| `database` | Database | MongoDB |
| `table` | 表 | 关系型数据库 |
| `collection` | 集合 | MongoDB |
| `bucket` | 桶 | MinIO, S3 |
| `directory` / `prefix` | 目录 | MinIO, S3 |
| `object` | 对象 | MinIO, S3 |

### Locator 格式

Locator 是资源的唯一标识符，格式为：

```
addp://engine/{engineId}/path/{path}?type={type}
```

**示例**：
- PostgreSQL 表：`addp://engine/1/path/public/users?type=table`
- MinIO 对象：`addp://engine/2/path/bucket1/images/photo.jpg?type=object`

## 后端实现指南

### 标准实现（Service 模块）

Service 模块已实现完整的数据源 API（[源码](../../service/backend/internal/api/data_source_handler.go)），其他模块可参考或代理。

**4 个端点**：
1. `GET /api/service/engines` - 获取引擎列表
2. `GET /api/service/engines/:id/tree?expand_depth=2` - 获取树结构
3. `GET /api/service/nodes/:id/children` - 懒加载子节点
4. `GET /api/service/tables/metadata?engine_id=1&schema=public&table=users` - 检测表元数据

**使用 TreeBuilder**：

```go
import "github.com/addp/common/resource"

// 1. 获取 Meta 数据
metadataTree, _ := metaClient.GetMetadataTree(engineID)

// 2. 使用 TreeBuilder 构建树
treeBuilder := resource.NewTreeBuilder(nil)
treeNode, _ := treeBuilder.BuildFromMetadataTree(engine, metadataTree)

// 3. 返回
c.JSON(http.StatusOK, treeNode)
```

### 其他模块实现

**所有模块必须独立实现**自己的数据源 API Handler，**不能相互调用**（ADDP 架构原则：模块间除 System/Meta 外不能直接依赖）。

| 模块 | 实现方式 | API 路径 |
|------|---------|---------|
| Service | 已实现 | `/api/service/engines`, `/api/service/engines/:id/tree` 等 |
| Transfer | 需实现 | `/api/transfer/engines`, `/api/transfer/engines/:id/tree` 等 |
| Orchestrator | 需实现 | `/api/orchestrator/engines`, `/api/orchestrator/engines/:id/tree` 等 |
| Develop | 需实现 | `/api/develop/engines`, `/api/develop/engines/:id/tree` 等 |

**统一实现方式**：
1. 调用 System 客户端获取引擎列表
2. 调用 Meta 客户端获取元数据树
3. 使用 common 的 TreeBuilder 构建标准树结构

参考 Service 的 data_source_handler.go 实现即可，核心代码相同。

## 常见问题

### 1. 树显示"No Data"

**原因**：
- 后端 API 未正确返回数据
- 认证失败（检查 token）
- 树结构不符合规范（缺少 `children` 或 `hasChildren` 字段）

**解决**：
- 检查后端日志，确认 API 正常返回
- 使用浏览器开发者工具检查网络请求
- 确保返回的 TreeNode 结构符合规范

### 2. 几何列检测失败

**原因**：
- Meta 模块未扫描该表
- 表中没有空间列

**解决**：
- 在 Meta 模块中触发表扫描
- 检查表是否真的有几何列（如 `geometry`、`geom` 列）

### 3. 懒加载不工作

**原因**：
- 节点的 `hasChildren` 设置错误
- 后端 `/nodes/:id/children` API 未实现

**解决**：
- 确保 `hasChildren` 正确反映节点是否有子节点
- 实现懒加载 API（参考 Service 实现）

### 4. 引擎列表为空

**原因**：
- 当前租户下没有配置引擎
- `engineTypes` 过滤过严

**解决**：
- 在 System 模块中配置存储引擎
- 检查 `engineTypes` prop 是否正确

### 5. 多模块如何复用

**方案**：所有模块**独立实现**数据源 Handler，调用 System + Meta 客户端，使用 common 的 TreeBuilder。

**不能跨模块调用**（ADDP 架构原则：模块间除 System/Meta 外不能直接依赖）。
