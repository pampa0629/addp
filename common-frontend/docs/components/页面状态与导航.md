## 可见页面自动刷新

[AutoRefreshControl](../../basic/src/components/AutoRefreshControl.vue)唯一维护刷新选择及状态的中英文展示；[createAutoRefresh](../../basic/src/utils/autoRefresh.mjs)拥有定时器和可见性监听，固定选项来自 `autoRefreshOptions`（字符串值 `15`、`10`、`30`、`60`、`off`）。主机与服务资源页面组合这两个实现，不另写调度器。

Owner 提供 `interval()`、`enabled()`，后者结合当前授权、请求忙碌等状态决定是否允许调度；`refresh()` 执行一轮查询，`pause()` 取消或失效在途请求，`visibilityChanged(visible)` 同步显示状态。只有整轮请求完成后才调用 `schedule()`；隐藏时停止计时并调用 `pause()`，恢复可见且允许刷新时才调用 `refresh()`。共享工具不读取业务 API、Token 或 Router，不自动重试未完成的请求。

`stop()` 只清理定时器，用于路由或手工操作前；卸载时调用 `dispose()`，另释放可见性监听；两者均不代替 Owner 取消或失效在途请求，后者沿[请求隔离契约](#请求取消与迟到响应隔离)处理。Monitor 的默认间隔、HTTP 拒绝停刷、旧值与筛选处理见[模块前端规则](../../../monitor/CLAUDE.md#前端共享与导航)及其正式规范；共享工具不解释 HTTP 状态。页面组合及可见性、撤权、失败处理仍按[共享测试分工](../../README.md#测试)在 Monitor／Console 对应门禁中验证，未运行或未覆盖项不计通过。

## 自动筛选与已提交范围

[createAutoFilter](../../basic/src/utils/autoFilter.mjs)统一管理文本筛选的提交计时与 `pending`，不持有筛选字段，也不读取 Router、AuthStore 或业务 API。Owner 提供 `apply()`、`enabled()`、`visible()`、`pause()`：文本变化调用 `queue()`，使用共享 300 毫秒防抖；清空或有限选项提交调用 `submit()`；键盘 Enter 调用 `enter(event)`，输入法合成及 keyCode 229 不触发提交。

`queue()` 先清除旧计时，允许提交时置 `pending=true` 并调用 `pause()`；可见时才排队。`submit()` 先清除计时及 `pending`，再检查 `enabled()` 并调用 `apply()`；它不另检查 `visible()`。隐藏时通过 `visibilityChanged(false)` 暂停计时并保留待提交状态，恢复可见后重新排队，最终提交仍复核 `enabled()`。当前页面、身份与功能权限是否允许提交由 Owner 提供，不因已排队而冻结授权。

与[自动刷新](#可见页面自动刷新)组合时，Owner 将 `pause()` 接到刷新 `stop()`，并在刷新 `enabled()` 中排除 `filterInput.pending`；后台刷新仅读取已提交范围，不调用筛选 `apply()` 或带入未提交文本。Owner 在 `apply()` 中核验完整筛选和时间有效性、提交 canonical URL 并处理业务失败；`pending=false` 只表示不再等待计时，不证明筛选已生效、读取已成功或已获授权。监控列表的提交、分页、相同 URL 恢复调度及手动刷新规则统一见[正式筛选与展示口径](../../../docs/spec/addp平台运行观测规范.md#63-趋势时段比较与总览)。

重置、手动刷新、路由／身份变化等操作由 Owner 调用 `cancel()`，卸载调用 `dispose()`；它们仅清理筛选计时和待提交标记，不改写 Owner 的输入值，也不取消已发出的业务请求。在途请求沿[请求隔离契约](#请求取消与迟到响应隔离)处理；`apply()` 的拒绝与错误仍由 Owner 处理，共享工具不自动重试或把失败当成功。共享生命周期、页面衔接与真实筛选验收按[测试分工](../../README.md#测试)分别记录，静态核对不证明权限、草稿恢复或请求取消已通过运行验收。

## 请求取消与迟到响应隔离

[createLatestRequestScope](../../basic/src/utils/latestRequestScope.mjs)统一拥有传输取消与请求代数。每轮先 `invalidate()` 取消已登记请求并取得 ticket，轮内通过 `request(work)` 将 `{ signal }` 传给请求客户端；成功、失败或结束处理写回页面状态前，Owner 都须检查 `current(ticket)`。底层即使忽略取消仍可能返回旧结果，作用域不会替调用方丢弃返回值。

卸载时调用 `dispose()`，使旧 ticket 失效并拒绝新的 `request()`。传输错误继续抛出；领域分页、授权判断、错误分类与旧状态清理仍归 Owner，不能以请求已取消代替当前权限核验。需要自动刷新的页面由 Owner 按[自动刷新契约](#可见页面自动刷新)组合两种工具，不另建一套取消状态；主机与服务监控的接入及迟到响应回归沿[共享测试与消费方分工](../../README.md#测试)分别记录，不将静态工具核对算作页面或真实请求验收。

## 按任务查看关联编排

`buildOrchestrationListRoute({ module, task_type, task_id })` 构造 Orchestrator 编排列表的唯一公开筛选路由，配合 `openConsoleRoute()` 跨模块导航。筛选三项必须完整，任务 ID 为正整数；`resolveOrchestrationTaskFilter(query)` 供 owner 恢复、验证同一契约。关联由编排步骤引用即时决定，不持久化反向绑定。

## 统一任务监控跳转

业务模块的任务定义列表和任务详情应使用共享按钮进入带 owner 筛选的 Monitor，不得各自实现模块级执行列表或重复导航逻辑：

```vue
<script setup>
import { MonitorExecutionsButton } from '@addp/common-frontend'
</script>

<template>
  <MonitorExecutionsButton module="transfer" task-type="sync" />
  <MonitorExecutionsButton
    module="transfer"
    task-type="sync"
    :source-task-id="task.id"
    scope="task"
  />
</template>
```

任务执行接口返回统一 `execution_id` 后，通过公共工具定位单次执行：

```js
import { openMonitorExecution } from '@addp/common-frontend'

await openMonitorExecution(execution.execution_id)
```

`MonitorExecutionsButton` 统一生成 `module + task_type + source_task_id` 查询并负责 Console bridge 导航；`openMonitorExecution()` 定位单次执行。两者在模块独立运行时都会回退到 Console 路由。业务模块不要自行硬编码 Console 端口、拼接跨模块 iframe URL，或复制按钮文案与交互。

## 模块公开导航与历史

模块内公开导航使用 `navigateConsoleModuleRoute()`；跨模块或需要由 Console 加载目标页面时使用 `openConsoleRoute()`。只有页面已经自行完成受控状态切换、只需要同步地址栏时，才直接使用底层 `syncConsoleRoute()`：

```js
import {
  buildManagerDataExplorerRoute,
  navigateConsoleModuleRoute,
  openConsoleRoute,
  syncConsoleRoute
} from '@addp/common-frontend'

await navigateConsoleModuleRoute(router, 'develop', {
  path: '/workflow',
  query: { action: 'edit', id: '544' }
})
await openConsoleRoute(buildManagerDataExplorerRoute(resourceLocator))
await openConsoleRoute('/manager/spatial-quick-view/vector-tile-cache?create=1')
await syncConsoleRoute('/manager/data-explorer?locator=...', { history: 'replace' })
```

`navigateConsoleModuleRoute()` 和 `openConsoleRoute()` 默认使用 `push`；`syncConsoleRoute()` 默认使用 `replace`，也可显式选择 `push`，仅用于当前 iframe 已完成的自身模块导航。standalone 下的模块内导航由模块 Router 执行所选历史操作。默认值与调用路径分别见[模块导航工具](../../basic/src/utils/moduleRouteNavigation.js)和[Console 导航工具](../../basic/src/utils/taskOwnerUrl.js)。

动作对应的历史选择、iframe 单条公开历史和同步时不重载规则统一见[浏览器历史语义](../../../docs/spec/addp前端路由与可恢复状态规范.md#六浏览器历史语义)、[Console 与模块同步](../../../docs/spec/addp前端路由与可恢复状态规范.md#七console-与模块同步)。创建成功的落点还须遵循[Canonical URL](../../../docs/spec/addp前端路由与可恢复状态规范.md#五canonical-url)中的读取权限分支，不为跳转扩大权限。导航失败必须暴露，不回退硬编码端口、旧参数或另一条路径。

跨模块打开 Manager 数据探查时必须使用 `buildManagerDataExplorerRoute(locator)`；它只接受 ResourceLocator 主身份并生成唯一公开路由。业务模块不得自行拼接 `/manager/data-explorer`、并行传递 `engine_id/schema/table`，也不得先请求 Meta 补齐 locator。

## 引擎监控跳转与请求隔离

System 引擎部署的“查看监控”使用 `openConsoleRoute(buildMonitorEngineResourcesRoute({ deployment_id }))`，由 Console 加载 Monitor。Monitor 页内切换使用同一契约的 `buildMonitorEngineResourcesLocation(query)`；查询参数的业务校验仍由 Monitor 维护。禁止用 System Router 执行 Monitor 的模块内导航。跨模块进入、返回恢复和无观测权限时不显示入口由既有 `make test-console-frontend` 浏览器门禁覆盖，无新增依赖或 CI 入口。

引擎页面与主机、服务监控共用[请求取消与迟到响应隔离](#请求取消与迟到响应隔离)；引擎筛选、授权与展示仍归 Monitor，通用 ticket 和传输生命周期不在本节重复维护。

## 模块实例登记端点

`getRegisteredEndpoint()`（`basic/src/utils/moduleRuntimeEndpoint.mjs`）是模块实例登记端点的唯一展示解析器。System 实例管理与 Monitor 服务监控均直接消费；它只提取服务 URL 或缺省时健康检查 URL 的 HTTP(S) 主机和端口，不显示路径/查询/凭据，不做 DNS 或宿主节点推断。无端点返回空值，由各领域展示相应空态。消费方沿既有 System、Monitor 和 Console 前端门禁验证。

## 执行血缘资源摘要

执行详情中的 `addp.lineage-facts/v1` 统一通过 `buildExecutionLineageSummary(metadata)` 归一化；它只处理上游已授权的事实，不代替 API 权限或安全裁剪。业务 ResourceLocator 复用共享定位符能力显示可读路径。Monitor 按 `inputs` 和 `outputs` 展示资源摘要，仅可解析的业务输入提供数据探查动作，并使用 `buildManagerDataExplorerRoute(locator)` 与 `openConsoleRoute()` 进入 Manager，不请求 Meta 补齐身份。

`addp-infra://` 只表示平台内部产物，显示文件名及内部产物标记，不提供 Meta 或 Manager 跳转；它不是业务数据项，也不能据其存储位置推断临时或长期生命周期。通用摘要不取代 Owner 专业血缘或 Meta 关系图，API 的字段范围与读取裁决沿[执行监控契约](../../../docs/spec/tasks/执行监控.md#租户执行诊断)。

## 数据元确定修订跳转

数据元冻结引用使用 `buildStandardElementRevisionRoute(elementId, revisionId)` 构造唯一公开地址，再调用 `openConsoleRoute()`。Standard 页内历史选择使用同一契约的 `buildStandardElementRevisionLocation()`；两个 ID 必须为正整数，禁止跳到默认当前修订替代历史引用。

## Console 页面描述与最近访问

Console 只自动记录侧边栏中的固定菜单路由。固定菜单的短标签若依赖侧边栏模块上下文，Console 配置必须另设全局语境下可独立识别的 `recentLabel`。详情、工作台、任务和执行等动态页面必须由业务模块在对象加载完成后通过 `useConsolePageDescriptor()` 提供页面语义；Console 不解析业务路由，也不跨模块查询对象名称。

```js
import { computed } from 'vue'
import { useConsolePageDescriptor } from '@common-ui'

useConsolePageDescriptor(router, 'graph', {
  title: computed(() => t('graph.browser.recentVisitTitle')),
  subject: computed(() => graph.value?.name || ''),
  ready: computed(() => Boolean(graph.value)),
})
```

- 展示统一为“页面标题 · 业务对象名称”；没有业务对象时只显示页面标题。
- `title` 是 Console 全局语境中的业务对象类型，必须脱离模块和页面上下文后仍能独立识别，例如“传输任务”“图谱构建任务”“质量检查执行”。不要直接复用“任务详情”“执行详情”“服务信息”等局部页面标题。
- `subject` 只承载具体对象的名称、标题或业务编码；不能依赖名称中恰好出现“导入”“导出”等词来补足 `title` 的业务语义。
- `title`、`subject`、`ready` 和 `recent` 可以是普通值、`ref` 或 `computed`，语言或对象变化后会自动重新发布。
- `subject` 优先使用名称、标题或业务编码；仅当对象确实没有业务名称时使用 ID。
- 创建、编辑、登录、OAuth 回调等临时页面不声明页面描述，因此不进入最近访问。
- 稳定动态页面必须等对象加载完成后再令 `ready=true`，不得先用模块名或路由参数占位。
- 最近访问保存完整公开 `fullPath`，包括可恢复状态所需的 query。
- 页面描述只提供展示语义，不执行导航；同源活动 iframe、已提交完整路由、当前页面权限和先到／迟到描述的接收规则统一见[Console 与模块同步](../../../docs/spec/addp前端路由与可恢复状态规范.md#七console-与模块同步)。真实路由变化沿[模块公开导航与历史](#模块公开导航与历史)的共享入口提交。

多个页面共享的稳定 Tab 使用 `resolveCanonicalTabRouteState()` 解析。业务模块负责提供允许值、默认值，以及已经按 owner 事实验证过的伴随 query；该函数统一省略默认 Tab、删除未知参数，并返回是否需要 `replace` 到 canonical URL。

## 关联流程与执行确认

`RelatedOrchestrationsDialog` 接收完整任务引用集合、由宿主认证 client 创建的 `createOrchestrationAPI(client)` 和权限布尔值，展示匹配流程及其全部步骤。`OrchestrationExecuteButton` 是 Model 与 Orchestrator 唯一执行确认实现，防止重复提交并返回 execution_id；不自动重试执行请求。Model 只组合物化任务身份。匹配复用 `matchesOrchestrationTask`，不按名称猜测关联。

## 未保存修改的离页保护

编辑器使用 `useUnsavedChangesGuard({ router, isDirty, shouldConfirmUpdate })`，传入响应式修改判定函数与同组件业务对象切换判定；Console 使用 `useConsoleUnsavedChangesGuard` 保护活动 iframe。两端复用[共享守卫](../../basic/src/composables/useUnsavedChangesGuard.js)，业务页面不复制确认框或 `beforeunload`。

导航前确认、同步时不重复确认、来源校验、取消与保存失败、仅内存状态等规则统一见[未保存修改的离页保护](../../../docs/spec/addp前端路由与可恢复状态规范.md#未保存修改的离页保护)。真实 Vue Router、iframe、历史及导航桥回归由 `make test-console-frontend` 执行，Platform CI 安装 Chromium 后执行同一入口；门禁覆盖与真实运行验收按[共享测试分工](../../README.md#测试)分别记录，未执行或未覆盖项不计通过。

## 部署清单与跨模块草稿

本节导航：[主机选择与部署清单](#主机选择与部署清单) · [Console 草稿移交](#console-草稿移交)。

### 主机选择与部署清单

`HostNodeSelect` 是受控主机选择的唯一组件，消费者传入 `api.nodes/api.node`、当前 `allowed/identity` 与标签；共享组件负责分页、搜索、读取取消、迟到排除，不读取私有 Store 或模块 API。`hostAdmission.mjs` 唯一校验有界 v2 文件与可选主机采集，System 负责身份写入，Monitor 负责自己的配置。

### Console 草稿移交

`openConsoleRoute(route, { draft })` 通过既有导航桥提交草稿，接收模块使用 `takeConsoleNavigationDraft()` 一次读取；Console 使用 `createNavigationDraftSlot`，实现见[内存草稿工具](../../basic/src/utils/navigationDraft.mjs)。Console 销毁时仍须清空草稿槽；容量、有效期、身份／权限与路由绑定、失效清理、禁止持久化及 standalone 接入规则统一见[Console 内存导航草稿](../../../docs/spec/addp前端路由与可恢复状态规范.md#console-内存导航草稿)。接收 Owner 仍须核验领域结构、主体及保存权限，传输成功不等于业务有效或保存成功。

实际使用和拒绝边界由 Console/System/Monitor 浏览器门禁覆盖，CI 沿现有注册自动发现；该覆盖说明不代表本次已执行真实草稿移交，按[共享测试分工](../../README.md#测试)记录实际验收范围。

## 运行实例时间筛选

System 实例管理与 Monitor 服务监控共用 Basic 的 `RuntimeInstanceTimeFilter` 和 `runtimeInstanceTime.mjs`。共享组件只持有登记／离线判定时间、时段和日期输入的展示及变更事件；各模块决定何时提交其草稿，不在组件中请求业务接口。唯一预设目录、RFC3339 转 UTC 及每请求时间边界换算归该工具，System 原内联控件和换算已删除。相对时段每请求取同一锚点，自定义起止固定；离线时间仍由 System 当前投影解释，不在前端重建历史。

## 服务实例离线原因

`RuntimeInstanceStopReasonSelect` 是 System 与 Monitor 的唯一原因选择器，空值表示全部原因；`runtimeInstanceStopReason.mjs` 维护 `graceful|lease_expired` 目录、单值 URL 规范化与译名键。组件只发出 `update:modelValue`／`change`，不查询 API、不决定状态或离线事实；System 组合立即查询，Monitor 组合表单提交。原因与状态／时间取交集，恢复后退出结果，租约超时只表示失联。模块用 System 返回的当前观测展示原因，不从采集失败推断。验证入口为 Common、System、Monitor 与 Console 既有前端门禁。
