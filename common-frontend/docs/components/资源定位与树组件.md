## ResourceLocator 定位符系统

跨存储引擎的资源定位规则、类型与路径示例统一见[ResourceLocator 路径规则](../../../docs/spec/addp存储引擎路径体系规范.md#四resourcelocator-路径规则)。`type` 表达 catalog 路径术语，不区分 Node／DataItem；`node_id`、`item_id` 互斥，分别携带真实 MetaNode、MetaItem ID，不能使用树渲染键代替。Provider 实时目录尚无 Meta 身份时保留原生 locator，不补造 ID，选择规则见下文[身份模式与回显](#身份模式与回显)。

以下仅用固定测试值演示编解码；业务页面消费接口或选择器返回的可信 locator，不把示例 ID 当作可用资源或权限证明。

**工具函数**:
```js
import {
  parseLocator,       // 解析 URI 为对象
  buildLocator,       // 构建 URI 字符串
  getPathString,      // 获取路径字符串（如 "public/users"）
  getFullName,        // 按当前类型分支拼接名称
  getLastSegment,     // 获取路径最后一段
  getParentLocator,   // 推导父路径提示，不含父节点 ID
  cloneLocator,       // 深拷贝定位符
  isLocatorEqual      // 比较引擎、类型与路径，不比较 Meta ID
} from '@addp/common-frontend'

const itemURI = 'addp://engine/1/path/public/users?type=table&item_id=100'
const locator = parseLocator(itemURI)
// locator.engineId === 1；locator.itemId === 100；locator.nodeId === undefined
// locator.path 为 ['public', 'users']，locator.type 为 'table'

const uri = buildLocator(locator) // 与 itemURI 相同
```

[工具实现](../../basic/src/types/resourceLocator.js)负责本地编解码与路径操作，不核验资源是否存在或当前访问权限。`getParentLocator` 推导的类型和路径不能代替查询或选择真实父节点；`isLocatorEqual` 也不能用作 Meta 身份或授权边界一致性校验。界面路径使用选择结果的 `display.path`，其格式化由 `formatLocatorDisplayPath` 负责，不把 URI 路径直接当作原生展示名称。

## 资源树选择器

跨模块资源选择统一使用 `ResourceTreePicker`。它基于标准 ResourceLocator 和 Meta resource-tree API，负责引擎选择、资源树浏览、懒加载、`initialLocator` 回显和 locator 主身份 selection 输出。

`ResourceTreePicker` 不负责业务 DTO 组装、空间能力检测、字段加载或新资源创建。调用方应在收到 locator 后按业务需要调用 capability API，并保存必要执行快照。

#### 共享所有权与访问会话

返回 locator selection 的表单必须复用 `ResourceTreePicker`／`ResourceTreeSelect`。完整工作区可以直接组合 `ResourceTree`，但只能提供领域数据、节点插槽和领域操作；树渲染、展开／折叠、搜索及搜索前展开状态恢复仍由共享组件拥有。直接组合的宿主须在 [唯一所有权测试](../../basic/tests/resourceTreePickerOwnership.test.mjs) 中明确登记，并验证它没有重新实现上述通用能力。

共享 `ResourceTree` 只在展开集合实际改变时回写 `expandedKeys`。默认展开或恢复树时，组件库发起的懒加载不能把相同集合反复通知父选择器，避免受控状态回写在渲染期间形成更新循环；相同状态也不得重新发起懒加载请求。

资源树请求统一复用 `createAPIClient()` 和宿主已绑定的 AuthStore，支持 401 刷新与单次重试；正常模块路由守卫负责先初始化会话。选择器不创建独立 AuthSession，iframe 内不直接刷新 Cookie。认证接入统一见[认证使用指南](../../basic/composables/AUTH_USAGE_GUIDE.md)。

#### 身份模式与回显

- `mode="item"` 选择已有 data item，`mode="node"` 选择已有资源节点，`mode="any"` 用于混合选择或 Provider 实时目录选择。实时目录由业务入口限制可选范围：授权使用 `selectable-filter` 限定精确叶子，手动扫描可选目录与叶子；适配器保留完整源目标，不补造 Meta 身份。
- 已有资源选择结果以 `selection.identity.locator` 作为唯一资源身份；`display` 只用于 UI 展示，`raw.node` 只作为调用方补充读取事实的原始材料。
- `initialLocator` 回显走 Meta resource-tree ancestors API。回显目标不满足当前 `mode` 或 `selectableFilter` 时，只允许展开和高亮，不应回填为有效 selection。
- 对明确不应出现的资源，优先通过 `nodeFilter` 直接过滤掉；`selectableFilter` 仅在需要保留上下文但禁止选择时使用。
- 选择器不构造尚不存在资源的 locator。创建新表、新文件或新对象时，业务表单应使用 `ResourceTreePicker mode="node"` 选择父节点，再输入名称，提交 `parent_locator + name`。

selection 的引擎名称、类型与原生路径取自 `display`；空间字段必须从 `resource.spatial.geometry_columns` 和 `resource.spatial.primary_geometry_column` 自动回填，无识别事实时不猜字段名、不让用户自由输入未识别字段名，也不从 `raw` 私有结构另行推导。空间能力与创建、读取权限仍由业务 Owner 复核。

#### 多选快照与异步核验

资源多选使用同一组件的 `multiple` 属性，此时 `modelValue` 和 `update:modelValue` 为按选择顺序排列、以 `identity.locator` 去重的 selection 数组。树节点与搜索结果共用勾选状态，取消勾选后重新选择会追加到末尾；切换引擎筛选时移除不在当前引擎范围的已选资源。`engineMultiple` 只控制引擎筛选，不代表资源多选。单选默认契约保持不变，业务侧不得从目录自动推导叶子。

共享选择器负责直属／递归选择、半选显示和 `maxSelections` 整批上限；搜索仅改变显示，选择范围始终来自未过滤的完整快照。可选叶子即选择终点，不遍历 whole 容器内部。

System 中尚未接入节点范围授权的引擎，其当前项快照批选沿 `branch-selection`，要求 adapter 声明 `completeTree: true` 且完整收集身份分页后返回整棵树，失败不得提交部分叶子。

可选的异步 `validateSelection(next)` 在提交 selection 前完成领域核验；核验中禁用交互，勾选仅作待确认显示，失败回退复选框且不提交 selection；禁用、换引擎、刷新、外部选择变化或卸载使在途结果失效。`busy`、`loading`、`ready` 事件供宿主组合操作状态，`reload()` 与 `removeSelection(locator)` 复用同一状态路径。

#### 紧凑输入与选择

紧凑输入框与树形下拉统一组合 `ResourceTreeSelect`，树、搜索结果和 selection 仍由 `ResourceTreePicker` 拥有。文字筛选场景由宿主消费 `input`；资源选择场景显式启用 `search-resources`，通过同一 adapter 的 `search` 查询候选，只有 `select` 返回的精确资源才能加入办理清单，自由文本不构成资源身份。

下拉箭头与键盘向下键打开浏览树，Esc 只关闭下拉并保留输入。

System 当前授权查询使用此紧凑组件；新增授权使用完整多选 Picker。候选来源与最终签发分别沿[授权候选与边界绑定](#system-授权候选与边界绑定)、[原生事实核对与签发限制](#原生事实核对与签发限制)，不在紧凑组件另建授权路径。

#### 实时目录适配

实时目录统一由 `createEngineCatalogTreeAdapter(engine, listChildren, { isSearchable })` 将 Engine Catalog 的原始节点数组转换为选择器节点，保留类型化路径和物理名称，不依赖 Meta 身份。宿主只适配 API 响应及领域候选策略：Meta 手动扫描允许精确目录与叶子，包括源端已存在但尚未入库的目标。

适配器拥有安全引擎 ID 校验、原生 locator 转换及有界搜索；失败不切换到 Meta 树，不读取内容或创建授权。搜索最多访问 2,000 个节点、返回前 20 个匹配候选。

#### System 授权候选与边界绑定

System 新增授权复用 `ResourceTreePicker multiple`，不维护第二套资源勾选状态。PG 以领域 adapter 在同一棵懒加载树中组合真实节点身份与 DataItem；节点和叶子独立勾选，选节点不装载全部叶子。持续范围的逐节点递归属于 Grant 参数，由 System 在已选清单维护，不等于共享选择器展开当前叶子的批量操作。

System 只负责将 selection 解析为可信 DataItem 边界、核验事实及批量签发，不向共享层传入权限写入职责。

System 的新增授权和当前授权过滤通过 `adapter` 复用此组件，候选只来自 System 转发的 Meta 数据项身份清单；复用 `readDataItemIdentityTree` / `buildDataItemIdentityTree`，完整分页和祖先链核验后才显示。节点只展开当前已识别数据项，不能作为 ACL；FileGDB 的同名 scope 节点与唯一整体项显示为一个可选叶子，不枚举内部原生碎片。

选择后再读取精确指纹的授权事实，支持普通表、已接入模型组成和 NFS FileGDB whole 边界。未完成基础识别或边界不完整时拒绝加入授权目标，不回退原生目录。locator 仅用于统一选择交互，不伪造 Meta item ID。

共享 `observeNativeApprovalBinding` 按既有指纹规则定位候选，经 System 读取 Meta 完整事实后严格比对类型化原生边界；候选指纹与树选择均不是归属或权限证明。

目标的无损数值路径序列化由 `serializeEngineCatalogTarget` 统一提供，System Grant 序列化携带已观察的数据项身份及预期边界摘要，复用共享绑定校验；不保留独立的批准模式初始化序列化路径。Catalog 的业务确认通过其 owner 的 `sharing_boundary` 读取对应绑定；两端不另写序列化实现，也不在失败重试时静默换成新边界。

#### 原生事实核对与签发限制

`readNativeApprovalFacts` 唯一负责原生候选到 DataItem 事实的读取和协议校验，返回基础识别状态；精确模型组成统一支持 FTP/NFS 的 file 目标与 MinIO 的原生 object 目标，格式限 IFC／3DS／DAE／OBJ／STL，其中 IFC／STL 只能包含唯一必需的 model 主文件。

GeoTIFF／COG 沿同一组成核对路径消费 Meta 已确认的 TIFF 授权事实。只接受唯一必需的 `image` 主文件，且组成的 `source_layout` 必须与外层边界的扫描布局一致。

保留 bucket/prefix 和物理名称，拒绝跨 bucket、目录外依赖及 file/object 混用，不把父节点或贴图当作独立模型授权；`observeNativeApprovalBinding` 复用它且只接受完整边界。

System 在待授权清单中逐项只读核对，区分识别缺失、不完整、待刷新、不支持、无核对权限与查询失败，支持显式重新核对。状态仅供当前草稿展示，不是许可或可复用凭据；未知和不完整状态不允许发起新的签发，既有不可变命令的历史找回不受此展示状态阻断。

签发前及服务端仍按原路径重新核验，不能直接消费页面保留的状态或静默换成新边界。核对不扫描、不读取业务内容、不写入授权。

### 选择与创建示例

```vue
    :selectable-filter="node => node.type === 'table'"
  />
</template>

<script setup>
import { ref } from 'vue'
import { ResourceTreePicker } from '@addp/common-frontend'

const selection = ref(null)
</script>
```

**新表目标片段**：仅演示选择已有 schema／database 父节点并填写名称；可创建的父类型还须由 Owner 按目标引擎能力限定。`mode="node"` 要求真实 `node_id`，不从数据项路径推导父身份。名称保留原始首尾空格，遵循[物理名称规则](../../../docs/spec/addp存储引擎路径体系规范.md#二full_name-规则)。父 locator 或名称缺失时不生成 DTO；生成 DTO 不表示已通过业务校验或创建授权。

```vue
<template>

    :selectable-filter="node => ['schema', 'database'].includes(node.type)"

<script setup>
import { computed, ref } from 'vue'
import { useI18n } from 'vue-i18n'
import { ResourceTreePicker } from '@addp/common-frontend'

const { t } = useI18n()
const parentSelection = ref(null)
const targetName = ref('')

const targetCreateDTO = computed(() => {
  const parentLocator = parentSelection.value?.identity?.locator
  return parentLocator && targetName.value.length > 0
    ? { parent_locator: parentLocator, name: targetName.value }
    : null
})
</script>
```

## 树形组件

资源树的展开能力只来自已加载的 `children` 或显式的 `hasChildren` / `metadata.has_children`，统一由 `hasExpandableChildren` 判断。`metadata.item_count` 仅属于 Node，统计有效子树的逻辑 DataItem，不是直接子节点事实。DataItem 使用真实 `item_id`，不携带 `item_count` 或虚拟 `node_id`，始终作为资源树叶子；表记录数和容器内部结构数量也不能用于显示展开箭头或触发增量加载。

`ResourceTree` 统一拥有未加载节点的展开交互：启用 `expandOnClickNode` 时，名称、文件夹图标和三角使用同一展开／收起事件及受控展开集合。非 lazy 模式下，即使 Element Plus 因 `children=[]` 将节点视为叶子，只要显式子资源事实为真，首次点击名称也必须发出 `node-expand`；宿主只响应事件加载资源，不在选中回调中补做展开。加载期间再次操作可以收起，迟到子资源响应不得重新展开。

- **ResourceTree** - 通用资源树组件
  - 配置式节点操作（刷新、查看详情等）
  - 宿主提供有界高度，树内部使用 Element Plus Scrollbar 滚动；长名称在行内截断，节点操作保持完整可点击，宿主不再叠加资源树滚动容器
  - 全树搜索，自动展开匹配路径，提供无匹配结果状态，清空后恢复搜索前状态
  - 智能展开状态管理
  - 双击展开/折叠交互
  - 支持 v-model 绑定（展开状态、选中节点、搜索关键词）
  - 自定义节点渲染（插槽支持）

**接入片段**：Owner 提供已授权并映射好的 `treeData`、有界 `treeHeight`、状态和事件处理函数。`treeTitle`、`filterEmptyText` 由本模块当前语言词条生成，`t` 使用既有国际化上下文；计数、搜索、空态和操作提示显式传入翻译，接入要求见[国际化规范](../../../docs/spec/addp国际化开发规范.md#组件使用)。树的 `id` 是渲染键，提交业务操作仍使用可信 locator 与真实 Node／DataItem 身份，不从示例键或标签推导。

`canRefreshTree`、`canRefreshNode` 由 Owner 根据当前权限和动作适用范围提供；显示／禁用状态只控制界面，刷新请求与权限复核仍归对应 Owner。以下片段组合到既有页面 setup 中：

```vue

<template>

    v-model:current-node-key="currentNodeKey"
```

**树形工具函数**：以下只演示普通数组上的结构操作，`root`／`leaf` 是示意渲染键，不是业务 locator 或数据库 ID；从 Vue Ref 调用时由宿主传入其数组值。

```js
import {
  // 数据结构操作
  flattenTree,        // 扁平化树为数组
  filterTree,         // 过滤树节点
  sortTree,           // 树节点排序
  cloneTree,          // 深拷贝树
  getAllNodeKeys,     // 获取所有渲染键

  // 节点查询
  findNodeById,       // 根据 ID 查找节点
  findNodePath,       // 查找节点路径（根到目标的所有 ID）
  getParentIds,       // 获取所有父节点 ID
  getLeafNodes,       // 获取所有叶子节点

  // 树遍历
  traverseTree,       // 递归遍历每个节点（提供回调）
  getTreeDepth        // 计算树的最大深度
} from '@addp/common-frontend'

// 使用示例

const nodes = [{
  id: 'root', label: 'root',
  children: [{ id: 'leaf', label: 'leaf' }]
}]

const allKeys = getAllNodeKeys(nodes) // ['root', 'leaf']
const node = findNodeById(nodes, 'leaf')
const allNodes = flattenTree(nodes)
const path = findNodePath(nodes, 'leaf') // ['root', 'leaf']

traverseTree(nodes, (node, parent, level) => {
  console.log(`Level ${level}: ${node.label}`)
})

const selected = filterTree(nodes, node => node.id === 'leaf')
const sorted = sortTree(nodes, (a, b) => a.label.localeCompare(b.label))
```

## 树管理组件 (Composables)

提供通用的树加载、缓存管理功能，适用于需要树形数据的场景。

### useTreeCache

树节点与搜索结果缓存按 `maxAge` 检查过期。当前 `maxSize` 仅在写入超过阈值时触发过期项清理，未过期项仍可能超过该数量；尚未提供按容量驱逐，不能将它视为已实现的硬上限。实际行为见[useTreeCache](../../basic/src/composables/useTreeCache.js)。

**使用示例**：`parentLocator` 和 `children` 由调用方提供；缓存复用不替代当前访问授权。

```javascript
import { useTreeCache } from '@addp/common-frontend'

const cache = useTreeCache({
  maxAge: 5 * 60 * 1000,  // 5分钟过期
  maxSize: 100             // 超过阈值时清理过期项
})

// 设置缓存
cache.setNodeChildrenCache(parentLocator, children)

// 获取缓存
const cached = cache.getNodeChildrenCache(parentLocator)

// 清空所有缓存
cache.clearCache()
```

### useTreeLoader

`useTreeLoader` 是接收客户端的低层加载器，默认 `apiBasePath` 为 `/meta`。本例的 `apiClient` 由 Owner 绑定当前用户会话，并以 `/api/v1` 为基址；不直接复用模块业务前缀客户端拼出错误路径，认证接入见[共享请求客户端](../../basic/composables/AUTH_USAGE_GUIDE.md#41-共享请求客户端)。字段与选项以[加载器实现](../../basic/src/composables/useTreeLoader.js)为准。

**使用示例**:
```javascript
import { useTreeLoader } from '@addp/common-frontend'

const treeLoader = useTreeLoader(apiClient, {
  apiBasePath: '/meta',
  enableCache: true,
  cacheOptions: { maxAge: 5 * 60 * 1000 }
})

// 增量加载子节点
const children = await treeLoader.loadNodeChildren(
  parentLocator
)

// 搜索节点
const results = await treeLoader.searchNodes(
  engineId,
  keyword,
  { nodeTypes, limit: 50 }
)

// 清空缓存
treeLoader.clearCache()
```

`parentLocator`、引擎、关键词和节点类型由 Owner 提供；接口失败会设置 `error` 并继续抛出异常，安全错误展示归调用方。缓存不自动监听身份／授权变化；搜索缓存键包含引擎、关键词和类型，未包含 `limit`，切换这些上下文时需处理失效，不能据旧缓存认定当前读取权限或覆盖范围。`forceRefresh` 只绕过本地缓存，不表示已执行 Meta 扫描。

受影响片段、导出和路径核对仅为静态证据；宿主高度、搜索恢复、增量加载、状态失效、权限与错误展示仍按[共享测试与消费方分工](../../README.md#测试)在实际接入处验证，未执行或未覆盖项不计通过。
