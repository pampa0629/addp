# ADDP 外部组件化需求草案

本文保留外部组件化的目标、现有基础和未决事项，尚不是已交付的低代码产品规范。共享组件的现行规则以[共享前端说明](../README.md)、[前端风格规范](addp前端风格设计规范.md)和[技术栈规约](../../docs/spec/addp技术栈规约.md)为准。

## 需求与范围

- 面向私有化部署客户，允许客户在自己的应用或低代码平台中复用 ADDP 的组件能力，兼顾技术人员配置和业务人员可视化组合。
- 保持 Vue 3 技术栈，复用共享实现；输出范围是独立 UI 组件或业务组合组件，不把整个模块页面复制成另一套产品。
- ResourceTree、StorageEngineForm、ScheduleConfig 是原草案列出的候选组件，具体首批范围仍需按真实客户场景确认。
- Web Components 是原草案的组件输出方向；平台专属属性面板、拖拽元数据和适配器是否需要，由目标平台的实际约束决定。

## 现有基础与边界

| 能力 | 当前事实 |
| --- | --- |
| Vue 共享组件 | 三个候选组件已有 Vue 实现，分别见[资源树](../basic/src/components/ResourceTree.vue)、[引擎表单](../basic/src/components/StorageEngineForm.vue)、[调度配置](../basic/src/components/ScheduleConfig.vue) |
| DAG 原生元素 | 已有 `registerDagViewerElement()` 与 `addp-dag-viewer`，仅适配 DAG 数据和高度，复用共享查看器；契约与验证入口见[只读 DAG 查看器](components/预览与结果展示.md#只读-dag-查看器) |
| 通用外部组件包 | 原草案中的 `common-frontend/webcomponents`、组件元数据发布及统一 `dist/addp-components.js` 尚未形成对应工程；现有 DAG 元素不代表这些组件已全部完成转换 |
| 平台适配 | 原草案列举的宜搭、Tmagic 等平台适配器尚未形成对应 `common-frontend/adapters` 工程，不能据此承诺零适配或可视化编辑已可用 |

已有能力在对应 README 与正式规范中维护，本文不重复记录实现过程或把静态源码存在当作外部客户运行验收通过。

## 必须沿用的现行约束

1. Vue 单一实例、共享能力唯一所有权、样式变量与国际化沿用 common-frontend 规范；组件封装不得复制资源树、表单或 DAG 渲染逻辑。
2. 浏览器认证沿用[登录认证规范](../../docs/spec/addp登录认证的统一要求.md)。Access Token 只在内存中管理，不通过 HTML attribute、页面配置、URL 或长期静态 Token 传递凭据；不恢复 JWT 自解析或另建刷新流程。
3. 控制面 API 消费沿用[客户端规范](../../docs/spec/api/客户端集成.md)。API Consumer Credential 只适用于正式发布的数据面，不能替代组件调用控制面接口的用户或服务身份。
4. 客户自部署不等于允许跨 origin 共享会话；Console 同 origin 入口、跨站点独立登录、Cookie 与消息来源边界仍按认证规范执行，单独配置 CORS 不构成授权。
5. 测试与构建复用[标准门禁](../../docs/spec/addp测试与验收规范.md)。新增工程或发布产物时，同次确认 owner、自动发现、构建与 CI 登记，不另造组件私有 SDK 或旁路测试入口。

## 实施前待确认

| 问题 | 需要确认的内容 |
| --- | --- |
| 首个真实消费场景 | 目标客户、宿主平台、用户类型，以及是否确实需要独立于 Console 的组件包 |
| 首批能力 | 哪些组件只接收数据，哪些需要访问 API；属性、事件、设置器与错误展示的实际交互契约 |
| 部署与认证 | 同 origin 部署还是跨站点部署；用户会话如何建立，哪些调用需要用户身份，哪些属于正式服务消费；公共服务或混合交付是否存在真实需求，另行确认 |
| 打包与发布 | 独立分发格式、依赖归属、样式加载、资源路径和升级边界；不能假定普通 Vue 组件可无调整直接转换 |
| 验收与交付 | 目标浏览器、宿主页面、权限矩阵、主题/语言、卸载清理与资源加载场景，以及相应 owner 门禁 |

上述场景未明确前，不把旧工期、包体积、首屏耗时、客户成功率或 CDN 地址作为承诺，也不据此开始新增平台适配工程。
