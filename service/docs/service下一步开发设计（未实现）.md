
## 七、安全与权限管理

### 7.1 鉴权机制（待定）

Service 模块的服务访问涉及两层鉴权：**基础认证**和**服务级授权**。当前鉴权策略的具体实现方案尚未最终确定，以下是初步思路：

**选项 A：Gateway 统一鉴权**
- **方案**：Gateway 负责 JWT 认证，Service 模块信任 Gateway 转发的请求
- **优点**：
  - 集中式认证管理，降低 Service 模块复杂度
  - 便于统一的认证策略和日志审计
  - 减少重复代码
- **缺点**：
  - OGC 公开端点（public_access=true）需要 Gateway 特殊处理
  - Service 模块无法独立部署和测试

**选项 B：Service 模块独立鉴权**
- **方案**：Service 模块自行验证 JWT token，独立判断用户权限
- **优点**：
  - Service 模块可以独立部署
  - 服务级细粒度权限控制（如：某些图层仅对特定用户开放）
- **缺点**：
  - 与 Gateway 鉴权逻辑重复
  - 增加 Service 模块复杂度

**建议方案**（待确认）
- **Gateway 负责基础 JWT 认证**：验证 token 有效性，提取用户身份
- **Service 模块负责服务级授权**：
  - 判断服务是否公开（public_access=true）
  - 租户级隔离（tenant_id 匹配）
  - 未来可扩展：服务级 ACL（访问控制列表）
- **OGC 公开端点处理**：
  - Gateway 对 `/ogc/*` 路径的公开服务不强制 JWT 认证
  - Service 模块根据 service_name 查询服务配置，判断是否允许匿名访问

**鉴权流程示例**（待定）
```
客户端请求 → Gateway
  ├─ 私有服务 → 验证 JWT → 转发到 Service → Service 验证 tenant_id
  └─ 公开服务 → 直接转发到 Service → Service 验证 public_access=true
```

### 7.2 限流策略（待定）

限流是防止服务滥用和保护系统稳定性的重要手段。当前限流策略的具体实现方案尚未最终确定，以下是初步思路：

**选项 A：Gateway 全局限流**
- **方案**：Gateway 层面实现全局限流，按 IP、用户、租户限流
- **限流维度**：
  - 按 IP 限流：防止 DDoS 攻击（如：每个 IP 每分钟最多 1000 请求）
  - 按用户限流：防止单个用户过度使用（如：每个用户每分钟最多 100 请求）
  - 按租户限流：防止单个租户占用过多资源（如：每个租户每分钟最多 500 请求）
- **优点**：
  - 保护整个平台，防止任何模块被拖垮
  - 集中式限流管理，便于监控和调整
- **缺点**：
  - 无法针对特定服务或图层进行细粒度限流

**选项 B：Service 模块服务级限流**
- **方案**：Service 模块为每个服务或图层配置独立的限流策略
- **限流维度**：
  - 按服务限流：每个服务每分钟最多 N 次请求
  - 按图层限流：热点图层单独限流
  - 按要素数限流：单次查询最多返回 M 个要素（已实现：max_features）
- **优点**：
  - 细粒度控制，保护高负载服务
  - 灵活配置，不同服务可以有不同的限流策略
- **缺点**：
  - 增加 Service 模块复杂度
  - 需要在数据库中存储限流配置

**建议方案**（待确认）
- **两层限流结合**：
  - **Gateway 全局限流**：按 IP、用户、租户限流，防止平台级攻击
  - **Service 服务级限流**：按服务、图层限流，保护高负载服务
- **限流配置**：
  - Gateway 限流配置在环境变量或配置文件中
  - Service 限流配置在数据库中（internal_services 表增加 rate_limit 字段）
- **限流算法**：
  - 使用令牌桶或滑动窗口算法
  - 基于 Redis 实现分布式限流

**限流响应**（待定）
- 超出限流时返回 HTTP 429（Too Many Requests）
- 响应头包含 X-RateLimit-* 信息（Limit、Remaining、Reset）

### 7.3 公开服务访问

**公开服务定义**
- 配置 `public_access=true` 的服务可以在不登录的情况下被访问
- 适用于对外开放的数据服务（如：行政区划、公开地图底图）

**公开服务的访问控制**（待定）
- **匿名访问**：不需要 JWT token，可直接访问 OGC 端点
- **限流保护**：公开服务仍然受到限流限制，防止滥用
- **服务目录**：公开服务可以在服务目录中匿名浏览（具体策略待定）

**公开服务的安全考虑**
- **数据敏感性**：确保公开的数据不包含敏感信息
- **资源消耗**：公开服务可能被大量访问，需要考虑缓存和 CDN 加速
- **滥用防护**：即使是公开服务，也需要限流和监控
