# Service 后续能力清单

[返回核心概念与架构](service核心概念和架构设计.md)

本文保留尚待确认的能力范围，不作为开发排期、已批准架构或验收结论。现行规则与已实现能力按下列入口维护，不再保留旧认证选型和按月阶段规划。

## 现行能力与正文归属

| 范围 | 当前边界与正文 |
| --- | --- |
| 身份与服务授权 | System opaque Token / AuthContext、Service owner 授权与 API Consumer 精确 Grant，见[查询发布与执行](architecture/查询发布与执行.md#身份授权与资源限制)及[认证授权规范](../../docs/spec/api/认证授权.md)。 |
| OAuth 第三方应用接入 | 已有统一 OAuth 与租户外部公共 Client，不再列作整体未实现；客户端实际适配与验收见[Workbench 服务消费专题](../../docs/next/ADDP%20Workbench数据服务消费与数据应用专题.md)。 |
| 现有限流与单次查询上限 | Gateway 已有 API Consumer 分钟限流；Query 的 `max_features` 约束单次返回行数。覆盖范围见[查询发布与执行](architecture/查询发布与执行.md#身份授权与资源限制)。 |
| 目录与模块协作 | Consumer Catalog 是需认证的只读消费投影，公开执行不等于匿名浏览目录；见[管理界面与模块协作](architecture/管理界面与模块协作.md)。 |
| 瓦片与外部服务 | 动态 MVT / 静态 PMTiles、现有协议与缓存边界见[瓦片发布与缓存](architecture/瓦片发布与缓存.md)；上游接入、代理与独立缺口见[外部服务架构](外部服务架构设计.md#后续事项与确认边界)。 |

## 待确认范围

同一事项已有专题时，由该专题维护细项。下表只保留后续需求与决策边界，不新增数据库字段、固定额度、算法、搜索后端或第二套授权机制。

| 事项 | 保留的需求与确认边界 |
| --- | --- |
| 服务授权细化 | 逐服务、图层的细粒度权限与公开/私有范围，沿统一 owner Resource Grant / Policy 推进；不另建 Service 私有 ACL，接入边界见[Workbench 后续事项](../../docs/next/ADDP%20Workbench数据服务消费与数据应用专题.md)。 |
| 限流、配额与统计报表 | IP、User、Tenant、服务、图层及匿名访问的覆盖范围，周期额度、统计归属与报表；需明确适用入口、限流失败策略及超限响应/响应头契约。不能由现有 API Consumer 限流推导这些能力均已接通。 |
| 公开服务保护与发现 | 明确敏感数据发布限制、匿名可见的目录投影、滥用监控及缓存/CDN 适用条件；匿名目录仍须单独确认，不放宽当前 Consumer Catalog 认证边界。 |
| WMS、WCS 与栅格发布 | WMS GetMap、WCS 的 DEM/影像访问，以及 PNG、JPEG、GeoTIFF 等输出的协议归属、数据来源和可验证最小范围；不视为当前矢量瓦片发布已支持。 |
| 样式能力 | SLD、可视化样式编辑及模板库的协议适用范围、样式保存与执行责任，先与现有客户端样式区分。 |
| 上游 OAuth2 | Registered Service 访问第三方 OAuth2 服务的凭据、续期和代理边界；与 System 为客户端签发 ADDP Token 的现有能力分别确认。 |
| 目录检索与热度 | 服务 BBox 筛选、全文检索增强、使用统计和热度排序；先明确与现有检索、消费目录及企业 Catalog 的职责，搜索后端另行评估。 |
| 运行监控与恢复 | 调用日志分析、响应时间/吞吐量、故障告警与自动恢复；复用 Gateway、System 和 Monitor 既有职责，不把已有消费日志等同于全部服务的监控闭环。 |
| 外部服务聚合 | 多个上游形成统一消费结果时的图层冲突、CRS 统一和元数据融合；是否需要虚拟服务对象及其授权、故障语义尚待确认。 |
| GraphQL 查询设想 | 保留按需字段和关联查询的需求，先核对现有结构化 Query 的覆盖与必要性；是否引入 GraphQL 尚未确认，不作为与 REST 并存的既定技术路线。 |
| 服务组合与编排 | 多服务的数据转换、过滤、聚合及可视化组合需求；先明确与 Develop、Orchestrator 既有工作流的边界，不另建编排主路径。 |
| 跨实例目录联邦 | 多 ADDP 实例的服务发现、跨实例查询及元数据同步，须先确认信任、身份、目录权威和一致性边界。 |
| Develop 发布协作 | SQL 查询结果一键发布、工作流输出自动登记及 Processing as a Service；现有 SQL 发布不等于这些交互与执行闭环已接通，需逐项核对输出身份、发布快照及授权。 |
| 服务推荐 | 用户行为、服务关联及空间范围推荐的实际价值、输入事实和授权边界；不因保存候选方向就默认采集用户行为或新增推荐系统。 |

## 实施与验证边界

进入实施前重新核对当前规范、代码与有效验收证据。涉及概念、协议、授权或模块边界的未决事项先讨论确认；已落地的规则归入正式概念/规范或对应模块专题，并从本清单移除。

按[测试与验收规范](../../docs/spec/addp测试与验收规范.md)选择现有根 Makefile 入口；Service / Gateway 的模块门禁、真实上游协议与跨模块验收分别报告，不把文档清理、配置保存或代码存在计为运行通过。
