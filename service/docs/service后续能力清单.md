# Service 后续能力清单

[返回核心概念与架构](service核心概念和架构设计.md)

本文索引尚待确认或落地的能力，不作为开发排期、已批准架构或验收结论。现行能力由对应专题维护；已有实现的验收缺口沿测试专题记录，不重新列为待开发功能。

## 现行能力与正文归属

| 范围 | 当前边界与正文 |
| --- | --- |
| 查询来源与消费契约 | 表、普通/联邦 SQL、analytical 来源，结构化筛选、稳定键、cursor 与有界导出，见[查询发布与执行](architecture/查询发布与执行.md)。 |
| 指标契约与页面操作 | 精确修订、管理/消费版本、重绑与编译契约见[指标来源与版本](architecture/指标来源与版本.md)，页面操作与验证见[操作索引](architecture/管理界面与模块协作.md#查询服务创建与详情)；编译成功不代替取数验收。 |
| 当前查询协议与入口 | REST/Features、DTO 与页面地址、公开入口及客户端验证，见[查询与要素协议](testing/查询与要素协议.md)。 |
| 身份、授权与查询保护 | opaque Token / AuthContext、User 权限、API Consumer Grant 与单表角色方式，见[身份与保护](architecture/查询发布与执行.md#身份授权与资源限制)；不等于下表 User 资源级授权或其他来源的角色方式已接通。 |
| OAuth 第三方应用接入 | OAuth 与外部 Client 规则见[消费规范](../../docs/spec/addp数据服务消费与数据应用规范.md)；客户端适配与证据缺口见[Workbench 后续事项](../../docs/next/ADDP%20Workbench数据服务消费与数据应用专题.md#三后续推进边界)。 |
| 现有限流与单次查询上限 | API Consumer 分钟限流与 Query 单次 `max_features` 上限，见[资源限制](architecture/查询发布与执行.md#身份授权与资源限制)。 |
| 现有消费访问记录 | API Consumer Query 请求的 Gateway 访问记录，范围与落库失败边界见[访问记录说明](../../gateway/docs/gateway架构说明.md#6-数据库)；不代替全入口计量或 System 审计。 |
| 目录与模块协作 | Consumer Catalog 是需认证的只读消费投影，公开执行不等于匿名浏览目录；认证与读取范围见[授权边界](architecture/查询发布与执行.md#身份授权与资源限制)，页面与职责见[管理界面与模块协作](architecture/管理界面与模块协作.md)。 |
| 瓦片与外部服务 | 动态 MVT / 静态 PMTiles、现有协议与缓存边界见[瓦片发布与缓存](architecture/瓦片发布与缓存.md)；上游接入、代理与独立缺口见[外部服务架构](外部服务架构设计.md#后续事项与确认边界)。 |

## 待确认范围

同一事项已有专题时，由该专题维护细项。下表只保留后续需求与决策边界，不新增数据库字段、固定额度、算法、搜索后端或第二套授权机制。

| 事项 | 保留的需求与确认边界 |
| --- | --- |
| 服务授权细化 | User 逐服务的 owner Resource Grant / Policy、其他服务类型与逐图层公开/私有权限，沿[Workbench 后续事项](../../docs/next/ADDP%20Workbench数据服务消费与数据应用专题.md#三后续推进边界)维护；API Consumer Grant 不替代该闭环，不另建 Service 私有 ACL。 |
| 查询角色方式边界 | 其他来源及身份的角色方式适配先确认；匿名、应用凭据和委托不能借用 User 角色，AK/SK 保护方式暂不设计。现有边界见[查询保护范围](architecture/查询发布与执行.md#登录用户的角色脱敏选择)。 |
| 发布血缘覆盖与页面 | 当前发布器的 SQL / 联邦 / analytical `serve` 同步与主查询详情查看器尚未接通，细项及验收见[发布血缘同步边界](architecture/查询发布与执行.md#发布血缘同步边界)。 |
| 限流与配额 | IP、User、Tenant、服务、图层及匿名入口的其余限流、周期额度；明确失败策略和超限响应/响应头，不外推已有分钟限流。 |
| 运行统计与报表 | 日志、调用量、成功率、错误率、延迟与吞吐分析、租户聚合及可视化报表；明确统计归属与实际覆盖，不以已有访问记录推导全入口统计。 |
| 公开发布约束与匿名发现 | 敏感数据公开发布限制、匿名目录、滥用监控及缓存/CDN；不从请求期保护推导发布检查或匿名发现成立，不放宽 Consumer Catalog 认证边界。 |
| 待接通协议与栅格发布 | WFS 发布仍未接通，见[WFS 边界](testing/查询与要素协议.md#wfs-边界)；WMS GetMap、WCS 的 DEM/影像与 PNG/JPEG/GeoTIFF 输出须确认协议归属、来源和最小验收范围。 |
| 样式能力 | SLD、可视化样式编辑及模板库仍须确认协议适用范围、保存与执行责任；现有[客户端样式](tile-guide/客户端接入.md#格式内部图层与样式)不等于服务端样式管理。 |
| 外部服务专属事项 | 代理接入与保护、上游 OAuth2、注册服务聚合等细项统一见[外部服务后续事项](外部服务架构设计.md#后续事项与确认边界)。 |
| 目录检索与热度 | 服务 BBox 筛选、全文检索增强、使用统计和热度排序；先明确与现有检索、消费目录及企业 Catalog 的职责，搜索后端另行评估。 |
| 故障监控与恢复 | 各类服务的告警与自动恢复，复用 Gateway、System、Monitor；已有日志与查询审计的[事实边界](../../docs/spec/addp数据服务消费与数据应用规范.md#58-data-application-资产运营指标评估)不代替完整监控闭环。 |
| GraphQL 必要性评估 | 仅评估[现有查询契约](architecture/查询发布与执行.md#统一执行契约)未覆盖的字段与关联需求；GraphQL 未确认，不预设与 REST 并存路线。 |
| 跨服务组合与编排 | 保留跨已发布服务的转换、过滤、聚合与可视化组合需求，区别于现有单服务查询及 SQL/指标来源；先明确与 Develop、Orchestrator 工作流的边界，不另建编排主路径。 |
| 跨实例目录联邦 | 多 ADDP 实例的服务发现、跨实例查询及元数据同步，须先确认信任、身份、目录权威和一致性边界。 |
| Develop 发布协作 | 一键发布 Develop SQL 结果、工作流输出登记及 Processing as a Service；输出身份、快照和授权待核对，现有 [SQL 创建契约](architecture/查询发布与执行.md#三种来源)不重复规划。 |
| 服务推荐 | 用户行为、服务关联及空间范围推荐的实际价值、输入事实和授权边界；不因保存候选方向就默认采集用户行为或新增推荐系统。 |

## 实施与验证边界

进入实施前重新核对当前规范、代码与有效验收证据。涉及概念、协议、授权或模块边界的未决事项先讨论确认；已落地的规则归入正式概念/规范或对应模块专题，并从本清单移除。

按[测试与验收规范](../../docs/spec/addp测试与验收规范.md)选择现有根 Makefile 入口；证据分层见[标准入口与证据](testing/验收方法与排查.md#标准入口与证据)，结果判定沿[统一验收边界](API测试指南.md#能力与验收边界)。Service / Gateway 门禁、真实上游及跨模块验收分别报告，不把文档清理、配置保存或代码存在计为运行通过。
