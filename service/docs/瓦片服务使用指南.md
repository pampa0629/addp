## 1. 简介

瓦片服务是 ADDP 平台提供的地图瓦片发布功能，支持将数据库中的空间数据发布为标准地图瓦片服务。

### 核心特性

- **动态瓦片生成**：从 PostgreSQL/PostGIS 数据库实时生成 MVT（Mapbox Vector Tile）瓦片
- **静态瓦片代理**：支持代理外部静态瓦片文件（PNG、JPEG、MVT）
- **多协议支持**：XYZ Tiles、WMTS、OGC Tiles API 1.0
- **智能缓存**：MinIO 对象存储缓存，支持 TTL 和按需清理
- **GIS 兼容**：兼容 QGIS、ArcGIS Pro 等 GIS 软件
- **Web 友好**：支持 OpenLayers、Leaflet、Mapbox GL JS 等主流 Web 地图库

### 支持的瓦片格式

- **MVT (Mapbox Vector Tile)**：矢量瓦片，文件小，支持动态样式
- **PNG**：栅格瓦片，适合静态底图
- **JPEG**：栅格瓦片，适合卫星影像

### 支持的坐标系

- **EPSG:3857 (Web Mercator)**：默认坐标系，Web 地图标准
- **EPSG:4326 (WGS84)**：支持自动转换到 3857

## 2. 快速开始

### 2.1 访问瓦片服务

1. 登录 ADDP 平台：http://localhost:5170
2. 在左侧导航栏选择 **数据服务 > 瓦片服务**
3. 点击 **创建瓦片服务** 按钮

### 2.2 3 步创建服务

瓦片服务创建采用 3 步向导模式：

**步骤 1：添加第一个图层**
- 选择图层类型：动态图层 或 静态图层
- 配置数据源（动态）或瓦片路径（静态）

**步骤 2：配置服务信息**
- 服务名称（唯一标识，用于 URL）
- 服务标题和描述
- 协议配置（XYZ Tiles、OGC Tiles、TMS）
- 访问控制（公开/私有）

**步骤 3：完成**
- 显示服务端点 URL
- 提供复制和测试功能

### 2.3 快速示例

创建一个简单的道路瓦片服务：

```yaml
服务配置:
  服务名称: beijing_roads
  标题: 北京道路瓦片服务
  协议: XYZ Tiles

图层配置:
  图层名称: roads
  类型: 动态图层
  数据源:
    存储引擎: PostgreSQL (ID: 1)
    Schema: public
    表: beijing_roads
    几何列: geom
    坐标系: EPSG:4326
```

创建成功后，瓦片端点为：
```
http://localhost:8000/tiles/beijing_roads/roads/{z}/{x}/{y}.mvt
```

## 3. 创建瓦片服务

### 3.1 动态图层

动态图层从数据库实时生成瓦片，适合需要实时更新的数据。

#### 3.1.1 配置步骤

1. **选择存储引擎**
   - 从下拉列表选择已配置的 PostgreSQL 存储引擎
   - 需要引擎中安装了 PostGIS 扩展

2. **选择 Schema 和表**
   - Schema：数据库模式（如 `public`）
   - 表：包含空间数据的表（如 `beijing_roads`）

3. **选择几何列**
   - 几何列：表中的空间列（通常为 `geom`、`geometry`、`the_geom`）
   - 系统会自动检测空间列

4. **指定坐标系**
   - SRID：空间参考系统标识符（如 `4326`）
   - 如果源数据不是 EPSG:3857，系统会自动转换

#### 3.1.2 高级配置

**MVT 参数**（可选）：

```json
{
  "extent": 4096,  // 瓦片范围，默认 4096
  "buffer": 256    // 缓冲区，避免边界裁剪，默认 256
}
```

**缓存配置**：

```json
{
  "enabled": true,  // 是否启用缓存
  "ttl": 3600       // 缓存时间（秒），默认 3600（1 小时）
}
```

#### 3.1.3 示例配置

**案例 1：道路图层**

```json
{
  "layer_name": "roads",
  "title": "道路图层",
  "layer_type": "dynamic",
  "layer_config": {
    "source": {
      "engine_id": 1,
      "schema": "public",
      "table": "beijing_roads",
      "geometry_column": "geom",
      "srid": 4326
    },
    "mvt": {
      "extent": 4096,
      "buffer": 256
    },
    "cache": {
      "enabled": true,
      "ttl": 3600
    }
  }
}
```

**案例 2：建筑物图层**

```json
{
  "layer_name": "buildings",
  "title": "建筑物图层",
  "layer_type": "dynamic",
  "layer_config": {
    "source": {
      "engine_id": 1,
      "schema": "public",
      "table": "buildings",
      "geometry_column": "geom",
      "srid": 4326
    },
    "mvt": {
      "extent": 4096,
      "buffer": 64
    },
    "cache": {
      "enabled": true,
      "ttl": 7200
    }
  }
}
```

#### 3.1.4 性能优化建议

**1. 确保空间索引**

```sql
-- 检查索引
SELECT indexname
FROM pg_indexes
WHERE tablename = 'beijing_roads'
  AND indexdef LIKE '%GIST%';

-- 创建空间索引
CREATE INDEX idx_beijing_roads_geom
ON public.beijing_roads
USING GIST(geom);
```

**2. 使用物化视图（可选）**

对于大数据表，可以为常用缩放级别创建物化视图：

```sql
-- 为 zoom 10 创建简化视图
CREATE MATERIALIZED VIEW mv_roads_z10 AS
SELECT id, name, ST_Simplify(geom, 0.001) AS geom
FROM public.beijing_roads
WHERE ST_Intersects(geom, ST_MakeEnvelope(...));

CREATE INDEX idx_mv_roads_z10_geom
ON mv_roads_z10
USING GIST(geom);

-- 定期刷新
REFRESH MATERIALIZED VIEW mv_roads_z10;
```

**3. 坐标系预计算**

如果源数据是 EPSG:4326，建议添加 EPSG:3857 列：

```sql
-- 添加 3857 列
ALTER TABLE public.beijing_roads
ADD COLUMN geom_3857 geometry(LineString, 3857);

-- 计算 3857 坐标
UPDATE public.beijing_roads
SET geom_3857 = ST_Transform(geom, 3857);

-- 创建索引
CREATE INDEX idx_roads_geom_3857
ON public.beijing_roads
USING GIST(geom_3857);
```

然后在图层配置中使用 `geom_3857` 作为几何列。

### 3.2 静态图层

静态图层使用预生成的瓦片文件，适合不需要更新的底图。

#### 3.2.1 配置步骤

1. **选择瓦片来源**
   - **外部瓦片**：从外部 S3/MinIO 存储读取
   - **内部缓存**：使用平台内部缓存的瓦片

2. **配置瓦片路径**
   - 瓦片存储路径（如 `s3://my-bucket/tiles/basemap`）
   - 路径需遵循 `{z}/{x}/{y}.{format}` 结构

3. **选择瓦片格式**
   - MVT：矢量瓦片
   - PNG：栅格瓦片
   - JPEG：栅格瓦片

4. **设置缩放范围**
   - 最小缩放级别（如 0）
   - 最大缩放级别（如 18）

#### 3.2.2 示例配置

**案例 1：OpenStreetMap 底图**

```json
{
  "layer_name": "osm",
  "title": "OpenStreetMap 底图",
  "layer_type": "static",
  "layer_config": {
    "source": "external",
    "tile_path": "s3://tiles/osm",
    "format": "png",
    "zoom_range": [0, 18]
  }
}
```

**案例 2：卫星影像**

```json
{
  "layer_name": "satellite",
  "title": "卫星影像",
  "layer_type": "static",
  "layer_config": {
    "source": "external",
    "tile_path": "s3://imagery/satellite",
    "format": "jpeg",
    "zoom_range": [0, 16]
  }
}
```

#### 3.2.3 上传静态瓦片

使用 MinIO 客户端（mc）上传瓦片：

```bash
# 配置 MinIO 客户端
mc alias set myminio http://localhost:19000 minioadmin minioadmin

# 上传瓦片目录
mc cp --recursive ./tiles/osm/ myminio/manager/tiles/osm/

# 验证上传
mc ls myminio/manager/tiles/osm/0/0/
```

瓦片目录结构示例：

```
tiles/osm/
├── 0/
│   └── 0/
│       └── 0.png
├── 1/
│   ├── 0/
│   │   ├── 0.png
│   │   └── 1.png
│   └── 1/
│       ├── 0.png
│       └── 1.png
└── 2/
    ...
```

## 4. 服务管理

### 4.1 查看服务详情

在服务列表页点击服务名称，进入详情页。详情页包含以下卡片：

1. **服务信息**：服务名称、标题、描述、坐标系、访问控制、状态
2. **图层管理**：图层列表、添加/编辑/删除图层、清理缓存
3. **服务端点**：XYZ Tiles、WMTS、OGC Tiles API 端点及复制功能
4. **地图预览**：在线预览瓦片效果
5. **集成示例**：OpenLayers、Leaflet、Mapbox GL JS 代码示例

### 4.2 图层管理

#### 4.2.1 添加图层

1. 在服务详情页点击 **添加图层** 按钮
2. 填写图层配置（与创建第一个图层类似）
3. 点击 **确定** 保存

一个瓦片服务可以包含多个图层，每个图层独立配置。

#### 4.2.2 编辑图层

1. 在图层列表中点击 **编辑** 按钮
2. 修改图层配置
3. 点击 **保存** 更新

**注意**：修改图层配置后，建议清理缓存以使更改生效。

#### 4.2.3 删除图层

1. 在图层列表中点击 **删除** 按钮
2. 确认删除操作

**注意**：删除图层会自动清理该图层的所有缓存。

### 4.3 缓存管理

#### 4.3.1 查看缓存状态

在服务详情页的图层列表中，每个图层显示：

- 缓存状态：启用/禁用
- 缓存 TTL：缓存有效期（秒）

#### 4.3.2 清理图层缓存

**何时需要清理缓存**：

- 源数据已更新
- 修改了图层配置
- 瓦片显示异常

**清理步骤**：

1. 在图层列表中点击 **清理缓存** 按钮
2. 确认操作
3. 系统会删除该图层的所有缓存瓦片

**注意**：清理缓存后，下次请求瓦片时会重新生成并缓存。

#### 4.3.3 缓存策略建议

| 数据更新频率 | 建议 TTL | 说明 |
|-------------|---------|------|
| 实时更新（1分钟内） | 300 秒（5 分钟） | 适合实时交通、传感器数据 |
| 每小时更新 | 3600 秒（1 小时） | 适合天气、监控数据 |
| 每天更新 | 86400 秒（1 天） | 适合日常业务数据 |
| 很少更新 | 604800 秒（7 天） | 适合基础底图、行政边界 |
| 静态数据 | 无限期 | 手动清理 |

## 5. 服务端点使用

### 5.1 XYZ Tiles

XYZ Tiles 是最常用的瓦片协议，兼容所有主流地图库。

#### 5.1.1 端点格式

```
http://localhost:8000/tiles/{serviceName}/{layerName}/{z}/{x}/{y}.{format}
```

**参数说明**：

- `{serviceName}`：服务名称（如 `beijing_roads`）
- `{layerName}`：图层名称（如 `roads`）
- `{z}`：缩放级别（0-22）
- `{x}`：瓦片 X 坐标
- `{y}`：瓦片 Y 坐标
- `{format}`：瓦片格式（`mvt`、`png`、`jpeg`）

#### 5.1.2 示例 URL

```
http://localhost:8000/tiles/beijing_roads/roads/12/3421/1532.mvt
```

#### 5.1.3 认证

**公开服务**：无需认证，直接访问

**私有服务**：需要 JWT token

```bash
# 获取 token
curl -X POST http://localhost:8000/api/system/login \
  -H "Content-Type: application/json" \
  -d '{"username": "admin", "password": "123456"}'

# 使用 token 请求瓦片
curl http://localhost:8000/tiles/beijing_roads/roads/12/3421/1532.mvt \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -o tile.mvt
```

#### 5.1.4 响应头

成功响应会包含以下响应头：

```
Content-Type: application/vnd.mapbox-vector-tile
X-Cache: HIT  # 或 MISS
Content-Encoding: gzip  # 如果启用了压缩
```

### 5.2 WMTS

WMTS (Web Map Tile Service) 是 OGC 标准，兼容 QGIS、ArcGIS Pro 等 GIS 软件。

#### 5.2.1 GetCapabilities 端点

```
http://localhost:8000/wmts/{serviceName}?request=GetCapabilities
```

示例：

```
http://localhost:8000/wmts/beijing_roads?request=GetCapabilities
```

#### 5.2.2 GetTile 端点

```
http://localhost:8000/wmts/{serviceName}?
  request=GetTile&
  layer={layerName}&
  style=default&
  tilematrixset=WebMercatorQuad&
  TileMatrix={z}&
  TileRow={y}&
  TileCol={x}&
  format=application/vnd.mapbox-vector-tile
```

#### 5.2.3 在 QGIS 中使用

1. 打开 QGIS
2. **图层 > 添加图层 > 添加 WMS/WMTS 图层**
3. 点击 **新建** 按钮
4. 填写连接信息：
   - 名称：`ADDP 瓦片服务`
   - URL：`http://localhost:8000/wmts/beijing_roads?request=GetCapabilities`
5. 点击 **连接** 按钮
6. 选择图层并添加到地图

#### 5.2.4 在 ArcGIS Pro 中使用

1. 打开 ArcGIS Pro
2. **插入 > 连接 > 服务器 > 新建 WMTS 服务器**
3. 填写 URL：`http://localhost:8000/wmts/beijing_roads?request=GetCapabilities`
4. 点击 **确定**
5. 在目录窗格中展开服务器连接，添加图层到地图

### 5.3 OGC Tiles API

OGC Tiles API 1.0 是最新的 OGC 标准，提供 RESTful API。

#### 5.3.1 Landing Page

```
GET http://localhost:8000/ogc/tiles/{serviceName}
```

返回服务描述和链接。

#### 5.3.2 Conformance

```
GET http://localhost:8000/ogc/tiles/{serviceName}/conformance
```

返回服务符合的 OGC 标准。

#### 5.3.3 TileMatrixSets

```
GET http://localhost:8000/ogc/tiles/{serviceName}/tileMatrixSets
```

返回支持的瓦片矩阵集（如 WebMercatorQuad）。

#### 5.3.4 Tilesets

```
GET http://localhost:8000/ogc/tiles/{serviceName}/tiles
```

返回所有图层的瓦片集列表。

#### 5.3.5 GetTile

```
GET http://localhost:8000/ogc/tiles/{serviceName}/tiles/{layerName}/{tileMatrixSetId}/{z}/{x}/{y}
```

示例：

```
http://localhost:8000/ogc/tiles/beijing_roads/tiles/roads/WebMercatorQuad/12/3421/1532
```

## 7. Web 地图库集成

### 7.1 OpenLayers

OpenLayers 是开源的 JavaScript 地图库，完美支持 MVT 瓦片。

#### 7.1.1 安装依赖

```bash
npm install ol
```

#### 7.1.2 加载 MVT 图层

```javascript
import Map from 'ol/Map'
import View from 'ol/View'
import VectorTileLayer from 'ol/layer/VectorTile'
import VectorTileSource from 'ol/source/VectorTile'
import MVT from 'ol/format/MVT'
import { fromLonLat } from 'ol/proj'

// 创建 MVT 图层
const vectorTileLayer = new VectorTileLayer({
  source: new VectorTileSource({
    format: new MVT(),
    url: 'http://localhost:8000/tiles/beijing_roads/roads/{z}/{x}/{y}.mvt'
  }),
  // 可选：自定义样式
  style: (feature) => {
    return new Style({
      stroke: new Stroke({
        color: '#409EFF',
        width: 2
      })
    })
  }
})

// 创建地图
const map = new Map({
  target: 'map',
  layers: [vectorTileLayer],
  view: new View({
    center: fromLonLat([116.4, 39.9]),  // 北京
    zoom: 12
  })
})
```

#### 7.1.3 添加底图

```javascript
import TileLayer from 'ol/layer/Tile'
import OSM from 'ol/source/OSM'

const map = new Map({
  target: 'map',
  layers: [
    // 底图
    new TileLayer({
      source: new OSM()
    }),
    // MVT 图层
    vectorTileLayer
  ],
  view: new View({
    center: fromLonLat([116.4, 39.9]),
    zoom: 12
  })
})
```

#### 7.1.4 私有服务认证

```javascript
const vectorTileSource = new VectorTileSource({
  format: new MVT(),
  url: 'http://localhost:8000/tiles/beijing_roads/roads/{z}/{x}/{y}.mvt',
  // 添加认证 header
  tileLoadFunction: (tile, src) => {
    const xhr = new XMLHttpRequest()
    xhr.open('GET', src)
    xhr.setRequestHeader('Authorization', 'Bearer YOUR_TOKEN')
    xhr.responseType = 'arraybuffer'
    xhr.onload = () => {
      const data = xhr.response
      const format = tile.getFormat()
      const features = format.readFeatures(data, {
        extent: tile.getExtent(),
        featureProjection: 'EPSG:3857'
      })
      tile.setFeatures(features)
    }
    xhr.send()
  }
})
```

### 7.2 Leaflet

Leaflet 是轻量级的 JavaScript 地图库，需要 `leaflet.vectorgrid` 插件支持 MVT。

#### 7.2.1 安装依赖

```bash
npm install leaflet leaflet.vectorgrid
```

#### 7.2.2 加载 MVT 图层

```javascript
import L from 'leaflet'
import 'leaflet.vectorgrid'

// 创建地图
const map = L.map('map').setView([39.9, 116.4], 12)

// 添加底图
L.tileLayer('https://{s}.tile.openstreetmap.org/{z}/{x}/{y}.png', {
  attribution: '© OpenStreetMap contributors'
}).addTo(map)
```

## 8. 最佳实践

### 8.1 性能优化

#### 8.1.1 数据库优化

**1. 空间索引**

确保所有几何列都有 GIST 索引：

```sql
CREATE INDEX idx_table_geom ON schema.table USING GIST(geom);
```

**2. 分析统计信息**

定期更新表统计信息：

```sql
ANALYZE schema.table;
```

**3. 查询优化**

使用 EXPLAIN ANALYZE 检查查询计划：

```sql
EXPLAIN ANALYZE
SELECT ST_AsMVT(q, 'layer_name', 4096, 'geom')
FROM (
  SELECT
    id,
    name,
    ST_AsMVTGeom(
      ST_Transform(geom, 3857),
      ST_TileEnvelope(12, 3421, 1532),
      4096,
      256,
      true
    ) AS geom
  FROM public.beijing_roads
  WHERE ST_Intersects(geom, ST_Transform(ST_TileEnvelope(12, 3421, 1532), 4326))
) AS q;
```

#### 8.1.2 缓存策略

**1. 合理设置 TTL**

- 实时数据：5-15 分钟
- 每小时更新：1 小时
- 每天更新：1 天
- 静态数据：7 天或更长

**2. 预热缓存**

对于重要区域，可以预先生成瓦片：

```bash
# 预热脚本示例
for z in {10..14}; do
  for x in $(seq 3400 3450); do
    for y in $(seq 1520 1550); do
      curl -s "http://localhost:8000/tiles/beijing_roads/roads/$z/$x/$y.mvt" > /dev/null
      echo "Generated tile: $z/$x/$y"
    done
  done
done
```

**3. 清理策略**

定期清理过期缓存：

```bash
# 清理 7 天前的缓存
mc rm --recursive --older-than 7d myminio/manager/service/
```

#### 8.1.3 瓦片参数优化

**extent 和 buffer 的选择**：

| 场景 | extent | buffer | 说明 |
|------|--------|--------|------|
| 高精度矢量 | 4096 | 256 | 标准配置，推荐 |
| 简单底图 | 2048 | 128 | 减少文件大小 |
| 复杂几何 | 8192 | 512 | 避免简化失真 |

**简化容差**：

对于大缩放级别（zoom < 10），可以简化几何：

```sql
SELECT
  id,
  name,
  ST_AsMVTGeom(
    ST_Simplify(ST_Transform(geom, 3857), 100),  -- 简化
    ST_TileEnvelope(8, 213, 95),
    4096,
    256,
    true
  ) AS geom
FROM public.beijing_roads
```

### 8.4 数据更新策略

#### 8.4.1 实时更新

**场景**：数据每分钟更新

**策略**：

1. 设置短 TTL（5-15 分钟）
2. 使用数据库触发器或应用层通知
3. 更新后主动清理缓存

```sql
-- 触发器示例
CREATE OR REPLACE FUNCTION notify_tile_update()
RETURNS TRIGGER AS $$
BEGIN
  PERFORM pg_notify('tile_update', json_build_object(
    'table', TG_TABLE_NAME,
    'id', NEW.id
  )::text);
  RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER trigger_tile_update
AFTER INSERT OR UPDATE OR DELETE ON public.beijing_roads
FOR EACH ROW EXECUTE FUNCTION notify_tile_update();
```

#### 8.4.2 批量更新

**场景**：数据每天批量更新

**策略**：

1. 设置长 TTL（1 天）
2. 更新完成后清理所有缓存

```bash
# 数据更新脚本
#!/bin/bash

# 1. 导入数据
psql -U postgres -d postgres -c "TRUNCATE public.beijing_roads"
psql -U postgres -d postgres -c "COPY public.beijing_roads FROM '/data/roads.csv' CSV HEADER"

# 2. 更新统计信息
psql -U postgres -d postgres -c "ANALYZE public.beijing_roads"

# 3. 清理瓦片缓存
curl -X DELETE http://localhost:8190/api/service/tile/1/layers/1/cache \
  -H "Authorization: Bearer $TOKEN"

echo "Data update completed"
```

## 9. 常见问题

### 9.1 瓦片无法显示

**问题**：地图中瓦片不显示或显示空白

**可能原因和解决方案**：

1. **坐标系不匹配**
   - 检查源数据 SRID 是否正确
   - 确认是否需要坐标转换（4326 → 3857）
   - 解决：在图层配置中指定正确的 SRID

2. **空间索引缺失**
   - 查询超时导致瓦片生成失败
   - 解决：创建 GIST 索引
   ```sql
   CREATE INDEX idx_table_geom ON schema.table USING GIST(geom);
   ```

3. **数据范围不在请求区域**
   - 检查数据边界是否覆盖请求的瓦片范围
   - 解决：使用 `ST_Extent(geom)` 查看数据边界

4. **认证失败**
   - 私有服务需要 JWT token
   - 解决：添加 Authorization header

5. **缓存问题**
   - 缓存了错误的瓦片
   - 解决：清理图层缓存

---

### 9.2 性能问题

**问题**：瓦片加载缓慢

**可能原因和解决方案**：

1. **数据量过大**
   - 单个瓦片包含过多要素
   - 解决：
     - 添加 WHERE 子句限制要素数量
     - 使用 ST_Simplify 简化几何
     - 创建物化视图

2. **缺少空间索引**
   - 全表扫描导致查询慢
   - 解决：创建 GIST 索引

3. **缓存未命中**
   - TTL 过短导致频繁重新生成
   - 解决：增加 TTL 时间

4. **数据库连接池不足**
   - 并发请求超过连接池大小
   - 解决：增加连接池大小
   ```go
   sqlDB.SetMaxOpenConns(20)
   sqlDB.SetMaxIdleConns(10)
   ```

5. **网络延迟**
   - 数据库和服务不在同一网络
   - 解决：部署在同一数据中心或使用专线

---

### 9.3 瓦片内容错误

**问题**：瓦片显示内容与预期不符

**可能原因和解决方案**：

1. **缓存过期**
   - 数据已更新但缓存未刷新
   - 解决：清理图层缓存

2. **图层配置错误**
   - 几何列名称错误
   - Schema 或表名错误
   - 解决：检查并修正图层配置

3. **坐标转换错误**
   - SRID 配置错误
   - 解决：验证源数据 SRID
   ```sql
   SELECT ST_SRID(geom) FROM schema.table LIMIT 1;
   ```

4. **样式问题**
   - 前端样式配置错误
   - 解决：检查 OpenLayers/Leaflet 样式代码

---

### 9.4 缓存管理

**问题**：如何有效管理瓦片缓存

**最佳实践**：

1. **监控缓存使用**
   ```bash
   # 查看 MinIO 存储使用情况
   mc du myminio/manager/service/
   ```

2. **定期清理**
   - 根据数据更新频率设置清理策略
   - 使用脚本自动清理

3. **缓存预热**
   - 为重要区域预先生成瓦片
   - 避免首次访问延迟

4. **分层缓存**
   - 低缩放级别（zoom < 10）：长 TTL
   - 高缩放级别（zoom > 14）：短 TTL

### 9.5 错误代码参考

| HTTP 状态码 | 错误原因 | 解决方案 |
|------------|---------|---------|
| 404 | 服务或图层不存在 | 检查 URL 中的 serviceName 和 layerName |
| 401 | 未认证 | 添加 Authorization header |
| 403 | 无权限访问 | 检查用户权限和服务 public_access 配置 |
| 500 | 服务器内部错误 | 查看服务日志，检查数据库连接 |
| 503 | 服务不可用 | 检查数据库和 MinIO 是否正常运行 |
