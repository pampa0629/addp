# Service 模块外部服务架构设计

本页说明第三方服务注册、后端代理与客户端直连的职责和现状。查询、图查询及瓦片发布见[Service 核心概念与架构](service核心概念和架构设计.md)；当前字段与写入流程见[数据库架构](数据库架构.md)。

## 对象与模块职责

| 对象 | 权威事实与职责 | 与外部接入的区别 |
| --- | --- | --- |
| ADDP 模块定义与运行实例 | System 保存持久模块身份、运行实例及租约；Gateway 消费路由快照并转发到可路由 Backend。 | 属于平台运行拓扑，不登记为第三方服务；模块注册不归 Service。 |
| 注册服务与注册图层 | Service 保存第三方端点、上游认证配置、能力元数据及解析出的图层。 | 位于 `service.registered_services`、`service.registered_service_layers`；上游不参加 ADDP 模块心跳。 |
| ADDP 自身发布的数据服务 | Service 维护 Query、Graph、Tile 等专业定义与各自的执行契约。 | 数据服务端点不是平台模块运行实例；注册一个 URL 也不自动建立 QueryService 的 Consumer Descriptor 或执行授权。 |

平台注册的概念与表归属沿[模块术语](../../docs/concepts/addp术语表.md#模块注册与运行)和[Gateway 注册与路由](../../docs/concepts/modules/Gateway注册与路由.md)维护。外部服务接入涉及的 Gateway 转发以 Service 模块为目标，不逐条管理其第三方注册记录或上游密钥；最终业务授权仍归资源 owner。

## 代理与直连的选择

两者描述请求经过哪里，不能单凭模式名称推导已经获得授权。

| 接入方式 | 适用条件与链路 | 代价与限制 |
| --- | --- | --- |
| 后端代理 | 需要在服务端装配上游凭据，或由平台控制访问时，由 Service 读取注册配置后请求上游。 | 平台承担转发带宽和上游等待；隐藏凭据、调用授权、租户范围与网络目标必须分别成立，当前接入缺口见下文。 |
| 客户端直连 | 上游明确允许客户端使用，且无需暴露私密凭据时，客户端读取获准的端点与能力后直接访问上游。 | 请求不经过 Service；平台不能据此统计完整上游流量或强制消费授权，仍受上游认证、网络与浏览器 CORS 条件约束。 |

高频瓦片或大流量可以作为评估直连的因素，不能取代凭据、上游许可和访问范围判断；是否更快需要按实际部署测量，不使用固定代理延迟作为承诺。地图的 CRS、图层、TileMatrixSet 和缩放范围来自真实能力文档，不使用示例服务的坐标系或网格参数作为通用配置。

需要隐藏上游私密凭据时，不得将它写入客户端请求、浏览器 URL 或公开配置。CORS 约束浏览器跨域读取，不替代身份认证和资源授权；详情页端点展示、上游身份、浏览器读取与实际客户端的验证统一见[原始端点与浏览器直连核对](testing/注册服务与代理.md#原始端点与浏览器直连核对)，不能从服务端探测或复制成功推导直连已通过。

当前模型、DTO 与注册页面没有 `proxy_mode`，详情展示原始端点及代理端点，不存在已接通的自动模式选择器。若要新增模式声明及切换规则，应先确认消费边界和单一契约，不能直接采用另一套前端请求工具或旧字段建议。

## 当前入口与请求链路

| 入口 | 当前路径与行为 | 依据 |
| --- | --- | --- |
| 注册管理 | `/api/v1/service/registered` 及其 ID、刷新、健康检查动作；前端通过唯一注册服务 API 客户端访问。 | [现行管理路由清单](tables/registered_services表.md#健康管理与消费)、[前端客户端](../frontend/src/api/registeredService.js) |
| Service 公开代理 | `ANY /api/service/registered/proxy/:id/*path`，独立于管理 API 挂载。 | [Service Router](../backend/internal/api/router.go)、[代理 Handler](../backend/internal/api/registered_service_handler.go) |
| Gateway 转发 | 控制面经 `/api/v1/:module/*` 转发；当前 Router 没有挂载上述公开注册代理路径。 | [Gateway Router](../../gateway/internal/router/router.go) |

端点持久字段与 DTO 投影见[注册服务表说明](tables/registered_services表.md)。生成或展示地址不证明统一入口可达或已获消费授权；Backend、Gateway 与直连的实际核对入口见[验证范围](#验证范围)。

当前 `ProxyServiceRequest` 的主要处理为：

1. 按注册服务 ID 读取配置，将请求子路径拼到 `endpoint_url`。
2. 构造上游请求，读入请求体并复制当前查询参数；复制客户端请求头时跳过 `Authorization`、`Host`、`Cookie`。
3. 按保存的上游认证配置装配凭据；规则与验证入口见下表“上游认证”。
4. 使用 60 秒超时请求上游，复制上游响应头和状态码，并流式返回响应体。请求体先完整读入内存，不能将响应流式转发解释为请求也按流传输。
5. 收到上游响应后发起异步调用摘要记录，响应体拷贝成功后再输出转发完成消息；具体含义见[代理日志边界](#代理日志边界)。

处理细节以[代理实现](../backend/internal/service/registered_service_service.go)为准；请求体转发、客户端完整接收与中断失败统一按[请求与响应完整性核对](testing/注册服务与代理.md#请求与响应完整性核对)验收，不以认证装配或转发完成日志代替完整性断言。

## 认证、租户与传输边界

| 边界 | 当前事实与约束 |
| --- | --- |
| 管理身份 | 管理 API 使用 canonical Bearer Tenant AuthContext 与 `service.external_registration.*` 精确 Permission，详情和写入按当前 Tenant 限定。平台用户令牌为 opaque Token，由 System 解析，不在 Gateway 或 Service 本地验证用户 JWT。 |
| 公开代理授权 | 路由没有复用管理认证，Repository 使用 `GetByID`，不带 Tenant 条件，也不按服务 `status` 筛选。传给日志的 Tenant/User 值不是授权证据，不能声明必须登录、按租户隔离或停用即阻断消费。 |
| 上游认证 | `auth_config` 是访问第三方的凭据，不授予平台调用者消费权；装配、更新与保护规则见[上游认证配置](数据库架构.md#上游认证配置)，各类型及健康/刷新/代理路径的验证见[上游认证矩阵](testing/注册服务与代理.md#上游认证矩阵)。当前 API Consumer 的 Query 授权或限流不覆盖注册代理。 |
| 管理 DTO | 字段隐藏与地址投影沿[注册服务表](tables/registered_services表.md)维护；隐藏认证配置不表示上游 URL、URL 内嵌参数或任意上游响应都已脱敏。 |
| 凭据存储 | 字段加密未接通；JSONB、加密与密钥轮换的事实及待确认范围统一见[上游认证配置](数据库架构.md#上游认证配置)。 |
| Header 与网络目标 | 请求只排除上述三个头，当前响应头逐项复制，不能宣称已实现完整敏感 Header 过滤。已登记的 URL 不等于 SSRF、DNS 重绑定或重定向目标限制已经接通。 |
| 调用记录与限流 | 代理应用日志、尚未接通的审计与统计见[代理日志边界](#代理日志边界)；Gateway 的 Query 消费方日志和限流不覆盖外部注册代理。 |

管理与公开代理的进一步事实、凭据和待确认范围见[数据库访问边界](数据库架构.md#认证与访问边界)；身份分类见[API 认证授权规范](../../docs/spec/api/认证授权.md)。这些事实不构成新的认证或代理方案。

## 代理日志边界

`ProxyServiceRequest` 与 `logProxyRequest` 使用 `log.Printf` 输出应用消息；经 Service 实例的运行日志路径排查，可信来源、正文权限与送达限制沿[运行日志规范](../../docs/spec/addp模块服务运行日志规范.md#五正文查询与历史分页)。当前消息的触发点与字段为：

| 消息 | 实际记录范围 | 不能据此推导的结论 |
| --- | --- | --- |
| `[Audit]` 调用摘要 | `client.Do` 取得上游响应后、响应体转发前发起异步记录，包含服务 ID、传入的 Tenant/User ID、方法、目标 URL、上游状态及耗时 | 前缀不代表已写入 System 审计；上游 4xx/5xx 也会记录，消息出现不证明响应体转发完成或业务成功 |
| `Proxy request completed` | 响应体 `io.Copy` 成功后，输出服务 ID、方法、目标 URL、上游状态及同一耗时 | 只表示该次响应体拷贝未报错，不代表上游业务成功、客户端完整接收或调用统计已落库 |
| 请求失败 / 响应体拷贝失败 | 分别在 `client.Do` 与 `io.Copy` 返回错误时输出服务 ID 和原始错误 | ID、配置读取、请求构造或请求体读取阶段提前返回，不触发上述调用摘要；这些消息不是全入口请求记录 |

摘要异步写出，与完成或拷贝错误消息的先后顺序不固定。摘要中的 Tenant/User 来自调用时传入的上下文值，缺少身份时可为 0，不是代理已完成身份或租户授权的证据。耗时从发起上游请求计至 `client.Do` 返回响应，不包含此前的配置与请求体准备，也不包含后续响应体拷贝；完成消息复用该值，不能用它计算完整代理延迟。

URL 字段输出注册端点与子路径拼成的 `targetURL`，不是最终经 Query 和上游认证装配后的请求快照。当前 URL 与原始错误输出没有显式脱敏，不能宣称敏感信息已经过滤；日志应遵循[认证凭据日志边界](../../docs/spec/addp登录认证的统一要求.md#24-认证凭据日志边界)，实际覆盖仍需验证。

`logProxyRequest` 未调用 System 审计 API；管理 API 组挂载的审计中间件也不覆盖该公开代理。当前没有 `service_call_logs` 模型、持久调用计数链路或 `access-logs` 查询路由；不能把应用消息汇总视为已接通逐服务次数、成功率、延迟统计、审计查询或导出。[Gateway 消费访问日志](../../gateway/docs/gateway架构说明.md#6-数据库)仅覆盖已验证 API Consumer 的 Query 请求，也不为此代理补齐计量。

## 能力解析与健康检查

当前注册类型为 WMS、WFS、WMTS、OGC API、XYZ 和 REST。创建先保存记录；只有 OGC 类型且显式开启自动刷新时才异步解析能力，保存成功不保证图层齐备。REST / XYZ 不因登记就自动获得通用能力解析或完整地图加载能力。

健康检查与元数据刷新由 Service 自有运行配置调度。上游探测结果、持久状态与公开代理消费授权各有边界，具体判定、定时范围和回写限制统一见[健康检查与定时刷新](数据库架构.md#健康检查与定时刷新)；图层解析与非原子刷新沿[注册服务流程](数据库架构.md#注册与元数据刷新)和[图层解析](tables/registered_service_layers表.md#解析与刷新)。

## 后续事项与确认边界

本表维护外部接入的专属缺口，跨服务类型的授权、限流/配额、运行统计与故障监控范围由[能力清单](service后续能力清单.md#待确认范围)维护。下列事项仍待确认、实现或验收，不代表已接通或通过，也不在本文确定新增表、字段、默认阈值或调度方案。

| 事项 | 需要确认或补齐的范围 |
| --- | --- |
| 接入与授权闭环 | 明确代理调用主体、租户/服务/图层范围、服务状态与禁用效果，核对 Gateway 可达性、直连许可和模式声明；不能只补转发路由就视为完成安全接入。 |
| 凭据与传输保护 | 存储加密与轮换、请求/响应敏感信息、URL 和重定向目标控制。 |
| 上游 OAuth2 | Registered Service 访问第三方 OAuth2 服务的凭据、续期和代理边界；与 System 为客户端签发 ADDP Token 的现有能力分别确认。 |
| 代理计量与审计 | 现有缺口统一见[代理日志边界](#代理日志边界)；审计查询/导出及 IP、User-Agent、请求体大小等脱敏元信息的必要范围另行确认。不记录上游凭据或请求正文，持久化归属及数据模型不沿用示意建表脚本或固定调用额度。 |
| 缓存与可用性 | Capabilities / GetMap 缓存、命中率、过期失效、故障时缓存回退和熔断效果；存储、TTL 与允许返回旧数据的条件另行设计。 |
| 告警与计费 | 通知条件、责任人和调用计费是否确有需求；不把示例阈值或商业化设想当作当前产品承诺。 |
| 能力解析 | [XML 解析的限制与完善范围](tables/registered_service_layers表.md#解析与刷新)，不能把 WFS / WMTS 刷新函数存在当作完整协议支持。 |
| 健康检查增强 | 在已有健康检查地址之外，自定义健康规则、历史记录、趋势与不可用告警的需求及数据归属仍需确认，不据当前单次结果声明已经提供。 |
| 图层管理 | 独立图层管理、启用/禁用、显示名称和批量配置的必要性与刷新覆盖规则需确认；当前没有独立图层 CRUD 路由，存储标记不构成消费授权。 |
| 外部服务聚合 | 多个上游形成统一消费结果时的图层冲突、CRS 统一和元数据融合；是否需要虚拟服务对象及其授权、故障语义尚待确认。 |
| 管理工具 | 地图/数据预览、代理端点测试、健康和调用监控面板、注册配置导入/导出的需求与边界需确认，不从管理详情页推导这些工具已接通。 |
| 错误与运行日志 | 错误响应遵循[API 规范](../../docs/spec/api/响应与错误.md)；请求关联、结构化输出及日志级别复用[运行日志规范](../../docs/spec/addp模块服务运行日志规范.md)。仍需核对具体注册/代理路径的错误分类、脱敏与接入覆盖，运行日志不能替代操作审计。 |
| 性能与资源控制 | 刷新频率与限流、需要并发时的有界调度、数据库查询与索引、代理连接复用、响应压缩及大请求/大响应传输的必要性和实测效果；不把示意并发代码当作已运行路径。 |

涉及身份、模块职责或权限结果的决定，先按现行概念和规范确认，再实现；确认后的能力按下述[验证范围](#验证范围)补齐证据，未实现或未运行项不计为通过。
