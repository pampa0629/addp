# Service 模块外部服务架构设计

## 📋 文档概述

本文档明确 Service 模块在 ADDP 架构中的职责定位，解决"外部数据服务"与"内部微服务"的概念混淆问题，并提供清晰的职责边界划分和实现方案。

---

## 🎯 核心问题

### 问题背景

Service 模块负责管理**外部数据服务**（OGC WMS/WFS、REST API 等），这些服务涉及：
- 服务 URL 存储和管理
- 服务认证配置（API Key、Bearer Token）
- 服务健康检查
- 服务调用路由和转发
- 服务访问鉴权和限流

同时，Gateway 模块负责管理**内部微服务**的路由（System、Manager、Meta 等）。

**核心困惑**: 这两类"服务"的职责边界应该如何划分？Service 模块注册的外部服务是否应该由 Gateway 统一管理？

---

## 📊 两类"服务"的本质区别

### 1️⃣ 内部微服务（ADDP 平台模块）

**定义**: ADDP 平台自身的组成模块。

**示例**:
- System Backend (用户认证、引擎管理)
- Manager Backend (数据管理、预览)
- Meta Backend (元数据扫描)
- Transfer Backend (数据导入导出)

**特点**:
- ✅ ADDP 平台的组成部分
- ✅ 启动时注册到服务注册中心
- ✅ Gateway 需要感知其存在并路由
- ✅ 需要统一认证、限流、日志
- ✅ 服务间通过 HTTP API 通信

**数据存储**: `system.service_registry` 表（未来实现）

**职责归属**: **Gateway 管理**

---

### 2️⃣ 外部数据服务（第三方服务）

**定义**: 独立于 ADDP 平台的第三方数据服务或用户发布的数据 API。

**示例**:
- 天地图 WMS 服务
- 用户注册的 GeoServer
- 第三方 REST API
- OGC WFS/WMTS 服务

**特点**:
- ✅ 独立于 ADDP 平台
- ✅ 由 Service 模块注册和管理元数据
- ✅ 可能需要 Gateway 代理转发（取决于使用场景）
- ✅ 需要服务级别的鉴权、限流
- ⚠️ 不会主动发送心跳（外部服务不属于 ADDP）

**数据存储**: `service.external_services` 表（已实现）

**职责归属**: **Service 模块管理**

---

## 🏗️ 外部服务的两种使用模式

根据业界最佳实践和安全需求，外部数据服务有两种典型的使用模式：

```
┌─────────────────────────────────────────────────────────────┐
│                     外部数据服务的两种使用模式                │
└─────────────────────────────────────────────────────────────┘
                              ↓
                    ┌─────────┴─────────┐
                    │                   │
           场景 1: 后端代理          场景 2: 前端直连
           (Gateway 转发)            (Service 提供元数据)
                    │                   │
                    ↓                   ↓
           高安全需求场景            低敏感场景
           (API Key 隐藏)            (公开 WMS 服务)
```

---

### 场景 1：后端代理模式（Gateway 转发）⭐

#### 适用场景

- ✅ 外部服务需要 **隐藏 API Key**（如付费地图服务）
- ✅ 需要 **统一鉴权**（用户必须登录 ADDP 才能访问）
- ✅ 需要 **访问控制**（不同租户访问不同服务）
- ✅ 需要 **流量统计**（计费、审计）
- ✅ 需要 **租户隔离**（Service A 仅租户 1 可见）

#### 架构设计

```
前端请求
  ↓
Gateway (/api/service/proxy/{service_id})
  ├─ 验证 JWT token（用户是否登录 ADDP）
  ├─ 记录访问日志
  └─ 转发到 Service 模块
  ↓
Service 模块
  ├─ 查询 external_services 表（根据 service_id）
  ├─ 验证租户权限（用户是否有权访问该服务）
  ├─ 构造外部服务请求
  ├─ 添加认证信息（API Key、Bearer Token）
  └─ 调用外部服务
  ↓
外部服务（WMS、REST API）
  ↓
返回结果（移除敏感 Header）
  ↓
前端接收数据（不知道真实 URL 和 API Key）
```

#### 请求示例

```bash
# 前端请求（通过 ADDP Gateway 代理）
GET /api/service/proxy/123?layers=cities&bbox=120,30,121,31
Authorization: Bearer <ADDP_JWT_TOKEN>

↓ Gateway 验证 JWT

↓ 转发到 Service 模块

# Service 模块查询 external_services 表
service_id=123 → {
  "url": "https://maps.example.com/wms",
  "auth_type": "api_key",
  "auth_config": {"api_key": "SECRET_KEY"}
}

↓ Service 模块构造真实请求

# 实际请求外部服务（API Key 在后端添加）
GET https://maps.example.com/wms?key=SECRET_KEY&layers=cities&bbox=...

↓ 返回结果给前端（不包含敏感信息）
```

#### 优点

- ✅ **API Key 隐藏**：前端无法获取外部服务的真实 URL 和认证信息
- ✅ **统一认证**：必须登录 ADDP 才能访问外部服务
- ✅ **租户隔离**：不同租户看到不同的服务列表
- ✅ **流量统计**：记录每个服务的调用次数、成功率、延迟
- ✅ **访问控制**：可以限制特定用户或角色访问特定服务
- ✅ **审计日志**：记录谁在什么时间访问了哪个外部服务

#### 缺点

- ⚠️ **增加后端压力**：所有请求都要经过 Service 模块转发
- ⚠️ **延迟增加**：多了一次代理跳转（通常 +10-50ms）
- ⚠️ **带宽消耗**：大文件传输会占用 Service 模块的带宽

---

### 场景 2：前端直连模式（Service 提供元数据）

#### 适用场景

- ✅ **公开的 WMS/WMTS 服务**（如天地图、OpenStreetMap）
- ✅ **不需要隐藏 URL**（服务提供商允许前端直接调用）
- ✅ **高性能需求**（减少一次代理跳转）
- ✅ **CDN 加速**（地图瓦片服务）
- ✅ **大流量场景**（每秒数百个瓦片请求）

#### 架构设计

```
前端请求元数据
  ↓
Service 模块 (/api/service/services/{service_id})
  ├─ 验证 JWT token（用户是否登录 ADDP）
  ├─ 验证租户权限
  └─ 返回服务配置（URL、图层列表、坐标系等）
  ↓
前端接收元数据
  ↓
前端直接调用外部服务（不经过 Gateway）
  ↓
外部服务（WMS、WMTS）
  ↓
前端接收数据
```

#### 请求示例

```javascript
// 第一步：获取服务元数据（通过 ADDP Gateway）
const response = await fetch('/api/service/services/123', {
  headers: { Authorization: `Bearer ${token}` }
})
const service = await response.json()
// 返回: {
//   id: 123,
//   name: "天地图矢量底图",
//   service_type: "wmts",
//   url: "https://t0.tianditu.gov.cn/vec_c/wmts",  // ⚠️ 前端可见
//   layers: [{ name: "vec", title: "矢量底图" }],
//   metadata: { ... }
// }

// 第二步：前端直接调用外部服务（绕过 Gateway）
const layer = new TileLayer({
  source: new WMTS({
    url: service.url,  // 直接使用外部服务 URL
    layer: 'vec',
    matrixSet: 'c',
  })
})
map.addLayer(layer)
```

#### 优点

- ✅ **减少后端压力**：不需要代理大量瓦片请求
- ✅ **性能更高**：前端直连 CDN，延迟更低
- ✅ **简化架构**：Service 只管元数据，不处理数据流
- ✅ **扩展性更好**：后端不成为瓶颈

#### 缺点

- ⚠️ **外部服务 URL 暴露**：前端可以看到真实 URL（适用于公开服务）
- ⚠️ **无法隐藏 API Key**：如果外部服务需要 API Key，必须放到前端（不安全）
- ⚠️ **难以统计流量**：无法精确统计外部服务的调用次数

## 🎯 职责边界明确化

### Service 模块的职责

| 职责 | 说明 | 示例 |
|------|------|------|
| **服务元数据管理** | 注册、查询、更新、删除外部服务信息 | 存储 WMS 服务的 URL、图层列表 |
| **服务能力探测** | 调用 GetCapabilities 并解析 | 自动解析 WMS 的图层列表、坐标系 |
| **服务健康检查** | 定时检查服务可用性，更新状态 | 每小时 ping 服务端点，标记 active/inactive |
| **服务代理转发**（场景 1） | 隐藏 API Key、添加认证信息、转发请求 | 代理请求到付费地图服务 |
| **服务调用统计** | 记录调用次数、成功率、延迟、错误率 | 统计哪个服务最常用、哪个服务最慢 |
| **租户隔离** | 验证用户是否有权访问该服务 | 租户 A 只能看到自己注册的服务 |

### Gateway 模块的职责

| 职责 | 说明 | 示例 |
|------|------|------|
| **内部微服务路由** | 转发到 System、Manager 等模块 | `/api/system/*` → System Backend |
| **统一认证入口** | 验证 JWT token | 所有请求验证 Authorization Header |
| **全局限流和熔断** | 防止恶意攻击、保护后端服务 | 每用户每分钟 100 次总请求 |
| **访问日志记录** | 记录所有 API 调用，用于审计和监控 | 记录请求时间、用户、路径、响应时间 |
| **外部服务代理转发**（场景 1） | 转发 `/api/service/proxy/*` 到 Service 模块 | Gateway 不知道外部服务详情，只负责转发 |

### 前端的职责

| 职责 | 说明 | 示例 |
|------|------|------|
| **根据场景选择调用方式** | 按需选择代理模式或直连模式 | 付费服务走代理，公开服务直连 |
| **公开服务直连**（场景 2） | 获取元数据后直接调用外部服务 | 加载天地图 WMTS 图层 |
| **敏感服务走代理**（场景 1） | 通过 `/api/service/proxy/*` 调用 | 访问高德地图 API（隐藏 Key） |

## 🔧 实现方案详解

### 场景 1 实现：后端代理模式

#### 1. Gateway 路由配置

```go
// gateway/internal/router/router.go
api := router.Group("/api")
api.Use(apiKeyAuthMiddleware.Handler())      // JWT 验证
api.Use(rateLimiterMiddleware.Handler())     // 限流
api.Use(accessLoggerMiddleware.Handler())    // 访问日志
{
    // Service 模块路由
    api.Any("/service/services", serviceProxy.Handle)       // 服务元数据 CRUD
    api.Any("/service/services/*path", serviceProxy.Handle) // 服务详情、图层列表

    // 外部服务代理路由（新增）
    api.Any("/service/proxy/:service_id", serviceProxy.Handle)
    api.Any("/service/proxy/:service_id/*path", serviceProxy.Handle)
}
```

**说明**:
- Gateway 不需要知道外部服务的详细信息
- Gateway 只负责：验证 JWT → 限流 → 记录日志 → 转发给 Service 模块
- 所有外部服务的逻辑都在 Service 模块中处理

#### 2. Service 模块代理实现

```go
// service/backend/internal/api/proxy_handler.go
package api

import (
    "io"
    "net/http"
    "github.com/gin-gonic/gin"
)

type ProxyHandler struct {
    serviceService *service.ExternalServiceService
}

// ProxyExternalService 代理转发到外部服务
func (h *ProxyHandler) ProxyExternalService(c *gin.Context) {
    serviceID := c.Param("service_id")
    subPath := c.Param("path") // 额外路径（如 /GetMap）

    // 1. 查询外部服务配置
    externalService, err := h.serviceService.GetExternalService(c.Request.Context(), serviceID)
    if err != nil {
        c.JSON(404, gin.H{"error": "Service not found"})
        return
    }

    // 2. 验证租户权限（当前用户是否有权访问该服务）
    currentTenantID := c.GetUint("tenant_id") // 从 JWT 中提取
    if externalService.TenantID != currentTenantID {
        c.JSON(403, gin.H{"error": "Access denied"})
        return
    }

    // 3. 检查服务状态
    if externalService.Status != "active" {
        c.JSON(503, gin.H{"error": "Service is unavailable"})
        return
    }

    // 4. 构造外部服务请求 URL
    externalURL := externalService.URL + subPath
    if c.Request.URL.RawQuery != "" {
        externalURL += "?" + c.Request.URL.RawQuery
    }

    // 5. 创建代理请求
    proxyReq, err := http.NewRequest(c.Request.Method, externalURL, c.Request.Body)
    if err != nil {
        c.JSON(500, gin.H{"error": "Failed to create proxy request"})
        return
    }

    // 6. 复制原始请求头（排除敏感头）
    for key, values := range c.Request.Header {
        if !isSensitiveHeader(key) {
            for _, value := range values {
                proxyReq.Header.Add(key, value)
            }
        }
    }

    // 7. 添加外部服务认证信息（核心功能：隐藏 API Key）
    switch externalService.AuthType {
    case "api_key":
        // API Key 认证（常见于地图服务）
        apiKey := externalService.AuthConfig["api_key"].(string)
        // 根据服务类型决定添加方式
        if externalService.ServiceType == "wms" || externalService.ServiceType == "wmts" {
            // 添加到 URL 参数
            q := proxyReq.URL.Query()
            q.Set("key", apiKey)
            proxyReq.URL.RawQuery = q.Encode()
        } else {
            // 添加到 Header
            proxyReq.Header.Set("X-API-Key", apiKey)
        }
    case "bearer":
        // Bearer Token 认证
        token := externalService.AuthConfig["token"].(string)
        proxyReq.Header.Set("Authorization", "Bearer "+token)
    case "basic":
        // Basic 认证
        username := externalService.AuthConfig["username"].(string)
        password := externalService.AuthConfig["password"].(string)
        proxyReq.SetBasicAuth(username, password)
    case "none":
        // 无需认证（公开服务）
    }

    // 8. 发送请求到外部服务
    startTime := time.Now()
    client := &http.Client{Timeout: 30 * time.Second}
    resp, err := client.Do(proxyReq)
    if err != nil {
        c.JSON(502, gin.H{"error": "External service unavailable", "details": err.Error()})
        h.serviceService.RecordServiceCall(serviceID, 502, time.Since(startTime))
        return
    }
    defer resp.Body.Close()

    // 9. 复制响应头（移除敏感 Header）
    for key, values := range resp.Header {
        if !isSensitiveHeader(key) {
            for _, value := range values {
                c.Header(key, value)
            }
        }
    }

    // 10. 返回响应状态码和 Body
    c.Status(resp.StatusCode)
    io.Copy(c.Writer, resp.Body)

    // 11. 记录服务调用统计
    h.serviceService.RecordServiceCall(serviceID, resp.StatusCode, time.Since(startTime))
}

// isSensitiveHeader 判断是否是敏感 Header（需要过滤）
func isSensitiveHeader(key string) bool {
    sensitiveHeaders := []string{
        "Authorization",
        "Cookie",
        "Set-Cookie",
        "X-API-Key",
        "X-Auth-Token",
    }
    for _, h := range sensitiveHeaders {
        if strings.EqualFold(key, h) {
            return true
        }
    }
    return false
}
```

**关键要点**:
- ✅ **API Key 完全隐藏**：前端无法获取外部服务的认证信息
- ✅ **租户隔离**：验证 `tenant_id` 确保用户只能访问所属租户的服务
- ✅ **多种认证方式**：支持 API Key、Bearer Token、Basic Auth
- ✅ **服务调用统计**：记录每次调用的状态码、响应时间
- ✅ **安全过滤**：移除敏感 Header，防止信息泄露

#### 3. 服务调用统计

```go
// service/backend/internal/service/external_service_service.go
func (s *ExternalServiceService) RecordServiceCall(serviceID string, statusCode int, duration time.Duration) {
    // 记录到统计表（用于计费、审计）
    callRecord := &models.ServiceCallLog{
        ServiceID:  serviceID,
        StatusCode: statusCode,
        Duration:   duration.Milliseconds(),
        CalledAt:   time.Now(),
    }
    s.repo.CreateCallLog(callRecord)

    // 更新 Redis 计数器（实时统计）
    s.redis.Incr(fmt.Sprintf("service:calls:%s:total", serviceID))
    if statusCode >= 200 && statusCode < 300 {
        s.redis.Incr(fmt.Sprintf("service:calls:%s:success", serviceID))
    } else {
        s.redis.Incr(fmt.Sprintf("service:calls:%s:error", serviceCode))
    }
}
```

### 场景 2 实现：前端直连模式

#### 1. Service 模块只提供元数据

```go
// service/backend/internal/api/service_handler.go
func (h *ServiceHandler) GetExternalService(c *gin.Context) {
    serviceID := c.Param("id")

    // 查询外部服务配置
    service, err := h.serviceService.GetExternalService(c.Request.Context(), serviceID)
    if err != nil {
        c.JSON(404, gin.H{"error": "Service not found"})
        return
    }

    // 验证租户权限
    currentTenantID := c.GetUint("tenant_id")
    if service.TenantID != currentTenantID {
        c.JSON(403, gin.H{"error": "Access denied"})
        return
    }

    // 返回服务元数据（包含 URL，但不代理请求）
    c.JSON(200, gin.H{
        "id":           service.ID,
        "name":         service.Name,
        "description":  service.Description,
        "service_type": service.ServiceType,
        "url":          service.URL,  // ⚠️ 前端可见（适用于公开服务）
        "layers":       service.Layers,
        "metadata":     service.Metadata,
        "status":       service.Status,
    })
}
```

**注意**:
- ⚠️ 这种模式下，`auth_config` 字段**不会**返回给前端
- ⚠️ 仅适用于**不需要认证**或**认证信息可以公开**的服务

#### 2. 前端直连外部服务

```javascript
// 场景 2：前端直连外部服务（适用于公开 WMS/WMTS 服务）
import { Map, View } from 'ol'
import TileLayer from 'ol/layer/Tile'
import WMTS from 'ol/source/WMTS'
import WMTSTileGrid from 'ol/tilegrid/WMTS'

async function loadWMTSLayer(serviceId) {
  // 1. 获取服务元数据（通过 ADDP Gateway）
  const response = await fetch(`/api/service/services/${serviceId}`, {
    headers: { Authorization: `Bearer ${getToken()}` }
  })

  if (!response.ok) {
    throw new Error('Failed to fetch service metadata')
  }

  const service = await response.json()
  // 返回: {
  //   id: 123,
  //   name: "天地图矢量底图",
  //   service_type: "wmts",
  //   url: "https://t0.tianditu.gov.cn/vec_c/wmts",
  //   layers: [{ name: "vec", title: "矢量底图" }]
  // }

  // 2. 前端直接调用外部服务（绕过 ADDP Gateway）
  const projection = 'EPSG:4326'
  const resolutions = []
  for (let i = 0; i < 18; i++) {
    resolutions[i] = 1 / Math.pow(2, i)
  }

  const wmtsLayer = new TileLayer({
    source: new WMTS({
      url: service.url,  // 直接使用外部服务 URL
      layer: service.layers[0].name,
      matrixSet: 'c',
      format: 'tiles',
      projection: projection,
      tileGrid: new WMTSTileGrid({
        origin: [-180, 90],
        resolutions: resolutions,
        matrixIds: resolutions.map((r, i) => i.toString()),
      }),
      style: 'default',
      wrapX: true,
    })
  })

  // 3. 添加图层到地图
  map.addLayer(wmtsLayer)
}
```

**说明**:
- ✅ 前端直接访问外部 WMTS 服务，不经过 ADDP Gateway
- ✅ 减少后端压力，性能更高
- ✅ 适用于**公开服务**（天地图、OpenStreetMap 等）
- ⚠️ 不适用于需要隐藏 API Key 的付费服务

## 🤔 如何决定使用哪种模式？

### 决策树

```
外部服务需要隐藏 API Key？
  ├─ 是 → 场景 1（后端代理）
  └─ 否 → 继续判断
      ↓
      是否需要租户隔离访问控制？
      ├─ 是 → 场景 1（后端代理）
      └─ 否 → 继续判断
          ↓
          是否是高频瓦片服务（如 WMTS）？
          ├─ 是 → 场景 2（前端直连）
          └─ 否 → 场景 1（后端代理，便于统计）
```

---

### 典型场景分类

| 服务类型 | 推荐模式 | 理由 |
|---------|---------|------|
| **付费地图 API**（如高德、百度地图） | 场景 1 | 必须隐藏 API Key，防止前端泄露 |
| **天地图 WMTS**（公开服务） | 场景 2 | 高性能，前端直连 CDN，无需代理大量瓦片 |
| **内部 GeoServer** | 场景 1 | 统一鉴权，租户隔离，访问控制 |
| **公开 WMS 服务**（如 OpenStreetMap） | 场景 2 | 减少后端压力，前端直接加载 |
| **用户自建 REST API** | 场景 1 | 安全性，访问控制，调用统计 |
| **第三方数据 API**（需要 Token） | 场景 1 | 隐藏 Token，统一认证 |
| **OGC WFS 服务**（公开要素服务） | 场景 1 或 2 | 公开服务可直连，内部服务需代理 |

---

### 配置字段建议

在 `external_services` 表中新增字段，明确使用模式：

```sql
ALTER TABLE service.external_services
ADD COLUMN proxy_mode VARCHAR(20) DEFAULT 'proxy' CHECK (proxy_mode IN ('proxy', 'direct'));
```

**字段说明**:
- `proxy`: 场景 1（后端代理模式）- 默认值，安全优先
- `direct`: 场景 2（前端直连模式）- 适用于公开服务

**前端判断逻辑**:
```javascript
const service = await getService(serviceId)

if (service.proxy_mode === 'proxy') {
  // 场景 1：通过 Gateway 代理
  url = `/api/service/proxy/${serviceId}`
} else {
  // 场景 2：前端直连
  url = service.url
}
```

## 🔒 安全性考量

### 场景 1（后端代理）的安全措施

1. **JWT 验证**（Gateway 层）
   - 所有请求必须携带有效的 JWT token
   - 验证用户是否登录 ADDP

2. **租户隔离**（Service 层）
   - 验证 `service.tenant_id == current_user.tenant_id`
   - 防止跨租户访问

3. **API Key 加密存储**
   - `auth_config` 字段应使用 AES 加密存储
   - 后端解密后添加到请求中

4. **限流保护**（Gateway + Service 层）
   - Gateway 限流：每用户每分钟 100 次总请求
   - Service 限流：每服务每小时 1000 次调用（防止滥用外部服务）

5. **敏感 Header 过滤**
   - 移除 `Authorization`、`Cookie`、`X-API-Key` 等敏感头
   - 防止前端获取认证信息

---

### 场景 2（前端直连）的安全措施

1. **元数据访问控制**
   - 获取服务元数据时仍需 JWT 验证
   - 只返回当前租户有权访问的服务

2. **隐藏敏感字段**
   - `auth_config` 字段**永远不返回**给前端
   - 仅返回公开信息（URL、图层列表、元数据）

3. **服务标记**
   - 明确标记 `proxy_mode = 'direct'`
   - 前端只能直连标记为 `direct` 的服务

4. **CORS 限制**
   - 外部服务应配置 CORS，仅允许 ADDP 前端域名访问
   - 防止其他网站滥用外部服务

## 📊 职责总结表

| 模块 | 职责 | 不负责 | 关键接口 |
|------|------|--------|---------|
| **Service** | • 外部服务元数据管理<br>• 服务能力探测（GetCapabilities）<br>• 服务健康检查<br>• 服务代理转发（场景 1）<br>• 服务调用统计<br>• 租户隔离验证 | • 内部微服务管理<br>• 全局限流和熔断<br>• JWT 认证 | `/api/service/services`<br>`/api/service/proxy/:id` |
| **Gateway** | • 内部微服务路由<br>• 统一 JWT 认证<br>• 全局限流和熔断<br>• 访问日志记录<br>• 转发到 Service 模块（代理模式） | • 外部服务元数据管理<br>• 外部服务直接调用<br>• 外部服务认证 | `/api/service/*` → Service Backend |
| **前端** | • 根据 `proxy_mode` 选择调用方式<br>• 公开服务直连（场景 2）<br>• 敏感服务走代理（场景 1） | • 直接访问需要认证的外部服务<br>• 管理 API Key | `fetch('/api/service/proxy/123')`<br>`fetch(service.url)` |
