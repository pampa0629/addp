## 性能评估

### 优势

1. **高吞吐量** - QPS 峰值 261 req/s，远超行业标准 (100 req/s)
2. **稳定可靠** - 所有测试 100% 成功，无任何错误
3. **数据库性能优异** - 缓存命中率 99.98%，几乎无磁盘 I/O
4. **扩展性良好** - 100 并发下仍能保持 255+ QPS

### 待优化点

1. **P99 延迟偏高** (1051ms)
   - 4.1% 的请求超过 755ms
   - 存在长尾延迟问题

2. **未启用应用层缓存**
   - 当前完全依赖数据库缓存
   - 缓存命中率虽高，但仍有优化空间

## 性能基准建议

### 生产环境配置

```yaml
服务配置:
  推荐并发数:     40-60 (最佳性能区间)
  限流阈值:       200 req/s (留 20% 余量)
  请求超时:       1000 ms (覆盖 99% 请求)
  默认页大小:     50 (性能最优)
  最大页大小:     200 (防止滥用)

数据库连接池:
  最大连接数:     50
  空闲连接数:     20
  连接生命周期:   3600 秒 (1小时)
```

### 监控告警阈值

| 指标 | 告警阈值 | 说明 |
|------|----------|------|
| QPS | < 100 | 性能显著下降 |
| 平均延迟 | > 300 ms | 响应变慢 |
| P99 延迟 | > 2000 ms | 尾部延迟过高 |
| 错误率 | > 1% | 服务不稳定 |
| 数据库连接数 | > 45 | 接近连接池上限 |

## 优化建议

### 短期优化 (立即可实施)

#### 1. 数据库索引优化

```sql
-- 为常用查询字段添加索引
CREATE INDEX CONCURRENTLY idx_ww_xzqdm ON service.ww_table(XZQDM);
CREATE INDEX CONCURRENTLY idx_ww_ydfldm ON service.ww_table(YDFLDM);

-- 空间索引 (如涉及空间查询)
CREATE INDEX CONCURRENTLY idx_ww_geometry
ON service.ww_table USING GIST(SmGeometry);
```

**预期提升**: QPS +20-30%, 延迟 -30-40%

#### 2. 调整数据库连接池

```bash
# .env 文件
DB_MAX_OPEN_CONNS=50      # 增加最大连接数
DB_MAX_IDLE_CONNS=20      # 增加空闲连接数
DB_CONN_MAX_LIFETIME=3600 # 连接生命周期
```

**预期提升**: P99 延迟 -20%

### 中期优化 (规划中)

#### 1. 引入 Redis 缓存

```go
// 缓存策略
缓存前 10 页数据
过期时间: 5 分钟
缓存键格式: query:{service_name}:{page}:{page_size}
```

**预期提升**: 缓存命中时延迟 -90%+

#### 2. 实现游标分页

替代 OFFSET 分页，优化大页码查询性能。

**预期提升**: 大页码查询性能提升 10-50 倍

#### 3. 启用 HTTP 响应压缩

使用 gzip 中间件压缩响应体。

**预期提升**: 响应体积 -60-80%, 传输时间 -50%

### 长期优化 (战略规划)

1. **读写分离** - 查询请求路由到从库，QPS 提升 2-3 倍
2. **数据预热** - 应用启动时预加载热点数据
3. **数据分片** - 仅针对超大数据集 (> 1000 万条)

## 测试方法

### 快速测试命令

```bash
# 安装压测工具
go install github.com/rakyll/hey@latest

# 轻量级测试 (100 请求, 10 并发)
hey -n 100 -c 10 -m POST -H "Content-Type: application/json" -d '{"page":{"limit":50}}' "http://localhost:5180/api/query/ww/query"

# 中等强度测试 (1000 请求, 50 并发)
hey -n 1000 -c 50 -m POST -H "Content-Type: application/json" -d '{"page":{"limit":50}}' "http://localhost:5180/api/query/ww/query"

# 高压测试 (持续 30 秒, 100 并发)
hey -z 30s -c 100 -m POST -H "Content-Type: application/json" -d '{"page":{"limit":50}}' "http://localhost:5180/api/query/ww/query"
```

### 监控数据库性能

```bash
# 检查数据库缓存命中率
docker exec addp-postgres psql -U addp -d addp -c "
SELECT
  datname,
  numbackends as connections,
  round((blks_hit::numeric / NULLIF(blks_hit + blks_read, 0) * 100)::numeric, 2) as cache_hit_ratio
FROM pg_stat_database
WHERE datname = 'addp';"

# 查看活跃连接数
docker exec addp-postgres psql -U addp -d addp -c "
SELECT
  count(*) as active_connections,
  max(now() - query_start) as max_query_duration
FROM pg_stat_activity
WHERE state = 'active' AND query NOT LIKE '%pg_stat_activity%';"
```
