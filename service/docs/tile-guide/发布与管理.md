# 瓦片服务：发布与管理

[返回使用指南](../瓦片服务使用指南.md)

登录 Console 后进入数据服务中的瓦片服务，公开路径为 `/service/tile`，模块内为 `/tile`。实际访问地址沿标准启动输出和当前部署，不以固定 localhost 端口作为前提。服务名是 URL 中的程序标识，标题是展示文本；图层名、表名和 MVT 内部图层名也须分别核对。

## 创建向导

当前向导依次添加首图层、配置服务信息、显示完成结果。创建 API 必须携带 `first_layer`，不先创建空服务再补第一层。

1. 选择动态空间表或静态业务 PMTiles，通过资源树读取真实 Meta 事实，填写图层名与标题。
2. 填写服务名、标题、描述、关键词、协议和 public/private 设置，按[格式与协议](../architecture/瓦片发布与缓存.md#格式与协议)核对选项对应的实际能力。
3. 创建后核对返回的服务、首图层及端点，再进入详情预览和[协议验证](../testing/瓦片协议.md)；创建成功不代替来源读取与消费验收。

默认服务 SRID 为 3857，不改变真实源 SRID。服务字段、当前管理方法和删除边界见[服务表说明](../tables/tile_services表.md)。

## 动态空间表

当前动态生成复用 [Common MVT 实现](../../../common/spatial/mvt.go)，使用 ST_TileEnvelope / ST_AsMVTGeom / ST_AsMVT 等 PostGIS 函数链。引擎已登记或可在资源树中选到，不证明所有数据库类型都具备这条执行能力；还须核对当前 Tenant、来源权限与数据保护门禁。

从资源树选择真实 Engine、Schema、表和几何列，Meta 提供几何类型和 SRID；前端同时提交 Locator，后端必需字段见[动态来源配置](../tables/tile_service_layers表.md#dynamic)。不手填未知几何列或默认认定其名为 geom。

生成时对非 3857 源几何调用 ST_Transform 转到 3857。`source.srid` 必须反映真实数据；修改配置不是修复错误的几何 SRID，也不能把默认 3857 当作所有源均已转换。

当前创建表单固定提交以下 `layer_config` MVT/缓存设置：

```json
{
  "mvt": {"extent": 4096, "buffer": 256},
  "cache": {"enabled": true, "ttl": 3600}
}
```

extent 是瓦片内部量化范围，buffer 用于边缘裁剪，不是数据地理范围；其他参数组合须验证接口与画面效果。缓存开关、TTL 和响应标记沿[缓存架构](../architecture/瓦片发布与缓存.md#动态缓存与过期边界)解释。

## 静态业务 PMTiles

1. 选择 Business 存储中已由 Meta 识别的 `data_type=media + format=pmtiles + layout=single` item，输入为含 item ID 的 ResourceLocator。
2. 确认 PMTiles v3、MVT、gzip 及 Meta 的归档识别事实；范围、层级和中心与协议声明的区别统一见[范围与层级边界](../architecture/瓦片发布与缓存.md#协议声明发布快照与数据覆盖)，不另设私有 sidecar manifest。
3. 图层名/标题为空时按 item 名称生成默认值，已有输入不覆盖。后端校验来源并生成 `source_snapshot`，客户端不自造发布快照。
4. 发布后读取业务归档，读取链路与快照校验见[静态来源契约](../tables/tile_service_layers表.md#static)；不保存裸路径、URL 模板、源凭据或 Manager infra 缓存引用。

文件准备和上传归相应业务存储与资源管理流程；本页不提供向平台数据库导入假定示例表的脚本。静态瓦片不因归档不常更新就自动具有无限期缓存语义。

## 详情与图层操作

详情页展示服务信息、图层、端点、地图预览和客户端示例。排序、可更新字段、父子归属与前后端路由不一致统一见[图层管理契约](../tables/tile_service_layers表.md#排序启用与管理)；按钮存在不表示页面动作已接通。

页面清缓存、删除/更新后的缓存行为及数据保护清理路径统一见[缓存架构](../architecture/瓦片发布与缓存.md#动态缓存与过期边界)。删除定义的源数据与级联边界沿[服务表说明](../tables/tile_services表.md#管理访问与删除)，实际操作按[管理与清理验证](../testing/瓦片协议.md#图层操作与缓存清理核对)分别留证，不以删除成功或成功提示代替缓存与消费结果核对。
