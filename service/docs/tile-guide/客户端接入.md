# 瓦片服务：客户端接入

[返回使用指南](../瓦片服务使用指南.md)

先取得已发布服务的真实 origin、服务名和图层名，再核对格式、内部图层、坐标和认证。可运行的 HTTP 样例、方法与状态分支统一见[瓦片协议测试](../testing/瓦片协议.md)，此处说明接入时需要确定的事实。

## 选择入口

| 入口 | 使用方式与限制 |
| --- | --- |
| XYZ | 路径为 `/tiles/{serviceName}/{layerName}/{z}/{x}/{y}.mvt`，x 为列、y 为行；当前主要读取 MVT，不把扩展名改成 png/jpeg 就当成栅格渲染。 |
| WMTS | `/wmts/{serviceName}` 返回 Capabilities；从 ResourceURL 核对实际取瓦片模板。当前没有独立 WMTS GetTile KVP 执行，不以同一路径附加 GetTile 参数代替 XYZ。 |
| OGC Tiles | 从 `/ogc/tiles/{serviceName}` 发现矩阵集、tileset 和读取链接；当前 GetTile 使用 WebMercatorQuad，路径中的 tileMatrix/tileRow/tileCol 顺序为 z/y/x。 |

端点的 host、HTTP/HTTPS、反向代理路径和部署 origin 必须与实际网络一致。元数据或配置里返回一个地址，不证明该地址已被 Gateway 接受或已完成客户端兼容性验收。

## 格式、内部图层与样式

MVT 是矢量载荷。使用能解析当前载荷的矢量瓦片读取器，先确认解码、几何类型和内部图层，再添加样式；不要将矢量文件作为图片加载。

动态图层生成时将发布的 layer_name 交给 MVT 生成器；静态 PMTiles 保留归档内部图层名，外层发布名称不保证与其相同。部分客户端用 source-layer 定位内部图层，必须从实际载荷或归档元数据核对，不能一律照抄源表名。

当前动态调用没有声明业务属性列集合，不能因源表存在 name/type/id 就承诺这些属性已进入 MVT。按真实载荷确认后，再设计点/线/面样式、属性着色、随缩放变化的宽度、悬停高亮和点击属性展示；这类客户端交互不等于服务端样式管理能力。

## 已有前端与外部客户端

ADDP 页面优先复用[共享地图模块](../../../common-frontend/map/README.md)中的 TilePreview / useVectorTileLoader，沿现有来源、Token、解码和错误处理路径接入。详情页已有 OpenLayers、Leaflet、Mapbox GL JS 的示例文本；它们是待核对的接入参考，不能据此声明安装任意版本即可兼容，也不复制为另一套平台加载器。

| 客户端 | 接入检查 |
| --- | --- |
| QGIS / ArcGIS Pro 等桌面 GIS | 核对实际版本支持的矢量瓦片/WMTS 接入方式、MVT 编码、矩阵集、私有认证及完整加载效果。仅列出 WMTS 连接不保证该客户端能渲染发布的矢量格式。 |
| OpenLayers | 核对 MVT 解析器、瓦片网格/投影、真实 URL 和内存 Token 传递，优先沿共享加载能力。 |
| Leaflet | 核对当前客户端/插件是否支持实际 MVT 与认证需求；图层样式键、属性和事件以解码结果为据。 |
| Mapbox GL JS | 核对矢量源、内部图层名、几何类型、样式和认证装配；背景底图与 ADDP 发布图层分开验证。 |

记录实际客户端、版本和测试结果，界面菜单沿该版本操作。背景底图的网络/许可/显示故障不直接证明 Service 矢量读取失败；同样，底图可见也不能证明发布图层已经加载。

## 空间范围与初始视角

静态发布快照中的有效 `spatial.extent` 优先用于全幅显示，只有范围无效或缺失才回退 center/zoom，并尊重归档的 min_zoom/max_zoom。当前预览由 `tilePreviewConfig` 与共享 TilePreview 配合处理，不能把某地区的中心点当成平台默认数据范围。

WMTS 元数据中的矩阵级别与固定范围不是每份数据的真实覆盖；请求坐标应落在发布来源的范围和有效层级内。空 PMTiles 瓦片可能是 HTTP 200 的 gzip 空 MVT，分开判断没有数据、载荷错误与存储失败。

## 私有访问与跨域

私有端点通过 `Authorization: Bearer <access_token>` 传递当前 Tenant User Access Token；System 提供权威 AuthContext，Service 不自行解析 Token。浏览器沿共享 Browser AuthSession 使用内存 Token，不写入 URL 或持久化存储。

跨域沿 Gateway 的[共享 CORS 中间件](../../../common/middleware/cors/middleware.go)配置和验证 origin、请求认证 Header 与可读响应 Header。CORS 不是服务授权，公开配置也不替代源数据保护。服务状态、协议开关和图层 enabled 的统一执行边界继续按[架构专题](../architecture/瓦片发布与缓存.md)核对。
