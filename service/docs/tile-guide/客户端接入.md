# 瓦片服务：客户端接入

[返回使用指南](../瓦片服务使用指南.md)

先取得已发布服务的真实 origin、服务名和图层名，再核对格式、内部图层、坐标和认证。可运行的 HTTP 样例、方法与状态分支统一见[瓦片协议测试](../testing/瓦片协议.md)，此处说明接入时需要确定的事实。

## 选择入口

| 入口 | 使用方式与限制 |
| --- | --- |
| XYZ | 使用 `/tiles/{serviceName}/{layerName}/{z}/{x}/{y}.mvt` 模板，x 为列、y 为行。 |
| WMTS | 从 `/wmts/{serviceName}` 获取 Capabilities，再核对 ResourceURL。 |
| OGC Tiles | 从 `/ogc/tiles/{serviceName}` 发现矩阵集、tileset 和读取链接。 |

矩阵声明、行列映射与读取限制见[协议边界](../architecture/瓦片发布与缓存.md#协议声明发布快照与数据覆盖)。先按[链接与入口边界](../architecture/瓦片发布与缓存.md#元数据链接与公开入口)确定 Backend、Gateway 或统一公开入口，再按[公开入口验证](../testing/瓦片协议.md#元数据链接与公开入口核对)检查原始链接和实际响应。

## 格式、内部图层与样式

格式能力见[格式与协议](../architecture/瓦片发布与缓存.md#格式与协议)。使用矢量瓦片读取器确认几何类型与内部图层，不把 MVT 当图片加载；解码与编码检查沿[载荷验证](../testing/瓦片协议.md#wmts-元数据与-xyz-读取)。

动态图层生成时将发布的 layer_name 交给 MVT 生成器；静态 PMTiles 保留归档内部图层名，外层发布名称不保证与其相同。部分客户端用 source-layer 定位内部图层，必须从实际载荷或归档元数据核对，不能一律照抄源表名。

当前动态调用未声明业务属性列集合，不能从源表字段推导 MVT 属性。按实际载荷设计点/线/面样式、属性着色、随缩放变化的宽度、悬停高亮和点击属性展示；客户端交互不等于服务端样式管理，服务端配置边界见[图层来源配置](../tables/tile_service_layers表.md#来源配置)。

## 已有前端与外部客户端

ADDP 页面优先复用[共享地图模块](../../../common-frontend/map/README.md)中的 TilePreview / useVectorTileLoader，沿现有来源、Token、解码和错误处理路径接入。详情页已有 OpenLayers、Leaflet、Mapbox GL JS 的示例文本；它们是待核对的接入参考，不能据此声明安装任意版本即可兼容，也不复制为另一套平台加载器。

| 客户端 | 接入检查 |
| --- | --- |
| QGIS / ArcGIS Pro 等桌面 GIS | 核对实际版本支持的矢量瓦片/WMTS 接入方式、MVT 编码、矩阵集、私有认证及完整加载效果。仅列出 WMTS 连接不保证该客户端能渲染发布的矢量格式。 |
| OpenLayers | 核对 MVT 解析器、瓦片网格/投影、真实 URL 和内存 Token 传递，优先沿共享加载能力。 |
| Leaflet | 核对当前客户端/插件是否支持实际 MVT 与认证需求；图层样式键、属性和事件以解码结果为据。 |
| Mapbox GL JS | 核对矢量源、内部图层名、几何类型、样式和认证装配；背景底图与 ADDP 发布图层分开验证。 |

记录实际客户端、版本和测试结果，界面菜单沿该版本操作。背景底图的网络/许可/显示故障不直接证明 Service 矢量读取失败；同样，底图可见也不能证明发布图层已经加载。

## 空间范围与初始视角

声明范围、快照字段、当前预览层级与实际覆盖统一见[范围与层级边界](../architecture/瓦片发布与缓存.md#协议声明发布快照与数据覆盖)。客户端按真实发布来源确定初始视角及测试坐标，不从全幅显示推导框内处处有数据；应记录实际选中图层、视角和可访问层级。

有数据、合法空瓦片、载荷错误与源读取失败分别按[元数据与覆盖验证](../testing/瓦片协议.md#元数据快照与覆盖核对)检查。

## 私有访问与跨域

私有端点使用当前 Tenant 的 User Access Token；Bearer 传递及 System 权威 AuthContext 沿[统一认证主路径](../../../docs/spec/addp登录认证的统一要求.md#一认证事实与唯一主路径)；Service 不自行解析 Token。浏览器复用共享 Browser AuthSession 的内存 Token，不写入 URL 或持久化存储。

跨域沿 Gateway 的[共享 CORS 中间件](../../../common/middleware/cors/middleware.go)配置和验证 origin、请求认证 Header 与可读响应 Header。CORS 不是服务授权；public/private、源数据保护及状态/开关阻断的区别统一见[管理与消费状态](../architecture/瓦片发布与缓存.md#管理与消费状态)，认证与错误按[访问用例](../testing/瓦片协议.md#空瓦片缓存与访问)核对。

第三方原始端点的上游认证与 CORS 按[浏览器直连专题](../testing/注册服务与代理.md#原始端点与浏览器直连核对)另验，不向第三方发送平台令牌；代理认证装配成功不证明浏览器直连可用。
