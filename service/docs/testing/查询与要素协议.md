## REST Query

当前入口为 `POST /api/query/:serviceName/query`。`QUERY_SERVICE_NAME` 使用服务程序标识，不是表名、图层名或显示标题。

```bash
: "${QUERY_SERVICE_NAME:?设置本次已发布查询服务的 service_name}"
cat > "$SERVICE_TEST_DIR/query.json" <<'JSON'
{"page":{"limit":10},"format":"json"}
JSON
curl -fsS -X POST "$SERVICE_API_BASE/api/query/$QUERY_SERVICE_NAME/query" \
  -H "Authorization: Bearer $SERVICE_USER_TOKEN" -H 'Content-Type: application/json' \
  --data-binary @"$SERVICE_TEST_DIR/query.json" \
  -D "$SERVICE_TEST_DIR/query.headers" -o "$SERVICE_TEST_DIR/query-result.json"
```

检查 `data` 始终是数组，空结果为 `[]`；`page.limit/has_more/next_cursor` 与实际行数匹配，保存响应的 `service_version`。游标是不透明令牌，下一页只使用返回值，并保持同一参数、筛选与排序；不要自行构造 offset、页码或稳定键。

下例仅在发布输出确有 `population` 且允许筛选、选择和排序时适用；使用实际冻结字段替换，不能从业务字段名推导权限：

```json
{
  "select": ["population"],
  "filter": {"field": "population", "op": "gt", "value": 1000000},
  "order_by": [{"field": "population", "direction": "desc"}],
  "page": {"limit": 10},
  "format": "json"
}
```

将符合当前契约的请求保存到上述 `query.json` 后复用同一入口；请求不接受 SQL、WHERE、ORDER BY 或 CQL 字符串。检查非法字段/类型/命名参数、超限和游标篡改均按实际错误出口拒绝，不通过伪造或删去保护条件获得成功。

CSV / GeoJSON 仍走同一 POST：只修改请求中的 `format`，CSV 可增加 `X-ADDP-Query-Intent: export` 表达审计用途，授权和数量上限不变。保存返回文件及 `X-ADDP-Has-More`、`X-ADDP-Next-Cursor`、`X-ADDP-Service-Version`；单次有界导出不等于全量导出。GeoJSON 需要已确认空间输出及已发布格式支持，非空间服务应验证格式拒绝，不强制假定所有失败都用同一状态码。

## 管理 DTO 与页面端点核对

- **DTO 生成地址**：[QueryServiceService](../../backend/internal/service/query_service_service.go) 的 `buildEndpoints` 按协议启用配置生成 `endpoints`：REST 对应 `rest_api`，Features 对应 `ogc_features` 与 `ogc_features_collections`。地址由启动时注入的 `cfg.GatewayURL` 加协议路径和 `service_name` 拼接；环境变量、默认值及转发头边界沿[地址来源说明](#元数据链接与公开入口核对)。这些字段是响应投影，不是数据库列；生成时不探测网络、不按服务状态或消费授权筛除，字段存在不证明当前可执行。
- **页面展示地址**：主查询详情 [QueryServiceDetail](../../frontend/src/views/QueryServiceDetail.vue) 当前未直接使用 DTO 的 `endpoints`，而是用该页面的 `window.location.origin` 拼接 REST 与 Features 地址，并另行生成 conformance/items 示例。因此管理响应、页面复制值与 Features 元数据原始链接可能使用不同 origin；iframe 场景也须核对页面自身的 origin。Features 的“测试”按钮只通过 `window.open` 打开地址，不自动附带管理请求的 Bearer，不能据此认定私有消费授权已通过。
- **转发与验收**：分别记录 DTO 值、页面复制值和元数据原始链接；REST 按[预览链路](#rest-测试按钮与页面预览)及 [POST 样例](#rest-query)取数，Features 按[公开入口核对](#元数据链接与公开入口核对)检查转发缺口与原始链接。手工改写地址成功不能代替展示地址或公开 HTTPS 验收。

### REST 测试按钮与页面预览

- **请求链路**：详情页 REST“测试”先重置预览游标，再调用 `loadPreviewData → queryServiceAPI.testQuery`；[查询客户端](../../frontend/src/api/queryExecutionClient.js)使用空 `baseURL`，向当前页面 origin 的 `POST /api/query/:serviceName/query` 发请求，不读取展示框或 DTO 的 URL。路径与页面展示值相同，但 DTO 的 `GATEWAY_URL` 可能不同。Console 与 Service 的 Vite 配置均将 `/api` 转到 `GATEWAY_PORT` 指定的 Gateway，产品部署沿根 Nginx `/api/` 规则；最终代理目标与公开 HTTPS 入口须核对实际部署。
- **请求与身份**：[预览请求构造器](../../frontend/src/utils/queryServicePreview.js)提交当前命名参数、字段选择、`page.limit/cursor` 和 `format=json`。共享[认证拦截器](../../../common-frontend/basic/src/composables/useAuth.js)有当前访问令牌时附带 User Bearer；此按钮不装配 `X-API-Key`，不能用于证明匿名或 API Consumer 消费通过。请求仍进入正式 Query Handler，管理页可见不授予查询权，服务状态、协议、Tenant/执行权限及源数据保护按实际身份校验。
- **验收范围**：预览接受 `data` 数组并更新分页，空数组也会提示加载成功；这只证明本次页面入口、身份和请求的响应被接受，不证明业务结果正确、后续分页或其他格式通过。记录浏览器实际请求 URL、身份类型、参数、服务版本与返回结果，并与展示地址、DTO 地址及目标公开地址逐项核对；保存证据时不记录令牌。若 URL 相同，本次预览可作为该入口的 User Bearer JSON 查询证据；其他地址、匿名/API Consumer、CSV/GeoJSON 和公开 HTTPS 链路仍按本页 [REST Query](#rest-query)、[权限与失败用例](#权限与失败用例)分别验收，不能以复制成功或直接用 GET 打开 POST 地址代替。

## OGC API Features

当前一个 QueryService 对应一个 collection，ID 为该服务的 `service_name`。先读取 collections 返回的 ID、items 链接及空间范围/CRS，不预设 `cities`、`geom` 或 WGS84。

| 方法 | 路径 | 检查内容 |
| --- | --- | --- |
| GET | `/ogc/features/:serviceName` | Landing Page 的标题及链接。 |
| GET | `/ogc/features/:serviceName/conformance` | 当前 conformance 声明；声明不替代兼容性验收。 |
| GET | `/ogc/features/:serviceName/collections` | collection 身份、空间事实及 items 链接。 |
| GET | `/ogc/features/:serviceName/collections/:collectionId/items` | GeoJSON FeatureCollection 与分页链接。 |
| GET | `/ogc/features/:serviceName/collections/:collectionId/items/:featureId` | 使用响应中的不透明 Feature ID 读取要素。 |

```bash
curl -fsS "$SERVICE_API_BASE/ogc/features/$QUERY_SERVICE_NAME/collections" \
  -H "Authorization: Bearer $SERVICE_USER_TOKEN" -o "$SERVICE_TEST_DIR/collections.json"
COLLECTION_ID=$(jq -er '.collections[0].id' "$SERVICE_TEST_DIR/collections.json")
curl -fsS -G "$SERVICE_API_BASE/ogc/features/$QUERY_SERVICE_NAME/collections/$COLLECTION_ID/items" \
  -H "Authorization: Bearer $SERVICE_USER_TOKEN" --data-urlencode 'limit=10' \
  -o "$SERVICE_TEST_DIR/features.json"
```

检查 `type=FeatureCollection`、`numberReturned` 等于本次实际要素数，以及 `links` 中的 self/next。下一页沿返回链接或其 `cursor` 请求，并保留 bbox 等原条件；返回的链接 origin 也须核对当前部署。单要素请求使用 `features[].id`，不把源表主键 `1` 当作 Feature ID。

空间筛选在已确认服务 CRS 和范围后进行：

```bash
: "${SERVICE_TEST_BBOX:?设置与当前服务空间契约匹配的四个数值坐标}"
curl -fsS -G "$SERVICE_API_BASE/ogc/features/$QUERY_SERVICE_NAME/collections/$COLLECTION_ID/items" \
  -H "Authorization: Bearer $SERVICE_USER_TOKEN" --data-urlencode 'limit=10' \
  --data-urlencode "bbox=$SERVICE_TEST_BBOX" -o "$SERVICE_TEST_DIR/features-bbox.json"
```

当前 Handler 读取 `limit`、`cursor`、`bbox`，未接通 CQL filter、offset、sortBy 或请求级 CRS 转换；这些参数可能未被消费，不能用 HTTP 200 证明筛选/重投影生效。BBOX 仅做四个数值的解析并形成空间谓词，坐标语义须结合发布契约核对。Router 也没有独立的 collection 详情路由，不把 collections 列表的一个元素误写成已挂载接口。

### 开发代理与 Console 统一入口

- **转发差异**：[Service Vite](../../frontend/vite.config.js)将 `/api`、`/ogc` 转发至 `GATEWAY_PORT` 指定的 Gateway；[Console Vite](../../../console/frontend/vite.config.js)只配置了其中的 `/api`，没有 `/ogc` 代理。[模块入口](../../../common-frontend/basic/src/utils/moduleFrontend.mjs)将 Service 页面放在 Console origin 的 `/module-ui/service/`，直接打开模块开发端口的页面导航也会跳转到同源入口。页面中的根路径 `/ogc/features` 不带模块前缀，不会经过 Service Vite 的 `/ogc` 规则；模块页面能加载或 REST 预览成功均不证明 Console 已转发 Features。不要通过添加 `/api` 或 `/module-ui/service` 前缀把缺失的协议入口解释为已接通。
- **地址、身份与验收**：记录最终页面 origin、实际请求 URL 与代理目标，按[DTO 与页面端点核对](#管理-dto-与页面端点核对)区分展示与新窗口身份，按[公开入口核对](#元数据链接与公开入口核对)验证真实 JSON/GeoJSON、原始 items/next 链接及私有服务认证。代理规则不授予权限，REST 的 API Consumer 验证也不覆盖 Features；Service 前端代理、Gateway、Console 与公开 HTTPS 分别留证。

### 元数据链接与公开入口核对

- **地址来源**：Landing Page、Collections 和 Items 的 self/items/next 业务链接由 [Features Handler](../../backend/internal/api/ogc_features_handler.go)使用启动时注入的 `cfg.GatewayURL` 拼接。该值来自 [Service 配置](../../backend/internal/config/config.go)的 `GATEWAY_URL`，未设置时默认 `http://localhost:8000`；不根据请求 Host、`Forwarded`、`X-Forwarded-*` 或 `ADDP_PUBLIC_ORIGIN` 自动推导。实际值须核对运行配置；不能将默认值、容器内地址或直连请求 origin 当作外部可达地址。
- **代理转发**：Service 与 Gateway 已挂载本节 Features 路由，Gateway 透明代理不改写响应 JSON 中的链接。仓库[根 Nginx](../../../nginx/nginx.conf)仅将 `/api/` 转发 Gateway，尚未转发 `/ogc/features`；该路径会落入 Console 的 `/`，HTTP 200 可能是前端页面。给路径加 `/api` 不是现有 Features 路由。公开 origin 沿[配置规范](../../../docs/spec/configuration/环境变量参考.md#端口分配)，HTTPS 终止沿[Nginx 说明](../../../nginx/README.md#https-配置)；公开地址配置、转发头或 TLS 已启用均不证明协议转发和生成链接已正确。
- **实际验收**：记录请求入口与响应原始链接的 scheme、host、port 和路径，核对额外代理前缀及原有查询条件；分别验证集合发现、沿 items/next 原始链接取数、私有服务身份和实际 GIS 客户端。上面的样例按 `SERVICE_API_BASE` 手工拼接地址，只验证所选入口，不能替代返回链接的可达性验收。直连成功、改写链接后成功或 conformance 声明成功均不能推导公开 HTTPS 链路通过；按[标准入口与证据](验收方法与排查.md#标准入口与证据)单列未接通、失败与未运行项。

## 权限与失败用例

身份、来源授权及保护规则见[身份授权与资源限制](../architecture/查询发布与执行.md#身份授权与资源限制)；角色方式的来源与身份限制见[登录用户的角色脱敏选择](../architecture/查询发布与执行.md#登录用户的角色脱敏选择)。下表用例不代表所有来源、身份组合均已有验收证据。

下表以服务、身份及其他输入满足对应检查的前置条件为准。具体分支和稳定码以[Query Handler](../../backend/internal/api/query_handler.go)、[Features Handler](../../backend/internal/api/ogc_features_handler.go)为据；本地化错误正文不做固定英文全文断言。

| 条件 | 当前预期 |
| --- | --- |
| REST 服务不存在 | 404，`service_not_found`。 |
| REST 服务停用 | 503，`service_inactive`。 |
| REST 私有服务匿名/跨 Tenant/缺执行 Permission | 分别核对 401/403/403 与对应稳定码。 |
| REST 协议未启用 | 501，`rest_api_disabled`。 |
| REST 请求未知字段、无效格式 | 核对 400 与 `invalid_query_request` / `invalid_query_format`。 |
| 命中查询数据保护拒绝 | 403，`data_protection_required`，不返回数据或原始敏感错误。 |
| Features 协议未启用 | 501；服务停用先返回 503。 |
| Features collection ID 不匹配 | 404。 |
| Features limit 非法、BBOX 非四个数值或 Feature ID 非法 | 400；limit 当前解析范围为 1–10000，执行仍受服务限制。 |
| 有效 Feature ID 对应查询无结果 | 404。 |

REST 的 API Consumer 验证另用 `X-API-Key`，不同时携带 Bearer；核对精确 Query Service Grant 与 Tenant，不能仅凭凭据有效或服务公开就判通过。其他公开协议不据此获得同一授权能力。

## WFS 边界

当前 Router 没有挂载 ADDP 自身的 WFS 发布路由；GetCapabilities / DescribeFeatureType / GetFeature、GML、CQL、startIndex、srsName、sortBy 属于待接通后的操作、格式与查询验收范围。WFS 共用结构化查询内核是规范要求；未来接通后再补真实入口、格式、分页与 GIS 客户端兼容性验收。注册第三方 WFS 的解析属于[注册服务测试](注册服务与代理.md)，不能当作 ADDP 已发布 WFS 的证据。
