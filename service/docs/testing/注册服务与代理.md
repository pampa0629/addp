## 注册与元数据

当前管理前缀为 `/api/v1/service/registered`。以下仅为本轮可清理的测试配置模板，将 `endpoint_url` 替换为受控上游的实际端点后再发送；不使用公众服务的品牌名称推导免费、匿名或认证方式。

```bash
cat > "$SERVICE_TEST_DIR/registered-create.json" <<'JSON'
{
  "service_name": "api_fixture_wms",
  "title": "受控 WMS 测试服务",
  "service_type": "wms",
  "endpoint_url": "https://upstream.example.test/wms",
  "auth_type": "none",
  "auto_refresh_metadata": false
}
JSON
```

```bash
curl -fsS -X POST "$SERVICE_API_BASE/api/v1/service/registered" \
  -H "Authorization: Bearer $SERVICE_USER_TOKEN" -H 'Content-Type: application/json' \
  --data-binary @"$SERVICE_TEST_DIR/registered-create.json" \
  -o "$SERVICE_TEST_DIR/registered-created.json"
REGISTERED_SERVICE_ID=$(jq -er '.id' "$SERVICE_TEST_DIR/registered-created.json")
curl -fsS "$SERVICE_API_BASE/api/v1/service/registered/$REGISTERED_SERVICE_ID" \
  -H "Authorization: Bearer $SERVICE_USER_TOKEN" -o "$SERVICE_TEST_DIR/registered-detail.json"
```

检查创建返回 201、ID 和 `service_name/title/endpoint_url`，详情不返回 `auth_config` 正文，但会返回上游 URL 与端点。开启自动刷新时创建可能早于图层完成；手动刷新或健康检查沿下列入口，不从 active 状态推断上游全部能力已可用：

| 方法 | 路径 | 检查内容 |
| --- | --- | --- |
| POST | `/api/v1/service/registered/:id/refresh` | 当前上游类型的能力解析、部分写入与独立状态回写，见下文核对范围。 |
| POST | `/api/v1/service/registered/:id/health` | 健康结果及状态回写；两者不能混为一个成功标记。 |
| GET | `/api/v1/service/registered/:id` | 当前 Tenant 的详情和解析图层。 |
| DELETE | `/api/v1/service/registered/:id` | 清理本轮新建的测试配置，不删除上游数据。 |

WMS / WFS / WMTS、OGC API、REST / XYZ 的解析差异及 XML 限制沿[图层说明](../tables/registered_service_layers表.md#解析与刷新)验证。列表搜索/分页、更新和跨 Tenant 详情按[现行管理契约](../tables/registered_services表.md#健康管理与消费)验收，不虚构注册图层的独立 CRUD 或日志查询接口。

## 原始端点与浏览器直连核对

- **展示与复制**：按[端点字段与 DTO 投影](../tables/registered_services表.md#字段)比对详情回读值与复制值；[注册详情](../architecture/管理界面与模块协作.md#注册页面交互与验收)对原始端点仅作展示与复制，不自动测试直连或选择代理模式。另验实际协议参数、可达性与浏览器消费条件。
- **上游认证**：管理请求的 ADDP User Bearer 与上游身份分别成立，不能把平台令牌发给第三方端点。DTO 不返回 `auth_config` 正文，`has_auth_config` 也不表示浏览器已取得上游凭据；Service 在健康、刷新或代理中装配认证成功，不证明浏览器可用同一身份直连。只在上游明确允许客户端使用且无需暴露私密凭据时，按其真实认证方式验收；不得把服务端保存的密钥搬进浏览器 URL 或公开配置。装配与保护范围见[上游认证矩阵](#上游认证矩阵)。
- **跨域与实际验收**：从实际 Console/客户端 origin 发起预期的浏览器请求，核对上游网络可达、认证、请求方法与 Header、需要时的 OPTIONS 预检及响应 CORS 头；使用 Cookie 等凭据时另核对 credentials 与服务端允许条件，规则沿 [MDN CORS](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/CORS)。CORS 不替代上游授权；在地址栏打开、curl 或 Service 后端读取成功，都不证明浏览器脚本能跨域读取。图片显示也不能替代需要读取像素或 WebGL 纹理的实际地图用法。记录浏览器/客户端版本、页面 origin、脱敏请求与响应类型、读取或地图结果，按[注册图层能力核对](#注册图层能力核对)验证真实数据；直连、代理与统一入口分别验收，失败与未运行项单列，不保存真实凭据。

## 注册图层能力核对

保存字段与协议差异沿[几何、范围与能力](../tables/registered_service_layers表.md#几何范围与能力)。用可清理的受控上游分别核对原始能力文档、详情 DTO 的解析值和实际地图/数据响应；只验证其中一层，不计为全部通过：

- WMS：对比多个 CRS/SRS、父子 Layer、命名空间及两种已识别范围标签的实际解析结果，记录缺失或错误匹配；GetMap 使用该上游的协议版本、图层名、CRS/SRS、BBOX 轴序、样式和尺寸，另验图像内容及已知位置，不把地理 bbox 直接作为任意 CRS 的请求范围。
- WFS：对比 DefaultCRS 与范围角点各自的来源，核对字符串值、缺失字段及命名空间；再按实际支持的协议请求受控要素并验证几何位置、坐标系与输出格式。FeatureType 入库不证明 DescribeFeatureType、要素读取或自动重投影已接通。
- WMTS：核对 tile_matrix_set 标识与上游能力的对应关系，再检查实际 SupportedCRS、矩阵标识、原点、分辨率/比例尺、瓦片/矩阵尺寸及限界，使用上游支持的请求方式验证选定行列的瓦片和位置；不从空 crs、旧 crs 或单个标识生成默认 XYZ 网格。
- 缺失、无法解析或不一致的 CRS/范围/网格分别记录；坐标字符串需在消费侧验证数值与轴序，不能把当前入库行为写成已有该校验。OGC API 的父 metadata、REST / XYZ 注册与图层表解析能力分别验收，不要求当前自动生成不存在的图层契约。

页面展示范围见[注册页面交互与验收](../architecture/管理界面与模块协作.md#注册页面交互与验收)。GetMap/GetFeature/GetTile 与浏览器定位须有实际响应及地图证据，按[标准入口与证据](验收方法与排查.md#标准入口与证据)区分页面夹具、受控上游与真实链路。

## 元数据刷新核对

入口与状态规则沿[注册与元数据刷新](../数据库架构.md#注册与元数据刷新)，协议差异沿[图层解析与刷新](../tables/registered_service_layers表.md#解析与刷新)。使用本轮可清理的注册记录和已知能力内容的受控上游，分别保存 HTTP 结果与详情回读断言，不用刷新成功提示代替图层核对：

- 创建异步刷新、手动刷新和定时刷新分别验证。创建 201 不等待自动刷新，异步失败也不自动改为 error；手动/定时刷新则检查最后的状态写入及其失败。定时循环只处理 active 的 OGC 服务。
- WMS 对比刷新前后图层，检查先删除后创建导致的空集、部分新行和 ID 变化；同时覆盖零解析结果。WFS / WMTS 对比新增、更新、上游已移除而仍保留的旧行，以及 enabled 被重新设为 true 的情况；OGC API 检查父 metadata，不要求生成对应图层行。
- 使用标准门禁内的受控夹具覆盖 metadata 更新、WMS 删除、图层查询/单行写入及最终状态写入失败，检查已提交数据是否保留；不修改个人数据库制造故障。部分单行错误可能仍返回 200 并写 active，最终状态写入失败也可能在数据已更新后返回 500，不能以 HTTP 状态单独判定图层完整或数据回滚。
- 分别核对 metadata.refreshed_at、图层内容/数量与 status/error_message；解析日志数量不等于入库数量，刷新也不更新 last_checked_at。上游能力、图层持久化、健康结果和公开代理消费各自验收；模拟上游不替代真实运行链路。

现有管理租户测试包含跨 Tenant 刷新返回 404；协议解析、部分写入、并发刷新、状态回写及真实调度须分别核对断言与执行证据。

## 健康结果与状态回写核对

探测条件和实际回写规则统一见[健康检查与定时刷新](../数据库架构.md#健康检查与定时刷新)。仅使用本轮创建的受控注册配置与上游，分别核对健康接口响应、随后管理详情中的 `status/error_message/last_checked_at`，以及独立的代理消费行为：

- 使用专用健康地址与默认端点两种情况，核对实际 GET、上游认证及 WMS / WFS / WMTS 的 GetCapabilities 参数。2xx 只证明当前 HTTP 探测成功，仍须独立验证能力正文、图层或数据。
- 分别覆盖 2xx、非 2xx、网络失败/超时及请求构造失败；按结果正文的 `status/status_code/message` 判定，不把健康接口 HTTP 200 当作 `healthy`。`checked_at`、`response_time` 与数据库检查时间按各自含义核对，不要求时间完全相等。
- 对比响应与详情回读：检查时间和状态是两次独立写入，不能用一项变化替代另一项；回写失败须使用标准门禁内的受控夹具验证，不修改个人数据库制造故障。恢复 active 后旧错误信息可能仍在，不能只凭 `error_message` 非空判定本次探测失败。
- 若验证手动检查 inactive，须记录可能写回 active 的当前行为；定时循环只选 active，不将 error/inactive 的自动重试或恢复计为已实现。调度日志中的成功数量也不证明状态全部落库。
- 健康/状态回写不代替[公开代理读取与授权检查](#代理读取与错误)：当前代理不筛 status，inactive/error 不代表消费已经被阻断；管理接口跨 Tenant 拒绝须与公开代理边界分别验收。

现有管理租户测试包含跨 Tenant 健康请求返回 404；上游探测、状态/时间分步写入、错误保留、真实调度及代理授权须分别留证。

## 上游认证矩阵

字段与装配规则统一见[上游认证配置](../数据库架构.md#上游认证配置)。使用隔离夹具的合成凭据和能核对实际请求的受控上游，分别验证健康、刷新与代理路径；比较在夹具内完成，报告仅保存脱敏断言，不打印认证 Header、完整 URL 参数或凭据正文。

| auth_type | 装配验证点 | 保护与异常边界 |
| --- | --- | --- |
| none | 不新增配置认证；分别检查已有 Header/Query 是否仍传递 | 不是清理凭据或撤销上游凭据；切换 none 后不能据此认定数据库旧配置已删除 |
| basic | 上游收到 Basic Authorization，夹具内解码后与合成 username/password 比较 | Base64 不计作加密；缺失、非字符串、空值及含分隔符的用户名分别核对，不宣称已完成字段有效性校验 |
| bearer | 上游收到固定 Bearer 前缀加配置 token，而非客户端的 ADDP Authorization | 核对空值、类型不符与 token 已带前缀的情况；本路径不获取、刷新或验证 Token 有效期，上游拒绝须独立记录 |
| api_key | 分别核对 name/location 指定的 Header 与 Query；覆盖同名客户端值时 Header 为覆盖、Query 为追加 | 核对缺失、类型不符、无效 location 和同名多值；不把 Query 已追加等同于上游接受或 URL/日志已脱敏，不使用旧参数别名 |

配置保存、DTO 投影、上游认证与凭据保护分开验收：

- 创建、更新后检查 DTO 不含 auth_config；has_auth_config 只作配置非空提示。用受控夹具核对 auth_config 整体替换、缺省/null 保留，以及只切换 none 不清除旧配置；不将前端必填提示视为后端配置校验。
- 代理先排除客户端 Authorization、Host、Cookie，再复制其他 Header/Query 并装配上游认证；其他客户端凭据不保证全部过滤，响应头和正文也未因装配成功而脱敏。健康或刷新通过不证明公开代理消费授权已接通。
- 数据库存储加密、实际 Service→上游 TLS、重定向目标，以及 URL/响应/日志泄露分别核对；当前字段加解密、强制 HTTPS、应用级重定向控制与完整敏感信息过滤未接通，不写成已通过。日志验证沿[代理日志核对](#代理日志核对)，不使用真实凭据制造泄露样本。

认证证据注明类型与健康/刷新/代理路径，真实上游、传输及存储保护分别留证；各层夹具与运行证据的区别遵循[标准入口与证据](验收方法与排查.md#标准入口与证据)。

## 代理读取与错误

Service 实际挂载 `ANY /api/service/registered/proxy/:id/*path`。本节样例使用 `SERVICE_BACKEND_BASE` 指向受控部署的 Backend origin，不含路径或末尾斜杠；管理请求继续使用公共准备的 `SERVICE_API_BASE`，两者可能不同，不能机械替换。

- **生成地址**：DTO 的 `endpoints.proxy` 由启动时注入的 `cfg.GatewayURL` 与代理路径拼接；该配置来自 `GATEWAY_URL`，未设置时默认 `http://localhost:8000`，实际值须核对运行配置。详情页展示或复制该值不探测可达性，也不把它转换成 Backend 直连地址。
- **转发范围**：Service / Console Vite 的 `/api` 规则和根 Nginx `/api/` 规则都将此请求送到 Gateway，但当前 [Gateway Router](../../../gateway/internal/router/router.go)没有注册代理路径；管理 API 的 `/api/v1/service/registered` 可用不证明公开代理已接通。入口类型沿[公共准备](../API测试指南.md#公共准备)辨认，不通过套用管理前缀构造替代消费路由。
- **实际验收**：Backend 直连仅覆盖 Service → 受控上游，不包含 Gateway、前端开发代理或公开 HTTPS；后者按实际路由和部署分别记录。保存实际请求 origin/路径、响应类型和上游断言，并与 DTO 原始地址对照；手工替换 origin 后成功不能计为 DTO 地址正确或统一入口通过，未接通、失败与未运行分别列明。

```bash
: "${SERVICE_BACKEND_BASE:?设置受控验收部署中 Service Backend 的实际 origin}"
curl -sS -G "$SERVICE_BACKEND_BASE/api/service/registered/proxy/$REGISTERED_SERVICE_ID/" \
  --data-urlencode 'service=WMS' --data-urlencode 'request=GetCapabilities' \
  -D "$SERVICE_TEST_DIR/proxy.headers" -o "$SERVICE_TEST_DIR/proxy-body.xml" \
  -w '%{http_code}\n'
```

此公开路由未挂管理认证，传 Bearer 也不构成已完成登录或租户隔离校验。当前按 ID 读取、不筛 Tenant/status；应将匿名、跨 Tenant、停用状态的消费阻断列为未闭合安全验收，不沿用旧“另一租户必然 403/404”的断言。管理详情的跨 Tenant 拒绝仍须独立验证。

### 请求与响应完整性核对

请求体完整读入内存、响应体流式转发的实现边界统一见[外部服务架构](../外部服务架构设计.md#当前入口与请求链路)；流式响应不表示请求体按流传输，也不证明客户端已完整接收。使用受控上游和有界合成数据分别验收：

- **请求体转发**：按上游实际支持的方法覆盖空体、非空文本及二进制请求，在夹具内比对发送端与上游实际收到的字节数、摘要或完整内容，同时核对方法、子路径、查询参数及 Content-Type。只记录脱敏断言，不保存业务正文或凭据；上游认证沿[认证矩阵](#上游认证矩阵)独立核对。当前 GetCapabilities 样例没有请求体，不能作为非空请求体完整转发的证据。
- **客户端响应**：使用具有已知内容的受控响应，比对上游输出与客户端实际保存结果的长度及摘要，压缩与解码采用同一比较口径；再按 Content-Type 解析 XML、JSON、图片或二进制。HTTP 200、可解析的部分内容、已收到响应头或 Service 拷贝完成日志均不替代完整性断言；协议参数与地图定位仍沿[注册图层能力核对](#注册图层能力核对)验收。
- **中断与失败**：通过标准门禁内的受控夹具分别覆盖请求体读取错误、上游慢响应/截断及客户端断开。请求体读取失败应在发往上游前返回错误，不能记作完整转发；响应中断须记录实际状态、客户端读取结果及已收到的字节数，区分响应尚未发送与已经发送，不能要求后者仍能返回完整 502，或把部分数据与错误正文混合作为正常响应。不从客户端断开推导上游已立即停止。现有入口未覆盖相应断言或尚未运行时单列为未验证，不把本页用例要求记为门禁已通过。

| 条件 | 当前预期 |
| --- | --- |
| 代理 ID 不能解析 | 400。 |
| 注册服务 ID 不存在 | 404。 |
| 上游网络不可达或请求构造失败 | Handler 通常返回 502；保存实际分支，避免断言固定英文错误全文。 |
| 上游返回 401/403 等状态 | 正常收到响应时转发上游状态与内容，不改写为已通过 ADDP 认证。 |
| 上游慢响应/流式中断 | 核对 60 秒超时及已发送响应的处理；不能假定中断后还能重写完整 502。 |

## 代理日志核对

实际消息、字段、耗时与未接通能力统一见[代理日志边界](../外部服务架构设计.md#代理日志边界)。在同一受控请求中分别核对上游接收内容、Service 响应与 Service 实例运行日志，不从 `[Audit]` 前缀或单条完成消息推断正式审计、调用统计或业务成功：

- 正常响应与上游 4xx/5xx：核对调用摘要中的服务、方法和上游状态；摘要可能先于响应体转发完成出现，完成消息的耗时仍只计至收到上游响应。
- 网络失败、超时与响应体中断：分别核对请求失败或拷贝失败输出；摘要可能已经写出而拷贝随后失败。ID 或配置等提前失败分支不要求出现调用摘要，不能据其缺失判定请求未发生。
- URL、上游认证与错误输出：只用不含真实凭据的合成值检查日志暴露范围；记录的 `targetURL` 不代替受控上游收到的最终参数。当前没有显式 URL/原始错误脱敏，不能把 DTO 隐藏 `auth_config` 计为日志脱敏通过。

运行日志查询按[统一规范](../../../docs/spec/addp模块服务运行日志规范.md#五正文查询与历史分页)核验实例、来源、权限和实际正文；本地打印不证明集中日志送达，查到正文也不证明 System 审计或统计已入库。实际断言及未覆盖项目按[统一验收边界](../API测试指南.md#能力与验收边界)记录。

正式审计、调用统计和 `access-logs` 查询仍按[后续范围](../外部服务架构设计.md#后续事项与确认边界)补齐再验收。测试结束仅删除本轮创建并记录了 ID 的配置，报告保留已脱敏的状态、响应类型和断言结果。
