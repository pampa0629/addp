# Service 注册服务与代理

[返回 API 测试指南](../API测试指南.md)

按[公共准备](../API测试指南.md#公共准备)准备当前 Tenant 用户和受控上游。管理面、Service 直连代理、Gateway 入口、上游响应分别验收；已知可达性与权限缺口见[外部服务架构](../外部服务架构设计.md)，不能以转发成功替代安全验收。

## 注册与元数据

当前管理前缀为 `/api/v1/service/registered`。以下仅为本轮可清理的测试配置模板，将 `endpoint_url` 替换为受控上游的实际端点后再发送；不使用公众服务的品牌名称推导免费、匿名或认证方式。

```bash
cat > "$SERVICE_TEST_DIR/registered-create.json" <<'JSON'
{
  "service_name": "api_fixture_wms",
  "title": "受控 WMS 测试服务",
  "service_type": "wms",
  "endpoint_url": "https://upstream.example.test/wms",
  "auth_type": "none",
  "auto_refresh_metadata": false
}
JSON
```

```bash
curl -fsS -X POST "$SERVICE_API_BASE/api/v1/service/registered" \
  -H "Authorization: Bearer $SERVICE_USER_TOKEN" -H 'Content-Type: application/json' \
  --data-binary @"$SERVICE_TEST_DIR/registered-create.json" \
  -o "$SERVICE_TEST_DIR/registered-created.json"
REGISTERED_SERVICE_ID=$(jq -er '.id' "$SERVICE_TEST_DIR/registered-created.json")
curl -fsS "$SERVICE_API_BASE/api/v1/service/registered/$REGISTERED_SERVICE_ID" \
  -H "Authorization: Bearer $SERVICE_USER_TOKEN" -o "$SERVICE_TEST_DIR/registered-detail.json"
```

检查创建返回 201、ID 和 `service_name/title/endpoint_url`，详情不返回 `auth_config` 正文，但会返回上游 URL 与端点。开启自动刷新时创建可能早于图层完成；手动刷新或健康检查沿下列入口，不从 active 状态推断上游全部能力已可用：

| 方法 | 路径 | 检查内容 |
| --- | --- | --- |
| POST | `/api/v1/service/registered/:id/refresh` | 当前上游类型的能力解析与失败/部分写入。 |
| POST | `/api/v1/service/registered/:id/health` | 健康结果及状态回写；两者不能混为一个成功标记。 |
| GET | `/api/v1/service/registered/:id` | 当前 Tenant 的详情和解析图层。 |
| DELETE | `/api/v1/service/registered/:id` | 清理本轮新建的测试配置，不删除上游数据。 |

WMS / WFS / WMTS、OGC API、REST / XYZ 的解析差异及 XML 限制沿[图层说明](../tables/registered_service_layers表.md#解析与刷新)验证。列表搜索/分页、更新和跨 Tenant 详情按[现行管理契约](../tables/registered_services表.md#健康管理与消费)验收，不虚构注册图层的独立 CRUD 或日志查询接口。

## 上游认证矩阵

为每种类型使用能验证收到内容的受控上游，测试值来自隔离夹具，报告不保存凭据正文。

| auth_type | auth_config | 验证点 |
| --- | --- | --- |
| none | 空配置。 | 不额外装配认证。 |
| basic | username、password。 | 上游接收到 Basic Authorization。 |
| bearer | token。 | 上游接收到 Bearer Authorization；它与 ADDP 用户令牌分开。 |
| api_key | key、name、location。 | 分别测试 header/query 的参数位置与值，不沿用旧 api_key/header 别名。 |

管理 DTO 不返认证配置、上游收到正确认证、数据库是否加密、URL/请求/响应/日志是否泄露是不同检查。当前字段加解密与完整响应 Header 过滤未接通，不把它们写成已通过；上游 URL 含凭据时也不能只检查 `auth_config`。

## 代理读取与错误

Service 实际挂载 `ANY /api/service/registered/proxy/:id/*path`，当前 Gateway Router 没有该转发路径。直连 Service 的测试 origin 使用 `SERVICE_BACKEND_BASE`，与管理面可能使用的 Gateway origin 分开；DTO 拼出的代理地址必须另验可达性。

```bash
: "${SERVICE_BACKEND_BASE:?设置受控验收部署中 Service Backend 的实际 origin}"
curl -sS -G "$SERVICE_BACKEND_BASE/api/service/registered/proxy/$REGISTERED_SERVICE_ID/" \
  --data-urlencode 'service=WMS' --data-urlencode 'request=GetCapabilities' \
  -D "$SERVICE_TEST_DIR/proxy.headers" -o "$SERVICE_TEST_DIR/proxy-body.xml" \
  -w '%{http_code}\n'
```

此公开路由未挂管理认证，传 Bearer 也不构成已完成登录或租户隔离校验。当前按 ID 读取、不筛 Tenant/status；应将匿名、跨 Tenant、停用状态的消费阻断列为未闭合安全验收，不沿用旧“另一租户必然 403/404”的断言。管理详情的跨 Tenant 拒绝仍须独立验证。

请求子路径、查询参数和请求体使用受控上游逐项核对；它接到的 Basic/Bearer/API Key 应来自已保存上游配置。响应体按上游 Content-Type 验证 XML、JSON、图片或二进制，GetMap 的 layers、BBOX、SRS/CRS 等来自该上游能力，不硬编码到所有服务。

| 条件 | 当前预期 |
| --- | --- |
| 代理 ID 不能解析 | 400。 |
| 注册服务 ID 不存在 | 404。 |
| 上游网络不可达或请求构造失败 | Handler 通常返回 502；保存实际分支，避免断言固定英文错误全文。 |
| 上游返回 401/403 等状态 | 正常收到响应时转发上游状态与内容，不改写为已通过 ADDP 认证。 |
| 上游慢响应/流式中断 | 核对 60 秒超时及已发送响应的处理；不能假定中断后还能重写完整 502。 |

当前代理只记录应用日志，正式 System 审计、调用统计和 access-logs 查询没有因此接通；需要这些能力时按[后续范围](../外部服务架构设计.md#后续事项与确认边界)补齐再验收。测试结束仅删除本轮创建并记录了 ID 的配置，报告保留已脱敏的状态、响应类型和断言结果。
