# Service 瓦片协议

[返回 API 测试指南](../API测试指南.md) · [返回瓦片使用指南](../瓦片服务使用指南.md) · [返回核心架构总入口](../service核心概念和架构设计.md)

先按[公共准备](../API测试指南.md#公共准备)选择已发布 TileService 和真实图层。当前主要验证动态 MVT 与业务 PMTiles v3 + gzip MVT；格式、协议、来源和缓存边界见[瓦片发布与缓存](../architecture/瓦片发布与缓存.md)。

操作步骤见[发布与管理](../tile-guide/发布与管理.md)、[客户端接入](../tile-guide/客户端接入.md)和[性能与排查](../tile-guide/性能与排查.md)。

## WMTS 元数据与 XYZ 读取

| 方法 | 路径 | 检查内容 |
| --- | --- | --- |
| GET | `/wmts/:serviceName` | Capabilities XML、图层身份、TileMatrixSet 与 ResourceURL。 |
| GET | `/tiles/:serviceName/:layerName/:z/:x/*yformat` | XYZ 瓦片；`*yformat` 的具体形式为 `/y.mvt`。 |

```bash
: "${TILE_SERVICE_NAME:?设置瓦片服务的 service_name}"
: "${TILE_LAYER_NAME:?设置该服务的真实 layer_name}"
curl -fsS "$SERVICE_API_BASE/wmts/$TILE_SERVICE_NAME" \
  -H "Authorization: Bearer $SERVICE_USER_TOKEN" -o "$SERVICE_TEST_DIR/wmts.xml"
```

Capabilities 的固定声明和执行限制沿[协议边界](../architecture/瓦片发布与缓存.md#协议声明发布快照与数据覆盖)，ResourceURL 的生成及公开可达性按[入口核对](#元数据链接与公开入口核对)验证；图层和坐标仍需通过 XYZ 载荷及客户端加载单独检查。

选择真实数据覆盖的坐标，读取并保存响应头及解码后的 MVT：

```bash
: "${TILE_Z:?设置测试缩放级别}"
: "${TILE_X:?设置测试瓦片列}"
: "${TILE_Y:?设置测试瓦片行}"
curl -fsS --compressed \
  "$SERVICE_API_BASE/tiles/$TILE_SERVICE_NAME/$TILE_LAYER_NAME/$TILE_Z/$TILE_X/$TILE_Y.mvt" \
  -H "Authorization: Bearer $SERVICE_USER_TOKEN" \
  -D "$SERVICE_TEST_DIR/tile.headers" -o "$SERVICE_TEST_DIR/tile.mvt"
```

检查 Content-Type、Content-Encoding 与实际载荷一致，用既有前端预览或已配置的 MVT 解码工具检查内部图层、要素与范围。`--compressed` 会按响应编码解压，保存的文件与线上 gzip 字节不同。

## OGC Tiles

| 方法 | 路径 | 检查内容 |
| --- | --- | --- |
| GET | `/ogc/tiles/:serviceName` | Landing Page 与部署链接。 |
| GET | `/ogc/tiles/:serviceName/conformance` | 当前符合性声明。 |
| GET | `/ogc/tiles/:serviceName/tileMatrixSets` | 矩阵集列表。 |
| GET | `/ogc/tiles/:serviceName/tileMatrixSets/:tileMatrixSetId` | 矩阵与坐标体系。 |
| GET | `/ogc/tiles/:serviceName/tiles` | tileset 与图层投影。 |
| GET | `/ogc/tiles/:serviceName/tiles/:layer/:tileMatrixSetId/:tileMatrix/:tileRow/:tileCol` | MVT 读取；矩阵、行、列分别对应 z、y、x。 |

```bash
curl -fsS --compressed \
  "$SERVICE_API_BASE/ogc/tiles/$TILE_SERVICE_NAME/tiles/$TILE_LAYER_NAME/WebMercatorQuad/$TILE_Z/$TILE_Y/$TILE_X" \
  -H "Authorization: Bearer $SERVICE_USER_TOKEN" \
  -D "$SERVICE_TEST_DIR/ogc-tile.headers" -o "$SERVICE_TEST_DIR/ogc-tile.mvt"
```

矩阵集限制和 XYZ 适配关系沿[协议边界](../architecture/瓦片发布与缓存.md#协议声明发布快照与数据覆盖)。比较两入口同一图层、同一 z/x/y 的解码内容，分别检查元数据和实际读取；不从配置键推导统一执行资格已接通。

## 元数据链接与公开入口核对

沿[链接与入口边界](../architecture/瓦片发布与缓存.md#元数据链接与公开入口)执行；公共准备中的 SERVICE_API_BASE 必须是本轮已确认的实际入口，报告注明 Backend、Gateway 或统一公开地址，不混用三者的通过证据：

- 保存原始 WMTS ResourceURL 和 OGC Tiles 服务 links 的脱敏结果，逐项核对 scheme、Host/端口、协议路径及额外代理前缀；同时记录用户访问地址和实际代理配置。生成值、预期公开地址与真实可达地址分别陈述，不将手工替换 scheme、Host 或路径后的成功计为原始链接正确。
- 在受控部署中分别检查元数据入口和实际瓦片读取。公开 HTTPS 须核对证书、代理路由与所需认证，再验证 XML/JSON 元数据及解码后的 MVT；单凭 HTTP 200、Console 页面、健康检查或配置语法通过不算协议链路通过。当前根 Nginx 的协议转发缺口须明确保留，直连 Gateway 成功不抵消该缺口。
- 检查实际客户端是否使用元数据链接，以及通过同一公开入口访问的结果。带前缀部署、转发头、公开 origin 配置和不同客户端分别说明已验证范围；没有真实运行证据的项标为未运行，不从源码拼接或请求模板推导已验收。

## 元数据、快照与覆盖核对

按[范围与层级边界](../architecture/瓦片发布与缓存.md#协议声明发布快照与数据覆盖)分别记录协议响应、发布快照和实际瓦片，不合并为单一“已支持”结论：

- WMTS / OGC Tiles：对比声明的矩阵、范围与图层，链接沿[公开入口核对](#元数据链接与公开入口核对)单独验证；矩阵集详情和 GetTile 的失败分支分开验证，不预设全部入口对高层级或越界坐标采用同一拒绝状态。
- PMTiles：对比受控归档经 Meta 识别的 min/max zoom、center、EPSG:4326 范围、header_hash 与后端冻结快照；原始识别和字段回读不代替真实 Range Read 或瓦片解码。覆盖当前 Header 与快照不符、存储/归档错误，不将其误计为空瓦片。
- 数据覆盖：选择已知有数据及无目录项的位置，在有效层级内验证载荷，并检查发布层级之外的实际结果；快照范围内可能仍有空洞，不能以中心点的一片数据推导全域覆盖。空响应、错误和成功载荷分别统计。
- 客户端：核对实际图层的初始全幅、回退视角与缩放限制；含 23–31 级的归档须单列当前预览范围和未验证级别，不把固定矩阵声明或辅助函数结果视为全层级地图验收。

现有快照冻结、归档范围外空瓦片和预览辅助函数测试只证明相应受控分支；不证明真实归档全覆盖、协议客户端兼容、公开链接可达或完整代理链路。运行证据分别注明源码/归档版本、身份、坐标、层级、结果及未运行项。

## 空瓦片、缓存与访问

- 静态 PMTiles 没有对应目录项或请求超出已发布级别时，当前返回 HTTP 200、gzip 编码的空 MVT；解压后的空载荷不能仅按文件大小判错。归档/存储异常仍是错误，不能伪装成空瓦片。不要沿用“无数据必为 204”的断言。
- 动态读取可能先经过来源保护拒绝。TTL、HIT/MISS 与静态标记的解释唯一沿[缓存架构](../architecture/瓦片发布与缓存.md#动态缓存与过期边界)。对同一 Tenant/服务/图层及 z/x/y，记录动态或静态来源、缓存配置、响应头和解码内容；用受控来源分别覆盖首次/重复读取、缓存关闭、源变化及跨过配置 TTL 的时刻，不将尚未实现的过期行为计为通过。
- 动态写入异步进行；没有写入完成证据时，不要求第二次请求必为 HIT，也不以 MISS 响应证明缓存已持久化。静态请求则结合 PMTiles 发布依赖、归档和实际载荷核对；标记、HTTP 200 或单次读取均不能代替新鲜度与内容断言。所用夹具和真实链路分别注明范围，未运行项不计为通过。
- 私有入口按 User AuthContext 校验：匿名 401、Tenant 不匹配 403；WMTS 错误是 XML，XYZ / OGC Tiles 错误是 JSON。服务状态、协议开关和图层 enabled 的统一阻断仍按架构专题保留为未决，不因保存成功就宣称生效。
- 不存在的服务或图层核对 404；XYZ 的非法 y.format 或不可解析整数核对 400；OGC Tiles 不支持的矩阵集核对 400。数值越界的处理依动态/静态读取路径，不将旧“所有 z 超过 22 均返回 400”的示例当统一契约。
- PNG/JPEG 响应类型映射不代表栅格渲染已实现；TMS、WMS GetMap 和高级样式也不凭配置或计划计入当前发布能力。若接入这些能力，先补 owner 契约与实现，再补对应验收。

## 图层操作与缓存清理核对

路由、字段、排序与父子归属沿[图层管理契约](../tables/tile_service_layers表.md#排序启用与管理)，缓存触发点沿[缓存架构](../architecture/瓦片发布与缓存.md#动态缓存与过期边界)。只使用本轮可清理的定义与受控来源，分别核对：

- 后端管理请求、详情回读及当前 Tenant / 父服务 / 图层归属。已有授权测试覆盖部分跨 Tenant、父子不匹配和删除后 404，不证明页面客户端使用了同一路由或全部变更已通过真实数据库验收。
- 页面新增、更新、删除的实际 URL 与返回状态；当前路径不一致仍记为未闭合，不能用直接请求后端成功替代页面动作验收，也不添加兼容别名取得通过。
- 记录删除与对象清理分开检查。当前没有正式手动清缓存入口，删除/更新也不自动证明旧缓存已清理；这些缺口不计为通过，不用手工删除 MinIO 对象或旁路脚本代替。数据保护投影的清理与在途读取屏障按其安全链路独立验收，不借其结果证明页面清理可用。
- 父服务删除后的图层结果按[实际级联约束](../tables/tile_service_layers表.md#索引与约束)核对，不从历史 SQL 或代码注释断言已经级联；源表、业务 PMTiles、动态缓存与 Service 定义分别记录。HTTP 成功、提示或 X-Cache 都不是缓存为空、内容已更新或业务源未变的完整证据。

运行结果需记录版本、身份、对象范围、实际状态及未运行项；本页保留验证要求，不声明上述缺口已有实现或运行证据。
