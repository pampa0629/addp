# Service 瓦片协议

[返回 API 测试指南](../API测试指南.md)

先按[公共准备](../API测试指南.md#公共准备)选择已发布 TileService 和真实图层。当前主要验证动态 MVT 与业务 PMTiles v3 + gzip MVT；格式、协议、来源和缓存边界见[瓦片发布与缓存](../architecture/瓦片发布与缓存.md)。

## WMTS 元数据与 XYZ 读取

| 方法 | 路径 | 检查内容 |
| --- | --- | --- |
| GET | `/wmts/:serviceName` | Capabilities XML、图层身份、TileMatrixSet 与 ResourceURL。 |
| GET | `/tiles/:serviceName/:layerName/:z/:x/*yformat` | XYZ 瓦片；`*yformat` 的具体形式为 `/y.mvt`。 |

```bash
: "${TILE_SERVICE_NAME:?设置瓦片服务的 service_name}"
: "${TILE_LAYER_NAME:?设置该服务的真实 layer_name}"
curl -fsS "$SERVICE_API_BASE/wmts/$TILE_SERVICE_NAME" \
  -H "Authorization: Bearer $SERVICE_USER_TOKEN" -o "$SERVICE_TEST_DIR/wmts.xml"
```

当前 Capabilities 声明 WebMercatorQuad 和 0–22 级矩阵，并以 ResourceURL 指向 XYZ；它不是单独挂载的 WMTS GetTile KVP 实现。检查模板与实际 HTTP/HTTPS、host、图层及坐标顺序，不能仅凭 XML 返回成功就认定桌面客户端已完成加载。图层真实范围和 PMTiles 级别仍按发布快照验证，不用能力文档中的固定边界替代真实数据范围。

选择真实数据覆盖的坐标，读取并保存响应头及解码后的 MVT：

```bash
: "${TILE_Z:?设置测试缩放级别}"
: "${TILE_X:?设置测试瓦片列}"
: "${TILE_Y:?设置测试瓦片行}"
curl -fsS --compressed \
  "$SERVICE_API_BASE/tiles/$TILE_SERVICE_NAME/$TILE_LAYER_NAME/$TILE_Z/$TILE_X/$TILE_Y.mvt" \
  -H "Authorization: Bearer $SERVICE_USER_TOKEN" \
  -D "$SERVICE_TEST_DIR/tile.headers" -o "$SERVICE_TEST_DIR/tile.mvt"
```

检查 Content-Type、Content-Encoding 与实际载荷一致，用既有前端预览或已配置的 MVT 解码工具检查内部图层、要素与范围。`--compressed` 会按响应编码解压，保存的文件与线上 gzip 字节不同。

## OGC Tiles

| 方法 | 路径 | 检查内容 |
| --- | --- | --- |
| GET | `/ogc/tiles/:serviceName` | Landing Page 与部署链接。 |
| GET | `/ogc/tiles/:serviceName/conformance` | 当前符合性声明。 |
| GET | `/ogc/tiles/:serviceName/tileMatrixSets` | 矩阵集列表。 |
| GET | `/ogc/tiles/:serviceName/tileMatrixSets/:tileMatrixSetId` | 矩阵与坐标体系。 |
| GET | `/ogc/tiles/:serviceName/tiles` | tileset 与图层投影。 |
| GET | `/ogc/tiles/:serviceName/tiles/:layer/:tileMatrixSetId/:tileMatrix/:tileRow/:tileCol` | MVT 读取；矩阵、行、列分别对应 z、y、x。 |

```bash
curl -fsS --compressed \
  "$SERVICE_API_BASE/ogc/tiles/$TILE_SERVICE_NAME/tiles/$TILE_LAYER_NAME/WebMercatorQuad/$TILE_Z/$TILE_Y/$TILE_X" \
  -H "Authorization: Bearer $SERVICE_USER_TOKEN" \
  -D "$SERVICE_TEST_DIR/ogc-tile.headers" -o "$SERVICE_TEST_DIR/ogc-tile.mvt"
```

当前 GetTile 只接受 WebMercatorQuad，转换坐标后复用 XYZ Handler。比较两入口的同一图层和 z/x/y，而不是把行列颠倒后仍期望同一内容。元数据和瓦片读取分别测试，不能由协议配置键推导统一执行资格已接通。

## 空瓦片、缓存与访问

- 静态 PMTiles 没有对应目录项或请求超出已发布级别时，当前返回 HTTP 200、gzip 编码的空 MVT；解压后的空载荷不能仅按文件大小判错。归档/存储异常仍是错误，不能伪装成空瓦片。不要沿用“无数据必为 204”的断言。
- 动态读取可能先经过来源保护拒绝。缓存启用时分别记录首次、命中和源变化后的请求；`X-Cache` 不足以证明缓存新鲜度，静态 PMTiles 当前也标为 HIT。缓存读取未按保存的 TTL 判断过期，不把到期自动重算计为通过。
- 私有入口按 User AuthContext 校验：匿名 401、Tenant 不匹配 403；WMTS 错误是 XML，XYZ / OGC Tiles 错误是 JSON。服务状态、协议开关和图层 enabled 的统一阻断仍按架构专题保留为未决，不因保存成功就宣称生效。
- 不存在的服务或图层核对 404；XYZ 的非法 y.format 或不可解析整数核对 400；OGC Tiles 不支持的矩阵集核对 400。数值越界的处理依动态/静态读取路径，不将旧“所有 z 超过 22 均返回 400”的示例当统一契约。
- PNG/JPEG 响应类型映射不代表栅格渲染已实现；TMS、WMS GetMap 和高级样式也不凭配置或计划计入当前发布能力。若接入这些能力，先补 owner 契约与实现，再补对应验收。
