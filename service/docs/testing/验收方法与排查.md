## 标准入口与证据

| 范围 | 标准入口或方法 | 证据边界 |
| --- | --- | --- |
| 当前工作区变更 | `make test-changed` | 按真实改动选择受影响 owner，未运行不计通过。 |
| Service T0–T3 | `make test-module MODULE=service` | 按现有登记发现语言、前端与基础设施门禁；缺条件不伪装通过。 |
| 前端确定性/构建 | `make test-service-frontend` | 不替代真实 Gateway、上游或浏览器整链路。 |
| Service PostgreSQL T2 | `make test-service-postgres` | 须提供安全的 `SERVICE_POSTGRES_TEST_DSN`；实际选择与未覆盖项见[迁移与持久化覆盖](#迁移与持久化覆盖)。 |
| 跨模块真实链路 | 已登记的 `make test-online ONLINE_SUITE=...` | 先选规范中实际存在且匹配范围的 suite；手工 HTTP 探查不另建旁路门禁。 |

手工样例用于受控环境的协议检查和排查，不能替代根入口。报告分别写明源码版本、部署/测试身份、资源与契约版本、执行命令、结果及未运行项；示例中的期望不是本次通过证据。注册页面和离页保护范围见[管理界面专题](../architecture/管理界面与模块协作.md#注册页面交互与验收)。

证据按实际断言分层：Service/Repository 夹具证明所测业务、Tenant 与错误分支；PostgreSQL 门禁证明所测数据库约束及写入结果；页面 HTTP 拦截夹具证明交互。受控上游不覆盖真实上游或正式调度，Backend 直连不覆盖 Gateway、页面及公开 HTTPS。完整链路须另有匹配来源与身份的运行证据，结果判定沿[统一验收边界](../API测试指南.md#能力与验收边界)。

## 迁移与持久化覆盖

标准入口为上表的 `make test-service-postgres`；[门禁脚本](../../../scripts/test/service-postgres-gate.sh)按测试名称选择用例，并拒绝出现 `SKIP`。缺少 DSN 直接失败，普通 Go T1 运行时因缺少 DSN 跳过的集成用例不计为 T2 通过。本地非 IAM Service 测试使用 `addp_test`，实际端口、安全连接和隔离规则沿[Infra 测试库说明](../../../scripts/infra/docs/PostgreSQL与测试库.md#postgresql-database-清单)；门禁不创建测试 database，也不连接开发业务库。

上述用例在外层事务内重建测试 schema 或构造记录并回滚，部分迁移方法使用内层事务；这不证明正式启动迁移具有整体原子性，也不覆盖提交后重启、崩溃恢复或任意历史库的完整升级。现行调用顺序、独立保护投影账本及历史 SQL 用途只由[迁移说明](../migrations/README.md)维护。

当前所选用例未逐项断言注册/瓦片服务名的跨 Tenant 唯一范围、瓦片图层同服务唯一性及父删除级联，也不审计全部索引、外键或账本内容。声明差异和待确认项统一见[历史 SQL 与数据库约束](../migrations/README.md#历史-sql-与数据库约束)，不能以夹具 AutoMigrate 成功或其他约束断言替代。保护相关用例与存储初始化也不能替代投影同步及真实请求验收；结果按[标准入口与证据](#标准入口与证据)分别记录未覆盖、未运行、失败和跳过项。

## 图查询服务验收入口

GraphQueryService 的路由与对象按[模块契约](../../CLAUDE.md#核心-api)维护。它使用 shape/cypher 配置、`parameters/page/page_size` 和表格/图结果，不套用 REST Query 的 cursor、输出契约或 API Consumer 验收结论；各引擎、配置与客户端组合分别验证。

| 核对范围 | 图查询独有约束 |
| --- | --- |
| 管理与执行 | 管理入口 `/api/v1/service/graph` 使用 Bearer Tenant AuthContext 和精确 `service.definition.*` Permission；Service/Gateway 的执行入口为 `POST /api/gquery/:serviceName`，不拼接管理前缀。 |
| DTO 与页面 | DTO 的 `endpoints.execute` 由启动注入的 `cfg.GatewayURL` 生成；[详情页](../../frontend/src/views/GraphQueryServiceDetail.vue)据它展示端点和 curl，[图查询客户端](../../frontend/src/api/graphQueryService.js)则复用空基址执行客户端请求页面同源路径。两种地址分别验收，展示或复制成功不证明可执行。 |
| 认证与保护 | 匿名须有 `public_access=true`；携带 Tenant 身份时，即使公开也须属于服务 Tenant，并检查 active 状态。当前[保护门禁](../../backend/internal/protection/gate.go)使用 `BeginUnresolvedRead`，投影不明或该 Tenant 存在纳管目标即拒绝。它未接入 REST Query 的 API Consumer Grant 和 `service_execute`，错误分类不能套用其稳定码及 403 断言。 |

确定性验证沿[标准入口](#标准入口与证据)：[管理租户测试](../../backend/internal/api/management_tenant_authorization_test.go)覆盖 SQLite/注入 AuthContext 下的部分管理操作；[DTO 路由回归](../../backend/internal/api/graph_query_execution_test.go)覆盖生成地址、认证/Tenant/状态/保护及旧路径不存在；[客户端回归](../../frontend/tests/graphQueryExecution.test.js)覆盖请求体、Bearer 装配和错误传播。这些夹具及其他 REST/Graph、构建、导航或 PostgreSQL 门禁均不能代替真实 System → Gateway → 图引擎与页面验收。完整链路沿现有 `graph-protection` Neo4j Hosted profile，场景与隔离要求统一见[图保护验收](../../../docs/spec/testing/scenarios/数据保护.md#graph-protection)。

有效证据：[2026-10-24 Neo4j Hosted 验收](https://github.com/pampa0629/addp/actions/runs/40050967852)，源码 `6621748b0`。两个不同非默认 Tenant 的普通 User 均仅有 `service.definition.read`，实际覆盖为：

- 本租户页面及 DTO 原始 HTTP 地址：未纳管时返回准确 3 行，纳管后均为当前 500 保护拒绝且无输出；公开匿名遵循相同取数/保护结果，私有匿名、无效 Bearer、停用及旧路径拒绝通过。

- 清理：业务资源剩余 0、清理错误 0，应用、合成图和 Infra 容器/网络/卷零残留。

[官方工件](https://github.com/pampa0629/addp/actions/runs/40050967852/artifacts/12544471651)保留 `service-graph-*-browser.json` 与截图、`graph-protection.json`、`online-report.json` 和 `summary.txt`。上述结论仅适用于该源码与场景；公开 HTTPS、外租户页面交互及 FalkorDB Service 目标图仍未验收。

### HTTPS 与 DTO 原始地址核对

先按[公共准备](../API测试指南.md#公共准备)确认入口与身份，部署须满足[专用环境规则](../../../docs/spec/testing/T4-Online验收规范.md#专用环境)。以下是待验方法，不是通过记录；临时 CA 结果不能外推公网 DNS、公共 CA 信任或生产证书续期。

| 核对项 | 必需断言与证据 |
| --- | --- |
| 证书与代理 | 按[HTTPS 部署说明](../../../nginx/README.md#https-配置)核对上级 TLS 代理 → 根 Nginx → Gateway → Service 的页面、iframe 构建资源及查询路径。客户端须验证信任链、SAN 和有效期，记录指纹、签发者与到期时间，不使用 `-k` 或 `ignoreHTTPSErrors`；证书不可信或主机名不匹配时不得发送凭据，也不接受降级或跳转到未批准 origin。根 Nginx 将 `X-Forwarded-Proto` 写为自身 scheme，不能据客户端 Header 推定后端所见协议。 |
| DTO 原始地址 | 确认 `endpoints.execute` 等于批准的 HTTPS origin 加执行路径，再原样请求；替换 host、scheme、端口或路径后成功不算原始地址通过。当前根 Compose 未向 Service 注入 `GATEWAY_URL`，默认 `http://localhost:8000`，仅设置 `ADDP_PUBLIC_ORIGIN` 不能证明 DTO 正确。 |
| 身份、状态与保护 | 复核上表全部身份、私有/公开、停用及纳管前后断言：私有匿名/无效 Bearer 为 401，外租户私有/公开均 404。两个入口都须有准确取数或无输出拒绝的证据，页面清除旧结果，不用管理员、匿名或 Backend 直连绕过门禁。System 生产 Cookie 约束沿[认证规范](../../../docs/spec/addp登录认证的统一要求.md#21-refresh-token)，其 Secure 取决于 `ENV=production`，上级 HTTPS 不会自动切换该模式。 |
| 证据与清理 | 分别保存页面 URL、原始 DTO、证书检查、身份/状态响应和 owner 清理回执，禁止归档凭据或私钥；核验业务资源、临时代理、证书私钥及基础设施的清理。TLS 握手不替代业务通过，未执行、失败、跳过和未覆盖项分别记录。 |

## 性能测量

在隔离且明确允许负载的部署中，分别测 REST Query、Features、动态瓦片、静态 PMTiles 和已接通代理，共用以下要求；取瓦片成功不等于编码和地图正确。

| 记录或评估项 | 通用要求 |
| --- | --- |
| 复现与负载 | 记录代码/部署及工具版本、拓扑、硬件、来源引擎、数据规模、字段/几何复杂度、响应行数/字节、并发、请求数/持续时间、预热与重复轮次；不保存 Token 或明文连接。 |
| 结果判定 | 结合业务断言与状态码区分成功、401/403、429、5xx、超时及零结果；HTTP 失败、超时或保护拒绝不计成功吞吐量，结果错误的 200 不计通过。 |
| 延迟与资源 | 保存原始报告及吞吐量、P50/P95/P99、错误率、源查询/连接等待、CPU/内存和网络字节。 |
| 优化对照 | 同一数据、版本、请求、权限与负载下逐项比较，区分缓存冷/热、失效及源变化；记录代价与结果正确性，不预先承诺固定提升幅度。 |

测量沿[标准入口](#标准入口与证据)使用现有能力；新增持续压测须确认 owner、夹具、数据边界和清理后登记，不向个人开发或业务库施压。本页不新增通用压测入口。门槛依据验收目标与可复现证据制定，单元/集成通过不代替性能通过；[Query 历史样本](../查询服务并发性能测试.md)、示例并发、页大小及缓存耗时不构成当前阈值或容量承诺。

## Query 专项测量与优化评估

通用记录与判定沿[性能测量](#性能测量)，另核对：

- 使用实际 Gateway/owner 路由，区分管理面、匿名、User Bearer 与 API Consumer，记录认证、授权和数据保护成本、服务契约版本及查询字段/过滤/排序/格式。
- 分别测首屏、真实 cursor 后续页及有界导出，不伪造 offset；页大小受服务契约约束。
- 数据库统计注明实例、库、采样区间和差分口径，不将累计命中率归因于某服务。

索引与统计信息按真实来源、执行计划和字段选择性核对，空间字段名、业务 schema 及数据库类型不能硬编码；涉及执行型计划分析时，确认资源范围和允许负载。连接池、超时、并发和告警阈值按实际瓶颈与验收目标确定，不直接套用历史样本数值。

结果缓存、预热、压缩、读写分离与分片只保留为有证据后评估的方向。缓存须先明确 Tenant/身份、授权和数据保护、服务契约/参数/过滤/排序/cursor、数据更新与撤权失效边界，不能只以服务名和页号作键；压缩核对完整路径实际编码与 CPU/网络成本。读写分离和分片涉及一致性及来源绑定，须先按架构规则确认，不在性能文档中直接宣布实施。

## 失败定位

| 现象 | 检查顺序 |
| --- | --- |
| 启动迁移失败 | 先记录源码/部署版本、目标库/schema 和首个迁移错误，沿[当前入口](../migrations/README.md#当前入口)定位失败阶段，再只读核对已落库结构、数据和对应账本。各阶段无共同事务，后续失败不代表此前变更已回滚；不按历史 SQL 文件顺序补跑或回滚。验证沿[迁移与持久化覆盖](#迁移与持久化覆盖)，结构迁移、数据迁移与接口验收分别判定，未覆盖或未执行不计通过。 |
| 404 | 先区分 Router 未挂载、资源不存在与 Tenant 隔离；核对入口 origin、程序标识和真实路径。Features 的 collection 列表元素不等于已挂载详情路由。 |
| 身份认证或执行授权拒绝（401/403） | 先辨认管理、查询执行或注册代理入口，再按[查询身份契约](../architecture/查询发布与执行.md#身份授权与资源限制)分开核对 User AuthContext、Tenant、精确 Permission 与 API Consumer Grant。注册代理的[上游拒绝与消费授权边界](注册服务与代理.md#代理读取与错误)单独核对，不把上游 401/403 当作 ADDP 管理认证结果。 |
| 查询角色资格拒绝 | 核对 403 / `query_protection_roles_unavailable`：当前调用者的角色资格无法确认或不满足所选方式，沿[角色选择契约](../architecture/查询发布与执行.md#登录用户的角色脱敏选择)核对当前第一方 User、同 Tenant 与有效角色，不借用发布人或管理员身份；与选择本身失效的 409 分别定位。 v27/v28 的会话差异、恢复清理和未运行边界见[角色资格场景接入](查询与要素协议.md#角色资格场景的隔离套件接入)。 |
| 查询通用数据保护拒绝 | 核对 403 / `data_protection_required`，按[权限与失败用例](查询与要素协议.md#权限与失败用例)检查源数据保护门禁；此码用于未命中角色专用错误的通用拒绝，不代表所有 403。Provider 类型化查询错误或 SQLSTATE 保持查询失败分类，不仅凭错误文案判断；拒绝响应不得返回数据或底层敏感错误。 |
| 查询角色选择失效 | 核对 409 / `query_protection_choice_invalid`，按[权限与失败用例](查询与要素协议.md#权限与失败用例)检查已保存的非空选择是否因方式撤销、修订变化或来源/字段不匹配而不可用。恢复沿[角色选择契约](../architecture/查询发布与执行.md#登录用户的角色脱敏选择)：主动移除选择并保存才恢复默认，不自动清除或降级；只重载管理版本不能修复失效选择。 |
| 查询管理版本冲突 | 核对 409 / `resource_version_conflict`：管理写操作携带的 `version` 已陈旧，冲突不得产生副作用。按[版本、并发与消费绑定](../architecture/指标来源与版本.md#版本并发与消费绑定)保留本地输入，由用户主动重新加载后再操作，不自动重试或静默换用最新版本；管理 `version` 与消费 `service_version` 分别维护。 |
| 501 | 核对 REST / Features 的协议开关和实际 Handler；不要把未实现端点的 404 与协议禁用混为一谈。 |
| 500/502/503 | 核对 Ready/注册状态、来源引擎和依赖、数据库/上游、真实错误分支；先保存状态与脱敏上下文，不仅凭英文消息推断原因。 |
| HTTP 成功但响应截断 | 按[完整性核对](注册服务与代理.md#请求与响应完整性核对)比对上游与客户端实际内容，再查超时、截断或断开。HTTP 200 或完成日志不证明完整接收，已发送响应后不保证完整 502；编码口径、混合错误正文及未验证项沿专题留证。 |
| 要素缺失或几何错误 | 核对发布快照中的字段、几何列、类型、CRS 与真实 Provider 结果；不固定使用 geom 或要求所有来源都调用 PostGIS 函数。 |
| 地图空白 | 检查载荷编码、MVT 内部图层、空间范围、缩放与行列；空 PMTiles 瓦片可为 200，不把所有空白归为 204。 |
| 客户端发现成功但不能取数 | 按[Features 公开入口核对](查询与要素协议.md#元数据链接与公开入口核对)或[瓦片公开入口核对](瓦片协议.md#元数据链接与公开入口核对)，依次检查原始响应链接、部署 origin/scheme、代理路由、认证和实际数据读取；直连或改写链接后成功不能替代公开 HTTPS 与原始链接验收，元数据发现成功不等于客户端端到端兼容。 |
| 原始端点可打开，但浏览器读取失败 | 按[浏览器直连核对](注册服务与代理.md#原始端点与浏览器直连核对)依次查实际 origin、上游身份、方法/Header 与 CORS。平台登录或已保存认证不表示浏览器取得上游身份；地址栏、curl 或后端成功不替代浏览器验收，凭据保护及直连/代理结果沿专题分别记录。 |
| 编译预览成功但未取数 | 按[执行查询预览](../architecture/指标来源与版本.md#执行查询预览)区分只读编译与数据测试；真实请求及 User 身份按[REST 页面预览](查询与要素协议.md#rest-测试按钮与页面预览)核对，两者分别验收。 |
| 查询正常但血缘为空 | 先按[发布血缘同步边界](../architecture/查询发布与执行.md#发布血缘同步边界)核对实际来源覆盖和页面归属，再查 Meta 请求、Tenant/权限、服务状态、发布身份、投递重试与当前投影。查询成功、重放运行或空图不代替完整链路验收；未接通与未验证分别记录。 |

403/409 按状态与稳定码分别定位，不解析本地化错误正文。角色资格与通用保护 403 的确定性断言、未覆盖范围见[权限与失败用例](查询与要素协议.md#权限与失败用例)；[旧游标撤销本地证据](查询与要素协议.md#角色方式撤销后的旧游标本地验收)仅证明所列源码、临时方式、当前用户及原生 MySQL 单表 JSON/CSV 的 409 拒绝、恢复与清理，不覆盖成员资格撤销、自然到期、其他身份/来源/协议或 Hosted，也不替代 403 或管理版本冲突验收。管理版本的确定性断言见[迁移与持久化覆盖](#迁移与持久化覆盖)，不替代真实并发部署；用例存在不等于本轮已运行，未执行、失败及未覆盖项按[标准入口与证据](#标准入口与证据)分别记录，不计通过。

运行日志的可信实例、查询权限、结构化字段及路径沿[运行日志规范](../../../docs/spec/addp模块服务运行日志规范.md)和[故障排查指南](../../../docs/guide/addp常见故障排查.md)核对；不把固定 `logs/service-backend.log` 当作所有部署的唯一来源，不把应用日志当正式审计。

遇到服务未启动或需要重启，使用标准生命周期流程，由用户在自己的终端按模块执行；本指南的测试命令不接管个人运行环境。接口实现变更应按[Swagger 规范](../../../docs/spec/addp-Swagger集成指南.md)同步生成和路由覆盖。
