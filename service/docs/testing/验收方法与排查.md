# Service 验收方法与排查

[返回 API 测试指南](../API测试指南.md)

本页保留协议互通、错误排查和性能测量的方法，不把样例请求成功当作整模块验收。测试分层与根 Make 入口沿[平台规范](../../../docs/spec/addp测试与验收规范.md)。

## 标准入口与证据

| 范围 | 标准入口或方法 | 证据边界 |
| --- | --- | --- |
| 当前工作区变更 | `make test-changed` | 按真实改动选择受影响 owner，未运行不计通过。 |
| Service T0–T3 | `make test-module MODULE=service` | 按现有登记发现语言、前端与基础设施门禁；缺条件不伪装通过。 |
| 前端确定性/构建 | `make test-service-frontend` | 不替代真实 Gateway、上游或浏览器整链路。 |
| Service PostgreSQL | `make test-service-postgres` | 使用标准隔离库与清理流程，不临时创建额外 database。 |
| 跨模块真实链路 | 已登记的 `make test-online ONLINE_SUITE=...` | 先选规范中实际存在且匹配范围的 suite；手工 HTTP 探查不另建旁路门禁。 |

手工样例用于受控环境的协议检查和排查，不能替代根入口。报告分别写明源码版本、部署/测试身份、资源与契约版本、执行命令、结果及未运行项；示例中的期望不是本次通过证据。注册页面和离页保护范围见[管理界面专题](../architecture/管理界面与模块协作.md#注册页面交互与验收)。

## 客户端互通

- Postman 等请求工具按本指南的当前路由、请求体和认证变量组织用例，不复制旧入口或把敏感凭据存入共享集合。
- GIS 客户端连接 OGC Features 的实际 Landing Page，记录客户端版本、集合发现、空间范围/CRS、分页、要素与私有服务认证结果；当前缺少独立 collection 详情入口，不能承诺任意客户端已兼容。
- WFS 客户端互通需等待 ADDP 发布入口接通；第三方 WFS 注册解析和外部代理不是该证明。
- Web 地图沿现有前端预览使用真实 ResourceURL、内部 MVT 图层名、范围与缩放配置，分别检查元数据、瓦片载荷和浏览器显示。Mapbox GL / OpenLayers 等客户端记录实际版本，认证使用共享 AuthSession，不另行持久化令牌。

## 性能测量

在明确隔离、数据来源和允许负载的验收部署中，分别测 REST Query、Features、动态瓦片、静态 PMTiles 和已接通代理。记录数据规模/字段/几何复杂度、来源引擎、响应行数/字节、并发、持续时间、错误率和延迟分布；有缓存时区分冷、热、失效与源变化。HTTP 失败或保护拒绝不能计作成功吞吐量，取瓦片成功也不能推导编码和地图结果正确。

使用已登记标准入口及其现有测量能力；若需要新的持续压测，先确认 owner、夹具、数据边界和清理，再纳入标准入口。吞吐量与延迟门槛应来自明确的验收目标和测量证据，示例并发/次数、缓存耗时不作验收阈值或平台承诺。[Query 历史样本](../查询服务并发性能测试.md)仅供追溯，不能作为当前性能验收结论。

## Query 专项测量与优化评估

先按当前发布契约验证结果正确，再开展负载测量。使用实际 Gateway/owner 路由与测试身份，记录认证、授权和数据保护成本；管理面测试、匿名、User Bearer 与 API Consumer 请求分别标识，不混为同一条消费路径。

| 记录或评估项 | 最小要求 |
| --- | --- |
| 可复现条件 | 代码/部署版本、工具版本、运行拓扑、硬件、来源引擎、服务契约版本、查询字段/过滤/排序/格式、响应行数和字节；不保存 Token 或明文连接。 |
| 负载与分页 | 记录并发、请求数/持续时间、预热与重复轮次。分别测首屏、沿真实 cursor 的后续页和有界导出，不伪造 offset；页大小受服务契约约束。 |
| 成功与拒绝 | 结合业务断言与状态码区分成功、401/403、429、5xx、超时及零结果。限流拒绝和认证失败不算成功吞吐量，结果错误的 200 也不算通过。 |
| 延迟与资源 | 保存原始报告及吞吐量、P50/P95/P99、错误率、源查询/连接等待、CPU/内存、网络字节；数据库统计明确实例、库、采样区间和差分口径，不将累计命中率直接归因于某服务。 |
| 优化对照 | 在同一数据、版本、查询、权限与负载条件下逐项比较，区分冷/热及缓存失效；记录代价与结果正确性，不预先承诺固定提升幅度。 |

索引与统计信息按真实来源、执行计划和字段选择性核对，空间字段名、业务 schema 及数据库类型不能硬编码；涉及执行型计划分析时，确认资源范围和允许负载。连接池、超时、并发和告警阈值按实际瓶颈与验收目标确定，不直接套用历史样本数值。

结果缓存、预热、压缩、读写分离与分片只保留为有证据后评估的方向。缓存须先明确 Tenant/身份、授权和数据保护、服务契约/参数/过滤/排序/cursor、数据更新与撤权失效边界，不能只以服务名和页号作键；压缩核对完整路径实际编码与 CPU/网络成本。读写分离和分片涉及一致性及来源绑定，须先按架构规则确认，不在性能文档中直接宣布实施。

本指南没有新增通用压测入口。新测量沿现有标准门禁及其能力执行；缺少适用的持续负载能力时先明确需求和登记范围，不直接向个人开发或业务库施压，也不把单元/集成通过当作性能通过。

## 失败定位

| 现象 | 检查顺序 |
| --- | --- |
| 404 | 先区分 Router 未挂载、资源不存在与 Tenant 隔离；核对入口 origin、程序标识和真实路径。Features 的 collection 列表元素不等于已挂载详情路由。 |
| 401/403 | 分开看 User AuthContext、Tenant、精确 Permission、API Consumer Grant 和源数据保护；注册代理不继承管理面的校验。 |
| 501 | 核对 REST / Features 的协议开关和实际 Handler；不要把未实现端点的 404 与协议禁用混为一谈。 |
| 500/502/503 | 核对 Ready/注册状态、来源引擎和依赖、数据库/上游、真实错误分支；先保存状态与脱敏上下文，不仅凭英文消息推断原因。 |
| 要素缺失或几何错误 | 核对发布快照中的字段、几何列、类型、CRS 与真实 Provider 结果；不固定使用 geom 或要求所有来源都调用 PostGIS 函数。 |
| 地图空白 | 检查载荷编码、MVT 内部图层、空间范围、缩放与行列；空 PMTiles 瓦片可为 200，不把所有空白归为 204。 |
| 客户端发现成功但不能取数 | 检查响应链接、部署 origin/scheme、路由、认证和实际数据读取；元数据成功不等于端到端兼容。 |
| 查询正常但血缘为空 | 先按[发布血缘同步边界](../architecture/查询发布与执行.md#发布血缘同步边界)核对来源与页面：当前仅同步具备源 item 身份和依赖摘要的快照，正常覆盖表来源；SQL/联邦 SQL/analytical 不据执行成功视为已同步。查看器在 `PublishedServiceDetail`，主查询详情 `QueryServiceDetail` 尚未集成。再核对实际 Meta 请求、Tenant/权限、服务状态、发布身份、投递重试及当前投影；查询成功、重放运行或空图不代替 Service → Meta → 页面完整链路验收，未接通与未验证项分别记录。 |

运行日志的可信实例、查询权限、结构化字段及路径沿[运行日志规范](../../../docs/spec/addp模块服务运行日志规范.md)和[故障排查指南](../../../docs/guide/addp常见故障排查.md)核对；不把固定 `logs/service-backend.log` 当作所有部署的唯一来源，不把应用日志当正式审计。

遇到服务未启动或需要重启，使用标准生命周期流程，由用户在自己的终端按模块执行；本指南的测试命令不接管个人运行环境。接口实现变更应按[Swagger 规范](../../../docs/spec/addp-Swagger集成指南.md)同步生成和路由覆盖。
