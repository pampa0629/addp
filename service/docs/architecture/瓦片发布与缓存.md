# Service 瓦片发布与缓存

[返回核心概念与架构](../service核心概念和架构设计.md)

说明动态 MVT、业务 PMTiles、协议入口及动态缓存边界；三维场景不合并进二维瓦片服务。

## 动态与静态来源

### 定位

瓦片服务发布多图层二维地图；当前动态图层生成 MVT，静态图层读取已识别的业务 PMTiles。协议与文件编码分别表达，栅格动态渲染仍需独立接入。

### 图层类型

**动态图层 (layer_type='dynamic')**

- 数据源：前端通过 ResourceLocator 选择空间表并使用 Meta 事实检测；当前后端动态配置要求 `source.engine_id/schema/table/geometry_column/srid`，不把 Locator 输入本身当作已完成的后端来源校验。
- 工作原理：实时查询数据库生成瓦片
- 支持格式：MVT（矢量）
- 缓存策略：可选启用瓦片缓存到 MinIO

**静态图层 (layer_type='static')**

- 数据源：通过资源树选择 Business 存储中 `data_type=media + format=pmtiles + layout=single` 的业务 item
- 工作原理：发布时由 Meta 校验 item 并冻结 PMTiles v3 header 摘要、层级、范围和源指纹快照；请求时通过 System engine provider Range Read 业务 PMTiles
- 支持格式：PMTiles v3 + gzip MVT；由 Meta 自动识别，不在表单中手工指定
- 地图初始视角：必须优先按发布快照中的 `capabilities.spatial.extent` 全幅显示数据，并使用 PMTiles 层级范围约束交互；范围不可用时才回退到 `center`，不得硬编码某个地区
- 空瓦片：合法坐标在 PMTiles 中没有目录项时返回 gzip 编码的空 MVT 和 HTTP 200；存储读取或归档校验失败仍返回错误
- 禁止输入裸存储路径、URL 模板或 Manager infra `storage_ref`

## 格式与协议

格式、容器与协议分别描述：

- 格式：当前接入 MVT；静态容器为 PMTiles v3 + gzip MVT。PNG/JPEG 的动态渲染不计作现有能力。
- 协议：当前 Router 挂载 XYZ、WMTS 与 OGC Tiles；TMS 配置键和界面选项仍存在，但没有对应公开路由。
- 动态 MVT 与静态 PMTiles 分别维护来源和执行边界，配置可见不等于真实读取、保护与发布链路均已验收。

## 动态缓存与过期边界

动态请求读取 `layer_config.cache.enabled` 与 `ttl`。启用后先尝试读取 MinIO 缓存，未命中再生成 MVT，并异步写入 gzip 缓存；读取和缓存写入必须保持现有数据保护的在途读取及失效屏障。

当前启动装配使用 infra MinIO 的 `service` bucket、`tiles` 前缀。对象路径包含 Tenant、服务和图层身份：

```text
tiles/{tenant_id}/{service_id}/{layer_id}/cache/{z}/{x}/{y}.mvt.gz
```

写入方法把 `ttl` 和 `created_at` 保存为对象元数据，当前 `GetCachedTile` 读取方法没有据此判断过期，不能据配置或元数据承诺到期自动重新生成。缓存新鲜度、失效与存储生命周期需要继续核对；静态业务 PMTiles 不走这条动态缓存路径。

内部存在清理图层/服务缓存的方法，Router 没有发布独立缓存 DELETE API。缓存清理能力以当前入口为准。当前删除图层/服务的业务方法仅调用 Repository，没有接通自动缓存清理；不能据删除成功断言缓存已清空。页面调用路径与操作边界见[发布与管理](../tile-guide/发布与管理.md#详情与图层操作)。

## 管理与消费状态

多底图来源的可选范围及其与发布图层的关系仍需确认；当前动态表与业务 PMTiles 的接入不等于任意第三方底图都能直接发布，也不据此新增另一种来源或执行路线。

创建服务必须携带 `first_layer`；默认服务 SRID 是 3857，不覆盖真实源 SRID。图层的排序、字段和静态发布快照见[图层表说明](../tables/tile_service_layers表.md)。

当前公开入口对 public/private Tenant 做身份判断，数据读取还有来源保护门禁；但 XYZ 图层查找没有按 `enabled` 过滤，服务状态、协议开关和图层启用不能仅凭已保存配置视为统一有效的消费阻断。该执行资格与级联删除约束差异继续保留为待核对事项。
