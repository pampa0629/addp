# Service 瓦片发布与缓存

[返回核心概念与架构](../service核心概念和架构设计.md)

说明动态 MVT、业务 PMTiles、协议入口及动态缓存边界；三维场景不合并进二维瓦片服务。

## 动态与静态来源

### 定位

瓦片服务发布多图层二维地图；当前动态图层生成 MVT，静态图层读取已识别的业务 PMTiles。协议与文件编码分别表达，栅格动态渲染仍需独立接入。

### 图层类型

**动态图层 (layer_type='dynamic')**

- 数据源：前端通过 ResourceLocator 选择空间表并使用 Meta 事实检测；后端所需字段由[动态来源配置](../tables/tile_service_layers表.md#dynamic)维护，不把 Locator 输入本身当作已完成的后端来源校验。
- 工作原理：实时查询数据库生成瓦片
- 支持格式：MVT（矢量）
- 缓存策略：可选启用瓦片缓存到 MinIO

**静态图层 (layer_type='static')**

- 数据源：通过资源树选择 Business 存储中 `data_type=media + format=pmtiles + layout=single` 的业务 item
- 工作原理：发布时由 Meta 校验 item 并冻结 PMTiles v3 header 摘要、层级、范围和源指纹快照；请求时通过 System engine provider Range Read 业务 PMTiles
- 支持格式：PMTiles v3 + gzip MVT；由 Meta 自动识别，不在表单中手工指定
- 地图初始视角：按发布快照的有效范围全幅显示，缺失或无效时回退中心点；实际预览层级限制与来源覆盖须分别核对，见[范围与层级边界](#协议声明发布快照与数据覆盖)，不得硬编码某个地区
- 空瓦片：合法坐标在 PMTiles 中没有目录项时返回 gzip 编码的空 MVT 和 HTTP 200；存储读取或归档校验失败仍返回错误
- 禁止输入裸存储路径、URL 模板或 Manager infra `storage_ref`

## 格式与协议

格式、容器与协议分别描述：

- 格式：当前接入 MVT；静态容器为 PMTiles v3 + gzip MVT。PNG/JPEG 的动态渲染不计作现有能力。
- 协议：当前 Router 挂载 XYZ、WMTS 与 OGC Tiles；TMS 配置键和界面选项仍存在，但没有对应公开路由。
- 动态 MVT 与静态 PMTiles 分别维护来源和执行边界，配置可见不等于真实读取、保护与发布链路均已验收。

## 协议声明、发布快照与数据覆盖

三者使用不同事实，不能由元数据返回成功推导归档全范围、全层级均有数据：

| 层次与入口 | 当前事实 | 使用与验证边界 |
| --- | --- | --- |
| WMTS Capabilities | 固定声明 WebMercatorQuad 的 0–22 级矩阵，各图层 WGS84BoundingBox 固定为 `-180 -90` 到 `180 90`；ResourceURL 指向 XYZ 的 `{TileMatrix}/{TileCol}/{TileRow}.mvt` | 不是按每份 PMTiles 快照生成的覆盖范围或级别；当前没有独立 WMTS GetTile KVP 执行 |
| OGC Tiles 元数据与读取 | 矩阵集详情同样构造 WebMercatorQuad 的 0–22 级；tileset 列表给出图层与读取链接，没有从 PMTiles 快照投影实际范围/层级 | GetTile 只接受 WebMercatorQuad，按 tileMatrix/tileRow/tileCol 转为 XYZ 的 z/y/x；不支持的矩阵集在详情返回 404、读取返回 400。声明到 22 不等于所有读取路径统一拒绝更高层级 |
| PMTiles 发布快照 | 后端从 Meta 识别事实冻结 `source_snapshot.min_zoom/max_zoom/center/spatial.extent`、身份、指纹及 header_hash；当前发布校验要求 `0 ≤ min_zoom ≤ max_zoom ≤ 31`，空间范围为 EPSG:4326 | 这是发布时识别的归档摘要，不是全部目录项与要素分布的逐项验证；原始 Header/元数据、冻结字段与实际瓦片内容分别核对 |
| 实际静态读取 | XYZ 与 OGC Tiles 最终共用 StaticTileService；按快照层级处理，正常源读取路径经 Engine Provider Range Read 并比对当前 header_hash | 超出发布层级或归档没有对应目录项可返回 gzip 空 MVT 和 HTTP 200；格式、归档或存储错误仍按实际分支失败，不从固定矩阵或快照矩形断言每个坐标都有数据 |

服务访问链接的生成与公开入口沿[链接边界](#元数据链接与公开入口)核对。协议声明、身份/保护、载荷和客户端兼容性分别验收，具体源代码见[WMTS](../../backend/internal/api/wmts_handler.go)、[OGC Tiles](../../backend/internal/api/ogc_tiles_handler.go)、[静态发布](../../backend/internal/service/tile_static_source.go)与[读取](../../backend/internal/service/tile_static_service.go)。

当前 `tilePreviewConfig` 使用快照 `spatial.extent`、center 与层级，再交给共享 TilePreview：有效范围优先用于全幅显示，无效或缺失时回退中心/缩放，不以固定地区或 WMTS 全球框替代。预览辅助函数仍将 minZoom/maxZoom 限制在 0–22，与发布校验允许到 31 的范围不同；含 23–31 级的归档不能据此声明已完成全层级预览。全幅视角和快照外接范围也不表示框内每个位置都有要素，实际核对见[元数据与覆盖验证](../testing/瓦片协议.md#元数据快照与覆盖核对)。

## 元数据链接与公开入口

WMTS 的服务访问地址、ResourceURL，以及 OGC Tiles 的服务 links，当前均使用 `http://` 加 Service 收到的 `c.Request.Host`，再拼接 `/wmts`、`/tiles` 或 `/ogc/tiles` 根路径。Host 取决于实际到达 Service 的请求，不能从浏览器地址推断；这些 Handler 不读取 Origin、X-Forwarded-Proto、X-Forwarded-Host 或 ADDP_PUBLIC_ORIGIN 来生成链接，也不保留额外部署前缀。协议标准 URI 与这里的服务访问链接是不同用途。

生成地址与入口可达性分别核对：

| 访问入口 | 仓库当前路径 | 不能据此推导的结论 |
| --- | --- | --- |
| Service Backend | 直接挂载 WMTS、XYZ 与 OGC Tiles | Backend 返回元数据或瓦片，不证明同路径在公开 HTTPS 入口可达 |
| Gateway | [Router](../../../gateway/internal/router/router.go)挂载 `/wmts`、`/tiles`、`/ogc/tiles` 并代理到 Service；Service 收到的 Host 仍须按实际请求核对 | Gateway 有路由，不证明上级代理也转发这些路径，或生成地址已使用用户访问的 scheme、端口和前缀 |
| 根 Nginx 统一入口 | [现行配置](../../../nginx/nginx.conf)将 `/api/` 转发 Gateway，未单独转发上述协议根路径，它们落入指向 Console 的 `/` | 不能把根入口 HTTP 200 当作协议响应，也不能擅自给协议 URL 加 `/api` 后当作已挂载接口；当前路径差异仍属未闭合入口 |

公开 origin 按[配置规范](../../../docs/spec/configuration/环境变量参考.md#根目录-env)选择，HTTPS 终止与代理部署沿[Nginx 说明](../../../nginx/README.md#https-配置)。ADDP_PUBLIC_ORIGIN 不启用 TLS，也不会自动改写这些 Handler 的链接或补齐协议转发。额外路径前缀、Host/端口及转发头须逐跳检查，不将统一入口 HTTPS、请求携带转发头或配置了公开地址写成元数据链接已正确生成。

本节只记录当前生成与路由事实，不确定新增入口或地址生成方案。链接原文、公开入口响应与客户端实际访问按[公开入口验证](../testing/瓦片协议.md#元数据链接与公开入口核对)分别留证；通过直连或改写地址的测试不能替代原始元数据链接的验收。

## 动态缓存与过期边界

动态请求读取 `layer_config.cache.enabled` 与 `ttl`。启用后先尝试读取 MinIO 缓存，未命中再生成 MVT，并异步写入 gzip 缓存；读取和缓存写入必须保持现有数据保护的在途读取及失效屏障。

当前启动装配使用 infra MinIO 的 `service` bucket、`tiles` 前缀。对象路径包含 Tenant、服务和图层身份：

```text
tiles/{tenant_id}/{service_id}/{layer_id}/cache/{z}/{x}/{y}.mvt.gz
```

写入方法把 `ttl` 和 `created_at` 保存为对象元数据，当前 `GetCachedTile` 只检查对象、解压并读取数据，没有据此判断过期；TTL 保存不是过期执行，不承诺到期自动删除或重新生成。缓存新鲜度、失效与存储生命周期仍须分别核对；静态业务 PMTiles 不走这条动态缓存路径。

`X-Cache` 由 [XYZ Handler](../../backend/internal/api/tile_endpoint_handler.go)的 fromCache 分支生成，当前语义为：

| 读取路径 | 响应标记 | 实际含义与边界 |
| --- | --- | --- |
| 动态缓存读取成功且数据非空 | HIT | 本次使用动态缓存对象，不证明仍在 TTL 内或内容与当前源数据一致 |
| 动态缓存关闭、读取失败/为空而重新生成 | MISS | 本次走动态生成，不证明缓存对象不存在；启用缓存时仍须等待并核对异步写入，响应成功不保证已写入 |
| 静态 PMTiles 成功返回，包括合法空瓦片 | HIT | 当前静态读取分支直接设置该标记，不表示命中上述 infra MinIO 动态缓存，也不证明归档未变化 |

因此不能把所有 HIT 合并为动态缓存命中率，也不能仅凭 HIT/MISS 判定新鲜度、TTL 执行、写入完成或数据正确。缓存过期、源变化、发布依赖与数据保护失效是不同检查；[实际验收](../testing/瓦片协议.md#空瓦片缓存与访问)应对照读取类型、对象和响应内容留证。

内部 `ClearLayerCache/ClearServiceCache` 可删除相应前缀下的对象，但 Router 未挂载独立缓存 DELETE API；页面清缓存调用的相对路径 `/service/tile/{serviceId}/layers/{layerId}/cache` 没有对应正式入口，不能据按钮、提示或请求发出判断清理成功。`DeleteLayer/DeleteService` 业务方法仅调用 Repository，没有接通删除后的自动缓存清理；更新配置也不自动证明旧缓存已失效。

[数据保护派生数据清理器](../../backend/internal/service/protection_derived_data.go)已在[启动入口](../../backend/cmd/server/main.go)装配到投影确认屏障，按 Tenant 枚举瓦片服务并调用 ClearServiceCache；这是独立的安全清理路径，不能据此宣称页面手动清理或删除链路已接通。图层管理路径沿[表契约](../tables/tile_service_layers表.md#排序启用与管理)，页面、管理 API、对象清理与安全失效的证据分别按[验证说明](../testing/瓦片协议.md#图层操作与缓存清理核对)核对。

## 管理与消费状态

多底图来源的可选范围及其与发布图层的关系仍需确认；当前动态表与业务 PMTiles 的接入不等于任意第三方底图都能直接发布，也不据此新增另一种来源或执行路线。

首图层创建与默认 SRID 的保存规则见[服务表说明](../tables/tile_services表.md#服务图层与协议)；图层配置、排序及发布快照结构见[图层表说明](../tables/tile_service_layers表.md)。

当前公开入口对 public/private Tenant 做身份判断，数据读取还有来源保护门禁；但 XYZ 图层查找没有按 `enabled` 过滤，服务状态、协议开关和图层启用不能仅凭已保存配置视为统一有效的消费阻断。该执行资格仍待核对；[级联删除约束](../tables/tile_service_layers表.md#索引与约束)另按实际数据库验证。
