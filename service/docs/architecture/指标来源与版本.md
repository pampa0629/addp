# Service 指标来源与版本

[返回核心概念与架构](../service核心概念和架构设计.md)

区分 Model 修订、QueryService 管理并发版本、消费契约版本及不执行数据的查询预览。

页面操作见[查询服务创建与详情](管理界面与模块协作.md#查询服务创建与详情)，实际取数与认证见[查询与要素协议](../testing/查询与要素协议.md)；本页编译预览的独有约束及验证入口见[执行查询预览](#执行查询预览)，证据分层沿[标准入口](../testing/验收方法与排查.md#标准入口与证据)。

## 来源选择与发布

查询服务创建页提供物理表、SQL、已发布指标实现三种来源。仅进入指标来源选择页时，共享前端 Model Client SDK 才携带当前用户 Bearer 身份调用现有 Model 指标实现读取 API；只展示已发布修订，必须显式选择实现和修订，不默认选择最新版本。Model 不可用、无读取权限或列表为空时显示对应状态和重试入口；其他来源不发起 Model 请求，也不受其结果影响。退出选择页后的迟到响应不得覆盖后续选择。

提交仍只走 `POST /api/v1/service/query` 的 `config_type=analytical + metric_source {implementation_id, revision_id}`。前端列表只辅助选择；Service 通过已有 Go Model Client SDK 在创建时重新校验精确修订、依赖与计划，禁止提交引擎、SQL 或参数／输出覆盖。Service 不增加 Model 启动探测、数据库访问或模块内部导入，不新增指标发布代理接口。此入口与 Model 工作区发布使用同一创建链路。

验证入口为 `make test-common-frontend test-service-frontend test-model-frontend`；覆盖 SDK 路由、已发布修订投影、权限／不可用状态、过期响应隔离、精确修订提交及普通来源独立创建。

指标服务详情和编辑页的输出格式说明读取已保存的协议配置；编辑标题、描述等普通信息时不提交只读协议配置，避免把已有 JSON/CSV 服务意外收窄为新建表单的 JSON 默认值。此行为由 Service 前端提交回归测试覆盖。

## 版本、并发与消费绑定

`PUT /api/v1/service/query/:id/metric-source` 是查询服务切换到确定指标实现修订的唯一命令，使用 `service.definition.update`。服务详情页复用已发布指标修订选择器执行此命令，普通编辑页只修改服务基本信息；具备指标实现读取权限时才展示切换入口。请求只接受 `metric_source` 与正整数 `version`。QueryService 聚合根持久化非空 BIGINT 版本，创建为 1，存量迁移补齐为 1；普通编辑、启停、删除、刷新快照与重绑均携带同一版本，在租户范围内同一事务锁行、比较版本、写入并递增。不存在或其他租户资源返回 404；陈旧版本返回 409 / `resource_version_conflict`，不得产生副作用。删除和刷新快照使用请求体 `{ "version": 1 }`。管理 DTO 返回最新 `version`，不再提供定义指纹字段。

`service_version` 仍只表示计算消费契约，缺少依赖快照或稳定键时为空，继续供查询、游标与 Consumer Descriptor 使用。重绑保留服务 ID、编码、访问控制与启停状态；定义版本不授予执行权，停用服务不自动启用。详情页提供显式启用／停用操作；未绑定完整指标计划时不可启用，未启用时禁止数据测试并显示原因；不执行业务查询的编译预览仍可查看。版本冲突保留参数和本地输入，用户主动重新加载后再操作，不自动重试。切换计算来源会改变 Consumer Descriptor 指纹，Workbench 必须重新绑定并发布应用新修订。

指标查询每次通过 Model 验证绑定的精确修订与依赖，并校验当前引擎能力、本地 `CompilerIdentity`、请求参数和服务消费版本；撤回、依赖漂移或实现版本不匹配即拒绝，不选最新版。继续使用 `MODEL_URL` 与现有 Tenant Service Token 路径。

指标服务详情分开展示服务启停状态与绑定修订状态。复用共享 Model Client 对确切实现的读取，仅从绑定的修订 ID 解析修订号及 `draft|published|withdrawn` 当前状态；不取最新修订，不把 Service 的 `active` 当作可查询证明。已撤回明确提示新查询会被拒绝，已发布仍说明执行时必须校验依赖、引擎与权限；无 Model 读取权限、修订不存在和读取失败分别提示，不能伪装为已发布。支持显式刷新此只读状态，保留参数输入和服务配置；切换来源、权限变化及卸载后忽略迟到响应。此展示不授予执行权、不自动重绑或改变服务启停，实际查询继续由 Service 实时校验。普通表与 SQL 来源不发起该读取。验证沿用 Service 前端确定性测试、构建和已登记 CI 门禁。

## 执行查询预览

管理接口 `POST /api/v1/service/query/:id/execution-query` 接受既有 `QueryExecutionRequest`，要求当前租户的 `service.definition.read`，仅用于 analytical 来源。通过租户与 ID 读取服务，动态调用 Model Client SDK 验证绑定修订与依赖，再复用实际执行的中立结果计划包装与引擎编译路径；当前参数、结果筛选、排序、选择和游标均参与编译。返回语言、带占位符的查询文本、按计划声明顺序排列的类型化参数（值以规范文本或 null 表达，避免浏览器数字精度损失）、引擎名称/类型/ID、服务版本和指标实现/修订/结果种类。

预览不调用 PrepareQuery、Execute 或数据库 EXPLAIN，不执行业务数据查询，不证明运行权限、数据质量断言或真实查询已经通过；停用服务允许查看，来源缺失、撤回、依赖漂移和非法请求仍拒绝。响应仅投影上述字段，不含引擎连接配置，使用 Cache-Control: no-store。不在公开查询端点、Consumer Descriptor 或 Workbench 暴露原生查询，不保存生成 SQL 副本，也不允许编辑后执行。

详情页以“查看执行查询”折叠区按当前测试条件显式生成，参数变化或服务重载立即清除旧结果。数据测试与查询预览复用请求构造逻辑。验证使用 `make test-module MODULE=service`，并按涉及范围执行 Service 前端、PostgreSQL 集成与 Swagger 覆盖入口；校验编译器一致性、类型化参数、非法请求、Tenant 隔离和前端过期结果清除。
