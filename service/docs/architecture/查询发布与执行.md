## 查询服务与来源

### 定位

查询服务围绕一个确定的发布契约提供数据查询和有界导出。来源可以是一张表、一条普通或联邦 SQL，或一个已发布指标实现修订；联邦 SQL 不限定为单一 Source Engine。

### 三种来源

**方式一：界面配置（Table 模式）**

- 通过资源树选择器选择资源
- 自动检测空间字段（调用 Meta resource-tree / item 能力）
- 支持配置默认返回字段和可过滤字段
- 对外只接受结构化字段选择、类型化过滤、排序和游标分页，不接受 SQL 片段

**方式二：SQL 配置（SQL 模式）**

- 编写自定义 SQL 查询语句
- 可以声明强类型标量命名参数，并在 SQL 中使用 `:name`；命名参数只用于影响固定 SQL 内部计算，不用于动态表名、字段名或 SQL 片段
- 新建服务选择查询引擎时，默认 SQL 从该引擎当前业务 Catalog 中选择有数据的真实表生成；返回表单前必须通过同一只读执行链路以最多 10 行完成验证
- 默认 SQL 是不含 `LIMIT/OFFSET` 的基础查询，发布后由 Service 在外层统一追加分页；工作台样例中的展示行数限制不属于查询服务定义
- 手动指定空间字段配置
- 固定 SQL 只作为发布来源；对外查询仍通过输出契约上的结构化查询能力执行
- 发布前必须通过所选查询引擎真实检测输出契约；DuckDB 联邦 SQL 在完成授权和挂载后使用 Runtime describe 能力取得字段，发布者从实际输出字段中声明非空唯一稳定键
- 数据库协议无法无歧义表达业务类型时，由发布者在已检测字段集合上显式收敛最终类型，执行结果必须按冻结输出契约归一化后再参与 cursor 和协议渲染。例如 MySQL 把 `BOOLEAN` 暴露为 `TINYINT`，只有发布者明确声明为 `bool` 的字段才把 `0 | 1` 转为布尔值，普通 `TINYINT` 不得被全局猜测为布尔值
- 不支持客户端提交 SQL、WHERE、ORDER BY 或其他原生表达式

**已发布指标来源（analytical）**

`config_type=analytical` 以 `metric_source {implementation_id, revision_id}` 引用确定的 Model 发布修订，由 Service 复核依赖并冻结唯一分析计划包。不接收调用方补写 Engine、SQL、参数或输出契约。具体发布、重绑与只读预览见[指标来源与版本](指标来源与版本.md)。

不同来源形成统一消费契约：输出字段、空间信息、非空唯一稳定排序键、查询字段策略、资源限制、执行绑定和依赖快照。修改执行语义须显式更新契约；管理并发 `version` 与消费契约 `service_version` 分别维护，见[指标来源与版本](指标来源与版本.md#版本并发与消费绑定)。

### 发布时的引擎发现与可用性

- 发布表单每次进入或展开引擎选择器时，必须从 System/Meta 的当前状态重新发现候选，不得把模块启动时的结果作为长期缓存。
- 候选列表展示已注册、active 且能力匹配的实例；离线、未知或检测中的实例保留展示但禁选，只有 online 实例可建立新的发布绑定。
- 全套服务刚重启时，Gateway 可能在 Meta 或 System 完成服务注册前短暂返回 502/503/504。前端必须把它识别为暂态发现失败并在有界时间内自动重试，不得把失败响应解释成“当前没有引擎”。
- 发布接口和实际服务执行仍须按绑定的 Engine Instance 做实时可用性校验；前端状态只能改善交互，不能替代后端校验。

### 协议支持

**REST API（默认启用）**

- 端点：`POST /api/query/{serviceName}/query`
- 请求体：`parameters`、`select`、结构化 `filter`、`order_by`、`page.limit`、`page.cursor`、`format`；`parameters` 只接受服务发布契约中声明的命名参数
- 输出格式：JSON、CSV、GeoJSON（有空间字段时）
- JSON 查询结果的 `data` 始终为数组，无匹配记录返回 `[]`；预览发起新查询时清除上一查询结果，空结果或请求失败均不得继续展示上一查询的数据。

**OGC API Features（自动启用）**

- 后端在有已确认空间输出时默认启用，发布者可覆盖协议配置；没有空间输出时强制关闭。
- 端点：`/ogc/features/{serviceName}/collections/{collectionId}/items`
- 沿 OGC API Features 1.0 的 collections/items 资源结构提供访问。

## 身份授权与资源限制

管理 API 通过 System 验证当前 Tenant AuthContext 与精确 Permission，统一使用 opaque Token；认证规则见[登录认证要求](../../../docs/spec/addp登录认证的统一要求.md)及[API 认证授权规范](../../../docs/spec/api/认证授权.md)。业务模块不自行验用户 JWT，也不信任调用方提交的 Tenant Header。

REST Query 的最终授权在 Service：私有服务要求当前 User Tenant 与服务匹配并具备执行权限；携带 API Consumer Credential 时，无论服务是否公开，都再次验证凭据并核对 Consumer Tenant 和精确 `(query, service_id)` Grant。`public_access` 允许匿名进入对应公开执行路径，不免除服务状态、协议、源数据授权及数据保护校验，也不授予管理权限。其他协议与注册代理的接入边界分别按各自专题核对。

Consumer Catalog 位于需 Tenant AuthContext 的管理命名空间，当前读取要求 `service.data_read.execute` 与 Tenant 查询执行范围；它不是匿名公开目录。第三方应用代表用户访问私有服务时沿[统一 OAuth 规范](../../../docs/spec/addp%20OAuth授权规范.md)接入，不增加 Service 私有认证方案。

### 登录用户的角色脱敏选择

原生单表 QueryService 可在 `data_config.protection_choices` 保存字段角色方式，空数组表示字段默认保护。候选来自当前显式 DataItem locator、本人的当前有效角色和 Service 本地保护投影，表单复用共享 `FieldMaskingChoices`；保存的只是来源字段及 Security 选项身份／修订，不含角色快照或算法参数。保存、保留选择的更新和每次调用交付均复核资格；已有服务更新权限的用户可仅提交版本与 `status=inactive` 直接停用，保留原选择，不依赖角色方式仍有效；重新启用、携带其他配置的更新及实际调用仍严格核验，不自动清除选择或恢复默认。普通 SQL、联邦、对象表、指标的非空角色选择尚未接入，明确拒绝。

同一保存选择用于 REST 的 JSON／CSV／GeoJSON 和 OGC Features，仍由同一 PreparedQuery 的真实输出血缘证明所选字段。调用者必须是同 Tenant 的当前第一方登录用户，不能借用发布人或管理员身份；匿名、应用凭据和委托不取得角色资格。未配置选择的服务继续原默认链路，不新增本人角色服务依赖。选项撤销、修订变化或角色失效时明确拒绝，只有用户主动移除选择并保存才恢复默认。服务消费版本须包含保存的选择，防止旧绑定或 cursor 继续使用改变后的语义。AK/SK 与应用保护方式绑定暂不设计。

Query 的 `max_features` 是服务级单次返回行数上限，与 `page.limit` 一起约束结构化查询，不能替代请求频率或周期配额。Gateway 的现有限流按 API Consumer ID 对 Query 请求计分钟数，只在取得 API Consumer 上下文时执行；匿名和 User Bearer 请求、其他协议及注册代理不能据此视为已受同样限流。具体实现与部署边界见[Gateway 架构](../../../gateway/docs/gateway架构说明.md)及[限流中间件](../../../gateway/internal/middleware/rate_limiter.go)，新增覆盖范围仍见[后续能力清单](../service后续能力清单.md)。

## 执行绑定与依赖快照

- `config_type` 为 `table`、`sql`、`analytical`；普通编辑不任意切换来源，指标来源变更走唯一重绑命令。
- `engine_id`: 普通 SQL 或表服务的 Source Engine；联邦 SQL 必须为空。
- `runtime_engine_id`: 联邦 SQL 的 DuckDB Runtime Engine；Parquet 对象表同时保存 Source `engine_id` 和该字段；关系表必须为空。
- `data_config` 保存来源定位、执行所需依赖快照和字段策略，不复制完整 Meta attributes。analytical 的参数、输出和稳定键从冻结计划包只读投影。
- `dependency_hash`: 只计算字段、主键、空间字段/CRS、对象表执行描述符、联邦 Source Engine ID 和 SQL query hash；排除行数、大小、扫描时间、数据更新时间、extent 和空间索引状态。
- `verification_status`: 新发布或显式刷新的快照为 `verified`；一次性迁移的历史快照为 `unverifiable`，需通过管理动作重新检查或刷新。
- DuckDB 联邦 SQL 在发布时冻结查询实际引用的 Source Engine ID，并只保存实际引用的对象表映射；两者都纳入 `dependency_hash`。执行时按冻结 ID 从 System 获取当前连接配置，不在请求期按名称重新绑定 Engine，也不再调用 Meta；数据源绑定或对象表映射变化需要重新发布查询服务。
- 历史来源必须能从同 Tenant 的 Locator 和具有 fingerprint 的 Meta item 建立可靠身份；无法恢复确定依赖的记录按 owner 迁移处理，不伪造发布快照。
- 无法从历史配置恢复对象表依赖时，运行时不保留 Meta 动态解析或按名称重新绑定的兼容分支，须重新建立发布定义。
- `protocols`: 协议配置，默认启用 REST API
- `public_access` 表达公开设置。私有消费根据当前 User 或正式 APIConsumer Credential 的类型走 owner 授权；凭据不替代源数据和 Security 保护校验。

## 发布血缘同步边界

发布主体身份与 `serve` 关系沿[血缘规范](../../../docs/spec/addp数据血缘能力规范.md#42-服务发布事实)。当前 [QueryService 发布器](../../backend/internal/service/query_service_service.go)把快照 `dependency_hash` 用作 `published_revision`；这只是当前发布身份的取值，不等同于管理 `version` 或消费 `service_version`，也不代表已经收集完整来源。

- **实际覆盖**：发布器要求 Meta Client、`source_snapshot.source.item_id` 与非空依赖摘要；缺少时直接跳过。当前表来源（含对象表）按该身份同步 item 粒度依赖。SQL / 联邦 SQL 快照没有该单一 Source，analytical 仅持有指标引用和计划包，当前均不由此发布器生成 `serve` 边；联邦 Source Engine ID、指标计划绑定或执行保护使用的 ReadSet / OutputLineage 不等于 Meta 已持久化的发布血缘。
- **投递与状态**：符合条件的 active 服务发送一个源 item 依赖，非 active 服务发送空依赖。创建及显式表快照刷新调用发布器；Service 启动后及每分钟按主键分页重放现存记录，补齐名称并重试失败投递。通知同步人类可读的 `Title`（载荷 `service_name`）及 `UpdatedAt`（`service_updated_at`）。创建投递失败会返回错误并尝试删除刚创建的服务，刷新后投递失败则记日志等待重放，因此 Service 保存与 Meta 投影不能视为跨模块原子更新。
- **完整性与展示**：Meta 关闭旧版本的当前投影、保留历史观察，并按 owner 更新时间忽略过期通知；Service 拥有来源和发布事实。无法解析完整源 item 时不得用 hash 或 Engine ID 伪造边。现有 [PublishedServiceDetail](../../frontend/src/views/PublishedServiceDetail.vue)包含按服务 ID 和依赖摘要查询 Meta 的查看器，但主查询详情 [QueryServiceDetail](../../frontend/src/views/QueryServiceDetail.vue)尚未集成该查看器，不能笼统宣称查询服务页面已具备完整血缘展示。

发布使用现有 Meta 服务发布接口，仅接受 `addp-service` 和 `meta.lineage.create`，不得借用仅面向 Catalog 的 resolver 权限。确定性投递与关系行为由 Service T1、Meta T1 核对，血缘生命周期迁移由 Meta PostgreSQL 门禁覆盖；这些范围不能替代跨模块运行验收。

按[标准入口与证据](../testing/验收方法与排查.md#标准入口与证据)分别核对来源冻结、投递失败与重放、启停和版本变化后的当前投影、历史观察、Tenant/权限及真实页面查询。空图可能来自未同步、无当前依赖或页面未发起查询；模拟 Meta 的投递测试、HTTP 成功和服务查询成功都不代替完整 Service → Meta → 页面链路验收，未运行项单列为未验证。

## 统一执行契约

表、固定 SQL 和联邦 SQL 只区分来源与 Runtime，REST Query 与 OGC API Features 共用结构化查询计划；WFS 共享同一内核是规范要求，当前 Router 未挂载独立 WFS 路由。

统一约束：

- 避免 SQL 注入和协议层重复构造 SQL
- 统一字段策略、稳定排序键、游标、授权、配额和审计
- 让 OGC bbox、Feature ID 和 REST 过滤共享同一类型化谓词
- 查询默认读取 `limit + 1` 行判断下一页，不执行精确 `COUNT(*)`

## 命名参数展示与固定选项

命名参数可携带 `presentation: {labels, descriptions}`，两项均按 `zh-cn`、`en` 提供文本；名称最多 100 字符，说明最多 500 字符。它只表达展示，不改变参数名、类型或日期计算规则。指标参数由 Model 在发布时冻结，Service 管理 DTO 与 Consumer Descriptor 只读透传，展示内容纳入消费契约指纹。普通 SQL 参数保留发布者填写的 `description`，不得同时声明 `presentation` 与 `description`。

Service 与 Workbench 使用共享参数展示组件，按当前语言显示业务名称和说明；没有展示信息的参数显示其声明名称，不按参数名猜测业务含义。Workbench 自定义的组件标签仍属于应用配置，服务说明来自确定的 Consumer Descriptor。Model 新发布修订应提供完整展示信息；既有修订不追补文案，更新展示须显式发布、重绑。

命名参数可声明 `options`，每项为 `{value, labels: {"zh-cn": "显示名称", "en": "Display label"}}`。不声明或空集合表示无枚举限制；非空集合至多 100 项，值必须是与参数类型匹配的非空标量且不重复，每种内置语言名称均非空、至多 100 字符，不接受其他语言键。类型化值比较区分数字、布尔与字符串。必填性与默认值继续遵循原有规则，默认值及执行输入必须属于允许值集合。

完整选项集合（含所有语言名称）纳入发布签名和 Consumer Descriptor 指纹，语言切换只影响客户端显示。指标来源由 Model 编译计划声明，Service 冻结且禁止管理请求覆盖；普通 SQL 服务由发布者声明。消费者只能读取 `input_contract.named_parameters[].options`，不得按参数名推断选项或扩展取值。现有服务须显式重绑、应用须发布新修订，不自动改写历史快照。

## 活跃消费契约

启用 REST 的 Query Service 只有在完整消费契约校验通过后才能处于 `active`。输出字段、非空唯一稳定键或 REST 返回格式缺失时，创建、更新和状态恢复都必须拒绝；既有的不合规记录由版本化数据迁移一次性置为 `error`，不能让单条坏记录破坏整个 Service Consumer Catalog，也不能在目录分页后静默过滤。
