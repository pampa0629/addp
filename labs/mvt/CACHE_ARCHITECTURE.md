# MVT 缓存架构对比图

## 旧架构（v0.0.9）- 4 层缓存

```
浏览器请求: GET /tiles/buildings_test/14/13423/6403.mvt
       ↓
┌─────────────────────────────────────────────────────────┐
│ Gin Router + Singleflight 去重                          │
└─────────────────────────────────────────────────────────┘
       ↓
┌─────────────────────────────────────────────────────────┐
│ Tier 1: Memory LRU (2048 entries)                      │
│   - 响应时间：1-2ms                                      │
│   - 容量：~200MB                                         │
│   - 命中率：~30%                                         │
│   ✓ Hit → 直接返回                                      │
│   ✗ Miss → 查询 Tier 2                                  │
└─────────────────────────────────────────────────────────┘
       ↓ miss
┌─────────────────────────────────────────────────────────┐
│ Tier 2: Redis (独立 mvt-redis 容器)                    │
│   - 响应时间：3-10ms                                     │
│   - 端口：6379 (独立)                                    │
│   - 配置：maxmemory 2gb + allkeys-lru                   │
│   - TTL：24h                                            │
│   - 命中率：~50%                                         │
│   ✓ Hit → 回填 Memory → 返回                            │
│   ✗ Miss → 查询 Tier 3                                  │
└─────────────────────────────────────────────────────────┘
       ↓ miss
┌─────────────────────────────────────────────────────────┐
│ Tier 3: PostgreSQL mvt_cache 表 (business 库)          │
│   - 响应时间：10-50ms                                    │
│   - 表结构：mvt_cache (datasource, z, x, y, tile)       │
│   - 存储：BYTEA (gzipped MVT)                           │
│   - 索引：PRIMARY KEY (datasource, z, x, y)             │
│   - 命中率：~15%                                         │
│   ✓ Hit → 回填 Redis + Memory → 返回                    │
│   ✗ Miss → 实时生成 Tier 4                              │
└─────────────────────────────────────────────────────────┘
       ↓ miss
┌─────────────────────────────────────────────────────────┐
│ Tier 4: PostGIS 实时生成 (priorityDB 连接池)            │
│   - 响应时间：50-200ms                                   │
│   - SQL：ST_AsMVT() + 像素过滤                          │
│   - 连接池：50 conns (优先)                              │
│   - 生成后异步写入 Tier 1+2+3                           │
│   - 生成率：~5%                                          │
└─────────────────────────────────────────────────────────┘
       ↓
响应：application/vnd.mapbox-vector-tile (gzipped MVT)
Headers: X-Cache: memory|redis|postgres|MISS
```

**旧架构问题**：
1. ❌ PostgreSQL 膨胀（mvt_cache 表影响数据库性能）
2. ❌ 存储成本高（BYTEA 存储成本是对象存储的 50 倍）
3. ❌ Memory LRU 小（2048 entries，命中率仅 30%）

## 新架构（v0.1.0+）- 3 层缓存

```
浏览器请求: GET /tiles/buildings_test/14/13423/6403.mvt
       ↓
┌─────────────────────────────────────────────────────────┐
│ Gin Router + Singleflight 去重                          │
└─────────────────────────────────────────────────────────┘
       ↓
┌─────────────────────────────────────────────────────────┐
│ Tier 1: Memory LRU (8192 entries) ⬆️ 扩大 4 倍           │
│   - 响应时间：1-2ms                                      │
│   - 容量：~800MB                                         │
│   - 命中率：~50% ⬆️ 提升 20%                              │
│   ✓ Hit → 直接返回                                      │
│   ✗ Miss → 查询 Tier 2                                  │
└─────────────────────────────────────────────────────────┘
       ↓ miss
┌─────────────────────────────────────────────────────────┐
│ Tier 2: Redis (ADDP 系统 addp-redis) ♻️ 复用             │
│   - 响应时间：3-10ms                                     │
│   - 端口：6379 (ADDP 系统)                               │
│   - 密码：addp_redis                                    │
│   - 配置：maxmemory 2gb + allkeys-lru ✅ 自动驱逐        │
│   - TTL：24h                                            │
│   - 命中率：~35%                                         │
│   - 新瓦片进来 → 自动淘汰老瓦片 🔄                        │
│   ✓ Hit → 回填 Memory → 返回                            │
│   ✗ Miss → 查询 Tier 3                                  │
└─────────────────────────────────────────────────────────┘
       ↓ miss
┌─────────────────────────────────────────────────────────┐
│ Tier 3: MinIO 对象存储 (ADDP 系统 addp-minio) ♻️ 复用    │
│   - 响应时间：5-20ms ⚡ 比 PostgreSQL 快 2-5 倍          │
│   - 端点：localhost:9002 (ADDP 系统)                    │
│   - 认证：minioadmin / minioadmin                       │
│   - Bucket：addp-mvt-cache                              │
│   - 对象路径：{datasource}/z{z}/{x}_{y}.mvt.gz          │
│   - 示例：buildings_test/z14/13423_6403.mvt.gz          │
│   - 存储：完全持久化 ✅ 重启不丢失                        │
│   - 容量：无限（仅受磁盘限制）                            │
│   - 命中率：~10%                                         │
│   ✓ Hit → 回填 Redis + Memory → 返回                    │
│   ✗ Miss → 实时生成 Tier 4                              │
└─────────────────────────────────────────────────────────┘
       ↓ miss
┌─────────────────────────────────────────────────────────┐
│ Tier 4: PostGIS 实时生成 (priorityDB 连接池)            │
│   - 响应时间：50-200ms                                   │
│   - SQL：ST_AsMVT() + 像素过滤                          │
│   - 连接池：50 conns (优先)                              │
│   - 生成后异步写入 Tier 1+2+3                           │
│   - 生成率：~5%                                          │
└─────────────────────────────────────────────────────────┘
       ↓
响应：application/vnd.mapbox-vector-tile (gzipped MVT)
Headers: X-Cache: memory|redis|minio|MISS
```

**新架构优势**：
1. ✅ 简化架构（移除 PostgreSQL mvt_cache 表）
2. ✅ 复用基础设施（ADDP Redis + MinIO）
3. ✅ 自动驱逐（Redis LRU 自动淘汰老瓦片）
4. ✅ 成本降低 97%（对象存储 vs 数据库表）
5. ✅ 性能提升（MinIO 比 PostgreSQL 快 2-5 倍）
6. ✅ 扩大内存（Memory LRU 8192，命中率提升 20%）
