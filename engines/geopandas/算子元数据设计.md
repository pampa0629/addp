## 四、三种元数据模式对比详解

在为你介绍实施方案前，先详细对比这三种业界主流的元数据管理模式：

### 模式 1：Pydantic BaseModel（推荐）

**核心理念**：使用 Python 数据验证库 Pydantic 定义结构化的元数据模型

**代码示例**：
```python
from pydantic import BaseModel, Field
from typing import Annotated

class OperatorParam(BaseModel):
    """算子参数定义"""
    name: str = Field(description="参数名称")
    type: str = Field(description="参数类型：input/output/param")
    required: bool = Field(default=True, description="是否必填")

class BufferOperatorMetadata(BaseModel):
    """Buffer 算子的元数据"""
    name: str = "buffer"
    category: str = "几何处理"
    distance: Annotated[float, Field(gt=0, description="缓冲距离")]
    resolution: Annotated[int, Field(ge=1, le=64)] = 16

# 使用：自动验证
config = BufferOperatorMetadata(distance=100, resolution=32)  # ✅ 正常
config = BufferOperatorMetadata(distance=-10)  # ❌ 抛出 ValidationError
```

**优势**：
- ✅ **类型安全**：运行时自动验证参数类型和约束（如 `distance > 0`）
- ✅ **IDE 支持**：完整的自动补全和类型检查
- ✅ **自动文档**：可生成 JSON Schema，用于 API 文档
- ✅ **错误提示清晰**：告诉用户"distance 必须大于 0"，而不是神秘的崩溃
- ✅ **序列化方便**：`model_dump()` 一键转换为字典/JSON

**劣势**：
- ❌ 需要引入外部依赖（`pydantic>=2.0`）
- ❌ 代码相对冗长（需要定义完整的类）
- ❌ 学习曲线（团队需要熟悉 Pydantic API）

**适用场景**：
- 企业级平台（如 ADDP）：需要严格的参数验证
- 复杂元数据：有嵌套结构、多层验证规则
- API 服务：需要自动生成 OpenAPI 文档
- **类似项目**：FastAPI、Hugging Face Transformers、LangChain

---

### 模式 2：装饰器 + Type Hints

**核心理念**：使用 Python 装饰器为函数附加元数据，通过 type hints 声明参数类型

**代码示例**：
```python
from typing import Annotated

def operator(name: str, category: str, description: str):
    """算子装饰器"""
    def decorator(func):
        func._operator_name = name
        func._operator_category = category
        func._operator_description = description
        return func
    return decorator

@operator(
    name="buffer",
    category="几何处理",
    description="对几何对象创建指定距离的缓冲区"
)
def buffer(
    gdf: gpd.GeoDataFrame,
    distance: Annotated[float, "缓冲距离，单位与坐标系一致"],
    resolution: Annotated[int, "分辨率，控制圆弧平滑度"] = 16
) -> gpd.GeoDataFrame:
    """Buffer 算子实现"""
    return gdf.buffer(distance, resolution=resolution)

# 运行时提取元数据
print(buffer._operator_name)  # "buffer"
```

**优势**：
- ✅ **代码简洁**：元数据声明紧凑，不需要单独的类定义
- ✅ **零依赖**：使用 Python 标准库即可实现
- ✅ **灵活性高**：可以动态修改装饰器逻辑
- ✅ **可读性好**：一眼看出函数的元数据

**劣势**：
- ❌ **无运行时验证**：`distance=-10` 也能通过，需要手动验证
- ❌ **IDE 支持有限**：`Annotated` 的元数据不会显示在自动补全中
- ❌ **元数据提取麻烦**：需要手动解析 `__annotations__` 和装饰器属性
- ❌ **嵌套元数据困难**：复杂的元数据结构（如 use_cases、notes）难以表达

**适用场景**：
- 研究项目：快速原型开发，不需要严格验证
- 简单元数据：只有基本的名称、类别、描述
- 性能敏感：避免 Pydantic 验证开销
- **类似项目**：LangChain Tools、PyTorch Custom Operators、MLflow

---

### 模式 3：类继承（BaseOperator）

**核心理念**：所有算子继承一个基类，通过类属性和方法定义元数据

**代码示例**：
```python
class BaseOperator:
    """所有算子的基类"""
    name: str
    category: str
    description: str

    def __init__(self, **kwargs):
        for key, value in kwargs.items():
            setattr(self, key, value)

    def execute(self, **kwargs):
        raise NotImplementedError

    def to_metadata(self) -> dict:
        """生成元数据字典"""
        return {
            'name': self.name,
            'category': self.category,
            'description': self.description
        }

class BufferOperator(BaseOperator):
    """Buffer 算子"""
    name = "buffer"
    category = "几何处理"
    description = "对几何对象创建指定距离的缓冲区"

    def execute(self, gdf, distance, resolution=16):
        return gdf.buffer(distance, resolution=resolution)

# 使用
op = BufferOperator()
result = op.execute(gdf, distance=100)
```

**优势**：
- ✅ **OOP 经典模式**：符合传统面向对象设计
- ✅ **继承机制强大**：可以在基类中实现通用逻辑（如日志、缓存）
- ✅ **框架感强**：清晰的抽象层次，适合大型框架
- ✅ **状态管理方便**：算子可以保存内部状态

**劣势**：
- ❌ **代码冗长**：每个算子都需要定义一个类
- ❌ **使用不便**：需要实例化对象才能调用（`BufferOperator().execute(...)`）
- ❌ **过度设计**：对于简单算子来说，类继承太重
- ❌ **测试复杂**：需要 mock 对象和继承链

**适用场景**：
- 框架开发：需要提供扩展点给第三方开发者
- 复杂状态管理：算子有内部状态（如连接池、缓存）
- 插件系统：需要动态加载和卸载算子
- **类似项目**：Apache Airflow、Scikit-learn Estimators、Kedro Nodes

## 模式选择建议

### 对于 ADDP GeoPandas 引擎，我推荐 **模式 1（Pydantic）+ 模式 2（装饰器）的混合方案**：

**实现思路**：
1. 使用 **Pydantic** 定义元数据模型（获得类型安全和自动文档）
2. 使用 **装饰器** 简化注册流程（保持代码简洁）
3. 算子函数本身保持简单（不使用类继承）

**代码示例**：
```python
# base.py：定义元数据模型
class OperatorMetadata(BaseModel):
    name: str
    category: str
    params: List[OperatorParam]
    # ... 其他字段

# geometric_operators.py：实现算子
def buffer(gdf, distance, resolution=16):
    """Buffer 算子实现"""
    return gdf.buffer(distance, resolution=resolution)

# 元数据定义（Pydantic 确保数据完整性）
BUFFER_METADATA = OperatorMetadata(
    name="buffer",
    category="几何处理",
    params=[
        OperatorParam(name="input", type="input", ...),
        OperatorParam(name="distance", type="param", ...),
    ],
    # ... 其他字段
)

# 注册（简单的辅助函数）
OPERATORS = {
    'buffer': {
        'function': buffer,
        **BUFFER_METADATA.to_legacy_dict()  # 转换为兼容格式
    }
}
```

**这种方案的优势**：
- ✅ **最佳实践**：FastAPI、Hugging Face 等现代 Python 项目都采用此模式
- ✅ **平衡性好**：既有类型安全，又保持代码简洁
- ✅ **向后兼容**：通过 `to_legacy_dict()` 方法输出旧格式字典
- ✅ **易于测试**：函数可以直接调用，不需要实例化对象

## 四、技术实现方案（基于混合模式）

### 4.1 基类设计（operators/base.py）

```python
from pydantic import BaseModel, Field
from typing import Any, Dict, List, Optional, Callable
from enum import Enum

class OperatorCategory(str, Enum):
    """算子分类枚举"""
    DATA_IO = "数据I/O"
    GEOMETRIC = "几何处理"
    SPATIAL_RELATION = "空间关系"
    PROPERTIES = "几何属性"
    FORMAT_CONVERSION = "格式转换"
    DATA_OPERATION = "数据操作"

class OperatorParam(BaseModel):
    """算子参数定义"""
    name: str = Field(description="参数名称")
    type: str = Field(description="参数类型：input/output/param")
    data_type: str = Field(description="数据类型：GeoDataFrame/str/float/int 等")
    required: bool = Field(default=True, description="是否必填")
    description: str = Field(description="参数说明")
    notes: Optional[str] = Field(None, description="注意事项")

class OperatorMetadata(BaseModel):
    """算子元数据模型"""
    name: str = Field(description="算子唯一标识符")
    category: OperatorCategory = Field(description="算子分类")
    description: str = Field(description="算子简要描述")
    brief_description: str = Field(description="简短说明（一句话）")

    # 详细元数据
    overview: str = Field(description="功能概述（50-100字）")
    params: List[OperatorParam] = Field(description="参数列表")
    use_cases: List[str] = Field(description="真实使用场景（4-5个）")
    notes: List[str] = Field(description="常见问题和优化建议（4-5个）")
    workflow_example: Dict[str, Any] = Field(description="DAG 示例")

    # 运行时绑定
    function: Optional[Callable] = Field(None, exclude=True, description="实际执行函数")

    def to_legacy_dict(self) -> dict:
        """转换为兼容旧格式的字典"""
        return {
            'function': self.function,
            'params': [p.model_dump() for p in self.params],
            'category': self.category.value,
            'description': self.description,
            'brief_description': self.brief_description,
            'detailed_description': {
                'overview': self.overview,
                'parameters': [p.model_dump() for p in self.params],
                'use_cases': self.use_cases,
                'notes': self.notes,
                'workflow_example': self.workflow_example
            }
        }

def register_operator(metadata: OperatorMetadata, func: Callable) -> tuple[str, dict]:
    """
    注册算子的辅助函数

    Args:
        metadata: 算子元数据
        func: 算子实现函数

    Returns:
        (算子名称, 兼容旧格式的字典)
    """
    metadata.function = func
    return metadata.name, metadata.to_legacy_dict()
```

### 4.3 统一导出（operators/__init__.py）

```python
"""
GeoPandas 空间算子模块

提供 21 个空间分析算子,支持数据 I/O、几何处理、空间关系分析等。
"""

from .base import OperatorMetadata, OperatorParam, OperatorCategory

# 导入所有算子实现
from .io_operators import load, save
from .geometric_operators import (
    buffer, intersection, union, centroid,
    difference, simplify, convex_hull, envelope
)
from .spatial_relations import contains, intersects, distance_to
from .properties_operators import get_area, get_length, get_bounds
from .format_operators import load_from_wkt, export_to_wkt
from .data_operations import (
    clip, voronoi, split_by_area, dissolve,
    batch_buffer, batch_centroid
)

# 导入所有算子元数据
from .io_operators import OPERATORS as IO_OPERATORS
from .geometric_operators import OPERATORS as GEOMETRIC_OPERATORS
from .spatial_relations import OPERATORS as SPATIAL_OPERATORS
from .properties_operators import OPERATORS as PROPERTIES_OPERATORS
from .format_operators import OPERATORS as FORMAT_OPERATORS
from .data_operations import OPERATORS as DATA_OPERATORS

# 合并所有算子元数据
OPERATORS = {}
for ops_dict in [
    IO_OPERATORS,
    GEOMETRIC_OPERATORS,
    SPATIAL_OPERATORS,
    PROPERTIES_OPERATORS,
    FORMAT_OPERATORS,
    DATA_OPERATORS
]:
    OPERATORS.update(ops_dict)

def list_operators():
    """
    返回标准化的算子元数据列表（向后兼容）

    Returns:
        包含所有算子元数据的列表
    """
    result = []
    for name, op_dict in OPERATORS.items():
        # 转换旧格式的参数类型映射
        params = []
        for param in op_dict['params']:
            param_type = param['type']
            if param_type == 'input':
                param['type'] = 'GeoDataFrame'
                param['is_input'] = True
            elif param_type == 'output':
                param['type'] = 'GeoDataFrame'
                param['is_output'] = True
            params.append(param)

        result.append({
            'name': name,
            'category': op_dict['category'],
            'description': op_dict['description'],
            'brief_description': op_dict['brief_description'],
            'params': params,
            'detailed_description': op_dict['detailed_description']
        })

    return result
```
