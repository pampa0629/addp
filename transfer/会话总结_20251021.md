- **文件**: `internal/connector/s3_reader.go`, `s3_writer.go`

### 阶段 2：SystemClient 集成（4项）

#### 5. 添加 SystemClient 到 TaskService（🔴 严重）
- **实现**: 在 TaskService 中添加 systemClient 字段

- **初始化**: 在 NewTaskService 中创建 SystemClient 实例
- **文件**: `internal/service/task_service.go`

#### 6. 实现资源配置获取（🔴 严重）
- **实现**: `GetResourceConfig()` 方法
- **功能**: 调用 SystemClient.GetResource() 获取资源
- **日志**: 添加详细的日志记录
- **文件**: `internal/service/task_service.go:523-540`

#### 7. 实现配置解析和合并（🔴 严重）
- **实现**:
  - `resolveConnectorConfig()` - 解析配置，优先使用资源配置
  - `resourceToConnectorConfig()` - 转换资源到连接器配置
- **逻辑**:
  1. 如果提供 resource_id，从 System 获取配置
  2. 转换 Resource 为连接器配置
  3. 合并 task.config 中的额外配置
  4. Fallback 到 task.config（如果获取失败）
- **支持类型**: postgresql, mysql, s3, minio
- **文件**: `internal/service/task_service.go:542-643`

## 🎯 核心成果

### 1. SystemClient 集成架构

```
用户创建任务
  ↓
提供 source_id / target_id
  ↓
TaskService.buildExecutionTask()
  ↓
resolveConnectorConfig()
  ├─ resource_id 存在？
  │  ├─ YES → SystemClient.GetResource()
  │  │         ↓
  │  │       resourceToConnectorConfig()
  │  │         ↓
  │  │       合并 task.config
  │  │         ↓
  │  │       返回完整配置
  │  │
  │  └─ NO  → 使用 task.config
  ↓
ExecutionEngine.Execute()
```

### 2. 配置合并规则

**资源配置优先（连接信息）**:
- host, port, user, password
- endpoint, access_key, secret_key, bucket
- database, driver

**任务配置优先（业务逻辑）**:
- query, table, schema
- prefix, file_name, file_type
- transforms, mappings

### 3. 使用示例对比

**之前（v1.0.0）**:
```json
{
  "config": {
    "source": {
      "type": "jdbc",
      "driver": "postgresql",
      "host": "prod-db.example.com",
      "port": 5432,
      "user": "app_user",
      "password": "SuperSecretPassword123!",  // ❌ 明文密码
      "database": "production",
      "query": "SELECT * FROM users"
    }
  }
}
```

**现在（v1.1.0）**:
```json
{
  "source_id": 10,  // ✅ 引用 System 资源
  "config": {
    "source": {
      "query": "SELECT * FROM users"  // ✅ 只需业务逻辑
    }
  }
}
```
