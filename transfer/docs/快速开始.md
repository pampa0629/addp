# Transfer 模块快速开始

更新时间：2026-05-30

本文只覆盖当前 Transfer 主路径：基于 System engine、source / target endpoint JSON、common engine / format / contentio 的 table Transfer。旧 `connector_type`、`source_id`、`target_id`、任务外层 `mappings`、私有 Reader / Writer 插件和 `go run` 启动方式不再作为开发入口。

## 一、启动

启动基础设施：

```bash
bash scripts/infra/up.sh
```

启动 Transfer：

```bash
bash scripts/dev/start.sh -transfer
```

后端修改后重启：

```bash
./scripts/dev/restart.sh -transfer
```

健康检查：

```bash
curl http://localhost:8083/health
```

API 前缀：

```text
/api/v1/transfer
```

## 二、创建 table Transfer 任务

下面示例展示 PostgreSQL native table 导出到 NFS CSV。示例中的 engine id 需要替换成 System 已注册的真实引擎 ID。

注意：Transfer 当前接口层只保留 `task_type=import`。导出、同步等更细任务语义后续由 Transfer 专题确认，不在当前接口中并行暴露。

```bash
curl -X POST http://localhost:8083/api/v1/transfer/task-definitions \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "道路表导出 CSV",
    "description": "从 PostgreSQL native table 导出到 NFS CSV",
    "task_type": "import",
    "batch_size": 10000,
    "auto_scan_metadata": true,
    "config": {
      "mode": "batch",
      "source": {
        "locator": "addp://engine/1/path/public/roads?type=table",
        "data_type": "table",
        "representation": "native"
      },
      "target": {
        "parent_locator": "addp://engine/2/path/exports?type=directory",
        "name": "roads.csv",
        "data_type": "table",
        "representation": "encoded",
        "format": "csv",
        "options": {"header": true},
        "policy": {"write_mode": "overwrite"}
      },
      "transforms": [
        {
          "type": "field_mapping",
          "version": "v1",
          "mode": "project",
          "fields": [
            {"source": "id", "target": "id", "target_type": "bigint"},
            {"source": "name", "target": "road_name", "target_type": "string"},
            {"source": "geom", "target": "geometry", "target_type": "geometry"}
          ]
        }
      ],
      "batch_size": 10000
    }
  }'
```

启动任务：

```bash
curl -X POST http://localhost:8083/api/v1/transfer/task-definitions/1/start \
  -H "Authorization: Bearer $TOKEN"
```

查询执行：

```bash
curl http://localhost:8083/api/v1/transfer/task-definitions/1/executions \
  -H "Authorization: Bearer $TOKEN"
```

查看进度：

```bash
curl http://localhost:8083/api/v1/transfer/executions/1/progress \
  -H "Authorization: Bearer $TOKEN"
```

查看日志：

```bash
curl http://localhost:8083/api/v1/transfer/executions/1/logs \
  -H "Authorization: Bearer $TOKEN"
```

## 三、常见任务形态

### 3.1 encoded file/object 导入 native table

```json
{
  "mode": "batch",
  "source": {
    "locator": "addp://engine/2/path/imports/roads.parquet?type=file",
    "data_type": "table",
    "representation": "encoded",
    "format": "parquet"
  },
  "target": {
    "parent_locator": "addp://engine/1/path/public?type=schema",
    "name": "roads_imported",
    "data_type": "table",
    "representation": "native",
    "policy": {"write_mode": "overwrite"}
  },
  "batch_size": 10000
}
```

### 3.2 encoded object 到 encoded object

```json
{
  "mode": "batch",
  "source": {
    "locator": "addp://engine/3/path/bucket/input/roads.csv?type=object",
    "data_type": "table",
    "representation": "encoded",
    "format": "csv",
    "options": {"header": true}
  },
  "target": {
    "parent_locator": "addp://engine/4/path/backup/output?type=prefix",
    "name": "roads.parquet",
    "data_type": "table",
    "representation": "encoded",
    "format": "parquet",
    "policy": {"write_mode": "overwrite"}
  }
}
```

### 3.3 Shapefile multi refs

Shapefile 作为 `data_type=table + format=shapefile + layout=multi` 进入 table Transfer。source 已入库时，使用 source locator 的 `item_id`，由 Transfer 从 Meta attributes 读取已确认 refs。

```json
{
  "mode": "batch",
  "source": {
    "locator": "addp://engine/3/path/bucket/gis/roads.shp?type=object&item_id=12",
    "data_type": "table",
    "representation": "encoded",
    "format": "shapefile"
  },
  "target": {
    "parent_locator": "addp://engine/1/path/public?type=schema",
    "name": "roads",
    "data_type": "table",
    "representation": "native",
    "policy": {"write_mode": "overwrite"}
  }
}
```

## 四、Checkpoint 和重试

当前 Transfer 已支持 checkpoint 观测和 restartable retry：

- `checkpoint_offset` 表示累计读取记录数。
- `checkpoint_state` 保存 batch 进度、`resume_marker` 和 `commit_marker` 等诊断信息。
- retry 会创建新的 execution 并从头执行。
- append 写入模式拒绝 retry。
- checkpoint resumable 尚未进入主链路，不应宣称“从中断点继续写入”。

重试失败执行：

```bash
curl -X POST http://localhost:8083/api/v1/transfer/executions/1/retry \
  -H "Authorization: Bearer $TOKEN"
```
