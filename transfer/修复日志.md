### 4. **优化 S3 临时文件清理**（重要问题）

**问题**:
- S3Reader 和 S3Writer 使用硬编码的 `/tmp/` 路径
- 临时文件清理机制不完善，异常退出时可能残留
- 缺少并发安全的文件名生成

**修复内容 (S3Reader)**:
- ✅ 使用 `os.CreateTemp("", "s3_reader_*.tmp")` 替代硬编码路径
- ✅ 添加 `tempFiles []string` 字段跟踪所有临时文件
- ✅ 在打开文件失败时立即清理临时文件
- ✅ 在 `Close()` 方法中清理所有临时文件
  ```go
  func (r *S3Reader) Close() error {
      // 关闭当前文件读取器
      if r.fileReader != nil {
          r.fileReader.Close()
      }

      // 清理所有临时文件
      for _, tempPath := range r.tempFiles {
          if err := os.Remove(tempPath); err != nil {
              fmt.Printf("warning: failed to remove temp file %s: %v\n", tempPath, err)
          }
      }
      r.tempFiles = nil

      return nil
  }
  ```

**修复内容 (S3Writer)**:
- ✅ 使用 `os.CreateTemp("", "s3_writer_*.tmp")` 替代硬编码路径
- ✅ 在打开文件失败时立即清理临时文件
- ✅ 使用 `defer` 确保 `Close()` 时一定清理临时文件
  ```go
  func (w *S3Writer) Close() error {
      // 确保清理临时文件（使用 defer 保证执行）
      defer func() {
          if w.tempFile != "" {
              if err := os.Remove(w.tempFile); err != nil {
                  fmt.Printf("warning: failed to remove temp file %s: %v\n", w.tempFile, err)
              }
          }
      }()

      // ... 其他清理逻辑
  }
  ```

**收益**:
- ✅ 并发安全：每次调用 `os.CreateTemp` 都生成唯一文件名
- ✅ 自动清理：使用系统临时目录，OS 可以定期清理
- ✅ 异常安全：使用 `defer` 确保即使出现错误也能清理
- ✅ 跨平台：不依赖 `/tmp/` 路径，适配 Windows/Linux/macOS

### 5. **集成 SystemClient**（严重问题）✅ 新增

**问题**: TaskService 无法从 System 模块获取资源配置，用户必须在任务配置中硬编码所有连接信息（包括密码）。

**修复内容**:
- ✅ 在 TaskService 中添加 SystemClient 字段
- ✅ 实现 `GetResourceConfig()` 方法从 System 获取资源
- ✅ 实现 `resolveConnectorConfig()` 方法解析配置（优先使用资源配置）
- ✅ 实现 `resourceToConnectorConfig()` 转换资源到连接器配置
- ✅ 支持配置合并（资源配置 + 任务配置）
- ✅ 支持 fallback 机制（获取失败时使用任务配置）
- ✅ 添加详细日志记录配置获取过程

**核心代码**:
```go
// TaskService 新增字段
type TaskService struct {
    // ...
    cfg           *config.Config
    systemClient  *commonClient.SystemClient
}

// 从 System 获取资源配置
func (s *TaskService) GetResourceConfig(ctx context.Context, resourceID uint) (*commonModels.Resource, error) {
    resource, err := s.systemClient.GetResource(resourceID)
    if err != nil {
        return nil, fmt.Errorf("failed to get resource: %w", err)
    }
    return resource, nil
}

// 解析配置（优先使用资源配置）
sourceConfig, err := s.resolveConnectorConfig(config, "source", task.SourceID)
targetConfig, err := s.resolveConnectorConfig(config, "target", task.TargetID)
```

**使用示例**:
```json
// 用户只需提供 resource_id，系统自动获取连接信息
{
  "name": "Daily Export",
  "source_id": 10,  // PostgreSQL 资源ID
  "target_id": 20,  // S3 资源ID
  "config": {
    "source": {"query": "SELECT * FROM users"},
    "target": {"prefix": "exports/"}
  }
}
```

**收益**:
- ✅ 安全性提升：密码不再明文存储在任务配置中
- ✅ 易用性提升：用户只需选择资源ID，无需重复配置连接信息
- ✅ 维护性提升：修改资源密码只需在 System 模块更新一次
- ✅ 灵活性提升：支持混合使用资源配置和任务配置

### 6. **实现内部 API Key 认证**（严重问题）✅ 新增

**问题**: 服务间调用缺少认证机制，存在安全风险。任何服务都可以调用 System 的内部 API。

**修复内容**:
- ✅ 在 Config 中添加 `InternalAPIKey` 字段
- ✅ 从环境变量 `INTERNAL_API_KEY` 读取密钥
- ✅ TaskService 使用 `NewSystemClientWithInternalKey` 初始化
- ✅ 支持 fallback 到 BaseConfig.InternalAPIKey
- ✅ 添加认证状态日志（INFO/WARN）
- ✅ 创建 .env.example 配置模板
- ✅ 编写完整的认证配置文档

**核心代码**:
```go
// Config 新增字段
type Config struct {
    // ...
    InternalAPIKey  string  // 服务间调用的 API Key
}

// 从环境变量读取
cfg.InternalAPIKey = commonConfig.GetEnv("INTERNAL_API_KEY", "")

// 如果本地未配置，从 BaseConfig 获取
if cfg.InternalAPIKey == "" {
    cfg.InternalAPIKey = cfg.BaseConfig.InternalAPIKey
}

// TaskService 使用内部认证
if cfg.InternalAPIKey != "" {
    systemClient = commonClient.NewSystemClientWithInternalKey(
        cfg.SystemServiceURL,
        cfg.InternalAPIKey,
    )
    slog.Info("SystemClient initialized with internal API key")
} else {
    systemClient = commonClient.NewSystemClient(cfg.SystemServiceURL, "")
    slog.Warn("SystemClient initialized without authentication")
}
```

**环境变量配置**:
```bash
# transfer/backend/.env
INTERNAL_API_KEY=your-production-internal-key

# 密钥生成（推荐）
openssl rand -base64 32
```

**收益**:
- ✅ 安全性大幅提升：防止未授权的服务间调用
- ✅ 审计能力提升：可追踪调用来源
- ✅ 生产就绪：符合企业安全规范
- ✅ 灵活配置：支持多种配置来源

**参考实现**: Meta 模块的内部认证机制
