# Transfer 模块 - 问题清单和改进建议

## 🔴 严重问题（必须修复）

### 1. **缺少 go.mod 依赖声明** ⚠️
**问题**: `backend/go.mod` 只声明了 common 模块，缺少所有第三方依赖

**影响**:
- 无法编译运行
- `go build` 会失败
- 依赖版本不明确

**修复方案**:
```go
module github.com/addp/transfer

go 1.23

replace github.com/addp/common => ../../common

require (
    github.com/addp/common v0.0.0-00010101000000-000000000000
    github.com/gin-gonic/gin v1.9.1
    github.com/hibiken/asynq v0.24.1
    github.com/robfig/cron/v3 v3.0.1
    github.com/aws/aws-sdk-go v1.45.0
    github.com/dgrijalva/jwt-go v3.2.0+incompatible
    gorm.io/gorm v1.25.4
    gorm.io/driver/postgres v1.5.3
    gorm.io/driver/mysql v1.5.2
)
```

**优先级**: 🔴 最高

---

### 2. **缺少数据库迁移和 AutoMigrate**
**问题**: `cmd/server/main.go` 中的 AutoMigrate 被注释掉了

**当前代码**:
```go
// 临时使用空的 AutoMigrate，待 models 完善后再启用
err := db.AutoMigrate()
```

**影响**:
- 数据库表不会自动创建
- 首次运行会失败
- 需要手动创建表

**修复方案**:
```go
// 导入 models
import (
    "github.com/addp/transfer/internal/models"
    "github.com/addp/transfer/pkg/pipeline"
)

// AutoMigrate
err := db.AutoMigrate(
    &models.Task{},
    &models.TaskExecution{},
    &models.DataMapping{},
    &pipeline.Checkpoint{},
)
```

**优先级**: 🔴 最高

---

### 3. **缺少 SQL 初始化脚本**
**问题**: 没有创建 `transfer` schema 的 SQL 脚本

**影响**:
- PostgreSQL 需要手动创建 schema
- 部署流程不完整

**修复方案**:
在 `scripts/init-db.sql` 中添加：
```sql
-- 创建 transfer schema
CREATE SCHEMA IF NOT EXISTS transfer;

-- 授权
GRANT ALL PRIVILEGES ON SCHEMA transfer TO addp;
```

**优先级**: 🔴 高

---

### 4. **TaskService 缺少 SystemClient 集成**
**问题**: TaskService 需要从 System 模块获取资源配置，但当前实现缺失

**影响**:
- 无法根据 source_id/target_id 获取数据源配置
- 需要在 config JSON 中硬编码所有连接信息

**修复方案**:
在 `TaskService.buildExecutionTask()` 中添加：
```go
// 从 System 获取资源配置
if task.SourceID != nil {
    systemClient := s.cfg.GetSystemClient(token)
    resource, err := systemClient.GetResource(*task.SourceID)
    if err != nil {
        return nil, err
    }
    // 合并到 config.source
}
```

**优先级**: 🔴 高

## 🟡 重要问题（建议修复）

### 5. **缺少错误处理和日志**
**问题**: 多处代码缺少详细的错误处理和日志记录

**示例**:
```go
// file_reader.go - 缺少错误日志
if _, err := os.Stat(r.filePath); os.IsNotExist(err) {
    return fmt.Errorf("file not found: %s", r.filePath)  // 应该记录日志
}
```

**修复方案**:
```go
import "log/slog"

if _, err := os.Stat(r.filePath); os.IsNotExist(err) {
    slog.Error("file not found", "path", r.filePath, "error", err)
    return fmt.Errorf("file not found: %s", r.filePath)
}
```

**优先级**: 🟡 中

---

### 6. **S3Reader/Writer 临时文件清理不完善**
**问题**: S3 连接器使用临时文件但清理机制不完善

**当前问题**:
- 临时文件路径硬编码 `/tmp/`
- 异常退出时可能残留临时文件
- 缺少并发安全的文件名

**修复方案**:
```go
import (
    "os"
    "path/filepath"
)

// 使用 os.CreateTemp 创建临时文件
tempFile, err := os.CreateTemp("", "s3_reader_*.tmp")
if err != nil {
    return err
}
defer os.Remove(tempFile.Name())  // 确保清理
```

**优先级**: 🟡 中

---

### 7. **缺少连接池管理**
**问题**: JDBC 连接器每次 Open 都创建新连接，没有连接池

**影响**:
- 频繁创建/关闭连接，性能差
- 无法限制最大连接数

**修复方案**:
```go
// 使用 database/sql 的连接池
db, err := sql.Open(driver, dsn)
db.SetMaxOpenConns(25)
db.SetMaxIdleConns(5)
db.SetConnMaxLifetime(5 * time.Minute)
```

**优先级**: 🟡 中

---

### 8. **缺少上下文超时控制**
**问题**: 长时间运行的任务缺少超时控制

**修复方案**:
```go
// 在 ExecutionEngine.Execute 中添加超时
ctx, cancel := context.WithTimeout(ctx, task.Timeout)
defer cancel()

// 监听上下文取消
select {
case <-ctx.Done():
    return fmt.Errorf("task timeout: %w", ctx.Err())
default:
    // 继续执行
}
```

**优先级**: 🟡 中

## 🟢 优化建议（可选）

### 9. **性能优化 - 批量写入优化**
**建议**: JDBCWriter 可以使用 COPY 协议（PostgreSQL）或批量 INSERT

**当前**: 逐行 INSERT
```go
for _, row := range batch.Rows {
    INSERT INTO table VALUES (...)
}
```

**优化**:
```go
// PostgreSQL COPY
COPY table FROM STDIN
// MySQL INSERT INTO VALUES
INSERT INTO table VALUES (...), (...), (...)
```

**收益**: 性能提升 5-10 倍

---

### 10. **添加指标监控**
**建议**: 集成 Prometheus 指标

**示例**:
```go
import "github.com/prometheus/client_golang/prometheus"

var (
    taskDuration = prometheus.NewHistogramVec(...)
    taskCounter = prometheus.NewCounterVec(...)
)

// 记录指标
taskDuration.WithLabelValues(taskType).Observe(duration)
taskCounter.WithLabelValues(taskType, status).Inc()
```

**收益**: 更好的可观测性

## 💡 架构改进建议

### 1. 引入消息队列解耦
当前 Worker 和 API Server 紧耦合，建议：
- 使用 Redis Streams 或 Kafka 作为事件总线
- API Server 发布任务事件
- Worker 订阅并处理

### 2. 添加配置中心
当前配置分散在环境变量中，建议：
- 使用 Consul/etcd 集中管理配置
- 支持动态配置更新
- 配置版本控制

### 3. 服务网格
生产环境建议：
- 使用 Istio/Linkerd 管理服务间通信
- 自动服务发现
- 流量控制和熔断

### 4. 数据血缘追踪
建议集成 Meta 模块：
- 记录数据来源和去向
- 建立数据血缘图谱
- 影响分析
