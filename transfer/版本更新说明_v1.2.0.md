### 2. SystemClient 集成

**功能描述**: Transfer 可从 System 模块动态获取数据源配置，无需在任务中硬编码连接信息

**使用场景**:

#### Before (v1.1.0)
```json
{
  "name": "用户数据同步",
  "config": {
    "source": {
      "type": "jdbc",
      "driver": "postgresql",
      "host": "192.168.1.100",     // ← 硬编码
      "port": 5432,
      "user": "user",
      "password": "plain_password",  // ← 明文密码
      "database": "source_db",
      "query": "SELECT * FROM users"
    },
    "target": { /* 同样的问题 */ }
  }
}
```

**问题**:
- ❌ 连接信息硬编码，修改困难
- ❌ 密码明文存储，安全风险高
- ❌ 配置重复（多个任务使用同一数据源）
- ❌ 无法统一管理数据源

#### After (v1.2.0)
```json
{
  "name": "用户数据同步",
  "source_id": 1,               // ← 引用 System 的 resource_id
  "target_id": 2,               // ← 引用 System 的 resource_id
  "config": {
    "source": {
      "query": "SELECT * FROM users WHERE created_at > :last_sync_time"
    },
    "target": {
      "table": "users_backup",
      "write_mode": "append"
    }
  },
  "schedule_expression": "0 2 * * *"
}
```

**优势**:
- ✅ 连接信息从 System 动态获取
- ✅ 密码在 System 中加密存储
- ✅ 修改数据源连接后自动生效
- ✅ 统一管理所有数据源

**技术实现**:
- 新增字段: `TaskService.systemClient`
- 新增方法: `GetResourceConfig()`, `resolveConnectorConfig()`, `resourceToConnectorConfig()`
- 修改文件: [transfer/backend/internal/service/task_service.go](./backend/internal/service/task_service.go)

**Fallback 机制**:
- 优先使用 `source_id`/`target_id` 获取资源
- 如果失败，回退到任务配置中的连接信息
- 保证向下兼容

**详细文档**: [SystemClient集成指南.md](./SystemClient集成指南.md)

### 3. 内部 API 认证

**功能描述**: Transfer 与 System 的服务间通信使用 `X-Internal-API-Key` 进行认证

**安全提升**:

#### Before (v1.1.0)
```
Transfer Service
    ↓ HTTP Request (无认证)
System /internal/resources/:id
    ↓ 返回敏感数据（密码已解密）
Transfer Service ✅ 获取成功

⚠️ 问题: 任何人都可以调用内部 API
```

#### After (v1.2.0)
```
Transfer Service
    ↓ HTTP Request with Header: X-Internal-API-Key
System Middleware: InternalAPIKeyAuth()
    ├─ 密钥正确 → 允许访问 ✅
    └─ 密钥错误 → 401 Unauthorized ❌
System /internal/resources/:id
    ↓ 返回敏感数据
Transfer Service ✅ 获取成功

✅ 保证: 只有持有正确密钥的服务才能访问
```

**技术实现**:
- 新增配置: `Config.InternalAPIKey`
- 修改文件: [transfer/backend/internal/config/config.go](./backend/internal/config/config.go)
- 修改初始化: 使用 `NewSystemClientWithInternalKey()`
- 参考实现: Meta 模块

**配置方式**:
```bash
# transfer/backend/.env
INTERNAL_API_KEY=your-strong-secret-key

# 必须与 System 的 INTERNAL_API_KEY 保持一致
```

**验证方法**:
- 启动日志包含: `INFO SystemClient initialized with internal API key`
- 无密钥时警告: `WARN SystemClient initialized without authentication`

**详细文档**: [内部API认证配置指南.md](./内部API认证配置指南.md)

## 🚀 部署指南

### 快速启动

**使用启动脚本（推荐）**:
```bash
# 从项目根目录
./scripts/start-transfer.sh
```

脚本会自动：
1. ✅ 检查 System Backend 是否运行
2. ✅ 检查并创建 PostgreSQL `transfer` schema
3. ✅ 检查 Redis 连接
4. ✅ 检查并创建 `.env` 配置文件
5. ✅ 验证 `INTERNAL_API_KEY` 配置
6. ✅ 启动 Transfer Backend
7. ✅ 等待服务健康检查通过

**手动启动前端**:
```bash
# Terminal 1: Portal
cd portal/frontend
npm install  # 首次
npm run dev

# Terminal 2: Transfer Frontend
cd transfer/frontend
npm install  # 首次
npm run dev
```

**访问**:
- Portal: http://localhost:5170
- Transfer: http://localhost:5176/transfer/

### 完整启动流程

**方式一：使用项目脚本（启动所有服务）**
```bash
./scripts/dev-start.sh
```

**方式二：仅启动 Transfer**
```bash
./scripts/start-transfer.sh
```

**详细说明**: 参见 [Portal集成启动指南.md](./Portal集成启动指南.md)

## 🔧 升级步骤

### 从 v1.1.0 升级到 v1.2.0

#### 步骤 1: 更新代码

```bash
git pull origin main
```

#### 步骤 2: 更新 Go 依赖

```bash
cd transfer/backend
go mod tidy
```

#### 步骤 3: 配置内部 API Key

```bash
# 复制配置模板（如果没有 .env）
cp .env.example .env

# 编辑配置
vim .env

# 设置 INTERNAL_API_KEY（必须与 System 一致）
INTERNAL_API_KEY=dev-internal-key  # 生产环境请更换为强密钥
```

#### 步骤 4: 重启服务

```bash
# 停止旧版本
kill $(cat .dev-pids/transfer.pid)

# 启动新版本
./scripts/start-transfer.sh
```

#### 步骤 5: 更新 Portal 前端

```bash
cd portal/frontend

# 拉取最新代码（Portal.vue 已更新）
git pull

# 重启
npm run dev
```

#### 步骤 6: 验证

```bash

# 应该看到:
```
