# Orchestrator 执行参数与上游输出绑定

## 用户可见模型

Orchestrator Step 的执行参数只有三种来源：

1. **工作流配置**：使用 owner 模块任务定义中已保存的当前值，Step 不保存覆盖字段。
2. **执行时指定**：Step 保存显式值，每次执行该编排都用此值覆盖工作流配置。
3. **上游输出**：Step 从直接依赖步骤已声明的稳定输出中选择一个值。

用户不编辑整份 JSON，也不手写输出路径。Orchestrator 从具体任务详情的 `execution_contract` 渲染输入控件，并从依赖任务的 `output_schema` 生成可选输出。

## 画布端口与连线

编排画布同时表达纯控制依赖和参数传值，但两者不得混为同一种连线：

- 纯控制依赖使用任务级控制端口和控制连线，只表示目标 Step 必须等待来源 Step 成功完成。
- 参数传值使用 `execution_contract.input_schema` 生成的输入端口和 `output_schema` 生成的稳定输出端口；参数连线同时隐含来源 Step 到目标 Step 的执行依赖。
- 同一来源 Step 与目标 Step 之间存在参数连线时，不再并行显示或保存一条重复的纯控制连线。多条参数连线可以共享同一个 `depends_on` 项。
- 一个输入参数最多绑定一个上游输出；一个稳定输出可以连接多个下游输入。
- 创建参数连线必须原子地写入参数绑定并补充 `depends_on`；删除同一任务对之间的最后一条参数连线时移除对应 `depends_on`。如仍需纯执行顺序，用户必须明确创建控制依赖。
- 参数表单和画布连线是同一份 `parameters` 事实的两个编辑入口，必须双向同步，不得各自保存一套绑定状态。

输入端口只对应用户可配置的逻辑输入。资源选择器表示的资源对象使用一个资源端口，`locator`、`geometry_column` 等内部身份或自动派生字段不拆成独立端口。输出端口只允许使用 owner 在 `output_schema` 中声明的可序列化稳定输出。

所有控制连线和参数连线共同参与 DAG 环路检测。一个 Step 可以等待多个上游 Step，启动条件固定为所有直接依赖均成功完成；一个 Step 成功后也可以使多个下游 Step 进入可执行状态。v1 只定义就绪关系，不承诺可执行 Step 并行运行，也不支持任意一个上游完成即触发的 OR 条件。

## 内部序列化

上游输出绑定在编排定义中的唯一内部格式为：

```text
{{step_id.outputs.declared.path}}
```

例如，Develop 工作流任务 `produce` 声明保存算子 `save_3` 的资源输出后，下游资源参数可以保存为：

```json
{
  "load_1": {
    "source_resource": {
      "locator": "{{produce.outputs.save_3.resource.locator}}"
    }
  }
}
```

该字符串是内部持久化格式，不是面向用户的表达式语言。不得支持 `{{step_id}}`、`{{step_id.result}}`、`metadata.result`、数组下标或任意响应字段路径，也不得在普通字符串中做局部插值。

## 保存校验

保存编排时必须完成以下校验：

1. `provider + task_type` 已由 `task.capabilities/v2` 声明且未停用。
2. 根据 `provider + task_type + task_id` 获取具体任务详情和 `execution_contract`。
3. 执行时指定的值必须符合目标任务 `input_schema`。
4. 输出绑定的来源步骤必须存在、是当前步骤的显式依赖且不能是自身。
5. 输出路径必须存在于来源任务 `output_schema`。
6. 目标参数路径必须存在于目标任务 `input_schema`，来源与目标类型必须兼容。

任一条件不满足时拒绝保存，不保留旧模板兼容路径。

## 执行流程

1. 执行开始前重新获取所有具体任务的最新 `execution_contract`，再次校验整份编排。
2. 按 DAG 拓扑顺序执行步骤。
3. 执行当前步骤前，从直接依赖步骤响应顶层 `outputs` 读取绑定值。
4. 将绑定值和 Step 执行时指定值组成该次请求的部分 `parameters`；未覆盖字段仍使用 owner 任务定义中已保存的工作流配置。
5. 按目标 `input_schema` 校验解析后的真实值，再调用 owner TaskProvider execute API。
6. owner 使用最新契约执行最终领域校验；覆盖只作用于本次 execution，不修改任务定义。

路径不存在、来源没有返回声明输出、类型不匹配或契约已变化时，当前步骤和父编排必须失败，不能把缺失值转成 `null` 或回退到任意结果字段。

## 稳定输出边界

跨任务只传递 owner 明确声明、可持久化和可序列化的稳定输出。数据资源优先使用 ResourceLocator：

```json
{
  "outputs": {
    "save_3": {
      "resource": {
        "locator": "addp://engine/3/path/public/roads?type=table",
        "type": "table"
      }
    }
  }
}
```

进程内 DataFrame、运行时句柄、临时文件、任意 execution metadata 和日志都不是稳定输出，不能作为跨任务参数来源。
