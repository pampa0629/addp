# Orchestrator 参数模板化功能说明

## 概述

Orchestrator 支持在 Step 参数中通过 `{{stepID.field}}` 引用前序步骤的执行结果。模板解析发生在调用 TaskProvider 执行接口之前，解析结果放入本次执行请求的 `parameters` 字段。

Orchestrator 只编排任务引用，不直接调用计算引擎。

## 模板语法

```text
{{stepID.field}}
{{stepID.nested.field}}
{{stepID.deeply.nested.field.value}}
```

规则：

1. `stepID` 对应 `steps[].id`。
2. 字段路径从 `stepResults[stepID].Result` 中读取。
3. 路径不存在或类型不匹配时返回 `nil`。
4. 非模板字符串原样保留。

## 示例

```json
{
  "name": "扫描后执行 Develop 工作流",
  "steps": [
    {
      "id": "scan",
      "name": "扫描元数据",
      "provider": "meta",
      "task_type": "scan",
      "task_id": 1,
      "parameters": {},
      "depends_on": [],
      "timeout": 600
    },
    {
      "id": "workflow",
      "name": "空间分析工作流",
      "provider": "develop",
      "task_type": "workflow",
      "task_id": 8,
      "parameters": {
        "source_item": "{{scan.item_id}}",
        "source_path": "{{scan.output.path}}"
      },
      "depends_on": ["scan"],
      "timeout": 1800
    },
    {
      "id": "export",
      "name": "导出结果",
      "provider": "transfer",
      "task_type": "import",
      "task_id": 3,
      "parameters": {
        "source": "{{workflow.result_dataset}}"
      },
      "depends_on": ["workflow"],
      "timeout": 1800
    }
  ]
}
```

## 执行流程

1. Orchestrator 对 `depends_on` 做拓扑排序。
2. 执行某个 Step 前，读取已完成前序步骤的 `StepResult.Result`。
3. `resolveTemplateReferences` 递归解析 `parameters`。
4. 解析后的参数通过 TaskProvider execute 请求发送给 owner 模块。
5. owner 模块决定是否支持本次执行参数覆盖；不支持时必须明确拒绝。

## StepResult 结构

```go
type StepResult struct {
    Status    string                 `json:"status"`
    Result    map[string]interface{} `json:"result"`
    Error     string                 `json:"error,omitempty"`
    StartedAt time.Time              `json:"started_at"`
    EndedAt   time.Time              `json:"ended_at"`
    Duration  int64                  `json:"duration"`
}
```

## 错误处理

| 场景 | 结果 |
| --- | --- |
| 引用不存在的步骤 | 模板值解析为 `nil` |
| 引用不存在的字段 | 模板值解析为 `nil` |
| 字段类型不匹配 | 模板值解析为 `nil` |
| 依赖步骤失败 | 当前步骤不会执行，父编排失败 |

## 最佳实践

- 显式声明 `depends_on`，不要引用未依赖的步骤结果。
- 参数模板只表达本次执行输入，不应改写 owner 模块任务定义。
- 对于 Develop 算子工作流，先在 Develop 中创建 `workflow` 任务，再在 Orchestrator 中引用该任务。
- 避免把大体量数据直接放入步骤结果，优先传递 item id、artifact id、path 或 execution id。
